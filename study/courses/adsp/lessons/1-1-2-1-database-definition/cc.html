데이터베이스를 “자료를 많이 저장한 곳”이라고만 기억하면 클라우드 폴더나 엑셀 파일 모음과 구별하기 어렵다. 데이터베이스는 조직의 업무에 필요한 데이터를 일정한 구조와 규칙 아래 통합하여 저장하고, 여러 사용자가 공동으로 신뢰성 있게 이용할 수 있게 만든 데이터의 집합이다. DBMS는 그 데이터 집합을 정의·조작·통제하는 소프트웨어다.

01

1. 데이터베이스의 기본 정의

1.1 조직의 공동 목적을 위한 구조화된 데이터 집합

데이터베이스는 관련 있는 데이터를 논리적으로 조직하여 저장한 집합이다. 핵심은 양이 아니라 관계, 구조, 규칙, 지속적 이용 목적이다. 쇼핑몰 데이터베이스라면 고객, 상품, 주문, 결제, 배송 데이터가 서로 연결되고, 고객 번호와 주문 번호 같은 식별 기준 및 값의 유효성 규칙이 관리된다.

다음 세 경우를 비교해 보자.

  1. 개인이 다운로드 폴더에 영수증 이미지를 모아 둠
    저장된 자료이지만 조직 전체의 구조·관계·공동 이용 규칙이 약하다.
  2. 부서별로 고객 명단을 각각 관리함
    운영 데이터이지만 중복과 정의 불일치 때문에 통합 데이터베이스라고 보기 어렵다.
  3. 고객을 하나의 식별 체계로 관리하고 주문·상담·배송이 이를 참조함
    조직의 업무 데이터를 통합하고 공동으로 이용하는 데이터베이스에 가깝다.

데이터베이스는 특정 파일 형식이나 관계형 테이블에만 한정되지 않는다. 문서형, 그래프형, 키–값형 데이터베이스도 목적에 맞는 구조와 관리 체계를 갖춘다. ADsP 기초에서는 구현 제품보다 데이터베이스의 정의 요소와 DBMS의 관리 기능을 이해하는 것이 중요하다.

1.2 데이터베이스를 설명하는 네 관점

전통적으로 데이터베이스는 통합된 데이터, 저장된 데이터, 운영 데이터, 공용 데이터라는 관점으로 설명한다.

1. 데이터베이스의 기본 정의 · 학습 표 1
관점의미확인 질문
통합된 데이터중복을 통제하고 일관된 기준으로 결합한 데이터같은 고객·상품이 부서마다 충돌하지 않는가
저장된 데이터컴퓨터가 접근할 수 있는 저장 매체에 지속적으로 기록된 데이터프로그램 종료 뒤에도 보존되고 다시 조회 가능한가
운영 데이터조직의 고유 기능 수행에 계속 필요한 데이터실제 주문·진료·수업·회계 업무에 사용되는가
공용 데이터여러 사용자와 응용 프로그램이 공동으로 이용하는 데이터권한을 가진 여러 주체가 같은 기준의 값을 사용하는가

네 요소는 서로 대체하지 않는다. 백업 매체에 파일을 저장했다는 사실만으로 운영·공용 데이터가 되지 않고, 여러 사람이 공유하는 문서라고 해서 데이터 정의와 중복 통제가 자동으로 이루어지는 것도 아니다.

02

2. 데이터베이스의 통합된 데이터

2.1 통합은 무조건 한곳에 모으는 일이 아니다

데이터베이스의 통합된 데이터란 조직 곳곳에 흩어진 관련 데이터를 일관된 정의와 관계 아래 이용할 수 있게 구성한 것을 뜻한다. 물리적으로 하나의 서버에 모두 저장해야 한다는 의미는 아니다. 여러 저장소에 분산되어 있어도 식별자, 스키마, 품질 규칙과 참조 관계가 일관되게 관리되면 논리적 통합을 이룰 수 있다.

통합의 목적은 다음 문제를 줄이는 데 있다.

  • 같은 고객이 부서마다 다른 번호와 주소로 기록됨
  • 상품 가격을 영업 시스템에서는 부가세 포함, 회계 시스템에서는 제외로 해석함
  • 한 파일에서 고객을 삭제했지만 다른 파일에는 남아 있음
  • 여러 사본 중 어느 값이 최신인지 알 수 없음
  • 주문과 배송을 연결할 공통 식별자가 없음

통합 데이터에서는 “고객”, “매출”, “활성 회원” 같은 핵심 개념의 정의, 식별 규칙, 관계, 갱신 책임을 정한다. 이를 통해 서로 다른 업무가 같은 사실을 일관되게 참조할 수 있다.

2.2 통합과 중복 통제

통합된 데이터는 흔히 “중복을 최소화한 데이터”로 설명된다. 여기서 최소화는 모든 중복을 물리적으로 제거한다는 뜻이 아니다. 성능, 가용성, 분석 편의를 위해 복제본이나 요약 테이블을 둘 수 있다. 중요한 것은 중복이 의도되고 관리되며 동기화 규칙이 명확한가이다.

2. 데이터베이스의 통합된 데이터 · 학습 표 2
중복 상황문제 또는 목적판단
부서가 같은 고객 주소를 독립 입력충돌·갱신 누락 가능통제되지 않은 중복
장애 대비 읽기 복제본가용성과 조회 성능 향상목적과 동기화가 명확한 관리된 중복
월별 매출 집계 테이블분석 응답 속도 향상생성 규칙·갱신 시점 관리 필요
백업 사본장애·오류 복구운영 원본과 구별되는 필수 사본

따라서 “데이터베이스에는 중복이 전혀 존재하지 않는다”는 문장은 틀리기 쉽다. 데이터베이스는 불필요하고 모순을 만드는 중복을 통제한다.

2.3 통합을 지탱하는 요소

  • 공통 식별자: 고객 ID, 상품 ID처럼 동일 대상을 연결한다.
  • 스키마: 데이터 구조, 속성, 관계를 정의한다.
  • 도메인 규칙: 값의 자료형, 범위, 코드 체계를 정한다.
  • 무결성 제약: 존재하지 않는 고객의 주문처럼 모순된 상태를 막는다.
  • 메타데이터: 데이터의 뜻, 출처, 단위, 책임자를 설명한다.
  • 갱신 책임: 어느 시스템과 담당자가 기준값을 변경하는지 정한다.

통합은 기술적 결합만이 아니다. 부서마다 다른 업무 용어와 기준을 합의하는 데이터 거버넌스가 함께 필요하다.

03

3. 저장·운영·공용 데이터

3.1 저장된 데이터

저장·운영·공용 데이터 중 저장된 데이터는 컴퓨터가 접근할 수 있는 저장 매체에 기록되어 지속적으로 보존되는 데이터다. 프로그램 실행 중 메모리에 잠시 존재하는 중간값과 달리, 전원이 꺼지거나 응용 프로그램이 종료되어도 다시 이용할 수 있어야 한다.

저장은 단순 보관을 넘어 다음을 포함한다.

  • 데이터 구조와 물리적 위치 관리
  • 검색을 위한 인덱스와 접근 경로
  • 장애에 대비한 로그와 백업
  • 보존 기간과 폐기 규칙
  • 저장 암호화와 접근 권한

데이터를 저장했다는 사실만으로 가치가 생기지는 않는다. 찾을 수 없거나 의미를 알 수 없고 복구할 수 없다면 운영 자산으로 쓰기 어렵다.

3.2 운영 데이터

운영 데이터는 조직의 고유한 기능을 수행하기 위해 계속 생성·갱신·참조되는 데이터다.

  • 대학: 학생, 교과목, 수강, 성적
  • 병원: 환자, 진료, 처방, 검사 결과
  • 은행: 계좌, 거래, 잔액, 고객
  • 제조사: 자재, 공정, 설비, 생산 실적
  • 쇼핑몰: 상품, 주문, 결제, 배송

일회성 행사 사진을 개인이 보관하는 것과 달리, 운영 데이터는 업무 절차의 현재 상태를 나타내고 다음 행동을 결정한다. 잘못된 재고 수량은 발주와 판매를 왜곡하고, 잘못된 계좌 잔액은 금융 거래에 직접 영향을 준다. 그래서 정확성, 일관성, 적시성과 변경 통제가 중요하다.

운영 데이터는 반드시 자주 변경되는 값만을 뜻하지 않는다. 상품 분류 기준이나 계정과목처럼 상대적으로 안정적이어도 조직 운영에 지속적으로 필요하면 운영 데이터다.

3.3 공용 데이터

공용 데이터는 권한을 가진 여러 사용자와 응용 프로그램이 공동으로 이용하는 데이터다. “공용”은 누구나 제한 없이 볼 수 있다는 뜻이 아니다. 동일한 데이터 자원을 권한과 규칙 아래 함께 사용한다는 뜻이다.

주문 데이터는 고객 서비스가 문의에 답할 때, 물류 시스템이 출고할 때, 회계가 매출을 인식할 때 각각 사용한다. 여러 사용자가 동시에 접근하므로 다음 관리가 필요하다.

  • 사용자·역할별 접근 권한
  • 동시 갱신 시 일관성을 지키는 동시성 제어
  • 여러 작업을 하나의 논리 단위로 처리하는 트랜잭션
  • 변경 이력과 감사 로그
  • 장애 시 복구와 서비스 연속성
  • 개인정보와 민감정보의 목적별 이용 통제

공용성이 높을수록 단일 기준을 이용하는 장점이 커지지만, 잘못된 데이터와 장애의 영향도 넓어진다. 공유 범위에 맞는 품질·보안·가용성 통제가 필요하다.

3.4 네 관점 종합 사례

대학교 수강 시스템을 보자.

  1. 학사과, 각 학과, 도서관의 학생 자료를 하나의 학번과 정의로 연결한다. → 통합된 데이터
  2. 학생·과목·수강 내역을 지속성 있는 저장장치에 기록하고 백업한다. → 저장된 데이터
  3. 수강신청, 성적 입력, 졸업 판정이라는 대학의 핵심 업무에 사용한다. → 운영 데이터
  4. 학생, 교수, 학사 담당자와 여러 응용 서비스가 권한에 따라 공동 이용한다. → 공용 데이터

하나의 수강 레코드가 네 종류 중 하나만 선택되는 것이 아니다. 동일 데이터베이스를 서로 다른 관점에서 설명한 것이다.

04

4. 데이터베이스와 데이터베이스 관리시스템

4.1 DB와 DBMS를 구별한다

데이터베이스와 데이터베이스 관리시스템은 대상과 도구의 관계다.

  • 데이터베이스(DB): 서로 관련된 데이터의 구조화된 집합
  • 데이터베이스 관리시스템(DBMS): 사용자가 데이터베이스를 정의·생성·조회·수정하고, 보안·무결성·동시성·복구를 관리할 수 있게 하는 소프트웨어
  • 데이터베이스 시스템: 데이터베이스, DBMS, 응용 프로그램, 사용자, 절차와 하드웨어를 포함한 전체 환경

도서관에 비유하면 데이터베이스는 분류되어 보관된 책과 대출 기록이고, DBMS는 등록·검색·대출·반납·권한·복구를 수행하는 관리 체계에 가깝다. 데이터가 DBMS 자체인 것은 아니다.

4.2 DBMS의 핵심 기능

정의 기능

어떤 데이터를 어떤 구조와 관계로 저장할지 정한다. 테이블, 속성, 자료형, 키, 제약조건, 뷰 등의 스키마를 정의한다.

코드 예시 · sql

CREATE TABLE customer (
  customer_id INTEGER PRIMARY KEY,
  name        VARCHAR(100) NOT NULL,
  grade_code  VARCHAR(10) NOT NULL
);

이 명령은 실제 고객 데이터를 조회하는 것이 아니라 데이터 구조와 규칙을 정의한다.

조작 기능

데이터를 검색·삽입·수정·삭제한다. 사용자는 질의 언어나 응용 프로그램을 통해 필요한 데이터를 다룬다.

코드 예시 · sql

SELECT grade_code, COUNT(*) AS customer_count
FROM customer
GROUP BY grade_code;

제어 기능

여러 사용자가 데이터를 안전하고 일관되게 공동 이용하도록 통제한다.

  • 무결성 제약으로 유효하지 않은 상태 방지
  • 권한 부여와 회수로 접근 통제
  • 트랜잭션과 동시성 제어로 충돌 방지
  • 로그·백업·복구로 장애 이전 상태 회복
  • 감사 기록으로 누가 무엇을 변경했는지 추적

DBMS가 항상 더 단순하거나 저렴한 것은 아니다. 설치·운영 인력, 자원, 라이선스, 보안 관리가 필요하다. 단순하고 임시적인 개인 자료라면 파일이 적합할 수 있다. 하지만 여러 업무가 핵심 데이터를 공동으로 갱신하고 일관성·복구가 중요하다면 DBMS의 가치가 커진다.

4.4 스키마와 인스턴스

  • 스키마: 데이터베이스의 구조와 제약을 설명하는 설계다. 상대적으로 자주 바뀌지 않는다.
  • 인스턴스: 특정 시점에 데이터베이스에 실제로 저장된 값의 상태다. 거래에 따라 계속 변한다.

주문(주문번호, 고객번호, 주문일시, 금액)이라는 정의는 스키마이고, 오늘 생성된 주문 1,250건은 현재 인스턴스의 일부다. DBMS는 스키마 규칙을 이용해 인스턴스가 올바른 상태를 유지하도록 한다.

4.5 데이터 독립성의 기초 의미

DBMS는 데이터 구조와 응용 프로그램 사이의 결합을 줄인다. 저장 위치나 인덱스를 바꾸어도 업무 프로그램을 모두 수정하지 않도록 물리적 변화의 영향을 감추고, 논리 구조의 일부 변화도 뷰와 인터페이스로 완화할 수 있다.

독립성은 “어떤 구조를 바꿔도 프로그램에 영향이 전혀 없다”는 절대적 보장이 아니다. 변경 영향을 관리 가능한 범위로 줄이는 설계 원칙이다.

05

5. 실무 설계 사례

지역 병원이 진료·검사·수납을 각 부서 파일로 관리해 다음 문제가 생겼다.

  • 환자 이름과 주소가 부서마다 다르다.
  • 검사 결과 파일을 복사하는 동안 최신본이 뒤바뀐다.
  • 두 직원이 같은 수납 상태를 동시에 수정해 값이 사라진다.
  • 담당자 퇴사 후 파일 암호를 알 수 없다.
  • 어느 백업으로 어느 시점까지 복구할 수 있는지 모른다.

개선 절차는 다음과 같다.

  1. 환자·진료·검사·수납의 공통 정의와 식별자를 정한다.
  2. 중복 필드의 기준 시스템과 갱신 책임을 정한다.
  3. 관계와 무결성 규칙을 스키마로 정의한다.
  4. 역할별 최소 권한과 민감정보 접근 기록을 설계한다.
  5. 진료 등록과 수납 변경을 트랜잭션으로 처리한다.
  6. 동시 갱신 충돌 규칙과 장애 복구 목표를 정한다.
  7. 기존 파일을 정제·매핑해 이관하고 결과를 대조한다.

여기서 데이터베이스는 통합된 환자·진료 데이터의 집합이고, DBMS는 구조 정의, 질의, 동시성, 권한, 복구를 수행한다. 병원 업무 절차와 사용자는 전체 데이터베이스 시스템의 일부다.

06

6. 시험에서 자주 틀리는 판단

함정 1. 통합 데이터는 중복이 전혀 없다

불필요하고 충돌을 만드는 중복을 통제한다는 뜻이다. 성능 복제, 요약, 백업처럼 목적이 명확한 중복은 존재할 수 있다.

함정 2. 공용 데이터는 누구나 볼 수 있다

권한을 가진 여러 사용자와 응용이 공동 이용한다는 뜻이다. 보안과 최소 권한이 전제된다.

함정 3. 운영 데이터는 매초 변경되어야 한다

조직의 고유 업무 수행에 계속 필요한 데이터라는 뜻이다. 변경 빈도가 낮은 기준정보도 운영 데이터일 수 있다.

함정 4. 데이터베이스와 DBMS는 같은 말이다

DB는 데이터 집합이고 DBMS는 이를 정의·조작·통제하는 소프트웨어다.

함정 5. 저장된 모든 파일은 데이터베이스다

저장은 한 요소일 뿐이다. 관련 데이터의 구조, 통합, 운영 목적, 공동 이용과 관리 규칙을 함께 보아야 한다.

함정 6. DBMS를 쓰면 품질 문제가 자동 해결된다

제약과 트랜잭션 기능을 제공하지만 올바른 정의, 품질 규칙, 책임과 운영 절차를 설계해야 한다.

7. 빠른 점검 체크리스트

데이터베이스 정의 판단

  • 관련 데이터가 공통 정의와 식별자로 연결되는가?
  • 불필요한 중복과 값 충돌을 통제하는가?
  • 프로그램 종료 뒤에도 지속적으로 저장되는가?
  • 조직의 실제 업무에 계속 필요한가?
  • 여러 사용자·응용이 권한 아래 공동 이용하는가?

DBMS 역할 판단

  • 스키마와 제약조건을 정의하는가?
  • 검색·삽입·수정·삭제를 지원하는가?
  • 무결성, 보안, 동시성, 트랜잭션을 제어하는가?
  • 로그, 백업, 복구 절차가 있는가?
  • 데이터와 응용 프로그램의 결합을 줄이는가?

9. 정답과 해설

  1. 3 — 통합은 공통 정의와 관계를 만들고 불필요한 중복과 불일치를 통제하는 것이다.
  2. 2 — 조직의 고유한 진료 업무에 지속적으로 필요한 데이터이므로 운영 데이터다.
  3. 2 — 공용은 무제한 공개가 아니라 권한을 가진 여러 주체의 공동 이용을 뜻한다.
  4. 3 — 데이터 집합인 DB와 관리 소프트웨어인 DBMS를 구별해야 한다.
  5. 3 — 보안, 무결성, 동시성, 트랜잭션, 복구는 대표적인 제어 기능이다.
  6. 3 — 목적과 동기화·전환 규칙이 명확한 복제는 관리된 중복이다.
  7. 2 — 스키마는 상대적으로 안정적인 설계이고 인스턴스는 계속 바뀌는 실제 값의 상태다.
  8. 4 — DBMS도 구축·운영 비용과 복잡성이 있으며 상황에 따라 적합성을 판단해야 한다.
  9. 2 — 실행이 끝나도 다시 접근할 수 있도록 저장 매체에 지속적으로 기록된 데이터다.
  10. 2 — 네 용어는 상호 배타적 유형이 아니라 데이터베이스를 설명하는 네 관점이다.
10

10. 핵심 요약

  • 데이터베이스는 조직의 업무에 필요한 관련 데이터를 구조와 규칙 아래 통합·저장하고 공동으로 이용하는 데이터 집합이다.
  • 데이터베이스의 통합된 데이터는 물리적으로 한곳에 모으는 것보다 공통 정의·식별자·관계와 중복 통제가 핵심이다.
  • 저장·운영·공용 데이터는 각각 지속적 기록, 조직 고유 업무에의 지속적 이용, 권한 아래 여러 사용자·응용의 공동 이용을 뜻한다.
  • 통합·저장·운영·공용은 서로 배타적인 종류가 아니라 같은 데이터베이스를 바라보는 관점이다.
  • 데이터베이스와 데이터베이스 관리시스템에서 DB는 데이터의 집합, DBMS는 이를 정의·조작·통제하는 소프트웨어다.
  • DBMS는 스키마 정의, 질의와 변경, 무결성·권한·동시성·트랜잭션·복구를 제공해 파일 중심 처리의 중복과 결합 문제를 줄인다.
  • DBMS가 품질을 자동 보장하지는 않는다. 올바른 데이터 정의, 제약, 책임과 운영 절차가 함께 필요하다.
