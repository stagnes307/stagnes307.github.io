02

2. 실시간 접근성과 계속적인 변화

2.1 실시간 접근성의 의미

실시간 접근성과 계속적인 변화 중 실시간 접근성은 사용자의 질의에 대해 업무상 허용되는 시간 안에 응답할 수 있다는 특성이다. “모든 질의가 0초에 끝난다”거나 “항상 하드 실시간 시스템이다”라는 뜻은 아니다. 서비스 목적에 맞는 응답 시간 기준을 정하고 이를 만족하는 것이 핵심이다.

  • 결제 승인: 수초 안에 응답하지 않으면 고객이 재시도할 수 있다.
  • 상품 검색: 대개 짧은 대기 안에 결과가 필요하다.
  • 월말 분석 보고서: 수분이 걸려도 업무상 허용될 수 있다.
  • 안전 제어: 일반 업무 데이터베이스보다 훨씬 엄격한 시간 보장이 필요할 수 있다.

같은 3초도 업무에 따라 실시간으로 충분하거나 너무 늦을 수 있다. 따라서 실시간성은 상대적인 업무 요구다.

2.2 실시간 접근을 지원하는 요소

  • 인덱스: 자주 검색하는 키와 조건의 탐색 범위를 줄인다.
  • 질의 최적화: 여러 실행 방법 중 비용이 낮은 계획을 선택한다.
  • 적절한 데이터 모델: 조회·변경 패턴에 맞게 구조를 설계한다.
  • 캐시와 요약 데이터: 반복 조회 또는 복잡한 집계의 응답을 줄인다.
  • 분할과 분산: 대규모 데이터를 업무 기준으로 나누어 처리한다.
  • 모니터링: 느린 질의, 잠금 대기, 자원 포화를 관찰한다.

인덱스를 많이 만들면 조회가 무조건 빨라지는 것은 아니다. 인덱스도 저장 공간을 사용하고 데이터 변경 때 함께 갱신해야 한다. 조회와 변경의 비율, 조건의 선택도, 데이터 규모를 고려해야 한다.

2.3 계속적인 변화

데이터베이스는 업무가 진행되는 동안 삽입, 삭제, 수정으로 계속 변화한다.

  • 신규 고객 가입 → 고객 행 삽입
  • 배송지 변경 → 주소 수정
  • 주문 취소 → 상태 변경 또는 취소 기록 추가
  • 보존 기간 만료 → 정책에 따른 삭제·비식별화

“계속 변화한다”는 말은 모든 데이터가 매 순간 바뀐다는 뜻이 아니다. 상품 코드나 조직 분류처럼 비교적 안정적인 기준정보도 있다. 데이터베이스 전체가 현실의 상태 변화를 지속적으로 반영할 수 있다는 뜻이다.

2.4 현재 상태와 이력

현재 값만 덮어쓰면 과거를 알 수 없다. 반대로 모든 변화를 무제한 저장하면 비용과 개인정보 위험이 증가한다. 업무 요구에 따라 다음을 결정한다.

계속적인 변화 속에서도 일관성을 지키려면 변경을 트랜잭션 단위로 처리하고 로그를 남겨야 한다. 주문은 생성됐지만 재고 차감이 빠지는 식의 부분 반영을 막아야 한다.

2.5 실시간과 최신성은 같은 말이 아니다

질의가 0.1초에 응답해도 어제의 복제본을 읽었다면 최신성이 낮을 수 있다. 반대로 방금 갱신된 정확한 값을 읽느라 2초가 걸릴 수 있다. 다음을 구별한다.

  • 응답 지연: 질의를 보낸 뒤 결과를 받기까지의 시간
  • 데이터 신선도: 결과가 현실의 최신 상태를 얼마나 반영하는가
  • 처리량: 일정 시간에 처리할 수 있는 요청 수
  • 일관성 수준: 동시 변경 중 어떤 상태를 읽도록 보장하는가

분산 환경에서는 더 빠른 지역 복제본과 완전히 최신인 원본 사이에 선택이 필요할 수 있다. 업무가 허용하는 지연과 불일치 범위를 명시해야 한다.

3. 동시 공용과 내용에 의한 참조

3.1 동시 공용

동시 공용과 내용에 의한 참조에서 동시 공용은 여러 사용자와 응용 프로그램이 같은 데이터베이스를 동시에 접근·갱신할 수 있다는 특성이다. 쇼핑몰에서는 고객이 주문하고, 물류 담당자가 출고하며, 상담원이 주문 상태를 조회하고, 정산 배치가 매출을 집계한다.

공동 이용은 단순히 여러 화면이 열리는 것을 뜻하지 않는다. 서로의 작업이 충돌해도 데이터가 올바른 상태를 유지해야 한다.

3.2 대표적인 동시성 문제

갱신 분실

재고가 10개일 때 사용자 A와 B가 모두 10을 읽는다. A가 2개 판매 후 8로 저장하고, B가 3개 판매 후 이전 값 10을 기준으로 7을 저장하면 A의 변경이 사라진다. 올바른 결과는 5다.

오염된 읽기

한 트랜잭션이 아직 확정하지 않은 값을 다른 사용자가 읽었다가, 첫 트랜잭션이 취소되면 존재하지 않았던 값에 근거해 판단한 셈이 된다.

반복 불가능한 읽기

한 작업 안에서 같은 행을 두 번 읽었는데 다른 사용자의 확정된 수정 때문에 값이 달라진다.

유령 데이터

같은 조건으로 행 집합을 다시 조회했을 때 다른 사용자의 삽입·삭제로 행 수가 달라진다.

동시성 문제를 막기 위해 잠금, 다중 버전 관리, 격리 수준, 원자적 조건 갱신 등을 사용한다. 통제를 과도하게 강하게 하면 대기가 늘어 성능이 떨어질 수 있으므로 업무의 정확성 요구와 처리량을 함께 본다.

3.3 트랜잭션 단위의 공동 이용

트랜잭션은 업무적으로 하나로 처리되어야 하는 작업의 묶음이다. 계좌 이체는 출금과 입금이 모두 성공하거나 모두 취소되어야 한다.

코드 예시 · text

트랜잭션 시작
  출금 계좌 잔액과 한도 확인
  출금 반영
  입금 반영
  이체 기록 생성
모든 단계 성공 → 확정
어느 단계 실패 → 전체 취소

동시 공용 환경에서는 트랜잭션이 서로의 중간 상태를 부적절하게 보지 않도록 하고, 충돌 시 대기·재시도·실패 중 어떤 정책을 사용할지 정해야 한다.

3.4 내용에 의한 참조

내용에 의한 참조는 사용자가 데이터가 디스크의 몇 번째 블록에 저장됐는지 알 필요 없이, 원하는 값과 조건을 제시해 데이터를 찾는 특성이다.

코드 예시 · sql

SELECT order_id, order_amount
FROM orders
WHERE customer_id = 2105
  AND order_status = 'PAID';

사용자는 고객 ID와 주문 상태라는 내용으로 요청한다. DBMS는 인덱스를 사용할지 전체를 읽을지, 어느 저장 위치에 접근할지를 결정한다. 데이터가 다른 페이지나 장치로 이동해도 같은 논리적 질의를 유지할 수 있다.

내용에 의한 참조가 가능하려면 값의 의미와 구조를 설명하는 스키마, 키, 코드 체계, 메타데이터가 필요하다. 서로 다른 부서가 ACTIVE의 뜻을 다르게 사용하면 같은 조건도 일관된 결과를 만들지 못한다.

3.5 물리 주소와 논리 조건의 구별

4. 데이터 독립성과 일관성

4.1 데이터 독립성

데이터 독립성과 일관성 중 데이터 독립성은 데이터의 저장 구조나 논리 구조가 바뀔 때 응용 프로그램에 미치는 영향을 줄이는 특성이다.

  • 물리적 데이터 독립성: 파일 배치, 인덱스, 저장 장치, 파티션 같은 물리 구조가 바뀌어도 논리 스키마와 응용이 가능한 한 영향을 받지 않는다.
  • 논리적 데이터 독립성: 테이블·속성·관계 같은 논리 구조가 일부 바뀌어도 사용자 뷰와 응용 인터페이스의 영향을 줄인다.

예를 들어 주문 테이블에 인덱스를 추가하고 저장 장치를 교체해도 기존 질의의 의미가 변하지 않는 것은 물리적 독립성의 사례다. 고객의 이름 구조를 분리하면서 기존 응용에는 호환 뷰를 제공하는 것은 논리적 독립성을 높이는 방법이다.

독립성은 변경 영향이 완전히 0이라는 뜻이 아니다. 업무 의미 자체가 바뀌거나 응용이 삭제된 열을 직접 사용하면 수정이 필요하다. 목적은 저장 세부사항과 업무 로직을 분리하고 변경 범위를 통제하는 것이다.

개념 관점: 조직 전체의 논리 구조와 관계
        ↓ 매핑
내부 관점: 파일·페이지·인덱스·저장 배치

내부 관점의 변화가 개념·외부 관점에 새어 나오지 않도록 하면 물리적 독립성이 높아진다. 개념 관점의 일부 변화가 외부 뷰와 응용에 미치는 영향을 완화하면 논리적 독립성이 높아진다.

4.3 일관성의 의미

일관성은 데이터베이스가 정의된 무결성 제약과 업무 규칙을 만족하고, 서로 관련된 값이 모순되지 않는 상태를 유지하는 것이다.

  • 주문의 고객 ID는 실제 존재하는 고객을 참조한다.
  • 재고 수량은 정책상 허용되지 않는 음수가 되지 않는다.
  • 주문 합계는 품목 금액·할인·세금 규칙과 맞는다.
  • 동일 코드가 시스템마다 다른 뜻으로 사용되지 않는다.
  • 하나의 트랜잭션이 부분 성공 상태를 남기지 않는다.

일관성은 “모든 복제본이 매 순간 완전히 같은 값”만을 뜻하지 않는다. 분산 복제에서는 짧은 동기화 지연을 허용할 수 있지만, 허용 범위와 최종 수렴, 충돌 해결 규칙이 필요하다. 업무 무결성과 복제 최신성을 구별해야 한다.

4.4 일관성을 지키는 수단

4. 데이터 독립성과 일관성 · 학습 표 4
수단역할예시
기본키행의 고유성 보장주문 번호 중복 금지

도메인·검사 제약값 범위와 형식 보장수량은 0 이상

기준정보 관리시스템 간 의미 통일상태 코드와 통화 단위 통합
조정·대사시스템 간 결과 검증결제 합계와 회계 전표 비교

제약을 많이 선언한다고 업무 일관성이 자동 완성되지는 않는다. “한 고객의 하루 환불 한도”처럼 여러 행과 시간이 관련된 규칙은 응용 로직, 트랜잭션, 배치 검증을 조합할 수 있다. 규칙의 소유자와 실패 처리도 정해야 한다.

4.5 독립성과 일관성의 관계

독립성은 변경의 영향을 줄이고, 일관성은 변경 후에도 데이터 의미와 규칙을 지킨다. 물리 저장을 바꾸면서 데이터 누락이 생기면 독립성 구현에 실패한 것이며 일관성도 훼손된다. 논리 스키마를 개편하면서 코드 의미가 달라졌는데 호환 뷰만 제공하면 문법은 유지되어도 업무 의미는 일관되지 않을 수 있다.

변경 전후에 다음을 확인한다.

  1. 기존 사용자 뷰와 질의가 같은 의미를 유지하는가?
  2. 데이터 건수·합계·참조 관계가 대조되는가?
  3. 새 제약과 변환 규칙이 업무 정의와 맞는가?
  4. 동시 변경과 복구 상황에서도 부분 상태가 남지 않는가?
  5. 호환 기간과 폐기 시점이 명확한가?
05

5. 종합 사례: 마지막 상품 한 개

재고가 한 개 남은 상품을 고객 A와 B가 동시에 주문한다.

  1. 두 고객은 상품 코드라는 내용으로 재고를 조회한다.
  2. 응답은 결제 흐름을 유지할 수 있는 실시간 접근성 기준을 만족해야 한다.
  3. 주문과 재고는 거래에 따라 계속 변화한다.
  4. 두 고객과 물류 시스템이 동시 공용하므로 단순히 각각 재고 1을 읽고 저장하면 초과 판매가 생길 수 있다.
  5. 재고 > 0 조건을 포함한 원자적 차감 또는 적절한 잠금으로 한 주문만 성공시켜 일관성을 지킨다.
  6. DB 관리자가 재고 조회용 인덱스를 바꾸더라도 주문 프로그램의 의미가 유지되면 물리적 데이터 독립성을 확보한 것이다.

안전한 개념적 갱신은 다음처럼 표현할 수 있다.

코드 예시 · sql

UPDATE inventory
SET quantity = quantity - 1
WHERE product_id = :product_id
  AND quantity > 0;

-- 변경된 행이 1개일 때만 주문을 계속한다.
-- 0개라면 품절로 처리하고 결제를 확정하지 않는다.

실제 구현은 DBMS와 트랜잭션 경계에 따라 달라지지만, 읽기와 쓰기 사이의 경쟁을 통제하고 결과 행 수를 확인한다는 판단이 중요하다.

6. 시험에서 자주 틀리는 판단

함정 1. 실시간 접근성은 지연이 0이라는 뜻이다

업무상 허용된 시간 안에 질의 결과를 제공하는 특성이다. 요구 시간은 업무마다 다르다.

함정 2. 계속적인 변화는 모든 값이 계속 바뀐다는 뜻이다

데이터베이스가 현실의 변화에 따라 삽입·수정·삭제되며 최신 상태를 반영한다는 뜻이다. 안정적인 기준정보도 존재한다.

함정 3. 동시 공용은 단순히 여러 명이 읽는 것이다

여러 사용자가 동시에 조회·갱신해도 충돌과 부분 상태를 통제해야 한다.

함정 4. 내용 참조는 저장 주소를 직접 지정하는 것이다

반대다. 사용자는 물리 위치가 아니라 키, 값, 조건과 관계로 원하는 데이터를 찾는다.

함정 5. 데이터 독립성은 구조를 자유롭게 바꿔도 영향이 전혀 없다는 뜻이다

물리·논리 구조 변화가 응용에 미치는 영향을 줄이는 성질이다. 의미가 바뀌는 변경은 호환 설계와 응용 수정이 필요할 수 있다.

함정 6. 일관성은 모든 사본이 항상 같은 시각의 값을 갖는 것만 뜻한다

업무 규칙과 무결성을 만족하는 상태가 핵심이다. 복제 신선도는 별도의 일관성 정책과 허용 지연으로 관리한다.

9. 정답과 해설

  1. 2 — 실시간은 업무 목적에 맞는 응답 시간이며 무조건 0초라는 뜻이 아니다.
  2. 1 — 현실의 업무 사건에 따라 데이터가 삽입·수정·삭제되는 특성을 보여 준다.
  3. 2 — 이전 값을 각각 읽고 덮어쓰면서 먼저 확정한 변경이 사라지는 갱신 분실이다.
  4. 3 — 물리 위치가 아니라 데이터의 값과 조건으로 대상을 찾는다.
  5. 1 — 내부 저장 방식 변화가 논리 구조와 응용에 영향을 주지 않도록 한 물리적 독립성 사례다.
  6. 2 — 논리 스키마 변화의 응용 영향을 뷰와 인터페이스로 줄인다.
  7. 4 — 통제되지 않은 충돌 중복은 일관성을 훼손한다.
  8. 1 — 짧은 응답 시간과 최신 데이터 사용 여부는 서로 다른 품질 축이다.
  9. 1 — 관련 작업의 원자성과 격리를 확보해 부분 반영과 동시 충돌을 통제한다.
  10. 2 — 변화·실시간·공동 이용이 결합되므로 무결성, 동시성, 논리적 접근과 변경 영향 통제가 함께 필요하다.

10. 핵심 요약

  • 실시간 접근성과 계속적인 변화는 업무상 허용 시간 안에 질의에 응답하고 현실의 사건에 따라 데이터를 지속적으로 삽입·수정·삭제하는 특성이다.
  • 실시간 접근성은 0초 응답이 아니며, 응답 지연·데이터 신선도·처리량·일관성 수준을 구별해야 한다.
  • 동시 공용과 내용에 의한 참조는 여러 사용자가 함께 접근·갱신하고, 물리 주소가 아니라 키·값·조건으로 데이터를 찾는 특성이다.
  • 동시 이용에는 갱신 분실과 비정상 읽기를 막는 트랜잭션·잠금·버전·격리 정책이 필요하다.
  • 데이터 독립성과 일관성은 물리·논리 구조 변경의 응용 영향을 줄이면서 키, 관계, 값 범위와 업무 규칙을 만족하는 상태를 유지하는 것이다.
  • 독립성은 변경 영향이 완전히 없다는 뜻이 아니고, 일관성은 복제본의 순간적 동일성만을 뜻하지 않는다.
  • 데이터베이스의 주요 특징은 서로 연결된다. 실시간으로 계속 변하는 공용 데이터를 안전하게 다루기 위해 내용 참조, 독립성, 동시성 제어와 일관성이 함께 필요하다.
