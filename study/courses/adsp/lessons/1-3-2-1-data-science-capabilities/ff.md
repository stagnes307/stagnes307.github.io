통계 지식만 있으면 구현·운영이 막힐 수 있고, 처리 기술만 뛰어나면 잘못된 목표를 빠르게 계산할 수 있다. 업무를 잘 알아도 표본·불확실성을 무시하면 경험을 일반화하기 어렵다. 시험에서는 데이터 사이언스를 **수학·통계, IT·데이터 처리, 비즈니스·커뮤니케이션의 교집합**으로 보고 사례에서 부족한 역량을 판단한다.

## 1. 구성 역량의 전체 구조

### 1.1 세 영역의 역할

```text
수학·통계학적 지식
  └─ 가정·불확실성·추론·평가의 타당성
          ╲
           데이터 사이언스
          ╱
정보기술·데이터 처리 ─ 수집·구현·확장·재현·운영
          ╲
       비즈니스 이해·커뮤니케이션
       └─ 문제·가치·행동·설득·책임
```

좋은 데이터 사이언스는 다음 세 질문에 동시에 답한다.

1. **통계적으로 믿을 수 있는가?** 자료와 가정·검증이 결론을 지지하는가?
2. **기술적으로 실행 가능한가?** 데이터를 안정적으로 만들고 결과를 반복·운영할 수 있는가?
3. **업무적으로 의미 있는가?** 중요한 의사결정을 개선하고 이해관계자가 행동할 수 있는가?

한 사람이 세 영역을 모두 같은 깊이로 갖추기 어렵다. 개인은 넓은 공통 이해와 하나 이상의 깊은 전문성을 갖추고, 팀은 상호 검토와 공통 언어로 빈틈을 메운다.

### 1.2 문제 단계별 역량 연결

| 단계 | 수학·통계 | IT·데이터 처리 | 비즈니스·커뮤니케이션 |
|---|---|---|---|
| 문제 정의 | 측정·가설·인과 질문 | 데이터 존재·획득 가능성 | 가치·의사결정·제약 합의 |
| 데이터 준비 | 표본·결측·편향 판단 | 수집·결합·품질·계보 | 업무 정의·예외·권한 확인 |
| 분석 | 방법·가정·불확실성 | 코드·성능·버전·재현 | 결과의 맥락·행동 해석 |
| 평가 | 지표·검증·오류 비교 | 반복 실행·시험 환경 | 오류 비용·가치·수용성 |
| 적용 | 실험·관찰 설계 | 배포·모니터링·복구 | 프로세스·책임·설득·변화관리 |

역량은 분석 단계만의 것이 아니다. 배포 뒤 실제 효과와 데이터 변화까지 관찰해야 구성 역량이 완성된다.

## 2. 수학·통계학적 지식

### 2.1 수학의 역할

**수학·통계학적 지식**에서 수학은 자료를 구조화하고 관계와 최적화 원리를 표현하는 언어다.

- 선형대수: 벡터·행렬, 거리, 차원 변환, 회귀·모형 계산
- 미적분: 변화율, 손실함수와 최적화, 연속 관계
- 확률: 불확실한 사건, 조건부 관계, 확률 모형
- 최적화: 목적함수와 제약 아래 최선의 선택
- 이산수학·논리: 그래프·관계·알고리즘 구조

시험 수준에서는 복잡한 증명보다 어떤 문제에 어떤 사고가 필요한지 이해한다. 예를 들어 예측 확률 0.8은 사건이 확정되었다는 뜻이 아니고, 반복되는 유사 조건에서의 불확실성 표현이다.

### 2.2 기술통계와 추론통계

기술통계는 관찰한 자료의 중심·산포·분포·관계를 요약한다. 추론통계는 표본으로 모집단의 특성이나 가설을 판단하며 표본오차와 불확실성을 다룬다.

| 구분 | 질문 | 예 |
|---|---|---|
| 기술통계 | 관찰 자료는 어떤 모습인가? | 평균·중앙값·분산·분포·상관 |
| 추정 | 모집단 값은 어느 범위인가? | 모비율 추정과 신뢰구간 |
| 가설검정 | 관찰 차이가 우연으로 설명 가능한가? | 두 정책의 전환율 차이 검정 |
| 예측 | 새 관측의 결과는 무엇일까? | 이탈 확률·수요 예측 |
| 인과 | 개입하면 결과가 얼마나 달라질까? | 가격 변경의 증분 효과 |

평균 하나만으로 비대칭 분포와 이상값을 숨길 수 있다. 통계적 유의성이 업무상 큰 효과를 뜻하지 않으며, 유의하지 않다는 결과가 효과가 정확히 0임을 증명하는 것도 아니다.

### 2.3 표본과 대표성

표본 크기가 커도 수집 방식이 편향되면 모집단을 대표하지 못한다. 온라인 설문 응답자가 전체 고객과 다를 수 있고, 서비스에 접근하지 못한 사람은 이용 기록에 나타나지 않는다. 표본틀, 선택·응답 과정, 가중, 결측을 확인한다.

무작위 표본은 알려지지 않은 요인의 균형을 기대하게 하지만 현실 제약이 있다. 관찰자료에서는 교란과 선택 편향을 명시하고 단정 수준을 조절한다. “빅데이터는 전수이므로 표본오차가 없다”는 주장도 분석 대상 모집단이 무엇인지, 빠진 집단과 측정 오류가 없는지 확인해야 한다.

### 2.4 확률과 조건부 판단

조건부확률은 새로운 증거가 있을 때 사건 가능성을 갱신하는 사고를 제공한다. 검사 정확도가 높아도 대상 사건 자체가 드물면 양성 중 실제 사건 비율이 예상보다 낮을 수 있다. 기본 발생률을 무시하면 이상 탐지·의료 선별·부정 거래에서 오탐을 과소평가한다.

분류 결과는 혼동행렬과 정확도·정밀도·재현율 등을 목적에 맞게 본다. 놓침과 오탐 비용이 다르면 임계값도 달라진다. 한 지표만 최고인 모형보다 업무 비용과 집단 영향을 균형 있게 선택한다.

### 2.5 상관·인과와 실험

상관은 변수의 동반 변화를 설명하지만 인과를 증명하지 않는다. 개입 의사결정에는 처리집단·대조집단, 무작위화, 전후 비교, 교란 통제 등 인과 설계를 검토한다.

실험에서도 무작위 배정 실패, 실험 간 간섭, 중도 이탈, 여러 지표 반복 검정, 짧은 기간의 신규효과를 주의한다. 통계 기법보다 업무가 실제로 어떤 처치를 받았는지 정확히 정의하는 것이 먼저다.

### 2.6 모형 평가와 일반화

학습자료에 맞는 정도와 새로운 자료에 일반화되는 능력을 구분한다. 학습·검증·시험자료를 역할별로 분리하고 시간 의존 문제는 미래를 과거로 예측하는 방식으로 나눈다. 정보 누수, 과적합, 여러 모형 비교 후 선택 편향을 막는다.

점 추정치와 함께 불확실성, 기간·집단별 안정성, 기준 모형 대비 개선을 보고한다. 모형 가정과 적용 범위를 문서화하고 환경이 변하면 재평가한다.

## 3. 정보기술과 데이터 처리 역량

### 3.1 데이터 생애주기를 구현하는 능력

**정보기술과 데이터 처리 역량**은 코딩 속도만이 아니라 원천에서 결과·운영까지 데이터가 정확하고 재현 가능하게 흐르도록 설계·구현하는 능력이다.

- 데이터베이스·파일·API·스트림에서 데이터 획득
- 스키마·자료형·키·시간·인코딩·단위 이해
- 정제·결합·집계·파생변수와 품질 검사
- 대용량·분산 처리와 자원·성능 관리
- 분석 코드·환경·의존성·데이터 버전 관리
- 자동 시험·배포·스케줄·관찰·복구
- 접근권한·비밀·민감정보·감사 통제

데이터 사이언티스트가 모든 플랫폼을 운영할 필요는 없지만 데이터 생성과 변환 과정이 분석 가정에 미치는 영향을 이해해야 한다.

### 3.2 데이터 구조와 결합

업무 키와 행의 의미를 정의하지 않으면 조인으로 데이터가 증식하거나 누락된다. 고객 한 명, 계약 한 건, 이벤트 한 번 중 분석 단위를 명확히 한다. 시간 데이터는 사건 시각·수집 시각·처리 시각을 구분하고 시간대와 지연 도착을 관리한다.

```text
주문 1건 ── 주문항목 여러 건
   │
   └──── 결제시도 여러 건

주문·항목·결제를 그대로 모두 조인하면 행이 곱해질 수 있음
→ 목표 분석 단위로 먼저 집계하거나 관계를 명시
```

결측·이상값을 단순 삭제하기 전에 발생 원인을 확인하고 원자료·변환 결과·제외 건수를 추적한다. 데이터 처리 로그는 행 수·키 유일성·합계·최소·최대와 버전을 포함할 수 있다.

### 3.3 프로그래밍과 재현성

분석 코드는 읽기 쉬운 함수와 단계, 명시적 입력·출력, 예외·로그, 자동 시험을 가져야 한다. 대화형 노트에서 우연히 실행 순서가 맞아 나온 결과를 재현 가능한 파이프라인으로 정리한다.

```text
원천 버전 + 변환 코드 + 매개변수 + 실행환경
                     ↓
                분석 데이터
                     ↓
모형 코드 + 난수·검증 설정 + 평가 기준
                     ↓
          모형·결과·증거 버전
```

개인 컴퓨터의 전역 패키지와 숨은 파일에 의존하지 않고 환경·의존성을 기록한다. 같은 입력으로 다시 실행했을 때 의미상 같은 결과를 얻고 변경 차이를 설명할 수 있어야 한다.

### 3.4 확장성과 성능

데이터가 크면 필요한 열·행을 일찍 줄이고, 자료형·파티션·인덱스·분산 처리 특성을 활용한다. 그러나 작은 데이터에도 복잡한 분산 시스템을 쓰면 운영비만 커질 수 있다. 처리량, 지연, 비용, 장애 복구 요구로 기술을 선택한다.

성능 최적화는 결과 정확성을 바꾸지 않아야 한다. 표본 처리와 전체 처리 결과, 부동소수점·병렬 집계 차이, 데이터 순서를 검증한다. 캐시는 입력·버전이 달라졌을 때 무효화되어야 한다.

### 3.5 운영과 관찰

모형을 파일로 전달하는 것과 운영 서비스로 관리하는 것은 다르다. 입력 스키마·품질, 지연, 처리량, 오류, 예측 분포, 성능·업무 효과를 관찰하고 재처리·되돌리기·중단 절차를 둔다.

훈련과 운영에서 변환 코드가 달라지는 훈련–서빙 불일치를 막는다. 개인정보·비밀이 로그와 실험 추적에 남지 않게 하고 최소 권한으로 데이터에 접근한다.

## 4. 비즈니스 이해와 커뮤니케이션

### 4.1 업무 문제를 분석 문제로 번역한다

**비즈니스 이해와 커뮤니케이션**은 도메인 용어를 아는 것을 넘어 고객 가치, 프로세스, 수익·비용 구조, 규제·현장 제약, 의사결정 권한을 이해하고 분석 질문으로 바꾸는 역량이다.

“매출을 높이자”를 분석하려면 어느 고객·상품·채널, 매출과 이익 중 무엇, 할인·재고·서비스 중 바꿀 수 있는 행동, 효과를 볼 기간을 정해야 한다. 문제 정의가 틀리면 기술적으로 완벽한 답도 쓸모없다.

### 4.2 현업 지식과 데이터 검증

현업 전문가는 코드값의 실제 의미, 정책 변경, 예외 처리, 데이터에 기록되지 않는 행동을 안다. 분석가는 이를 질문하고 데이터 패턴으로 검증한다. 어느 한쪽의 해석을 무조건 따르지 않는다.

예를 들어 “취소” 상태가 고객 취소뿐 아니라 재고 부족·결제 실패를 함께 포함한다면 이탈 분석의 의미가 달라진다. 정책 적용일과 시스템 변경을 모르면 모형이 업무 변화를 고객 특성으로 오해할 수 있다.

### 4.3 이해관계자와 성공 기준

같은 분석도 경영진은 전략 가치와 위험, 현업은 행동 기준과 예외, IT는 인터페이스·운영, 감사자는 근거·책임을 원한다. 이해관계자별 결정과 필요한 정보를 확인한다.

성과지표는 정확도뿐 아니라 실제 증분 가치, 처리시간, 사용률, 오류 비용, 공정성·안전, 운영비를 포함한다. 성공·중단·재검토 조건을 사전에 합의해 결과에 따라 기준을 바꾸는 일을 막는다.

### 4.4 결과 전달

좋은 전달 구조는 다음과 같다.

1. 결정해야 할 문제와 현재 기준을 먼저 말한다.
2. 핵심 결론과 권고를 한 문장으로 제시한다.
3. 필요한 데이터 근거와 비교를 보여 준다.
4. 가정·불확실성·오류·적용 범위를 공개한다.
5. 대안의 가치·비용·위험을 비교한다.
6. 다음 행동·책임자·검증 계획을 제안한다.

복잡한 모형 구조를 모두 설명하는 것이 소통은 아니다. 대상이 결정할 수 있는 수준으로 정확히 단순화하되 근거를 왜곡하지 않는다. 그래프는 축·분모·기간·표본을 명확히 하고 과장된 시각 효과를 피한다.

### 4.5 협업과 갈등 조정

현업은 빠른 답을, 분석가는 더 나은 데이터를, IT는 안정성을, 보안은 위험 통제를 요구할 수 있다. 공동 목표와 비협상 제약, 단계적 대안을 분리한다. 모호한 요구는 예시 결과와 작은 프로토타입으로 확인한다.

분석가가 “데이터가 없어서 불가능”이라고 끝내기보다 어떤 최소 데이터로 어떤 수준의 답이 가능한지, 추가 수집의 가치와 기간을 설명한다. 불확실성을 숨기지 않으면서 의사결정 가능한 선택지를 제공한다.

## 5. 역량 결합 사례와 판단 절차

### 5.1 사례: 고객센터 재문의 감소

회사가 재문의율을 낮추려 한다. 수학·통계 역량은 상담 유형별 기준율, 표본·기간, 재문의 정의, 상담원·고객 특성의 교란, 개입 효과 검증을 설계한다. 단순 상관으로 상담원 책임을 단정하지 않는다.

IT·처리 역량은 전화·채팅·고객·해결 이력을 동일 문의 단위로 결합하고, 시스템 변경과 시간·중복을 처리한다. 코드·데이터 버전을 고정하고 매일 지표와 품질을 재현한다.

비즈니스·소통 역량은 재문의가 항상 나쁜지 확인한다. 복잡한 문제의 정당한 후속 문의와 첫 문의 미해결을 구분하고, 상담원이 바꿀 수 있는 지식검색·이관·후속 연락을 정의한다. 처리시간·해결률·고객 만족·직원 부담을 함께 경영진과 현업에 설명한다.

### 5.2 부족 역량 진단 절차

1. 핵심 의사결정·행동·가치·위험을 명확히 설명할 수 있는가?
2. 데이터 행의 의미·원천·품질·대표성·시간을 추적할 수 있는가?
3. 분석 방법의 가정·검증·불확실성·오류 비용을 설명할 수 있는가?
4. 코드·환경·데이터·모형 결과를 반복 재현할 수 있는가?
5. 결과를 실제 시스템·프로세스에 통합하고 관찰·복구할 수 있는가?
6. 이해관계자가 근거와 한계를 이해하고 행동·이의제기할 수 있는가?

실패 지점에 맞는 전문가와 학습·검토를 배치한다. 모든 문제를 도구 구매나 교육 한 번으로 해결하려 하지 않는다.

## 6. 시험에서 자주 틀리는 판단

### 함정 1. 데이터 사이언스는 통계학만을 뜻한다

통계 타당성에 더해 데이터 처리·운영과 비즈니스·소통이 필요하다.

### 함정 2. 빅데이터는 표본·추론 지식이 필요 없다

빠진 집단·측정 오류·선택 편향과 불확실성은 데이터가 커도 남는다.

### 함정 3. 통계적 유의성은 업무 효과가 크다는 뜻이다

효과 크기·비용·위험과 실제 의사결정 중요성을 별도로 본다.

### 함정 4. 코딩이 되면 데이터 처리 역량이 충분하다

키·시간·품질·계보·재현·성능·운영·보안이 함께 필요하다.

### 함정 5. 복잡한 분산 기술은 모든 데이터에 더 좋다

규모·지연·비용·운영 요구에 비해 적합한 기술을 선택한다.

### 함정 6. 현업 경험은 주관적이므로 분석에서 제외한다

업무 정의·예외·행동 제약의 중요한 맥락이며 데이터로 검증하며 활용한다.

### 함정 7. 정확한 결과는 설명 없이도 채택된다

이해관계자의 결정·가치·위험 언어로 전달하고 업무 변화와 책임을 설계해야 한다.

## 9. 정답과 해설

1. **2** — 타당한 추론, 안정적 데이터·구현, 올바른 문제·행동·전달의 교집합이 데이터 사이언스다.
2. **1** — 기술통계는 관찰한 자료 자체를 요약하고 추론통계는 표본을 바탕으로 모집단을 불확실성과 함께 판단한다.
3. **2** — 체계적 선택 편향은 표본 수를 늘려도 사라지지 않고 더 정밀한 잘못된 결론을 만들 수 있다.
4. **1** — 사건이 드물면 오탐 수가 많을 수 있고 실제 의사결정에는 오탐·미탐 비용이 다르다.
5. **4** — 근거 없는 확정은 분석 오류이며 IT 역량은 수집·처리·재현·운영과 보호를 다룬다.
6. **1** — 서로 다른 다측 관계가 곱해져 주문금액과 행 수를 중복 계산할 수 있다.
7. **2** — 입력과 변환·환경·모형·평가 조건이 고정·추적되어야 결과를 다시 만들고 차이를 설명한다.
8. **2** — 업무 맥락이 있어야 올바른 목표·행동·지표·오류 비용을 정하고 결과를 실제 가치로 연결한다.
9. **2** — 의사결정을 중심에 두고 결론과 근거·불확실성, 대안·행동을 연결해야 한다.
10. **3** — 어느 하나만으로는 타당하지만 실행 불가하거나, 빠르지만 잘못된 문제를 푸는 결과가 생긴다.

## 10. 핵심 요약

- **수학·통계학적 지식**은 표본·불확실성·가정·추론·평가와 일반화의 타당성을 제공한다.
- 큰 데이터도 대표성·측정 오류·상관과 인과·과적합 문제에서 자유롭지 않다.
- **정보기술과 데이터 처리 역량**은 키·시간·품질·계보부터 코드·환경·배포·관찰·복구까지 결과를 재현·운영하게 한다.
- 기술 선택은 데이터 규모·지연·비용·운영 요구에 맞아야 한다.
- **비즈니스 이해와 커뮤니케이션**은 업무 문제·가치·행동·오류 비용을 정의하고 결론·근거·한계·대안을 전달한다.
- 세 역량은 문제 정의부터 운영 피드백까지 서로 검토·보완하며 개인의 폭과 팀의 깊이로 결합한다.
