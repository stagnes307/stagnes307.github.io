# 2-1-1-1. 분석 기획의 개념과 목표

> **학습 범위**: 이 레슨은 ADsP `데이터분석 기획 > 데이터분석 기획의 이해 > 분석 기획 방향성 도출` 중 **`분석 기획의 정의`**, **`목표 시점별 분석 기획`**, **`분석 주제와 방법의 조합`**을 다룬다. 분석을 시작하기 전에 무엇을 왜 분석하고, 언제 어떤 가치에 도달하며, 대상과 방법의 불확실성을 어떻게 관리할지 정하는 것이 목표다.

분석 기획은 “데이터를 모아서 모델을 만들어 보자”는 선언이 아니다. 해결해야 할 업무 문제, 기대 가치, 분석 범위, 필요한 데이터와 역량, 결과를 사용할 의사결정, 제약과 위험을 연결해 실행 가능한 분석 과제로 만드는 활동이다. 시험에서는 분석 기획과 분석 수행을 혼동하거나 단기 과제와 장기 역량 구축, 분석 대상과 방법의 확정 여부를 바꾸어 제시하므로 판단 기준을 구조화해야 한다.

---

## 1. 분석 기획의 정의

**`분석 기획의 정의`**는 조직의 목표를 달성하기 위해 분석 과제를 발굴·정의하고, 분석 수행에 필요한 계획과 관리 방안을 설계하는 것이다. 핵심 질문은 다음과 같다.

1. 어떤 업무 의사결정이나 행동을 개선하려는가?
2. 현재 성과와 목표 사이의 차이는 무엇인가?
3. 분석 결과를 누가 언제 어떤 방식으로 사용할 것인가?
4. 필요한 데이터는 존재하며 합법적·신뢰성 있게 사용할 수 있는가?
5. 시간·예산·인력·기술 제약 안에서 어떤 산출물을 만들 것인가?
6. 성공과 중단을 무엇으로 판단할 것인가?

분석 기획의 산출물은 상황에 따라 과제 정의서, 분석 질문, 가설, 성과지표, 데이터 요구사항, 수행 범위, 일정·역할, 위험·검증 계획, 결과 활용 방안 등이 된다. 형식보다 중요한 것은 각 항목이 서로 연결되는가이다.

```text
조직 목표
   ↓
업무 문제와 의사결정
   ↓
분석 질문·가설
   ↓
데이터·방법·검증 계획
   ↓
분석 결과
   ↓
업무 행동과 성과 측정
```

분석 정확도가 높아도 결과를 사용할 프로세스가 없으면 가치가 생기지 않는다. 반대로 업무 효과를 강조하더라도 데이터로 답할 수 없는 질문이면 실행 가능성이 낮다. 기획은 가치와 실행 가능성을 동시에 맞추는 작업이다.

## 2. 분석 기획과 유사 활동의 구분

| 활동 | 중심 질문 | 대표 결과 |
|---|---|---|
| 전략 수립 | 조직이 어디로 갈 것인가 | 목표, 우선순위, 투자 방향 |
| 분석 기획 | 어떤 분석으로 어떤 결정을 개선할 것인가 | 과제·지표·데이터·실행 계획 |
| 분석 설계 | 과제를 어떤 자료와 기법으로 검증할 것인가 | 변수, 표본, 실험·모델 설계 |
| 분석 수행 | 실제 데이터를 어떻게 처리·모델링할 것인가 | 코드, 모델, 분석 결과 |
| 운영 전개 | 결과를 업무에 어떻게 적용·감시할 것인가 | 프로세스, 시스템, 운영지표 |

경계는 협업 과정에서 이어지지만 역할은 다르다. 기획 단계에서 특정 알고리즘의 세부 하이퍼파라미터까지 확정하려 하면 데이터 이해 전의 성급한 결정이 된다. 반대로 “AI로 매출 향상”만 적고 대상 의사결정과 검증 지표를 정하지 않으면 분석 과제로 보기 어렵다.

## 3. 좋은 분석 목표의 조건

### 3.1 업무 행동과 연결된다

“이탈을 분석한다”보다 “갱신 30일 전 고객 중 상담 우선 대상을 선별해 유지 활동의 효율을 높인다”가 실행 가능하다. 분석 결과를 받을 주체, 행동 시점, 선택 가능한 조치를 명시한다.

### 3.2 측정 가능하다

모델 성능과 업무 성과를 구분한다. 예측 정확도나 재현율은 분석 품질 지표이고, 유지율·처리시간·비용 절감은 업무 효과 지표다. 둘 사이의 인과를 자동으로 가정하지 말고 현장 적용 시험으로 확인한다.

### 3.3 범위와 기준 시점이 분명하다

대상 고객, 제품, 지역, 기간, 제외 조건을 정한다. 과거 데이터를 학습에 쓰면서 미래 정보를 섞지 않도록 기준 시점을 정의한다. 성공 기준뿐 아니라 데이터 부족·법적 제약·효과 부재 때 중단하거나 재기획할 기준도 둔다.

### 3.4 가치와 비용을 함께 본다

가능한 총효과만 제시하지 말고 데이터 확보, 개발, 운영, 변화관리 비용과 잘못된 판단의 손실을 고려한다. 작은 모델 개선보다 업무 절차 단순화가 더 큰 가치를 낼 수 있다.

## 4. 목표 시점별 분석 기획

**`목표 시점별 분석 기획`**은 분석을 통해 가치를 얻으려는 시간 범위에 따라 접근을 달리하는 관점이다. 여기서는 전체 방향을 이해하고, 단기 과제와 장기 마스터 플랜의 세부 비교는 뒤의 전용 레슨에서 학습한다.

### 4.1 단기 목표

현재의 명확한 문제를 제한된 기간에 해결하는 과제 단위 접근이다. 예를 들어 다음 달 캠페인의 반응 가능 고객을 선별하거나 반복 보고서 작성 시간을 줄이는 과제가 해당한다. 빠른 성과와 학습이 장점이지만, 공통 데이터·인프라 없이 과제별 임시 처리를 반복하면 중복과 기술 부채가 쌓인다.

### 4.2 장기 목표

조직이 지속적으로 분석을 수행할 데이터, 기술, 인력, 거버넌스와 과제 포트폴리오를 단계적으로 구축하는 접근이다. 데이터 표준화, 통합 플랫폼, 분석 조직 역량, 모델 운영 체계 등이 포함될 수 있다. 방향성과 재사용성이 장점이지만, 현장 가치가 늦거나 환경 변화로 계획이 낡을 수 있다.

### 4.3 결합 원칙

장기 방향 안에서 단기 과제를 선택하고, 단기 과제에서 얻은 데이터 품질·효과·운영 교훈으로 장기 계획을 갱신한다.

```text
장기 목표와 원칙
      ↓ 우선순위 제공
단기 과제 실행 → 효과·장애·데이터 학습
      ↑                 │
      └──── 장기 계획 보정 ────┘
```

시험에서 “단기는 전술적이므로 장기 계획과 무관하다”, “마스터 플랜은 한 번 만들면 고정한다”는 진술은 적절하지 않다.

## 5. 분석 주제와 방법의 조합

**`분석 주제와 방법의 조합`**은 분석하려는 대상이 알려졌는지, 해결 방법이 알려졌는지를 두 축으로 놓고 기획의 불확실성을 판단하는 틀이다. 조합의 세부 유형인 최적화·솔루션·통찰·발견은 다음 레슨에서 집중적으로 다룬다.

| 분석 주제 | 분석 방법 | 기획의 중심 |
|---|---|---|
| 알려짐 | 알려짐 | 성능·비용·절차 개선과 적용 범위 확정 |
| 알려짐 | 불명확 | 여러 방법 후보 탐색과 검증 설계 |
| 불명확 | 알려짐 | 보유 방법으로 의미 있는 패턴·질문 탐색 |
| 불명확 | 불명확 | 탐색 범위·학습 기준·중단 기준 설정 |

“알려졌다”는 말은 절대적이지 않다. 업무 담당자는 문제를 안다고 생각하지만 분석 가능한 변수와 목표 정의가 불명확할 수 있다. 방법도 알고리즘 이름을 들어 봤다는 것과 데이터·제약에 맞는 검증된 절차가 있다는 것은 다르다. 기획 회의에서 근거를 통해 두 축을 판정한다.

분석 주제와 방법이 모두 불명확한 경우에도 무제한 탐색을 허용하지 않는다. 탐색 기간, 사용할 데이터, 유망함을 판단할 신호, 다음 의사결정과 중단 조건을 정한다. 불확실성이 클수록 작은 실험과 단계별 승인이 중요하다.

## 6. 분석 기획의 판단 절차

### 단계 1: 업무 맥락을 확인한다

조직 목표, 고객·규제·시장 변화, 현재 프로세스와 성과를 확인한다. 요청자가 말한 현상을 그대로 문제로 확정하지 않는다. “매출 하락”은 결과이며 고객 감소, 전환율, 단가, 공급 제한 등 원인이 다를 수 있다.

### 단계 2: 의사결정과 이해관계자를 식별한다

분석 결과로 바뀔 결정, 결정권자, 실제 사용자, 영향을 받는 집단을 적는다. 결과 사용 시점이 실시간인지 월별인지에 따라 필요한 데이터와 시스템이 달라진다.

### 단계 3: 분석 질문과 성공 기준을 정의한다

설명, 진단, 예측, 추천 중 원하는 답의 성격을 구분하고 검증 가능한 질문으로 바꾼다. 모델 지표, 업무 지표, 공정성·안전 제약과 기준 시점을 정한다.

### 단계 4: 주제·방법 불확실성을 판정한다

대상 변수가 명확한지, 해결 방법이 조직에서 검증됐는지 근거를 확인한다. 불확실성에 맞춰 비교 실험·탐색·전문가 협업의 크기를 정한다.

### 단계 5: 가용 데이터와 실행 제약을 조사한다

데이터의 존재, 접근권한, 기간, 품질, 대표성, 결합키, 개인정보·활용 목적을 확인한다. 필요한 결과 시점, 인력, 도구, 운영 환경도 검토한다. 아직 보지 않은 데이터를 “충분하다”고 가정하지 않는다.

### 단계 6: 과제 범위와 계획을 승인한다

포함·제외 범위, 산출물, 역할, 일정, 의존성, 위험, 검토 지점을 기록한다. 초기 데이터 탐색 결과에 따라 범위를 조정할 변경 절차도 둔다.

### 단계 7: 활용과 사후 측정을 설계한다

결과 전달 방식, 인간 검토, 업무 적용 시험, 모니터링, 재학습·중단 조건을 정한다. 보고서 작성으로 과제를 끝내지 않는다.

## 7. 사례: 고객 문의 처리시간 개선

경영진이 “AI로 상담을 자동화해 처리시간을 30% 줄이라”고 요청했다.

1. 현재 처리시간을 접수·대기·상담·후처리로 분해한다.
2. 의사결정은 자동 답변 도입 여부가 아니라 문의를 적절한 담당에게 우선 배정하는 것으로 좁힌다.
3. 분석 질문을 “접수 시점 정보로 문의 유형과 긴급도를 분류할 수 있는가”로 정의한다.
4. 업무 목표는 평균뿐 아니라 상위 지연, 재문의율, 오분류 손실을 포함한다.
5. 과거 문의 텍스트·처리 이력의 접근권한, 개인정보, 분류 라벨 일관성을 확인한다.
6. 주제는 알려졌지만 검증된 방법은 불명확하므로 여러 기준모델과 운영 규칙을 비교한다.
7. 6주 단기 실험으로 효과를 확인하되 장기적으로 분류체계와 데이터 수집 개선에 연결한다.

처리시간 감소만 최적화하면 어려운 문의를 조기에 종료해 재문의가 늘 수 있다. 따라서 속도, 해결률, 고객 피해와 상담원 부담을 함께 본다.

### 기획 검토 회의에서 확인할 판단표

| 검토 질문 | 충분한 근거 | 보완이 필요한 신호 |
|---|---|---|
| 문제인가, 수단인가 | 개선할 결정·행동이 명시됨 | “AI·대시보드 도입”만 제시 |
| 시점이 명확한가 | 기준 시점과 결과 사용 시점이 있음 | 현재 DB의 모든 값을 사용 |
| 가치가 측정되는가 | 기준선·업무 지표·비용이 있음 | 모델 정확도 목표만 있음 |
| 데이터가 가능한가 | 권한·품질·대표성 표본 확인 | 시스템에 있다는 설명뿐 |
| 불확실성을 관리하는가 | 주제·방법 가정과 실험 관문이 있음 | 성공 수치를 사전 확정 |
| 결과가 사용되는가 | 사용자·업무 흐름·감시 책임이 있음 | 보고서 전달로 종료 |

검토 결과는 승인과 반려만 있는 것이 아니다. 질문은 가치 있지만 목표값이 불안정하면 라벨 정의·수집을 선행 과제로 둘 수 있다. 데이터는 충분하지만 업무 행동이 없으면 활용 프로세스를 먼저 설계한다. 작은 실험으로 핵심 가정을 검증할 수 있으면 조건부 승인하고, 권한이나 안전 문제가 통제되지 않으면 기대 성과가 커도 중단한다. 이러한 결정과 가정의 소유자·재검토 날짜를 남겨야 이후 결과가 달라졌을 때 합리적으로 재기획할 수 있다.

## 8. 기획 산출물 체크리스트

- [ ] 분석 요청이 아니라 실제 업무 문제와 의사결정을 적었다.
- [ ] 사용자·결정권자·영향 집단과 결과 사용 시점이 명확하다.
- [ ] 분석 질문, 기준 시점, 대상·제외 범위가 검증 가능하다.
- [ ] 분석 성능과 업무 성과 지표를 구분했다.
- [ ] 주제와 방법의 알려짐·불명확함을 근거로 판정했다.
- [ ] 단기 성과와 장기 데이터·역량 방향을 연결했다.
- [ ] 데이터 존재·품질·권한·대표성을 실제로 확인했다.
- [ ] 비용·일정·인력·규제·운영 장애와 중단 기준이 있다.
- [ ] 결과의 업무 적용, 인간 검토, 모니터링 계획이 있다.
- [ ] 가정과 변경 이력을 남겨 재기획할 수 있다.

## 9. 자주 틀리는 시험 함정

1. 분석 기획을 분석 기법이나 도구 선정과 동일시한다.
2. “AI 활용”을 구체적인 분석 목표라고 본다.
3. 모델 정확도 상승을 업무 가치 실현과 같다고 판단한다.
4. 단기 과제는 장기 인프라·거버넌스와 무관하다고 본다.
5. 장기 마스터 플랜은 환경이 바뀌어도 고정해야 한다고 본다.
6. 분석 대상이나 방법의 “알려짐”을 담당자의 확신만으로 판정한다.
7. 주제와 방법이 불명확하면 기획 없이 자유 탐색한다고 본다.
8. 데이터가 시스템에 존재하면 분석에 사용할 권한·품질도 충족한다고 본다.
9. 보고서 전달을 분석 활용의 완료로 본다.
10. 성공 기준만 두고 중단·원복·재기획 기준을 생략한다.

“고객 이탈을 분석한다”를 실행 가능한 분석 목표로 바꿀 때 추가할 요소는 무엇인가?

### 문제 3

## 11. 정답과 해설

### 문제 1 정답과 해설

분석 기획은 조직 목표를 위해 분석 과제를 발굴·정의하고 수행·활용 계획을 세우는 활동이다. 과제 정의서, 분석 질문·가설, 성과지표, 데이터 요구, 일정·역할·위험 계획 등이 산출물이다.

### 문제 2 정답과 해설

대상 고객과 기준 시점, 결과를 사용할 주체·행동, 예측 또는 진단 질문, 모델·업무 성공 기준, 제외 범위와 제약을 추가해야 한다.

### 문제 3 정답과 해설

이탈 예측 재현율은 모델이 이탈자를 얼마나 찾는지 나타내는 분석 지표다. 실제 유지율 증가와 연락 비용 감소는 현장 적용 결과인 업무 지표다. 전자가 좋아도 잘못된 캠페인이면 후자는 나빠질 수 있다.

### 문제 4 정답과 해설

장기 계획이 공통 데이터·역량과 과제 우선순위를 제공하고, 단기 과제가 빠른 가치와 실제 장애에 대한 학습을 만든다. 단기 결과로 장기 계획을 주기적으로 보정한다.

### 문제 5 정답과 해설

분석하려는 주제가 알려졌는지와 해결 방법이 알려졌는지이다. 알고리즘 이름을 안다는 사실보다 해당 문제·데이터에서 검증된 방법인지가 중요하다.

### 문제 6 정답과 해설

탐색 범위·기간·데이터·유망 신호·중단 기준이 없으면 비용만 커지고 선택 편향이 생긴다. 작은 실험과 단계별 검토로 불확실성을 줄여야 한다.

### 문제 7 정답과 해설

데이터 존재와 접근권한, 기간·양, 품질·결측, 대표성, 결합키, 갱신 주기, 개인정보와 활용 목적 적합성을 확인한다.

### 문제 8 정답과 해설

어려운 문의를 조기 종료하면 평균은 줄지만 해결률이 낮아지고 재문의·고객 피해가 늘 수 있다. 상위 지연, 해결률, 오분류 비용과 상담원 부담을 함께 측정해야 한다.

### 문제 9 정답과 해설

업무 맥락 확인 → 의사결정·이해관계자 식별 → 분석 질문·성공 기준 정의 → 주제·방법 불확실성 판정 → 데이터·제약 검토 → 범위·일정·역할 승인 → 활용·사후 측정 설계 순이다.

## 12. 핵심 요약

- **`분석 기획의 정의`**는 조직 목표를 분석 가능한 과제로 바꾸고 데이터·방법·수행·활용·검증 계획을 세우는 것이다.
- 좋은 분석 목표는 업무 의사결정, 기준 시점, 측정 가능한 분석·업무 지표, 범위와 중단 기준을 포함한다.
- **`목표 시점별 분석 기획`**은 단기 과제의 빠른 가치와 장기 마스터 플랜의 공통 역량을 연결하고 반복 보정하는 관점이다.
- **`분석 주제와 방법의 조합`**은 대상과 방법의 알려짐 여부로 불확실성을 판정해 최적화·방법 탐색·주제 탐색·발견형 접근의 크기를 정한다.
- 분석 기획의 최종 기준은 모델을 만드는가가 아니라 신뢰 가능한 데이터로 실제 의사결정을 개선하고 그 효과와 위험을 측정할 수 있는가이다.
