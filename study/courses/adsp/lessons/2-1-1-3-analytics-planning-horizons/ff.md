# 2-1-1-3. 목표 시점별 분석 기획

> **학습 범위**: 이 레슨은 ADsP `데이터분석 기획 > 데이터분석 기획의 이해 > 분석 기획 방향성 도출` 중 **`과제 단위의 단기 접근`**, **`마스터 플랜 단위의 장기 접근`**, **`분석 기획 고려사항`**을 다룬다. 빠르게 현안 가치를 검증하는 단기 과제와 조직의 분석 역량·과제 포트폴리오를 구축하는 장기 계획을 구분하고 연결하는 것이 목표다.

목표 시점은 단순히 일정 길이를 뜻하지 않는다. 단기 접근은 하나의 업무 문제와 산출물의 완료에 초점을 두고, 장기 접근은 여러 과제와 공통 데이터·기술·인력·거버넌스를 단계적으로 구축하는 데 초점을 둔다. 시험에서는 둘을 상호 배타적으로 보거나 장기 계획을 고정 문서로 표현하는 선택지를 경계해야 한다.

---

## 1. 목표 시점이 기획에 미치는 영향

분석 기획자는 “언제까지 무엇을 의사결정할 수 있어야 하는가”를 먼저 확인한다. 다음 주 판촉 대상 선정과 3년간 전사 분석 체계 구축은 같은 방식으로 계획할 수 없다.

| 구분 | 과제 단위 단기 접근 | 마스터 플랜 단위 장기 접근 |
|---|---|---|
| 중심 | 구체적인 현안과 결과 | 조직의 방향·역량·과제 포트폴리오 |
| 시간 | 제한된 수행·적용 기간 | 단계적 로드맵과 반복 갱신 |
| 범위 | 한 업무·부서·의사결정 | 여러 업무와 공통 기반 |
| 성과 | 과제 지표와 빠른 업무 효과 | 재사용성, 성숙도, 지속 가치 |
| 위험 | 임시 데이터·중복 구축 | 과대 설계·가치 지연 |
| 보완 | 공통 원칙에 맞춰 수행 | 단기 성과와 학습으로 수정 |

“단기=간단한 분석”, “장기=복잡한 모델”은 잘못된 대응이다. 복잡한 사기 탐지 긴급 개선도 단기 과제가 될 수 있고, 기본 데이터 품질 표준화는 장기 계획이 될 수 있다.

## 2. 과제 단위의 단기 접근

**`과제 단위의 단기 접근`**은 명확한 업무 문제를 제한된 기간과 자원으로 해결하고 결과를 적용·평가하는 방식이다.

### 2.1 적합한 상황

- 의사결정 시한이 명확하고 늦으면 가치가 사라진다.
- 문제·대상·사용자가 비교적 구체적이다.
- 작은 범위에서 데이터와 효과를 확인할 수 있다.
- 규제·안전 위험을 통제한 시험이 가능하다.
- 장기 투자를 결정하기 전에 실증 근거가 필요하다.

예를 들어 다음 분기 갱신 고객의 상담 우선순위를 정하는 과제는 결과 사용 시점이 명확하다. 과거 갱신·상담 데이터를 점검하고 6주 동안 기준모델과 현장 시험을 수행할 수 있다.

### 2.2 단기 과제의 구성

```text
현안·의사결정
  → 분석 질문과 범위
  → 최소 필요 데이터
  → 기준선과 검증 방법
  → 제한된 분석·시험
  → 업무 적용과 효과 측정
  → 종료·확대·재기획 판단
```

단기 과제 정의서에는 대상·기준 시점, 분석 결과를 사용할 사람, 비교 기준, 최소 산출물, 일정·역할, 데이터 접근, 위험과 중단 조건을 둔다. “일단 모델을 만든 후 활용을 찾는다”는 순서는 피한다.

### 2.3 빠름과 성급함의 차이

빠른 접근은 검증을 생략한다는 뜻이 아니다. 범위를 줄이고 우선순위를 명확히 해 학습 주기를 짧게 하는 것이다. 작은 표본 탐색 → 기준모델 → 제한 사용자 시험처럼 단계별 증거를 만든다.

성급한 접근의 신호는 다음과 같다.

- 데이터 권한·대표성 확인 전 성공 수치를 약속한다.
- 검증 데이터에 맞춰 반복 조정하면서 독립 평가를 하지 않는다.
- 임시 수작업을 운영 체계로 간주한다.
- 모델 지표만 측정하고 현장 행동·효과를 보지 않는다.
- 종료 뒤 데이터·코드·결과를 재사용할 형태로 남기지 않는다.

### 2.4 단기 과제 종료 판단

성공이면 운영 전개 또는 범위 확대를 결정한다. 가치가 있지만 데이터가 부족하면 수집 개선을 장기 계획에 반영한다. 효과가 없으면 가설·범위·방법 중 무엇이 틀렸는지 기록하고 종료할 수 있다. 매몰비용 때문에 무조건 확대하지 않는다.

## 3. 마스터 플랜 단위의 장기 접근

**`마스터 플랜 단위의 장기 접근`**은 조직 전략과 연계해 분석 과제, 공통 데이터·플랫폼, 인력·조직, 거버넌스와 변화관리를 단계적으로 설계하는 방식이다.

### 3.1 마스터 플랜의 구성

1. **비전과 원칙**: 분석이 어떤 전략적 의사결정을 개선할지 정의한다.
2. **현황 진단**: 데이터, 시스템, 인력, 문화, 관리 체계의 성숙도를 본다.
3. **과제 포트폴리오**: 후보 과제를 가치·실행 가능성·시급성·의존성으로 평가한다.
4. **공통 역량**: 데이터 표준, 품질, 플랫폼, 보안, 모델 운영, 교육을 계획한다.
5. **단계적 로드맵**: 선행 조건과 빠른 성과를 고려해 순서·마일스톤을 정한다.
6. **투자·책임**: 예산, 데이터 소유자, 실행 조직, 의사결정 구조를 정한다.
7. **성과·갱신**: 단계별 지표와 재검토 주기를 둔다.

장기 계획의 핵심은 모든 미래 과제를 상세히 확정하는 것이 아니다. 변화에도 유지할 원칙과 공통 기반, 현재 근거로 우선순위를 정하고, 단기 실행 결과로 다음 단계를 조정하는 것이다.

### 3.2 과제 포트폴리오

후보 과제를 하나의 점수만으로 줄 세우지 않는다.

| 평가 관점 | 질문 |
|---|---|
| 전략 가치 | 핵심 목표와 의사결정을 개선하는가 |
| 업무 효과 | 수익·비용·위험·고객 경험 변화가 측정되는가 |
| 데이터 준비 | 필요한 기간·품질·권한의 데이터가 있는가 |
| 기술 실행 | 방법·인프라·운영 통합이 가능한가 |
| 조직 수용 | 사용 부서·책임자·프로세스 변경이 준비됐는가 |
| 의존성 | 선행 데이터·제도·시스템이 무엇인가 |
| 위험 | 개인정보·공정성·안전·평판 위험이 통제되는가 |

높은 가치·높은 난도의 과제는 선행 기반을 먼저 만들 수 있다. 낮은 가치지만 쉬운 과제만 반복하면 전략적 성과가 부족하고, 높은 가치만 보고 실행 불가능한 과제를 먼저 선택하면 신뢰를 잃는다.

### 3.3 단계적 로드맵

```text
1단계: 데이터 정의·책임·접근의 최소 기반
  ├─ 빠른 효과 과제 A
  └─ 데이터 품질 개선
2단계: 공통 분석 환경과 재사용 자산
  ├─ 과제 B 확장
  └─ 운영 감시 체계
3단계: 여러 업무로 확산·자동화
  └─ 성과와 위험에 따라 재우선순위
```

로드맵은 날짜 목록이 아니라 선행관계와 의사결정 관문을 포함한다. 1단계 효과가 없거나 규제가 바뀌면 2단계 범위를 수정할 수 있어야 한다.

## 4. 단기와 장기의 연결

### 4.1 장기가 단기에 제공하는 것

- 공통 고객·상품 정의와 데이터 품질 원칙
- 승인된 기술·보안·개인정보 기준
- 중복 투자를 막는 플랫폼·재사용 계획
- 과제 우선순위와 성과 측정 방향
- 결과를 운영·확산할 조직 책임

### 4.2 단기가 장기에 제공하는 것

- 실제 데이터 품질과 접근 장애
- 사용자 행동과 업무 효과의 증거
- 필요한 역량·인프라의 구체적 요구
- 예상 비용과 운영 위험
- 중단할 가정과 새 과제 후보

단기 실증을 장기 계획의 “홍보 사례”로만 쓰지 않는다. 실패와 제약도 투자 순서를 개선하는 중요한 학습이다.

## 5. 분석 기획 고려사항

**`분석 기획 고려사항`**은 흔히 가용 데이터, 적절한 활용 시나리오, 실행 장애의 세 관점으로 정리할 수 있다. 용어를 외우기보다 실제 점검 질문에 적용한다.

### 5.1 가용 데이터

데이터가 존재하는지만 보지 않는다.

- 기간·건수·세분성은 분석 질문에 충분한가?
- 목표 시점 전에 사용할 수 있는 값인가?
- 결측·오류·중복·정의 변경을 추적할 수 있는가?
- 대상 모집단을 대표하는가?
- 결합 키와 이력이 안정적인가?
- 접근·결합·보존에 법적·계약상 권한이 있는가?
- 향후 운영에서도 같은 품질과 주기로 들어오는가?

과거 결과 뒤에 생성된 값을 예측 입력으로 쓰면 데이터 누수가 된다. 현재 DB에 있다는 사실보다 의사결정 시점에 이용 가능했는지를 확인한다.

### 5.2 적절한 활용 시나리오

분석 결과가 어느 업무에서 누가 언제 사용되는지 정의한다. 점수나 군집을 만든 뒤 사용처를 찾는 것이 아니라, 가능한 행동과 제약에서 필요한 결과를 역으로 설계한다.

```text
결과 사용자: 갱신 상담 관리자
사용 시점: 갱신 30일 전 주간 배정
분석 출력: 위험 등급 + 주요 근거 + 최신 시각
가능 행동: 상담 우선 배정, 정보 확인
금지 행동: 자동 계약 거절
성과 측정: 유지율, 상담비용, 불만·오류 집단
```

사용자가 결과를 신뢰·이해할 수 있는지, 기존 시스템에 전달할 수 있는지, 행동할 자원과 권한이 있는지도 본다.

### 5.3 실행 장애 요소

기술만이 아니라 데이터 소유권, 부서 간 이해, 업무 절차, 규제, 예산, 인력, 기존 시스템, 사용자 저항, 설명·감사 요구가 장애가 된다. 장애를 프로젝트 말기에 발견하지 않도록 사전 계획을 세운다.

| 장애 | 조기 확인 | 대응 예시 |
|---|---|---|
| 데이터 접근 | 소유자·승인 기간 | 최소 데이터로 사전 승인 |
| 정의 불일치 | 부서별 지표 비교 | 공통 정의·책임자 합의 |
| 현장 수용 | 사용자 인터뷰·관찰 | 인간 검토와 단계적 시험 |
| 시스템 연계 | 인터페이스·지연 측정 | 배치 적용 또는 중간 계층 |
| 규제·공정성 | 목적·영향 검토 | 제외 변수만이 아닌 결과 감시 |

“장벽이 낮다”는 통제를 생략한다는 뜻이 아니라 실행을 막을 장애를 미리 식별·완화한다는 뜻이다.

## 6. 목표 시점 선택 절차

### 단계 1: 가치 실현 시한을 확인한다

결정이 필요한 날짜, 기대 효과가 유지되는 기간, 규제·계약 마감과 전략 투자 기간을 구분한다.

### 단계 2: 문제와 기반의 준비도를 진단한다

문제 정의·데이터·사용자·기술이 준비되었으면 단기 과제로 검증할 수 있다. 여러 과제가 같은 데이터 부족에 막히면 공통 기반을 장기 계획에 둔다.

### 단계 3: 단기 과제와 장기 역량을 함께 설계한다

단기 과제의 최소 범위와 장기 재사용 조건을 정한다. 장기 계획에는 단기 검증 관문과 취소·재우선순위 조건을 둔다.

### 단계 4: 데이터·활용·장애를 점검한다

가용 데이터, 활용 시나리오, 실행 장애를 증거로 평가하고 책임자와 완화 계획을 정한다.

### 단계 5: 검토 주기와 학습 전달을 정한다

단기 종료 시 어떤 교훈을 마스터 플랜에 반영할지, 장기 로드맵을 언제 다시 우선순위화할지 결정한다.

## 7. 사례: 제조 품질 분석 체계

회사는 다음 달 특정 라인의 불량 급증을 줄이는 동시에 2년 안에 전 공장 품질 분석 체계를 구축하려 한다.

- 단기: 대상 라인·제품·기간을 한정하고 검사·공정 데이터를 결합해 불량 원인 후보와 경보 기준을 검증한다.
- 장기: 설비·제품 코드 표준, 센서 품질, 데이터 보존, 공장별 책임자, 공통 플랫폼과 모델 감시를 단계화한다.
- 연결: 단기 과제에서 발견한 설비 시각 불일치와 작업 코드 오류를 장기 데이터 표준 1순위로 반영한다.
- 고려사항: 불량 라벨의 검사자 편차, 경보를 확인할 현장 인력, 공정 중단 권한, 센서 변경 시 재검증을 다룬다.

단기 모델 정확도가 높아도 현장 경보 대응 시간이 없으면 활용 시나리오가 부적절하다. 장기 플랫폼을 먼저 완성할 때까지 모든 과제를 미루는 것도 학습과 가치 실현을 늦춘다.

## 8. 산출물 체크리스트

- [ ] 가치 실현 시점과 의사결정 마감이 명확하다.
- [ ] 단기 과제의 대상·기간·산출물·종료 기준이 있다.
- [ ] 단기 임시 구현과 운영 가능한 자산을 구분했다.
- [ ] 장기 비전·현황·과제 포트폴리오·공통 역량이 연결된다.
- [ ] 로드맵에 선행관계·검토 관문·재우선순위 조건이 있다.
- [ ] 데이터 존재·품질·시점·권한·대표성을 확인했다.
- [ ] 분석 결과의 사용자·시점·행동·금지 행동을 정했다.
- [ ] 기술·조직·규제·시스템 장애와 책임자를 지정했다.
- [ ] 단기 성공·실패의 학습이 장기 계획으로 전달된다.
- [ ] 비용·효과·위험을 주기적으로 다시 평가한다.

## 9. 자주 틀리는 시험 함정

1. 단기 접근을 언제나 임시·저품질 분석이라고 본다.
2. 장기 접근을 단일 대형 시스템 구축과 동일시한다.
3. 단기 과제와 마스터 플랜을 상호 배타적으로 본다.
4. 마스터 플랜은 최초 승인 뒤 변경하지 않는다고 본다.
5. 쉬운 과제부터 모두 수행하면 전략 우선순위가 자동 충족된다고 본다.
6. 데이터가 저장되어 있으면 가용 데이터 조건을 만족한다고 본다.
7. 높은 모델 성능이면 활용 시나리오가 없어도 가치가 생긴다고 본다.
8. 실행 장애를 기술 문제로만 한정한다.
9. 빠른 성과를 위해 데이터 권한·독립 검증을 생략한다.
10. 실패한 단기 과제는 장기 계획에 제공할 가치가 없다고 본다.

단기·장기 목표 시점을 선택하고 연결하는 절차를 요약하시오.

## 11. 정답과 해설

### 문제 1 정답과 해설

단기는 하나의 현안·의사결정을 제한된 기간에 해결하고 효과를 확인한다. 장기는 여러 과제와 데이터·기술·인력·거버넌스 공통 역량을 단계적으로 구축한다.

### 문제 2 정답과 해설

빠른 접근은 범위를 줄이되 권한·기준선·독립 검증·효과 측정을 유지한다. 성급함은 데이터와 위험 확인, 검증, 운영·종료 계획을 생략하는 것이다.

### 문제 3 정답과 해설

분석 비전·원칙, 현황·성숙도 진단, 과제 포트폴리오, 공통 데이터·플랫폼·인력·거버넌스, 단계적 로드맵, 투자·책임, 성과·갱신 계획을 들 수 있다.

### 문제 4 정답과 해설

쉬워도 가치가 낮을 수 있고, 어렵지만 전략 가치가 크면 선행 기반을 구축할 필요가 있다. 가치, 데이터·기술 준비, 조직 수용, 의존성·위험을 함께 봐야 한다.

### 문제 5 정답과 해설

장기는 공통 데이터·보안 원칙과 우선순위를 제공한다. 단기는 실제 품질·효과·장애와 필요한 역량에 대한 증거를 제공해 장기 계획을 보정한다.

### 문제 6 정답과 해설

예측이나 의사결정 뒤에 생성된 값은 현재 DB에 있어도 당시 사용할 수 없었다. 이를 입력에 쓰면 미래 정보가 누수되어 실제보다 좋은 결과가 나온다.

### 문제 7 정답과 해설

결과 사용자, 사용 시점, 출력 형태, 가능한 행동·금지 행동, 기존 시스템 전달 방식, 업무 성과·부작용 지표를 포함한다.

### 문제 8 정답과 해설

부서 간 데이터 소유권에는 책임자·승인 합의, 사용자 저항에는 참여형 설계·단계 시험, 규제·공정성에는 사전 영향 검토와 결과 감시를 둘 수 있다.

### 문제 9 정답과 해설

가치 시한 확인 → 문제·기반 준비도 진단 → 단기 최소 과제와 장기 공통 역량 설계 → 데이터·활용·장애 점검 → 검토 주기와 학습 전달 확정 순이다.

## 12. 핵심 요약

- **`과제 단위의 단기 접근`**은 구체적 문제를 제한된 범위에서 빠르게 검증·적용하되 데이터 권한, 기준선, 효과 측정과 종료 기준을 지키는 방식이다.
- **`마스터 플랜 단위의 장기 접근`**은 전략과 연계한 과제 포트폴리오, 공통 데이터·기술·인력·거버넌스를 단계적 로드맵으로 구축·갱신하는 방식이다.
- 장기 계획은 단기 과제에 원칙과 기반을 제공하고, 단기 과제는 실제 효과·장애·데이터 학습으로 장기 계획을 보정한다.
- **`분석 기획 고려사항`**은 가용 데이터, 적절한 활용 시나리오, 실행 장애를 실제 증거로 점검하는 것이다.
- 목표 시점의 선택은 일정 길이보다 가치 실현 시한, 문제·데이터 준비도, 공통 기반 의존성과 학습 전달 구조로 판단한다.
