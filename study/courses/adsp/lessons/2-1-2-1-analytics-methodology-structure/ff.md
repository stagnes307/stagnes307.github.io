# 2-1-2-1. 분석 방법론의 구조

> **학습 범위**: 이 레슨은 ADsP `데이터분석 기획 > 데이터분석 기획의 이해 > 분석 방법론` 중 **`방법론의 필요성`**, **`계층적 프로세스 모델`**, **`단계·태스크·스텝의 관계`**를 다룬다. 분석을 개인 경험에만 의존하지 않고 반복·검토 가능한 체계로 수행하기 위해 방법론이 필요한 이유와 Phase–Task–Step 계층을 정확히 구분하는 것이 목표다.

KDD, CRISP-DM, 빅데이터 분석 방법론의 고유 단계는 뒤 레슨에서 다룬다. 여기서는 서로 다른 방법론을 읽고 적용할 수 있는 공통 구조에 집중한다. 시험에서는 단계·태스크·스텝의 크기와 산출물을 바꾸거나, 방법론을 고정된 일방향 절차로만 설명하는 선택지를 주의해야 한다.

---

## 1. 방법론의 필요성

**`방법론의 필요성`**은 분석 품질을 특정 분석가의 감각과 기억에만 맡기지 않고, 조직이 합의한 절차·역할·산출물·검토 기준으로 관리하기 위해서다.

분석은 데이터 이해, 품질 처리, 모델 선택, 평가, 업무 적용이 서로 영향을 준다. 탐색 과정에서 목표가 잘못 정의됐음을 발견하거나 모델 평가에서 데이터 누수를 찾아 준비 단계로 돌아갈 수 있다. 체계가 없으면 이런 되돌림이 학습인지 임의 시행착오인지 구분하기 어렵다.

### 1.1 재현성과 일관성

같은 입력과 조건에서 누가 수행해도 주요 판단과 결과를 추적할 수 있게 한다. 모든 분석가가 똑같은 모델을 만들어야 한다는 뜻이 아니라, 데이터·가정·검증·변경 이유를 확인할 수 있어야 한다.

### 1.2 누락 방지

모델링에 집중하다 업무 목표, 개인정보, 데이터 품질, 배포·모니터링을 빼먹는 일을 줄인다. 단계별 필수 산출물과 검토 관문이 체크리스트 역할을 한다.

### 1.3 의사소통과 책임

업무 담당자, 데이터 소유자, 분석가, 개발·운영·검토자가 같은 용어와 진행 상태를 공유한다. 어느 결과를 누가 작성·검토·승인하는지 명확해진다.

### 1.4 품질과 위험 통제

독립 검증, 데이터 누수 점검, 편향·보안·법적 검토, 변경 관리와 중단 기준을 과정 안에 배치한다. 최종 정확도 하나만으로 승인하는 위험을 줄인다.

### 1.5 자산 재사용과 개선

데이터 정의, 코드, 특징, 시험, 운영 교훈을 재사용할 수 있다. 프로젝트 회고로 불필요한 단계는 줄이고 반복 장애에 대한 통제를 보강해 조직 방법론을 개선한다.

| 방법론이 없는 신호 | 발생 위험 | 방법론의 대응 |
|---|---|---|
| 분석가마다 시작점이 다름 | 범위·품질 편차 | 공통 단계와 진입 조건 |
| 모델 성능만 보고 완료 | 업무 가치·운영 누락 | 평가·전개 관문 |
| 데이터 변경 근거 없음 | 재현 실패 | 산출물·버전 추적 |
| 질문 때마다 구두 설명 | 책임·인수인계 불명확 | 역할·검토·승인 기록 |
| 실패 원인을 남기지 않음 | 같은 시행착오 반복 | 회고와 방법론 개선 |

## 2. 방법론은 무엇을 제공하는가

방법론은 일반적으로 다음 요소를 연결한다.

- **원칙**: 가치, 객관성, 재현성, 보안 등 지켜야 할 기준
- **프로세스**: 분석을 진행하는 큰 흐름과 반복 관계
- **활동**: 각 구간에서 수행할 업무
- **산출물**: 판단과 결과를 남기는 문서·데이터·코드·모델
- **역할**: 작성, 검토, 승인, 운영 책임
- **기법·도구**: 활동을 수행하는 선택 가능한 수단
- **관문**: 다음 단계 진행·보완·중단을 판단하는 기준

방법론과 도구는 다르다. 노트북, SQL, 시각화 제품, 모델 라이브러리는 활동을 돕는 도구다. 도구를 설치했다고 업무 이해·데이터 검증·전개 절차가 생기지는 않는다. 방법론과 방법도 구분한다. 방법론은 전체 수행 체계이고, 회귀분석이나 군집분석은 특정 문제에 쓰는 분석 방법이다.

## 3. 계층적 프로세스 모델

**`계층적 프로세스 모델`**은 복잡한 분석 과정을 큰 목적에서 실행 행동까지 여러 수준으로 나누는 구조다. ADsP에서는 보통 단계(Phase), 태스크(Task), 스텝(Step)의 세 계층으로 설명한다.

```text
방법론
  ├─ 단계 Phase A
  │    ├─ 태스크 Task A-1
  │    │    ├─ 스텝 Step A-1-a
  │    │    └─ 스텝 Step A-1-b
  │    └─ 태스크 Task A-2
  └─ 단계 Phase B
       └─ 태스크 Task B-1
            └─ 스텝 Step B-1-a
```

계층화의 장점은 경영진에게는 단계 수준의 진행·투자를, 프로젝트 관리자에게는 태스크의 일정·책임·산출물을, 수행자에게는 스텝의 구체 작업과 도구를 보여 줄 수 있다는 것이다.

### 3.1 단계(Phase)

단계는 방법론의 생명주기를 구성하는 가장 큰 논리 구간이다. 서로 다른 목적과 주요 산출물을 가지며 프로젝트 상태를 경영·관리 수준에서 구분한다. 예를 들면 기획, 데이터 준비, 분석, 평가·전개 같은 범주다.

단계 종료에는 다음을 확인할 수 있다.

- 단계 목표가 충족되었는가?
- 필수 태스크와 산출물이 완료됐는가?
- 위험과 미해결 사항이 허용 범위인가?
- 다음 단계로 진행, 이전 단계로 회귀, 중단 중 무엇을 선택할 것인가?

### 3.2 태스크(Task)

태스크는 단계 목표를 달성하기 위한 논리적 활동 묶음이다. 명확한 입력·출력, 책임자, 품질 기준을 두며 프로젝트 관리의 작업 단위가 된다. “데이터 품질 확인”, “모델 평가”, “배포 계획 수립”처럼 목적이 있는 활동이다.

태스크는 단지 해야 할 일 제목이 아니다. 완료 조건과 산출물이 있어야 한다. “데이터를 살펴봄”보다 “분석 변수의 결측·범위·중복 보고서와 처리 결정 승인”이 관리 가능하다.

### 3.3 스텝(Step)

스텝은 태스크를 실제로 수행하는 세부 절차다. 자료·기법·도구·담당자와 연결되는 실행 수준이며, 입력을 어떤 행동으로 처리해 어떤 출력으로 만드는지 설명한다.

예를 들어 데이터 품질 태스크는 다음 스텝을 가질 수 있다.

1. 변수 정의서와 원천 데이터 스키마를 비교한다.
2. 변수별 결측률·유일값·범위·분포를 계산한다.
3. 업무 규칙 위반과 이상 사례를 표본 확인한다.
4. 원인과 영향에 따라 수정·제외·보존을 결정한다.
5. 처리 전후 수치와 승인 근거를 기록한다.

실행 명령 하나가 반드시 스텝 하나인 것은 아니다. 스텝은 재현 가능한 의미 단위로 나눈다.

## 4. 단계·태스크·스텝의 관계

**`단계·태스크·스텝의 관계`**는 단순 포함 관계이면서 목표–활동–절차의 추적 관계다.

| 계층 | 핵심 질문 | 관리 범위 | 대표 산출물 |
|---|---|---|---|
| 단계 | 왜 이 구간을 수행하는가 | 생명주기 목적·관문 | 단계 계획, 승인 결과 |
| 태스크 | 무엇을 완료해야 하는가 | 논리 활동·책임 | 정의서, 보고서, 모델 |
| 스텝 | 어떻게 실행하는가 | 기법·도구·세부 행동 | 쿼리, 코드, 점검표, 실행 로그 |

위에서 아래로는 목표가 구체화되고, 아래에서 위로는 실행 증거가 모인다.

```text
단계 목표
  ↓ 분해
태스크 완료 조건
  ↓ 절차화
스텝 입력·행동·출력
  ↑ 실행 증거
태스크 산출물
  ↑ 검토·승인
단계 관문
```

스텝이 많이 수행됐다고 단계 목표가 자동 달성되는 것은 아니다. 수십 개 모델을 학습했어도 업무 목표와 독립 검증이 없으면 평가 단계의 완료 근거가 부족하다.

## 5. 반복과 회귀가 있는 구조

계층이 있다고 반드시 폭포수처럼 한 번만 내려가는 것은 아니다. 분석은 가설과 데이터 이해가 함께 발전하므로 반복이 자연스럽다.

### 5.1 반복의 예

- 데이터 이해 중 목표 변수가 잘못 정의되어 업무 이해로 돌아간다.
- 모델 평가에서 특정 기간 성능 저하를 발견해 데이터 준비를 보완한다.
- 전개 시험에서 응답 지연이 커 특징 계산과 모델을 단순화한다.

### 5.2 통제된 반복

반복 이유, 변경된 가정, 영향을 받는 산출물, 재검증 범위를 기록한다. 그냥 이전 코드를 덮어쓰면 어떤 시도가 왜 실패했는지 알 수 없다. 반복에는 종료 조건과 시간·비용 한도가 필요하다.

### 5.3 관문

관문은 승인만을 위한 형식이 아니다. 다음 네 결과를 선택할 수 있다.

1. 진행: 기준을 충족해 다음 단계로 간다.
2. 조건부 진행: 경미한 미해결 항목과 책임·기한을 남긴다.
3. 보완·회귀: 이전 태스크·단계의 입력을 수정한다.
4. 중단: 가치·실행 가능성·위험이 기준을 충족하지 못한다.

## 6. 방법론 적용 수준을 조정한다

방법론은 모든 프로젝트에 같은 문서 수와 기간을 강제하는 규정집이 아니다. 위험과 복잡도에 비례해 조정하되 핵심 통제는 보존한다.

| 상황 | 간소화 가능 | 유지해야 할 것 |
|---|---|---|
| 일회성 내부 탐색 | 문서 형식·회의 수 | 목적, 데이터 권한, 가정·결과 기록 |
| 반복 보고 자동화 | 모델 비교 절차 | 데이터 정의, 검증, 운영 책임 |
| 고위험 자동 의사결정 | 거의 없음 | 독립 검증, 공정성·안전, 승인·감시 |
| 연구형 발견 과제 | 고정 산출물 일부 | 탐색 범위, 선택 편향 통제, 중단 기준 |

간소화는 생략 근거와 책임자를 기록한다. 개인정보 검토나 검증 데이터 분리를 “민첩성”이라는 이유로 없애서는 안 된다.

## 7. 사례: 배송 지연 예측 프로젝트의 계층화

다음은 특정 방법론 이름을 쓰지 않고 공통 구조로 나눈 예다.

### 단계 A: 문제와 수행 계획

- 태스크 A-1: 지연 의사결정 정의
  - 스텝: 지연 기준 시점 합의
  - 스텝: 경고 사용 주체와 행동 확인
  - 산출물: 업무·분석 목표서
- 태스크 A-2: 타당성·위험 계획
  - 스텝: 데이터·권한·일정 확인
  - 산출물: 계획·위험표

### 단계 B: 데이터와 분석

- 태스크 B-1: 데이터 품질·준비
  - 스텝: 주문·차량·날씨의 시점과 결합키 검증
  - 산출물: 분석 데이터와 품질 보고서
- 태스크 B-2: 모델링·검증
  - 스텝: 시간 순서에 따른 학습·검증 분리
  - 스텝: 기준모델과 후보 비교
  - 산출물: 모델·평가 보고서

### 단계 C: 평가와 활용

- 태스크 C-1: 업무 평가
  - 스텝: 하루 경보 처리량과 지연 감소 시험
- 태스크 C-2: 운영 계획
  - 스텝: 감시·재학습·중단 조건 정의

각 스텝의 결과가 태스크 산출물로 집계되고, 태스크 완료가 단계 관문의 근거가 된다. 모델링 스텝에서 미래 날씨 확정값 사용을 발견하면 데이터 준비로 돌아가 시점을 수정한다.

## 8. 방법론 선택·적용 판단 절차

### 단계 1: 프로젝트 특성을 진단한다

업무 위험, 데이터 성숙도, 문제 확실성, 운영 통합, 규제, 팀 경험과 규모를 확인한다.

### 단계 2: 필요한 통제를 정한다

어떤 산출물과 독립 검증, 승인·감사, 반복 관문이 필수인지 정한다. 이름이 유명한 방법론보다 요구 통제와 맞는지가 중요하다.

### 단계 3: 계층을 프로젝트에 매핑한다

단계 목표, 태스크 책임·산출물, 스텝의 입력·도구·완료 기준을 정의한다. 하나의 업무를 여러 계층에 중복 배치하지 않는다.

### 단계 4: 반복·변경 계획을 둔다

어떤 결과에서 어디로 돌아갈지, 산출물 버전과 재검증 범위를 정한다.

### 단계 5: 회고로 개선한다

완료 후 누락·병목·과도한 문서·효과적인 검토를 기록해 조직 표준을 갱신한다.

## 9. 산출물 체크리스트

- [ ] 방법론 적용 목적과 프로젝트 위험을 정의했다.
- [ ] 단계별 목표·진입·종료·관문 기준이 있다.
- [ ] 태스크마다 입력·출력·책임자·완료 기준이 있다.
- [ ] 스텝이 재현 가능한 행동과 도구·증거로 표현됐다.
- [ ] 상위 목표와 하위 산출물이 추적된다.
- [ ] 업무·데이터·분석·운영 역할이 함께 참여한다.
- [ ] 회귀 이유와 변경된 산출물·재검증 범위를 기록한다.
- [ ] 간소화한 통제와 근거·승인자가 명확하다.
- [ ] 비밀·개인정보·편향·데이터 누수 검토가 포함됐다.
- [ ] 프로젝트 회고가 방법론 개선으로 연결된다.

## 10. 자주 틀리는 시험 함정

1. 방법론을 분석 알고리즘 모음으로 본다.
2. 도구를 도입하면 방법론이 자동 적용된다고 본다.
3. 단계보다 태스크가 더 큰 계층이라고 뒤집는다.
4. 스텝을 목적만 있고 실행 방법이 없는 큰 활동으로 본다.
5. 하위 작업 수가 많으면 상위 목표가 자동 완료된다고 본다.
6. 계층적 구조는 반드시 일방향 폭포수라고 판단한다.
7. 분석의 회귀를 모두 계획 실패라고 본다.
8. 민첩한 과제는 데이터 권한·검증·기록을 생략해도 된다고 본다.
9. 모든 프로젝트에 같은 문서·승인 강도를 적용한다.
10. 최종 모델만 보존하고 판단·실패·데이터 버전을 남기지 않는다.

## 11. 확인 문제

분석 방법론이 필요한 이유를 네 가지 쓰시오.

### 문제 2

분석 방법론과 분석 도구의 차이를 설명하시오.

### 문제 3

단계, 태스크, 스텝을 큰 순서대로 쓰고 각각의 핵심 질문을 제시하시오.

### 문제 5

### 문제 6

분석 방법론에서 반복과 회귀가 필요한 사례를 하나 쓰시오.

통제된 반복을 위해 기록할 항목을 쓰시오.

### 문제 8

### 문제 9

프로젝트에 방법론의 계층 구조를 적용하는 절차를 요약하시오.

## 12. 정답과 해설

### 문제 1 정답과 해설

재현성과 일관성, 필수 활동 누락 방지, 역할·의사소통 명확화, 품질·위험 통제, 산출물 재사용과 조직 학습을 위해 필요하다.

### 문제 2 정답과 해설

방법론은 원칙·프로세스·활동·산출물·역할·관문을 연결한 수행 체계다. 도구는 SQL, 노트북, 시각화 제품처럼 특정 스텝을 실행하도록 돕는 수단이다.

### 문제 3 정답과 해설

단계는 “왜 이 생명주기 구간을 수행하는가”, 태스크는 “무엇을 완료하는가”, 스텝은 “어떻게 실행하는가”에 답한다.

### 문제 4 정답과 해설

명확한 목적, 입력·출력, 책임자, 산출물과 품질·완료 기준이 있어야 일정과 검토를 관리할 수 있다.

### 문제 5 정답과 해설

스텝은 실행 증거일 뿐이다. 그 결과가 태스크 산출물로 통합되고 단계 목표·품질·위험 관문을 충족해야 상위 단계가 완료된다.

### 문제 6 정답과 해설

모델 평가에서 미래 정보를 사용한 데이터 누수를 발견하면 데이터 준비로 돌아가 변수 시점과 분할을 고치고 모델링·평가를 다시 수행해야 한다.

### 문제 7 정답과 해설

회귀 이유, 바뀐 가정·입력, 영향을 받는 산출물 버전, 책임자, 재검증 범위, 시간·비용 한도와 종료 기준을 기록한다.

### 문제 8 정답과 해설

분석 목적, 데이터 사용 권한, 가정·변환·결과 기록, 탐색·검증 분리, 개인정보·안전 검토와 중단 기준은 규모가 작아도 유지해야 한다.

### 문제 9 정답과 해설

프로젝트 위험·특성 진단 → 필수 통제 선택 → 단계 목표와 관문 정의 → 태스크의 책임·산출물 분해 → 스텝의 입력·행동·증거 구체화 → 반복·변경 관리 → 회고·표준 개선 순이다.

## 13. 핵심 요약

- **`방법론의 필요성`**은 분석을 개인 경험에만 맡기지 않고 재현성, 누락 방지, 협업, 품질·위험, 자산 재사용을 체계화하는 데 있다.
- **`계층적 프로세스 모델`**은 복잡한 분석을 단계(Phase)–태스크(Task)–스텝(Step)으로 분해해 서로 다른 관리 수준을 연결한다.
- **`단계·태스크·스텝의 관계`**는 목적–논리 활동–실행 절차의 포함·추적 관계이며 하위 증거가 상위 관문을 충족해야 한다.
- 분석 방법론은 고정된 일방향 절차가 아니라 근거 있는 반복·회귀를 허용하되 변경 이유와 재검증 범위를 관리한다.
- 프로젝트 위험에 맞게 산출물 형식은 조정할 수 있지만 데이터 권한, 독립 검증, 추적성, 안전과 중단 기준은 임의로 생략하지 않는다.
- 방법론의 품질은 문서 수가 아니라 상위 목표에서 하위 실행 증거까지 연결되고 다음 판단을 재현할 수 있는지로 평가한다.
