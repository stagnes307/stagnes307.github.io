# 2-1-2-2. KDD 분석 방법론

> **학습 범위**: 이 레슨은 ADsP `데이터분석 기획 > 데이터분석 기획의 이해 > 분석 방법론` 중 **`데이터 선택과 전처리`**, **`데이터 변환과 마이닝`**, **`결과 평가와 해석`**을 다룬다. KDD의 선택–전처리–변환–데이터 마이닝–해석·평가 흐름을 이해하고, 각 단계의 목적·입력·산출물과 반복 관계를 사례에 적용하는 것이 목표다.

KDD는 Knowledge Discovery in Databases, 즉 데이터베이스에서 유용한 지식을 발견하는 전체 과정이다. 데이터 마이닝은 그중 패턴·모델을 찾는 한 단계다. 시험에서 KDD와 데이터 마이닝을 동일시하거나 전처리와 변환의 순서를 바꾸는 선택지를 주의해야 한다.

---

## 1. KDD의 전체 구조

KDD는 대량 데이터에서 유효하고 새로우며 잠재적으로 유용하고 이해 가능한 패턴을 찾아 지식으로 해석하는 반복 과정이다.

```text
업무·도메인 이해
      ↓
데이터 선택 Selection
      ↓
전처리 Preprocessing
      ↓
변환 Transformation
      ↓
데이터 마이닝 Data Mining
      ↓
해석·평가 Interpretation/Evaluation
      ↺ 필요하면 이전 단계로 회귀
```

각 단계가 답하는 질문은 다음과 같다.

| 단계 | 핵심 질문 | 대표 산출물 |
|---|---|---|
| 선택 | 어떤 데이터가 질문과 모집단을 대표하는가 | 목표 데이터셋·추출 명세 |
| 전처리 | 오류·결측·중복·불일치를 어떻게 처리할까 | 품질 보고서·정제 데이터 |
| 변환 | 마이닝에 적합한 표현으로 어떻게 바꿀까 | 분석 변수·변환 파이프라인 |
| 마이닝 | 어떤 기법으로 패턴·모델을 찾을까 | 규칙·군집·모델·패턴 |
| 해석·평가 | 결과가 유효·유용·이해 가능한가 | 평가·시각화·지식·재작업 결정 |

KDD를 선형 자동화로만 보면 안 된다. 평가에서 쓸모없는 패턴이 나오면 변수 변환이나 데이터 선택으로 돌아가고, 전처리에서 질문을 답할 기간이 부족함을 발견하면 범위를 다시 정의한다.

## 2. 데이터 선택과 전처리

## 2.1 데이터 선택

**`데이터 선택과 전처리`** 중 선택은 분석 목표와 도메인 지식에 따라 원천 데이터에서 필요한 대상·기간·변수·사건을 정해 목표 데이터셋을 만드는 단계다.

### 선택의 판단 기준

- 분석 단위는 고객, 거래, 상품, 세션 중 무엇인가?
- 기준 시점과 관찰·예측 기간은 어떻게 나뉘는가?
- 목표 모집단과 제외 대상은 무엇인가?
- 결과 변수와 후보 입력 변수는 언제 생성되는가?
- 여러 원천의 결합키와 시점 관계가 유효한가?
- 접근권한·활용 목적·보존 기간이 허용되는가?
- 선택된 표본이 실제 적용 대상을 대표하는가?

예를 들어 “다음 달 이탈 고객 예측”에서 해지 처리 뒤 기록되는 상담 종료 코드를 입력으로 고르면 미래 정보가 섞인다. 변수의 DB 저장 시각이 아니라 예측 기준 시점에 실제 이용 가능했는지 확인한다.

### 선택 편향

응답한 고객만 포함한 만족도 데이터, 생존한 계정만 남은 장기 거래 데이터처럼 선택 과정 자체가 결과와 관계되면 편향이 생긴다. 편리한 데이터가 아니라 목표 모집단을 대표하도록 추출 기준과 누락 집단을 기록한다.

### 목표 데이터셋 명세 예

```text
분석 단위: 고객 1명
기준 시점: 매월 마지막 날
관찰 기간: 기준 시점 이전 90일
예측 기간: 이후 30일
대상: 기준 시점에 유효한 일반 고객
제외: 시험 계정, 탈퇴 완료 계정
목표: 예측 기간 내 자발적 해지 여부
주요 원천: 계약, 이용, 상담, 청구
```

이 명세가 있어야 같은 고객이 여러 시점에 포함되는지, 학습·평가 분리와 변수 시점을 판단할 수 있다.

## 2.2 데이터 전처리

전처리는 선택한 데이터의 잡음, 결측, 중복, 이상, 불일치와 오류를 진단·처리하는 단계다. 값을 깨끗해 보이게 만드는 것이 아니라 오류 원인과 분석 영향에 맞춰 처리한다.

| 문제 | 먼저 확인할 것 | 처리 예시 |
|---|---|---|
| 결측 | 발생 원인·집단·시점 | 보존, 대치, 지시변수, 제외 |
| 이상값 | 오류인지 희귀한 실제 사건인지 | 원천 수정, 제한, 변환, 별도 분석 |
| 중복 | 동일 사건인지 반복 발생인지 | 키·시각·업무 규칙으로 판정 |
| 단위 불일치 | 원·천원, 초·분 등 메타정보 | 공통 단위 변환과 검증 |
| 코드 변화 | 시기별 분류체계 | 대응표와 유효기간 적용 |
| 라벨 오류 | 생성 절차·검토자 편차 | 표본 재검토, 규칙 보완 |

평균 대치가 항상 정답은 아니다. 결측이 특정 고객군이나 장애 시점에 집중되면 결측 자체가 정보일 수 있고 단순 대치가 관계를 왜곡한다. 이상값도 사기 거래 탐지에서는 핵심 대상일 수 있으므로 목적을 보고 결정한다.

전처리 통계량은 학습 데이터에서 추정해 검증·운영 데이터에 동일하게 적용한다. 전체 데이터의 평균·범주를 미리 사용하면 평가 정보가 학습에 누수될 수 있다.

## 3. 데이터 변환과 마이닝

## 3.1 데이터 변환

**`데이터 변환과 마이닝`** 중 변환은 정제된 데이터를 선택한 마이닝 기법이 학습하고 비교하기 적합한 표현으로 바꾸는 단계다.

대표 활동은 다음과 같다.

- 변수 선택과 차원 축소
- 범주형 값 인코딩
- 단위 맞춤과 표준화·정규화
- 로그·제곱근 등 분포 변환
- 날짜·거래에서 기간·빈도·최근성 변수 생성
- 문서에서 토큰·빈도·임베딩 등 표현 생성
- 여러 행을 분석 단위로 집계
- 학습·검증·평가 데이터 분리와 변환 파이프라인 고정

전처리와 변환은 이어지지만 목적이 다르다. 전처리는 품질 문제를 다루고, 변환은 마이닝에 적합한 표현을 만든다. 결측 처리와 스케일 조정처럼 실제 작업이 맞닿을 수 있으므로 산출물에서 목적과 순서를 기록한다.

### 변환의 판단 기준

1. 업무 의미를 보존하는가?
2. 적용 시점에 계산 가능한가?
3. 학습과 운영에서 동일하게 재현되는가?
4. 목표값이나 미래 정보를 간접적으로 포함하지 않는가?
5. 지나친 차원·희소성·다중공선성을 만들지 않는가?
6. 해석 요구와 기법 가정에 맞는가?

예를 들어 고객의 “향후 30일 총 구매액”은 과거 고객 분류에는 쓸 수 있어도 기준 시점의 미래 구매 예측 입력에는 사용할 수 없다.

## 3.2 데이터 마이닝

데이터 마이닝은 준비된 데이터에 알고리즘을 적용해 패턴·규칙·모델을 찾는 단계다.

| 목적 | 대표 문제 | 결과 형태 |
|---|---|---|
| 분류 | 이탈 여부, 불량 여부 | 범주·확률 |
| 예측 | 수요, 가격, 시간 | 연속값·구간 |
| 군집 | 유사 고객 그룹 | 군집과 특성 |
| 연관 | 함께 구매되는 품목 | 연관 규칙 |
| 이상 탐지 | 비정상 거래·센서 | 이상 점수·경보 |
| 요약 | 데이터의 주요 구조 | 축약 표현·설명 |

기법 선택은 유행보다 목표, 변수 형태, 데이터량·품질, 해석성, 오류 비용, 처리시간, 운영 환경에 맞춘다. 단순 기준선과 비교하고 동일한 데이터 분할·평가 조건을 사용한다.

### 과적합과 탐색 편향

많은 기법·변수·임계값을 시험하면 우연히 검증 데이터에 좋은 결과가 나올 수 있다. 최종 평가 데이터를 반복 선택에 사용하지 않고, 교차검증·시간 분리 등 문제에 맞는 방법으로 일반화 성능을 추정한다. 시계열·고객 반복 관측은 무작위 행 분할이 동일 개체 정보를 양쪽에 섞을 수 있다.

## 4. 결과 평가와 해석

**`결과 평가와 해석`**은 마이닝 결과가 데이터에서 계산됐다는 사실을 넘어 유효성, 새로움, 유용성, 이해 가능성을 검토하고 지식으로 정리하는 단계다.

### 4.1 기술적 평가

분류의 정확도·정밀도·재현율, 예측 오차, 군집 안정성, 규칙의 지지도·신뢰도 등 목적에 맞는 지표를 사용한다. 하나의 지표만 보지 않고 클래스 불균형, 비용, 기간·집단별 성능과 불확실성을 본다.

### 4.2 업무 평가

패턴이 어떤 의사결정을 바꾸며 가치가 있는지 확인한다. 이탈 점수가 정확해도 연락 가능한 고객 수보다 경보가 많으면 운영하기 어렵다. 모델 효과와 캠페인·프로세스 효과를 현장 시험으로 구분한다.

### 4.3 타당성과 새로움

이미 업무 규칙으로 알려진 사실을 다시 찾은 것인지, 우연한 상관인지, 외부 기간·집단에서도 반복되는지 본다. 상관관계를 인과로 표현하지 않는다.

### 4.4 이해와 표현

도메인 전문가와 함께 패턴의 의미, 적용 조건, 예외를 해석한다. 시각화, 규칙 요약, 중요 변수, 대표 사례를 사용하되 설명이 모델의 실제 동작을 충실히 반영하는지 확인한다.

### 4.5 다음 결정

- 채택: 기준을 충족해 제한된 현장 적용으로 이동
- 보완: 변수·전처리·기법을 수정해 반복
- 재선택: 대상·기간·데이터 원천을 다시 구성
- 중단: 가치·타당성·권한·위험이 기준 미달

## 5. KDD 단계 간 반복과 추적

평가에서 성능이 낮다고 무조건 더 복잡한 모델로 가지 않는다.

```text
평가 문제                 돌아갈 단계
라벨 정의가 업무와 다름 → 데이터 선택
센서 오류가 특정 기간 집중 → 전처리
분포 치우침·표현 부족    → 변환
기법 가정이 맞지 않음    → 마이닝
업무 행동과 연결 안 됨   → 목표·선택 재검토
```

반복할 때 데이터셋 버전, 전처리·변환 규칙, 기법·매개변수, 평가 결과와 선택 이유를 기록한다. 좋은 결과만 남기면 선택 과정의 편향과 실패 원인을 알 수 없다.

### 단계별 추적 기록

선택 명세에는 원천·추출 조건·기준 시점과 제외 이유를, 전처리 기록에는 문제 원인·처리 전후 건수와 승인을 남긴다. 변환 명세에는 변수 계산식·시간 창·학습에서 추정한 값을, 마이닝 기록에는 데이터 버전·기법·매개변수·실행 환경을 연결한다. 평가 보고서는 어떤 후보를 어떤 자료와 지표로 비교했는지, 왜 채택·보완·중단했는지를 보여 줘야 한다.

이 연결이 없으면 결과가 나빠졌을 때 원천 데이터 변화인지 전처리·변환 변화인지 모델 변화인지 구분할 수 없다. 반대로 모든 중간 파일을 무기한 보존하는 것이 목적은 아니다. 재현·감사에 필요한 코드, 명세, 불변 입력 식별자와 보존 정책을 정한다.

## 6. 사례: 온라인 구독 고객의 이탈 지식 발견

### 선택

매월 말 유효 고객을 분석 단위로 정하고 이전 90일 이용·결제·상담 데이터를 선택한다. 이후 30일 자발적 해지를 목표로 삼고 시험 계정과 이미 해지된 고객을 제외한다.

### 전처리

서비스 장애 기간의 이용량 결측을 실제 미사용과 구분한다. 상담 코드 체계가 바뀐 시점을 대응표로 통합하고, 고객 중복 계정을 업무 규칙으로 판정한다.

### 변환

최근 접속 이후 일수, 이용 빈도 변화, 결제 실패 횟수, 상담 감성 요약을 기준 시점 이전 정보로 만든다. 변환 통계는 학습 기간에서만 추정한다.

### 마이닝

단순 규칙과 여러 분류 후보를 시간 순서 분할로 비교한다. 상담팀이 처리할 수 있는 경보 수를 고려해 임계값을 평가한다.

### 해석·평가

전체 재현율뿐 아니라 신규·장기 고객별 오류, 경보당 실제 이탈, 유지 활동의 효과를 본다. 특정 상담 코드가 이탈 뒤 정리되는 값임을 발견하면 해당 변수를 제거하고 변환 단계로 돌아간다.

최종 지식은 “모델 A의 점수가 높다”가 아니라 “최근 이용 감소와 반복 결제 실패가 함께 나타난 일부 고객에서 이탈 위험이 높으며, 갱신 전 상담 우선 배정으로 시험할 가치가 있다”처럼 조건·한계·행동과 함께 표현한다.

## 7. 수행 체크리스트

- [ ] 분석 단위·기준 시점·관찰·예측 기간을 정의했다.
- [ ] 목표 모집단과 제외 조건, 표본 대표성을 확인했다.
- [ ] 변수의 실제 이용 가능 시점과 데이터 권한을 검토했다.
- [ ] 결측·이상·중복·단위·코드 변화의 원인을 진단했다.
- [ ] 전처리·변환 통계가 학습 자료에서만 추정됐다.
- [ ] 변환이 업무 의미를 보존하고 운영에서 재현된다.
- [ ] 목적·데이터·제약에 맞는 마이닝 기법과 기준선을 썼다.
- [ ] 탐색·선택과 최종 평가 데이터를 분리했다.
- [ ] 기술 지표, 집단·기간 안정성, 업무 가치와 위험을 평가했다.
- [ ] 단계 회귀와 데이터·규칙·모델 버전을 기록했다.

## 8. 자주 틀리는 시험 함정

1. KDD와 데이터 마이닝을 같은 범위로 본다.
2. 데이터 변환을 전처리보다 앞 단계로 외운다.
3. 선택 단계에서 편리한 데이터만 뽑고 모집단 대표성을 보지 않는다.
4. 현재 DB에 있는 값이면 과거 기준 시점에도 사용 가능했다고 본다.
5. 결측과 이상값은 항상 제거하거나 평균으로 대치한다.
6. 전처리 통계량을 전체 데이터로 계산해 평가 정보가 누수된다.
7. 변환 변수가 업무 의미와 시점을 보존하는지 확인하지 않는다.
8. 가장 복잡한 마이닝 기법을 가장 좋은 지식으로 본다.
9. 탐색한 동일 데이터로 최종 유효성을 확정한다.
10. 높은 상관·예측 성능을 원인과 업무 효과로 단정한다.

## 10. 정답과 해설

### 문제 1 정답과 해설

KDD는 데이터 선택부터 전처리·변환·마이닝·해석·평가를 거쳐 지식을 발견하는 전체 과정이다. 데이터 마이닝은 준비된 데이터에서 패턴이나 모델을 찾는 한 단계다.

### 문제 2 정답과 해설

데이터 선택 → 데이터 전처리 → 데이터 변환 → 데이터 마이닝 → 결과 해석·평가 순이다. 평가 결과에 따라 앞 단계로 반복할 수 있다.

### 문제 3 정답과 해설

무엇을 한 행으로 볼지와 어느 시점 정보까지 허용할지 결정해 데이터 누수를 막고, 선택 표본이 실제 적용 대상을 대표하는지 판단하기 위해서다.

### 문제 4 정답과 해설

전처리는 오류·결측·중복 같은 품질 문제를 다룬다. 변환은 정제 데이터를 모델에 적합한 표현으로 바꾸며, 예를 들어 거래를 고객별 최근성·빈도로 집계한다.

### 문제 5 정답과 해설

검증·평가 데이터의 평균·범주 정보가 학습 변환에 들어가 미래 평가 정보를 미리 본 효과가 생긴다. 학습에서 추정한 규칙을 나머지 데이터에 적용해야 한다.

### 문제 6 정답과 해설

분석 목적, 변수·라벨 형태, 데이터량·품질, 해석 요구, 오류 비용, 처리시간·운영 환경, 단순 기준선 대비 이익을 고려한다.

### 문제 7 정답과 해설

기간·집단별 안정성, 새로움과 우연 가능성, 업무 의사결정·효과, 운영 용량·비용, 공정성·안전과 해석 가능성을 확인한다.

### 문제 8 정답과 해설

데이터 선택으로 돌아가 목표 사건·대상·기간 명세를 바로잡아야 한다. 잘못된 라벨 위에서 변환이나 모델만 바꾸면 질문과 다른 결과를 정교하게 학습할 뿐이다.

### 문제 9 정답과 해설

고객·시점·기간 선택 → 결측·코드·중복 전처리 → 최근성·빈도 등 시점 안전 변수 변환 → 기준선과 분류 후보 마이닝 → 시간·집단·업무 효과 평가 → 누수나 가치 문제에 따라 이전 단계 보완 순이다.

## 11. 핵심 요약

- KDD는 유용한 지식을 발견하는 전체 반복 과정이고 데이터 마이닝은 그 안의 패턴·모델 탐색 단계다.
- **`데이터 선택과 전처리`**는 질문에 맞는 대상·시점·변수를 선택하고 결측·오류·중복·불일치의 원인과 영향을 처리한다.
- **`데이터 변환과 마이닝`**은 정제 데이터를 목적·기법에 맞는 표현으로 만들고 기준선과 공정한 조건에서 패턴·모델을 탐색한다.
- **`결과 평가와 해석`**은 기술 성능뿐 아니라 새로움, 안정성, 업무 유용성, 이해 가능성, 위험을 검토해 지식과 다음 행동으로 정리한다.
- 단계 순서는 선택 → 전처리 → 변환 → 마이닝 → 해석·평가이며 결과에 따라 근거를 기록하고 이전 단계로 반복한다.
