학습 범위: 이 레슨은 ADsP 데이터분석 기획 > 데이터분석 기획의 이해 > 분석 과제 발굴 중 문제 탐색, 문제 정의, 해결방안 탐색과 타당성 검토를 다룬다. 조직의 전략·업무 현안에서 출발해 문제를 넓게 탐색하고, 데이터로 답할 분석 문제로 변환한 뒤, 가능한 해결방안과 경제적·데이터·기술 타당성을 평가해 과제 후보를 선정하는 것이 목표다.

하향식 접근은 경영진이 말한 해결책을 그대로 실행하는 방식이 아니다. 상위 목표에서 출발하되 원인·영향·이해관계자를 탐색하고, 분석 외 해결책까지 비교한다. 시험에서는 문제 탐색과 문제 정의를 바꾸거나 타당성 검토를 기술 가능성 하나로 좁히는 선택지를 주의해야 한다.

02

2. 문제 탐색

문제 탐색은 요청받은 표면 현상을 곧바로 분석 문제로 확정하지 않고, 전략·업무모델·외부환경·기존 사례를 통해 중요한 기회와 위험을 구조적으로 찾는 단계다.

03

2.1 전략과 현상에서 시작한다

“매출이 감소했다”, “민원이 늘었다”, “AI를 도입하자”는 아직 분석 문제라기보다 현상이나 해결 수단 제안이다. 다음을 확인한다.

  • 어떤 전략 목표와 성과가 영향을 받는가?
  • 변화는 어느 고객·제품·지역·기간에 집중되는가?
  • 현재 업무 흐름에서 누가 어떤 결정을 내리는가?
  • 알려진 원인과 아직 가정인 원인은 무엇인가?
  • 결과를 바꿀 수 있는 행동·권한이 있는가?
  • 문제를 방치하거나 잘못 해결할 때 손실은 무엇인가?

증상–원인 후보–의사결정을 구분한다.

코드 예시 · text

증상: 배송 불만 증가
원인 후보: 출고 지연, 운송 경로, 주소 오류, 기대일 안내 오류
의사결정: 주문별 사전 경고, 배차 조정, 고객 안내
분석 기회: 어느 주문이 언제 어떤 이유로 지연될 가능성이 큰가
04

2.2 비즈니스 모델 관점의 탐색

업무를 한 부서의 화면에 한정하지 않고 다음 영역에서 문제 후보를 살핀다.

2.2 비즈니스 모델 관점의 탐색 · 학습 표 2
영역탐색 질문예시 기회
고객누구의 요구·행동·경험이 달라지는가이탈·민원·추천
제품·서비스가치·품질·가격·구성이 적절한가품질 예측·조합 최적화
업무 운영프로세스·자원·공급·채널의 병목은 무엇인가수요·재고·일정 개선
규제·감사준수·공정성·부정·안전 위험은 무엇인가이상 거래·준수 감시
지원 인프라데이터·IT·인력·재무 기반의 제약은 무엇인가장애 예측·역량 계획

영역 이름 자체보다 고객 가치와 운영·통제·지원 요소를 빠짐없이 보는 것이 중요하다. 한 영역의 개선이 다른 영역에 부작용을 만들 수 있다. 재고를 줄이면 보관비는 감소하지만 결품과 고객 이탈이 늘 수 있다.

05

2.3 외부·내부 참조 활용

산업 참조모델, 규제 요구, 경쟁·유사기관 사례, 공개된 분석 활용 사례를 살펴 문제 후보를 확장할 수 있다. 내부적으로는 기존 프로젝트, 감사·민원·장애 보고, 전략 KPI, 데이터 카탈로그를 활용한다.

참조 사례를 그대로 복사하지 않는다. 고객, 프로세스, 데이터 정의, 규제와 운영 능력이 다르다. 사례는 질문을 발견하는 자극이며 타당성의 증거는 조직 데이터와 현장 검증에서 만들어야 한다.

06

2.4 문제 탐색의 우선순위

후보를 전략 연계, 영향 규모, 시급성, 통제 가능성, 데이터 가능성, 위험으로 1차 선별한다. 이때 정확한 투자 수익을 계산하기보다 심층 정의할 후보를 좁힌다.

“영향이 크다”와 “분석으로 개선 가능하다”를 구분한다. 환율 변화는 영향이 커도 조직이 통제하기 어렵고, 분석은 예측·시나리오 대응에만 도움을 줄 수 있다.

07

3. 문제 정의

문제 정의는 탐색한 업무 문제를 데이터와 분석으로 답할 수 있는 명확한 질문으로 변환하는 단계다.

3.1 업무 문제와 분석 문제

3.2 원인·상관·예측을 구분한다

“어떤 고객이 이탈할까”는 예측 질문이고 “왜 이탈하는가”는 설명·인과 질문이다. 예측 중요 변수가 개입 가능한 원인이라고 단정하지 않는다. 할인 정책 효과를 알고 싶다면 단순 과거 상관보다 실험·준실험과 교란 통제가 필요할 수 있다.

3.3 범위와 성공 기준

대상·기간·지역·상품, 제외 조건과 결과 사용 시점을 정한다. 모델 성능, 업무 효과, 운영 용량, 공정성·안전의 성공 기준을 분리한다. 데이터가 없을 때 대리변수를 쓰면 무엇을 실제 측정하는지 검토한다.

3.4 정의 검증 질문

  1. 결과를 받으면 실제로 다른 행동을 할 수 있는가?
  2. 기준 시점에 사용할 데이터로 질문에 답할 수 있는가?
  3. 목표 사건을 일관되게 관찰·라벨링할 수 있는가?
  4. 오류의 종류별 비용을 설명할 수 있는가?
  5. 분석 없이 해결할 더 직접적인 방법은 없는가?
08

4. 해결방안 탐색

해결방안 탐색과 타당성 검토 중 해결방안 탐색은 정의된 문제에 대해 분석 방법, 업무 규칙·프로세스, 데이터 수집, 시스템 개선을 포함한 여러 대안을 비교하는 단계다.

4.1 분석 대안

  • 현황 기술·시각화와 경보 대시보드
  • 진단 분석과 원인 후보 탐색
  • 분류·회귀·시계열 예측
  • 군집·연관·이상 탐지
  • 최적화·시뮬레이션
  • 실험·인과 효과 평가

기법 이름보다 출력과 의사결정의 적합성을 본다. 설명이 필요한 감사 판단에 해석 불가능한 점수만 주거나, 개입 효과 질문에 예측 모델만 쓰면 목적이 맞지 않는다.

4.2 비분석 대안

데이터 입력 오류 때문에 민원이 생겼다면 입력 검증과 업무 교육이 예측 모델보다 직접적일 수 있다. 시스템 용량 증설, 규칙 정비, 표준화, 프로세스 단순화도 후보에 둔다.

4.3 결합 대안

분석 점수 + 업무 규칙 + 인간 검토처럼 결합할 수 있다. 예를 들어 사기 점수가 임계값을 넘더라도 자동 차단이 아니라 검토 큐의 우선순위로 사용해 오류 피해를 줄인다.

4.4 자체 개발·구매·기존 활용

조직 역량과 요구에 따라 기존 시스템 기능, 상용 서비스, 오픈소스·자체 분석을 비교한다. 구매 제품의 데모 성능이 조직 데이터의 품질·규제·운영 적합성을 보장하지 않는다. 작은 실증으로 검증한다.

4. 해결방안 탐색 · 학습 표 4
대안장점위험·검증점
기존 규칙 개선빠르고 설명 쉬움복잡 패턴·유지보수 한계
분석 모델 개발맞춤 가능데이터·운영·감시 필요
외부 솔루션구축 기간 단축 가능종속, 데이터 이전, 실제 적합성
프로세스 개선원인을 직접 제거 가능조직 변경·교육 필요

5. 타당성 검토

타당성 검토는 “모델을 만들 수 있는가”보다 넓다. 경제, 데이터, 기술, 조직·운영, 규제·윤리를 함께 본다.

10

5.1 경제적 타당성

기대 편익과 총비용, 오류 손실, 불확실성을 평가한다.

  • 편익: 수익 증가, 비용·시간 절감, 손실·위험 감소, 고객 경험
  • 구축비: 데이터 정비, 인력, 도구·인프라, 연계·시험
  • 운영비: 수집·저장·점수, 감시·재학습, 지원·감사
  • 오류비: 오탐·미탐, 잘못된 개입, 평판·규제 손실
  • 기회비용: 다른 과제를 미루는 비용

낙관·기준·비관 시나리오를 비교하고 핵심 가정에 민감한지 본다. 모델 정확도 1% 향상을 곧바로 매출 1% 증가로 환산하지 않는다.

11

5.2 데이터 타당성

  • 필요한 데이터가 기간·세분성·양을 충족하는가?
  • 목표 라벨과 기준 시점이 신뢰 가능한가?
  • 결측·편향·대표성·스키마 변화가 통제되는가?
  • 접근·결합·활용 목적·보존이 허용되는가?
  • 운영에서도 같은 데이터가 제때 생성되는가?

데이터가 부족하면 즉시 과제를 폐기하기보다 범위 축소, 선행 수집, 대리 지표의 한계, 실험 설계를 비교한다.

12

5.3 기술 타당성

문제에 적합한 방법, 팀 역량, 처리 규모·지연, 시스템 통합, 설명성·보안, 장애 복구, 유지보수 가능성을 확인한다. 연구 환경 모델이 실제 응답시간과 비용을 충족하는지 실증한다.

13

5.4 조직·운영 타당성

결과 사용자가 행동할 권한·시간·자원을 갖는지, 프로세스 변경과 교육을 수용하는지, 데이터·모델 소유자가 누구인지 본다. 경보를 확인할 인력이 없다면 좋은 모델도 운영되지 않는다.

14

5.5 규제·윤리 타당성

개인정보 처리 목적, 최소 수집, 공정성, 설명·이의제기, 자동 결정 제한, 감사 요구를 검토한다. 민감 변수를 제거하는 것만으로 차별 위험이 사라지지 않으므로 대리변수와 결과 집단별 영향을 본다.

15

6. 타당성 의사결정

코드 예시 · text

가치 높음 + 실행 가능 → 우선 과제로 선정
가치 높음 + 실행 부족 → 선행 데이터·기반 과제 후 재검토
가치 낮음 + 실행 쉬움 → 자동 우선하지 말고 목적 재검토
가치 낮음 + 실행 어려움 → 보류·중단
위험 통제 불가          → 효과와 무관하게 반려

점수 합산만으로 필수 조건을 덮지 않는다. 법적 권한 없음, 목표 라벨 부재, 안전 위험 통제 불가처럼 치명적인 조건은 별도 관문으로 둔다. 선정하지 않은 후보도 근거와 재검토 조건을 기록한다.

16

7. 사례: 병원 예약 미방문 감소

문제 탐색

미방문율 증가로 진료 자원이 낭비되고 대기 환자가 늘었다. 환자, 진료과, 예약 채널, 알림, 이동 접근성, 취소 절차를 살핀다. 현상은 특정 진료과·예약 리드타임에 집중된다.

문제 정의

“예약 48시간 전 이용 가능한 정보로 미방문 위험을 추정해 추가 확인이 필요한 예약을 선별한다”로 정의한다. 자동 취소는 금지하며, 연락 가능 인원과 환자 불편·집단별 오류를 성공 기준에 포함한다.

해결방안 탐색

단순 리드타임 규칙, 위험 모델, 알림 방식 개선, 취소 절차 단순화, 대기명단 운영을 비교한다. 예측과 프로세스 개선의 결합을 후보로 둔다.

타당성 검토

과거 예약·취소 데이터의 시간과 라벨을 확인하고 연락 동의·민감정보 최소화를 검토한다. 상담 인력, 메시지 비용, 미방문 감소 편익, 특정 집단의 접촉 격차, 시스템 연계를 평가한다.

판단

한 진료과에서 위험 순위 + 쉬운 취소 링크를 제한 시험하고, 미방문율뿐 아니라 취소 후 슬롯 재배정, 민원, 연락 실패를 측정한다. 데이터가 부족한 소규모 진료과는 같은 모델을 강제하지 않는다.

17

8. 발굴 산출물과 체크리스트

주요 산출물은 전략·현상 근거, 문제 후보 목록, 이해관계자·업무 흐름, 분석 문제 정의서, 대안 비교표, 경제·데이터·기술·조직·규제 타당성, 우선순위와 선행과제, 선정·보류·중단 근거다.

  • [ ] 표면 증상, 원인 가설, 의사결정을 구분했다.
  • [ ] 고객·제품·업무·규제·지원 인프라 관점을 탐색했다.
  • [ ] 외부 사례를 조직 조건 검증 없이 복사하지 않았다.
  • [ ] 분석 문제에 대상·단위·시점·출력·행동이 있다.
  • [ ] 예측·설명·인과·최적화 질문을 구분했다.
  • [ ] 분석·규칙·프로세스·시스템 대안을 함께 비교했다.
  • [ ] 경제 편익과 구축·운영·오류 비용을 평가했다.
  • [ ] 데이터 권한·품질·대표성·운영 시점이 확인됐다.
  • [ ] 기술·조직·규제·윤리의 필수 관문을 통과했다.
  • [ ] 선정·보류·중단과 선행과제의 근거가 기록됐다.

9. 자주 틀리는 시험 함정

  1. 경영진이 제시한 기술을 문제 정의로 그대로 사용한다.
  2. 문제 탐색 없이 처음 보이는 현상을 분석 문제로 확정한다.
  3. 외부 우수 사례는 조직 데이터와 무관하게 적용 가능하다고 본다.
  4. 업무 문제를 분석 문제로 변환할 때 기준 시점·행동을 생략한다.
  5. 예측 변수를 원인으로 해석한다.
  6. 해결방안을 분석 모델 하나로 제한한다.
  7. 기술 구현 가능성만으로 타당성이 충분하다고 본다.
  8. 기대 매출만 계산하고 운영·오류·변화관리 비용을 빼먹는다.
  9. 데이터가 저장돼 있으면 권한·대표성·시점도 적합하다고 본다.
  10. 필수 규제·안전 조건을 높은 총점으로 상쇄한다.

병원 예약 미방문 사례의 발굴 과정을 네 단계에 맞춰 요약하시오.

11. 정답과 해설

문제 1 정답과 해설

문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토 순이다. 검토 결과에 따라 앞 단계로 돌아가 범위나 대안을 보완한다.

문제 2 정답과 해설

매출·민원 변화 같은 현상은 여러 원인으로 생길 수 있다. 증상을 곧 원인으로 보면 잘못된 데이터와 방법을 선택하므로, 업무 흐름과 근거로 원인 가설을 구분해야 한다.

문제 3 정답과 해설

고객, 제품·서비스, 업무 운영, 규제·감사, IT·인력 등 지원 인프라 관점이다.

문제 4 정답과 해설

대상·분석 단위, 기준 시점·관찰 기간, 입력 가능 정보, 출력, 결과를 사용할 의사결정·행동, 모델·업무 성공 조건과 제약을 포함한다.

문제 5 정답과 해설

예측은 관측 정보로 미래 결과를 맞히는 데 초점을 둔다. 인과는 특정 개입이 결과를 얼마나 바꾸는지 묻기 때문에 교란 통제와 실험·준실험 설계가 필요할 수 있다.

문제 6 정답과 해설

입력 검증, 프로세스 단순화, 규칙·교육·설비 개선이 모델보다 원인을 직접, 저렴하고 안전하게 해결할 수 있기 때문이다. 결합 대안도 평가한다.

문제 7 정답과 해설

경제적, 데이터, 기술, 조직·운영, 규제·윤리 타당성을 본다. 프로젝트에 따라 보안·안전을 별도 필수 관문으로 둘 수 있다.

문제 8 정답과 해설

즉시 대규모 모델을 시작하지 않고 선행 데이터 수집·정의 개선, 범위 축소, 작은 실증을 계획해 재검토할 수 있다. 필수 데이터 확보가 불가능하면 보류·중단한다.

문제 9 정답과 해설

미방문이 집중되는 업무 구간 탐색 → 예약 48시간 전 위험 선별 문제 정의 → 규칙·모델·알림·취소 절차 대안 비교 → 데이터·비용·인력·동의·공정성 검토 후 제한 시험 선정 순이다.

21

12. 핵심 요약

  • 하향식 분석 과제 발굴은 조직 전략·현안에서 문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토의 흐름으로 진행한다.
  • 문제 탐색은 고객·제품·업무·규제·지원 인프라와 내외부 사례에서 증상·원인·의사결정을 구분해 기회 후보를 찾는 단계다.
  • 문제 정의는 업무 문제를 대상·시점·출력·행동·성공 기준이 있는 데이터 분석 질문으로 변환하는 단계다.
  • 해결방안 탐색과 타당성 검토는 분석·규칙·프로세스·시스템 대안을 비교하고 경제·데이터·기술·조직·규제·윤리 가능성을 평가하는 단계다.
  • 높은 기대 가치가 권한 없음이나 안전 위험을 상쇄하지 않으며, 선정·선행과제·보류·중단의 근거와 재검토 조건을 기록해야 한다.
