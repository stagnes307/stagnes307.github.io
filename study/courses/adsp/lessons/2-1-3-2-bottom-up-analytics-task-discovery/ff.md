분석 과제는 항상 경영진이 “이탈률을 5% 낮춰라”처럼 완성된 문제를 내려 주면서 시작하지 않는다. 무엇이 중요한지, 어떤 데이터가 신호를 담는지, 실제로 바꿀 수 있는 요인이 무엇인지조차 모를 수 있다. 이런 상황에서는 데이터와 현장을 탐색하며 예상하지 못한 패턴을 발견하고, 프로토타입으로 가치와 실행 가능성을 확인하는 상향식 접근이 유용하다.

## 1. 상향식 분석 과제 발굴의 의미

상향식 접근은 보유 데이터, 관찰된 현상, 현업의 작은 이상과 실험 결과에서 출발해 문제와 기회를 발견하는 방식이다. 먼저 가설을 완성해 놓고 검증하기보다 탐색을 통해 “무엇을 물어야 하는가”를 구체화한다.

```text
데이터·현장 관찰
→ 반복 패턴·이상·군집·관계 발견
→ 가능한 업무 의미와 가설 생성
→ 가치·실행 가능성이 있는 후보 선택
→ 작은 프로토타입과 현장 검증
→ 분석 과제로 구체화하거나 폐기·수정
```

상향식은 목표가 전혀 없는 무작위 탐색이 아니다. 기업 전략, 법·윤리, 사용 가능한 자원이라는 탐색 경계를 정하되, 문제와 해법을 데이터 학습 과정에서 함께 발전시킨다.

### 1.1 하향식과의 비교

| 구분 | 하향식 접근 | 상향식 접근 |
|---|---|---|
| 출발점 | 전략·업무 문제와 목표 | 데이터·현상·패턴·기술 가능성 |
| 핵심 질문 | 정의된 문제를 어떻게 풀까 | 데이터가 어떤 문제와 기회를 보여 주는가 |
| 적합 상황 | 문제·성과 기준이 비교적 명확 | 문제 구조와 기회가 불명확 |
| 대표 활동 | 문제 탐색·정의, 해법·타당성 검토 | 탐색 분석, 패턴 발견, 프로토타입 |
| 위험 | 기존 프레임에 갇힘 | 목적 없는 탐색·우연한 패턴 과대해석 |
| 보완 | 데이터로 가정 검증 | 전략·현업 가치로 후보 수렴 |

두 방식은 경쟁 관계가 아니다. 상향식으로 발견한 패턴을 하향식 절차로 문제 정의·효과 지표·실행 계획에 연결할 수 있고, 하향식 과제 수행 중 예상 밖 패턴을 발견해 새 상향식 과제를 만들 수 있다.

## 2. 기존 문제 해결 방식의 한계

### 2.1 문제를 이미 안다고 가정한다

**기존 문제 해결 방식의 한계**는 먼저 문제가 명확하고 전문가가 원인과 해결 후보를 충분히 알고 있다고 전제하는 데서 나타난다. 안정적인 업무에는 효과적이지만 새로운 시장, 복잡한 고객 행동, 대규모 센서 데이터처럼 사전 지식이 부족한 영역에서는 중요한 신호를 놓칠 수 있다.

예를 들어 매출 하락 원인을 가격으로 미리 규정하면 할인 효과만 분석하게 된다. 실제 원인이 검색 실패, 배송 불확실성, 특정 기기의 결제 오류일 수 있어도 초기 프레임 밖의 데이터를 보지 않는다.

### 2.2 경험과 직관의 범위에 갇힌다

전문가의 경험은 중요한 지식이지만 과거 환경에서 형성되었다. 다음 변화는 기존 규칙의 한계를 만든다.

- 신규 채널과 고객 행동 등장
- 제품·정책·경쟁 환경 변화
- 사람이 동시에 비교하기 어려운 많은 변수
- 드물지만 피해가 큰 복합 이상
- 부서 경계를 넘는 연쇄 효과

상향식 탐색은 전문가를 대체하지 않는다. 사람이 놓치기 쉬운 패턴 후보를 제시하고, 전문가는 데이터 생성 과정과 업무 의미를 검토한다.

### 2.3 정형화된 문제만 다룬다

기존 방식은 입력, 규칙, 원하는 출력이 명확한 구조적 문제에 강하다. 하지만 고객의 미충족 요구, 새 세그먼트, 알려지지 않은 부정 거래 유형처럼 결과 변수와 범주 자체가 정해지지 않은 문제도 있다. 이런 경우 처음부터 완성된 요구사항과 평가 지표를 만들기 어렵다.

### 2.4 평균과 기존 분류가 예외를 숨긴다

전체 평균 매출은 안정적이어도 특정 지역·시간·상품 조합에서 급격한 변화가 생길 수 있다. 기존 고객 등급이 실제 행동 집단을 설명하지 못할 수도 있다. 미리 정한 집계와 범주만 보면 새로운 군집과 이상을 발견하기 어렵다.

### 2.5 해결책 중심의 착수

“챗봇을 도입하자”, “추천 모델을 만들자”처럼 기술을 먼저 정하면 실제 문제가 그 기술에 맞게 왜곡된다. 상향식 접근도 새 기술 시연으로 흐를 수 있으므로 다음을 구별한다.

- **기술 가능성**: 데이터로 구현할 수 있는가?
- **업무 유용성**: 중요한 결정을 실제로 개선하는가?
- **조직 실행성**: 사용할 사람·절차·권한이 있는가?
- **경제성**: 편익이 구축·운영·위험 비용보다 큰가?

### 2.6 완전한 계획을 요구한다

불확실한 과제에서 처음부터 범위·일정·효과를 정확히 확정하려 하면 두 문제가 생긴다. 검증 전 가정을 사실처럼 계획에 넣거나, 불확실성을 이유로 탐색을 시작하지 못한다. 작은 검증 단위와 단계별 중단 기준이 필요하다.

## 3. 지도·비지도 학습 기반 접근

### 3.1 지도학습의 기본 구조

**지도·비지도 학습 기반 접근** 중 지도학습은 예측하려는 정답 또는 목표값이 포함된 과거 사례를 이용해 입력과 결과의 관계를 학습한다.

- 분류: 이탈 여부, 부정 거래 여부, 불량 유형
- 회귀: 수요량, 가격, 처리시간, 고객 가치

```text
과거 입력 특성 X + 알려진 목표 y
→ 학습
→ 새 입력 X의 목표 y 예측
```

지도학습은 목표가 비교적 명확할 때 강하다. 하지만 상향식 과제 발굴에서도 기존 라벨로 예상 밖의 중요 변수, 오류 집단, 잔차 패턴을 발견해 문제 정의를 바꿀 수 있다.

### 3.2 지도학습으로 과제를 발견하는 방법

- 단순 기준 모델과 복잡한 모델의 차이를 비교해 숨은 비선형 관계를 찾는다.
- 오류가 집중되는 집단을 분석해 데이터 품질 또는 새 업무 문제를 찾는다.
- 변수 중요도와 부분 관계를 살펴 새로운 가설을 만든다.
- 시간별 성능 저하를 통해 환경 변화와 새 세그먼트를 발견한다.
- 예측 가능성이 실제 개입 가능성과 같은지 질문한다.

예를 들어 이탈 예측 오류가 가족 요금제 고객에게 집중된다면 모델 개선뿐 아니라 고객 단위 정의가 계정이 아닌 가구여야 한다는 새 과제가 생길 수 있다.

### 3.3 지도학습의 한계

- 목표 라벨이 없거나 생성 비용이 크다.
- 과거 결정이 편향되었다면 라벨도 편향을 담는다.
- 발생하지 않은 새 유형을 기존 범주로만 분류한다.
- 예측은 잘해도 원인과 개입 효과를 보장하지 않는다.
- 희귀 사건은 사례가 너무 적어 학습이 어렵다.

“과거 우수 직원” 라벨로 채용 모델을 만들면 과거 평가 체계와 기회 불평등을 학습할 수 있다. 라벨의 생성 과정과 업무 의미를 확인해야 한다.

### 3.4 비지도학습의 기본 구조

비지도학습은 미리 정한 목표값 없이 데이터의 구조, 유사성, 잠재 패턴과 이상을 찾는다.

- 군집분석: 유사한 고객·상품·행동 집단 발견
- 연관분석: 함께 발생하는 항목과 사건 조합 발견
- 차원축소: 많은 변수의 주요 구조를 적은 축으로 표현
- 이상탐지: 일반 패턴에서 크게 벗어난 사례 발견
- 주제·패턴 탐색: 텍스트나 행동의 잠재 구조 발견

비지도 결과는 “정답”이 아니다. 알고리즘 설정과 거리·유사도 정의에 따라 패턴이 달라지며, 발견된 집단이 업무적으로 의미 있고 안정적인지 검증해야 한다.

### 3.5 비지도학습으로 과제를 발굴하는 절차

1. 분석 단위와 기간을 정한다.
2. 데이터 품질, 규모와 변수 의미를 확인한다.
3. 질문을 제한하지 않되 탐색 경계를 정한다.
4. 여러 방법·설정에서 안정적인 패턴을 비교한다.
5. 현업 사례와 외부 자료로 패턴의 의미를 해석한다.
6. 가치·위험·실행 가능성이 있는 후보를 고른다.
7. 별도 데이터와 실험으로 재현성과 효과를 검증한다.

고객을 다섯 군집으로 나누었다고 “다섯 종류의 고객이 실제 존재한다”고 단정하지 않는다. 군집별 행동 차이가 재현되는지, 다른 마케팅·서비스가 필요한지, 차별 위험은 없는지 확인한다.

### 3.6 지도와 비지도의 결합

| 결합 방식 | 예시 | 과제 발굴 가치 |
|---|---|---|
| 군집 후 지도학습 | 행동 군집별 이탈 모델 | 집단별 원인과 모델 차이 발견 |
| 비지도 이상 후보 후 라벨링 | 이상 거래를 조사자가 확인 | 새 부정 유형과 학습 데이터 생성 |
| 지도 오류의 군집화 | 오분류 사례를 유사 패턴으로 묶음 | 모델·데이터·업무 정의 문제 발견 |
| 표현 학습 후 분류 | 고차원 자료를 요약해 목표 예측 | 비정형 신호의 활용 가능성 검증 |

실무에서는 완전히 지도 또는 비지도 한 가지로 끝나기보다 탐색과 검증을 반복한다.

### 3.7 알고리즘 결과를 과제로 바꾸는 질문

- 패턴이 다른 기간과 표본에서도 재현되는가?
- 데이터 수집 방식이 만든 인공적 패턴은 아닌가?
- 현업이 설명할 수 있는 행동·프로세스와 연결되는가?
- 이 결과로 바꿀 수 있는 결정이 있는가?
- 기대 효과와 잘못된 적용의 피해는 무엇인가?
- 필요한 데이터와 운영 체계를 지속적으로 확보할 수 있는가?

패턴 발견과 분석 과제 발굴 사이에는 업무 번역과 가치 검증이 있다.

## 4. 프로토타이핑과 시행착오

### 4.1 프로토타입의 목적

**프로토타이핑과 시행착오**는 최종 시스템의 축소판을 예쁘게 만드는 일이 아니다. 중요한 가정이 맞는지 빠르고 저렴하게 확인하는 학습 수단이다.

상향식 과제에는 보통 세 불확실성이 있다.

1. **문제 불확실성**: 발견한 패턴이 실제로 중요한가?
2. **데이터·기술 불확실성**: 필요한 신호를 안정적으로 만들 수 있는가?
3. **실행·가치 불확실성**: 결과를 사용하면 행동과 성과가 나아지는가?

프로토타입은 세 불확실성 중 가장 위험한 것을 먼저 검증한다.

### 4.2 최소 실행 가능한 분석

완성형 자동화 대신 제한된 데이터와 수동 절차로 핵심 가치 흐름을 확인할 수 있다.

- 한 지역·한 상품·짧은 기간으로 범위 제한
- 기존 보고서와 간단한 규칙을 기준선으로 설정
- 고가 플랫폼 대신 재현 가능한 소규모 분석 사용
- 자동 판단 대신 분석가가 결과를 검토해 현업에 전달
- 핵심 지표와 안전 기준만 먼저 측정

초기 프로토타입의 목표는 최고 정확도가 아니라 계속 투자할 근거를 얻는 것이다.

### 4.3 반복 학습 주기

```text
가정 명시
→ 최소 프로토타입 설계
→ 데이터·사용자·성과 관찰
→ 가정이 틀린 이유 분석
→ 문제·데이터·해법 수정
→ 확대·전환·중단 결정
```

각 반복에는 학습 질문과 종료 조건이 있어야 한다. “계속 개선한다”는 말만 있고 중단 기준이 없으면 성과 없는 시범사업이 장기화된다.

### 4.4 시행착오를 안전하게 만드는 장치

- 작은 대상과 짧은 기간에서 시작
- 고객·안전·법적 영향이 큰 결정은 사람 승인 유지
- 기존 방식과 비교할 기준선 설정
- 실패 시 원상복구 가능한 절차
- 개인정보와 권한을 본 시스템 수준으로 통제
- 성공 지표와 함께 피해·부작용 지표 정의
- 결과가 좋지 않아도 기록하고 공유하는 문화

“빨리 실패하라”는 말은 피해를 무시하라는 뜻이 아니다. 회복 가능한 작은 실패로 큰 잘못을 예방하라는 뜻이다.

### 4.5 실패 유형과 다음 행동

| 결과 | 해석 후보 | 다음 행동 |
|---|---|---|
| 패턴 재현 실패 | 우연, 데이터 오류, 환경 차이 | 데이터·기간·가정 재검토 또는 폐기 |
| 예측은 되나 행동 불가 | 바꿀 수 없는 변수 중심 | 개입 가능한 요인으로 문제 재정의 |
| 현업이 사용하지 않음 | 시점·설명·절차·인센티브 문제 | 사용자와 흐름 재설계 |
| 효과 있으나 비용 과다 | 운영·수집 비용이 편익 초과 | 단순화·대상 축소·중단 |
| 평균 효과 있으나 집단 피해 | 공정성·안전 문제 | 통제 강화, 집단별 정책, 중단 |

실패는 원인을 학습했을 때 자산이 된다. 결과가 나쁘다는 이유로 측정 기준을 바꾸거나 불리한 사례를 제외하면 학습이 사라진다.

### 4.6 프로토타입에서 본 시스템으로

시범 분석이 성공했다고 바로 전사 자동화하지 않는다. 다음을 확인한다.

1. 다른 기간·지역·집단에서도 효과가 재현되는가?
2. 데이터 수집과 품질 책임을 지속할 수 있는가?
3. 성능·보안·복구·모니터링 요구를 만족하는가?
4. 사용자 교육과 예외 처리 절차가 있는가?
5. 모델·규칙의 변경 승인과 중단 기준이 있는가?
6. 실제 편익이 운영 비용과 위험보다 큰가?

프로토타입 코드를 그대로 운영에 쓰기보다 검증한 지식과 요구사항을 입력으로 운영 시스템을 설계한다.

## 5. 종합 사례: 제조 설비의 새로운 이상 유형

공장은 기존 임계치 경보로 설비를 관리하지만 간헐적 고장을 놓친다.

1. 정상·고장 규칙을 더 복잡하게 만드는 기존 방식만으로는 알려지지 않은 복합 신호를 찾기 어렵다. → **기존 문제 해결 방식의 한계**
2. 진동·온도·전류·소리 데이터를 시간 패턴으로 묶고 비지도 이상탐지로 일반 운전과 다른 구간을 찾는다.
3. 정비 기록과 작업자 관찰로 이상 구간의 실제 원인을 확인해 새 라벨을 만든다.
4. 지도학습으로 고장 전조를 예측하고, 오분류 사례를 다시 군집화해 추가 유형을 탐색한다. → **지도·비지도 학습 기반 접근**
5. 한 생산라인에서 경보를 작업자에게만 제시하고 사람이 점검 여부를 결정한다.
6. 조기 발견, 오탐 정지, 점검 시간, 안전 사건을 함께 측정한다.
7. 효과가 없으면 특징·시간창·문제 정의를 수정하고, 반복 실패하면 과제를 중단한다. → **프로토타이핑과 시행착오**

이 과정에서 알고리즘이 만든 이상 점수는 과제의 답이 아니라 현업 검증을 시작하는 후보 신호다.

## 6. 시험에서 자주 틀리는 판단

### 함정 1. 상향식은 목적 없이 데이터를 뒤지는 것이다

전략·윤리·자원의 탐색 경계를 두고 패턴에서 가치 있는 문제 후보를 찾는 접근이다.

### 함정 2. 상향식과 하향식은 함께 쓸 수 없다

상향식 발견을 하향식으로 구체화하고, 하향식 수행 중 새 패턴을 상향식 과제로 발전시킬 수 있다.

### 함정 3. 지도학습은 정답이 있으므로 편향이 없다

라벨이 과거 판단과 측정 편향을 담을 수 있다. 생성 과정과 업무 의미를 검토해야 한다.

### 함정 4. 비지도 군집은 현실의 참된 집단이다

변수·거리·설정에 따른 탐색 결과다. 안정성, 업무 의미와 행동 가능성을 별도 검증한다.

### 함정 5. 프로토타입의 목표는 최고 성능의 완제품이다

가장 중요한 불확실성을 낮은 비용과 위험으로 검증하는 것이 목표다.

### 함정 6. 시행착오는 통제 없이 빨리 실패하는 것이다

작은 범위, 안전 기준, 사람 승인, 비교와 복구 장치로 학습 가능한 실패를 만든다.

- 기술이나 해결책을 문제보다 먼저 정하지 않았는가?
- 탐색의 전략·법·윤리·비용 경계가 있는가?

- 비지도 패턴이 다른 표본에서도 안정적인가?
- 발견된 패턴을 현업 사례와 업무 가치로 해석했는가?

## 9. 정답과 해설

1. **2** — 상향식은 보유 데이터와 현상에서 예상하지 못한 패턴·문제 후보를 발견하는 데서 시작한다.
2. **2** — 사전 지식과 기존 분류에 갇히면 변화한 환경과 복합 패턴을 놓칠 수 있다.
3. **2** — 목표 라벨이 있는 사례를 이용해 새 입력의 분류나 수치를 예측한다.
4. **2** — 목표값 없이 구조를 찾되 결과의 안정성과 업무 의미를 후속 검증한다.
5. **1** — 과거 의사결정과 기회 격차가 라벨에 반영되면 모델이 이를 반복할 수 있다.
6. **2** — 알고리즘 패턴 자체는 과제가 아니며 재현성·의미·행동·가치로 번역해야 한다.
7. **2** — 본격 투자 전에 문제·기술·실행의 핵심 가정을 학습하는 수단이다.
8. **4** — 고위험 전사 자동화는 실패 영향을 제한하지 못하므로 안전한 시행착오가 아니다.
9. **2** — 분석 결과가 실제 결정 흐름에 맞게 전달·설명되고 행동 권한과 연결되어야 한다.
10. **2** — 발견과 문제 구조화를 순환하면서 두 접근의 장점을 결합할 수 있다.

## 10. 핵심 요약

- 상향식 분석 과제 발굴은 데이터·현장 관찰에서 패턴과 이상을 발견하고 업무 의미와 가치를 검증해 문제를 구체화하는 접근이다.
- **기존 문제 해결 방식의 한계**는 문제와 원인을 이미 안다고 가정해 기존 경험·분류 밖의 새로운 신호와 기회를 놓칠 수 있다는 점이다.
- **지도·비지도 학습 기반 접근**에서 지도학습은 목표 라벨과 입력의 관계를 학습하고, 비지도학습은 목표 없이 군집·연관·이상과 잠재 구조를 탐색한다.
- 지도 라벨의 편향과 비지도 패턴의 불안정성을 확인하고, 알고리즘 결과를 현업 의미·행동·가치로 번역해야 한다.
- **프로토타이핑과 시행착오**는 문제·데이터·실행의 핵심 불확실성을 작은 비용과 위험으로 검증하는 반복 학습 방식이다.
- 기준선, 성공·중단·안전 지표, 사람 승인과 롤백을 두고 실패 원인도 지식으로 남겨야 한다.
- 상향식과 하향식은 상호 보완적이다. 패턴 발견과 전략적 문제 정의·타당성 검토를 순환하면 더 강한 분석 과제를 만들 수 있다.
