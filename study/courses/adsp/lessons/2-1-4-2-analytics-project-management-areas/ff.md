# 2-1-4-2. 분석 프로젝트 관리 영역

> **학습 범위**: 이 레슨은 ADsP `데이터분석 기획 > 데이터분석 기획의 이해 > 분석 프로젝트 관리방안` 중 **범위·일정·원가 관리**, **품질·위험·의사소통 관리**, **조달·자원·이해관계자 관리**를 다룬다. 프로젝트 관리 영역을 독립된 체크 상자가 아니라 데이터·모델·업무 적용을 함께 통제하는 상호 의존 체계로 이해하는 것이 목표다.

분석 프로젝트는 모델 개발만 관리해서는 완료되지 않는다. 데이터 접근 지연이 일정과 원가를 바꾸고, 설명 요구가 품질과 범위를 바꾸며, 현업 참여 부족이 모델 채택을 막는다. 따라서 각 관리 영역의 계획, 기준선, 변화, 책임과 산출물을 연결해 봐야 한다.

---

## 1. 관리 영역의 전체 지도

| 관리 영역 | 중심 질문 | 대표 산출물 | 분석 프로젝트 특화 쟁점 |
|---|---|---|---|
| 범위 | 무엇을 포함·제외하는가 | 범위 기술, 작업 분해, 수용 기준 | 탐색과 운영 전환의 경계 |
| 일정 | 언제 어떤 의존을 완료하는가 | 일정표, 이정표, 단계 관문 | 데이터 승인·실험 반복의 변동 |
| 원가 | 어떤 자원에 얼마를 쓰는가 | 예산·실적·예측 | 저장·연산·외부 데이터·운영 비용 |
| 품질 | 무엇을 만족해야 수용하는가 | 품질 계획, 검증 결과 | 데이터·모델·업무·운영 품질 |
| 위험 | 무엇이 목표를 위협하거나 기회가 되는가 | 위험 등록부·대응 | 라벨·누출·편향·분포 변화 |
| 의사소통 | 누가 언제 무엇을 알아야 하는가 | 보고·회의·결정 기록 | 불확실성과 모델 한계 번역 |
| 조달 | 외부에서 무엇을 어떤 조건으로 얻는가 | 제안·계약·검수 기준 | 데이터 권리·모델·클라우드 종속 |
| 자원 | 어떤 인력·환경·역량이 필요한가 | 역할·투입·역량 계획 | 분석·현업·데이터·운영 협업 |
| 이해관계자 | 누가 영향·권한·관심을 갖는가 | 관계자 분석·참여 계획 | 데이터 주체·결정 대상 포함 |

한 영역의 결정은 다른 영역으로 전파된다. 외부 데이터를 추가하면 범위가 늘고, 계약·원가·일정·품질·권리 위험이 함께 바뀐다. 관리자는 변경 영향 전체를 검토해야 한다.

```text
범위 기준선 ──> 일정·원가 계획
     │                 │
     ├──> 품질·수용 기준
     └──> 자원·조달 요구

위험·이해관계자·의사소통은 모든 영역의 결정과 변경을 연결
```

## 2. 범위·일정·원가 관리

### 2.1 범위 관리

**범위·일정·원가 관리** 중 범위 관리는 프로젝트가 제공할 결과와 수행할 작업의 경계를 정의·승인·통제한다. 분석에서는 다음을 명확히 한다.

- 해결할 업무 문제와 대상 사용자·의사결정
- 분석 단위, 기간, 대상 집단·채널·지역
- 포함할 데이터 확보·품질·탐색·모델링 작업
- 시제품, 인터페이스, 시험 운영, 운영 전환의 포함 여부
- 성능·설명·공정성·지연·보안 수용 기준
- 제외 범위와 향후 확장 조건

작업 분해 구조는 산출물을 만들기 위한 작업을 관리 가능한 단위로 나눈다.

```text
고객 이탈 조기지원 프로젝트
 ├ 문제·기준선 확정
 ├ 데이터 확보·권리·품질 진단
 ├ 기준 모델과 오류 분석
 ├ 후보 모델·설명·검증
 ├ 현업 시제품·제한 시험
 └ 운영 설계·모니터링·인계
```

“정확도를 높인다”는 작업이 아니다. 어떤 입력과 완료 기준을 가진 산출물을 만드는지 써야 한다. 범위 검증은 이해관계자가 산출물을 수용 기준과 대조하는 활동이고, 범위 통제는 변경의 가치·일정·비용·위험 영향을 검토하는 활동이다.

분석 중 새 패턴이 보였다고 관련 없는 새 목표를 조용히 추가하면 범위 팽창이 된다. 가치가 있다면 변경 요청이나 별도 후보로 기록한다. 반대로 가설이 틀려 범위를 합리적으로 축소·전환하는 것은 승인된 학습 기반 조정이다.

### 2.2 일정 관리

일정은 활동, 순서, 기간, 의존성, 자원과 이정표를 계획하고 진행을 통제한다. 분석 일정에서는 데이터 접근·추출·라벨 검토, 현업 피드백, 보안 승인, 외부 계약과 실험 반복이 주요 의존이다.

| 활동 | 선행 조건 | 완료 증거 | 일정 위험 |
|---|---|---|---|
| 데이터 추출 | 접근 승인·정의 합의 | 재현 가능한 스냅샷 | 승인·원천 시스템 지연 |
| 품질 진단 | 추출·업무 기준 | 품질 보고·대안 | 숨은 코드 변경 |
| 기준 모델 | 라벨·분할 확정 | 독립 검증 결과 | 누출·불균형 재작업 |
| 현업 시험 | 설명·화면·교육 | 과업·채택 결과 | 참여자 일정 부족 |
| 운영 인계 | 모니터링·책임 | 점검·되돌림 절차 | 운영 환경 차이 |

탐색 작업은 정확한 기간 예측이 어렵다. 시간상자와 단계 관문을 사용해 정해진 시점에 계속·보완·중단을 결정한다. 일정 여유는 무계획한 버퍼가 아니라 데이터 승인 등 식별된 위험에 근거해 둔다. 모델 실험 횟수를 무제한 허용하지 않는다.

### 2.3 원가 관리

원가는 인력·장비뿐 아니라 데이터와 모델의 생애주기 비용을 포함한다.

- 내부·외부 인력의 분석, 데이터, 개발, 현업 검토 시간
- 외부 데이터 구매·갱신·사용량 비용
- 저장·연산·네트워크·개발·시험·운영 환경 비용
- 라벨링, 품질 개선, 보안·법무·감사 비용
- 시스템 통합, 교육, 프로세스 변경과 지원 비용
- 모니터링, 재학습, 장애 대응, 모델 폐기 비용

초기 시제품이 저렴해도 운영 부하에서 연산비와 사람 검토비가 커질 수 있다. 고정 비용과 사용량에 따른 변동 비용, 일회성 구축과 지속 운영 비용을 구분한다. 편익을 과대평가하거나 통제 비용을 제외하지 않는다.

### 2.4 세 영역의 균형

범위를 줄이면 일정·원가가 줄 수 있지만 핵심 가치까지 빠지면 의미가 없다. 일정 단축을 위해 품질 검증을 생략하면 이후 오류 비용이 커진다. 원가를 줄이려고 외부 대역만 사용하면 실제 운영 성능을 놓칠 수 있다. 변경안마다 가치·수용 기준을 먼저 지키고 세 제약의 영향을 비교한다.

## 3. 품질·위험·의사소통 관리

### 3.1 품질 관리의 네 층

**품질·위험·의사소통 관리**에서 분석 품질은 모델 점수 하나가 아니다.

| 품질 층 | 확인 항목 | 대표 증거 |
|---|---|---|
| 데이터 품질 | 정의, 정확·완전·일관·적시·대표성 | 프로파일·대사·계보 |
| 분석 품질 | 재현성, 누출 방지, 일반화, 오류·편향 | 독립 검증·실험 기록 |
| 업무 품질 | 행동 가능성, 설명, 과업 시간, 순증 효과 | 현업 시험·성과 비교 |
| 운영 품질 | 지연, 가용성, 변화 감지, 복구·중단 | 모니터링·장애 시험 |

품질 계획은 누가 어떤 데이터와 지표로 언제 검토할지 정한다. 품질 보증은 올바른 절차와 기준이 적용되는지를 예방적으로 점검하고, 품질 통제는 산출물을 측정해 결함을 찾고 수정한다. 명칭보다 예방·측정·개선의 구분을 이해한다.

### 3.2 위험 관리

위험은 아직 발생하지 않은 불확실한 사건이나 조건으로 프로젝트 목표에 부정 또는 긍정 영향을 줄 수 있다. 이미 발생한 데이터 접근 실패는 이슈로 관리한다.

위험 등록부에는 ID, 원인-사건-영향, 발생 가능성·영향, 소유자, 대응, 촉발 조건, 잔여 위험, 상태를 기록한다.

```text
원인: 과거 해지 코드가 조직 개편마다 다름
위험 사건: 잘못된 라벨로 모델이 학습될 수 있음
영향: 성능 과대평가·고객 오접촉·재작업
대응: 기간별 코드 매핑 검토, 표본 재라벨링, 기준 미달 시 범위 축소
촉발 조건: 라벨 일치도가 승인 기준 아래
소유자: 데이터 책임자+분석 책임자
```

회피, 완화, 전가, 수용 등 대응을 상황에 맞게 선택한다. 외부 공급자 계약으로 책임 일부를 나눠도 최종 고객 영향이 사라지는 것은 아니다. 긍정 기회는 고품질 공통 데이터가 여러 과제에 재사용되는 경우처럼 확대·공유할 수 있다.

### 3.3 의사소통 관리

분석가는 기술 결과를 이해관계자의 결정 언어로 전달해야 한다. 경영진에는 가치·위험·결정 사항, 현업에는 오류 유형·업무 변화, 데이터 담당에는 정의·품질, 운영에는 지연·장애·모니터링, 보안·법무에는 수집·권리·영향을 전달한다.

| 대상 | 필요한 정보 | 빈도·형식 예 |
|---|---|---|
| 후원자 | 가치, 일정, 주요 위험, 결정 요청 | 단계 관문 요약·결정 기록 |
| 현업 사용자 | 결과 의미, 오류, 처리 절차 | 시제품 검토·사용 안내 |
| 분석·개발 | 데이터·실험·인터페이스 변경 | 작업판·기술 문서 |
| 데이터 소유자 | 품질·계보·접근·수정 | 품질 이슈 보고 |
| 운영·보안 | 장애·변화·권한·감사 | 운영 준비 점검 |
| 영향 대상 대표 | 설명·이의·불리한 영향 | 사용성·영향 검토 |

의사소통 계획에는 발신자, 수신자, 내용, 형식, 주기, 보안 등급, 피드백·결정 방법을 넣는다. 회의 횟수가 많다고 소통이 좋은 것은 아니다. 결정과 가정, 변경 이유가 추적되어야 한다.

## 4. 조달·자원·이해관계자 관리

### 4.1 조달 관리

**조달·자원·이해관계자 관리** 중 조달은 외부 데이터, 도구, 클라우드, 모델·개발 서비스, 라벨링 등을 구매·계약·검수하는 활동이다.

조달 전에는 직접 구축과 외부 구매를 비교한다.

- 전략적으로 내부에 축적할 핵심 역량인가?
- 공급자가 더 나은 데이터·전문성·속도를 제공하는가?
- 총소유비용과 확장 비용이 어떻게 변하는가?
- 데이터 이동·종속·종료·이식이 가능한가?
- 품질·보안·법적 책임과 감사 권한이 명확한가?

외부 데이터 계약에는 정의, 대상·기간, 갱신, 품질·오류 정정, 허용 용도·재배포, 보존·삭제, 장애·종료 시 인계가 필요하다. 모델 서비스는 입력·출력, 지연, 성능 변화 통지, 설명과 데이터 사용 범위를 확인한다. 데모 정확도만으로 구매하지 않는다.

### 4.2 자원 관리

분석 프로젝트 자원은 역할이 다양한 다기능 팀이다.

| 역할 | 핵심 책임 |
|---|---|
| 현업 책임자 | 문제·규칙·적용·성과·사용자 참여 |
| 데이터 소유자·관리자 | 정의·품질·접근·계보·보존 |
| 분석가·데이터 과학자 | 가설·방법·검증·설명·한계 |
| 데이터·소프트웨어 엔지니어 | 안정적 파이프라인·인터페이스·배포 |
| 프로젝트 관리자 | 범위·일정·원가·위험·결정 통합 |
| 운영·보안·법무 | 가용성·감사·보호·규정·사고 대응 |

사람 수뿐 아니라 필요한 시점의 가용성과 역량을 본다. 현업 전문가가 마지막 검수 때만 참여하면 잘못된 라벨과 업무 적용 문제를 늦게 발견한다. 단일 전문가 의존은 지식 공유, 짝 검토, 문서와 대체 인력으로 완화한다.

연산 자원도 예약과 우선순위가 필요하다. 실험이 운영 시스템을 방해하지 않도록 격리하고, 사용량·비용 한도와 민감 데이터 접근을 통제한다.

### 4.3 이해관계자 관리

이해관계자는 프로젝트에 영향을 주거나 영향을 받는 개인·집단이다. 후원자와 사용자뿐 아니라 분석 결과로 평가·거절·추천을 받는 고객·직원, 데이터 제공자, 규제기관, 운영지원 조직도 포함한다.

영향력과 관심, 기대·우려, 현재·목표 참여 수준을 분석한다.

| 집단 | 관심·우려 | 필요한 참여 |
|---|---|---|
| 경영 후원자 | 가치·일정·평판 위험 | 우선순위·자원·관문 결정 |
| 현업 사용자 | 업무 부담·설명·성과 | 요구·시제품·시험 공동 설계 |
| 데이터 제공자 | 품질 책임·추가 작업 | 정의·수정·계보 합의 |
| 운영팀 | 장애·모니터링·지원 | 초기부터 운영 요구 검토 |
| 고객·직원 | 권리·공정성·이의 제기 | 사용성·영향·설명 검토 |
| 감독·감사 | 규정·증거·책임 | 기준·통제·감사 가능성 확인 |

높은 영향력 집단만 관리하면 실제 사용자의 저항과 영향 대상의 피해를 놓친다. 참여는 홍보가 아니라 요구·대안·결정에 실질적으로 반영되어야 한다.

## 5. 통합 사례: 대출 상담 우선순위 분석

### 범위·일정·원가

첫 단계는 신청 승인 자동화가 아니라 상담이 필요한 기존 고객의 우선순위 제안으로 제한한다. 데이터 권리·품질 진단, 기준 모델, 상담원 시제품, 제한 시험, 모니터링 설계까지 포함한다. 신용 데이터 접근 승인과 상담원 시험 일정을 선행 의존으로 두고, 외부 데이터 비용·사람 검토 시간·운영 추론 비용을 예산에 넣는다.

### 품질·위험·의사소통

데이터 정의·기간별 대표성, 시간 누출 방지, 집단별 오류, 설명 이해, 상담 처리 지연을 품질 기준으로 둔다. 과거 상담 배정의 편향을 라벨로 학습하는 위험과 점수를 사실상 거절에 사용하는 범위 오용을 등록한다. 후원자에게는 순증 상담 성과와 위험, 상담원에게는 점수 이유와 무시·정정 절차를 전달한다.

### 조달·자원·이해관계자

외부 신용 정보는 허용 목적·갱신·오류 정정·종료 삭제를 계약한다. 분석가, 신용정책 전문가, 상담원, 데이터·운영·보안 담당이 초기부터 참여한다. 점수 대상 고객의 설명·이의 제기와 취약 집단 영향을 검토한다.

한 영역을 생략하면 다른 영역이 실패한다. 좋은 모델이라도 상담원 참여와 결과 전달이 없으면 사용되지 않고, 외부 데이터 계약이 늦으면 일정이 무너진다.

## 6. 관리 판단 절차

1. 승인된 문제·가치·범위와 수용 기준을 기준선으로 잡는다.
2. 산출물을 작업으로 나누고 데이터·승인·현업 의존성을 연결한다.
3. 인력·환경·조달을 시점별로 배치하고 전체 생애주기 원가를 추정한다.
4. 데이터·분석·업무·운영 품질 기준과 검토 책임을 정한다.
5. 위험·기회를 원인-사건-영향으로 쓰고 소유자·대응을 배정한다.
6. 이해관계자별 정보·참여·결정 방식을 의사소통 계획에 넣는다.
7. 진행 중 실적·품질·위험·변경을 같은 기준 시점에서 검토한다.
8. 변경이 모든 관리 영역과 잔여 위험에 미치는 영향을 평가해 승인한다.
9. 종료 시 산출물, 계약, 접근권한, 운영 책임과 학습을 인계한다.

## 7. 시험에서 자주 틀리는 포인트

1. 분석 프로젝트 관리를 일정표 작성으로만 본다.
2. 모델 개발만 범위로 두고 데이터·시험 운영·모니터링을 누락한다.
3. 탐색이므로 일정과 종료 기준을 둘 수 없다고 본다.
4. 시제품 비용만 계산하고 운영·라벨·현업 검토 비용을 제외한다.
5. 품질을 전체 정확도 하나로 본다.
6. 이미 발생한 이슈와 미래 위험을 구분하지 않는다.
7. 외부에 전가한 위험이 조직에서 사라졌다고 본다.
8. 의사소통을 보고서 배포나 회의 횟수로 평가한다.
9. 외부 도구의 데모 성능만 보고 데이터 권리·종료·종속을 놓친다.
10. 경영진·개발자만 이해관계자로 보고 실제 사용자와 영향 대상을 제외한다.

## 확인 문제

분석 프로젝트의 아홉 관리 영역을 쓰시오.

범위 기술서에서 분석 프로젝트가 명시해야 할 항목 다섯 가지를 쓰시오.

### 문제 3
분석 일정에서 일반적으로 큰 의존성이 되는 항목 네 가지를 쓰시오.

### 문제 4
분석 프로젝트의 생애주기 원가에 포함할 비용 여섯 가지를 쓰시오.

### 문제 5
분석 품질의 네 층과 각 대표 검증을 한 가지씩 쓰시오.

### 문제 6
위험 등록부의 원인-사건-영향을 라벨 불일치 사례로 작성하시오.

### 문제 7
후원자와 현업 사용자에게 전달할 정보가 어떻게 다른지 설명하시오.

### 문제 8
외부 데이터 조달 계약에서 확인할 항목 다섯 가지를 쓰시오.

### 문제 9
분석 프로젝트의 주요 역할 네 가지와 책임을 쓰시오.

### 문제 10
높은 영향력 집단 외에 실제 사용자와 분석 대상자를 이해관계자로 포함해야 하는 이유를 쓰시오.

## 정답과 해설

### 정답 1
범위, 일정, 원가, 품질, 위험, 의사소통, 조달, 자원, 이해관계자 관리다.

### 정답 2
업무 문제·의사결정, 대상·기간·단위, 포함 데이터·분석 작업, 시제품·운영 전환 경계, 수용 기준, 제외 범위 중 다섯 가지다.

### 정답 3
데이터 접근 승인·추출, 라벨·품질 검토, 보안·법무 승인, 외부 계약, 현업 시제품·시험 일정 중 네 가지다.

### 정답 4
인력, 외부 데이터, 저장·연산·네트워크, 라벨·품질, 통합·교육·프로세스 변경, 모니터링·재학습·장애·폐기 비용이다.

### 정답 5
데이터 품질은 프로파일·대사, 분석 품질은 독립 검증, 업무 품질은 현업 과업·성과 시험, 운영 품질은 지연·장애·모니터링 시험으로 확인한다.

### 정답 6
과거 코드 정의가 기간마다 다르다는 원인 때문에 잘못된 라벨로 학습하는 사건이 생겨 성능 과대평가와 고객 오접촉·재작업 영향을 낼 수 있다고 쓴다.

### 정답 7
후원자는 가치·일정·주요 위험과 결정 요청이 필요하고, 현업 사용자는 결과의 의미·오류·처리 절차·설명과 피드백 방법이 필요하다.

### 정답 8
데이터 정의·대상·기간, 갱신, 품질·정정, 허용 용도·재배포, 보안, 보존·삭제, 종료 인계 중 다섯 가지다.

### 정답 9
현업은 문제·적용·성과, 데이터 담당은 정의·품질·권한, 분석가는 방법·검증·한계, 엔지니어는 파이프라인·배포, 관리자는 영역 통합 중 네 가지를 쓸 수 있다.

### 정답 10
사용성·업무 부담을 좌우하는 사용자의 참여가 없으면 채택이 실패하고, 결과의 오류·편향·권리 영향을 직접 받는 대상의 관점을 빼면 위험과 설명·이의 요구를 놓치기 때문이다.

## 핵심 요약

- **범위·일정·원가 관리**는 분석의 대상·산출물·운영 경계, 데이터·승인·반복 의존, 전체 생애주기 비용을 통제한다.
- **품질·위험·의사소통 관리**는 데이터·분석·업무·운영 품질, 불확실한 원인-사건-영향, 대상별 결정 정보를 연결한다.
- **조달·자원·이해관계자 관리**는 외부 데이터·도구 계약, 다기능 팀과 환경, 후원자·사용자·영향 대상의 참여를 다룬다.
- 관리 영역은 독립적이지 않으며 범위 변경 하나가 일정·원가·품질·위험·자원·계약에 전파된다.
- 모델 점수와 시제품 비용만으로 완료를 판단하지 않고 현업 채택·운영·권리·모니터링까지 관리한다.
- 기준선, 책임자, 변경 영향과 결정 기록이 분석의 반복성과 프로젝트 통제를 함께 가능하게 한다.
