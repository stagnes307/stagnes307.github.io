# 2-1-4-3. 분석 프로젝트 실행 통제

> **학습 범위**: 이 레슨은 ADsP `데이터분석 기획 > 데이터분석 기획의 이해 > 분석 프로젝트 관리방안` 중 **데이터 확보 위험 관리**, **모델 품질과 일정의 균형**, **반복 결과의 검토와 의사결정**을 다룬다. 계획을 작성하는 데서 끝나지 않고 실행 중 증거를 수집해 편차·위험·가정을 갱신하고, 계속·보완·범위 조정·운영 전환·중단을 결정하는 방법을 익히는 것이 목표다.

분석 프로젝트는 일정대로 활동을 수행했다고 성공하지 않는다. 데이터가 목표 시점과 집단을 대표하는지, 모델의 개선이 실제 업무 가치에 충분한지, 남은 시간 안에 안전한 적용이 가능한지를 계속 확인해야 한다. 실행 통제는 분석가의 탐색을 방해하는 감시가 아니라, 가장 중요한 불확실성에 자원을 집중하고 잘못된 가정을 조기에 중단하게 하는 의사결정 체계다.

---

## 1. 실행 통제의 순환

```text
계획 기준선·가정·수용 기준
            ↓
실행 결과·데이터·비용·일정 증거 수집
            ↓
계획 대비 편차와 새 위험·학습 분석
            ↓
시정·예방·범위·우선순위 대안 평가
            ↓
계속 | 보완 | 축소·전환 | 운영 시험 | 중단 결정
            ↓
기준선·등록부·다음 반복 계획 갱신
```

통제의 기준은 최초 계획만이 아니다. 승인된 변경을 반영한 최신 기준선, 현재의 데이터·모델 증거, 프로젝트 가치와 최소 안전 기준을 함께 사용한다.

| 통제 대상 | 관찰 증거 | 편차 질문 | 가능한 조치 |
|---|---|---|---|
| 데이터 | 확보율, 품질, 시점, 대표성 | 계획한 분석·운영에 충분한가 | 대체·추가 수집·범위 축소 |
| 분석 | 기준 대비 성능, 오류, 안정성 | 중요한 업무 오류가 줄었는가 | 특징·방법 조정·가설 폐기 |
| 일정·원가 | 이정표, 소진, 재작업 | 지연 원인이 일시적·구조적인가 | 순서·자원·범위 변경 |
| 현업 적용 | 과업 시간, 채택, 피드백 | 결과가 실제 판단에 쓰이는가 | 설명·화면·프로세스 수정 |
| 위험·책임 | 이슈, 집단별 영향, 장애 | 수용 범위와 통제를 지키는가 | 완화·중단·승인 상향 |

## 2. 데이터 확보 위험 관리

### 2.1 확보 위험의 분류

**데이터 확보 위험 관리**는 파일 전달 여부보다 넓다.

| 위험 유형 | 사례 | 조기 신호 |
|---|---|---|
| 존재·범위 | 필요한 과거 기간이나 대상이 없음 | 테이블은 있으나 건수·기간 부족 |
| 접근·권리 | 승인·계약·목적 제한으로 사용 불가 | 요청 장기 대기, 사용 범위 불명확 |
| 정의·품질 | 코드·단위·라벨이 기간별 불일치 | 대사 실패, 갑작스러운 분포 변화 |
| 결합 | 공통 키·시간이 맞지 않아 연결 실패 | 낮은 연결률·다중 매칭 |
| 대표성 | 특정 채널·집단이 과소 관찰 | 집단별 누락·라벨률 차이 |
| 적시성 | 분석·운영 시점보다 늦게 도착 | 지연·배치 실패·재처리 증가 |
| 지속성 | 원천 시스템 변경으로 입력 중단 | 스키마·이벤트 변경 통지 누락 |
| 보안 | 민감정보 노출·과도 권한 | 원문 로그·공유 계정·반출 요청 |

“데이터 확보 90%”처럼 필드 수나 테이블 수만 세면 핵심 라벨 하나의 부재를 가릴 수 있다. 업무 중요도와 분석 의존성으로 핵심 데이터, 보완 가능 데이터, 선택 데이터를 구분한다.

### 2.2 초기 확인과 지속 통제

착수 직후 실제 표본을 추출해 기간·건수·키·분포·널·코드·라벨·시각을 확인한다. 데이터 사전이나 담당자의 말만 믿지 않는다. 이후에도 추출마다 스키마, 건수, 범위, 통제 합계와 분포를 자동·수동 점검한다.

```text
원천 계약 확인
  ├ 스키마·단위·코드·시각
  ├ 도착 주기·허용 지연·재처리
  ├ 품질 책임·변경 통지
  └ 접근·보존·삭제
        ↓
수집 검증 → 대사·프로파일 → 격리·수정 → 승인 데이터셋
```

데이터 계보는 원천에서 변환·특징·모델 입력까지 추적한다. 문제를 발견하면 어떤 실험·결과가 영향을 받았는지 찾을 수 있어야 한다.

### 2.3 대응 전략

- **회피**: 권리·품질 위험이 큰 원천을 범위에서 제외한다.
- **완화**: 표본 재라벨링, 코드 매핑, 추가 검증, 대체 특징을 준비한다.
- **대체**: 더 적합한 내부·외부 데이터나 수작업 기준을 사용한다.
- **단계화**: 데이터가 충분한 대상·기간부터 시작한다.
- **수용**: 영향이 작고 감시 가능한 누락은 한계를 명시하고 진행한다.
- **중단·전환**: 핵심 목표를 판정할 데이터가 없으면 수집·품질 과제로 바꾼다.

대체 데이터는 같은 개념을 측정하는지 확인한다. 웹 접속 빈도를 고객 관심의 대리값으로 쓰면 인터넷 이용 방식의 집단 차이가 편향을 만들 수 있다. 결측값을 단순 평균으로 채웠다고 확보 위험이 해결되는 것도 아니다.

### 2.4 데이터 이슈의 의사결정 기준

이슈를 발견하면 영향받는 대상·기간·실험, 오류 방향, 업무 결과, 수정 비용을 평가한다. 핵심 라벨 오류처럼 기존 결과를 무효화하면 즉시 중단·재실행하고, 일부 낮은 영향 필드의 결측이면 제외·민감도 분석 후 진행할 수 있다. 담당자가 임의로 묵인하지 않고 정해진 위험 소유자와 승인권자가 결정한다.

## 3. 모델 품질과 일정의 균형

### 3.1 모델 품질의 다차원성

**모델 품질과 일정의 균형**에서 품질은 최고 점수 하나가 아니다.

- 예측·분류·추정 성능과 불확실성
- 새 기간·집단에서의 일반화와 안정성
- 중요한 오류의 비용과 집단별 형평
- 현업이 이해·검토할 수 있는 설명 가능성
- 추론 지연, 가용성, 연산·사람 검토 비용
- 데이터 누락·변화·공격에 대한 견고성
- 재현성, 유지보수성, 모니터링 가능성

더 복잡한 모델이 검증 점수를 조금 높여도 처리 지연과 운영비가 크고 설명이 어려우면 수용되지 않을 수 있다. 반대로 일정 때문에 기준선보다 나쁜 모델을 배포해서도 안 된다. 최소 품질 기준을 지키면서 추가 개선의 한계 가치를 비교한다.

### 3.2 기준 모델과 개선 곡선

초기에 단순 규칙·현재 업무 방식·기본 모델의 성능과 비용을 측정한다. 후보 모델의 개선을 이 기준과 비교한다.

```text
추가 실험 1: 중요 오류 큰 폭 감소 / 비용 작음 → 우선
추가 실험 2: 전체 점수 소폭 상승 / 설명·지연 악화 → 재검토
추가 실험 3: 같은 결과 반복 / 일정 소진 큼 → 중단 후보
```

실험 횟수가 늘수록 검증 데이터에 맞춘 선택 편향이 생길 수 있다. 최종 평가는 별도로 보존한 데이터에서 수행하고, 실험마다 가설·변경·결과를 기록한다.

### 3.3 시간상자와 품질 관문

모델링 반복에 시간상자를 두고 다음 관문에서 판단한다.

| 관문 | 필수 증거 | 결정 예 |
|---|---|---|
| 신호 관문 | 데이터·라벨 진단, 기준 모델 | 신호 없음→수집/중단 |
| 방법 관문 | 후보 비교, 오류·안정성 | 유망 방법 선택·범위 축소 |
| 업무 관문 | 설명·과업·처리 용량 | 시제품 수정·시험 진행 |
| 운영 관문 | 지연·장애·모니터링·보안 | 제한 배포·보류·되돌림 |
| 가치 관문 | 기준 대비 순증 성과·부작용 | 확대·개선·중단 |

일정을 맞추기 위해 품질 관문을 삭제하지 않는다. 대신 적용 범위를 낮은 위험 대상으로 줄이거나 사람 검토를 추가하고, 운영 자동화는 다음 단계로 미룰 수 있다.

### 3.4 우선순위가 높은 개선

전체 점수보다 업무 영향이 큰 오류를 먼저 줄인다. 예를 들어 사기 탐지에서 고액 미탐, 의료 지원에서 위험 환자 누락, 상담 분류에서 개인정보 노출 오류가 중요할 수 있다. 데이터 누출·잘못된 라벨·비대표 분할은 모델 튜닝보다 먼저 고친다.

개선 백로그에는 가설, 예상 품질 효과, 일정·원가, 위험, 필요한 데이터와 판정 기준을 적는다. 기대 효과 대비 비용이 낮은 항목을 우선하고, 탐색 가치는 있지만 일정 내 증거가 어려운 항목은 후속 연구로 넘긴다.

### 3.5 일정 편차 대응

지연 원인이 데이터 승인처럼 외부 의존인지, 반복 오류처럼 내부 품질인지, 최초 추정이 틀린 구조 문제인지 구분한다.

- 작업 순서를 바꾸어 병렬로 할 수 있는 준비를 앞당긴다.
- 핵심 데이터·대상·산출물에 집중해 범위를 축소한다.
- 병목 역할에 자원을 추가하되 학습·협업 비용을 고려한다.
- 단순 모델과 사람 검토로 단계적 적용을 설계한다.
- 운영 전환을 미루고 탐색 결론·데이터 기반을 인계한다.
- 가치·안전 기준을 충족하지 못하면 중단한다.

야근이나 품질 검사 생략을 유일한 대응으로 삼지 않는다.

## 4. 반복 결과의 검토와 의사결정

### 4.1 반복 검토 자료

**반복 결과의 검토와 의사결정**을 위해 매 반복에서 다음을 같은 형식으로 제시한다.

1. 검증한 질문과 이전 가정
2. 사용한 데이터 버전·범위·품질·변경
3. 기준선과 후보 방법, 실험 설정
4. 전체·중요 오류·집단별 결과와 불확실성
5. 현업 사용성·운영 비용·위험 영향
6. 계획 대비 일정·원가·범위 편차
7. 새 학습, 남은 불확실성, 추천 대안
8. 필요한 결정과 결정 기한·책임자

그래프 한 장이나 평균 점수만으로 검토하지 않는다. 실패 사례의 원문 표본, 혼동행렬, 시간별 성능, 데이터 결측과 업무 시나리오를 함께 본다.

### 4.2 의사결정 선택지

| 결정 | 적용 상황 | 후속 조치 |
|---|---|---|
| 계속 | 가설이 지지되고 다음 실험 가치가 큼 | 다음 질문·시간상자 승인 |
| 보완 | 데이터·검증·설명 부족이 해결 가능 | 책임·기한·재검토 기준 설정 |
| 범위 축소 | 일부 대상에서만 품질·가치가 충분 | 적용·비적용 경계와 위험 기록 |
| 전환 | 예측보다 진단·수집·규칙이 적합 | 목표·산출물 변경 승인 |
| 제한 시험 | 기술·안전 기준 충족, 업무 효과 불확실 | 비교 설계·사람 검토·중단 기준 |
| 운영 확대 | 순증 가치와 운영 통제 증거 충분 | 모니터링·책임·변경 기준선 |
| 중단 | 핵심 신호·행동·권리·가치 부족 | 근거·학습·재사용 산출물 인계 |

검토 회의에서 “좋아 보인다”가 아니라 각 선택의 증거와 잔여 위험을 기록한다. 분석팀은 기술 권고를 하고 현업·후원자·위험 책임자가 권한에 따라 수용한다.

### 4.3 단계별 증거의 강도

탐색 단계의 결과는 가설 생성과 가능성 판단에는 충분할 수 있지만 자동 의사결정 배포의 근거로는 부족하다. 운영 영향이 클수록 독립 검증, 실제 환경 시험, 집단별 결과, 설명·이의 제기, 장애·되돌림의 강한 증거가 필요하다.

### 4.4 결정 기록과 후속 추적

결정 로그에는 날짜, 결정, 근거, 검토한 대안, 가정, 승인자, 후속 책임·기한, 재검토 촉발 조건을 기록한다. 모델을 선택하지 않은 이유도 남기면 같은 논쟁을 반복하지 않는다. 결정 후 위험 등록부·범위·일정·예산·산출물 기준선을 갱신한다.

## 5. 구체 사례: 반품 위험 예측

### 데이터 확보 위험

반품 사유가 상담 시스템에는 자유 문장, 물류 시스템에는 코드로 남아 서로 일치하지 않는다. 일부 채널은 반품 접수만 있고 실제 회수·검수 결과가 없다. 먼저 반품 라벨을 정의하고 기간·채널별 일치도를 표본 검토한다. 핵심 채널의 실제 결과가 없으면 첫 범위를 데이터가 완전한 채널로 제한하거나 라벨 개선 과제로 전환한다.

### 품질과 일정

초기 기준 모델은 전체 정확도가 높지만 반품이 드문 상품군을 거의 찾지 못한다. 복잡한 모델 추가보다 클래스별 오류, 비용, 상품군별 대표성을 먼저 본다. 출시 일정이 가깝다면 자동 주문 제한 대신 상담 검토 우선순위로 낮은 위험의 제한 시험을 할 수 있다.

### 반복 검토

반복 보고에는 채널별 라벨 신뢰도, 기준 대비 중요 반품 재현율, 정상 주문 오경보, 상담 처리 용량, 고객 불편, 추가 데이터 비용을 넣는다. 선택지는 전체 확대가 아니라 데이터 완전 채널 시험, 라벨 개선 후 재검토, 과제 중단까지 포함한다.

## 6. 실행 통제 체크리스트

- 최신 승인 범위·일정·원가·수용 기준을 사용하고 있는가?
- 핵심 데이터의 존재·권리·품질·결합·적시·지속 위험을 추적하는가?
- 데이터 변경이 기존 실험과 결과에 미친 영향을 찾아 재검증했는가?
- 모델 품질을 전체 점수 외에 중요 오류·집단·설명·지연·비용으로 보는가?
- 기준 모델과 추가 실험의 한계 가치를 비교하는가?
- 반복마다 질문·시간상자·산출물·중단 기준이 있는가?
- 현업 채택과 운영 장애를 모델 성능과 함께 검토하는가?
- 의사결정 대안, 근거, 잔여 위험, 승인자와 후속 책임을 기록하는가?
- 일정 대응으로 최소 안전·품질 기준을 삭제하지 않는가?
- 중단·전환에서도 데이터 정의·학습·재사용 산출물을 인계하는가?

## 7. 시험에서 자주 틀리는 포인트

1. 데이터 파일을 한 번 받으면 확보 위험이 끝났다고 본다.
2. 확보율을 필드·테이블 개수로만 계산해 핵심 라벨 부재를 숨긴다.
3. 결측 대치가 대표성·권리·적시성 위험도 해결한다고 본다.
4. 최고 모델 점수를 품질 전체로 본다.
5. 일정 단축을 위해 독립 검증과 안전 관문을 없앤다.
6. 반복 횟수가 많으면 자동으로 모델이 좋아진다고 본다.
7. 검증 데이터를 계속 보며 후보를 고르고 최종 평가라고 부른다.
8. 회의에서 결과만 보고 데이터 버전·오류 사례·업무 비용을 누락한다.
9. 분석가가 가치·위험 수용까지 혼자 결정한다.
10. 중단 결정에서 근거와 학습을 남기지 않는다.

## 정답과 해설

### 정답 1
기준선 확인, 실행 증거 수집, 편차·위험·학습 분석, 대안 평가, 계속·보완·조정·중단 결정, 기준선과 다음 반복 갱신 순이다.

### 정답 2
존재·범위, 접근·권리, 정의·품질, 결합, 대표성, 적시성, 지속성, 보안 중 다섯 가지다.

### 정답 3
대부분의 설명 변수가 있어도 예측할 핵심 결과 라벨이 잘못 기록되거나 운영 시점 이후에만 생성된다면 모델을 올바르게 학습·검증할 수 없다.

### 정답 4
대체 변수는 목표 개념을 직접 측정하지 않고 이용 환경·집단 특성에 따라 다르게 나타날 수 있어 특정 집단을 체계적으로 과소·과대평가할 수 있기 때문이다.

### 정답 5
예측 성능, 새 기간·집단 안정성, 중요 오류·형평, 설명 가능성, 지연·비용, 견고성, 재현·운영 가능성 중 여섯 가지다.

### 정답 6
현재 업무·단순 방법의 성능과 비용을 제공해 복잡한 모델의 순증 개선이 추가 시간·운영 위험을 정당화하는지 판단하게 한다.

### 정답 7
적용 범위 축소, 작업 순서 조정, 병목 자원 보강, 단순 모델+사람 검토, 운영 전환 연기, 안전 기준 미달 시 중단 중 네 가지다.

### 정답 8
질문·가정, 데이터 버전·품질, 기준·후보 방법, 전체·중요·집단별 결과, 현업·운영 영향, 일정·원가 편차, 새 학습·대안·결정 요청 중 여섯 가지다.

### 정답 9
제한 시험은 실제 효과를 학습하기 위한 통제된 작은 적용인 반면, 운영 확대는 더 많은 대상에게 지속적 영향을 주므로 독립 검증·안전·공정성·장애·되돌림과 순증 가치의 강한 증거가 필요하다.

### 정답 10
날짜, 결정 내용, 근거, 검토 대안, 가정·잔여 위험, 승인자, 후속 책임·기한, 재검토 촉발 조건 중 여섯 가지다.

## 핵심 요약

- **데이터 확보 위험 관리**는 존재·접근·품질·결합·대표성·적시·지속·보안을 초기부터 운영까지 추적하는 활동이다.
- 핵심 데이터가 부적합하면 대체·완화·단계화·범위 축소·수집 과제 전환·중단을 근거로 선택한다.
- **모델 품질과 일정의 균형**은 기준 모델 대비 순증 효과와 성능·안정·오류·설명·지연·비용을 함께 비교한다.
- 일정 압박에도 최소 품질·안전 관문을 없애지 않고 적용 범위·자동화 수준·작업 순서를 조정한다.
- **반복 결과의 검토와 의사결정**은 데이터 버전, 오류·업무·운영 증거, 편차와 대안을 바탕으로 계속·보완·축소·전환·시험·확대·중단을 결정한다.
- 결정 근거·잔여 위험·승인자·재검토 조건과 최신 기준선을 남겨야 반복 분석이 통제 가능한 학습이 된다.
