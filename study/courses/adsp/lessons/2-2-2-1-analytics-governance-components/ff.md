# 2-2-2-1. 분석 거버넌스의 구성

> **학습 범위**: 이 레슨은 ADsP `데이터분석 기획 > 분석 마스터플랜 > 분석 거버넌스 체계 수립` 중 **조직과 역할**, **프로세스와 운영 규정**, **분석 시스템과 데이터**를 다룬다. 분석을 일회성 프로젝트나 개인 역량에 맡기지 않고, 과제 발굴부터 운영·폐기까지 일관된 가치·품질·책임을 유지하는 거버넌스 체계를 설계하는 것이 목표다.

거버넌스는 결재 단계를 늘리는 통제 조직만을 뜻하지 않는다. 누가 과제를 선택하고 데이터를 승인하며 모델의 오류·변경·중단에 책임지는지, 어떤 표준 절차와 증거를 사용할지, 어떤 공통 시스템과 신뢰 가능한 데이터를 제공할지를 연결한다. 너무 약하면 중복·오용·책임 공백이 생기고, 너무 무거우면 작은 저위험 분석까지 지연된다. 가치와 위험에 비례한 통제가 중요하다.

---

## 1. 분석 거버넌스의 목적과 원칙

### 1.1 목적

- 전략과 분석 과제의 우선순위를 일치시킨다.
- 데이터·모델·의사결정의 품질과 재현성을 유지한다.
- 개인정보·보안·공정성·규제·윤리 위험을 통제한다.
- 중복 투자와 도구·지표·데이터 정의의 난립을 줄인다.
- 공통 자산을 재사용하고 전문 역량과 현업 채택을 키운다.
- 운영 모델의 변화·장애·오류를 감지하고 책임 있게 수정·중단한다.
- 가치와 비용을 측정해 포트폴리오를 지속적으로 개선한다.

### 1.2 설계 원칙

| 원칙 | 의미 |
|---|---|
| 가치 정렬 | 모든 분석은 문제·의사결정·성과 책임과 연결한다. |
| 명확한 책임 | 데이터·모델·업무 결정·운영 위험의 소유자를 구분한다. |
| 위험 비례 | 영향이 큰 분석에 더 강한 검증·승인·감사를 적용한다. |
| 생애주기 | 발굴·개발뿐 아니라 배포·감시·변경·폐기를 포함한다. |
| 추적·재현 | 데이터 계보, 코드·모델 버전, 결정 근거를 남긴다. |
| 재사용·표준 | 공통 정의·도구·패턴을 제공하되 현업 차이를 허용한다. |
| 독립 검토 | 중요한 모델은 개발자와 다른 관점에서 검증한다. |
| 지속 개선 | 사고·성과·변화를 규정·교육·시스템에 환류한다. |

```text
조직과 역할 ───── 의사결정·책임
      │                  │
프로세스와 운영 규정 ─ 표준·관문·증거
      │                  │
분석 시스템과 데이터 ─ 실행·추적·재사용 기반

세 요소가 함께 작동해야 거버넌스가 실효성을 가짐
```

## 2. 조직과 역할

### 2.1 주요 의사결정 층

**조직과 역할**은 명칭보다 책임의 완결성이 중요하다.

| 층·역할 | 핵심 책임 | 대표 결정 |
|---|---|---|
| 경영·전략 협의체 | 가치·우선순위·투자·중대 위험 | 포트폴리오·관문·위험 수용 |
| 분석 거버넌스 책임 | 정책·표준·성과·갈등 조정 | 공통 규정·예외·역량 계획 |
| 과제·현업 소유자 | 문제·업무 적용·성과·사람 결정 | 사용 범위·업무 수용·중단 |
| 데이터 소유자 | 데이터 목적·접근·품질·보존 책임 | 사용·공유·정정·삭제 승인 |
| 데이터 관리자 | 정의·표준·메타데이터·품질 운영 | 코드·사전·품질 규칙 관리 |
| 모델·분석 소유자 | 방법·성능·한계·변경 생애주기 | 모델 버전·재검증 권고 |
| 독립 검증·위험 | 편향·누출·안전·규정 검토 | 수용·조건부 승인·보완 권고 |
| 기술·운영 | 플랫폼·배포·감시·장애·보안 | 운영 변경·복구·접근 통제 |

한 사람이 여러 역할을 맡을 수 있지만 중요한 고위험 모델에서 개발과 최종 검증이 완전히 같으면 이해충돌이 생길 수 있다. 조직 규모에 맞게 교차 검토나 독립 승인 구조를 둔다.

### 2.2 중앙집중·분산·연합형 구조

| 구조 | 장점 | 한계 | 적합 상황 |
|---|---|---|---|
| 중앙집중 | 표준·전문성·도구 재사용, 통제 일관 | 현업 맥락·속도 부족, 병목 | 초기 역량 구축·고위험 공통 분석 |
| 분산 | 현업 문제 이해와 빠른 적용 | 중복·정의 불일치·품질 편차 | 부문 자율성과 성숙한 역량 |
| 연합형 | 중앙 표준·플랫폼+현업 실행 결합 | 책임 경계·조정 복잡 | 여러 사업부의 규모 있는 조직 |

중앙 조직이 모든 분석을 직접 수행할 필요는 없다. 표준, 공통 플랫폼, 고위험 검증과 전문 지원을 제공하고 현업 팀이 문제·적용을 소유하는 연합형을 선택할 수 있다. 최적 구조는 조직 크기, 규제, 데이터 공유, 현업 다양성과 역량에 따라 다르다.

### 2.3 책임 배분 원칙

- 하나의 중요 결정에는 최종 책임자를 명확히 한다.
- 데이터 소유와 업무 결정 소유, 모델 개발·운영 책임을 구분한다.
- 분석가는 결과의 한계를 설명하고 현업은 실제 사용 맥락과 성과를 책임진다.
- 공급자에게 개발을 맡겨도 조직의 위험·고객 책임은 사라지지 않는다.
- 오류를 발견한 사람이 안전하게 상향·중단할 권한을 갖게 한다.
- 예외 승인에는 이유·기한·보완 통제·재검토 책임을 둔다.

책임표를 작성할 때 모두를 승인자로 지정하면 의사결정이 지연된다. 담당, 최종 책임, 자문, 통보를 구분한다.

### 2.4 역량과 커뮤니티

거버넌스는 규정뿐 아니라 분석가·데이터 관리자·현업 분석 사용자 교육, 공통 사례·코드·검증 패턴 공유, 전문가 커뮤니티와 경력 체계를 포함한다. 현업이 데이터를 해석하고 질문할 수 있어야 중앙팀 병목과 무비판적 모델 사용을 줄일 수 있다.

## 3. 프로세스와 운영 규정

### 3.1 분석 생애주기 프로세스

**프로세스와 운영 규정**은 과제의 처음과 끝을 연결한다.

```text
과제 제안·등록
 → 가치·위험·우선순위 평가
 → 데이터 사용·분석 설계 승인
 → 개발·실험·독립 검증
 → 제한 시험·업무 수용
 → 배포·모니터링·변경
 → 정기 재검토·사고 대응
 → 폐기·대체·기록 보존
```

낮은 위험의 탐색 분석과 고객 권리에 영향을 주는 자동 결정에 같은 절차를 적용하면 비효율적이다. 위험 등급에 따라 필요한 문서·검증·승인·모니터링 깊이를 다르게 한다. 단, 낮은 위험이어도 데이터 권리와 기본 재현성은 지킨다.

### 3.2 과제 등록과 우선순위 규정

과제 등록에는 문제·의사결정·대상·예상 가치·데이터·위험·소유자를 포함한다. 중복 과제와 공통 기반을 식별하고 포트폴리오 기준으로 우선순위를 평가한다. 긴급 과제의 예외 절차와 기존 과제 자원 영향도 기록한다.

### 3.3 데이터 사용 규정

- 수집·이용 목적과 적법·정당한 근거
- 최소 필요 항목과 접근 역할·환경
- 민감도 분류, 반출·공유·결합·가명 처리
- 데이터 사전·품질·계보·원천 변경 통지
- 보존 기간·삭제·백업·감사 로그
- 오류 정정과 데이터 주체 권리·문의 처리

접근 승인은 한 번 받으면 영구 유효한 것이 아니다. 목적·데이터·사용자·환경·기간이 바뀌면 재검토한다.

### 3.4 분석·모델 표준

문제·목표 시점, 데이터 분할, 기준 모델, 누출 방지, 지표, 오류·집단별 평가, 불확실성, 재현성을 표준화한다. 모델 문서에는 목적·금지 사용, 데이터·라벨, 방법·성능, 한계·알려진 취약 집단, 설명, 운영 입력·출력, 모니터링·재학습·중단 조건을 담는다.

표준은 특정 알고리즘을 강제하기보다 검증해야 할 질문과 증거를 정한다. 고위험 모델은 독립 검증과 실제 영향 시험, 사람 검토·이의 제기, 되돌림을 추가한다.

### 3.5 배포·변경·모니터링 규정

승인된 모델·코드·데이터 계약만 운영에 배포하고 버전·승인·되돌림을 추적한다. 입력 분포, 누락·지연, 성능·집단별 오류, 업무 성과, 사용률, 장애·비용을 감시한다.

재학습은 자동으로 새 모델을 운영에 바꾸는 것과 다르다. 새 데이터 품질, 성능·영향, 회귀·보안 검토와 승인을 거쳐야 한다. 긴급 수정도 사후 기록과 검토를 남긴다.

### 3.6 사고·이슈·이의 제기

잘못된 결과, 데이터 유출, 집단 불이익, 분포 변화, 서비스 장애의 신고·분류·봉쇄·복구·통지·원인 분석과 재발 방지 절차를 둔다. 영향 대상이 결과 이유를 확인하고 오류 데이터를 정정하거나 사람 재검토를 요청할 경로를 설계한다.

### 3.7 폐기 규정

목적 종료, 성능 저하, 데이터 권리 변경, 대체 모델, 비용·위험 증가 시 폐기를 검토한다. 호출을 중단하고 의존 시스템을 전환하며 모델·접근 권한·데이터·복제본을 보존 정책에 따라 처리한다. 결정·감사에 필요한 기록은 정해진 기간 동안 보관한다.

## 4. 분석 시스템과 데이터

### 4.1 시스템 구성

**분석 시스템과 데이터**는 거버넌스 규정을 실제 실행·증명하는 기반이다.

| 시스템 능력 | 거버넌스 목적 |
|---|---|
| 데이터 카탈로그·사전 | 데이터 의미·소유자·품질·사용 조건 발견 |
| 계보·메타데이터 | 원천부터 보고·모델까지 영향 추적 |
| 접근·권한·비밀 관리 | 최소 권한, 분리, 만료·감사 |
| 품질·대사 | 오류·누락·분포·계약 위반 탐지 |
| 버전·실험 추적 | 코드·데이터·모델·결과 재현 |
| 모델 등록·배포 | 승인 버전·환경·되돌림 통제 |
| 모니터링·알림 | 입력·성능·업무·위험 변화 감지 |
| 이슈·결정 기록 | 예외·사고·승인·변경 책임 추적 |

도구를 설치했다고 거버넌스가 작동하는 것은 아니다. 소유자, 갱신 프로세스, 품질 지표와 실제 사용이 없으면 카탈로그도 오래된 목록이 된다. 반대로 모든 통제를 수작업 문서로만 하면 규모가 커질수록 누락된다. 정책과 자동화·사람 검토를 조합한다.

### 4.2 데이터 표준과 메타데이터

고객, 매출, 이탈처럼 핵심 용어의 업무 정의, 계산식, 코드, 단위, 적용 기간, 소유자를 관리한다. 기술 스키마뿐 아니라 업무 의미와 품질 기준이 필요하다. 동일 명칭의 서로 다른 정의와 다른 명칭의 같은 개념을 식별한다.

메타데이터에는 원천·생성 시각, 갱신 주기, 민감도, 계보, 품질·제약, 사용 승인과 변경 이력을 연결한다. 사용자는 데이터가 자신의 분석 시점·대상에 적합한지 판단할 수 있어야 한다.

### 4.3 데이터 품질 책임

품질 문제를 중앙팀이 모두 고치는 구조는 지속되지 않는다. 원천 업무 소유자가 생성 규칙과 정정을, 데이터 관리자가 표준·측정을, 사용자가 목적별 적합성과 발견 오류를 책임지는 분담이 필요하다.

품질 지표는 전체 평균뿐 아니라 핵심 필드·집단·기간별로 본다. 오류가 모델과 의사결정에 미친 영향을 계보로 추적하고, 중요도에 따라 원천 수정·격리·재실행·공지한다.

### 4.4 분석·모델 자산 관리

모델만 등록하지 않고 목적, 소유자, 데이터·코드 버전, 승인 상태, 사용 시스템, 성능·한계, 모니터링, 마지막 검토·만료일을 관리한다. 동일 목적의 중복 모델과 승인되지 않은 개인 모델이 운영에 쓰이는 것을 찾는다.

특징·전처리·평가 코드의 재사용은 일관성과 속도를 높이지만, 목적·시점이 다른 과제에 무비판적으로 적용하면 데이터 누출과 편향을 복제할 수 있다. 재사용 조건과 검증 범위를 문서화한다.

### 4.5 보안·격리·감사

개발·시험·운영 환경을 구분하고 민감 데이터 접근을 역할·기간·목적에 제한한다. 원문을 로컬 파일이나 로그에 복제하지 않도록 통제한다. 누가 어떤 데이터와 모델을 조회·변경·배포했는지 감사할 수 있어야 한다. 공유 계정은 책임 추적을 어렵게 한다.

## 5. 거버넌스 운영 지표

거버넌스 성과를 승인 건수나 문서 수만으로 측정하면 관료화될 수 있다.

| 목표 | 지표 방향 예 |
|---|---|
| 가치 정렬 | 전략 과제의 실제 업무 성과·중단 의사결정 |
| 속도 | 승인·데이터 준비·배포 소요와 병목 |
| 품질 | 재현 실패, 데이터 계약 위반, 운영 성능 저하 |
| 재사용 | 공통 데이터·코드·플랫폼 사용과 준비 시간 감소 |
| 책임 | 미소유 자산, 기한 지난 검토, 예외 장기화 |
| 위험 | 사고·불리한 영향·이의 처리와 재발 방지 |
| 역량 | 교육 후 실제 적용, 현업·전문가 참여 |

빠른 처리만 목표로 하면 통제가 약해지고, 위반 0만 목표로 하면 신고를 숨길 수 있다. 발견·대응 시간과 학습·개선까지 본다.

## 6. 사례: 고객 추천 거버넌스

### 조직과 역할

마케팅 소유자는 추천 목적·캠페인·성과를, 데이터 소유자는 구매·행동 데이터 사용과 품질을, 분석 소유자는 모델 검증·한계를, 채널 운영자는 화면·장애를 책임진다. 독립 검토는 민감 특성 대리·집단별 노출·과도한 접촉을 확인한다.

### 프로세스와 규정

과제 등록에서 순증 가치와 금지 추천 대상을 정의한다. 데이터 사용 목적·보존, 시간 분할 검증, 기준 추천, 집단별 오류·노출 다양성, 제한 시험과 고객 제어를 요구한다. 모델 변경은 승인·비교 시험을 거치고 성능·클릭뿐 아니라 반품·피로·이의·장기 다양성을 감시한다.

### 시스템과 데이터

고객·상품 정의와 동의 상태, 데이터 계보를 카탈로그에 둔다. 승인 모델 버전과 특징을 등록하고, 추천 요청·노출·반응·오류를 상관 ID로 추적한다. 동의 철회·입력 누락 시 비개인화 기본값으로 전환한다.

추천 매출만 높다고 거버넌스 목적을 달성한 것이 아니다. 과도한 개인화, 편향된 노출과 예상하지 못한 데이터 사용을 통제하면서 고객·사업 가치를 지속해야 한다.

## 7. 거버넌스 설계 판단 절차

1. 조직의 전략·분석 유형·규제·오류 영향을 분류한다.
2. 현재 과제 발굴부터 폐기까지 책임·절차·시스템 공백을 찾는다.
3. 중앙·분산·연합 구조와 의사결정 층을 조직 맥락에 맞게 정한다.
4. 데이터·모델·업무·운영의 소유·검증·승인 책임을 배정한다.
5. 위험 등급별 필수 생애주기 절차·산출물·관문을 정한다.
6. 데이터 표준·계보·품질, 실험·모델 버전, 배포·감시 시스템을 연결한다.
7. 교육·커뮤니티·공통 자산과 현업 참여 방식을 마련한다.
8. 작은 과제에서 절차의 속도·효과·부담을 시험해 조정한다.
9. 가치·속도·품질·재사용·위험 지표로 운영하고 사고·변화를 환류한다.

## 8. 시험에서 자주 틀리는 포인트

1. 분석 거버넌스를 중앙 통제 조직 또는 승인 회의 하나로 본다.
2. 모든 분석에 같은 무거운 절차를 적용한다.
3. 중앙집중이 항상 좋거나 분산이 항상 민첩하다고 본다.
4. 데이터 소유자와 모델·업무 결정 책임을 한 역할로 혼동한다.
5. 외부 공급자에게 개발을 맡기면 조직 책임도 이전된다고 본다.
6. 모델 개발·배포까지만 규정하고 변경·사고·폐기를 누락한다.
7. 데이터 카탈로그 도구 설치를 데이터 거버넌스 완료로 본다.
8. 모델 정확도만 등록하고 목적·금지 사용·한계·소유자를 기록하지 않는다.
9. 승인 건수와 문서 수가 많을수록 거버넌스가 우수하다고 본다.
10. 실제 사용자·분석 대상자의 설명·이의·정정 경로를 제외한다.

## 정답과 해설

### 정답 1
조직과 역할은 의사결정·책임을, 프로세스와 규정은 생애주기 표준·관문을, 시스템과 데이터는 실행·추적·재사용 기반을 제공한다. 세 요소가 연결되어야 실효성이 있다.

### 정답 2
가치 정렬, 명확한 책임, 위험 비례, 생애주기, 추적·재현, 재사용·표준, 독립 검토, 지속 개선 중 다섯 가지다.

### 정답 3
데이터 소유자는 이용 목적·접근·품질·보존을, 모델 소유자는 방법·성능·한계·버전을, 현업 소유자는 실제 의사결정·성과·사용 범위와 사람 영향을 책임진다.

### 정답 4
중앙집중은 표준·전문성이 강하지만 병목과 현업 거리 위험, 분산은 현업 속도가 높지만 중복·품질 편차 위험, 연합형은 두 장점을 결합하지만 책임 경계 조정이 복잡하다.

### 정답 5
탐색 보고서와 생명·권리에 영향을 주는 자동 결정의 오류 영향이 다르기 때문이다. 영향이 클수록 독립 검증·승인·설명·감시·감사를 강화해야 한다.

### 정답 6
과제 제안·등록, 가치·위험·우선순위, 데이터·설계 승인, 개발·검증, 제한 시험·업무 수용, 배포·감시·변경, 정기 검토·사고 대응, 폐기 순이다.

### 정답 7
목적·금지 사용, 소유자, 데이터·라벨, 방법·성능, 주요 오류·집단별 결과, 한계, 설명, 운영 입출력, 모니터링·재학습·중단 중 여섯 가지다.

### 정답 8
카탈로그·사전, 계보, 접근 통제, 품질·대사, 버전·실험 추적, 모델 등록·배포, 모니터링, 이슈·결정 기록 중 다섯 가지다.

### 정답 9
소유자와 갱신 책임, 업무 정의·품질·계보, 접근 절차와 실제 사용자 채택이 없으면 목록이 빠르게 낡고 의사결정에 쓰이지 않기 때문이다.

### 정답 10
문서·승인이 많아도 가치가 없거나 지연만 늘 수 있다. 실제 업무 성과, 승인·데이터 준비 속도, 재현·품질 위반, 공통 자산 재사용, 위험 탐지·대응·재발 방지를 함께 본다.

## 핵심 요약

- **조직과 역할**은 전략 협의체, 현업·데이터·모델·운영 소유자와 독립 검증의 의사결정·책임을 배정한다.
- 중앙집중·분산·연합 구조는 조직 규모·규제·현업 다양성·역량에 맞게 선택하며 위험이 큰 결정은 독립성을 확보한다.
- **프로세스와 운영 규정**은 과제 등록부터 데이터 승인, 개발·검증, 시험, 배포·감시·변경, 사고·이의, 폐기까지 위험 비례로 적용한다.
- **분석 시스템과 데이터**는 카탈로그·계보·품질·권한·버전·배포·모니터링으로 정책을 실행하고 증명한다.
- 거버넌스는 도구·조직·문서 하나가 아니라 사람·절차·기술의 연결이며 외부 조달로 최종 책임이 사라지지 않는다.
- 가치·속도·품질·재사용·책임·위험 지표와 지속적 학습으로 관료화와 무통제 사이의 균형을 유지한다.
