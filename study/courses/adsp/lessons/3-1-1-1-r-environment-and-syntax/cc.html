01

1. 학습 목표와 실기 판단 기준

학습을 마치면 R 자체와 RStudio의 역할을 구분하고, 콘솔과 스크립트 중 어느 곳에서 명령을 실행해야 하는지 설명할 수 있어야 한다. 또한 유효한 이름으로 객체를 만들고 산술·비교·논리 연산을 수행하며, 막힌 함수는 도움말에서 인수와 반환값을 확인하고, 현재 작업공간을 점검할 수 있어야 한다.

시험에서는 단순히 실행 결과를 외우기보다 다음 판단 순서를 적용한다.

  1. 지금 보고 있는 것은 언어 실행기인 R인가, 작업을 돕는 통합 개발 환경인가?
  2. 기호가 객체에 값을 대입하는 연산자인가, 두 값을 비교하는 연산자인가?
  3. 연산의 우선순위와 벡터 길이가 결과에 영향을 주는가?
  4. 객체가 존재하는지, 이름의 대소문자가 일치하는지 확인했는가?
  5. 함수의 사용법을 추측하지 않고 도움말의 Usage와 Arguments를 확인했는가?
  6. 결과를 콘솔 기록에만 두지 않고 스크립트에 남겼는가?
02

2. R과 RStudio 환경

2.1 R의 역할

R은 통계 계산, 데이터 처리, 시각화를 위한 언어이자 실행 환경이다. 사용자가 표현식을 입력하면 R이 해석하고 결과를 반환한다. RStudio는 R을 더 편리하게 쓰도록 콘솔, 소스 편집기, 객체 목록, 도움말과 파일 탐색기 등을 한 화면에 배치한 통합 개발 환경이다. 따라서 RStudio를 설치했다고 해서 R 언어의 규칙이 달라지지 않으며, RStudio 없이도 R은 실행될 수 있다.

2. R과 RStudio 환경 · 학습 표 1
구분RRStudio
핵심 역할코드를 해석하고 계산을 수행코드 작성·실행·탐색을 지원

시험 판단언어 및 실행 환경R을 사용하는 IDE

RStudio의 Source 패널에는 재실행할 코드를 작성하고, Console에는 선택한 코드의 즉시 결과와 오류가 나타난다. Environment 패널은 현재 세션에 존재하는 객체를 보여 주고, Help 패널은 함수 문서를 표시한다. 콘솔에만 입력한 명령은 수정 이력과 실행 순서를 잃기 쉬우므로 분석 절차는 스크립트에 남기는 것이 원칙이다.

2.2 재현 가능한 시작 절차

안정적인 작업은 다음 순서로 시작한다.

  1. 분석별 프로젝트 또는 전용 폴더를 정한다.
  2. 새 R 스크립트를 만들고 목적, 입력, 기대 결과를 주석으로 기록한다.
  3. R 버전과 세션 정보를 확인한다.
  4. 필요한 객체를 스크립트에서 처음부터 생성한다.
  5. 위에서 아래로 다시 실행해 같은 결과가 나오는지 확인한다.

R.version.string sessionInfo()

sessionInfo 함수의 결과는 R 버전, 운영체제, 로케일, 붙어 있는 패키지 정보를 포함한다. 버전 차이로 결과가 달라질 가능성을 검토할 때 유용하다. 시험에서 RStudio 버전과 R 버전을 같은 것으로 취급하면 오답이다.

현재 위치는 getwd 함수로 확인한다. 경로는 문자열을 직접 이어 붙이기보다 file.path 함수를 이용하면 운영체제별 구분자 차이를 줄일 수 있다.

getwd() inputpath <- file.path('data', 'sales.csv') inputpath

여기서는 실제 파일을 읽지 않는다. 고정된 예제 데이터를 코드 안에서 만들면 외부 파일이나 네트워크에 의존하지 않아 누구나 결과를 재현할 수 있다.

3. 객체 생성과 연산자

3.1 객체와 대입

R의 객체는 값에 이름을 붙여 재사용하게 하는 단위다. 일반적으로 왼쪽 대입 연산자 <- 를 사용한다. = 도 많은 문맥에서 대입에 쓰이지만, 함수 인수 이름을 지정하는 = 과 혼동하기 쉬우므로 학습 코드에서는 <- 를 일관되게 쓰는 편이 명확하다.

unitprice <- 12000 quantity <- 3 totalprice <- unitprice * quantity totalprice # 36000

객체 이름은 영문자 또는 점으로 시작할 수 있으나 점 다음에 숫자가 바로 오면 안 된다. 이후에는 문자, 숫자, 점, 밑줄을 사용할 수 있다. R은 대소문자를 구분하므로 score, Score, SCORE는 서로 다른 이름이다. 함수 이름과 지나치게 비슷하거나 의미 없는 x1 같은 이름보다 unit_price처럼 역할이 드러나는 이름이 유지보수에 유리하다.

다음 점검 함수가 유용하다.

ls() exists('totalprice') class(totalprice) typeof(total_price)

ls는 현재 작업공간의 객체 이름을 보여 주고 exists는 특정 이름의 존재 여부를 논리값으로 반환한다. class는 객체를 어떤 방식으로 다룰지 나타내는 상위 수준 분류이고, typeof는 내부 저장 유형을 보여 준다. 둘은 항상 같은 문자열을 반환하는 함수가 아니다.

3.2 산술 연산자

3. 객체 생성과 연산자 · 학습 표 2
연산자의미예
+, -덧셈, 뺄셈8 + 2, 8 - 2
*, /곱셈, 나눗셈8 * 2, 8 / 2
^거듭제곱2 ^ 3
%%나머지17 %% 5
%/%정수 나눗셈의 몫17 %/% 5
:연속 정수 수열1:5

괄호가 우선하며, 그다음 거듭제곱, 단항 부호, 곱셈·나눗셈, 덧셈·뺄셈 순으로 해석된다. 우선순위를 암기하는 것보다 의도를 괄호로 명시하는 습관이 안전하다.

base <- 10 rate <- 0.2 base * (1 + rate) # 12

R의 기본 연산은 벡터화되어 여러 값에 한꺼번에 적용된다.

price <- c(1000, 1500, 2000) quantity <- c(2, 1, 3) amount <- price * quantity amount # 2000 1500 6000

두 피연산자의 길이가 다르면 짧은 쪽이 반복되는 재활용 규칙이 적용된다. 긴 길이가 짧은 길이의 배수가 아니면 경고가 날 수 있고, 배수이면 경고 없이 실행되어 의도하지 않은 결과가 생길 수 있다. 따라서 계산 전 length를 확인하거나 길이가 같은지 명시적으로 검사한다.

3.3 비교와 논리 연산자

3. 객체 생성과 연산자 · 학습 표 3
연산자의미주의점
==, !=같다, 다르다=는 비교가 아니라 다른 역할
<, <=, >, >=대소 비교경계 포함 여부 확인
&원소별 AND벡터 각 위치를 비교
|원소별 OR벡터 각 위치를 비교
!NOT논리값을 반전
&&, ||첫 원소만 단축 평가주로 if의 단일 조건
%in%집합에 포함되는지 검사여러 후보 비교에 적합

score <- c(72, 88, 91) passed <- score >= 80 excellent <- score >= 90 passed & !excellent # FALSE TRUE FALSE

grade <- c('B', 'A', 'C') grade %in% c('A', 'B') # TRUE TRUE FALSE

벡터 전체가 조건을 만족하는지 묻는다면 all, 하나라도 만족하는지 묻는다면 any를 사용한다.

all(score >= 60) any(score >= 90)

실수 계산은 표현 오차 때문에 ==가 기대와 달라질 수 있다. 허용 오차를 고려할 때는 all.equal의 결과가 TRUE인지 확인하거나 차이의 절댓값을 기준과 비교한다.

isTRUE(all.equal(0.1 + 0.2, 0.3)) abs((0.1 + 0.2) - 0.3) < 1e-8

3.4 안전한 작은 분석 예시

고정된 주문 금액으로 목표 달성 여부를 판정해 보자.

orderamount <- c(42000, 58000, 73000, 49000) target <- 50000 reached <- orderamount >= target achievementrate <- mean(reached) * 100 achievementrate # 50

논리값 TRUE와 FALSE는 많은 산술 문맥에서 각각 1과 0으로 처리되므로 mean(reached)는 TRUE의 비율이 된다. 다만 이 성질을 사용할 때는 reached가 논리 벡터인지 확인해야 한다. 객체 생성, 비교, 집계가 스크립트에 차례로 남아 있어 새 세션에서도 동일하게 실행된다.

4. 도움말과 작업공간

4.1 도움말을 읽는 절차

함수 이름을 알면 ?mean 또는 help('mean')으로 문서를 연다. 이름은 모르지만 개념어를 안다면 help.search('arithmetic mean') 또는 ??mean처럼 검색한다. args(mean)은 인수 형태를 빠르게 확인하고 example(mean)은 제공되는 예제를 실행한다.

?mean help('mean') args(mean) help.search('arithmetic mean')

도움말은 보통 Description, Usage, Arguments, Details, Value, Examples로 구성된다. 문제 해결 순서는 다음과 같다.

  1. Usage에서 함수 호출 형태와 기본값을 확인한다.
  2. Arguments에서 각 인수가 기대하는 값과 길이를 읽는다.
  3. Value에서 반환되는 객체의 의미와 구조를 확인한다.
  4. Details에서 예외 규칙과 결측값 처리 규칙을 확인한다.
  5. Examples를 작은 고정 입력으로 재현한다.

함수 이름이 여러 패키지에 겹칠 수 있다. 이때 package::function 형태는 어느 패키지의 함수를 부르는지 명시한다. 현재 레슨에서는 외부 패키지를 설치하지 않지만, 이름 충돌의 진단 원리로 알아 둔다.

4.2 작업공간의 의미

작업공간은 현재 R 세션에 존재하는 객체의 집합이다. ls로 이름을 보고, 특정 객체는 rm으로 제거한다.

temporaryvalue <- 99 exists('temporaryvalue') rm(temporaryvalue) exists('temporaryvalue') # FALSE

rm(list = ls())는 모든 객체를 제거하므로 학습 중 무심코 실행하면 필요한 결과도 사라진다. 문제 해결을 위해 무조건 전체 삭제하기보다 제거 대상 이름을 확인하고 좁게 지정한다. 객체를 저장한 .RData를 자동 복원하면 스크립트에 없는 객체가 우연히 남아 성공하는 숨은 의존성이 생길 수 있다. 따라서 스크립트를 처음부터 실행해 필요한 객체를 모두 다시 만들 수 있어야 한다.

작업 디렉터리는 파일 경로를 해석하는 기준 위치이고 작업공간은 메모리의 객체 집합이다. 이름이 비슷해도 서로 다른 개념이다. setwd로 경로를 계속 변경하는 코드는 실행자마다 깨질 수 있으므로 프로젝트 기준 상대 경로와 file.path를 우선한다.

5. 통합 업무 사례

교육 담당자가 네 명의 실습 점수로 합격률을 보고한다고 하자. 입력은 스크립트에 고정하고, 기준도 별도 객체로 둔다.

traineescore <- c(78, 84, 91, 67) passcutoff <- 80 passflag <- traineescore >= passcutoff passrate <- mean(pass_flag)

exists('passrate') class(passflag) pass_rate # 0.5

판단 과정은 다음과 같다.

  1. traineescore와 passcutoff가 생성되었는지 확인한다.
  2. 비교 연산 결과가 논리 벡터인지 확인한다.
  3. 네 점수와 네 판정의 길이가 같은지 확인한다.
  4. mean이 논리값을 1과 0으로 계산한다는 의미를 설명한다.
  5. 모든 코드를 새 세션에서 위에서 아래로 다시 실행한다.

산출물은 실행 가능한 R 스크립트, 사용한 입력과 기준에 대한 주석, sessionInfo 기록, 기대 결과다. 점수 자료구조의 세부 조작이나 결측값 보정은 후속 레슨 범위다.

06

6. 시험 함정과 오답 교정

  1. R과 RStudio를 같은 프로그램이라고 단정한다. R은 언어·실행 환경이고 RStudio는 이를 지원하는 IDE다.
  2. <-와 ==를 혼동한다. 전자는 대입, 후자는 동등 비교다.
  3. =를 모든 상황에서 비교 연산자로 본다. 비교는 ==를 사용한다.
  4. 대소문자를 무시한다. R의 객체 이름은 대소문자를 구분한다.
  5. &와 &&를 같다고 본다. &는 원소별, &&는 첫 원소 중심의 단축 평가다.
  6. 길이가 다른 벡터 계산을 무조건 오류라고 본다. 재활용될 수 있으며, 그것이 오히려 위험 요소다.
  7. 실수의 == 결과를 항상 신뢰한다. 표현 오차를 고려해 all.equal 또는 허용 오차를 쓴다.
  8. 콘솔 기록만으로 재현 가능하다고 생각한다. 명령 순서와 입력을 스크립트에 남겨야 한다.
  9. 작업공간과 작업 디렉터리를 혼동한다. 전자는 객체, 후자는 경로 기준이다.
  10. 막힌 함수를 추측으로 호출한다. 도움말의 Usage, Arguments, Value를 확인한다.

9. 정답과 해설

  1. 정답 2. R은 언어와 실행 환경이며 RStudio는 소스 편집기와 콘솔 등을 제공하는 IDE다.
  2. 정답 2. <-는 명시적인 왼쪽 대입 연산자다. ==는 동등 비교다.
  3. 정답 3. R은 대소문자를 구분하므로 두 이름은 별개다.
  4. 정답 1. %%는 나머지를 구하므로 17을 5로 나눈 나머지는 2다.
  5. 정답 2. &는 벡터의 대응 원소별로 AND를 계산한다. &&는 첫 원소를 중심으로 단축 평가한다.
  6. 정답 2. 짧은 쪽이 재활용될 수 있으며 의도하지 않은 계산도 실행될 수 있어 length 점검이 필요하다.
  7. 정답 2. args는 함수의 형식 인수와 기본값을 간단히 보여 준다.
  8. 정답 1. exists는 주어진 이름의 객체가 환경에 존재하는지 논리값으로 반환한다.
  9. 정답 2. 작업공간은 현재 세션에서 이름으로 접근할 수 있는 객체 집합이다. 경로 기준인 작업 디렉터리와 다르다.
  10. 정답 3. 입력과 전 처리 순서가 스크립트에 있고 새 세션에서도 실행되어야 숨은 객체 의존성을 줄일 수 있다.
10

10. 핵심 요약

  • R은 계산을 실행하는 언어·환경이고 RStudio는 이를 지원하는 IDE다.
  • 콘솔은 즉시 확인에 유용하지만 재현할 절차는 스크립트에 남긴다.
  • 객체는 의미 있는 이름과 <-로 생성하며 R은 대소문자를 구분한다.
  • 산술·비교·논리 연산에서는 우선순위, 벡터 길이, 원소별 연산 여부를 확인한다.
  • 길이가 다른 벡터는 재활용될 수 있으므로 경고 유무만 믿지 않는다.
  • 함수는 도움말의 Usage, Arguments, Value를 읽어 요구 조건과 반환값을 확인한다.
  • ls와 exists는 객체 상태를, getwd는 경로 기준을 확인하며 두 개념을 혼동하지 않는다.
  • 고정 입력과 세션 정보를 남기고 새 세션에서 처음부터 실행하는 것이 재현성의 기본이다.
