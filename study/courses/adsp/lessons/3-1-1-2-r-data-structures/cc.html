1. 학습 목표와 구조 선택 원리

분석 코드의 오류는 계산식보다 데이터를 잘못된 구조에 넣어서 생기는 경우가 많다. 학습 후에는 차원 수, 원소의 동질성, 열별 자료형, 범주 수준의 필요 여부를 근거로 벡터·행렬·리스트·배열·데이터 프레임·요인을 선택할 수 있어야 한다.

구조 선택은 다음 네 질문으로 시작한다.

  1. 값이 1차원인가, 2차원인가, 3차원 이상인가?
  2. 모든 원소가 같은 원자 자료형이어야 하는가?
  3. 행과 열이 관측치와 변수로 해석되는 직사각형 자료인가?
  4. 값 자체뿐 아니라 범주의 가능한 수준과 순서도 보존해야 하는가?

02

2. 벡터와 행렬

2.1 벡터의 성질

벡터는 R의 가장 기본적인 1차원 구조다. c 함수로 값을 결합한다.

score <- c(82, 91, 76, 88) student <- c('민수', '지영', '수빈', '현우') passed <- c(TRUE, TRUE, FALSE, TRUE)

각 벡터의 모든 원소는 동일한 원자 자료형을 공유한다. 대표 원자형은 logical, integer, double, character, complex, raw다. 숫자 뒤에 L을 붙이면 명시적으로 integer를 만들 수 있지만 일반 수치 상수는 보통 double이다.

integervalue <- 3L doublevalue <- 3 typeof(integervalue) typeof(doublevalue)

서로 다른 원자형을 한 벡터에 넣으면 공통으로 표현 가능한 형으로 강제 변환된다. 일반적으로 logical에서 integer, double, character 방향으로 변환 범위가 넓어진다.

mixed <- c(TRUE, 2, '3') typeof(mixed) # character

문자 '3'이 하나 들어가면서 TRUE와 2도 문자 표현으로 바뀐다. 출력 모양만 보고 숫자라고 생각하면 이후 평균 계산이 실패할 수 있으므로 str, typeof, class로 확인한다.

벡터에는 names 속성으로 각 원소의 의미를 붙일 수 있다.

monthlysales <- c(120, 135, 128) names(monthlysales) <- c('1월', '2월', '3월') monthly_sales

이름은 값과 별도의 속성이며 원소 자료형을 바꾸지 않는다. length는 원소 수를 반환한다. 벡터는 엄밀히 행이나 열의 방향을 가지지 않으므로 1×n 행렬과 같은 개념이 아니다.

2.2 행렬의 성질

행렬은 행과 열을 가진 2차원 원자 구조다. matrix 함수의 nrow, ncol로 모양을 정한다. 기본 채움 방향은 열 방향이며 byrow = TRUE를 주면 행 방향으로 채운다.

salesmatrix <- matrix( c(12, 15, 18, 20, 17, 22), nrow = 2, byrow = TRUE ) rownames(salesmatrix) <- c('온라인', '매장') colnames(salesmatrix) <- c('1월', '2월', '3월') salesmatrix

위 행렬은 온라인 행에 12, 15, 18이, 매장 행에 20, 17, 22가 배치된다. byrow의 기본값을 잊으면 같은 값이 다른 위치에 들어간다. dim은 행과 열 수를, nrow와 ncol은 각각 한 축의 크기를 알려 준다.

dim(salesmatrix) nrow(salesmatrix) ncol(sales_matrix)

행렬도 벡터처럼 모든 원소가 같은 자료형이어야 한다. 수치 행렬에 문자 하나를 결합하면 전체가 문자형으로 강제 변환될 수 있다. 제품명 같은 식별 열과 수치 열을 한 행렬에 억지로 넣기보다 열별 자료형을 허용하는 데이터 프레임을 사용한다.

행렬은 동일 단위의 수치 연산에 적합하다. 연산자 는 원소별 곱셈이고 행렬곱은 %%이므로 구분해야 한다. 구조를 고르는 문제에서 단순히 표처럼 보인다는 이유만으로 행렬이라고 판단하지 말고 열의 자료형이 같은지 확인한다.

3. 리스트와 배열

3.1 리스트

리스트는 요소마다 길이와 자료형, 구조가 달라도 되는 컨테이너다. 분석 결과의 수치, 설명, 판정, 표를 하나로 묶기에 알맞다.

report <- list( title = '분기 품질 보고', average = 87.5, passed = TRUE, scores = c(82, 91, 89, 88) ) str(report)

report는 문자 하나, 수치 하나, 논리값 하나, 수치 벡터를 함께 보관한다. 리스트 안에 또 다른 리스트나 데이터 프레임을 넣을 수도 있으므로 중첩 구조를 표현할 수 있다. 다만 구조가 자유로운 만큼 요소 이름과 의미를 문서화하지 않으면 사용자가 반환값을 이해하기 어렵다.

리스트의 length는 최상위 요소 수를 의미한다. 내부에 있는 scores의 원소 수를 자동으로 합산하지 않는다. unlist는 재귀적으로 원소를 벡터로 펴지만 서로 다른 형이 섞이면 강제 변환될 수 있어 구조를 잃을 위험이 있다.

리스트는 다음 상황에 적합하다.

  • 한 함수가 통계량, 상태, 진단 메시지를 함께 반환할 때
  • 길이가 다른 여러 벡터를 이름으로 묶을 때
  • 모델 결과처럼 구성 요소가 서로 다른 복합 객체를 담을 때

모든 항목이 같은 길이의 열이고 행 단위 관측치로 해석된다면 리스트보다 데이터 프레임이 더 명확하다.

3.2 배열

배열은 행렬을 3차원 이상으로 일반화한 원자 구조다. 모든 원소는 같은 자료형이고 dim 속성으로 각 축의 크기를 갖는다.

performance <- array( 1:12, dim = c(2, 3, 2), dimnames = list( 지점 = c('서울', '부산'), 월 = c('1월', '2월', '3월'), 지표 = c('매출', '건수') ) ) dim(performance) # 2 3 2

이 배열은 지점 2개, 월 3개, 지표 2개의 조합에 12개 값을 저장한다. 세 축의 의미와 순서를 dimnames로 명시하면 숫자 위치만 기억하는 오류를 줄일 수 있다. 시계열처럼 한 축에 시간, 다른 축에 측정 대상, 또 다른 축에 조건이 있는 경우에 유용하다.

배열은 원소가 동질적이고 축이 규칙적일 때 적합하다. 지점별 담당자 이름, 매출 수치, 운영 여부처럼 자료형이 서로 다른 변수를 함께 담는 분석표라면 데이터 프레임을 사용해야 한다.

4. 데이터 프레임과 요인

4.1 데이터 프레임

데이터 프레임은 행이 관측치, 열이 변수를 나타내는 2차원 표 구조다. 각 열은 하나의 벡터이므로 열 내부는 같은 자료형이어야 하지만 열 사이의 자료형은 달라도 된다.

customers <- data.frame( customer_id = c(101L, 102L, 103L), segment = c('일반', '우수', '일반'), amount = c(32000, 58000, 41000), active = c(TRUE, TRUE, FALSE), stringsAsFactors = FALSE ) str(customers)

customer_id는 정수, segment는 문자, amount는 수치, active는 논리 열이다. 모든 열의 길이는 같아야 하며 한 행은 같은 고객에 대한 값이어야 한다. 행의 의미를 정하는 관측 단위, 즉 한 행의 입도를 먼저 선언해야 한다. 고객별 표에 주문별 금액을 그대로 섞으면 한 행의 의미가 무너진다.

data.frame은 행렬과 달리 열마다 자료형이 다를 수 있다. 그렇다고 한 열 안에서 수치와 문자를 원래 형태 그대로 혼합할 수 있는 것은 아니다. 한 열은 하나의 벡터이므로 공통 자료형으로 바뀐다.

4.2 요인

요인은 제한된 범주와 수준을 표현하는 구조다. 화면에는 범주명이 보이지만 내부적으로 수준 집합과 정수 코드 정보를 가진다.

grade <- factor( c('보통', '우수', '보통', '미흡'), levels = c('미흡', '보통', '우수') ) levels(grade) table(grade)

levels를 명시하면 현재 관측에 없는 범주도 가능한 범주로 보존할 수 있다. 명목형 범주는 순서가 없으므로 단순 factor를 사용한다. 미흡 < 보통 < 우수처럼 순서 비교가 의미 있다면 ordered = TRUE를 지정한다.

satisfaction <- factor( c('보통', '우수', '미흡'), levels = c('미흡', '보통', '우수'), ordered = TRUE ) is.ordered(satisfaction)

수준의 표시 순서가 곧 현실의 순서라는 보장은 없다. levels를 데이터에 처음 나타난 순서나 가나다순에 맡기면 기준 범주와 도표 순서가 의도와 다를 수 있다. 업무 정의에 따라 levels를 명시해야 한다.

요인을 숫자로 바로 바꾸면 표시된 숫자가 아니라 내부 수준 코드가 나올 수 있다. 예를 들어 factor(c('10', '20'))에 as.numeric을 적용하면 10과 20이 아니라 1과 2가 될 수 있다. 숫자 문자열인 요인을 실제 수치로 바꿔야 할 때는 의미와 수준을 검증한 뒤 문자로 거쳐 변환한다. 세부 변환 절차는 다음 레슨 범위지만 이 함정은 구조 이해에 필수다.

5. 통합 업무 사례와 판단 절차

교육 운영팀이 수강생별 이름, 반, 점수, 수료 여부를 관리하고, 반별로 세 번의 평가 점수를 별도로 계산한다고 하자.

  1. 수강생별 이질적인 변수는 데이터 프레임으로 만든다.
  2. 반은 가능한 범주가 정해져 있으므로 요인으로 만든다.
  3. 세 평가 점수가 모두 같은 단위라면 수치 행렬로 만든다.
  4. 표, 계산 기준, 설명을 하나의 결과로 넘길 때는 리스트로 묶는다.

trainees <- data.frame( name = c('가람', '나래', '다온'), classgroup = factor(c('A', 'B', 'A'), levels = c('A', 'B')), finalscore = c(86, 74, 92), completed = c(TRUE, FALSE, TRUE) )

exam_scores <- matrix( c(80, 84, 86, 71, 75, 74, 88, 90, 92), nrow = 3, byrow = TRUE, dimnames = list(trainees$name, c('1차', '2차', '3차')) )

result <- list( learnertable = trainees, scorematrix = exam_scores, rule = '최종 점수와 수료 여부는 운영 기준에 따라 확정' ) str(result)

산출물 검토 체크리스트는 행의 관측 단위, 열별 자료형, 행렬 원소의 동일 단위, 요인의 수준 순서, 리스트 요소 이름을 포함해야 한다. 구조가 적절하면 후속 계산과 시각화의 의미가 선명해진다.

6. 시험 함정과 자주 틀리는 포인트

  1. 벡터를 자료형이 다른 값의 보관함으로 본다. 원자 벡터는 하나의 자료형으로 강제 변환된다.
  2. 벡터와 1행 행렬을 같다고 본다. 행렬에는 2차원 dim 속성이 있다.
  3. matrix의 기본 채움 방향을 행으로 외운다. 기본은 열 방향이다.
  4. 행렬은 열마다 자료형이 달라도 된다고 본다. 행렬 전체가 한 원자형이다.
  5. 리스트의 length가 내부 모든 값의 개수라고 생각한다. 최상위 요소 수다.
  6. 배열은 자료형이 서로 다른 축을 담는다고 본다. 배열도 원자형이 하나다.
  7. 데이터 프레임의 length를 행 수라고 본다. 일반적으로 열 수다.
  8. 요인의 화면 값과 내부 코드가 같다고 본다. 수준과 정수 코드가 분리되어 있다.
  9. ordered factor와 일반 factor를 구분하지 않는다. 전자만 범주의 순서를 명시한다.
  10. class와 typeof가 항상 같다고 본다. 데이터 프레임처럼 서로 다를 수 있다.
07

7. 수행 체크리스트

  • [ ] 한 행 또는 한 원소의 의미를 먼저 정의했다.
  • [ ] 차원 수와 원소 동질성을 기준으로 구조를 골랐다.
  • [ ] 벡터의 강제 형 변환 가능성을 확인했다.
  • [ ] 행렬의 채움 방향과 dim을 확인했다.
  • [ ] 리스트 요소에 의미 있는 이름을 부여했다.
  • [ ] 배열 각 축의 의미를 dimnames로 기록했다.
  • [ ] 데이터 프레임의 열 길이가 같고 열별 자료형이 적절한지 확인했다.
  • [ ] 범주형 변수의 levels와 ordered 여부를 업무 정의와 맞췄다.
  • [ ] class, typeof, length, dim, str의 질문이 서로 다름을 확인했다.
  • [ ] 숫자처럼 보이는 문자·요인을 수치로 오인하지 않았다.

9. 정답과 해설

  1. 정답 2. 원자 벡터는 한 자료형을 가지므로 서로 다른 값은 공통 자료형으로 강제 변환될 수 있다.
  2. 정답 1. matrix는 기본적으로 열 방향으로 값을 채우며 byrow = TRUE일 때 행 방향이다.
  3. 정답 2. 행렬은 2차원 원자 구조이므로 전체 원소가 같은 자료형을 공유한다.
  4. 정답 3. 리스트는 요소마다 구조와 자료형, 길이가 달라도 된다.
  5. 정답 1. 배열은 동일 자료형의 값을 여러 차원 축으로 저장하는 구조다.
  6. 정답 2. 데이터 프레임은 열 벡터의 리스트처럼 동작하므로 length는 일반적으로 열 수다.
  7. 정답 1. ordered factor는 levels에 지정된 범주의 순서를 표현한다.
  8. 정답 2. 요인은 내부 정수 코드와 표시 수준을 가지므로 직접 수치 변환하면 코드가 반환될 수 있다.
  9. 정답 2. dim은 각 차원의 크기를 반환하며 데이터 프레임에서는 행 수와 열 수를 준다.
  10. 정답 3. 구조는 화면 모양보다 차원, 원소의 동질성, 관측 단위, 범주의 의미로 선택해야 한다.
10

10. 핵심 요약

  • 벡터는 1차원 원자 구조이며 서로 다른 원자형은 공통 형으로 강제 변환될 수 있다.
  • 행렬은 2차원 동질 구조이고 기본적으로 열 방향으로 채워진다.
  • 리스트는 길이와 자료형이 다른 요소를 이름으로 묶는 복합 컨테이너다.
  • 배열은 같은 자료형의 값을 2차원 이상 규칙적인 축에 저장한다.
  • 데이터 프레임은 행을 관측치, 열을 변수로 해석하며 열마다 자료형이 다를 수 있다.
  • 요인은 가능한 범주 levels를 보존하고 ordered 여부로 순서 의미를 표현한다.
  • class와 typeof, length와 dim은 서로 다른 질문에 답하므로 목적에 맞게 사용한다.
  • 구조를 고를 때 차원, 동질성, 관측 단위, 범주 수준을 먼저 판단한다.
