> 이 레슨은 이미 만들어진 R 객체에서 필요한 값을 정확히 선택하고, 자료형을 진단·변환하며, 결측값 때문에 계산 의미가 왜곡되지 않게 처리하는 범위에 집중한다. 데이터 구조 자체의 정의는 이전 레슨, 반복문과 사용자 정의 함수는 다음 레슨에서 다룬다.

## 1. 학습 목표와 안전한 처리 순서

데이터 선택과 변환의 핵심은 선택한 행·열의 의미와 변환 후 값이 보존되었다는 근거다. 학습 후에는 [, [[, $의 반환 차이를 설명하고, 양수·음수·논리·이름 인덱스를 올바르게 사용하며, class와 typeof로 현재 형을 확인한 뒤 as 계열 함수로 안전하게 변환할 수 있어야 한다. 또한 NA가 포함된 계산에서 제거 여부를 업무 규칙에 따라 결정해야 한다.

실기 판단은 다음 순서를 따른다.

1. 원본 객체의 구조, 크기, 열 이름과 자료형을 확인한다.
2. 선택 조건이 위치, 이름, 논리식 중 무엇인지 정한다.
3. 선택 결과의 행 수·열 수와 class가 예상과 같은지 검증한다.
4. 변환 전 값의 허용 형식과 실패 가능성을 확인한다.
5. 결측의 의미와 제거·유지·대체 정책을 정한다.
6. 변환 후 결측 개수, 범위, 고유값과 표본 행을 다시 검증한다.

## 2. 인덱싱과 부분집합

### 2.1 벡터 인덱스

벡터는 대괄호 안에 위치, 제외 위치, 논리 조건, 이름을 넣어 부분집합을 선택할 수 있다.

    score <- c(민수 = 82, 지영 = 91, 수빈 = 76, 현우 = 88)
    score[c(1, 4)]
    score[-3]
    score[score >= 85]
    score[c('지영', '현우')]

양수 인덱스는 선택, 음수 인덱스는 제외를 뜻한다. 두 부호를 한 번에 섞으면 오류가 발생한다. 논리 인덱스는 TRUE인 위치를 선택하며 조건 벡터의 길이가 대상과 맞는지 확인해야 한다.

이름 인덱스는 열이나 원소의 순서가 바뀌어도 의미가 드러난다. 존재하지 않는 이름을 선택하면 NA가 생길 수 있으므로 요청한 이름이 names 안에 있는지 setdiff 등으로 확인하는 것이 안전하다.

### 2.2 행렬과 데이터 프레임 인덱스

2차원 객체는 [행, 열] 순서다.

    sales <- matrix(
      c(120, 135, 142, 98, 110, 125),
      nrow = 2,
      byrow = TRUE,
      dimnames = list(c('온라인', '매장'), c('1월', '2월', '3월'))
    )
    sales['온라인', '2월']
    sales[, c('1월', '3월'), drop = FALSE]

행이나 열 하나만 선택하면 기본적으로 차원이 줄어 벡터가 될 수 있다. 후속 코드가 행렬을 기대한다면 drop = FALSE로 2차원을 유지한다. 반환 구조를 확인하지 않으면 nrow 같은 함수가 예상과 다르게 동작한다.

데이터 프레임에서도 [행, 열]을 쓴다.

    customers <- data.frame(
      id = c(101L, 102L, 103L, 104L),
      segment = c('일반', '우수', '일반', '우수'),
      amount = c(32000, 58000, 41000, 67000),
      active = c(TRUE, TRUE, FALSE, TRUE),
      stringsAsFactors = FALSE
    )

    active_rows <- customers[customers$active, , drop = FALSE]
    amount_table <- customers[, c('id', 'amount'), drop = FALSE]

쉼표 앞은 행 조건, 뒤는 열 선택이다. 조건 뒤의 빈 열 위치는 모든 열을 뜻한다. drop = FALSE를 명시하면 한 열만 골라도 데이터 프레임 구조를 유지할 수 있어 반환 계약이 선명하다.

### 2.3 [, [[, $의 차이

데이터 프레임과 리스트에서 선택 연산자는 반환 수준이 다르다.

| 표현 | 주된 목적 | 데이터 프레임에서의 대표 결과 |
|---|---|---|
| x[i] | 컨테이너의 부분집합 | 선택한 열을 가진 데이터 프레임 |
| x[[i]] | 단일 요소 추출 | 해당 열의 벡터 |
| x$name | 이름이 고정된 단일 요소 | 해당 열의 벡터 |
| x[row, col] | 행·열 교차 선택 | 조건에 따라 표 또는 단순화된 값 |

    class(customers['amount'])
    # data.frame
    class(customers[['amount']])
    # numeric
    class(customers$amount)
    # numeric

[는 바깥 컨테이너를 유지하는 경향이 있고 [[는 한 요소의 내용을 꺼낸다. $는 대화형 코드에서 읽기 쉽지만 열 이름이 변수에 저장되어 있을 때는 customers[[column_name]]처럼 [[를 써야 한다.

부분 문자열이 열 이름과 우연히 일치하는 $의 부분 매칭에 의존하면 스키마 변경에 취약하다. 정확한 열 이름을 사용하고 names로 존재 여부를 검증한다.

### 2.4 조건식과 부분집합 검증

여러 조건은 괄호와 원소별 논리 연산자를 쓴다.

    selected <- customers[
      customers$active & customers$amount >= 50000,
      c('id', 'amount'),
      drop = FALSE
    ]

&&와 ||는 첫 원소만 보는 단축 평가이므로 행별 필터 조건에는 &와 |를 사용한다. 필터 전후 nrow를 비교하고, 선택 결과가 조건을 모두 만족하는지 all로 확인한다.

    nrow(customers)
    nrow(selected)
    all(selected$amount >= 50000)

## 3. 자료형 확인과 변환

### 3.1 확인이 변환보다 먼저다

자료형 변환은 값의 의미를 바꿀 수 있으므로 현재 상태를 먼저 확인한다.

    raw_code <- c('10', '20', '30')
    class(raw_code)
    typeof(raw_code)
    is.character(raw_code)

| 질문 | 대표 함수 |
|---|---|
| 상위 클래스가 무엇인가 | class |
| 내부 저장 유형이 무엇인가 | typeof |
| 수치·문자·논리인지 | is.numeric, is.character, is.logical |
| 요인인지 | is.factor |
| 데이터 프레임인지 | is.data.frame |
| 구조 전체가 어떤가 | str |

is.numeric은 정수와 실수형을 모두 TRUE로 판단할 수 있고 typeof는 integer와 double을 구분한다. 시험 문제의 질문이 상위 구조인지 내부 저장형인지 읽고 함수를 선택해야 한다.

### 3.2 명시적 변환과 검증

as.numeric, as.character, as.logical, as.integer, as.factor 등은 명시적 변환에 사용한다.

    parsed <- as.numeric(raw_code)
    parsed
    # 10 20 30

숫자로 해석할 수 없는 문자열은 변환 경고와 함께 NA가 될 수 있다.

    raw_amount <- c('1200', '오류', '850')
    amount <- suppressWarnings(as.numeric(raw_amount))
    invalid <- is.na(amount) & !is.na(raw_amount)
    raw_amount[invalid]
    # 오류

논리 변환에서도 임의의 표현을 자동 해석한다고 가정하면 안 된다. TRUE와 FALSE 규칙을 먼저 정하고 명시적인 비교로 만드는 편이 안전하다.

    raw_active <- c('Y', 'N', 'Y')
    active <- raw_active == 'Y'

요인을 숫자로 바꿀 때는 내부 코드 함정이 있다.

    level_value <- factor(c('10', '20', '10'))
    as.numeric(level_value)
    # 표시값이 아니라 수준 코드가 될 수 있음
    as.numeric(as.character(level_value))
    # 10 20 10

문자를 거치는 방식도 모든 값이 실제 숫자 형식이라는 검증이 전제다. 통화 기호, 천 단위 쉼표, 공백이 있다면 먼저 허용 형식을 정의하고 정제 결과를 확인한다.

### 3.3 강제 변환과 정보 손실

    as.integer(3.9)
    # 3
    as.logical(c(0, 1, -2))
    # FALSE TRUE TRUE

변환 전후에는 최소한 다음을 검사한다.

- 전체 길이와 행 수가 유지되었는가?
- 새 NA가 몇 개 생겼는가?
- 허용 범위를 벗어난 값이 생겼는가?
- 고유 범주와 빈도가 예상과 같은가?
- 원본 열을 보존해 실패 값을 추적할 수 있는가?

## 4. 결측값을 고려한 기본 연산

### 4.1 NA, NaN, Inf, NULL 구분

NA는 값이 관측되지 않았거나 알 수 없음을 나타낸다. NaN은 정의되지 않은 수치 계산 결과이며 is.na로도 TRUE가 된다. Inf와 -Inf는 무한대를 뜻하며 결측은 아니므로 is.finite로 유한성을 확인한다. NULL은 길이 0인 객체 또는 요소의 부재를 나타내며 NA 하나와 같지 않다.

| 표현 | 의미 | 대표 점검 |
|---|---|---|
| NA | 알 수 없는 값 | is.na, anyNA |
| NaN | 정의되지 않은 수치 | is.nan, is.na |
| Inf, -Inf | 양·음의 무한대 | is.infinite, is.finite |
| NULL | 객체·요소의 부재 | is.null |

NA는 ==로 비교하지 않는다.

    value <- c(10, NA, 30)
    is.na(value)
    anyNA(value)

value == NA는 각 결과가 NA가 되어 어떤 위치가 결측인지 판별하지 못한다. 반드시 is.na를 사용한다.

### 4.2 결측이 포함된 연산

    score <- c(82, NA, 91, 77)
    mean(score)
    # NA
    mean(score, na.rm = TRUE)
    # 83.33333...

기본 mean은 결측이 하나라도 있으면 NA를 반환한다. na.rm = TRUE는 관측된 값만으로 계산하지만 무조건 정답은 아니다. 결측이 무응답인지, 측정 실패인지, 0을 의미하는지에 따라 해석이 달라진다. 결측을 제거한 평균에는 사용된 관측 수와 결측 수를 함께 보고한다.

    observed_n <- sum(!is.na(score))
    missing_n <- sum(is.na(score))

sum, min, max 등의 많은 함수도 na.rm 인수를 제공하지만 함수별 도움말을 확인해야 한다. 결측 제거 후 원소가 하나도 남지 않은 경우 반환값이 특별할 수 있으므로 length와 유한성까지 점검한다.

### 4.3 논리식의 세 값

R의 논리 계산은 TRUE, FALSE, NA를 가질 수 있다.

    TRUE & NA
    # NA
    FALSE & NA
    # FALSE
    TRUE | NA
    # TRUE

FALSE & NA는 한쪽이 거짓이면 전체가 거짓임을 확정할 수 있다. TRUE | NA도 한쪽이 참이므로 참이다. 나머지는 결측값을 알아야 확정할 수 있다. 필터 조건에 NA가 들어가면 결과에도 예상치 않은 NA 행이 나타날 수 있으므로 조건을 명시한다.

    amount <- c(100, NA, 300)
    keep <- !is.na(amount) & amount >= 200
    amount[keep]
    # 300

### 4.4 완전한 행과 대체 판단

데이터 프레임에서 complete.cases는 지정한 열들이 모두 결측이 아닌 행을 찾는다.

    survey <- data.frame(
      id = 1:4,
      age = c(25, NA, 31, 28),
      score = c(80, 75, NA, 92)
    )
    complete.cases(survey[c('age', 'score')])

## 5. 통합 업무 사례

문자형으로 전달된 캠페인 성과표를 검증한다고 하자.

    raw <- data.frame(
      campaign = c('A', 'B', 'C', 'D'),
      clicks = c('120', '95', '오류', '140'),
      cost = c(30000, NA, 25000, 42000),
      active = c('Y', 'N', 'Y', 'Y'),
      stringsAsFactors = FALSE
    )

    clicks_num <- suppressWarnings(as.numeric(raw$clicks))
    conversion_failed <- is.na(clicks_num) & !is.na(raw$clicks)
    active_flag <- raw$active == 'Y'
    usable <- active_flag & !is.na(clicks_num) & !is.na(raw$cost)

    analysis_data <- data.frame(
      campaign = raw$campaign[usable],
      clicks = clicks_num[usable],
      cost = raw$cost[usable]
    )

    nrow(raw)
    nrow(analysis_data)
    raw$clicks[conversion_failed]

판단 절차는 원본 보존, 형 확인, 변환 실패 식별, 결측 정책 적용, 선택 결과 검증 순이다. 산출물에는 전체 4건, 변환 실패 캠페인, 비용 결측 건수, 최종 분석 건수, 사용한 조건이 기록되어야 한다. 단순히 정상 행만 출력하면 제외 근거를 추적할 수 없다.

## 6. 시험 함정과 자주 틀리는 포인트

1. **양수와 음수 위치를 한 인덱스에 섞는다.** 선택과 제외 지시가 충돌한다.
2. **행렬에서 행과 열 순서를 뒤집는다.** [행, 열] 순서다.
3. **한 열 선택 후에도 항상 표 구조라고 생각한다.** 차원이 줄 수 있어 drop = FALSE가 필요하다.
4. **[와 [[가 같은 결과를 반환한다고 본다.** 전자는 부분 컨테이너, 후자는 단일 요소 추출에 가깝다.
5. **행별 조건에 &&를 사용한다.** 벡터 필터에는 원소별 &를 사용한다.
6. **class와 typeof를 같은 질문으로 본다.** 상위 클래스와 내부 저장형은 다를 수 있다.
7. **변환 경고를 숨기면 문제가 해결된다고 본다.** 실패 위치와 원문 값을 별도로 검증해야 한다.
8. **요인을 as.numeric으로 바로 바꾼다.** 표시값 대신 수준 코드가 나올 수 있다.
9. **x == NA로 결측을 찾는다.** is.na를 사용해야 한다.
10. **na.rm = TRUE를 언제나 올바른 처리로 본다.** 제거 가능성은 업무 의미와 결측 원인에 따라 정한다.

## 7. 수행 체크리스트

- [ ] 선택 전에 str, dim, names로 원본을 확인했다.
- [ ] 위치·이름·논리 인덱스 중 의도에 맞는 방법을 골랐다.
- [ ] 2차원 선택에서 행과 열 순서를 확인했다.
- [ ] 반환 구조 유지가 필요하면 drop = FALSE를 썼다.
- [ ] [, [[, $의 반환 수준을 구분했다.
- [ ] 변환 전에 class, typeof, is 계열 함수로 형을 확인했다.
- [ ] 변환 후 새 NA와 실패 원문을 점검했다.
- [ ] 요인의 내부 코드를 표시값으로 오인하지 않았다.
- [ ] 결측은 is.na 또는 anyNA로 찾았다.
- [ ] 제거·유지·대체 정책과 최종 사용 건수를 기록했다.

## 9. 정답과 해설

1. **정답 2.** 음수 위치 인덱스는 해당 위치를 제외한다.
2. **정답 3.** [행, 열]에서 첫 행을 고르고 drop = FALSE로 2차원을 유지한다.
3. **정답 2.** [[는 지정한 한 열의 내용인 벡터를 추출한다. d['amount']는 한 열 데이터 프레임이다.
4. **정답 2.** &는 벡터의 대응 원소별로 AND를 계산한다.
5. **정답 1.** typeof는 객체의 내부 저장 유형을 반환한다.
6. **정답 1.** 요인의 직접 수치 변환은 표시 문자열이 아니라 내부 수준 코드를 반환할 수 있다.
7. **정답 2.** 결측 여부는 ==가 아니라 is.na로 판별한다.
8. **정답 2.** na.rm = TRUE는 해당 계산에서 결측을 제외한다. 원본을 수정하거나 결측 의미를 판단하지 않는다.
9. **정답 2.** 한쪽이 FALSE이면 다른 값이 무엇이든 AND 결과는 FALSE로 확정된다.
10. **정답 3.** 변환 전 진단과 변환 후 검증, 원본 보존이 정보 손실과 실패 은폐를 줄인다.

## 10. 핵심 요약

- 벡터는 양수·음수·논리·이름 인덱스로 선택하며 선택 의미가 충돌하지 않게 한다.
- 2차원 객체는 [행, 열] 순서이고 구조 유지가 필요하면 drop = FALSE를 사용한다.
- [는 부분 컨테이너, [[와 $는 단일 요소의 내용을 꺼내는 데 주로 사용한다.
- 변환 전에 class, typeof, is 계열 함수로 상태를 확인하고 원본 값을 보존한다.
- 요인의 직접 수치 변환은 내부 수준 코드를 낼 수 있으므로 표시값과 허용 형식을 검증한다.
- NA는 is.na로 찾으며 NaN, Inf, NULL과 의미가 다르다.
- na.rm은 결측을 계산에서 제외할 뿐 결측 원인을 해결하지 않는다.
- 선택·변환 전후 건수, 구조, 결측, 실패 원문을 기록해야 결과를 재현하고 감사할 수 있다.
