01

1. 학습 목표와 구현 원칙

학습 후에는 단일 조건과 벡터 조건을 구분해 if와 ifelse를 선택하고, for·while·repeat의 종료 조건을 설명할 수 있어야 한다. 또한 입력 검증, 기본 인수, 반환값이 명확한 함수를 작성하며, apply·lapply·sapply·vapply·tapply의 입력과 결과를 비교할 수 있어야 한다.

제어 구조와 함수 선택은 다음 순서로 판단한다.

  1. 조건이 길이 1의 참·거짓인가, 여러 원소의 판정인가?
  2. 반복 횟수가 정해졌는가, 상태가 만족될 때까지 반복하는가?
  3. 반복 과정에서 앞 단계의 상태가 다음 단계에 필요한가?
  4. 같은 로직을 이름 있는 함수로 분리할 가치가 있는가?
  5. 반복 대상과 반환 자료형을 미리 확정할 수 있는가?
  6. 입력 경계와 빈 입력, 결측값을 검증했는가?
02

2. 조건문과 반복문

2.1 if와 else

if는 길이 1의 논리 조건에 따라 한 분기를 실행한다.

score <- 84 if (score >= 80) { grade <- '통과' } else { grade <- '재검토' } grade # 통과

조건에는 TRUE 또는 FALSE 하나가 들어가야 한다. 여러 점수 벡터를 if에 직접 넣어 각 원소를 판정하려 하면 첫 값만 사용되거나 오류·경고가 발생할 수 있다. 벡터 전체가 조건을 만족하는지는 all, 하나라도 만족하는지는 any로 한 개의 논리값을 만든다.

scores <- c(84, 91, 77) if (all(scores >= 60)) { status <- '전원 기준 이상' } else { status <- '기준 미달 포함' }

결측이 있는 조건은 참과 거짓을 확정할 수 없다. if에 넣기 전 is.na로 정책을 정하거나 isTRUE를 이용해 오직 TRUE일 때만 분기하도록 한다.

approved <- NA if (isTRUE(approved)) { messagetext <- '승인' } else { messagetext <- '승인 아님 또는 미확정' }

2.2 ifelse와 switch

ifelse는 벡터의 각 원소에 대해 조건을 적용해 같은 길이의 결과를 만든다.

scores <- c(84, 91, 77) labels <- ifelse(scores >= 80, '통과', '재검토') labels # 통과 통과 재검토

ifelse는 편리하지만 yes와 no 결과를 공통 자료형으로 맞추는 과정에서 클래스 속성이 단순화될 수 있다. 날짜나 요인처럼 속성이 중요한 객체는 결과 class를 확인하거나 명시적인 인덱스 대입을 고려한다.

switch는 하나의 값에 따라 여러 선택지 중 하나를 고를 때 사용할 수 있다.

method <- 'median' result <- switch( method, mean = mean(c(2, 5, 20)), median = median(c(2, 5, 20)), stop('지원하지 않는 방법입니다.') ) result # 5

2.3 for 반복문

for는 정해진 시퀀스의 값을 하나씩 꺼내 반복한다.

values <- c(3, 5, 8, 2) doubled <- numeric(length(values))

for (i in seq_along(values)) { doubled[i] <- values[i] * 2 } doubled

결과 크기를 알고 있다면 numeric(length(values))처럼 미리 할당한다. 매 반복마다 c로 벡터 끝에 값을 붙이면 객체를 반복 복사해 비효율적일 수 있다. 인덱스가 필요 없으면 값 자체를 순회해 합계를 만들 수도 있다.

total <- 0 for (value in values) { total <- total + value }

seq_along은 빈 벡터에서도 안전한 인덱스 시퀀스를 만든다. 1:length(values)는 빈 경우 1:0이 되어 원하지 않는 반복을 만들 수 있다.

2.4 while과 repeat

while은 조건이 TRUE인 동안 반복하므로 반복 횟수가 사전에 확정되지 않은 경우 적합하다.

balance <- 100 periods <- 0L

while (balance < 150 && periods < 20L) { balance <- balance * 1.05 periods <- periods + 1L }

조건에 영향을 주는 balance와 periods가 본문에서 반드시 갱신되어야 한다. periods < 20L 같은 상한은 예상치 못한 무한 반복을 막는 방어 장치다.

repeat는 명시적인 break를 만날 때까지 계속한다.

count <- 0L repeat { count <- count + 1L if (count >= 3L) { break } }

next는 현재 반복의 나머지를 건너뛰고 다음 반복으로 진행한다. break는 반복문 자체를 끝낸다. 종료 조건을 본문 아래에만 두면 적어도 한 번 실행된다는 점을 설명할 수 있어야 한다.

3. 사용자 정의 함수

3.1 함수의 구성

함수는 입력 인수, 본문, 반환값으로 구성한다.

safeaverage <- function(x, removena = FALSE) { if (!is.numeric(x)) { stop('x는 수치형이어야 합니다.') } if (!is.logical(removena) || length(removena) != 1L) { stop('removena는 길이 1의 논리값이어야 합니다.') } mean(x, na.rm = removena) }

safe_average(c(70, 80, 90)) # 80

R 함수는 명시적 return이 없어도 마지막 평가 값을 반환한다. 반환 계약에는 자료형, 길이, 이름, 결측 가능성을 포함한다.

3.2 인수와 호출

인수는 위치 또는 이름으로 전달할 수 있고 기본값을 가질 수 있다.

clamp <- function(x, lower = 0, upper = 100) { if (lower > upper) { stop('lower는 upper보다 클 수 없습니다.') } pmin(pmax(x, lower), upper) }

clamp(c(-5, 40, 120)) clamp(x = c(-5, 40, 120), upper = 90)

이름 있는 호출은 인수가 많을 때 의미가 분명하고 순서 변경에 덜 취약하다. ...은 추가 인수를 다른 함수로 전달하는 데 쓰지만 허용 인수를 문서화하지 않으면 오타가 조용히 전달될 수 있다.

3.3 범위와 부수 효과

함수 안에서 만든 일반 객체는 지역 환경에 존재하고, 함수는 자신이 만들어진 환경을 따라 바깥 이름을 찾는 어휘적 범위를 사용한다. 전역 객체에 암묵적으로 의존하면 같은 함수가 세션 상태에 따라 다른 결과를 낸다.

taxrate <- 0.1 addtaxbad <- function(amount) { amount * (1 + taxrate) }

위 함수는 tax_rate가 바뀌면 결과도 바뀐다. 의존성을 인수로 드러내는 편이 재현 가능하다.

add_tax <- function(amount, rate) { if (!is.numeric(amount) || !is.numeric(rate)) { stop('amount와 rate는 수치형이어야 합니다.') } amount * (1 + rate) }

함수 안에서 전역 대입이나 파일 삭제 같은 부수 효과를 피하고, 같은 입력에는 같은 반환값을 주도록 설계하면 테스트가 쉬워진다. 난수가 필요하면 시드 정책을 호출부에서 명시하고 함수 설명에 기록한다.

3.4 함수 검증 시나리오

할인 후 금액을 계산하는 함수를 만든다.

discounted_price <- function(price, rate = 0) { if (!is.numeric(price) || any(!is.finite(price))) { stop('price는 유한한 수치여야 합니다.') } if (!is.numeric(rate) || length(rate) != 1L || is.na(rate) || rate < 0 || rate > 1) { stop('rate는 0 이상 1 이하의 수치 하나여야 합니다.') } price * (1 - rate) }

discounted_price(c(10000, 20000), rate = 0.1) # 9000 18000

정상값, 경계값 0과 1, 빈 입력, 잘못된 자료형, NA와 Inf를 각각 시험한다. 오류를 일부러 발생시키는 검증은 tryCatch나 테스트 도구로 확인할 수 있지만 여기서는 실행 가능한 정상 예제와 판단 기준을 분리한다.

4. apply 계열 함수

4.1 apply

apply는 주로 행렬이나 배열의 특정 차원에 함수를 적용한다. MARGIN = 1은 행, MARGIN = 2는 열이다.

scores <- matrix( c(80, 90, 85, 70, 75, 80), nrow = 2, byrow = TRUE, dimnames = list(c('A', 'B'), c('1차', '2차', '3차')) ) apply(scores, 1, mean) apply(scores, 2, mean)

데이터 프레임에 apply를 사용하면 내부적으로 행렬로 바뀔 수 있다. 열 자료형이 섞여 있으면 전체가 문자형이 되어 수치 함수가 실패할 수 있으므로 동질 수치 행렬인지 확인한다.

4.2 lapply, sapply, vapply

lapply는 리스트나 벡터의 각 요소에 함수를 적용하고 결과를 항상 리스트로 반환한다.

groups <- list(A = c(80, 90), B = c(70, 75, 80)) lapply(groups, mean)

sapply는 가능한 경우 결과를 벡터나 행렬로 단순화한다.

sapply(groups, mean) # 이름 있는 수치 벡터

단순화 결과는 입력과 반환 길이에 따라 달라질 수 있으므로 재사용 함수의 반환 구조가 흔들릴 수 있다. vapply는 FUN.VALUE로 예상 형과 길이를 명시해 불일치하면 오류를 낸다.

vapply(groups, mean, numeric(1))

4.3 tapply와 그룹별 처리

amount <- c(30, 50, 40, 80, 60) region <- c('동부', '서부', '동부', '서부', '동부') tapply(amount, region, mean)

tapply의 첫 인수는 계산할 벡터, 두 번째는 그룹을 정의하는 인자, 세 번째는 적용 함수다. 관측되지 않은 요인 수준이나 결측 그룹 처리에 따라 결과가 달라질 수 있으므로 levels와 NA 정책을 확인한다.

5. 통합 업무 사례와 산출물

지점별 월 점수 목록을 받아 평균을 계산하되, 결과가 수치 하나임을 보장한다고 하자.

branch_scores <- list( 서울 = c(82, 88, 91), 부산 = c(75, 80, 79), 대전 = c(90, 93, 89) )

checked_mean <- function(x) { if (!is.numeric(x) || length(x) == 0L || anyNA(x)) { stop('각 점수는 결측 없는 수치 벡터여야 합니다.') } mean(x) }

branchmean <- vapply(branchscores, checkedmean, numeric(1)) branchmean

판단 절차는 입력 계약 정의, 단일 그룹 함수 검증, 전체 그룹 적용, 반환형 확인 순이다. 산출물에는 checked_mean 함수, 정상·오류 조건 목록, 이름 있는 수치 벡터 결과, sessionInfo가 포함된다. 특정 지점만 별도 분기하기보다 입력이나 기준 인수로 차이를 표현한다.

6. 시험 함정과 자주 틀리는 포인트

  1. if에 벡터 조건을 넣어 원소별 판정을 기대한다. if는 논리값 하나를 요구한다.
  2. ifelse가 모든 클래스 속성을 보존한다고 본다. 결과가 공통형으로 단순화될 수 있다.
  3. 1:length(x)가 빈 입력에서도 안전하다고 본다. seq_along을 사용한다.
  4. while의 상태 갱신을 빠뜨린다. 종료되지 않을 수 있어 상한도 둔다.
  5. break와 next를 혼동한다. break는 종료, next는 다음 반복으로 이동한다.
  6. 함수가 전역 객체에 의존해도 재현 가능하다고 본다. 의존성은 인수로 드러낸다.
  7. 마지막 표현식의 반환을 잊는다. R 함수는 마지막 평가 값을 반환한다.
  8. apply를 혼합형 데이터 프레임에 무조건 적용한다. 행렬 강제 변환으로 자료형이 바뀔 수 있다.
  9. lapply와 sapply의 반환이 같다고 본다. lapply는 리스트, sapply는 가능한 만큼 단순화한다.
  10. apply 계열이 모든 반복문보다 항상 빠르다고 단정한다. 구조와 의도를 기준으로 선택한다.

7. 수행 체크리스트

  • [ ] if 조건이 길이 1인지 확인했다.
  • [ ] 벡터 분기에는 ifelse의 형 변환 가능성을 검토했다.
  • [ ] 반복 횟수 또는 종료 조건과 안전 상한을 명시했다.
  • [ ] for 결과 공간을 가능한 경우 미리 할당했다.
  • [ ] 함수 입력의 자료형, 길이, 범위, 결측을 검사했다.
  • [ ] 외부 상태 의존성을 함수 인수로 드러냈다.
  • [ ] 반환값의 자료형과 길이를 문서화했다.
  • [ ] apply의 MARGIN과 입력의 동질성을 확인했다.
  • [ ] 반환 안정성이 필요하면 lapply 또는 vapply를 선택했다.
  • [ ] 정상·경계·오류 입력으로 결과를 검증했다.

9. 정답과 해설

  1. 정답 2. ifelse는 조건 벡터의 각 원소에 yes와 no 결과를 대응시킨다.
  2. 정답 1. all은 모든 원소가 TRUE인지 논리값 하나로 반환한다.
  3. 정답 2. seq_along은 입력 길이가 0이어도 안전한 인덱스 시퀀스를 만든다.
  4. 정답 1. 상태가 바뀌지 않으면 무한 반복할 수 있으므로 갱신과 안전 상한이 필요하다.
  5. 정답 2. break는 반복문을 끝내고 next는 현재 회차만 건너뛴다.
  6. 정답 2. 숨은 전역 상태를 줄이고 계약을 검증해야 같은 입력에서 같은 결과를 재현하기 쉽다.
  7. 정답 2. apply의 MARGIN 2는 열, 1은 행을 뜻한다.
  8. 정답 1. lapply는 각 결과를 리스트 요소로 담아 반환한다.
  9. 정답 1. vapply의 FUN.VALUE인 numeric(1)이 각 결과의 형과 길이를 검증한다.
  10. 정답 2. 문법 선호보다 입력·반복 단위·반환 계약을 근거로 선택해야 한다.
10

10. 핵심 요약

  • if는 단일 조건, ifelse는 원소별 벡터 조건에 적합하다.
  • for는 반복 대상이 명확할 때, while과 repeat는 상태 기반 종료에 사용한다.
  • 반복문은 종료 조건과 상태 갱신을 명시하고 결과 공간을 가능한 경우 미리 만든다.
  • 함수는 입력 검증, 외부 의존성, 반환 자료형과 길이를 계약으로 드러낸다.
  • apply는 행렬·배열의 축, lapply는 리스트 반환, sapply는 단순화, vapply는 반환형 검증에 초점이 있다.
  • tapply는 한 벡터를 그룹 기준으로 나누어 같은 함수를 적용한다.
  • apply 계열은 무조건 더 빠른 대체물이 아니라 반복 의도와 구조를 표현하는 선택지다.
  • 고정 입력과 정상·경계·오류 조건을 함께 검사해야 구현이 재현 가능해진다.
