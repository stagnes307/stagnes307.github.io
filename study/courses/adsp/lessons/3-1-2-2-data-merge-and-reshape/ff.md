# 3-1-2-2. 데이터 결합과 재구조화 · 데이터 병합 · 긴 형식과 넓은 형식 변환 · 피벗과 재구조화

> 이 레슨은 여러 표를 키로 안전하게 병합하고 동일한 정보를 긴 형식과 넓은 형식 사이에서 재구조화하는 데 집중한다. 데이터 마트의 목적·입도 설계는 이전 레슨, 그룹 집계와 파생변수 산식은 다음 레슨 범위다.

## 1. 학습 목표와 작업 원칙

분석에서 병합 오류는 실행 실패보다 조용한 행 증식과 손실의 형태로 나타나는 경우가 많다. 학습 후에는 결합 키와 일대일·일대다·다대다 관계를 진단하고, 내부·왼쪽·오른쪽·전체 외부 병합의 보존 기준을 설명할 수 있어야 한다. 또한 한 행의 관측 단위를 근거로 긴 형식과 넓은 형식을 선택하고, 재구조화 전후 정보가 보존되었는지 검증할 수 있어야 한다.

안전한 판단 순서는 다음과 같다.

1. 각 입력 표에서 한 행의 의미와 후보 키를 선언한다.
2. 키 자료형, 공백·대소문자·코드 체계, 결측을 확인한다.
3. 키의 중복으로 결합 관계를 판정한다.
4. 분석 질문에 따라 어느 표의 행을 보존할지 정한다.
5. 결합 전후 행 수, 미매칭 키, 중복과 통제 합계를 비교한다.
6. 재구조화할 때 식별 열, 시간·측정 열, 값 열을 명시한다.
7. 긴 형식과 넓은 형식을 왕복해 값과 키가 보존되는지 확인한다.

## 2. 데이터 병합

### 2.1 키와 결합 관계

병합 키는 서로 다른 표의 같은 대상을 연결하는 열이다. 화면의 행 순서나 이름이 우연히 같다는 이유로 결합하면 안 된다. 고객 ID, 주문 ID, 상품 코드처럼 업무적으로 동일성을 보장하는 키를 사용한다.

| 관계 | 왼쪽 키 | 오른쪽 키 | 일반적 의미 |
|---|---|---|---|
| 일대일 | 유일 | 유일 | 고객 기본과 고객 상태 |
| 일대다 | 유일 | 중복 가능 | 고객과 여러 주문 |
| 다대일 | 중복 가능 | 유일 | 여러 주문과 상품 기준 |
| 다대다 | 중복 | 중복 | 양쪽 조합이 모두 늘어날 수 있음 |

다대다 병합은 같은 키의 왼쪽 행 수와 오른쪽 행 수가 곱해진다. 왼쪽에 A가 2행, 오른쪽에 A가 3행이면 A 결과는 최대 6행이 된다. 이것이 업무적으로 의도한 조합인지 확인하지 않으면 금액이 중복된다.

    customer <- data.frame(
      customer_id = c(101L, 102L, 103L),
      segment = c('일반', '우수', '일반'),
      stringsAsFactors = FALSE
    )

    order <- data.frame(
      order_id = c(1L, 2L, 3L, 4L),
      customer_id = c(101L, 101L, 102L, 104L),
      amount = c(30000, 20000, 55000, 18000)
    )

    anyDuplicated(customer$customer_id)
    # 0
    anyDuplicated(order$order_id)
    # 0

customer_id는 고객 표에서 유일하지만 주문 표에서는 반복되므로 고객 대 주문은 일대다다. 주문 표의 customer_id 중 104는 고객 표에 없으므로 매칭 정책이 필요하다.

### 2.2 병합 유형

base R의 merge는 기본적으로 공통 키가 있는 행만 남기는 내부 병합처럼 동작한다.

    inner_result <- merge(
      order,
      customer,
      by = 'customer_id',
      all = FALSE,
      sort = FALSE
    )

왼쪽 표의 모든 행을 보존하려면 all.x = TRUE를 쓴다.

    left_result <- merge(
      order,
      customer,
      by = 'customer_id',
      all.x = TRUE,
      sort = FALSE
    )

customer_id 104의 segment는 NA가 된다. 오른쪽 보존은 all.y = TRUE, 양쪽 전체 보존은 all = TRUE다.

| 병합 | merge 인수 | 보존 기준 |
|---|---|---|
| 내부 | all = FALSE | 양쪽에 키가 있는 행 |
| 왼쪽 외부 | all.x = TRUE | 왼쪽 모든 행 |
| 오른쪽 외부 | all.y = TRUE | 오른쪽 모든 행 |
| 전체 외부 | all = TRUE | 양쪽 모든 키 |

주문을 모두 감사하려면 왼쪽 주문을 보존한다. 등록 고객 중 주문이 없는 고객까지 보려면 고객을 기준 표로 두고 주문을 결합한다. 보존할 모집단을 먼저 정해야 한다.

### 2.3 키 이름과 복합 키

열 이름이 다르면 by.x와 by.y를 지정한다.

    left_table <- data.frame(client_key = c(1L, 2L), value = c(10, 20))
    right_table <- data.frame(customer_id = c(1L, 2L), group = c('A', 'B'))

    matched <- merge(
      left_table,
      right_table,
      by.x = 'client_key',
      by.y = 'customer_id'
    )

고객별 월 자료처럼 키가 여러 열이면 by에 벡터를 준다.

    by_columns <- c('customer_id', 'month')

병합 전 두 표에 모든 키 열이 존재하고 자료형이 같은지 확인한다. 한쪽이 정수 101이고 다른 쪽이 문자 '101'이면 의미가 같아 보여도 변환 규칙이 필요하다. 선행 0이 의미 있는 코드 '001'을 수치 1로 바꾸면 구분 정보가 사라질 수 있다.

키 결측은 대상을 식별하지 못한다는 뜻이다. 결측끼리 연결할지 임의로 결정하지 말고 업무 규칙에 따라 오류 격리, 보완, 제외를 선택한다. 공백 제거와 대소문자 통일도 모든 코드에 일괄 적용하기 전에 코드 정의를 확인한다.

### 2.4 미매칭과 행 증식 검증

결합 전 미매칭 키를 먼저 찾는다.

    missing_customer <- setdiff(
      unique(order$customer_id),
      unique(customer$customer_id)
    )
    missing_customer
    # 104

왼쪽에서 오른쪽에 없는 행을 논리 조건으로 분리할 수도 있다.

    unmatched_order <- order[
      !order$customer_id %in% customer$customer_id,
      ,
      drop = FALSE
    ]

병합 후에는 다음을 확인한다.

- 보존 대상 표의 행이 누락되지 않았는가?
- 키 중복 때문에 예상보다 행이 늘지 않았는가?
- 미매칭 건수와 비율이 허용 기준 안인가?
- 같은 이름의 비키 열에 붙은 .x, .y 접미사가 뜻하는 바가 무엇인가?
- 병합 전후 통제 금액과 건수가 관계에 맞게 유지되는가?

### 2.5 행·열 방향 단순 결합

rbind는 열 구조가 같은 표를 행 방향으로 이어 붙일 때 사용한다. 예를 들어 같은 스키마의 1월·2월 자료를 합칠 수 있다. 열 이름, 자료형, 단위가 같은지 먼저 검증한다.

cbind는 행 순서대로 열을 붙여 키를 확인하지 않는다. 업무 키로 대상을 맞춰야 한다면 merge를 사용한다.

## 3. 긴 형식과 넓은 형식 변환

### 3.1 긴 형식과 넓은 형식

같은 자료도 관측 단위를 어떻게 두느냐에 따라 형태가 달라진다.

넓은 형식은 한 대상의 반복 측정값이 여러 열에 펼쳐진다.

| customer_id | sales_Jan | sales_Feb |
|---|---:|---:|
| 101 | 30 | 40 |
| 102 | 20 | 25 |

긴 형식은 반복 측정의 이름과 값을 별도 열로 쌓는다.

| customer_id | month | sales |
|---|---|---:|
| 101 | Jan | 30 |
| 101 | Feb | 40 |
| 102 | Jan | 20 |
| 102 | Feb | 25 |

| 형식 | 한 행의 의미 | 장점 | 주의점 |
|---|---|---|---|
| 넓은 형식 | 대상 한 개 | 보고서·열 간 비교가 직관적 | 측정 시점이 늘면 열 증가 |
| 긴 형식 | 대상×측정 단위 | 그룹·시각화·반복 처리에 유리 | 식별키 중복 의미 확인 |

긴 형식이 언제나 우월한 것은 아니다. 분석 함수와 보고 목적, 반복 측정의 수, 스키마 변화 가능성을 기준으로 선택한다.

### 3.2 넓은 형식에서 긴 형식으로

base R의 reshape를 사용한 고정 예제다.

    wide <- data.frame(
      customer_id = c(101L, 102L),
      sales_Jan = c(30, 20),
      sales_Feb = c(40, 25)
    )

    long <- reshape(
      wide,
      varying = c('sales_Jan', 'sales_Feb'),
      v.names = 'sales',
      timevar = 'month',
      times = c('Jan', 'Feb'),
      idvar = 'customer_id',
      direction = 'long'
    )
    rownames(long) <- NULL
    long

varying은 펼쳐져 있던 측정 열, v.names는 값 열, timevar는 측정 이름 열, times는 각 열에 대응하는 값, idvar는 대상 식별키다. resulting long의 한 행은 고객×월이다.

변환 전에 varying 열이 모두 같은 단위인지 확인한다. sales_Jan과 cost_Feb를 함께 쌓으면 month 값만으로 측정 종류를 설명할 수 없다. 열 이름에서 여러 요소를 분리해야 한다면 측정 종류와 시점을 각각의 열로 설계한다.

### 3.3 긴 형식에서 넓은 형식으로

    wide_again <- reshape(
      long,
      idvar = 'customer_id',
      timevar = 'month',
      direction = 'wide'
    )
    wide_again

고객×월 조합이 유일해야 한 셀에 값 하나가 들어간다. 같은 고객과 월에 sales가 두 건이면 무엇을 선택하거나 합칠지 결정할 수 없으므로 먼저 중복 원인을 해결해야 한다. 중복을 편의상 합산하는 것은 재구조화가 아니라 집계 규칙을 추가하는 일이며 다음 레슨의 판단 대상이다.

긴 자료의 완전한 조합이 없으면 넓은 결과에 NA가 생길 수 있다. NA는 해당 조합의 관측이 없다는 뜻일 수 있고 실제 값 0과 다르다.

### 3.4 피벗과 재구조화

피벗은 한 열의 범주를 새 열 축으로 돌리거나, 여러 열을 이름-값 쌍으로 모으는 재구조화 사고방식이다. 넓게 피벗할 때는 식별 열, 새 열 이름이 될 변수, 셀 값이 될 변수를 정한다. 길게 피벗할 때는 유지할 식별 열, 모을 측정 열, 새 이름 열과 값 열을 정한다.

범주별 건수표는 xtabs로 재현할 수 있다.

    visits <- data.frame(
      region = c('동부', '동부', '서부', '서부'),
      channel = c('웹', '매장', '웹', '웹')
    )
    pivot_count <- xtabs(~ region + channel, data = visits)
    pivot_count
    as.data.frame(pivot_count)

xtabs 결과는 교차표 구조이며 as.data.frame으로 긴 형식의 조합과 빈도를 얻을 수 있다. 관측되지 않은 조합과 요인 수준, 결측 범주가 표에 포함되는지는 자료형과 옵션에 따라 달라질 수 있으므로 결과의 dimnames와 합계를 검사한다.

### 3.5 재구조화 보존 검증

재구조화는 값의 표현을 바꾸는 작업이므로 원칙적으로 정보가 임의로 늘거나 사라지면 안 된다.

1. 변환 전 대상 식별키의 개수를 기록한다.
2. 긴 형식의 대상×측정 키가 유일한지 확인한다.
3. 측정값의 비결측 개수와 통제 합계를 비교한다.
4. 예상한 측정 수준이 모두 존재하는지 확인한다.
5. 넓게 되돌린 뒤 원본의 키와 값을 같은 순서로 정렬해 비교한다.

## 4. 통합 업무 사례

교육팀이 수강생 기본표와 월별 평가표를 결합해 반복 측정을 긴 형식으로 준비한다고 하자.

    learner <- data.frame(
      learner_id = c(1L, 2L, 3L),
      group = c('A', 'A', 'B')
    )

    score_wide <- data.frame(
      learner_id = c(1L, 2L, 3L),
      score_1 = c(80, 75, 90),
      score_2 = c(85, 79, 92)
    )

    stopifnot(anyDuplicated(learner$learner_id) == 0L)
    stopifnot(anyDuplicated(score_wide$learner_id) == 0L)

    combined <- merge(
      learner,
      score_wide,
      by = 'learner_id',
      all.x = TRUE,
      sort = FALSE
    )

    score_long <- reshape(
      combined,
      varying = c('score_1', 'score_2'),
      v.names = 'score',
      timevar = 'exam',
      times = c('1차', '2차'),
      idvar = c('learner_id', 'group'),
      direction = 'long'
    )
    rownames(score_long) <- NULL

산출물에는 입력별 입도와 키, 관계 진단, 보존 기준, 미매칭 목록, 병합 전후 행 수, 긴 자료의 learner_id×exam 유일성, 변환 전후 비결측 값 개수가 포함된다. 점수 평균을 새로 계산하는 것은 이 레슨의 주범위가 아니다.

## 5. 시험 함정과 자주 틀리는 포인트

1. **행 순서가 같아 보인다는 이유로 cbind한다.** 키 기반 동일성을 보장하지 않는다.
2. **키 중복을 확인하지 않고 merge한다.** 다대다 관계에서 행이 곱으로 늘 수 있다.
3. **내부 병합이 언제나 정답이라고 본다.** 보존할 모집단에 따라 유형을 선택한다.
4. **행 수만 같으면 병합이 정확하다고 본다.** 누락과 중복이 상쇄될 수 있다.
5. **키의 숫자와 문자 표현을 무조건 수치로 통일한다.** 선행 0 같은 의미가 사라질 수 있다.
6. **왼쪽 병합의 미매칭 NA를 실제 값으로 본다.** 연결 실패 여부를 따로 점검한다.
7. **긴 형식과 넓은 형식의 차이를 행 수만으로 본다.** 한 행의 관측 단위가 달라진다.
8. **중복 키를 임의 합산해 넓게 만든다.** 집계 규칙을 별도로 정의해야 한다.
9. **재구조화 후 행 순서가 달라지면 정보 손실이라고 본다.** 키와 값으로 비교한다.
10. **관측되지 않은 조합의 NA를 0과 같다고 본다.** 미관측과 실제 0은 다르다.

- [ ] 어느 표의 모집단을 보존할지 기록했다.

## 8. 정답과 해설

1. **정답 4.** 같은 키의 왼쪽 2행과 오른쪽 3행이 모든 조합을 만들면 2×3인 6행이 된다.
2. **정답 1.** all.x = TRUE는 왼쪽 행을 모두 남기고 미매칭 오른쪽 값에 NA를 둔다.
3. **정답 3.** 기본 내부 병합은 양쪽에 공통 키가 있는 행만 결과에 포함한다.
4. **정답 1.** cbind는 업무 키를 대조하지 않으므로 행 수가 같아도 다른 대상을 연결할 수 있다.
5. **정답 1.** 반복 측정 자료의 긴 형식은 보통 대상과 시점 또는 측정 종류 조합이 한 행이다.
6. **정답 1.** 한 셀에 값이 하나여야 넓은 형식으로 모호함 없이 배치할 수 있다.
7. **정답 1.** idvar는 재구조화 전후 같은 대상을 식별하는 열 또는 열들의 집합이다.
8. **정답 3.** 누락과 증식은 행 수에서 상쇄될 수 있으므로 미매칭·빈도·통제량을 함께 본다.
9. **정답 2.** 중복은 입도 오류나 실제 반복 사건일 수 있다. 집계는 재구조화와 별개로 정의해야 한다.
10. **정답 2.** 순서는 바뀔 수 있으므로 의미 있는 키와 값의 개수·합계를 기준으로 비교한다.

## 9. 핵심 요약

- 병합 전 각 표의 입도, 키, 키 자료형과 중복을 먼저 확인한다.
- 일대다와 다대다 관계는 행 증식을 만들 수 있으므로 기대 관계를 계약으로 둔다.
- 내부·왼쪽·오른쪽·전체 병합은 보존할 모집단을 기준으로 선택한다.
- cbind는 키를 맞추지 않으므로 행 순서를 동일성 근거로 삼으면 안 된다.
- 긴 형식은 대상×측정 단위, 넓은 형식은 대상 한 행에 측정값을 열로 펼친 구조다.
- 피벗은 식별 열, 이름 열, 값 열을 명확히 정하는 재구조화 작업이다.
- 넓게 만들기 전 식별키×측정키의 유일성을 확인하고 중복을 임의 집계하지 않는다.
- 병합·재구조화 전후 미매칭, 키별 빈도, 비결측 값, 통제 합계를 비교해 정보 보존을 증명한다.
