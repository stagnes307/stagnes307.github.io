학습 범위: 이 레슨은 ADsP 데이터분석 > R기초와 데이터 마트 > 데이터 마트 중 그룹별 집계, 파생변수 생성, 분석 단위 데이터셋 완성을 다룬다. 거래처럼 여러 행으로 저장된 원천을 고객·상품·기간 등 분석 단위로 요약하고, 기준 시점에 사용 가능한 정보로 파생변수를 만든 뒤 한 행의 의미와 키가 보장된 분석 데이터셋을 완성하는 것이 목표다.

집계는 단순히 합계를 구하는 일이 아니다. 분석 질문과 행의 단위를 먼저 정하지 않으면 조인 뒤 중복 합산, 평균의 평균, 미래 정보 누수 같은 오류가 발생한다. R 예제는 외부 패키지 없이 실행되며 날짜와 결측 처리 기준을 명시한다.

01

1. 분석 단위와 데이터의 입도

입도(granularity)는 한 행이 표현하는 가장 세밀한 단위다.

  • 주문 원천: 주문 한 건 또는 주문–상품 한 줄
  • 일별 요약: 고객–날짜 한 행
  • 고객 분석 마트: 고객–기준 시점 한 행
  • 상품 분석 마트: 상품–월 한 행

분석 단위와 집계 키는 질문에서 결정한다. “고객별 최근 90일 구매 특성으로 다음 달 이탈을 예측한다”면 한 행은 고객–기준 시점이고, 주문 데이터는 기준 시점 이전 90일로 제한한 뒤 고객별로 집계한다.

코드 예시 · text

원천 입도: 주문–상품 행
  → 필터: 기준 시점 이전 관찰 기간
  → 행 수준 파생: 수량 × 단가
  → 고객별 집계: 건수·금액·최근일
  → 고객 기준표와 결합
  → 한 행 = 고객–기준 시점

키의 후보를 말로만 추정하지 말고 중복을 검사한다. 고객 마트라면 customer_id 또는 customer_id + snapshot_date가 유일해야 한다.

02

2. 재현 가능한 예제 데이터

코드 예시 · r

orders <- data.frame(
  order_id   = 1:8,
  customer   = c("A", "A", "B", "B", "B", "C", "C", "D"),
  order_date = as.Date(c("2026-01-03", "2026-01-20", "2026-01-05",
                         "2026-01-18", "2026-01-25", "2026-01-09",
                         "2026-01-28", "2026-01-11")),
  qty        = c(1, 2, 1, 3, 2, 1, 4, 2),
  unit_price = c(100, 80, 120, 50, 70, 200, 40, 90),
  returned   = c(FALSE, FALSE, TRUE, FALSE, FALSE, FALSE, TRUE, FALSE)
)

customers <- data.frame(
  customer = c("A", "B", "C", "D", "E"),
  segment  = c("new", "regular", "regular", "new", "new")
)

snapshot_date <- as.Date("2026-02-01")
orders$amount <- orders$qty * orders$unit_price
orders

amount는 주문 행 수준의 파생변수다. 이후 고객별로 합산한다. 고객 E는 주문이 없으므로 주문표에서 시작해 집계하면 사라진다. 최종 분석 모집단이 전체 고객이라면 고객 기준표를 왼쪽에 두고 결합해야 한다.

03

3. 그룹별 집계

그룹별 집계는 같은 키를 가진 여러 행에 합계·평균·최솟값·최댓값·건수 등의 함수를 적용해 상위 입도로 요약하는 작업이다.

3.1 합계와 평균

코드 예시 · r

amount_sum <- aggregate(amount ~ customer, data = orders, FUN = sum)
amount_mean <- aggregate(amount ~ customer, data = orders, FUN = mean)
names(amount_sum)[2] <- "total_amount"
amount_sum

예상 합계는 A=260, B=410, C=360, D=180이다. 합계를 쓰는지는 의미에 달려 있다. 거래금액은 합산 가능하지만 고객 만족도 점수나 비율을 무조건 합하면 의미가 없다.

3.2 행 수와 고유 건수

length는 그룹의 행 수를 센다.

코드 예시 · r

order_rows <- aggregate(order_id ~ customer, data = orders, FUN = length)
names(order_rows)[2] <- "row_count"
order_rows

원천 한 행이 주문–상품이면 행 수는 상품 줄 수이지 주문 건수가 아니다. 주문 건수는 고유 order_id 수를 세야 한다.

코드 예시 · r

unique_orders <- aggregate(order_id ~ customer, data = orders,
                           FUN = function(x) length(unique(x)))
names(unique_orders)[2] <- "order_count"

시험에서 n() 또는 행 개수와 고유 식별자 개수를 혼동하지 않는다.

3.3 논리값과 조건부 집계

R에서 TRUE는 합계 계산 시 1, FALSE는 0처럼 다룰 수 있다.

코드 예시 · r

return_count <- aggregate(returned ~ customer, data = orders,
                          FUN = function(x) sum(x, na.rm = TRUE))
names(return_count)[2] <- "return_count"

결측을 na.rm = TRUE로 제외할 때는 “반품 아님”으로 간주한 것이 아니다. 알려진 값 중 TRUE 수를 센 것이다. 분모가 필요한 반품률에서는 결측 상태 행을 제외했는지, 0으로 처리했는지를 기록한다.

3.4 날짜 집계

코드 예시 · r

last_order <- aggregate(order_date ~ customer, data = orders, FUN = max)
names(last_order)[2] <- "last_order_date"
last_order$recency_days <- as.integer(snapshot_date - last_order$last_order_date)

최근성은 기준 시점에서 마지막 구매일까지의 일수다. 기준 시점 이후 주문이 섞이면 음수가 되므로 필터와 검증이 필요하다.

05

5. 파생변수 생성

파생변수 생성은 원래 변수의 계산·조건·시간 관계를 이용해 분석 목적에 더 직접적인 변수를 만드는 작업이다.

5.1 행 수준 파생

  • amount = qty × unit_price
  • is_large = amount >= 기준값
  • weekday = 요일(order_date)
  • net_amount = 판매액 - 유효한 환불액

행 수준 계산 후 집계해야 하는지, 집계 후 계산해야 하는지 구분한다. 총매출은 행별 금액을 합산한다. 고객 반품률은 고객별 반품 건수 ÷ 유효 주문 건수로 계산한다.

5.2 비율 변수

코드 예시 · r

safe_ratio <- function(num, den) {
  ifelse(is.na(den) | den == 0, NA_real_, num / den)
}

분모가 0일 때 무조건 0을 반환하면 “기회가 없어서 측정 불가”와 “기회가 있었지만 발생 0”을 섞는다. 업무 정의에 따라 NA, 0, 별도 지시변수를 선택한다.

5.3 시간 창 변수

최근 7일·30일·90일 합계, 직전 기간 대비 변화율, 최근 활동 이후 일수는 예측에서 유용하다. 창의 시작·끝 포함 규칙과 시간대를 명시한다.

코드 예시 · r

in_window <- orders$order_date < snapshot_date &
             orders$order_date >= snapshot_date - 30
orders_30 <- orders[in_window, ]

order_date < snapshot_date는 기준 당일 정보의 사용 여부를 명시한 것이다. 실제 업무가 기준 시각까지 당일 자료를 쓸 수 있다면 시각 단위로 다시 정의한다.

5.4 범주화와 플래그

연속값을 구간화하면 설명이 쉬워지지만 정보가 줄고 경계 근처 값이 인위적으로 갈린다. 구간은 업무 기준 또는 학습 자료에서 정하고 평가 자료를 보고 유리하게 바꾸지 않는다.

5.5 데이터 누수

파생변수가 목표 사건 뒤에 생성된 값, 결과를 직접 반영한 코드, 전체 기간 통계, 평가 데이터의 평균을 사용하면 누수가 생긴다. 변수 이름이 과거형이어도 생성 시점을 확인한다.

6. 분석 단위 데이터셋 완성

분석 단위 데이터셋 완성은 집계표와 기준 모집단을 올바른 관계로 결합하고, 한 행의 의미·키·변수 시점·품질을 검증하는 단계다.

6.1 집계표 결합

코드 예시 · r

customer_features <- Reduce(
  function(x, y) merge(x, y, by = "customer", all = TRUE),
  list(amount_sum, unique_orders, return_count, last_order)
)

mart <- merge(customers, customer_features, by = "customer", all.x = TRUE)
mart$total_amount[is.na(mart$total_amount)] <- 0
mart$order_count[is.na(mart$order_count)] <- 0
mart$return_count[is.na(mart$return_count)] <- 0
mart$return_rate <- safe_ratio(mart$return_count, mart$order_count)
mart

주문 없는 고객 E의 금액·건수는 업무 정의상 0으로 두지만 마지막 주문일과 최근성은 관측이 없으므로 NA를 유지할 수 있다. 모든 결측을 같은 값으로 채우지 않는다.

6.2 조인 카디널리티

고객 1행과 고객별 집계 1행을 결합하면 일대일이다. 집계하지 않은 주문표를 고객표에 붙이면 일대다로 행이 늘어난다. 두 일대다 테이블을 고객키만으로 결합하면 다대다 곱으로 금액이 중복될 수 있다.

코드 예시 · r

stopifnot(!anyDuplicated(mart$customer))
stopifnot(nrow(mart) == nrow(customers))
stopifnot(all(mart$order_count >= 0))

6.3 완성 검증

  • 행 수와 유일 키가 예상과 같은가?
  • 분석 모집단이 필터·조인 때문에 사라지지 않았는가?
  • 합계가 원천 통제 합계와 일치하는가?
  • 비율 범위와 날짜 논리가 유효한가?
  • 기준 시점 이후 정보가 없는가?
  • 변수명·단위·계산식·결측 의미가 문서화됐는가?
  • 학습과 운영에서 같은 파이프라인이 재현되는가?

7. 구체 사례: 고객 월별 구매 마트

목표는 2026년 2월 1일 기준 고객별 최근 30일 활동으로 상담 우선순위를 지원하는 것이다.

  1. 고객 기준표를 모집단으로 고정한다.
  2. 주문을 [2026-01-02, 2026-02-01) 범위로 제한한다.
  3. 행별 금액을 계산한 뒤 고객별 총액·고유 주문 수·반품 수·마지막 주문일을 집계한다.
  4. 고객 기준표에 왼쪽 결합해 주문 없는 고객을 보존한다.
  5. 주문 없는 경우 건수·금액은 0, 최근일은 NA라는 의미를 정한다.
  6. 반품률의 분모 0은 NA로 두고 “무구매” 플래그를 별도로 만든다.
  7. 키 유일성, 전체 합계, 날짜·비율 범위와 기준 시점을 검증한다.

분석용 마트를 다시 상품군별로 만들면 한 행이 고객–상품군이 되므로 키와 행 수가 달라진다. 같은 파일명으로 덮지 말고 입도와 기준 시점을 메타정보에 포함한다.

8. 작업 체크리스트

  • [ ] 한 행의 분석 단위와 유일 키를 먼저 정의했다.
  • [ ] 원천 행 수와 사건 고유 건수를 구분했다.
  • [ ] 집계 함수가 변수의 의미와 단위에 맞다.
  • [ ] 평균의 평균 대신 건수·가중치를 고려했다.
  • [ ] 날짜 창과 경계·시간대·기준 시점이 명시됐다.
  • [ ] 파생변수 계산에 미래·목표·평가 정보가 없다.
  • [ ] 비율의 분모 0과 결측 의미를 구분했다.
  • [ ] 조인 전후 키 중복과 행 수 변화를 확인했다.
  • [ ] 원천 통제 합계와 마트 합계가 일치한다.
  • [ ] 변수 정의·단위·버전과 재현 코드를 남겼다.
09

9. 자주 틀리는 시험 함정

  1. 원천 행 수를 주문 고유 건수로 본다.
  2. 그룹 크기가 다른 평균들을 단순 평균한다.
  3. 고객 모집단 대신 주문표에서 시작해 무구매 고객을 잃는다.
  4. 두 일대다 테이블을 집계 없이 결합해 다대다 중복을 만든다.
  5. 분모 0인 비율을 무조건 0으로 바꾼다.
  6. 기준 시점 이후 정보로 파생변수를 만든다.
  7. 날짜 창의 시작·끝 포함 여부를 기록하지 않는다.
  8. na.rm = TRUE를 결측이 0이라는 뜻으로 해석한다.
  9. 모든 결측을 같은 값으로 대치해 미관측과 0을 섞는다.
  10. 행 수만 맞으면 키·합계·시점 검증이 끝났다고 본다.

11. 정답과 해설

문제 1 정답과 해설

입도는 원천 한 행이 나타내는 단위이고 분석 단위는 최종 한 행의 의미다. 원천이 더 세밀하면 분석 키로 그룹화해 집계하며 최종 유일 키를 확인한다.

문제 2 정답과 해설

한 주문에 여러 상품이 있으면 같은 주문번호가 여러 행에 나타난다. 행 수는 상품 줄 수이고 주문 건수는 고유 주문번호 수다.

문제 3 정답과 해설

지점별 표본 수가 다르면 각 평균의 단순 평균은 작은 지점에도 같은 가중치를 준다. 원래 합계와 건수를 합쳐 계산하거나 표본 수로 가중한다.

문제 4 정답과 해설

주문 금액은 각 행에서 수량 × 단가를 계산한 뒤 고객별로 합산한다. 평균 단가와 총수량을 곱하면 상품별 수량 차이 때문에 값이 달라질 수 있다.

문제 5 정답과 해설

분모 0은 사건 기회가 없어 비율을 정의할 수 없다는 뜻일 수 있다. 실제 사건 0과 구분해 NA와 별도 지시변수 등 업무 규칙을 적용한다.

문제 6 정답과 해설

창의 끝이 기준 시점 이전인지, 각 값이 그때 실제 사용 가능했는지, 전체·평가 기간 통계를 사용하지 않았는지, 시간대와 경계 포함 규칙을 확인한다.

문제 7 정답과 해설

전체 고객 기준표를 왼쪽에 두고 고객별로 이미 한 행이 된 집계표를 all.x = TRUE와 같은 왼쪽 결합으로 붙여야 한다.

문제 8 정답과 해설

유일 키·행 수, 원천과 집계 합계, 비율·날짜 범위, 모집단 누락, 미래 정보, 결측 의미와 변수 정의를 확인한다.

문제 9 정답과 해설

분석 단위·기준 시점 정의 → 관찰 기간 필터 → 행 파생 → 그룹별 집계 → 기준 모집단에 결합 → 결측·비율 의미 결정 → 키·행·합계·시점 검증 순이다.

12. 핵심 요약

  • 그룹별 집계는 분석 단위 키로 행을 묶어 의미에 맞는 합계·고유 건수·평균·날짜·조건부 통계를 계산하는 작업이다.
  • 파생변수 생성은 행·시간·비율·범주 정보를 분석 목적에 맞게 표현하되 분모 0과 데이터 누수를 통제하는 작업이다.
  • 분석 단위 데이터셋 완성은 기준 모집단에 집계표를 올바른 카디널리티로 결합하고 한 행의 의미와 유일 키를 보장하는 과정이다.
  • 행 수와 사건 수, 평균과 가중평균, 미관측과 0, 기준 시점 이전과 이후 정보를 반드시 구분한다.
  • 최종 마트는 코드 실행 성공이 아니라 키·행 수·통제 합계·범위·시점·결측 의미와 운영 재현성 검증으로 완성된다.
