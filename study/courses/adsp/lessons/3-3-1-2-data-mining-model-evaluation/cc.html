FF 원문 제목3-3-1-2. 데이터 마이닝 모델 평가

학습 범위: 이 레슨은 ADsP 데이터분석 > 정형 데이터 마이닝 > 데이터 마이닝 개요 중 학습·검증·테스트 데이터, 과대적합과 일반화, 교차검증과 성능 비교를 다룬다. 모델 적합·선택·최종 평가에 쓰는 데이터를 분리하고, 보지 않은 데이터에 대한 일반화 성능을 공정하게 추정하며, 교차검증의 설계와 불확실성을 반영해 후보를 비교하는 것이 목표다.

평가 지표의 종류 자체는 분류분석 전용 레슨에서 상세히 다룬다. 여기서는 어떤 자료로 언제 평가하는지가 중심이다. 높은 점수보다 먼저 데이터 누수, 반복 관측, 시간 순서와 튜닝 편향을 확인해야 한다.

01

1. 모델 평가가 답하는 질문

학습 데이터에서 오차가 작다는 사실은 모델이 이미 본 사례를 설명한다는 뜻이다. 실제 목표는 같은 생성 과정에서 앞으로 만날 새로운 사례에 얼마나 잘 작동하는가이다.

코드 예시 · text

원천 데이터
  → 학습: 모수·규칙 적합
  → 검증: 후보·하이퍼파라미터·임계값 선택
  → 테스트: 선택이 끝난 한 모델의 최종 일반화 평가

평가 설계는 모델을 만들기 전에 정한다. 후보 결과를 본 뒤 유리한 기간·지표·표본을 고르면 점수가 낙관적으로 편향된다.

02

2. 학습·검증·테스트 데이터

03

2.1 학습 데이터

학습·검증·테스트 데이터 중 학습 데이터(training set)는 모델의 계수, 규칙, 나무 분할, 이웃 구조와 전처리 통계 등을 적합하는 데 사용한다.

학습에서 추정해야 할 항목은 다음과 같다.

  • 결측 대치의 평균·중앙값·모형
  • 표준화의 평균·표준편차
  • 범주 사전과 희귀 범주 결합 규칙
  • 변수 선택·차원축소 방향
  • 모델 계수와 내부 구조

전체 데이터의 평균으로 표준화한 뒤 분할하면 검증·테스트 분포가 학습에 들어간다. 먼저 분할하고 학습에서 변환 규칙을 적합해 나머지에 고정 적용한다.

04

2.2 검증 데이터

검증 데이터(validation set)는 다음 선택에 사용한다.

  • 알고리즘·변수 조합 선택
  • 규제 강도·나무 깊이·이웃 수 같은 하이퍼파라미터 조정
  • 조기 종료 시점 선택
  • 분류 임계값 결정
  • 후보 중 최종 모델 선택

검증 데이터를 수십 번 확인해 선택하면 사실상 학습한 것과 비슷해진다. 최종 성능으로 보고하지 않고 독립 테스트를 남긴다.

05

2.3 테스트 데이터

테스트 데이터(test set)는 모든 모델·전처리·하이퍼파라미터·임계값 선택이 끝난 뒤 한 번에 가까운 독립 평가에 사용한다. 테스트 결과를 보고 다시 모델을 바꾸면 그 자료는 새 검증 데이터가 된다. 새로운 독립 테스트가 필요하다.

테스트는 실제 운영 조건을 대표해야 한다. 오래된 임의 표본만으로 미래·새 지점 성능을 보장하지 않는다.

06

2.4 단순 홀드아웃 분할

코드 예시 · r

set.seed(307)
n <- 100
id <- seq_len(n)

train_id <- sample(id, size = 60, replace = FALSE)
remain <- setdiff(id, train_id)
valid_id <- sample(remain, size = 20, replace = FALSE)
test_id <- setdiff(remain, valid_id)

c(train = length(train_id), valid = length(valid_id), test = length(test_id))
length(intersect(train_id, valid_id))

결과 크기는 60·20·20이고 교집합은 0이다. 비율은 절대 규칙이 아니다. 데이터량, 희귀 클래스, 튜닝 크기와 최종 평가 정밀도에 따라 정한다.

07

3. 분할 단위를 올바르게 정한다

무작위 행 분할이 항상 독립 평가를 만들지는 않는다.

3.1 반복 개체

한 고객의 여러 거래가 학습·테스트에 나뉘면 고객 고유 패턴을 외워 새 고객보다 높은 점수가 나온다. 적용 대상이 새 고객이면 고객 단위로 묶어 분할한다.

코드 예시 · r

set.seed(307)
customers <- paste0("C", sprintf("%02d", 1:20))
test_customers <- sample(customers, 4)

거래 행은 customer %in% test_customers로 한쪽에만 둔다.

3.2 시간 순서

미래 예측에서는 과거로 학습하고 이후 기간으로 평가한다. 무작위 분할은 미래 제도·상품·고객 정보가 학습에 섞이고 계절·변화를 평균화할 수 있다.

코드 예시 · text

학습: 1월~6월
검증: 7월~8월
테스트: 9월~10월

시간 교차검증은 학습 창을 확장하거나 이동시키면서 항상 검증보다 앞에 둔다.

3.3 공간·조직·장치

새 지점·병원·장비로 일반화하려면 해당 군집을 통째로 테스트에 남긴다. 같은 지점 표본을 무작위로 섞은 평가는 지점 효과를 학습할 수 있다.

3.4 계층·층화

클래스 비율이 매우 불균형하면 각 분할에 양성 사례가 거의 없을 수 있다. 층화 분할로 비율을 보존하되 고객·시간 그룹 제약과 함께 만족해야 한다. 단순 층화가 독립성을 대신하지 않는다.

08

4. 과대적합과 일반화

09

4.1 과소적합

과대적합과 일반화 중 과소적합(underfitting)은 모델이 너무 단순하거나 학습이 부족해 실제 구조를 포착하지 못한 상태다. 학습·검증 오차가 모두 높다.

10

4.2 과대적합

과대적합(overfitting)은 학습 자료의 일반 구조뿐 아니라 우연한 잡음까지 맞춰 학습 성능은 높지만 새로운 자료 성능이 나쁜 상태다.

4.2 과대적합 · 학습 표 1
상태학습 성능검증·테스트 성능대응 방향
과소적합낮음낮음표현·모델 용량·학습 점검
적절높음비슷하게 높음독립 평가·운영 검증
과대적합매우 높음현저히 낮음규제·단순화·자료·검증 개선

과대적합 원인은 복잡한 모델만이 아니다. 작은 표본, 많은 변수·후보 반복, 라벨 오류, 누수, 비대표 검증자료도 원인이다.

11

4.3 편향–분산 관점

모델이 단순하면 평균적으로 구조를 놓치는 편향이 클 수 있고, 지나치게 유연하면 표본이 바뀔 때 예측이 크게 달라지는 분산이 커질 수 있다. 테스트 오차를 개념적으로

[ text{예측오차} approx text{편향}^2 + text{분산} + text{줄일 수 없는 잡음} ]

으로 이해할 수 있다. 모든 문제에서 복잡도를 낮추는 것이 답은 아니며 검증으로 균형을 찾는다.

12

4.4 일반화

일반화는 학습하지 않은 대상에서 성능을 유지하는 능력이다. “어디까지 새로움”인지 명시한다.

  • 같은 기간의 새 행
  • 미래 기간
  • 새 고객·지점·장치
  • 정책·상품 변화 이후

한 조건의 일반화 결과를 다른 조건으로 확대하지 않는다. 시간 외삽과 새 기관 외삽은 별도 평가다.

13

5. 데이터 누수

누수(leakage)는 실제 예측 시점에 사용할 수 없거나 검증·테스트에서만 알아야 할 정보가 학습에 들어가는 것이다.

5. 데이터 누수 · 학습 표 2
누수 유형예방지
목표 누수해지 후 처리 코드로 해지 예측기준 시점 변수 목록
전처리 누수전체 데이터 평균으로 대치학습에서 적합·고정 적용
그룹 누수같은 환자 기록이 양쪽에 존재환자 단위 분할
시간 누수미래 집계가 과거 행에 포함시점 기반 창·분할
선택 누수테스트를 보고 변수·모델 선택독립 테스트 봉인

성능이 지나치게 높거나 단순 식별자가 강한 변수일 때 누수를 의심한다. 변수 이름보다 생성 과정과 이용 시점을 확인한다.

14

6. 교차검증

교차검증과 성능 비교 중 교차검증(cross-validation)은 데이터의 여러 부분을 번갈아 검증으로 사용해 홀드아웃 한 번의 우연성을 줄이는 방법이다.

15

6.1 k-겹 교차검증

데이터를 k개 폴드로 나누고 매번 하나를 검증, 나머지를 학습에 사용한다. k회 점수를 평균하고 변동을 함께 본다.

코드 예시 · r

set.seed(307)
n <- 20
k <- 5
fold_id <- sample(rep(1:k, length.out = n))
table(fold_id)

각 폴드가 4개씩이다. 실제 모델 평가에서는 각 반복 안에서 전처리 적합부터 모델 학습까지 다시 수행해야 한다.

[ overline{M}=frac{1}{k}sum{j=1}^{k}Mj ]

평균만 보고 후보를 고르지 말고 폴드별 분산, 최악 성능, 집단·기간 차이를 확인한다.

16

6.2 LOOCV

Leave-One-Out CV는 n개 중 하나씩 검증해 n번 학습한다. 학습 자료를 많이 쓰지만 계산량이 크고 추정 분산이 반드시 낮은 것은 아니다. 반복 관측·시간 구조를 자동 해결하지 않는다.

17

6.3 반복 교차검증

폴드 분할을 여러 시드로 반복해 분할 우연성을 본다. 같은 데이터가 반복 사용되므로 단순 독립 반복처럼 표준오차를 계산하지 않는다. 반복 결과는 안정성 진단으로 사용한다.

18

6.4 층화·그룹·시간 교차검증

  • 층화 CV: 각 폴드의 클래스 비율을 비슷하게 유지
  • 그룹 CV: 같은 고객·기관을 한 폴드에만 배치
  • 시간 CV: 과거 학습–미래 검증 순서를 유지

문제 구조에 맞는 제약이 일반 k-fold보다 우선한다.

19

7. 하이퍼파라미터와 중첩 교차검증

하이퍼파라미터를 같은 교차검증 점수로 선택하면 그 점수는 선택 과정에 최적화되어 약간 낙관적이다. 최종 일반화 추정에는 독립 테스트나 중첩 교차검증을 사용한다.

코드 예시 · text

바깥 폴드: 최종 평가 역할
  └─ 안쪽 폴드: 하이퍼파라미터·후보 선택
       → 선택 모델을 바깥 학습 전체에 적합
       → 바깥 검증에서 평가

모든 후보가 같은 바깥 분할을 사용해야 비교가 가능하다. 중첩 CV는 계산량이 크므로 데이터량·후보 수와 독립 테스트 보유 여부에 따라 선택한다.

20

8. 성능 비교

8.1 같은 사례와 지표

후보 A와 B를 같은 폴드·같은 전처리·같은 지표로 평가한다. 서로 다른 분할 평균을 비교하면 분할 차이와 모델 차이가 섞인다.

8.2 차이와 불확실성

평균 0.812와 0.815 차이가 실질적인지 본다. 폴드별 차이, 시간·집단 안정성, 반복 변동과 업무 비용을 확인한다. 교차검증 폴드는 독립 표본이 아니므로 단순 t검정을 기계적으로 적용하지 않는다.

8.3 다중 비교

수백 후보 중 최고 점수는 우연히 높을 수 있다. 탐색 범위를 제한하고 단순 기준선, 사전 계획, 중첩 평가와 최종 테스트를 사용한다.

8.4 성능 외 기준

점수가 비슷하면 설명성, 학습·예측 시간, 메모리, 안정성, 데이터 요구, 유지보수, 공정성과 오류 비용을 비교한다. 약간 높은 점수가 운영 기준 위반을 상쇄하지 않는다.

21

9. 평가 판단 절차

  1. 적용 대상과 일반화 조건·기준 시점을 정의한다.
  2. 분할 단위를 행·고객·시간·기관 중 올바르게 정한다.
  3. 독립 테스트를 봉인하고 학습·검증 구조를 설계한다.
  4. 모든 전처리·변수선택·튜닝을 학습·검증 안에서 수행한다.
  5. 후보에 동일 폴드·지표·업무 제약을 적용한다.
  6. 평균뿐 아니라 변동·최악 집단·시간 안정성을 비교한다.
  7. 모델 선택 후 테스트에서 한 번 평가하고 신뢰구간·표본 수를 보고한다.
  8. 운영 데이터 품질·분포·성능·업무 효과 감시를 연결한다.
22

10. 사례: 고객 이탈 모델

한 고객에게 월별 행이 12개씩 있다. 행을 무작위로 나누면 같은 고객이 학습·테스트에 들어가 누수가 생긴다.

  1. 미래 신규 고객에 적용하려면 고객 단위 그룹 분할을 한다.
  2. 기존 고객의 다음 달을 예측한다면 과거 월 학습–미래 월 테스트를 사용한다.
  3. 결측 대치와 표준화는 각 학습 폴드에서 계산한다.
  4. 여러 모델·임계값은 검증 또는 안쪽 CV로 선택한다.
  5. 동일 고객·기간 조건의 독립 테스트를 마지막에 사용한다.
  6. 평균 성능뿐 아니라 신규·장기 고객, 월별 변화와 상담 용량을 본다.
23

11. 체크리스트

  • [ ] 모델 선택과 최종 평가 자료를 분리했다.
  • [ ] 전처리·변수선택도 평가 루프 안에서 적합했다.
  • [ ] 고객·시간·기관 반복 구조를 분할에 반영했다.
  • [ ] 테스트 결과를 보고 다시 모델을 바꾸지 않았다.
  • [ ] 과소·과대적합과 누수를 구분했다.
  • [ ] k-fold의 각 폴드에서 전체 학습 절차를 반복했다.
  • [ ] 튜닝 점수와 독립 일반화 점수를 구분했다.
  • [ ] 후보가 같은 폴드·지표·표본으로 비교됐다.
  • [ ] 평균·변동·집단·기간·업무 비용을 함께 봤다.
  • [ ] 평가 설계와 시드·데이터·코드 버전을 기록했다.
24

12. 자주 틀리는 시험 함정

  1. 검증 데이터와 테스트 데이터를 같은 선택 용도로 쓴다.
  2. 테스트 성능을 보고 하이퍼파라미터를 바꾼 뒤 같은 점수를 최종 보고한다.
  3. 분할 전 전체 데이터로 대치·표준화한다.
  4. 같은 고객의 반복 행을 독립으로 무작위 분할한다.
  5. 미래 예측에서 시간 순서를 무시한 k-fold만 쓴다.
  6. 학습 성능이 높으면 일반화도 높다고 본다.
  7. LOOCV가 모든 상황에서 가장 정확하고 편향이 없다고 본다.
  8. 교차검증 평균만 보고 폴드 변동을 무시한다.
  9. 많은 후보 중 최고 점수가 선택 편향을 갖지 않는다고 본다.
  10. 작은 성능 차이가 설명성·비용·위험보다 항상 중요하다고 본다.

14. 정답과 해설

문제 1 정답과 해설

학습은 모델·전처리 모수를 적합하고, 검증은 후보·하이퍼파라미터·임계값을 선택하며, 테스트는 모든 선택 뒤 한 모델의 최종 일반화 성능을 평가한다.

문제 2 정답과 해설

반복 선택이 검증자료의 우연한 특성에 맞춰져 점수가 낙관적으로 된다. 선택에 사용하지 않은 테스트나 바깥 CV가 필요하다.

문제 3 정답과 해설

고객 고유 패턴이 양쪽에 들어가 모델이 새 고객 일반화가 아니라 동일 고객 인식을 하게 되고 성능이 과대평가된다.

문제 4 정답과 해설

과소적합은 학습·검증 성능이 모두 낮다. 과대적합은 학습 성능은 매우 높지만 검증·테스트 성능이 크게 낮아 간격이 크다.

문제 5 정답과 해설

전체 데이터 평균 대치, 결과 뒤 생성된 변수, 동일 고객의 양쪽 포함, 미래 기간 정보 사용, 테스트를 보고 변수 선택을 들 수 있다.

문제 6 정답과 해설

k개 폴드 중 하나씩 검증하고 나머지로 전체 파이프라인을 적합해 k회 점수를 얻는다. 평균은 (bar M=k^{-1}sum{j=1}^kMj)다.

문제 7 정답과 해설

층화는 희귀 클래스 비율 유지, 그룹은 고객·기관 반복을 한쪽에 묶기, 시간 CV는 과거 학습으로 미래를 평가할 때 사용한다.

문제 8 정답과 해설

안쪽 루프는 바깥 학습 자료 안에서 후보와 하이퍼파라미터를 선택한다. 바깥 루프는 그 선택 절차 전체를 보지 않은 자료에서 평가한다.

문제 9 정답과 해설

일반화 대상 정의 → 그룹·시간을 반영한 분할 → 테스트 봉인 → 학습 내부 전처리·튜닝 → 동일 폴드·지표 비교 → 변동·업무 조건 선택 → 테스트 최종 평가 → 운영 감시 순이다.

27

15. 핵심 요약

  • 학습·검증·테스트 데이터는 각각 적합, 선택, 최종 평가 역할이며 전처리·변수선택도 이 경계를 지켜야 한다.
  • 과대적합과 일반화는 학습 잡음에 맞춘 성능과 새 고객·미래·새 기관에서 유지되는 성능을 구분하는 개념이다.
  • 교차검증과 성능 비교는 k개 부분을 번갈아 평가하되 클래스·그룹·시간 구조와 튜닝 선택 편향을 반영해야 한다.
  • 후보는 동일 폴드·지표·전처리로 비교하고 평균뿐 아니라 변동·집단·기간·업무 비용을 본다.
  • 테스트를 선택에 사용하지 않고 데이터 누수 없는 전체 절차를 평가해야 일반화 성능을 신뢰할 수 있다.
