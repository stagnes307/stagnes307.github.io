🌐 1. 공개 데이터 접근

공개 데이터 접근이란 무엇인가

공개 데이터는 정부·공공기관·기업·연구기관 등이 외부에 제공하는 데이터야.

  • 공공데이터포털의 CSV 파일
  • 행정기관의 Excel 통계자료
  • 기상·교통 등의 Open API
  • 공개된 JSON 데이터
  • 분석용으로 제공된 CSV 데이터셋

여기서 먼저 판단할 것은 “어떤 방식으로 제공되고 있는가?”야.

파일인가, API인가

이 구분이 첫 번째 분기점이야.

파일이면 읽으면 되고, API이면 요청해야 해. 이 차이를 확실하게 잡아두자.

CSV 파일 접근

가장 기본적인 형태야.

import pandas as pd

df = pd.read_csv("data.csv")

여기서 일어나는 일을 풀면,

data.csv
   ↓ read_csv()
pandas
   ↓
DataFrame df

즉 pd.read_csv()는 단순한 파일 열기가 아니라 CSV 데이터를 DataFrame으로 적재하는 함수야.

URL에 있는 CSV도 직접 읽을 수 있어

import pandas as pd

url = "https://example.com/data.csv"

df = pd.read_csv(url)
웹 서버의 CSV
      ↓
   URL 접근
      ↓
pd.read_csv()
      ↓
 DataFrame

Excel 데이터

df = pd.read_excel("data.xlsx")

여러 시트가 있으면 특정 시트를 지정할 수도 있어.

df = pd.read_excel("data.xlsx", sheet_name="Sheet1")

즉 시험에서 가장 먼저 생각해야 하는 대응 관계는 이거야.

데이터대표 함수

📡 2. API를 통한 공개 데이터 접근

파일은 이미 만들어진 데이터를 가져오는 방식이야. API는 조금 다르다.

서버에 원하는 데이터를 요청하면 서버가 결과를 보내주는 방식이야.

API 요청의 구조

나
↓
"서울의 특정 데이터를 주세요"
↓
API 서버
↓
JSON 등의 응답
↓
나

Python에서는 보통 requests 라이브러리를 사용해.

import requests

url = "https://api.example.com/data"

response = requests.get(url)

여기서 중요한 구분이 하나 있어.

response ≠ DataFrame

응답에서 데이터를 꺼내고 다시 DataFrame으로 만들어야 해.

JSON 응답 처리

import requests
import pandas as pd

url = "https://api.example.com/data"

response = requests.get(url)

data = response.json()

df = pd.DataFrame(data)

전체 흐름은 이거야.

API 서버
→
requests.get()
→
response.json()
→
DataFrame

requests.get()이 데이터를 요청하고, response.json()이 응답 내용을 Python 자료구조로 변환하고, pd.DataFrame()이 그것을 분석 가능한 표로 적재하는 거야.

🧩 3. API의 파라미터

공개 API에서는 전체 데이터를 무작정 보내주지 않는 경우가 많아. 우리가 조건을 지정해 요청하지. 

지역 = 서울
연도 = 2025
페이지 = 1
한 페이지 데이터 수 = 100

같은 조건이 파라미터야.

params = {
    "region": "Seoul",
    "year": 2025,
    "page": 1,
    "perPage": 100
}

response = requests.get(url, params=params)

즉 requests.get(url)은 단순 요청이고, requests.get(url, params=params)은 조건을 포함한 요청이라고 보면 돼.

인증키가 있는 경우

공공 API에는 흔히 서비스키나 인증키가 필요해.

params = {
    "serviceKey": "발급받은_인증키",
    "pageNo": 1,
    "numOfRows": 100
}
response = requests.get(url, params=params)
API는 URL + 필요한 요청 파라미터를 이용해 데이터를 요청한다.

📥 4. 데이터 수집

접근할 수 있다고 해서 수집이 끝난 건 아니야. 데이터를 실제로 확보해야 하지.

파일형 데이터의 수집

df = pd.read_csv("data.csv")
파일 읽기
+
DataFrame 적재

그래서 파일형 데이터는 접근·수집·적재가 거의 동시에 일어나는 경우가 많아.

API형 데이터의 수집

import requests

response = requests.get(url, params=params)

여기서 반드시 확인할 만한 것이 응답 상태야.

print(response.status_code)

대표적으로 HTTP 상태 코드 200은 요청이 정상적으로 처리됐다는 뜻이야.

요청
↓
서버 응답
↓
상태 확인
↓
데이터 변환

정상 응답만 처리하는 구조

response = requests.get(url, params=params)

if response.status_code == 200:
    data = response.json()
else:
    print("데이터 수집 실패")
중요한 사고 습관: “코드가 실행됐다”와 “데이터가 정상적으로 수집됐다”는 같은 말이 아니다.

🪆 6. 실제 API JSON이 한 단계 더 복잡한 이유

API 응답에서 초보자가 자주 막히는 곳이 있어. JSON 안에 우리가 원하는 데이터가 바로 있지 않고 중첩되어 있는 경우야. 

data = {
    "response": {
        "items": [
            {"city": "서울", "value": 10},
            {"city": "부산", "value": 20}
        ]
    }
}

그냥 pd.DataFrame(data)한다고 우리가 원하는 표가 만들어지지는 않아.

먼저 실제 데이터가 있는 위치까지 들어가야 해.

items = data["response"]["items"]

df = pd.DataFrame(items)
data
└─ response
   └─ items
      ├─ 서울 / 10
      └─ 부산 / 20

따라서 필요한 것은 data["response"]["items"]야.

핵심 원칙

JSON API를 만나면 바로 DataFrame부터 만들려고 하지 말고, “실제 행 데이터가 JSON의 어느 위치에 들어 있지?”부터 확인해야 해.

🔎 수집 결과 확인

데이터를 적재하고 바로 모델링으로 가면 안 돼. 데이터가 의도한 모습으로 들어왔는지 먼저 확인해야 해.

👀 1. 데이터 일부 확인 — head()

df.head()
df.head(10)
  • 열 이름이 맞는지
  • 데이터가 실제로 들어왔는지
  • 값의 형태가 예상과 비슷한지

📐 2. 데이터 크기 확인 — shape

df.shape
# (행, 열)

예: (1000, 8) → 1000행 × 8열.

🏷️ 3. 열 이름 확인 — columns

df.columns

분석 전에 필요한 변수가 실제로 있는지 확인하는 데 사용해.

🧬 4. 자료형과 결측 상태 확인 — info()

df.info()

행 수, 열 이름, Non-Null 개수, 데이터 타입을 확인할 수 있어.

🕳️ 5. 결측치 확인

df.isnull().sum()
df.isna().sum()

각 열에 결측값이 몇 개 있는지 확인해.

📊 6. 기초 통계량 확인 — describe()

df.describe()

개수, 평균, 표준편차, 최솟값, 사분위수, 최댓값 등을 확인해.

⚠️ 공개 데이터에서 자주 만나는 문제

한글이 깨진다 — 인코딩

df = pd.read_csv("data.csv")

파일의 인코딩에 따라,

df = pd.read_csv("data.csv", encoding="cp949")
df = pd.read_csv("data.csv", encoding="euc-kr")
UnicodeDecodeError 같은 문제가 나면 파일의 문자 인코딩이 현재 읽는 방식과 맞지 않을 가능성을 의심한다.

구분자가 쉼표가 아니다

df = pd.read_csv("data.csv", sep=";")
df = pd.read_csv("data.tsv", sep="\t")

즉 read_csv()의 본질은 단순히 .csv 확장자를 읽는 것이 아니라 구분자로 나뉜 표 형태의 데이터를 읽는 것이라고 이해하면 좋아.

🔄 공개 API의 여러 페이지 수집

공개 API에서는 데이터를 한 번에 전부 보내주지 않는 경우가 많아. 

1페이지 → 100건
2페이지 → 100건
3페이지 → 100건
...

이걸 페이지네이션(pagination)이라고 해.

all_data = []

for page in range(1, 6):

    params = {
        "page": page,
        "perPage": 100
    }

    response = requests.get(url, params=params)
    data = response.json()

    all_data.extend(data)
df = pd.DataFrame(all_data)
page 1 ─┐
page 2 ─┤
page 3 ─┼→ all_data → DataFrame
page 4 ─┤
page 5 ─┘

이 부분에서 중요한 건 코드 자체보다 왜 반복하는지야. API가 한 번에 제공하는 데이터 개수가 제한되어 있기 때문이야.

🎯 실기에서 특히 구별해야 할 포인트

requests.get()과 pd.read_csv()는 역할이 다르다

pd.read_csv(...)는 표 형태 파일을 읽어서 DataFrame으로 적재하는 쪽이고, requests.get(...)은 웹 서버에 HTTP 요청을 보내 응답을 받는 것이야.

requests.get() 결과가 바로 DataFrame은 아니지.

response.json()과 pd.DataFrame()도 다르다

data = response.json()은 JSON 응답을 Python 리스트나 딕셔너리 등의 구조로 바꾸는 단계야. 그 다음 df = pd.DataFrame(data)가 표 형태 DataFrame을 만드는 단계고.

response → Python 자료구조 → DataFrame

head()만 보고 끝내면 부족하다

데이터가 존재하는 것과 분석 가능한 상태인 것은 다르기 때문에 df.shape, df.info(), df.isnull().sum() 같은 구조 확인도 같이 하는 게 좋아.
