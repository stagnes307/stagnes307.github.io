#빅데이터분석기사 #실기 #분석모형선택 #후보모형 #데이터특성 #분석목적

🎯 먼저 잡을 핵심: “좋은 모형”이 아니라 “이 문제에 맞는 모형”

빅데이터분석기사 실기에서 후보 모형 선정과 비교의 핵심은 특정 알고리즘을 외우는 게 아니야.

판단 순서는 거의 항상 이렇게 잡으면 돼.

데이터 특성 파악 → 분석 목적 확인 → 가능한 후보 모형 선정 → 같은 기준으로 비교 → 최종 모형 결정

즉, 랜덤포레스트가 강력하다거나 XGBoost가 성능이 좋다는 사실만으로 모형을 고르면 안 돼.
무엇을 예측하려는지, 목표변수가 어떤 형태인지, 데이터 크기와 변수 구조가 어떤지가 먼저야.

🔍 1. 데이터 특성 파악: “이 데이터가 어떤 모형을 허용하지?”

모형을 고르기 전에 가장 먼저 볼 건 데이터의 구조야.

목표변수의 형태

가장 중요한 기준이야.

목표변수	문제 유형	대표 후보 모형
연속형 수치	회귀	선형회귀, 의사결정나무 회귀, 랜덤포레스트 회귀
범주형	분류	로지스틱 회귀, 의사결정나무, 랜덤포레스트, 부스팅
목표변수 없음	군집	K-means, 계층적 군집
시간의 흐름이 중요	시계열	시계열 모형, 시계열 기반 예측

예를 들어,

고객의 구매금액을 예측한다 → 회귀

고객이 이탈한다/안 한다를 예측한다 → 분류

비슷한 고객끼리 그룹을 나눈다 → 군집

여기서 가장 먼저 갈리는 거야.

변수의 형태도 본다

입력변수가 어떤 형태인지도 중요해.

연속형 변수가 많은가?

범주형 변수가 많은가?

결측치가 있는가?

이상치가 많은가?

변수 수가 매우 많은가?

데이터 수가 충분한가?

클래스가 불균형한가?

예를 들어 선형모형은 변수와 목표값 사이의 선형적 관계를 잘 포착하지만, 복잡한 비선형 관계에서는 한계가 있을 수 있어.

반대로 의사결정나무 계열은 비선형적인 관계를 비교적 자연스럽게 표현할 수 있어.

데이터 크기도 중요하다

데이터가 작으면 너무 복잡한 모형은 오히려 과적합될 수 있어.

반대로 데이터가 매우 많고 변수 간 관계가 복잡하면 단순한 선형모형만으로 충분한 성능을 얻기 어려울 수도 있어.

그래서 데이터 특성 파악은 결국 이런 질문이야.

“이 데이터에 어떤 모형이 적절한가?”

🎯 2. 분석 목적 확인: “내가 무엇을 잘해야 하지?”

같은 데이터라도 분석 목적이 다르면 좋은 모형이 달라져.

예측 정확도가 가장 중요한 경우

예를 들어 고객 이탈을 최대한 정확히 맞히는 것이 목적이라면,

랜덤포레스트

Gradient Boosting

XGBoost 계열

같은 복잡한 모형을 후보로 고려할 수 있어.

이때는 예측 성능이 중요한 비교 기준이 돼.

설명력이 중요한 경우

은행 대출심사처럼

“왜 이 고객을 위험 고객으로 판단했는가?”

를 설명해야 한다면 복잡한 모형보다 해석이 쉬운 모형이 더 적합할 수 있어.

예를 들어

선형회귀

로지스틱 회귀

비교적 작은 의사결정나무

등이 후보가 될 수 있지.

여기서는 단순히 성능만 볼 게 아니라 해석 가능성도 평가해야 해.

운영 효율이 중요한 경우

실제 서비스에서는

학습 시간이 너무 긴가?

예측 시간이 너무 긴가?

메모리를 지나치게 사용하는가?

유지보수가 어려운가?

같은 현실적인 조건도 중요해.

따라서 모형 선택은 결국 성능과 제약조건 사이의 균형이야.

🧩 3. 후보 모형 선정: 처음부터 하나만 선택하지 않는다

실기에서 중요한 사고방식 하나.

처음부터 최종 모형을 결정하지 않는다.

먼저 몇 개의 합리적인 후보 모형을 만든 뒤 성능을 비교해.

예를 들어 이진 분류 문제라고 해보자.

후보를 이렇게 만들 수 있어.

기준 모형

로지스틱 회귀

장점:

구조가 단순함

학습이 빠름

해석이 쉬움

기준 성능을 만들기 좋음

이런 모형을 흔히 baseline model, 즉 기준 모형으로 활용해.

비선형 후보

의사결정나무

장점:

비선형 관계 표현 가능

변수 간 상호작용을 표현하기 쉬움

결과 해석이 비교적 직관적

단점:

깊어지면 과적합하기 쉬움

앙상블 후보

랜덤포레스트

여러 개의 결정나무를 결합해서 예측해.

일반적으로 단일 결정나무보다 안정적인 경우가 많아.

부스팅 후보

Gradient Boosting 계열의 모형도 고려할 수 있어.

이 계열은 이전 모형의 오차를 다음 모형이 보완하면서 학습하는 방식이야.

복잡한 관계를 잘 학습해서 높은 예측력을 얻을 가능성이 있지만, 하이퍼파라미터 조정과 계산 비용 등을 함께 봐야 해.

⚖️ 4. 후보 모형 비교: 같은 시험장에서 경쟁시켜야 한다

후보 모형을 만들었다면 같은 조건에서 비교해야 해.

여기서 중요한 원칙은

동일한 학습 데이터와 동일한 검증 기준으로 비교한다.

A 모델은 학습 데이터 성능을 보고, B 모델은 테스트 데이터 성능을 보면 공정한 비교가 아니겠지.

그래서 일반적으로

학습 데이터 → 모델 학습
검증 또는 테스트 데이터 → 성능 비교

라는 구조를 사용해.

📊 5. 분류 문제에서 모형 비교

분류에서는 여러 평가 지표가 있어.

Accuracy 정확도

전체 예측 중 맞힌 비율이야.

Accuracy=
TP+TN+FP+FN
TP+TN
	​


직관적이지만 불균형 데이터에서는 주의해야 해.

예를 들어 전체 고객의 99%가 정상이고 1%가 이상 고객이라면 모든 고객을 정상이라고 예측해도 정확도는 99%가 되겠지.

그래서 다른 지표를 함께 봐야 해.

“Positive라고 잡은 것 중 얼마나 진짜였나?”

실제 Positive 중 모형이 찾아낸 비율.

즉,

“실제로 찾아야 할 것 중 얼마나 찾아냈나?”

F1-score

F1=2×
Precision+Recall

	​


둘 사이의 균형을 보고 싶을 때 많이 사용해.

ROC-AUC

분류 임계값을 변화시켰을 때 모형이 양성과 음성을 얼마나 잘 구별하는지를 평가하는 대표적인 지표야.

AUC가 클수록 일반적으로 분류 능력이 좋다고 볼 수 있어.

🧠 시험에서 특히 중요한 사고방식
🔄 학습 성능이 좋다고 좋은 모형은 아니다

예를 들어 두 모델이 있다고 해보자.

모델	Train Accuracy	Test Accuracy
A	99%	78%
B	91%	88%

처음 보면 A가 좋아 보일 수 있어.

그런데 실제로 새로운 데이터에 대한 성능은 B가 더 좋아.

A는 학습 데이터를 지나치게 잘 외운 과적합(overfitting) 가능성이 커.

따라서 후보 모형 비교에서는

훈련 데이터 성능보다 검증·테스트 데이터에서의 일반화 성능

이 중요해.

⚖️ 성능 차이가 작다면 단순한 모형이 유리할 수도 있다

예를 들어

모델	Accuracy
Logistic Regression	0.89
Random Forest	0.90

성능 차이가 0.01이라면 무조건 랜덤포레스트를 선택해야 할까?

그렇지는 않아.

해석이 쉽고

학습이 빠르고

운영이 간단하다

는 장점이 있어.

따라서 실제 모형 선정은 보통 다음 요소를 함께 고려해.

예측 성능 + 해석 가능성 + 계산 비용 + 안정성 + 운영 목적
