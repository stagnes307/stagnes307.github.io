목표 변수의 의미

목표 변수(target variable)는 분석모형이 예측하거나 설명하려는 대상이야.

종속 변수(dependent variable), 반응 변수(response variable), 타깃(target), 레이블(label) 같은 표현도 만나게 돼. 용어가 조금 달라도 핵심 관계는 같아.

입력 데이터 → 모형 → 목표 변수 예측

고객 해지를 예측한다면 해지여부가 목표 변수야. 0은 유지, 1은 해지처럼 표현될 수 있어.

같은 데이터도 목적에 따라 달라진다

고객 해지 예측
목표 변수 → 해지여부
일반적 문제 유형 → 분류
다음 달 구매금액 예측
목표 변수 → 구매금액
일반적 문제 유형 → 회귀

0과 1로 저장되어 있어도 그것이 해지/유지라는 범주를 뜻한다면 분류 문제야. 저장 형식보다 의미를 봐야 해.

목표 변수 예 일반적인 문제
범주형합격/불합격분류
범주형A/B/C 고객군다중분류
연속형매출액회귀
연속형주택가격회귀

🧩 입력 변수는 “무엇을 보고 맞힐 것인가?”

목표 변수를 정했다면 다음 질문은 “그 목표를 예측하기 위해 모형에게 어떤 정보를 보여줄 것인가?”야. 그 정보들이 입력 변수(input variable)야.

독립 변수, 설명 변수, 예측 변수, 특징(feature) 같은 표현도 비슷한 관계를 가리켜. 머신러닝에서는 특히 feature라는 말을 많이 써.

변수역할
나이입력 변수
월소득입력 변수
이용기간입력 변수
최근접속일수입력 변수
해지여부목표 변수
CORE RELATION
나이 + 월소득 + 이용기간 + 최근접속일수
↓
해지여부
X = 입력 변수들의 집합
y = 목표 변수
X = df[['나이', '월소득', '이용기간', '최근접속일수']]
y = df['해지여부']

여기서 아직 모델을 학습시키는 게 아니야. 지금 하는 일은 “누가 문제를 풀고, 누가 정답인가”를 결정하는 단계라고 보면 돼.

🔍 모든 목표 변수 이외의 열이 입력 변수는 아니다

IDENTIFIER

고객ID

C001, C002 같은 값은 각 고객을 구분하기 위한 식별자일 가능성이 높아. 값 자체가 고객의 해지를 설명하는 의미 있는 특성은 아닐 수 있어.

→ 식별 변수로 유지하거나 분석 입력에서는 제외
LEAKAGE RISK

해지사유

해지할지 미리 예측하려는데 해지사유가 해지 후에 생기는 정보라면, 모형은 사실상 정답을 미리 보는 셈이야.

→ 데이터 누수(data leakage)
예측 시점 체크
이 정보, 그때도 알고 있을까?

🧠 변수 역할 확인 — 열마다 세 가지 질문을 던져

01

이것이 우리가 맞히려는 값인가?

그렇다면 목표 변수.

예: 부도여부 → 기업 부도 예측의 목표 변수
02

목표를 예측하는 데 사용할 정보인가?

그렇다면 입력 변수 후보.

부채비율 · 매출액 · 영업이익률 · 기업연령
03

예측에는 넣지 않아야 하는가?

그렇다면 식별·제외 변수.

ID · 순번 · 이름 · 원본 인덱스 · 예측 이후 정보
역할판단 질문
목표 변수무엇을 맞힐까?
입력 변수무엇을 보고 맞힐까?
식별·제외 변수모형에 보여주면 안 되는 것은 무엇일까?

⚠️ 시험에서 자주 흔들리는 세 가지 경계

숫자라고 전부 입력 변수인 것은 아니다

회원번호 10001, 10002 같은 값은 숫자형이어도 식별자일 수 있어. 숫자형 → 입력 변수라는 규칙은 없어.

문자열이라고 무조건 제외하는 것도 아니다

지역 = 서울/부산/대전 같은 변수는 문자열이지만 의미 있는 정보일 수 있어. 적절한 인코딩을 거치면 입력 변수로 사용할 수 있어.

목표 변수와 강하게 관련 있다고 무조건 좋은 변수도 아니다

합격여부 예측에 최종합격통보일을 넣는다면 성능은 좋아 보일 수 있지만, 예측 시점에 알 수 없는 정보라면 누수야.

좋은 입력 변수의 기준은 단순히 “목표 변수와 관계가 강한가?”가 아니라 “실제로 예측할 순간에도 이용 가능한가?”까지 포함해.

🛠️ 실기 코드에서는 어떻게 나타날까?

train 데이터의 목표 변수가 target이라면 가장 기본적인 구조는 이렇게 잡을 수 있어.

X = train.drop(columns=['target'])
y = train['target']

식별 변수 id까지 제외해야 한다면:

X = train.drop(columns=['target', 'id'])
y = train['target']
target
정답이므로 X에서 제거
id
식별용이라면 입력에서 제거
나머지 적절한 변수
X의 feature로 사용

코드보다 먼저 와야 하는 건 왜 각 열을 다르게 취급했는가라는 판단이야.

이 구조를 잡아두면 이후의 데이터 분할, 전처리, 모형 학습, 예측, 평가가 전부 자연스럽게 이어져.

그래서 모형 선택보다 먼저 데이터의 역할을 올바르게 나누는 것이 중요해. 아무리 좋은 알고리즘을 써도 X와 y를 잘못 구성하면 모형 자체가 잘못된 문제를 풀게 되니까.

시험장 한 문장

💡 목표 변수(y)는 “무엇을 맞힐까?”, 입력 변수(X)는 “무엇을 보고 맞힐까?”다.

그리고 한 질문만 더 붙이면 실전성이 생겨.

“이 정보는 실제 예측하는 시점에도 알 수 있는가?”

이 세 질문이면 변수 역할의 핵심이 거의 정리돼.
