#빅데이터분석기사 #실기 #분석모형구축 #모형변수지정 #목표변수 #입력변수 #변수역할

이번 단원에서 제일 중요한 건 “이 열이 무엇을 뜻하느냐”보다 “모형 안에서 이 열에게 무슨 역할을 맡길 거냐”야.

데이터가 이렇게 있다고 해보자.

고객ID	나이	월소득	이용기간	최근접속일수	해지여부
C001	27	320	14	2	0
C002	51	610	3	19	1
C003	34	450	28	1	0

우리가 만들려는 모형의 목적이 “고객이 해지할지 예측하는 것”이라면 역할은 자연스럽게 갈려.

해지여부를 맞히기 위해 나이·월소득·이용기간 등을 사용한다.

이 한 문장이 오늘 단원의 거의 전부야. 이제 이걸 시험에서 정확히 다룰 수 있게 쪼개보자.

참고로 학습 상태는 나중에 **저장**이라고 입력하면 이어서 공부할 수 있게 보존할 수 있어.
원하면 주제 뒤에 **.cc**를 붙여 같은 내용을 HTML 학습 화면으로 볼 수도 있어.

🎯 먼저 잡을 구분 — 목표 변수는 “무엇을 맞힐 것인가?”
목표 변수의 의미

목표 변수(target variable)는 분석모형이 예측하거나 설명하려는 대상이야.

다른 표현도 같이 익혀두면 좋아.

목표 변수

종속 변수(dependent variable)

반응 변수(response variable)

타깃(target)

레이블(label, 특히 분류 문제)

용어가 조금씩 달라도 핵심 관계는 같아.

입력 데이터 → 모형 → 목표 변수 예측

앞의 고객 데이터에서 목적이

“고객 해지 여부를 예측한다.”

라면,

목표 변수 = 해지여부

0 = 유지

1 = 해지

가 되는 거야.

목표 변수는 분석 목적이 결정한다

같은 데이터라도 무엇을 분석하느냐에 따라 목표 변수가 달라질 수 있어.

예를 들어 고객 데이터에 다음 열이 있다고 하자.

나이 / 월소득 / 구매금액 / 해지여부

분석 목적 ① 고객 해지 예측

목표 변수:

해지여부

이 값은 0과 1 같은 범주니까 일반적으로 분류(classification) 문제로 볼 수 있어.

분석 목적 ② 다음 달 구매금액 예측

목표 변수:

구매금액

구매금액처럼 연속적인 수치를 예측한다면 일반적으로 회귀(regression) 문제가 돼.

즉,

목표 변수의 형태가 분석모형의 유형과 연결된다.

목표 변수	예	일반적인 문제
범주형	합격/불합격	분류
범주형	A/B/C 고객군	다중분류
연속형	매출액	회귀
연속형	주택가격	회귀

여기서 중요한 건 데이터형 자체만 기계적으로 보는 게 아니야.

0, 1로 저장되어 있어도 그것이 해지/유지라는 범주를 나타낸다면 분류 문제야.

🧩 입력 변수는 “무엇을 보고 맞힐 것인가?”

목표 변수를 정했다면 다음 질문은 이거야.

그 목표를 예측하기 위해 모형에게 어떤 정보를 보여줄 것인가?

그 정보들이 입력 변수(input variable)야.

다음 용어들도 비슷한 의미로 자주 등장해.

입력 변수

독립 변수(independent variable)

설명 변수(explanatory variable)

예측 변수(predictor)

특징(feature)

머신러닝에서는 특히 feature라는 표현을 많이 써.

고객 해지 모형이라면

목표가 해지여부라면 다음처럼 구성할 수 있어.

변수	역할
나이	입력 변수
월소득	입력 변수
이용기간	입력 변수
최근접속일수	입력 변수
해지여부	목표 변수

관계로 쓰면,

나이 + 월소득 + 이용기간 + 최근접속일수 → 해지여부

가 돼.

보통 코드나 수식에서는 이 관계를 조금 더 압축해서

X = 입력 변수들의 집합

y = 목표 변수

라고 표현해.

예를 들어 데이터프레임 df가 있다면 개념적으로는

Python
실행됨
X = df[['나이', '월소득', '이용기간', '최근접속일수']]
y = df['해지여부']

처럼 나누는 거야.

여기서 아직 모델을 학습시키는 게 아니야.

지금 하는 일은 “누가 문제를 풀고, 누가 정답인가”를 결정하는 단계라고 보면 돼.

🔍 모든 목표 변수 이외의 열이 입력 변수는 아니다

여기가 실기에서 꽤 중요한 구분이야.

처음 데이터가 다음과 같다고 해보자.

고객ID	나이	이용기간	해지사유	해지여부
C001	27	14	-	0
C002	51	3	가격불만	1

목표가 해지여부라고 해서

목표 변수만 빼고 나머지를 전부 X로 넣는다.

라고 하면 위험해.

고객ID

고객ID는 각 고객을 구분하기 위한 식별자(identifier)일 가능성이 높아.

예를 들어

C001, C002, C003 ...

이라는 값 자체가 일반적으로 고객의 해지를 설명하는 의미 있는 특성은 아니지.

그래서 보통은

식별 변수로 유지하거나

분석 입력에서는 제외

하게 돼.

해지사유

이건 더 위험해.

우리는 해지할지 미리 예측하려고 하는데 해지사유는 보통 해지가 발생한 뒤 알 수 있는 정보야.

그걸 입력 변수로 넣으면 어떻게 될까?

모형은 시험 볼 때 사실상 정답을 미리 보고 있는 셈이야.

이런 문제를 데이터 누수(data leakage)라고 해.

즉,

입력 변수인가?

를 판단할 때는 단순히 열 이름만 보는 게 아니라,

실제 예측 시점에 이 정보를 사용할 수 있는가?

까지 생각해야 해.

🧠 변수 역할 확인 — 열마다 세 가지 질문을 던져

실기에서 데이터가 주어지면 각 변수에 대해 다음 순서로 보면 안정적이야.

첫째, 이것이 우리가 맞히려는 값인가?

그렇다면 목표 변수.

예:

부도여부

목적:

기업의 부도 여부 예측

→ 부도여부 = 목표 변수

둘째, 목표를 예측하는 데 사용할 정보인가?

그렇다면 입력 변수 후보.

예:

부채비율

매출액

영업이익률

기업연령

→ 입력 변수 후보

셋째, 분석을 위해 존재하지만 예측에는 넣지 않아야 하는가?

이런 열도 존재해.

대표적인 예가:

ID

순번

이름

원본 데이터 인덱스

예측 시점 이후 생성된 정보

야.

따라서 변수 역할을 단순화하면 이렇게 생각할 수 있어.

역할	질문
목표 변수	무엇을 맞힐까?
입력 변수	무엇을 보고 맞힐까?
식별·제외 변수	모형에 보여주면 안 되는 것은 무엇일까?
⚠️ 시험에서 자주 흔들리는 세 가지 경계
숫자라고 전부 입력 변수인 것은 아니다

회원번호 = 10001, 10002, 10003

처럼 숫자로 되어 있어도 식별자일 수 있어.

따라서

숫자형 → 입력 변수

라는 규칙은 없어.

변수의 의미와 역할을 먼저 봐야 해.

문자열이라고 무조건 제외하는 것도 아니다

지역 = 서울 / 부산 / 대전

같은 변수는 문자열이지만 고객 행동과 관련 있는 정보일 수 있어.

이 경우 적절한 인코딩을 거치면 입력 변수로 사용할 수 있어.

즉,

문자열 → 무조건 삭제

도 틀린 접근이야.

목표 변수와 강하게 관련 있다고 무조건 좋은 입력 변수도 아니다

합격여부를 예측한다고 하자.

입력 변수 후보에

최종합격통보일

이 들어 있다면 합격 여부와 매우 강하게 관련되어 있을 거야.

그런데 예측 시점에 최종합격통보일을 알 수 없다면?

그건 좋은 변수가 아니라 누수 변수야.

그래서 좋은 입력 변수의 기준은 단순히

목표 변수와 관계가 강한가?

만이 아니라,

예측할 순간에도 실제로 이용 가능한가?

까지 포함해.

🛠️ 실기 코드에서는 어떻게 나타날까?

예를 들어 train 데이터의 목표 변수가 target이라면 가장 기본적인 구조는 이런 식이야.

Python
실행됨
X = train.drop(columns=['target'])
y = train['target']

의미는 간단해.

y

→ 모형이 맞혀야 할 정답

X

→ 정답을 맞히기 위해 사용할 정보

그런데 식별 변수 id도 제외해야 한다면,

Python
실행됨
X = train.drop(columns=['target', 'id'])
y = train['target']

처럼 구성할 수 있어.

여기서 코드 자체보다 중요한 건 왜 target과 id를 다르게 취급했는가야.

target → 정답이므로 X에서 제거

id → 식별용이므로 입력에서 제거

나머지 적절한 변수 → X에 포함

이 판단 구조가 먼저고 코드는 그걸 구현하는 수단이야.

🧪 train과 test에서 한 번 더 조심

빅데이터분석기사 실기에서는 학습용 데이터와 시험용 데이터가 나뉘는 형태를 만날 수 있어.

개념적으로:

train

입력 변수 + 목표 변수

test

입력 변수

형태가 되는 경우가 많아.

왜 test에는 목표 변수가 없을까?

그 값을 우리가 예측해서 제출해야 하기 때문이야.

그래서 흐름을 보면:

train의 X + train의 y → 모형 학습 → test의 X → test의 y 예측

이 구조를 머릿속에 잡아두면 이후의

데이터 분할

전처리

모형 학습

예측

평가

가 전부 이어져.

🧭 세 항목을 하나의 판단 절차로 묶어보자

실전에서 변수 목록을 받았다고 하자.

회원번호 / 성별 / 연령 / 이용개월 / 최근방문일수 / 해지여부

그리고 요구사항이

“고객의 해지 여부를 예측하시오.”

라면 이렇게 읽어.

1단계 — 목표 변수 지정

문장에서 예측 대상을 찾는다.

→ 해지여부

2단계 — 입력 변수 후보 지정

예측에 사용할 수 있는 특성을 찾는다.

→ 성별 / 연령 / 이용개월 / 최근방문일수

3단계 — 역할이 다른 변수 확인

회원번호

→ 고객을 식별하기 위한 값인지 검토
→ 식별자라면 입력 변수에서 제외

결국 구조는

X = 성별 + 연령 + 이용개월 + 최근방문일수

y = 해지여부

가 돼.

이렇게 문제의 분석 목적 → 변수 역할 → X와 y 구성 순서로 생각하면 돼.

🔗 다음 단계와 연결되는 이유

이 부분을 정확히 해야 이후 모형 구축이 제대로 돌아가.

입력·목표 변수를 잘못 정하면,

목표 변수를 X에 포함

→ 정답을 모형에게 보여줌
→ 비정상적으로 높은 성능 가능

식별자를 무분별하게 X에 포함

→ 의미 없는 패턴을 학습할 수 있음

예측 이후 정보를 X에 포함

→ 데이터 누수 발생

필요한 입력 변수를 제외

→ 예측에 사용할 정보 감소

즉 모형 선택보다 먼저 데이터의 역할을 올바르게 나누는 것이 중요해.

성능이 좋은 알고리즘을 써도 X와 y를 잘못 구성하면 모형 자체가 잘못된 문제를 풀게 되니까.

💡 시험장에서 기억할 한 문장

헷갈리면 이걸 떠올리면 돼.

목표 변수(y)는 “무엇을 맞힐까?”, 입력 변수(X)는 “무엇을 보고 맞힐까?”다.

그리고 한 질문만 더 붙이면 실전성이 생겨.

“이 정보는 실제 예측하는 시점에도 알 수 있는가?”

이 세 질문이면 변수 역할의 핵심이 거의 정리돼.
