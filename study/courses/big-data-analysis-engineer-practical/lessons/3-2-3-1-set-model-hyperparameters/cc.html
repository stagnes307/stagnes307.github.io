매개변수 설정과 비교

이번 단원의 중심은 하나야. 모델이 데이터에서 배우는 값과 우리가 학습 전에 정해 주는 값을 구분하고, 후보 설정을 검증 성능으로 비교하는 흐름을 익히는 것.

TUNING CONSOLE GENERALIZATION

01 · FIRST DISTINCTION

먼저 잡을 핵심 — 무엇을 사람이 정하고, 무엇을 모델이 배우는가?

빅데이터분석기사 실기에서 매개변수 지정은 보통 모델을 만들 때 우리가 직접 설정하는 값, 즉 머신러닝에서 엄밀히 말하면 하이퍼파라미터(hyperparameter)를 다룬다고 이해하면 돼. 

DecisionTreeClassifier(max_depth=5)

여기서 max_depth=5는 학습 전에 우리가 지정해. 반면 실제 분기 기준이나 트리 구조는 fit() 과정에서 데이터로부터 학습돼.

구분 의미 예
모델 파라미터학습 과정에서 데이터로부터 결정회귀계수, 트리의 분기 기준
하이퍼파라미터학습 전에 분석자가 지정max_depth, n_neighbors, C
시험의 ‘매개변수’문맥에 따라 넓게 표현모델 생성 시 조정하는 값
시험용 감각: 모델을 생성할 때 괄호 안에 넣어서 조정하는 값이라면 우선 “설정 대상 매개변수”라고 생각하면 돼.

02 · WHY TUNE?

매개변수 의미 — 왜 조정하는 걸까?

같은 알고리즘이라도 매개변수 값에 따라 모델의 복잡도와 예측 성능이 달라져. 의사결정나무의 max_depth를 보면 가장 직관적이야.

1

너무 작음

모델이 지나치게 단순해 데이터의 패턴을 충분히 잡지 못함.

→ 과소적합

2

적절함

필요한 패턴을 학습하면서 새 데이터에도 비교적 안정적으로 적용됨.

→ 좋은 일반화

3

너무 큼

훈련 데이터를 지나치게 세밀하게 외워 새 데이터에서는 성능이 떨어질 수 있음.

→ 과적합

목표는 훈련 데이터에서 가장 높은 점수가 아니라, 새로운 데이터에서도 잘 작동하는 설정을 찾는 거야.

자주 나오는 모델별 매개변수

모델주요 매개변수의미
Decision Treemax_depth트리의 최대 깊이
Decision Treemin_samples_split노드를 분할하기 위한 최소 표본 수
Random Forestn_estimators생성할 트리 개수
Random Forestmax_depth각 트리의 최대 깊이
KNNn_neighbors예측에 사용할 이웃의 수
Logistic RegressionC규제 강도의 역수
SVMC오분류 허용과 복잡도 사이의 조절
SVMgamma개별 데이터가 영향을 미치는 범위
C는 특히 조심. 값이 커질수록 규제가 강해지는 게 아니라 규제가 약해져. 왜냐하면 C가 규제 강도의 역수이기 때문이야.

03 · CANDIDATE SPACE

후보 값 지정 — 하나를 찍지 말고 여러 값을 시험한다

적절한 깊이를 모르는 상황이라면 한 값을 감으로 고정하는 대신, 비교할 후보군을 만든다. 

param_grid = {
    'max_depth': [3, 5, 7, 10],
    'min_samples_split': [2, 5, 10]
}

가능한 조합은 4 × 3 = 12개. 각 설정을 평가해서 가장 좋은 조합을 찾는 구조야.

max_depth훈련 정확도검증 정확도해석
20.780.77다소 단순
50.880.85적절
100.970.82과적합 가능
201.000.76과적합 가능성 큼
매개변수 비교 기준 = 훈련 성능 최대화가 아니라 일반화 성능 최대화.

04 · VALIDATION FLOW

설정 결과 비교 — 검증 데이터를 사용한다

매개변수 비교에서 중요한 건 “어디서 고르고, 어디서 마지막 확인을 하느냐”야.

테스트 데이터로 매개변수를 고르면 왜 안 될까?

테스트 데이터는 최종 성능 확인용이야. 테스트 점수를 여러 번 들여다보며 최적 설정을 고르면, 테스트 데이터 자체가 모델 선택 과정에 개입하게 돼.

max_depth=3 → test accuracy 0.82
max_depth=5 → test accuracy 0.87
max_depth=7 → test accuracy 0.89

따라서 7 선택 ← 이러면 테스트 데이터로 튜닝한 셈

원칙: 훈련 → 검증/교차검증으로 튜닝 → 테스트로 최종 평가

05 · AUTOMATED SEARCH

GridSearchCV — 후보 조합을 자동으로 비교하기

from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import GridSearchCV

model = DecisionTreeClassifier(random_state=42)

params = {
    'max_depth': [3, 5, 7, 10],
    'min_samples_split': [2, 5, 10]
}

grid = GridSearchCV(
    model,
    param_grid=params,
    cv=5,
    scoring='accuracy'
)

grid.fit(X_train, y_train)
model

비교할 분석모형

param_grid

시험할 매개변수 후보

cv=5

5겹 교차검증

scoring='accuracy'

후보를 비교할 평가 지표

학습이 끝난 뒤 자주 확인하는 세 가지

grid.best_params_

가장 좋은 매개변수 조합

grid.best_score_

교차검증에서 얻은 최고 점수

grid.best_estimator_

선택된 최적 모델

예를 들어 {'max_depth': 5, 'min_samples_split': 10}이 나왔다면, 설정한 후보 조합 가운데 교차검증 결과가 가장 좋았던 조합이라는 뜻이야.

06 · SCORING

무엇을 기준으로 비교할까?

매개변수 비교에는 반드시 평가지표가 필요해. 분류와 회귀 지표를 섞으면 안 돼.

분류

Accuracy · Precision · Recall · F1-score · ROC-AUC

회귀

MAE · MSE · RMSE · R²

불균형 분류 문제라면 단순 정확도보다 F1이나 ROC-AUC가 더 적절할 수 있어. 

GridSearchCV(
    model,
    params,
    cv=5,
    scoring='f1'
)

회귀에서는 예를 들어 이렇게 쓸 수 있어.

GridSearchCV(
    model,
    params,
    cv=5,
    scoring='neg_mean_squared_error'
)
원래 MSE는 작을수록 좋은 지표인데, GridSearchCV는 기본적으로 점수가 클수록 좋은 모델로 처리해. 그래서 음수를 붙여 비교할 수 있게 만든 거야. 예를 들어 -100 > -300이므로 -100인 모델이 더 좋다고 판단해.

07 · SEARCH SPACE

Grid Search와 후보 값의 관계

params = {
    '매개변수1': [후보1, 후보2, 후보3],
    '매개변수2': [후보1, 후보2]
}

Grid Search는 이 후보들의 모든 조합을 비교해. 

from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(random_state=42)

params = {
    'n_estimators': [100, 200],
    'max_depth': [3, 5, 10]
}
100 / 3
100 / 5
100 / 10
200 / 3
200 / 5
200 / 10

총 6개 조합이고, cv=5라면 각 조합을 여러 fold에서 학습·평가하게 돼. 따라서 후보값은 무조건 많이 넣는 게 아니라 의미 있는 범위에서 지정해야 해.

08 · EXAM REASONING

시험장에서의 사고 순서

  1. 01
    어떤 모델인가?

    조정 가능한 매개변수를 확인한다.

  2. 02
    어떤 값을 시험할 것인가?

    후보값 목록을 만든다.

  3. 03
    무엇으로 좋고 나쁨을 판단할 것인가?

    문제 유형에 맞는 평가지표를 결정한다.

  4. 04
    어떻게 신뢰성 있게 비교할 것인가?

    검증 데이터 또는 교차검증을 이용한다.

  5. 05
    어떤 설정을 선택할 것인가?

    검증 성능이 가장 좋은 설정을 선택한다.

  6. 06
    테스트 데이터는 언제 쓰는가?

    최종 모델 성능 확인에 사용한다.

10 · FAULT LINES

헷갈리기 쉬운 세 가지 구분

헷갈리는 생각정확한 이해
훈련 정확도가 가장 높은 모델을 선택한다검증 성능이 좋은 모델을 선택
테스트 데이터로 가장 좋은 설정을 찾는다테스트는 최종 평가에 사용
후보값은 많을수록 무조건 좋다계산량과 범위를 고려해 합리적으로 지정
그리고 하나 더. GridSearchCV 자체가 모델 알고리즘은 아니야. 여러 매개변수 조합을 시험해서 모델을 선택하도록 도와주는 탐색 도구야.

11 · TAKEAWAY

이번 단원에서 가져가야 할 것

DecisionTreeClassifier(max_depth=5)를 보고 5는 학습 전에 지정하는 값이라고 바로 연결.

{'max_depth':[3,5,7]}을 보고 비교할 후보군이라고 바로 연결.

GridSearchCV(..., cv=5)를 보고 후보들을 교차검증으로 비교한다고 연결.

best_params_를 보고 가장 좋은 설정을 확인한다고 연결.

후보값 지정 → 검증 → 비교 → 최적값 선택 → 테스트 평가

이 순서가 3-2-3-1 전체를 관통하는 구조야.
