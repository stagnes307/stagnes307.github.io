🎯 먼저 잡을 핵심 — “무엇을 사람이 정하고, 무엇을 모델이 배우는가?”

빅데이터분석기사 실기에서 매개변수 지정은 보통 모델을 만들 때 우리가 직접 설정하는 값, 즉 머신러닝에서 엄밀히 말하면 하이퍼파라미터(hyperparameter)를 다룬다고 이해하면 돼.

예를 들어 의사결정나무를 만든다고 해보자.

Python
실행됨
DecisionTreeClassifier(max_depth=5)

여기서 max_depth=5는 학습 전에 우리가 지정해. 반면 데이터로부터 실제 분기 기준이나 각 노드의 구조가 결정되는 것은 fit() 과정에서 모델이 학습해.

구분	의미	예
모델 파라미터	학습 과정에서 데이터로부터 결정	회귀계수, 트리의 분기 기준
하이퍼파라미터	학습 전에 분석자가 지정	max_depth, n_neighbors, C
시험에서의 표현	둘을 넓게 묶어 ‘매개변수’라고 표현하기도 함	매개변수 설정 및 비교

시험용으로는 이렇게 기억하면 충분해.

모델을 생성할 때 괄호 안에 넣어서 조정하는 값 → 매개변수 설정 대상으로 생각한다.

🔧 1. 매개변수 의미 — 왜 조정하는 걸까?

같은 알고리즘이라도 매개변수 값에 따라 모델의 복잡도와 예측 성능이 달라져.

의사결정나무의 max_depth를 생각하면 아주 명확해.

max_depth가 너무 작음
→ 모델이 단순함
→ 데이터의 패턴을 충분히 학습하지 못함
→ 과소적합

적절한 max_depth
→ 필요한 패턴을 학습
→ 새로운 데이터에서도 좋은 성능

max_depth가 너무 큼
→ 훈련 데이터를 지나치게 세밀하게 학습
→ 과적합

따라서 목표는 훈련 데이터에서 가장 높은 점수를 만드는 것이 아니라,

새로운 데이터에서도 잘 작동할 설정을 찾는 것이야.

자주 나오는 모델별 매개변수
모델	주요 매개변수	의미
Decision Tree	max_depth	트리의 최대 깊이
Decision Tree	min_samples_split	노드를 분할하기 위한 최소 표본 수
Random Forest	n_estimators	생성할 트리 개수
Random Forest	max_depth	각 트리의 최대 깊이
KNN	n_neighbors	예측에 사용할 이웃의 수
Logistic Regression	C	규제 강도의 역수
SVM	C	오분류 허용과 복잡도 사이의 조절
SVM	gamma	개별 데이터가 영향을 미치는 범위

여기서 특히 하나 조심해야 해.

C는 값이 클수록 규제가 강해지는 게 아니라 규제가 약해져.

왜냐하면 C가 규제 강도의 역수이기 때문이야.

🧪 2. 후보 값 지정 — 하나를 찍지 말고 여러 값을 시험한다

예를 들어 의사결정나무의 깊이를 정해야 하는데 적절한 값이 무엇인지 모른다고 하자.

그렇다고 그냥

Python
실행됨
max_depth=5

라고 감으로 결정하기보다 다음처럼 후보를 만든다.

Python
실행됨
param_grid = {
    'max_depth': [3, 5, 7, 10],
    'min_samples_split': [2, 5, 10]
}

그러면 가능한 조합은

4 × 3 = 12개

가 돼.

모델은 이 12개의 설정을 각각 평가해서 가장 좋은 조합을 찾게 돼.

후보값은 왜 여러 개 필요한가?

예를 들어 검증 성능이 다음과 같다고 해보자.

max_depth	훈련 정확도	검증 정확도	해석
2	0.78	0.77	다소 단순
5	0.88	0.85	적절
10	0.97	0.82	과적합 가능
20	1.00	0.76	과적합 가능성 큼

훈련 정확도만 보면 20이 최고야.

그런데 우리가 원하는 건 처음 보는 데이터에 대한 성능이지.

그래서 이 경우에는 max_depth=5가 더 합리적인 선택이야.

이 차이를 확실히 잡아야 해.

매개변수 비교 기준 = 훈련 성능 최대화가 아니라 일반화 성능 최대화

🔍 3. 설정 결과 비교 — 검증 데이터를 사용한다

여기서 중요한 데이터 흐름이 나와.

훈련 데이터
      ↓
여러 매개변수 후보 학습
      ↓
검증 또는 교차검증으로 비교
      ↓
최적 매개변수 결정
      ↓
최종 모델
      ↓
테스트 데이터 평가
테스트 데이터로 매개변수를 고르면 안 되는 이유

테스트 데이터는 최종 성능 확인용이야.

만약

max_depth=3 → test accuracy 0.82
max_depth=5 → test accuracy 0.87
max_depth=7 → test accuracy 0.89

따라서 7 선택

처럼 해버리면 사실상 테스트 데이터를 모델 선택에 사용한 거야.

그 순간 테스트 데이터가 더 이상 순수한 최종 평가 데이터가 아니게 돼.

그래서 실무와 시험 개념 모두에서 기본 원칙은

훈련 → 검증/교차검증으로 튜닝 → 테스트로 최종 평가

야.

⚙️ 4. GridSearchCV — 후보 조합을 자동으로 비교하기

scikit-learn에서는 GridSearchCV가 이 과정을 한 번에 처리해줘.

Python
실행됨
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import GridSearchCV

model = DecisionTreeClassifier(random_state=42)

params = {
    'max_depth': [3, 5, 7, 10],
    'min_samples_split': [2, 5, 10]
}

grid = GridSearchCV(
    model,
    param_grid=params,
    cv=5,
    scoring='accuracy'
)

grid.fit(X_train, y_train)

여기서 각 부분의 의미를 연결해보자.

코드	의미
model	비교할 분석모형
param_grid	시험할 매개변수 후보
cv=5	5겹 교차검증
scoring='accuracy'	후보를 비교할 평가 지표
fit()	각 후보 조합을 실제로 학습하고 비교

학습이 끝나면 다음이 특히 중요해.

Python
실행됨
grid.best_params_

가장 좋은 매개변수 조합을 확인하고,

Python
실행됨
grid.best_score_

교차검증에서 얻은 최고 점수를 확인하고,

Python
실행됨
best_model = grid.best_estimator_

선택된 최적 모델을 바로 가져올 수 있어.

예를 들면 결과가

Python
실행됨
{'max_depth': 5, 'min_samples_split': 10}

처럼 나올 수 있어.

그 의미는 단순해.

설정한 후보 조합 가운데 교차검증 결과가 가장 좋았던 조합이라는 뜻이야.

📊 5. 무엇을 기준으로 비교할까?

매개변수 비교에는 반드시 평가지표가 필요해.

분류와 회귀의 지표를 섞으면 안 돼.

문제 유형	대표 평가 지표
분류	Accuracy
분류	Precision
분류	Recall
분류	F1-score
분류	ROC-AUC
회귀	MAE
회귀	MSE / RMSE
회귀	R²

예를 들어 불균형 분류 문제라면 단순 정확도보다 F1이나 ROC-AUC가 더 적절할 수 있어.

Python
실행됨
GridSearchCV(
    model,
    params,
    cv=5,
    scoring='f1'
)

회귀라면 예를 들어 다음처럼 사용할 수 있어.

Python
실행됨
GridSearchCV(
    model,
    params,
    cv=5,
    scoring='neg_mean_squared_error'
)

여기서 scikit-learn의 neg_mean_squared_error가 처음 보면 좀 이상하지.

원래 MSE는 작을수록 좋은 지표인데, GridSearchCV는 기본적으로 점수가 클수록 좋은 모델로 처리해. 그래서 MSE에 음수를 붙여 비교할 수 있게 만든 거야.

즉,

-100 > -300

이므로 -100을 만든 모델이 더 좋은 모델이야.

🧠 6. Grid Search와 후보 값의 관계

GridSearchCV에서 가장 중요한 구조는 이것뿐이야.

Python
실행됨
params = {
    '매개변수1': [후보1, 후보2, 후보3],
    '매개변수2': [후보1, 후보2]
}

그러면 모든 조합을 비교해.

예를 들어 Random Forest라면

Python
실행됨
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(random_state=42)

params = {
    'n_estimators': [100, 200],
    'max_depth': [3, 5, 10]
}

비교되는 조합은 총 6개야.

100 / 3
100 / 5
100 / 10
200 / 3
200 / 5
200 / 10

cv=5까지 사용한다면 각 조합을 교차검증해야 하므로 실제 학습은 더 많이 수행돼.

그래서 후보값을 무조건 많이 넣는다고 좋은 건 아니야.

의미 있는 범위 안에서 후보값을 지정해야 한다는 게 핵심이야.

🧭 7. 시험장에서의 사고 순서

코드를 통째로 외우기보다는 다음 관계를 기억하는 게 좋아.

① 어떤 모델인가?
→ 조정 가능한 매개변수를 확인한다.

② 어떤 값을 시험할 것인가?
→ 후보값 목록을 만든다.

③ 무엇으로 좋고 나쁨을 판단할 것인가?
→ 문제 유형에 맞는 평가 지표를 결정한다.

④ 어떻게 신뢰성 있게 비교할 것인가?
→ 검증 데이터 또는 교차검증을 이용한다.

⑤ 어떤 설정을 선택할 것인가?
→ 검증 성능이 가장 좋은 설정을 선택한다.

⑥ 테스트 데이터는 언제 쓰는가?
→ 최종 모델 성능 확인에 사용한다.

이 흐름이면 코드가 조금 달라져도 판단할 수 있어.

여기서 시험에 필요한 핵심 문장을 압축하면 이거야.

매개변수 후보값을 설정하고, 검증 또는 교차검증 결과를 평가지표로 비교하여 일반화 성능이 가장 우수한 설정을 선택한다.

💡 헷갈리기 쉬운 세 가지 구분
헷갈리는 생각	정확한 이해
훈련 정확도가 가장 높은 모델을 선택한다	검증 성능이 좋은 모델을 선택
테스트 데이터로 가장 좋은 설정을 찾는다	테스트는 최종 평가에 사용
후보값은 많을수록 무조건 좋다	계산량과 과적합을 고려해 합리적인 범위를 지정

그리고 하나 더.

GridSearchCV 자체가 모델 알고리즘은 아니야.

여러 매개변수 조합을 시험해서 모델을 선택하도록 도와주는 탐색 도구야.

이걸 분리해서 이해하면 많이 안 헷갈려.

✅ 이번 단원에서 가져가야 할 것

이 단원을 제대로 이해했다면 DecisionTreeClassifier(max_depth=5)를 보고 5는 학습 전에 지정하는 값, {'max_depth':[3,5,7]}를 보고 후보군, GridSearchCV(..., cv=5)를 보고 후보들을 교차검증으로 비교, best_params_를 보고 가장 좋은 설정 확인이라고 바로 연결되면 돼.

특히 후보값 지정 → 검증 → 비교 → 최적값 선택 → 테스트 평가의 순서를 기억해. 이게 3-2-3-1 전체를 관통하는 구조야.
