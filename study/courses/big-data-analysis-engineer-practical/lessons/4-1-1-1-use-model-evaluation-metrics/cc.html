평가지표 계산과 선택

좋은 점수는 하나가 아니다. 문제 유형과 오류 비용을 먼저 정하고, 혼동행렬과 오차에서 목적에 맞는 숫자를 꺼내 읽는다.

목적별 지표 선택지표 계산지표 방향 해석
1

먼저 문제와 비용을 구분한다

분류는 범주 오류를, 회귀는 수치 오차를 다룬다. 같은 분류라도 FN과 FP 중 무엇이 더 치명적인지에 따라 우선 지표가 달라진다.

CLASSIFICATION

희귀 양성을 놓치지 않기

사기·위험 탐지처럼 FN 비용이 크면 재현율을 우선하고 정밀도로 경보 품질을 함께 확인한다.

CLASSIFICATION

잘못된 경보 줄이기

양성 판정 뒤 비싼 조치가 이어진다면 정밀도를 우선해 FP가 감당 가능한지 확인한다.

REGRESSION

예측오차의 크기 읽기

직관적 평균오차는 MAE, 큰 오차를 강하게 벌하려면 RMSE를 사용한다.

2

혼동행렬에서 네 지표를 꺼낸다

양성은 반드시 “찾고 싶은 대상”으로 먼저 정의한다. 정밀도는 예측 양성의 순도, 재현율은 실제 양성의 탐지율이다.

정확도 · 전체 중 정답(TP + TN) / 전체
정밀도 · 경보의 순도TP / (TP + FP)
재현율 · 실제 양성 탐지율TP / (TP + FN)
F1 · 두 관점의 균형2 × P × R / (P + R)
불균형 주의
양성이 1%라면 모두 음성으로 예측해도 정확도는 99%다. 관심 클래스의 재현율과 정밀도를 함께 본다.
3

지표마다 좋은 방향이 다르다

손실은 줄이고, 성능 점수는 높인다. 단, 기준선과 데이터 척도를 함께 읽어야 한다.

4

숫자보다 먼저 선택 규칙을 세운다

결과를 본 뒤 기준을 바꾸지 않도록 양성, 비용, 제약, 보조 지표를 순서대로 정한다.

양성 정의

1이 실제 관심 대상인가? pos_label과 확률 열의 클래스 순서를 확인한다.

오류 비용

FN과 FP 중 어느 오류가 더 비싼지 업무 상황으로 설명한다.

주 지표·제약

예: 재현율 0.90 이상을 만족하는 후보 중 F1 최대.

보조 확인

혼동행렬과 보조 지표로 경보 폭증이나 불균형 착시를 점검한다.

5

시험장에서 바로 쓰는 지표 선택표

지표 이름만 암기하지 말고 “무엇을 분모로 삼는가”와 “어느 방향이 좋은가”를 함께 기억한다.

6

누수 없이 계산하는 최소 코드

전처리를 파이프라인 안에 넣고, 학습에 쓰지 않은 테스트 데이터에서 지표를 계산한다.

PYTHON · SCIKIT-LEARNTRAIN → TEST
model = make_pipeline(SimpleImputer(strategy="median"),
                      StandardScaler(),
                      LogisticRegression(max_iter=1000))
model.fit(X_train, y_train)

pred = model.predict(X_test)
prob = model.predict_proba(X_test)[:, 1]

print(confusion_matrix(y_test, pred))
print("F1:", f1_score(y_test, pred))
print("AUC:", roc_auc_score(y_test, prob))
데이터 누수 방지
전체 데이터로 결측치·평균·표준편차를 먼저 계산하지 않는다. 테스트셋으로 임계값이나 후보를 반복 조정하지 않는다.
한 문장 요약: 좋은 평가지표는 가장 큰 숫자가 아니라, 같은 평가 데이터에서 목적에 맞는 오류를 정확히 드러내는 숫자다.
