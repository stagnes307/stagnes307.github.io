Model Selection Protocol · 4-1-2-1

여러 모형의 공정한 비교

같은 트랙에서 달리지 않은 점수는 순위를 매길 수 없다. 데이터, 폴드, 지표, 전처리 원칙을 통제하고 선택 규칙을 먼저 잠근다.

  • 동일 평가조건 설정
  • 평가지표 비교
  • 최종 후보 선택

핵심: 후보 선택은 검증 데이터에서, 최종 확인은 잠가 둔 테스트셋에서 한 번.

1

비교 전에 네 가지를 잠근다

숫자를 본 뒤 조건을 바꾸면 공정성이 무너진다. 데이터 역할과 지표, 분할, 재현 조건을 먼저 기록한다.

DATA

테스트셋은 먼저 떼어 잠그고, 남은 개발 데이터에서 후보를 비교한다.

FOLDS

모든 후보에 같은 StratifiedKFold 인덱스를 사용한다.

METRICS

업무 목적의 주 지표와 부작용을 보는 보조 지표를 명시한다.

SEED

분할과 확률적 학습의 random_state를 기록해 재현한다.

2

후보마다 필요한 전처리를 파이프라인으로

같은 원본 행과 폴드를 쓰되 알고리즘에 필요한 변환은 다를 수 있다. 핵심은 각 변환이 학습 폴드 안에서만 적합되는 것이다.

평균과 변동성을 한 표에서 읽는다

아래 값은 선택법을 설명하기 위한 예시다. 재현율 0.80 이상을 통과한 후보 중 F1이 가장 높은 모델을 고른다.

읽는 순서

  1. 재현율 제약 미달 후보를 제외한다.
  2. 통과 후보의 F1 평균을 비교한다.
  3. 표준편차로 폴드별 흔들림을 확인한다.
  4. 성능이 비슷하면 단순성과 비용을 본다.

주의: 예시 표의 숫자는 모델 학습 출력이 아니라 선택 규칙을 시각화한 값이다. 실제 선택에는 실행한 교차검증 결과를 사용한다.

4

선택 규칙은 결과보다 먼저

최고 숫자를 바로 고르지 않는다. 제약을 통과시키고, 주 지표로 정렬하고, 안정성과 복잡도를 확인한다.

5

비교 순위를 왜곡하는 네 가지 누수

모든 후보에 같은 누수가 생겼더라도 공정하지 않다. 알고리즘마다 누수 정보에 반응하는 정도가 달라 순위까지 변할 수 있다.

전체 데이터 전처리

분할 전 평균·중앙값·스케일을 계산하면 검증과 테스트 정보가 학습에 들어간다.

후보마다 다른 분할

서로 다른 검증 표본이면 모델 차이와 분할 운을 구분할 수 없다.

테스트셋으로 후보 선택

여러 테스트 점수를 보고 최고값을 고르면 마지막 평가의 독립성이 사라진다.

예측 시점 이후 변수

목표 확정 뒤 생성된 열은 높은 점수를 만들지만 실제 예측에는 사용할 수 없다.

6

같은 폴드를 재사용하는 핵심 코드

7

최종 테스트는 선택된 한 후보만

개발 데이터 전체로 다시 학습한 뒤 잠가 둔 테스트셋에서 한 번 확인한다. 결과를 보고 후보를 바꾸면 테스트가 다시 선택 데이터가 된다.

검증 단계와 최종 평가 단계의 역할 구분
단계사용 데이터할 수 있는 일하면 안 되는 일
후보 비교개발 데이터의 교차검증모델·설정·지표 비교테스트 점수 참조
최종 확인잠가 둔 테스트셋선택 모델 일반화 보고결과를 보고 재선택
한 문장 요약: 공정한 모형 비교는 같은 문제를 풀게 하고, 검증에서 미리 정한 규칙으로 고른 뒤, 테스트에서 단 한 번 확인하는 절차다.
