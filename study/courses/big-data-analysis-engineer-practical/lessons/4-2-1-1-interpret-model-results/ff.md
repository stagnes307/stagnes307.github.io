# 4-2-1-1. 결과 해석과 설명

> **공식 학습 범위**: 빅데이터 분석 실무의 「데이터 모형 평가 작업 > 분석결과 활용하기」에 따라 최종모형 또는 분석결과를 해석할 수 있어야 한다.

이 레슨은 다음 세 토픽을 빠짐없이 다룬다: **모형 출력 해석**, **분석 결과 요약**, **해석 한계 확인**. 좋은 해석은 숫자를 다시 읽어 주는 일이 아니다. 분석 목적에 맞는 지표를 선택하고, 그 값이 어떤 데이터와 기준에서 계산되었는지 밝히며, 예측과 인과를 구분하고, 적용 범위를 넘지 않도록 한계를 함께 제시하는 작업이다.

---

## 1. 해석의 출발점: 질문·출력·근거를 연결한다

모형 결과를 받으면 곧바로 “중요 변수는 무엇인가?”부터 묻기 쉽다. 그러나 먼저 분석 질문과 출력의 종류를 확인해야 한다.

| 분석 목적 | 대표 출력 | 먼저 확인할 해석 질문 |
|---|---|---|
| 회귀 | 연속형 예측값, 잔차, MAE·RMSE·결정계수 | 오차의 크기가 업무 단위로 어느 정도인가? |
| 이진 분류 | 클래스, 양성 확률, 혼동행렬, 정밀도·재현율 | 어떤 임계값에서 어떤 오류를 감수했는가? |
| 다중 분류 | 클래스별 확률, 클래스별 성능 | 특정 클래스만 성능이 낮지 않은가? |
| 군집 | 군집 번호, 중심, 군집별 요약 | 군집이 실제로 구별되며 설명 가능한가? |

같은 숫자도 맥락에 따라 의미가 달라진다. 정확도 0.90은 양성 비율이 0.50인 데이터에서는 유용할 수 있지만, 양성 비율이 0.02인 데이터에서는 모두 음성으로 예측한 단순 기준보다 못할 수 있다. RMSE 12도 목표값의 일반적 범위가 0~30인지 0~10,000인지에 따라 해석이 다르다. 따라서 결과 보고에는 **평가 데이터**, **기준모형**, **지표 방향**, **업무 단위**가 함께 있어야 한다.

## 2. 토픽 ① 모형 출력 해석

### 2.1 예측값과 평가지표를 함께 읽는다

회귀에서는 예측값과 실제값의 차이인 잔차를 본다. MAE는 절대오차의 평균이므로 목표변수와 같은 단위를 가진다. RMSE는 큰 오차에 더 민감하다. 결정계수는 변동 설명 정도를 나타내지만 “예측이 몇 퍼센트 정확하다”는 뜻이 아니다. 지표 하나만으로 결론 내리지 말고 업무상 큰 오차가 중요한지, 전반적인 평균 오차가 중요한지를 연결한다.

다음 Python 코드는 외부 파일 없이 실행할 수 있다.

```python
import numpy as np
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

y_true = np.array([120, 150, 170, 200, 260], dtype=float)
y_pred = np.array([128, 143, 180, 194, 238], dtype=float)

mae = mean_absolute_error(y_true, y_pred)
rmse = np.sqrt(mean_squared_error(y_true, y_pred))
r2 = r2_score(y_true, y_pred)
residual = y_true - y_pred

print(f"MAE={mae:.2f}, RMSE={rmse:.2f}, R2={r2:.3f}")
print("잔차:", residual.tolist())
assert len(residual) == len(y_true)
assert mae >= 0 and rmse >= mae
```

예상 출력은 `MAE=10.60`, `RMSE`는 약 `12.11`, `R2`는 약 `0.936`이다. 이때 “93.6% 정확하다”라고 쓰면 안 된다. “이 평가 표본에서 평균 절대오차는 목표값 단위로 10.6이며, 큰 오차에 민감한 RMSE는 약 12.11이다”가 더 정확하다. 표본이 5건뿐이므로 일반화 성능을 확정할 수도 없다.

분류에서는 클래스 예측만 보지 말고 확률과 임계값을 확인한다. 임계값이 달라지면 혼동행렬과 정밀도·재현율이 달라진다.

```python
import numpy as np
from sklearn.metrics import confusion_matrix, precision_score, recall_score

y_true = np.array([0, 0, 0, 1, 1, 1, 1, 1])
prob = np.array([0.05, 0.30, 0.55, 0.42, 0.62, 0.71, 0.80, 0.91])

for threshold in (0.5, 0.7):
    pred = (prob >= threshold).astype(int)
    cm = confusion_matrix(y_true, pred, labels=[0, 1])
    p = precision_score(y_true, pred, zero_division=0)
    r = recall_score(y_true, pred, zero_division=0)
    print(threshold, cm.tolist(), round(p, 3), round(r, 3))
```

임계값 0.5에서는 거짓 양성 한 건이 있지만 양성 네 건을 찾는다. 0.7에서는 거짓 양성이 사라지는 대신 양성 두 건을 놓친다. 따라서 “0.7이 더 좋다”가 아니라 **거짓 양성과 거짓 음성 중 어느 비용이 큰지**에 따라 선택해야 한다.

### 2.2 계수와 변수 중요도를 구분한다

선형회귀 계수는 다른 조건이 같다는 모형 내부 가정 아래, 해당 입력이 한 단위 증가할 때 예측값이 얼마나 변하는지를 나타낸다. 로지스틱 회귀 계수는 로그 오즈 변화이며, `exp(계수)`는 오즈비다. 단위와 전처리 방식이 다르면 계수 크기를 단순 비교하기 어렵다. 범주형 변수의 계수는 기준 범주와의 차이로 해석한다.

트리 계열의 변수 중요도는 예측에 기여한 정도를 요약하지만 변화 방향을 직접 말하지 않는다. 중요도가 높다고 원인이라는 뜻도 아니다. 상관된 변수 사이에서는 중요도가 나뉘거나 한 변수에 치우칠 수 있다. 따라서 다음처럼 “모형이 이 변수를 많이 사용했다”는 수준으로 표현하고 인과 표현을 피한다.

```python
import pandas as pd

importance = pd.Series(
    [0.52, 0.31, 0.17],
    index=["최근구매액", "방문횟수", "가입기간"]
).sort_values(ascending=False)

print(importance)
assert abs(importance.sum() - 1.0) < 1e-9
assert importance.index[0] == "최근구매액"
```

이 결과는 “최근구매액이 결과를 발생시킨다”가 아니라 “이 모형의 예측 분기에서 최근구매액의 상대적 기여도가 가장 크게 계산되었다”라고 해석한다.

### 2.3 개별 예측과 전체 결과를 분리한다

전체 지표가 좋아도 특정 행의 예측이 맞는다는 보장은 없다. 개별 결과를 설명할 때는 행 식별자, 예측값 또는 확률, 적용 임계값, 실제값이 있다면 오차를 함께 제시한다. 민감정보가 포함된 식별자는 그대로 노출하지 않는다.

```python
import pandas as pd

result = pd.DataFrame({
    "row_id": [101, 102, 103],
    "actual": [1, 0, 1],
    "prob_positive": [0.83, 0.57, 0.48]
})
threshold = 0.6
result["prediction"] = (result["prob_positive"] >= threshold).astype(int)
result["correct"] = result["actual"] == result["prediction"]

print(result.to_string(index=False))
assert set(result["prediction"]).issubset({0, 1})
```

102번은 확률이 0.57이지만 임계값 0.6 아래라 음성으로 분류된다. “57% 확률이므로 양성”처럼 임계값과 클래스 결정을 혼동하지 않는다.

## 3. 토픽 ② 분석 결과 요약

### 3.1 좋은 요약의 다섯 문장 구조

시험 답안이나 분석 보고의 요약은 다음 순서를 쓰면 누락을 줄일 수 있다.

1. **목적**: 무엇을 예측·분류·설명했는가.
2. **데이터와 분할**: 어떤 평가 데이터에서 확인했는가.
3. **최종모형과 기준**: 무엇을 최종 선택했고 무엇과 비교했는가.
4. **핵심 결과**: 지표 값, 방향, 임계값 또는 오차 단위를 쓴다.
5. **한계와 다음 행동**: 적용 범위와 추가 검증 필요성을 쓴다.

예를 들어 “고객 이탈을 예측하기 위해 학습 데이터로 모형을 구축하고, 학습에 사용하지 않은 평가 데이터에서 확인했다. 최종모형은 기준모형보다 재현율이 높았고, 임계값 0.40에서 재현율 0.82·정밀도 0.61이었다. 이 값은 현재 평가 표본과 클래스 정의에 한정되며, 운영 전 시간대가 다른 데이터에서 재검증해야 한다.”처럼 쓴다.

“성능이 매우 좋다”, “유의미하다”처럼 기준이 없는 형용사는 피한다. 통계적 유의성을 검정하지 않았다면 “유의하다”라고 쓰지 않는다. 결과표의 소수 자릿수는 요구 형식에 맞추고, 원본 계산값을 임의로 먼저 반올림한 뒤 다시 계산하지 않는다.

### 3.2 집단별 결과를 확인한다

전체 평균이 특정 집단의 낮은 성능을 가릴 수 있다. 데이터에 정당한 집단 구분이 있고 개인정보·윤리상 허용되는 범위라면 집단별 표본 수와 지표를 함께 본다.

```python
import pandas as pd

df = pd.DataFrame({
    "group": ["A", "A", "A", "B", "B", "B"],
    "actual": [1, 0, 1, 1, 0, 1],
    "pred":   [1, 0, 1, 0, 0, 0]
})

summary = (
    df.assign(correct=df["actual"].eq(df["pred"]))
      .groupby("group", as_index=False)
      .agg(n=("correct", "size"), accuracy=("correct", "mean"))
)
print(summary)
assert summary["n"].sum() == len(df)
```

이 예에서는 A와 B의 성능 차이가 크지만 각 집단이 3건뿐이다. 차이를 일반화하기보다 “소표본에서 차이가 관찰되었으므로 더 많은 표본으로 확인해야 한다”고 요약한다.

### 3.3 표와 파일의 값이 같은지 검증한다

분석 결과 요약은 사람이 읽는 문장과 제출 파일의 계산 근거가 일치해야 한다. 코드에서 지표를 변수로 저장하고, 출력용 표에도 같은 변수를 사용하면 전사 오류를 줄일 수 있다.

```r
actual <- c(1, 0, 1, 1, 0)
pred   <- c(1, 0, 0, 1, 0)
accuracy <- mean(actual == pred)
summary_table <- data.frame(metric="accuracy", value=accuracy)
print(summary_table)
stopifnot(nrow(summary_table) == 1, accuracy >= 0, accuracy <= 1)
```

예상 정확도는 `0.8`이다. 반올림 표시가 필요하면 출력 단계에서 처리하고 원 계산값은 보존한다.

## 4. 토픽 ③ 해석 한계 확인

### 4.1 반드시 점검할 여섯 가지 한계

1. **표본 대표성**: 평가 데이터가 실제 적용 대상과 같은 모집단·기간에서 왔는가?
2. **데이터 누수**: 예측 시점에 알 수 없는 정보가 입력에 섞이지 않았는가?
3. **검증 독립성**: 학습·매개변수 선택에 사용한 데이터로 최종 성능을 보고하지 않았는가?
4. **상관과 인과**: 예측 관계를 원인·효과로 확대하지 않았는가?
5. **불균형과 임계값**: 클래스 비율과 오류 비용을 반영했는가?
6. **시간 변화**: 계절성·정책·행동 변화로 데이터 분포가 달라질 가능성이 있는가?

무작위 분할이 언제나 옳지는 않다. 미래 예측 문제에서는 과거로 학습하고 이후 시점으로 평가해야 한다. 동일 고객의 여러 행이 학습과 평가에 동시에 들어가면 개인 특성이 누수될 수 있으므로 고객 단위 분할이 필요할 수 있다.

### 4.2 예측과 인과를 구분하는 표현

잘못된 표현: “방문횟수를 늘리면 구매가 증가한다.”

안전한 표현: “다른 입력을 함께 사용한 이 예측모형에서 방문횟수는 구매 예측과 관련된 패턴을 보였다. 관찰자료 기반 예측 결과만으로 방문횟수 증가의 인과효과를 확정할 수 없다.”

모형이 높은 성능을 보이더라도 편향된 과거 기록을 학습했다면 그 편향을 재현할 수 있다. 민감한 의사결정에 사용할 때는 집단별 오류, 설명 가능성, 인간 검토 절차를 별도로 확인해야 한다.

### 4.3 적용 범위를 문장으로 고정한다

결론 끝에 다음 틀을 사용하면 과장을 막을 수 있다.

> 이 결과는 [데이터 기간·대상], [평가 방법], [임계값 또는 지표 정의]에서 얻었다. [누락 변수·표본 크기·분포 변화]의 한계가 있으므로 [새 기간 검증·외부 검증·운영 모니터링] 후 적용한다.

## 5. 비교 정리와 시험 함정

| 혼동하기 쉬운 항목 | 올바른 구분 |
|---|---|
| 예측확률과 예측클래스 | 확률을 임계값과 비교해 클래스를 정한다. |
| 변수 중요도와 인과효과 | 중요도는 모형 내부 예측 기여이며 인과를 증명하지 않는다. |
| 결정계수와 정확도 | 결정계수는 회귀 변동 설명 지표이지 정답 비율이 아니다. |
| 학습 성능과 일반화 성능 | 최종 해석은 독립 평가 데이터 성능을 중심으로 한다. |
| 전체 지표와 모든 집단의 성능 | 전체 평균이 집단별·클래스별 오류를 가릴 수 있다. |
| 통계적 유의성과 업무적 중요성 | 검정 결과와 실제 효과 크기는 별개로 해석한다. |

시험에서 자주 발생하는 실수는 지표 방향을 반대로 읽는 것이다. MAE·RMSE·로그손실은 일반적으로 작을수록 좋고, 정확도·정밀도·재현율·AUC는 일반적으로 클수록 좋다. 단, 서로 다른 평가 데이터에서 얻은 값을 직접 비교하면 안 된다. 또 테스트셋을 반복해서 보고 모델을 선택하면 테스트셋이 사실상 검증셋이 된다.

## 6. 확인 문제

### 문제 1

양성 확률이 0.65인 관측치가 있다. 임계값이 0.7일 때 예측 클래스와 올바른 설명은 무엇인가?

**정답**: 예측 클래스는 음성(0)이다.

**해설**: 0.65는 양성에 대한 모형 출력 확률이지만 0.7보다 작다. 확률 자체와 임계값을 적용한 클래스 결과를 구분해야 한다.

### 문제 2

회귀모형의 결정계수가 0.88이다. “88% 정확한 모형”이라고 해석해도 되는가?

**정답**: 아니다.

**해설**: 결정계수는 평가 데이터에서 목표변수 변동을 모형이 설명하는 상대적 정도다. 개별 예측의 정답 비율이 아니며 MAE·RMSE와 잔차도 함께 확인해야 한다.

### 문제 3

트리 모형에서 소득 변수의 중요도가 가장 높았다. “소득을 올리면 반드시 구매한다”는 결론을 내릴 수 있는가?

**정답**: 없다.

**해설**: 변수 중요도는 예측에 사용된 상대적 기여를 나타낼 뿐 변화 방향이나 인과효과를 증명하지 않는다. 교란요인과 자료 수집 구조도 고려해야 한다.

### 문제 4

전체 정확도는 높지만 희귀 양성 클래스의 재현율이 낮다. 무엇을 추가로 보고해야 하는가?

**정답**: 클래스별 표본 수, 혼동행렬, 양성 정밀도·재현율, 적용 임계값과 오류 비용을 함께 보고한다.

**해설**: 불균형 데이터에서는 전체 정확도가 다수 클래스 성능만 반영할 수 있다.

### 문제 5

매개변수 선택에 사용한 검증셋에서 가장 높은 점수를 얻었다. 이 점수를 최종 일반화 성능으로 확정해도 되는가?

**정답**: 안 된다.

**해설**: 검증셋은 선택 과정에 사용되었으므로 낙관적일 수 있다. 선택과 독립된 테스트셋 또는 적절한 중첩 검증에서 최종 성능을 확인한다.

## 7. 최종 요약

- **모형 출력 해석**은 출력 종류, 지표 방향, 임계값, 단위와 평가 데이터를 함께 읽는 일이다.
- **분석 결과 요약**은 목적·데이터·최종모형·핵심 지표·한계를 짧고 재현 가능하게 연결한다.
- **해석 한계 확인**에서는 대표성, 누수, 검증 독립성, 인과 과장, 불균형, 시간 변화를 점검한다.
- 높은 성능이나 큰 중요도만으로 인과관계와 무제한 적용 가능성을 주장하지 않는다.
- 좋은 결론은 성능 수치만 제시하지 않고 그 수치가 유효한 조건과 다음 검증 행동까지 말한다.
