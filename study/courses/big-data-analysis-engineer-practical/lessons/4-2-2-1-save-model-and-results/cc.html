결과와 산출물 저장

파일을 만들었다는 사실이 아니라, 요구한 구조로 저장하고 다시 읽어 동일함을 증명했을 때 저장이 완료된다.

MODEL전처리 + 모형 + 입력 스키마
RESULT.CSV식별자 + 예측값 + 검증

1

세 종류를 분리해 저장한다

제출용 결과, 재사용할 모형, 생성 조건은 목적과 검증법이 다르다.

TOPIC 01

예측·분석결과 저장

행 식별자와 예측의 대응, 열 이름·순서, 확률·클래스 구분, 인덱스 포함 여부를 보존한다.

TOPIC 02

모형 산출물 저장

모형 객체만 떼어 두지 말고 전처리, 입력 열, 범주 수준, 학습 조건을 함께 관리한다.

TOPIC 03

저장 결과 검증

존재와 크기를 확인한 뒤 다시 읽어 행·열·자료형·값·예측 일치 여부를 검사한다.

2

저장의 완전한 수명주기

생성 직후 재로딩 검증까지 한 흐름으로 작성한다.

① 대응원 행과 예측 연결
② 구조열·순서·형식 확정
③ 저장정확한 경로·이름
④ 재로딩실제 파일 다시 읽기
⑤ 비교스키마·값 일치
3

예측·분석결과 저장

예측 배열이 아니라 제출 규격을 만족하는 행 단위 결과를 만든다.

submission = pd.DataFrame({
  "customer_id": test["customer_id"],
  "probability": probability
})

assert len(submission) == len(test)
submission.to_csv(
  "result.csv", index=False
)
가장 흔한 오류

index=False를 빠뜨려 불필요한 첫 열을 만들거나, 데이터 정렬 후 식별자와 예측 배열의 순서가 어긋난다.

결과 열의 종류와 저장 전 확인 사항
요구 결과저장할 값핵심 확인
이진 클래스0·1 또는 문제에서 정한 범주임계값 적용 결과와 클래스 표현
양성 확률요구한 클래스의 확률 열모형의 클래스 순서와 0~1 범위
회귀 예측연속형 예측값결측·무한대와 요구 자릿수
요약 통계계산값 또는 집계표그룹 누락, 단위, 반올림 시점
4

모형 산출물 저장

재사용할 때 같은 입력이 같은 변환과 예측을 거치도록 묶는다.

파이프라인에 포함할 것

  • 결측 처리와 스케일 변환
  • 범주형 인코딩과 범주 수준
  • 학습된 최종모형과 매개변수
  • 입력 열 이름과 열 순서
  • 학습·평가 분할과 지표 기준

모형만 저장하고 전처리를 잊으면 새 데이터 예측이 달라질 수 있다.

재현 메타데이터

  • 목표변수와 입력 스키마
  • 난수 시드와 주요 설정
  • 데이터 기준 시점과 생성 시각
  • 평가지표와 임계값 정의
  • 언어·라이브러리 환경 정보

개인정보, 비밀키, 민감한 서버 주소는 메타데이터에 넣지 않는다.

보안 주의

언어별 직렬화 파일은 신뢰할 수 있는 출처에서 만든 것만 불러온다. 일부 형식은 로드 과정에서 코드를 실행할 수 있으며, 버전이 달라지면 호환되지 않을 수 있다.

저장 결과 검증

파일 존재 확인은 첫 단계일 뿐이다.

1존재·크기정확한 경로에 있고 비어 있지 않은가?
2재로딩실제 저장 파일을 오류 없이 다시 읽는가?
3스키마행 수·열 이름·순서·자료형이 맞는가?
4값 비교식별자, 범위, 결측, 원 예측과 일치하는가?
actual = pd.read_csv("result.csv")

assert actual.shape == expected.shape
assert actual.columns.tolist() == expected.columns.tolist()
assert actual["id"].tolist() == expected["id"].tolist()
assert np.isfinite(actual["prediction"]).all()
assert np.allclose(actual["prediction"], expected["prediction"])
  • 파일 이름과 확장자가 문제 지시와 같은가?
  • 지정한 디렉터리에 저장했는가?
  • 행 수가 평가 데이터와 같은가?
  • 열 이름과 열 순서가 정확한가?
  • 불필요한 인덱스 열이 없는가?
  • 결측·무한대·값 범위 위반이 없는가?
  • 확률과 클래스 중 요구값을 저장했는가?
  • 다시 읽은 값이 원 계산값과 일치하는가?

실패 증상에서 원인 찾기

증상별 첫 점검 지점을 기억한다.

저장 실패 원인과 검증 방법
증상가능한 원인대응
행 수가 다름필터·결측 제거 후 인덱스 불일치원 평가 식별자와 1:1 대응 확인

파일을 찾지 못함현재 작업경로 또는 파일명 오해제시 경로와 파일 존재 여부 확인

시험 함정 6

마지막 1분에 자주 생기는 제출 오류를 차단한다.

① 인덱스 열

기본 저장 옵션을 그대로 써서 요구하지 않은 열이 생긴다.

② 결과 종류

클래스 대신 확률을, 확률 대신 클래스를 제출한다.

③ 행 순서

전처리 중 정렬한 뒤 원 식별자와 예측의 대응이 어긋난다.

④ 파일 규격

이름·확장자·열 이름·열 순서를 문제와 다르게 쓴다.

⑤ 조기 반올림

지표 계산 전에 예측값을 반올림해 결과가 달라진다.

⑥ 재로딩 생략

메모리 객체만 확인하고 실제 저장 파일을 열어 보지 않는다.

8

확인 문제

답을 생각한 뒤 펼쳐서 해설을 확인한다.

1. CSV 첫 열에 0, 1, 2가 추가되었다. 원인은?

정답: 데이터프레임 인덱스가 저장되었다. 문제에서 요구하지 않으면 Python은 index=False, R은 row.names=FALSE를 사용한다.

2. 이진 분류 확률 배열의 두 번째 열을 무조건 제출해도 되는가?

정답: 아니다. 각 열이 어떤 클래스인지 모형의 클래스 순서를 확인한 뒤 요구한 클래스의 확률을 선택한다.

3. 파일 존재와 크기만 확인하면 검증이 끝나는가?

정답: 아니다. 다시 읽어 행·열 구조, 식별자 대응, 결측·무한대, 원 값과의 일치를 검사한다.

4. 표준화 후 학습한 모형 객체만 저장하면 어떤 문제가 있는가?

정답: 새 입력에 동일한 표준화를 적용하지 못해 예측이 달라질 수 있다. 전처리와 모형을 함께 저장하고 입력 스키마를 기록한다.

한 줄 기억: 저장 완료 = 정확한 구조로 쓰기 + 실제 파일 다시 읽기 + 스키마와 값 일치 증명.
