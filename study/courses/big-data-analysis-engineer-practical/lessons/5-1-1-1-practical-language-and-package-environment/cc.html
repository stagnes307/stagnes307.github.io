2

문제별 R·Python 선택

“더 좋아 보이는 언어”보다 “제한 안에 검증까지 끝낼 언어”가 정답이다.

Py

Python을 선택할 때

  • pandas 자료 조작이 익숙하다.
  • 모형의 fit/predict 흐름을 안다.
  • 예외 메시지와 배열 형태를 고칠 수 있다.
  • CSV 저장·재로딩을 확실히 한다.
OR
R

R을 선택할 때

  • data.frame 조작이 익숙하다.
  • 기본 통계 함수와 formula를 안다.
  • 오류·경고와 자료형을 고칠 수 있다.
  • 답안 값과 CSV 구조를 검증한다.

유형 또는 문제별 언어 선택이 제공되는 경우 각 문제 시작 시 선택 상태를 확인한다. 변경 가능 여부와 조작 방법은 실제 화면 안내에 따른다.

3

제공 패키지 확인

목록 전체를 길게 출력하지 말고 실제 사용할 기능만 확인한다.

import sys
import importlib.util

print(sys.version.split()[0])
needed = ["numpy", "pandas", "sklearn"]
available = {
  name: importlib.util.find_spec(name) is not None
  for name in needed
}
print(available)

# 실제 사용할 함수로 작은 연산까지 확인
print(R.version.string)
print(.libPaths())

needed <- c("stats", "utils")
available <- vapply(
  needed, requireNamespace, logical(1),
  quietly=TRUE
)
print(available)

# 제공된 기능만 사용
버전의 올바른 역할

버전은 함수명이나 매개변수 호환 문제를 좁히기 위한 정보다. 교재의 숫자를 절대 기준으로 외우지 말고 현재 세션의 실행 결과를 따른다.

4

추가 설치 제한

설치 시도를 빼고도 완주할 수 있도록 의존성을 줄인다.

위험한 계획

“필요한 모듈이 없으면 시험 중 설치한다.”

  • 네트워크와 권한이 제한될 수 있다.
  • 설치 시간이 실행 시간과 풀이 시간을 잡아먹는다.
  • 의존성 충돌을 현장에서 해결하기 어렵다.

안전한 대체 순서

  1. 이름과 가져오기 경로를 재확인한다.
  2. 그 기능이 정말 필요한지 판단한다.
  3. 기본 함수나 제공된 패키지로 단순화한다.
  4. 허용되고 익숙하다면 다른 언어를 검토한다.
설치 없이 해결하는 작업별 대안
작업의존성을 키우는 행동단순한 대안 방향
평균·중앙값·표준편차새 통계 패키지부터 탐색Python/NumPy·pandas 또는 R 기본 함수
범주별 집계낯선 확장 도구 사용pandas groupby 또는 R aggregate
결측 대체특수 자동화 도구 설치열 통계량 계산 후 명시적 대체와 검증
CSV 저장별도 입출력 도구 추가pandas 또는 R 기본 쓰기 함수와 재로딩
금지할 습관

패키지가 없다는 메시지를 보자마자 설치 명령을 실행하지 않는다. 최신 공식 안내의 허용 범위를 따르고, 기본 전략은 이미 제공된 기능만 사용하는 것이다.

확인 문제

먼저 판단한 뒤 펼쳐서 정답과 해설을 확인한다.

1. 평소 쓰던 패키지가 보이지 않으면 설치부터 해야 하는가?

정답: 아니다. 이름·가져오기 경로를 확인하고 기본 기능 또는 이미 제공된 패키지로 대체한다. 추가 설치를 전제로 풀이하지 않는다.

2. R과 Python 중 항상 더 유리한 언어가 있는가?

정답: 없다. 문제 요구, 실제 환경, 숙련도, 오류 대응과 출력 검증 가능성을 기준으로 문제별 선택한다.

3. 패키지 가져오기에 성공하면 확인이 끝나는가?

정답: 아니다. 실제 사용할 함수로 작은 데이터를 처리해 반환 구조와 자료형까지 확인한다.

4. 교재와 시험 화면의 버전이 다르면 무엇을 기준으로 하는가?

정답: 최신 공식 안내, 실제 시험 화면, 현재 세션의 실행 결과를 기준으로 한다.

한 줄 기억: 언어는 완주 가능성으로 선택하고, 패키지는 현장에서 확인하며, 설치 없는 대안을 준비한다.
