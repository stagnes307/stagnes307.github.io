# 5-1-1-1. R·Python 시험환경과 패키지 확인

> **학습 위치**: 이 레슨은 공식 실기 체험환경과 수험 안내를 바탕으로 시험 실행환경 적응을 돕는 보충 학습이다. 패키지 버전과 제공 목록은 변경될 수 있으므로 실제 시험 화면과 최신 안내를 최종 기준으로 삼는다.

이 레슨의 세 토픽은 **문제별 R·Python 선택**, **제공 패키지 확인**, **추가 설치 제한**이다. 목표는 특정 버전 번호나 패키지 목록을 외우는 것이 아니다. 시험 시작 후 주어진 환경을 짧게 확인하고, 문제별로 적절한 언어를 선택하며, 설치 시도 없이 제공된 기능만으로 풀이를 완성하는 절차를 익히는 것이다.

## 1. 시험환경을 대하는 원칙

개인 컴퓨터에서는 인터넷 검색, 패키지 설치, 편집기 확장 기능을 자유롭게 쓸 수 있다. 시험환경은 그렇지 않을 수 있다. 따라서 다음 네 가지 원칙이 안전하다.

1. 최신 공식 안내와 시험 화면에 표시된 규칙을 우선한다.
2. 언어와 패키지 버전은 현장에서 직접 확인하며 기억에 의존하지 않는다.
3. 추가 설치가 필요한 풀이보다 기본 기능과 제공 패키지로 끝나는 풀이를 준비한다.
4. 언어 선택 후 작은 진단 코드를 실행해 입력 파일·출력 경로·핵심 함수가 동작하는지 확인한다.

“내 컴퓨터에서 되었으니 시험장에서도 된다”는 가정이 가장 위험하다. 반대로 버전이 불확실하다고 아무것도 할 수 없는 것도 아니다. 데이터 읽기, 자료형 확인, 결측 처리, 기본 통계, 단순 모형, 예측, CSV 저장 같은 핵심 흐름을 버전중립적인 함수로 준비하면 환경 차이에 강해진다.

## 2. 토픽 ① 문제별 R·Python 선택

### 2.1 익숙함과 완주 가능성을 먼저 본다

언어 선택은 “어느 언어가 더 우수한가?”가 아니라 “이 문제를 제한된 환경에서 더 빠르고 검증 가능하게 완주할 수 있는가?”로 결정한다.

| 판단 기준 | 확인 질문 |
|---|---|
| 숙련도 | 오류 메시지를 읽고 스스로 고칠 수 있는 언어인가? |
| 데이터 조작 | 행·열 선택, 결측 처리, 그룹 집계를 실수 없이 할 수 있는가? |
| 모형 구현 | 필요한 모형과 예측 인터페이스를 익숙하게 사용하는가? |
| 출력 검증 | 요구 파일을 만들고 다시 읽어 구조를 확인할 수 있는가? |
| 환경 적합성 | 필요한 패키지가 실제로 제공되는가? |

유형별로 언어를 선택할 수 있는 시험 화면이라면 각 문제를 시작할 때 선택 상태를 확인한다. 선택 방식이나 변경 가능 여부는 실제 화면 안내에 따른다. “첫 문제에서 Python을 골랐으니 모든 문제도 Python일 것”처럼 화면을 확인하지 않고 추정하지 않는다.

### 2.2 같은 문제를 두 언어로 무리하게 준비하지 않는다

평소 연습에서는 두 언어의 대응을 이해하면 좋지만, 시험 중에는 익숙한 한 언어로 일관된 풀이를 만드는 편이 오류를 줄인다. 다음은 같은 집계의 Python과 R 예시다.

```python
import pandas as pd

df = pd.DataFrame({
    "group": ["A", "A", "B", "B"],
    "score": [10, 14, 9, 15]
})
answer = df.groupby("group", as_index=False)["score"].mean()
print(answer)

assert answer.shape == (2, 2)
assert answer.loc[answer["group"].eq("A"), "score"].iloc[0] == 12
```

```r
df <- data.frame(
  group=c("A", "A", "B", "B"),
  score=c(10, 14, 9, 15)
)
answer <- aggregate(score ~ group, data=df, FUN=mean)
print(answer)

stopifnot(nrow(answer) == 2)
stopifnot(answer$score[answer$group == "A"] == 12)
```

둘 다 결과는 A 평균 12, B 평균 12다. 중요한 것은 짧은 코드가 아니라 검증까지 포함해 정확히 실행할 수 있는가다.

### 2.3 언어 선택 체크포인트

문제를 읽고 다음을 30초 안에 확인한다.

- 입력 파일 형식과 경로를 읽을 수 있는가?
- 요구 통계량 또는 모형을 익숙한 함수로 구현할 수 있는가?
- 범주형 자료와 결측값 처리 방법을 알고 있는가?
- 요구 답안이 숫자인지 CSV인지 구분했는가?
- 결과 검증용 `shape`, `head`, `summary`, `str` 사용법이 익숙한가?

하나의 희귀 기능 때문에 덜 익숙한 언어로 바꾸는 것은 신중해야 한다. 기본 기능으로 대체 가능한지 먼저 생각한다.

## 3. 토픽 ② 제공 패키지 확인

### 3.1 기억이 아니라 실행환경에서 확인한다

제공 패키지 목록과 버전은 공지 또는 환경에 따라 달라질 수 있다. 특정 버전을 이 교안에서 고정해 외우지 않는다. Python에서는 다음과 같이 기본 환경과 필요한 모듈의 가져오기 가능 여부를 확인할 수 있다.

```python
import sys
import importlib.util

print("Python:", sys.version.split()[0])

needed = ["numpy", "pandas", "sklearn"]
availability = {
    name: importlib.util.find_spec(name) is not None
    for name in needed
}
print(availability)

missing = [name for name, ok in availability.items() if not ok]
print("확인되지 않은 모듈:", missing)
```

`find_spec`가 참이라고 모든 세부 기능이 보장되는 것은 아니다. 실제 사용할 모듈과 함수를 짧게 가져오고 최소 연산까지 수행한다.

```python
try:
    import numpy as np
    import pandas as pd
    from sklearn.model_selection import train_test_split

    probe = pd.DataFrame({"x": [1, 2], "y": [0, 1]})
    assert probe.shape == (2, 2)
    assert np.mean(probe["x"]) == 1.5
    print("핵심 가져오기와 기본 연산 확인")
except (ImportError, AttributeError) as error:
    print(type(error).__name__, str(error))
```

시험에서는 긴 진단 출력을 만들 필요가 없다. 실제로 사용할 라이브러리만 확인한다. `pip list` 전체를 출력해 시간을 쓰거나 화면을 복잡하게 만들기보다 핵심 import가 성공하는지 본다.

### 3.2 버전 확인은 호환성 판단에만 사용한다

Python 패키지가 import 되었다면 보통 다음처럼 버전을 확인할 수 있다.

```python
import numpy as np
import pandas as pd
import sklearn

print("numpy", np.__version__)
print("pandas", pd.__version__)
print("sklearn", sklearn.__version__)
```

버전 숫자는 “어떤 답이 맞다”를 결정하는 암기 항목이 아니다. 자신이 준비한 코드에서 함수명이나 매개변수 호환 문제가 생겼을 때 원인을 좁히는 정보다. 최신 버전에서만 존재하는 편의 기능 대신 널리 쓰이는 기본 인터페이스를 연습하는 것이 안전하다.

R에서는 세션과 설치 패키지를 다음처럼 확인할 수 있다.

```r
print(R.version.string)
print(.libPaths())

needed <- c("stats", "utils")
available <- vapply(needed, requireNamespace, logical(1), quietly=TRUE)
print(available)
stopifnot(all(available))
```

특정 외부 패키지를 사용할 예정이라면 이름을 `needed`에 넣어 확인한다. 기본 패키지로 풀 수 있는 문제라면 외부 패키지 의존성을 늘리지 않는다.

### 3.3 함수 존재와 반환 구조를 확인한다

패키지가 있어도 함수 사용법을 잘못 기억할 수 있다. 작은 시험 데이터로 반환 형상을 확인한다.

```python
import numpy as np
from sklearn.linear_model import LinearRegression

X = np.array([[1], [2], [3], [4]])
y = np.array([3, 5, 7, 9])
model = LinearRegression().fit(X, y)
pred = model.predict(np.array([[5], [6]]))

print(pred, pred.shape)
assert pred.shape == (2,)
assert np.all(np.isfinite(pred))
```

이 작은 확인은 실제 데이터의 열 모양이 `(행,)`인지 `(행, 1)`인지 혼동하는 실수를 줄여 준다.

### 3.4 입력 파일과 작업 경로도 환경의 일부다

패키지만 확인하고 데이터 경로를 추정하면 안 된다. 화면에 제시된 경로와 파일명을 그대로 사용하고, 읽은 직후 구조를 확인한다.

```python
from pathlib import Path

# 실제 시험에서는 화면에 제시된 경로 문자열로 교체한다.
candidate = Path("data.csv")
print("현재 작업경로:", Path.cwd())
print("입력 파일 존재:", candidate.exists())
```

파일이 없다고 임의의 디렉터리를 순회하거나 전체 시스템을 탐색하지 않는다. 문제와 화면이 제공한 위치를 다시 확인한다.

## 4. 토픽 ③ 추가 설치 제한

### 4.1 설치 명령을 풀이 전략으로 삼지 않는다

시험환경에서는 네트워크와 추가 설치가 제한될 수 있다. 따라서 `pip install`, `install.packages()` 같은 명령을 해결책으로 계획하지 않는다. 설치를 시도하면 시간만 잃거나 실행 제한에 걸릴 수 있다. 실제 허용 범위는 최신 안내를 따르되, 기본 전략은 **이미 제공된 패키지만 사용**하는 것이다.

잘못된 접근:

```text
필요한 모듈이 없으면 시험 중 설치하면 된다.
```

안전한 접근:

```text
1) 제공 여부를 확인한다.
2) 없으면 기본 기능 또는 제공된 다른 패키지로 풀이를 단순화한다.
3) 문제에서 요구하지 않은 고급 기능은 제거한다.
```

### 4.2 의존성을 줄이는 대체 전략

| 필요한 작업 | 의존성이 큰 접근 | 단순 대안의 방향 |
|---|---|---|
| 평균·중앙값·표준편차 | 별도 통계 패키지 탐색 | Python 표준/NumPy·pandas 또는 R 기본 함수 |
| 범주별 집계 | 낯선 확장 패키지 | pandas `groupby` 또는 R `aggregate` |
| 결측 대체 | 특수 전처리 도구 | 열 중앙값 계산 후 명시적 대체 |
| 단순 회귀·분류 | 자동화 프레임워크 | 제공된 기본 모형 인터페이스 |
| CSV 저장 | 별도 입출력 패키지 | pandas/R 기본 쓰기 함수 |

대안은 무조건 짧아야 하는 것이 아니라 **내가 검증할 수 있어야** 한다.

```python
import pandas as pd

df = pd.DataFrame({"x": [1.0, None, 3.0, 100.0]})
median = df["x"].median()
df["x_filled"] = df["x"].fillna(median)

print(df)
assert df["x_filled"].isna().sum() == 0
assert median == 3.0
```

별도 설치 없이 중앙값 대체와 검증을 끝냈다. 이상값 100을 자동 제거하지 않은 점도 중요하다. 결측과 이상값은 서로 다른 판단이다.

### 4.3 미제공 패키지를 발견했을 때의 순서

1. 패키지 이름 오탈자와 import 경로를 확인한다.
2. 실제 문제에 그 패키지가 꼭 필요한지 판단한다.
3. 기본 언어 기능 또는 이미 확인된 패키지로 대체한다.
4. 다른 언어가 훨씬 익숙하고 문제 화면에서 선택 가능하다면 언어 선택을 재검토한다.
5. 설치 명령이나 인터넷 검색에 의존하지 않는다.

예외 메시지 전체를 무작정 지우지 말고 첫 원인부터 읽는다. `ModuleNotFoundError`는 모듈 부재 또는 이름 오류이고, `ImportError`는 모듈 내부의 특정 이름을 가져오지 못한 경우도 있다. 둘을 모두 “데이터 오류”로 오해하지 않는다.

## 5. 시험 시작 직후 3분 환경 점검 루틴

### 단계 1: 문제와 제출 형식 확인

숫자 입력인지 CSV 제출인지, 사용 가능한 언어 선택 UI가 있는지, 파일 경로가 어떻게 제시되는지 읽는다.

### 단계 2: 선택 언어의 최소 진단

```python
import sys
from pathlib import Path

print(sys.version.split()[0])
print(Path.cwd())
```

또는 R에서:

```r
print(R.version.string)
print(getwd())
```

### 단계 3: 핵심 패키지 가져오기

실제로 사용할 것만 import/load 하고 오류가 없는지 본다. 설치는 시도하지 않는다.

### 단계 4: 입력 데이터 구조 확인

```python
# df를 문제에서 제시한 파일로 읽은 직후 수행
print(df.shape)
print(df.head())
print(df.dtypes)
print(df.isna().sum())
```

R에서는 `dim(df)`, `head(df)`, `str(df)`, `colSums(is.na(df))`를 사용할 수 있다.

### 단계 5: 작은 출력 검증

결과 파일이 필요한 문제라면 임시로 헤더와 몇 행을 만들고 쓰기·읽기 흐름을 확인한 뒤 실제 결과로 덮어쓴다. 다만 문제에서 정한 파일 이름을 임시 실험으로 잘못 덮어쓰지 않도록 별도 이름을 쓴다.

## 6. 비교와 시험 함정

| 함정 | 왜 위험한가 | 안전한 대응 |
|---|---|---|
| 개인 PC의 버전을 시험환경과 같다고 가정 | 함수·매개변수가 다를 수 있음 | 현장에서 버전과 import를 짧게 확인 |
| 문제별 언어 상태를 확인하지 않음 | 의도와 다른 언어에서 코드를 실행 | 각 문제 시작 시 선택 상태 확인 |
| 패키지가 없으면 설치부터 시도 | 네트워크·설치 제한과 시간 손실 | 제공 패키지와 기본 기능으로 대체 |
| 전체 패키지 목록을 길게 출력 | 핵심 확인을 놓치고 시간 소모 | 실제 사용할 패키지만 확인 |
| 최신 편의 함수에 의존 | 구버전에서 동작하지 않을 수 있음 | 널리 쓰이는 기본 인터페이스 사용 |
| import 성공만 보고 끝냄 | 실제 함수·반환 구조에서 오류 가능 | 작은 데이터로 최소 연산 실행 |
| 경로를 기억으로 추정 | 입력·출력 파일을 못 찾음 | 화면의 정확한 경로와 존재 여부 확인 |

## 7. 확인 문제

### 문제 1

평소 쓰던 패키지가 시험환경에서 확인되지 않는다. 가장 먼저 `pip install`을 실행해야 하는가?

**정답**: 아니다.

**해설**: 이름과 import 경로를 확인한 뒤, 제공된 기본 기능이나 다른 제공 패키지로 대체한다. 추가 설치를 전제로 풀이하지 않는다.

### 문제 2

R과 Python 중 어떤 언어가 항상 더 유리한가?

**정답**: 항상 유리한 언어는 없다.

**해설**: 문제 요구, 실제 제공 환경, 자신의 숙련도, 오류 대응 능력, 출력 검증 가능성을 기준으로 문제별 선택한다.

### 문제 3

패키지 import에 성공했다. 환경 확인이 완전히 끝났는가?

**정답**: 아니다.

**해설**: 실제 사용할 함수로 작은 입력을 처리해 반환 구조와 기본 동작을 확인하고, 입력 파일과 출력 경로도 확인한다.

### 문제 4

교재에 적힌 패키지 버전과 시험 화면의 버전이 다르다. 무엇을 기준으로 해야 하는가?

**정답**: 실제 시험 화면과 최신 공식 안내, 실행 결과를 기준으로 한다.

**해설**: 버전 목록은 변경될 수 있으므로 교재 숫자를 절대 기준으로 삼지 않는다.

### 문제 5

모듈이 없을 때 사용할 수 있는 안전한 대체 전략 세 가지를 쓰시오.

**정답 예시**: 기본 언어 함수로 구현한다, 이미 제공된 다른 패키지의 기본 기능을 사용한다, 문제에서 허용하고 더 익숙하다면 다른 언어를 선택한다.

## 8. 최종 요약

- **문제별 R·Python 선택**은 언어의 우열이 아니라 제한된 환경에서 완주하고 검증할 수 있는지를 기준으로 한다.
- **제공 패키지 확인**은 기억이 아니라 현재 세션의 import, 버전, 최소 연산으로 수행한다.
- **추가 설치 제한**을 전제로 기본 기능과 제공 패키지만으로 풀 수 있는 대안을 준비한다.
- 구체적인 패키지 목록과 버전, UI 동작은 변경될 수 있으므로 최신 공식 안내와 실제 시험 화면이 최종 기준이다.
- 시험환경 적응의 핵심은 화려한 도구가 아니라 짧은 진단, 단순한 구현, 입출력 검증이다.
