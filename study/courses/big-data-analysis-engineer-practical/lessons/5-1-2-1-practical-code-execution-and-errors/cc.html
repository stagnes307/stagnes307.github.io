코드 실행·저장·오류 대응

실행을 짧게 나누고, 중요한 지점마다 저장하며, 오류 유형과 상태를 근거로 한 가지 원인씩 복구한다.

실전 지도1분 실행 제한코드 저장과 초기화오류 메시지 확인확인 문제
체험환경 보충 학습

실제 실행 제한 적용 방식, 버튼 이름, 초기화 범위는 최신 공식 안내와 시험 화면을 따른다. 여기서는 변경 가능한 UI를 단정하지 않고, 어떤 환경에서도 통하는 실행·저장·복구 원칙을 익힌다.

1

안전한 실행의 세 축

시간, 상태, 원인을 따로 관리하면 복구가 빨라진다.

TOPIC 01

1분 실행 제한

한 번의 실행을 작게 유지하고 중복 계산, 과도한 탐색, 전체 출력, 종료 없는 반복을 제거한다.

TOPIC 02

코드 저장과 초기화

실행 성공과 저장 성공을 구분하고, 중요한 단계마다 저장한 뒤 초기화 범위와 재실행 순서를 확인한다.

TOPIC 03

오류 메시지 확인

오류 유형과 발생 단계를 읽고 최소 상태를 출력해 한 가지 원인만 수정한 뒤 관련 단계부터 검증한다.

1분 실행 제한

제한을 우회하려 하지 말고 각 실행의 비용을 줄인다.

느려지는 대표 원인

  • 매개변수 후보와 교차검증 반복을 과도하게 늘림
  • 반복문 안에서 파일 읽기와 전처리를 되풀이함
  • 큰 데이터와 로그를 전부 화면에 출력함
  • 종료 조건이 틀린 반복문을 실행함
  • 데이터 크기 확인 없이 복잡한 모형부터 시작함
from time import perf_counter

start = perf_counter()
answer = df.groupby(
  "group", as_index=False
)["value"].mean()
elapsed = perf_counter() - start

print(answer)
print(f"{elapsed:.4f}초")
assert len(answer) > 0

코드 저장과 초기화

실행, 코드 저장, 결과 파일 저장은 서로 다른 상태다.

입력 성공파일·shape 확인 후

출력 검증파일 재로딩 후
큰 변경 전초기화·수정 전에

재시작 가능한 이름과 순서

df2, df3 대신 train_raw, train_clean, prediction, submission처럼 역할이 보이는 이름을 쓴다.

원본을 바로 덮어쓰지 않으면 잘못된 변환에서 쉽게 돌아올 수 있다.

초기화 전 다섯 확인

  1. 현재 코드를 저장했는가?
  2. 필요 결과 파일이 존재하는가?
  3. 초기화 범위를 화면에서 읽었는가?
  4. 재실행 순서를 알고 있는가?
  5. 오류 원인을 먼저 확인했는가?
재현성 시험

시험 함정 6

실행 성공처럼 보이지만 제출을 망치는 행동을 구분한다.

① 한 번에 전체 실행

오류 후보가 많아 최초 원인을 찾기 어려워진다.

② 표본 결과 제출

시험용 일부 행 결과를 최종 답으로 착각한다.

③ 실행과 저장 혼동

코드가 동작했지만 저장되지 않은 상태로 초기화한다.

④ 순서 의존

메모리에 남은 객체 때문에 위에서부터 재실행하면 실패한다.

⑤ 다중 수정

오류를 보고 여러 곳을 바꿔 어떤 수정이 효과였는지 모른다.

⑥ 광범위 예외 처리

오류를 숨겨 결과가 없거나 잘못되어도 계속 진행한다.

8

확인 문제

먼저 답한 뒤 펼쳐서 해설을 확인한다.

1. 실행 제한을 피하려면 모든 작업을 병렬화해야 하는가?

정답: 아니다. 먼저 데이터 크기와 느린 구간을 확인하고 중복 계산, 과도한 후보, 불필요한 출력을 줄인다.

2. 20행 표본에서 정상 실행되었다. 그 결과를 제출해도 되는가?

정답: 아니다. 표본은 구조 점검용이다. 최종 답은 요구된 전체 데이터에서 다시 계산하고 검증한다.

3. 초기화 전에 확인할 핵심 두 가지는?

정답 예시: 현재 코드가 저장되었는지, 필요한 결과 파일이 실제 생성되었는지 확인한다. 초기화 범위와 재실행 순서도 읽는다.

4. KeyError: 'age'의 첫 진단은?

정답: 실제 열 이름 목록을 출력해 오탈자, 대소문자, 앞뒤 공백을 확인한다.

5. 모든 오류를 광범위한 예외 처리로 넘기면 안전한가?

정답: 아니다. 오류가 숨겨져 잘못된 결과를 제출할 수 있다. 구체적 원인만 처리하고 정상 결과를 검증한다.

한 줄 기억: 짧게 실행하고, 자주 저장하고, 오류 유형과 상태를 근거로 하나씩 복구한다.
