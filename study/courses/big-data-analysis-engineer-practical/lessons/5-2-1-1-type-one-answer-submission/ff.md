> **범위 안내**: 이 레슨은 공식 출제범위 자체가 아니라 한국데이터산업진흥원(K-DATA)의 「빅데이터분석기사 실기 체험 환경 가이드」와 체험환경을 바탕으로 만든 제출 절차 보충 학습이다. 체험문제는 실제 출제 경향과 다를 수 있고 화면·파일명·열 이름·제출 형식도 바뀔 수 있으므로, 실제 응시 시에는 문제 화면과 최신 안내를 최종 기준으로 삼는다.

이 레슨의 정확한 토픽은 **풀이 코드 작성**, **제출 형식 확인**, **계산값 입력**이다. 제1유형의 핵심은 계산을 한 번 성공하는 데서 끝나지 않는다. 문제의 조건을 코드로 옮기고, 중간 결과를 검증하고, 요구된 형식으로 만든 단일 값을 별도의 답안 제출 화면에 옮겨야 완주다.

## 1. 공식 체험환경에서 확인되는 흐름

공식 가이드의 체험환경에서는 제1유형의 문제 풀이 화면과 답안 제출 화면이 분리되어 있다. 풀이 화면에서 문항을 읽고 코드를 실행한 뒤 답안 제출 화면으로 이동한다. 소문항이 여러 개면 제시된 소문항 순서대로 입력하고, 각 소문항이 요구하는 형식을 지켜 제출한다. 답안을 여러 번 제출할 수 있으며 가이드상 마지막으로 제출한 답안이 채점 대상이므로, 고친 값을 입력했다면 마지막 제출 상태까지 확인해야 한다.

여기서 중요한 구분은 다음과 같다.

| 단계 | 해야 할 일 | 남겨야 할 확인 증거 |
|---|---|---|
| 문제 읽기 | 데이터, 조건, 제외 규칙, 연산 순서 파악 | 조건을 짧은 주석이나 메모로 재작성 |
| 풀이 | 읽기 → 정제 → 필터 → 계산을 코드로 분리 | 행 수, 열 이름, 중간 통계량 출력 |
| 형식화 | 반올림·정수화·소수 자릿수 등 지시 적용 | 원값과 제출 문자열을 나란히 확인 |
| 입력 | 별도 화면의 올바른 소문항 칸에 값 입력 | 입력 형식 오류 메시지 여부 확인 |
| 제출 | 제출 후 최종 상태 확인 | 수정했다면 다시 제출했는지 확인 |

특정 자릿수, 파일 경로, 열 이름을 미리 외우면 안 된다. 모두 해당 문제의 지시에서 가져와야 한다.

## 2. 토픽 ① 풀이 코드 작성

### 2.1 조건을 연산 순서로 번역한다

문장에서 숫자만 찾지 말고 다음 여섯 항목을 먼저 표시한다.

1. 어느 파일 또는 데이터프레임을 쓰는가?
2. 계산 대상 열은 무엇인가?
3. 자료형과 결측값은 어떻게 다루는가?
4. 어떤 행을 포함하거나 제외하는가?
5. 집계·정렬·차이·비율 중 무엇을 어떤 순서로 계산하는가?
6. 최종 출력 형식은 무엇인가?

예를 들어 “`group`이 A인 행에서 결측을 제외한 `score` 평균을 구하고 소수 둘째 자리까지 반올림하라”는 지시는 `선택 → 결측 제외 → 평균 → 마지막 반올림` 순서다. 평균 전에 각 값을 반올림하거나, 전체 평균을 구한 뒤 A만 고르는 코드는 다른 답을 만들 수 있다.

### 2.2 Python 재현 예제

다음 코드는 외부 파일 없이 그대로 실행되는 연습 예제다. 실제 문제에서는 `StringIO` 부분을 화면에 제시된 파일 읽기로 바꾸되 열 이름과 조건은 문제 지시 그대로 사용한다.

```python
from io import StringIO
import pandas as pd
import math

csv_text = """id,group,score
1,A,10.0
2,A,12.5
3,B,20.0
4,A,
5,A,15.0
"""
df = pd.read_csv(StringIO(csv_text))

required = ["id", "group", "score"]
assert list(df.columns) == required, f"열 불일치: {df.columns.tolist()}"
assert len(df) == 5, f"행 수 불일치: {len(df)}"

selected = df.loc[df["group"].eq("A"), "score"].dropna()
assert len(selected) == 3, f"계산 대상 행 수 확인 필요: {len(selected)}"

raw_answer = float(selected.mean())
assert math.isfinite(raw_answer), "답이 유한한 숫자가 아님"

digits = 2  # 실제 문제의 자릿수 지시에서 가져온다.
rounded_answer = round(raw_answer, digits)
submit_text = f"{rounded_answer:.{digits}f}"

print("대상값:", selected.tolist())
print("원 계산값:", raw_answer)
print("제출 문자열:", submit_text)
assert submit_text == "12.50"
```

실제 파일을 읽는 최소 뼈대는 다음과 같다. `data/type1.csv`와 `score`는 예시 이름이며, 임의로 추측하지 말고 문제에 표시된 문자열로 교체한다.

```python
from pathlib import Path
import pandas as pd

input_path = Path("data/type1.csv")
assert input_path.is_file(), f"입력 파일을 찾을 수 없음: {input_path}"

df = pd.read_csv(input_path)
print("shape:", df.shape)
print("columns:", df.columns.tolist())
print(df.head())

required_columns = {"group", "score"}
missing = required_columns - set(df.columns)
assert not missing, f"누락 열: {sorted(missing)}"
```

경로가 틀렸을 때 상위 폴더 전체를 탐색하는 대신 문제 화면의 데이터 탭과 제시 경로를 다시 읽는다. 열 이름의 대소문자, 공백, 한글 표기도 그대로 비교한다.

### 2.3 R 재현 예제

같은 계산을 R 기본 기능으로 실행할 수 있다.

```r
text_data <- "id,group,score
1,A,10.0
2,A,12.5
3,B,20.0
4,A,
5,A,15.0"

df <- read.csv(text=text_data, stringsAsFactors=FALSE)
required <- c("id", "group", "score")
stopifnot(identical(names(df), required))
stopifnot(nrow(df) == 5)

selected <- df$score[df$group == "A" & !is.na(df$score)]
stopifnot(length(selected) == 3)

raw_answer <- mean(selected)
stopifnot(is.finite(raw_answer))

digits <- 2  # 실제 문제의 자릿수 지시로 교체
rounded_answer <- round(raw_answer, digits)
submit_text <- sprintf(paste0("%.", digits, "f"), rounded_answer)

print(selected)
print(raw_answer)
print(submit_text)
stopifnot(submit_text == "12.50")
```

실제 파일에서는 `file.exists()`로 경로를, `names()`로 열을, `nrow()`로 행 수를 먼저 확인한다.

```r
input_path <- "data/type1.csv"  # 실제 제시 경로로 교체
stopifnot(file.exists(input_path))
df <- read.csv(input_path, stringsAsFactors=FALSE)
print(dim(df))
print(names(df))
print(head(df))
stopifnot(all(c("group", "score") %in% names(df)))
```

### 2.4 중간 검증은 답을 바꾸지 않는다

검증 출력은 계산값을 손으로 수정하는 과정이 아니다. 다음을 확인하는 안전장치다.

- 필터 전후 행 수가 조건과 맞는가?
- 결측 제외가 요구된 열에만 적용되었는가?
- 숫자처럼 보이는 문자열이 실제 숫자로 변환되었는가?
- 최댓값·평균·개수 등 요구한 통계량을 계산했는가?
- 결과가 길이 1인 유한한 값인가?

Python에서 `pd.to_numeric(..., errors="coerce")`를 쓰면 변환 실패가 결측으로 바뀐다. 편리하지만 실패 행을 조용히 버릴 수 있으므로 변환 전후 결측 개수를 비교해야 한다. R의 `as.numeric()`도 변환 경고와 새 결측을 확인한다.

## 3. 토픽 ② 제출 형식 확인

### 3.1 계산값과 제출값을 분리한다

`raw_answer`는 가능한 한 충분한 정밀도를 유지하고, 반올림은 마지막 한 번만 수행한다. 문제에서 “소수 둘째 자리까지 반올림”과 “소수 둘째 자리로 표시”를 함께 요구하면 숫자 반올림 후 고정 자릿수 문자열로 확인할 수 있다. 반면 정수만 입력하라고 하면 소수 문자열을 넣지 않는다. 형식은 문제 지시가 정한다.

```python
raw_answer = 12.5

as_two_decimals = f"{round(raw_answer, 2):.2f}"  # '12.50'
as_integer = str(int(round(raw_answer)))          # '12'

print(as_two_decimals, as_integer)
```

두 표현은 서로 대체할 수 없다. 정답의 수학적 값이 같아 보여도 입력 UI의 형식 검증을 통과하지 못할 수 있다.

### 3.2 반올림 위치를 표시한다

다음 두 계산은 일반적으로 같지 않다.

```python
values = [1.245, 1.245, 1.255]
wrong = sum(round(x, 2) for x in values) / len(values)
right = round(sum(values) / len(values), 2)
print(wrong, right)
```

문제에서 중간 단계 반올림을 명시하지 않았다면 전체 계산을 끝낸 뒤 최종값에 적용하는 것이 기본이다. 다만 사용 언어의 부동소수점 표현과 반올림 규칙이 경계값에서 영향을 줄 수 있으므로, 문제에서 특정 처리 함수를 지시하면 그 지시를 따른다. 임의로 “무조건 올림”이나 “무조건 버림”으로 바꾸지 않는다.

### 3.3 제출 직전 형식 검사

- 천 단위 쉼표, `%`, 통화기호 같은 장식 문자를 요구했는가?
- 숫자 하나만 입력하는 칸에 설명 문장을 붙이지 않았는가?
- 음수 부호와 소수점 문자가 유지되었는가?
- 지수 표기 대신 일반 소수 표기가 필요한가?
- 소문항별 자릿수가 서로 다른데 한 규칙을 복사하지 않았는가?

공식 가이드의 예시처럼 요구 소수 자릿수를 초과하면 입력 형식 오류가 표시될 수 있다. 오류 메시지가 보이면 계산을 전부 다시 하기 전에 먼저 해당 소문항의 입력 형식과 자릿수를 확인한다.

## 4. 토픽 ③ 계산값 입력

### 4.1 소문항 순서와 값의 대응을 고정한다

소문항이 세 개라면 코드 결과도 순서를 붙여 출력한다.

```python
answers = {
    "소문항1": 12.50,
    "소문항2": 3,
    "소문항3": -0.125,
}
for label, value in answers.items():
    print(label, value)
```

답안 화면에서 칸의 순서를 다시 읽고 하나씩 옮긴다. 화면 이동 후 기억에 의존하거나 출력 순서가 다른 딕셔너리·표를 그대로 복사하지 않는다. 입력 후에는 각 칸을 문제 번호와 역대조한다.

### 4.2 마지막 제출을 관리한다

공식 체험환경 가이드에서는 답안을 여러 번 제출할 수 있고 마지막 제출 답안이 채점 대상이라고 안내한다. 따라서 오타를 발견해 값을 고쳤다면 입력만 고치고 끝내지 말고 제출 동작과 최종 상태까지 확인한다. 반대로 검증하지 않은 새 값을 마지막 순간에 덮어쓰지 않는다.

안전한 종료 순서는 다음과 같다.

1. 실행 결과에서 원값과 형식화 값을 확인한다.
2. 답안 제출 화면의 문항·소문항을 다시 읽는다.
3. 각 값을 지정 형식으로 입력한다.
4. 형식 오류 메시지가 없는지 본다.
5. 제출한다.
6. 수정했다면 마지막 제출 내용이 수정본인지 확인한다.

## 5. 실수와 오류 대응

| 증상 | 가능한 원인 | 먼저 할 일 |
|---|---|---|
| `FileNotFoundError` 또는 파일 없음 | 경로·파일명 오타 | 문제의 데이터 경로를 문자 단위로 재확인 |
| `KeyError` 또는 열 없음 | 열 이름 오타·공백·대소문자 | 실제 열 목록 출력 후 요구 열과 비교 |
| 답이 `NaN` | 대상 행 없음·모두 결측·변환 실패 | 필터 행 수와 결측 수 확인 |
| 예상보다 행이 많음 | `and`/`or`, `&`/`|` 조건 오류 | 조건을 하나씩 적용하고 행 수 출력 |
| 소수 형식 오류 | 자릿수 초과·장식 문자 포함 | 문제의 형식 예와 제출 문자열 비교 |
| 값은 맞는데 소문항이 틀림 | 출력·입력 순서 혼동 | 번호를 붙여 다시 출력하고 칸과 대응 |

체험환경의 코딩 영역에서 오류가 나면 실행 결과의 첫 오류 원인부터 고친다. 경고가 있어도 실행과 결과가 정상인 경우가 있지만, 경고가 계산 대상이나 형 변환에 영향을 주는지는 확인해야 한다. 경고를 무조건 무시하지 않는다.

## 6. 시험 함정 체크리스트

- 조건의 경계가 `>`인지 `>=`인지 확인하지 않았다.
- 결측을 전체 행에서 제거해 다른 열 때문에 표본이 줄었다.
- 정렬 후 첫 행과 최댓값을 같은 것으로 가정했다.
- 비율에 100을 곱할지 문제를 읽지 않았다.
- 그룹 개수와 행 개수를 혼동했다.
- 중간 계산마다 반올림해 누적 오차를 만들었다.
- 정답 숫자와 형식화 문자열을 구분하지 않았다.
- 풀이 화면에서 값만 확인하고 별도 답안 화면 제출을 잊었다.
- 값을 고쳤지만 다시 제출하지 않았다.

## 7. 확인 문제

### 문제 1

“A 그룹의 `score` 평균을 구한 뒤 소수 둘째 자리까지 표시”라는 지시에서 가장 안전한 순서는 무엇인가?

1. 각 값을 먼저 둘째 자리로 반올림 → 전체 평균
2. A 그룹 선택 → 필요한 결측 처리 → 평균 → 마지막 반올림·형식화
3. 전체 평균 → A 그룹 선택
4. 출력된 첫 숫자를 그대로 입력

### 문제 2

계산 결과가 `12.5`이고 입력 형식이 소수 둘째 자리까지라면 제출 전에 무엇을 확인해야 하는가?

### 문제 3

값을 수정했지만 제출 버튼을 다시 누르지 않았다. 공식 체험환경 가이드의 마지막 제출 원칙을 고려하면 왜 위험한가?

## 정답과 해설

1. **정답: 2번.** 필터와 결측 처리의 범위를 먼저 확정하고 집계를 끝낸 뒤 최종 단계에서 반올림해야 연산 순서가 보존된다.
2. **정답: `12.50`처럼 요구 자릿수를 갖춘 입력 표현인지 확인한다.** 수학적 값만 같다고 입력 형식까지 같은 것은 아니다. 문제의 예시와 오류 메시지를 함께 확인한다.
3. **정답: 마지막으로 실제 제출된 답안이 채점 대상이므로 수정 전 값이 남을 수 있다.** 입력 수정과 제출 완료는 별개의 동작이다.

## 8. 요약

- **풀이 코드 작성**에서는 파일·열·조건·결측·연산 순서를 나누고 중간 행 수와 결과 길이를 검증한다.
- **제출 형식 확인**에서는 원 계산값을 유지한 뒤 문제 지시에 맞춰 마지막에 반올림하고 입력 문자열을 점검한다.
- **계산값 입력**에서는 별도 답안 화면의 소문항 순서에 맞춰 옮기고 형식 오류와 마지막 제출 상태를 확인한다.
- 체험환경 절차는 적응용 보충 자료이며 실제 시험에서는 최신 안내와 화면의 파일명·열·자릿수·제출 규칙이 최우선이다.
