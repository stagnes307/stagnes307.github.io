## 1. 공식 가이드에서 확인되는 환경 지도

공식 가이드는 실기 체험환경을 클라우드 기반 CBT와 Chrome 브라우저 환경으로 설명한다. 문제별로 R 또는 Python을 선택할 수 있으며 제공 패키지는 회차별로 다를 수 있다. 제공 패키지만 이용할 수 있고 시험 중 추가 설치는 불가하다고 안내한다. 특정 버전이나 목록을 외우지 말고 실제 화면에서 확인해야 하는 이유다.

가이드의 코딩 제약에는 다음 내용이 포함된다.

- 코드 라인별 실행 기능은 제공되지 않는다.
- 그래프 기능, 단축키, 자동완성 기능은 제공되지 않는다.
- 코드 실행 시간은 1분으로 제한되고 초과 시 강제 실행 취소된다.
- `help`, `dir`, `?` 등을 활용한 함수 참조는 가능하다.

이 규칙은 긴 셀 하나를 무작정 실행하기보다, 전체 코드가 짧은 시간 안에 재실행 가능하고 중간 검증 출력이 명확해야 함을 뜻한다. 시험 중 패키지 설치나 인터넷 검색에 기대는 계획은 세우지 않는다.

### 화면 영역의 역할

공식 가이드는 문제영역, 코딩영역, 실행결과 영역, 내비게이션 영역을 구분한다. 문제·데이터·제출 형식, 선택 언어와 코드, 실행 결과와 오류, 문제 제목과 제출 상태를 각 영역에서 확인한다.

가이드에는 데이터 세트 확인, 언어 선택, 초기화, 저장, 실행, 테스트 관련 버튼, 제출 기능이 설명되어 있다. 체험환경에서는 저장 기능이 활성화되지 않고 문제 이동 시 코드와 메모장이 초기화되지만 실제 시험에서는 정상 작동한다고 명시한다. 이 차이를 “실제 시험에서도 저장이 안 된다”로 일반화하면 안 된다. 가이드는 코드를 주기적으로 저장하면서 풀이할 것을 권장한다.

## 3. 토픽 ② 코드 실행과 결과 검토

### 3.1 전체 실행을 짧은 단계로 설계한다

라인별 실행이 제공되지 않는 환경을 대비하여, 코드는 위에서 아래로 한 번에 실행돼야 한다. 그러나 논리적으로는 다음 블록을 분리한다.

1. 설정: 경로, 열 이름, 출력 이름
2. 입력: 파일 읽기
3. 검증: 행·열·자료형·결측
4. 처리: 필터·변환·모형·통계
5. 산출: 값 또는 제출 프레임
6. 재검증: 길이·범위·형식·파일 재읽기

각 블록의 출력은 짧고 판별 가능하게 만든다. 전체 데이터프레임을 모두 출력하면 핵심 오류가 묻힐 수 있다.

### 3.2 세 유형을 한 번에 점검하는 Python 연습

다음 코드는 외부 입력 없이 그대로 실행되며, 제1유형 값, 제2유형 한 열 CSV, 제3유형 통계 계산의 제출 직전 형태를 연습한다. 실제 문제의 계산법을 대신하는 코드는 아니다.

```python
from pathlib import Path
from io import StringIO
import csv
import math
import pandas as pd
from scipy import stats

# 공통 연습 데이터
text = """id,group,value
1,A,10
2,A,12
3,B,18
4,A,14
5,B,16
"""
df = pd.read_csv(StringIO(text))
assert df.columns.tolist() == ["id", "group", "value"]
assert len(df) == 5

# 제1유형: A 그룹 평균, 예시로 소수 둘째 자리 표시
type1_raw = float(df.loc[df["group"].eq("A"), "value"].mean())
type1_text = f"{type1_raw:.2f}"
assert type1_text == "12.00"

# 제2유형: 평가 행마다 예시 예측값 생성, 한 열 CSV 저장
prediction_col = "pred"       # 실제 지정 헤더로 교체
output_path = Path("result.csv")  # 실제 지정 파일명으로 교체
prediction = df["value"] / df["value"].max()
answer = pd.DataFrame({prediction_col: prediction})
assert answer.shape == (len(df), 1)
assert answer[prediction_col].between(0, 1).all()
answer.to_csv(output_path, index=False)

with output_path.open("r", encoding="utf-8", newline="") as file:
    header = next(csv.reader(file))
assert header == [prediction_col]
reloaded = pd.read_csv(output_path)
assert reloaded.shape == (len(df), 1)

# 제3유형: value 평균이 13과 다른지 양측 단일표본 t 검정
test_result = stats.ttest_1samp(df["value"], popmean=13,
                                alternative="two-sided")
type3_stat = float(test_result.statistic)
type3_p = float(test_result.pvalue)
assert math.isfinite(type3_stat)
assert 0 <= type3_p <= 1

print("제1유형 제출값:", type1_text)
print("제2유형 파일:", output_path, reloaded.shape, reloaded.columns.tolist())
print("제3유형 소문항1 통계량:", f"{type3_stat:.3f}")
print("제3유형 소문항2 p-value:", f"{type3_p:.3f}")
```

이 코드에서 `result.csv`, `pred`, 반올림 자릿수는 연습값이다. 실제 문제의 지시와 다르면 반드시 바꾼다. `scipy`가 제공되지 않으면 설치하지 말고 실제 제공 패키지와 R 기본 통계 함수 등 가능한 경로를 확인한다.

### 3.3 같은 점검의 R 연습

```r
text_data <- "id,group,value
1,A,10
2,A,12
3,B,18
4,A,14
5,B,16"
df <- read.csv(text=text_data, stringsAsFactors=FALSE)
stopifnot(identical(names(df), c("id", "group", "value")))
stopifnot(nrow(df) == 5)

# 제1유형
type1_raw <- mean(df$value[df$group == "A"])
type1_text <- sprintf("%.2f", type1_raw)
stopifnot(type1_text == "12.00")

# 제2유형
prediction_col <- "pred"       # 실제 지정 헤더로 교체
output_path <- "result.csv"    # 실제 지정 파일명으로 교체
answer <- data.frame(df$value / max(df$value))
names(answer) <- prediction_col
stopifnot(nrow(answer) == nrow(df), ncol(answer) == 1)
write.csv(answer, output_path, row.names=FALSE)
reloaded <- read.csv(output_path, check.names=FALSE)
stopifnot(identical(names(reloaded), prediction_col))
stopifnot(nrow(reloaded) == nrow(df))

# 제3유형
test_result <- t.test(df$value, mu=13, alternative="two.sided")
type3_stat <- unname(test_result$statistic)
type3_p <- test_result$p.value
stopifnot(is.finite(type3_stat), type3_p >= 0, type3_p <= 1)

cat("제1유형 제출값:", type1_text, "\n")
cat("제2유형 파일:", output_path, dim(reloaded), names(reloaded), "\n")
cat("제3유형 소문항1 통계량:", sprintf("%.3f", type3_stat), "\n")
cat("제3유형 소문항2 p-value:", sprintf("%.3f", type3_p), "\n")
```

### 3.4 Error와 Warning을 구분한다

공식 가이드는 실행 결과에 Error와 Warning 등 시스템 메시지가 표시될 수 있다고 설명한다. Error가 나오면 원인을 찾아 코드를 수정한다. Warning은 코드가 정상 실행되고 결과와 무관하다고 확인되는 경우 고려하지 않아도 된다고 안내하지만, 그 확인 과정은 생략하면 안 된다.

안전한 오류 읽기 순서는 다음과 같다.

1. 첫 Error의 유형과 메시지를 읽는다.
2. 파일 경로, 열 이름, 자료형, 함수 인수를 차례로 확인한다.
3. 수정 후 전체 코드를 다시 실행한다.
4. 결과가 이전 실행의 잔여물이 아닌지 확인한다.
5. Warning이 있다면 표본 제거·수렴 실패·형 변환 등 결과 영향 여부를 판단한다.

1분 실행 제한을 피하려고 검증을 모두 삭제하지 않는다. 과도한 반복, 필요 없는 모형 탐색, 전체 데이터 출력, 중복 학습을 줄여 재실행 가능한 코드로 만든다. 실행 시간이 초과하면 작은 표본에서 문법과 흐름을 점검한 뒤 전체 데이터로 돌아가되, 최종 결과는 반드시 전체 요구 데이터로 계산한다.

## 4. 토픽 ③ 답안·파일 최종 제출

### 4.1 유형별 제출 분기

공식 가이드의 흐름을 유형별로 정리하면 다음과 같다.

| 유형 | 풀이 화면 산출물 | 최종 제출 |
|---|---|---|
| 제1유형 | 계산값과 형식화 값 | 별도 답안 제출 화면에서 소문항 순서대로 입력 |
| 제2유형 | 예측 코드와 지정 CSV | 코드 제출 후 생성 CSV의 파일명·헤더·행 수 검증 |
| 제3유형 | 통계 결과 성분과 형식화 값 | 별도 답안 제출 화면에서 소문항 순서대로 입력 |

제1·3유형은 코딩 화면에 숫자를 출력했다고 제출된 것이 아니다. 별도 답안 제출 화면으로 이동해야 한다. 제2유형은 파일이 생성됐다는 메시지만 보지 말고 실제 파일을 다시 읽어 구조를 확인한다.

### 4.2 제1·3유형 최종 확인

- 소문항 번호와 출력 라벨이 대응하는가?
- 원값이 아니라 지시 자릿수로 형식화한 값인가?
- 음수 부호, 소수점, 지수 표기가 허용 형식과 같은가?
- 입력 형식 오류 메시지가 없는가?
- 값을 수정한 뒤 다시 제출했는가?

공식 가이드는 답안을 여러 번 제출할 수 있고 마지막 제출 답안이 채점 대상이라고 안내한다. 마지막 순간에 검증하지 않은 값을 덮어쓰지 않는다.

### 4.3 제2유형 최종 확인

```python
from pathlib import Path
import pandas as pd

output_path = Path("result.csv")       # 실제 지정 파일명
prediction_col = "pred"                # 실제 지정 칼럼명
expected_rows = len(test)               # 실제 평가 데이터 행 수

assert output_path.parent == Path(".")
assert output_path.is_file()
check = pd.read_csv(output_path)
assert check.columns.tolist() == [prediction_col]
assert check.shape == (expected_rows, 1)
assert check[prediction_col].notna().all()
assert not any(str(c).startswith("Unnamed") for c in check.columns)
```

공식 가이드의 제2유형 체험 형식은 지정 예측 칼럼 1개, 자동 인덱스 제거, 지정 파일명 사용, 별도 디렉터리 금지를 안내한다. 실제 문제에 다른 형식이 명시되면 그 지시가 우선이다. 제출 전 검증이 끝난 코드를 마지막으로 실행하고 제출 상태를 확인한다.

### 4.4 메모장과 문제 이동

가이드상 메모장은 문제 풀이 화면에서 사용할 수 있고 답안 제출 화면에는 제공되지 않는다. 문제별 탭 자동 이동 옵션을 켜면 문제 번호에 맞춰 메모 탭이 이동하고, 끄면 이동 후에도 작성 탭을 유지할 수 있다. 메모 내용은 입력 후 자동 저장 안내가 표시된다고 설명한다. 다만 체험환경에서는 이 기능이 비활성화될 수 있고 실제 시험에서 정상 작동한다고 구분한다.

메모에는 정답만 적기보다 다음처럼 대응 정보를 남긴다.

```text
2번 소문항1 = 통계량 원값 / 제출 자릿수
2번 소문항2 = p-value 원값 / 제출 자릿수
제2유형 = 파일명 / 예측 헤더 / 평가 행 수
```

좌측 내비게이션이나 화면 하단의 이전·다음 문제로 이동할 때 문제 제목과 번호를 다시 확인한다. 체험환경에서는 이동 시 코드와 메모가 초기화될 수 있으므로, 체험 연습 중 사라진 내용을 실제 시험 저장 정책으로 오해하지 않는다.

## 5. 자주 발생하는 함정과 대응

| 함정 | 결과 | 대응 |
|---|---|---|
| 문제 이동 전에 제출 계약을 기록하지 않음 | 파일명·자릿수 혼동 | 유형별 계약표 작성 |
| 데이터 탭을 보지 않고 경로 추측 | 파일 읽기 실패 | 화면의 정확한 경로 사용 |
| 제공되지 않은 패키지 설치 시도 | 시간 손실·실행 실패 | 제공 패키지와 기본 기능 사용 |
| 라인별 실행을 전제로 상태 누적 | 전체 실행 실패 | 위에서 아래로 재현 가능한 코드 |
| 실행 결과만 보고 제출 완료로 착각 | 답안 미제출 | 유형별 별도 제출 흐름 확인 |
| CSV 자동 인덱스 포함 | 열 수 불일치 | 저장 후 재읽기 |
| 반올림을 중간 계산에 적용 | 최종값 오차 | 마지막 단계 형식화 |
| 수정 후 재제출 누락 | 이전 답안이 마지막 상태 | 재실행·재검증·재제출 |

## 6. 확인 문제

### 문제 1

체험환경에서 문제를 이동하자 코드가 초기화되었다. 이것만 보고 실제 시험에서도 저장 기능이 없다고 결론 내리면 안 되는 이유는 무엇인가?

### 문제 2

제2유형에서 `result.csv`가 생성되었다. 제출 전에 최소한 어떤 구조를 다시 확인해야 하는가?

### 문제 3

제3유형 통계량을 코딩 화면에 정확히 출력했다. 왜 아직 제출 완료가 아닐 수 있는가?

### 문제 4

실행 결과에 Warning이 보이지만 숫자도 출력되었다. 가장 안전한 대응은 무엇인가?

## 정답과 해설

1. **정답: 공식 가이드가 체험환경에서는 저장과 이동 시 유지 기능이 제한되지만 실제 시험에서는 정상 작동한다고 별도로 설명하기 때문이다.** 체험 UI의 제약을 실제 정책으로 확대 해석하지 않는다.
2. **정답: 실제 지정 파일명, 별도 디렉터리 여부, 정확한 예측 헤더, 한 열 구조, 자동 인덱스 부재, 평가 데이터와 같은 행 수, 결측 여부를 재읽어 확인한다.** 실제 문제 지시가 최우선이다.
3. **정답: 제3유형은 문제 풀이 화면과 별도 답안 제출 화면이 분리되어 있기 때문이다.** 소문항 순서와 형식을 맞춰 입력하고 제출 상태까지 확인해야 한다.
4. **정답: Warning의 원인이 표본 제거, 형 변환, 수렴 등 결과에 영향을 주는지 확인한다.** 정상 실행과 무관함이 확인된 경우에만 넘기며 무조건 무시하지 않는다.
