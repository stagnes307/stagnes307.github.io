> **데이터 → 가공·분석 → 가치 창출 → 이를 수행하는 조직과 사람**

## 🏭 1. 데이터 산업은 무엇을 파는 산업일까?

데이터 산업(Data Industry)을 단순히 **“데이터를 파는 산업”**이라고 기억하면 범위가 너무 좁아.

핵심은 **데이터의 생산·수집·처리·분석·유통·활용 과정에서 경제적 가치를 만드는 산업**이라는 거야.

예를 들어 카드 결제 기록 자체는 그냥 데이터야. 하지만 그것을 분석해서

* 고객 소비 패턴을 찾아내고
* 고객군을 나누고
* 상품을 추천하고
* 위험 고객을 탐지한다면

데이터가 **의사결정에 사용할 수 있는 가치**로 바뀌지.

### 데이터에서 가치까지

흐름을 이렇게 기억해.

**데이터 생성 → 수집 → 저장 → 처리 → 분석 → 유통·활용 → 가치 창출**

여기서 중요한 건 데이터 산업이 어느 한 단계만을 의미하지 않는다는 거야.

---

## 🧩 2. 데이터 산업의 3가지 큰 영역

시험에서는 데이터 산업을 세 영역으로 구분하는 틀이 중요해.

| 구분                         | 핵심 질문                 | 대표 내용                  |
| -------------------------- | --------------------- | ---------------------- |
| **데이터 처리 및 관리 솔루션 개발·공급업** | 데이터를 무엇으로 처리하는가?      | DB, 데이터 관리 시스템, 분석 솔루션 |
| **데이터 구축 및 컨설팅 서비스업**      | 데이터를 어떻게 만들고 활용할 것인가? | 데이터 구축, 분석, 컨설팅        |
| **데이터 판매 및 제공 서비스업**       | 데이터를 어떻게 제공하는가?       | 데이터 판매, 정보 제공, 데이터 서비스 |

이걸 이름째 외우기보다 기능으로 먼저 구분하면 편해.

### 처리·관리 솔루션

**도구를 만드는 쪽**이야.

데이터베이스 관리 시스템, 분석 플랫폼, 데이터 처리 소프트웨어처럼 데이터가 움직이고 분석될 수 있게 만드는 기술적 기반이지.

핵심어는 **솔루션·시스템·소프트웨어**.

### 구축·컨설팅

**데이터를 만들어 쓰게 해주는 쪽**이야.

기업의 데이터를 정비하거나 데이터베이스를 구축하고, 분석 프로젝트를 수행하거나 데이터 활용 전략을 컨설팅하는 활동이 포함돼.

핵심어는 **구축·분석·컨설팅**.

### 판매·제공

이미 확보하거나 가공한 데이터를 **외부 고객에게 제공해 가치화하는 쪽**이야.

시장정보, 신용정보, 위치정보, 산업통계 같은 데이터를 판매하거나 데이터 기반 정보 서비스를 제공하는 형태를 떠올리면 돼.

핵심어는 **판매·제공·유통**.

### 시험용 구분선

헷갈릴 때 이렇게 자르면 돼.

**도구를 만든다 → 솔루션**
**기업의 데이터를 만들어주거나 활용을 돕는다 → 구축·컨설팅**
**데이터 자체나 데이터 기반 정보를 제공한다 → 판매·제공**

## 🔗 3. 데이터 산업을 ‘가치사슬’로 보면

데이터 산업의 여러 참여자는 서로 독립적으로 움직이는 게 아니라 **데이터 가치사슬(Data Value Chain)** 안에서 연결돼.

예를 들어 온라인 쇼핑몰을 생각해보자.

고객의 클릭과 구매 기록이 발생하고
→ 시스템이 데이터를 수집하고
→ 저장·정제하고
→ 분석하여 구매 성향을 추정하고
→ 추천 시스템에 적용하고
→ 결과적으로 매출이나 고객 만족도를 높여.

그래서 데이터의 가치는 원래부터 데이터 안에 들어 있는 게 아니야.

**데이터를 목적에 맞게 처리하고 활용할 때 가치가 발생한다.**

이게 빅데이터 분야에서 굉장히 중요한 관점이야.

---

## 💎 4. 왜 빅데이터 시대에는 데이터 산업이 커질까?

데이터가 많아진 것만으로는 설명이 부족해.

세 가지 변화가 같이 일어났어.

### 데이터의 폭발적 증가

온라인 서비스, 모바일 기기, SNS, 센서, IoT 등에서 데이터가 지속적으로 생성돼.

### 처리 기술의 발전

분산 저장·처리와 클라우드 같은 기술 덕분에 예전에는 감당하기 어려웠던 데이터도 처리할 수 있게 됐어.

### 데이터 기반 의사결정의 확대

기업이 경험이나 직관만으로 결정하기보다 데이터를 이용하여

**예측하고 → 비교하고 → 최적화하는 방식**

으로 이동했지.

결국 빅데이터는 단순한 IT 기술 변화가 아니라 **기업의 의사결정 방식과 산업구조를 바꾸는 변화**야.

## 🏢 5. 왜 별도의 빅데이터 조직이 필요할까?

기업에 데이터만 많다고 데이터 기업이 되는 건 아니야.

예를 들어 마케팅팀은 고객 데이터를 알고, IT팀은 시스템을 알고, 경영진은 사업목표를 알아.

그런데 이 세 영역이 연결되지 않으면 이런 일이 생겨.

**사업 문제는 있는데 분석을 못하거나,
분석 기술은 있는데 사업에 쓸 곳을 못 찾는 것.**

그래서 빅데이터 조직의 본질적인 역할은

> **비즈니스 문제와 데이터·분석 역량을 연결하는 것**

이라고 보면 돼.

## 🧱 6. 빅데이터 조직의 세 가지 구조

필기에서 특히 중요한 부분이야.

**집중형 · 기능형 · 분산형**

세 구조의 차이를 단순 암기하지 말고 **“분석 인력이 어디에 있는가?”**로 판단하면 쉬워.

| 구조      | 분석 인력 위치     | 장점            | 대표 위험     |
| ------- | ------------ | ------------- | --------- |
| **집중형** | 중앙 전문조직      | 전문성·표준화       | 현업과 거리    |
| **기능형** | 각 현업 부서      | 업무 이해도        | 중복·일관성 부족 |
| **분산형** | 중앙조직 + 현업 배치 | 전문성과 현업 이해 결합 | 조정 복잡성    |

## 🎯 7. 집중형 조직 — 전문가를 한곳에 모은다

**집중형(Centralized)**은 데이터 분석가와 데이터 사이언티스트 같은 전문 인력을 하나의 중앙 조직에 모으는 방식이야.

예를 들면 회사에 별도의 **데이터분석센터**가 있고 마케팅팀이나 생산팀에서 분석을 요청하는 구조지.

### 장점

분석 전문가가 함께 있기 때문에

* 분석기술을 공유하기 쉽고
* 분석 방법을 표준화하기 쉽고
* 전문성을 지속적으로 키우기 좋아.

### 한계

문제는 **현업과의 거리**야.

분석팀이 마케팅이나 생산 현장을 충분히 이해하지 못하면 기술적으로 멋진 분석을 했는데 실제 업무에는 별 도움이 안 될 수도 있어.

그래서 이렇게 기억하면 돼.

> **집중형 = 분석 전문성↑ / 현업 밀착성↓**

---

## 🧑‍💼 8. 기능형 조직 — 현업이 직접 분석한다

**기능형(Functional)**은 별도의 강력한 중앙 분석조직보다 각 업무 부서에서 자체적으로 분석을 수행하는 구조야.

마케팅 분석가는 마케팅부서에, 재무 분석가는 재무부서에 있는 식이지.

### 장점

현업 담당자가 분석하기 때문에 **업무에 대한 이해가 깊어.**

“우리 고객에게 지금 필요한 분석이 무엇인가?”를 빨리 알 수 있지.

### 한계

하지만 각 부서가 따로 움직이면서

* 분석 방법이 제각각이 되고
* 같은 데이터를 여러 번 만들거나
* 기술과 인력을 중복 투자하거나
* 기업 전체의 데이터 표준이 깨질 수 있어.

그래서

> **기능형 = 현업 밀착성↑ / 전사 표준화↓**

라고 잡으면 돼.

---

## 🌐 9. 분산형 조직 — 중앙과 현업을 연결한다

여기가 기능형과 가장 잘 헷갈려.

**분산형(Distributed)**에서는 분석 조직의 전문성을 유지하면서 분석 인력이 현업 부서와 밀접하게 일하도록 배치돼.

핵심은 **중앙의 전문성 + 현업의 업무지식**을 연결하려 한다는 거야.

예를 들어 중앙 데이터 조직이 분석 방법과 표준을 관리하지만 데이터 분석가는 마케팅·생산·재무 부서와 직접 협업하는 형태를 생각하면 돼.

### 시험에서 잡아야 할 차이

기능형도 현업에 분석 인력이 있고 분산형도 현업에 분석 인력이 있을 수 있어.

그러니까 **“현업에 있다”만 보고 판단하면 틀릴 수 있어.**

진짜 구분선은 이것이야.

**기능형**
→ 부서별 분석 기능이 상대적으로 독립적

**분산형**
→ 중앙의 전문 분석역량을 유지하면서 현업으로 연결·확산

그래서 분산형은 흔히

> **전문성 + 현업 밀착성의 결합**

을 노리는 구조라고 이해하면 돼.

## ⚖️ 10. 세 조직 구조를 한 장면으로 비교

회사가 “고객 이탈을 예측하라”고 한다고 해보자.

### 집중형이라면

마케팅팀이 중앙 분석팀에 문제를 전달하고 분석팀이 모델을 만들어줘.

**중앙 분석센터 → 현업 지원**

### 기능형이라면

마케팅팀 내부의 분석 담당자가 직접 문제를 해결해.

**마케팅팀 → 자체 분석**

### 분산형이라면

중앙 데이터 조직의 분석 체계와 전문성을 활용하면서 마케팅 영역에 밀착된 분석가가 문제를 해결해.

**중앙 전문성 ↔ 현업 분석**

이 세 장면을 떠올릴 수 있으면 조직 유형 문제가 상당히 쉬워져.

## 👔 11. CDO — 데이터의 방향을 책임진다

**CDO(Chief Data Officer, 최고데이터책임자)**는 기업 차원의 데이터 전략과 거버넌스를 이끄는 역할이야.

실무 분석 하나를 직접 수행하는 사람이기보다

**데이터를 기업의 자산으로 어떻게 관리하고 활용할 것인가**

를 책임지는 쪽에 가까워.

주요 관심사는

* 데이터 전략
* 데이터 거버넌스
* 데이터 품질
* 데이터 활용 문화
* 데이터 관련 조직 간 조정

이야.

---

## 🔬 12. 데이터 사이언티스트 — 데이터에서 모델과 통찰을 만든다

**데이터 사이언티스트(Data Scientist)**는 데이터를 이용해 문제를 정의하고 분석하며 예측 모델 등을 만드는 역할이야.

필요한 능력을 세 영역으로 생각하면 좋아.

### 분석·통계 역량

통계, 머신러닝, 모델링 같은 능력.

### 컴퓨팅 역량

프로그래밍과 데이터 처리 능력.

### 비즈니스 이해와 커뮤니케이션

좋은 모델을 만드는 것만으로 끝나지 않고 **분석 결과가 무엇을 의미하는지 설명하고 실제 의사결정으로 연결**해야 하니까 중요해.

그래서 데이터 사이언티스트는 단순히 “수학을 잘하는 사람”도, “코딩을 잘하는 사람”도 아니야.

**데이터 + 분석기술 + 비즈니스 문제 해결 능력**

의 결합이라고 보는 게 정확해.

---

## 🛠️ 13. 데이터 엔지니어 — 분석 가능한 데이터 환경을 만든다

**데이터 엔지니어(Data Engineer)**는 데이터가 제대로 수집·저장·처리될 수 있도록 데이터 인프라와 파이프라인을 구축해.

예를 들어 여러 시스템에서 들어오는 고객 데이터를 하나의 분석 환경으로 가져오려면

**수집 → 변환 → 저장**

과정이 안정적으로 돌아가야 하지.

이 기반을 만드는 역할이 데이터 엔지니어야.

따라서 가장 쉬운 구분은

> **데이터 엔지니어는 분석할 수 있는 환경을 만들고, 데이터 사이언티스트는 그 데이터를 이용해 모델과 통찰을 만든다.**

야.

## 📊 14. 데이터 분석가 — 비즈니스 질문을 데이터로 푼다

**데이터 분석가(Data Analyst)**는 기업의 실제 업무 질문을 데이터로 분석하는 역할에 초점이 있어.

예를 들면

* 지난달 매출이 감소한 이유
* 고객군별 구매 패턴
* 광고 캠페인의 성과
* 특정 제품의 이탈률

같은 문제를 분석하지.

데이터 사이언티스트와 경계가 완전히 고정돼 있는 것은 아니지만, 시험 공부에서는 이렇게 대비하면 편해.

| 역할         | 초점             |
| ---------- | -------------- |
| 데이터 분석가    | 현황·원인·성과 분석    |
| 데이터 사이언티스트 | 고급 분석·예측·모델링   |
| 데이터 엔지니어   | 데이터 수집·처리·인프라  |
| CDO        | 전사 데이터 전략·거버넌스 |

## 🗂️ 15. 그 밖의 주요 데이터 역할

### 데이터 아키텍트

기업의 데이터가 어떤 구조로 저장되고 연결될지를 설계해.

즉 **데이터 구조의 설계자**라고 보면 돼.

### DBA

**Database Administrator**.

데이터베이스를 설치·운영하고 성능·보안·백업 등을 관리하는 역할이야.

### 데이터 스튜어드

데이터의 의미·품질·표준 등을 관리하면서 조직의 데이터 거버넌스가 실제 현장에서 지켜지도록 돕는 역할이야.

이 역할들은 시험에서 이름과 책임 영역을 섞어서 출제하기 좋아.

## 🚨 16. 필기시험에서 특히 헷갈리는 경계

### 집중형 vs 기능형

**집중형**은 전문가가 **중앙에 모인다.**
**기능형**은 분석 기능이 **현업 부서에 들어간다.**

### 기능형 vs 분산형

둘 다 현업 가까이에서 분석할 수 있지만,

**기능형 = 부서 자체 중심**
**분산형 = 중앙 전문성을 현업과 연결**

이라는 차이가 핵심.

### 데이터 사이언티스트 vs 데이터 엔지니어

**사이언티스트 = 분석·모델링**
**엔지니어 = 데이터 파이프라인·인프라**

### 데이터 분석가 vs CDO

**분석가 = 구체적 분석 문제 해결**
**CDO = 기업 전체 데이터 전략과 관리 방향**

## 🧷 17. 시험 직전 압축 암기

딱 이것만 다시 떠올려도 좋아.

**데이터 산업 3영역**

> 솔루션 / 구축·컨설팅 / 판매·제공

**빅데이터 조직 3유형**

> 집중 / 기능 / 분산

**조직 구조의 판단 기준**

> 분석 인력이 어디에 있고, 중앙 전문조직과 현업이 어떤 관계인가?

**핵심 인력**

> CDO = 전략
> Data Scientist = 모델·분석
> Data Engineer = 데이터 기반
> Data Analyst = 업무 분석

그리고 가장 중요한 관계 하나:

> **좋은 데이터 분석은 기술만의 문제가 아니라, 데이터·조직·인력이 맞물리는 문제다.**
