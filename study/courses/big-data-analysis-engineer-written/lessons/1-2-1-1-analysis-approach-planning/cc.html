🗺️ ① 분석 로드맵 설정

먼저 전체 길을 그린다

로드맵은 특정 알고리즘을 고르는 단계가 아니야. 분석 활동 전체를 바라보면서 어떤 분석을 어느 순서로 추진할 것인지 큰 경로를 설계하는 것에 가깝다.

예를 들어 어떤 쇼핑몰이 고객 이탈 문제를 해결하려고 한다고 해보자. 바로 머신러닝 모델부터 고르는 게 아니라, 현황 파악 → 이탈 원인 분석 → 이탈 예측 → 현업 적용 처럼 분석 활동을 단계화할 수 있어.

단계화가 필요한 이유

기업에는 분석하고 싶은 문제가 하나만 있는 게 아니야. 매출 예측도 하고 싶고, 고객 이탈도 알고 싶고, 추천 시스템도 만들고 싶을 수 있지.

그런데 데이터와 인력, 예산은 제한되어 있으니까 어떤 분석을 먼저 하고 어떤 분석을 이후에 할지 정해야 한다.

그래서 로드맵에서는 주로 분석의 단계, 추진 순서, 우선순위, 일정, 필요한 자원과 결과 활용 방향을 생각하게 돼.

시험 신호

우선순위

일정
추진 순서

“회귀분석을 적용한다”, “의사결정나무를 사용한다”는 로드맵보다 구체적인 분석 방안에 더 가깝다.

🎯 ② 분석 문제 정의

현업의 고민을 분석 가능한 질문으로 바꾼다

로드맵이 길을 정했다면 이제 정확히 무엇을 풀 것인가를 결정해야 해. 여기서 가장 중요한 구분은 비즈니스 문제와 분석 문제는 같지 않다는 거야.

비즈니스 문제

“요즘 고객들이 자꾸 떠나요.”

현상은 보이지만 분석 대상과 목표가 아직 모호함

분석 문제

최근 고객 행동 데이터를 이용해 향후 일정 기간 내 이탈 가능성이 높은 고객을 예측하고, 이탈에 영향을 미치는 주요 요인을 파악한다.

즉, 막연한 현상 → 분석 가능한 질문으로 바꾸는 과정이 분석 문제 정의의 핵심이야.

좋은 문제 정의에는 경계가 있다

“고객을 분석한다”는 너무 넓어. 반면 누구를 대상으로 하는지, 무엇을 알고 싶은지, 어떤 범위에서 볼 것인지, 어떤 결과를 얻어야 하는지가 명확하면 분석 문제도 명확해져.

분석 질문 분석 목적
어떤 고객이 구매를 많이 하는가? 고객 특성 파악
고객은 왜 이탈하는가? 원인·영향요인 파악
어떤 고객이 다음 달 이탈할 것인가? 예측
어떤 상품을 추천해야 구매할 가능성이 높은가? 추천·의사결정
중요 관계: 문제 정의 → 필요한 데이터 결정 → 적합한 분석 방법 결정

🧪 ③ 데이터 분석 방안

이제 실제 해법을 설계한다

분석 문제가 명확해졌다면 그다음부터는 어떻게 분석할 것인지 결정할 수 있어. 여기서 단순히 “머신러닝을 사용한다”라고 끝내면 부족해.

데이터

무엇을 사용할 것인가

구매 횟수, 최근 구매일, 방문 빈도, 이용 기간, 문의·불만 기록 등 문제 해결에 필요한 데이터를 판단한다.

존재 여부 · 확보 가능성 · 품질 확인

방법

어떤 분석을 사용할 것인가

현황은 기술통계·시각화, 집단 구분은 군집분석, 미래 예측은 회귀·분류 등 목적에 맞는 방법을 고려한다.

기법이 먼저가 아니라 문제가 먼저

평가·활용

결과를 어떻게 판단할 것인가

결과가 충분히 정확하고 유용한지 평가하고, 실제 업무의 어떤 의사결정에 사용할지도 연결한다.

분석 결과 ≠ 프로젝트 종료

실행 구조

데이터 확보 → 데이터 처리 → 분석 수행 → 결과 평가 → 활용

🔗 하나의 사례로 연결

배달 지연을 줄인다면?

1 · 분석 로드맵 설정

배달 지연 현황 파악 → 지연 원인 분석 → 지연 가능성 예측 → 운영 시스템 적용

핵심은 특정 알고리즘이 아니라 전체 분석 프로젝트의 진행 순서.

2 · 분석 문제 정의

주문 시점의 여러 정보를 이용하여 배달 지연 발생 여부를 예측하고 주요 지연 요인을 파악한다.

“배달이 늦다”라는 현업 문제가 분석 가능한 질문으로 구체화됨.

3 · 데이터 분석 방안

주문시간, 거리, 음식점 준비시간, 기사 배차시간 등을 확보·전처리하고, 지연 여부를 예측할 수 있는 분석 방법을 적용한 뒤 성능을 평가한다.

필요하면 예측 결과를 실제 배차나 고객 안내에 활용.

전체 구조

“배달 지연을 줄이자” → 로드맵: 어떤 단계로 추진하지? → 문제 정의: 정확히 무엇을 알아내야 하지? → 분석 방안: 어떤 데이터와 방법으로 알아내지?

⚠️ 필기에서 잘 꼬이는 경계

비슷해 보여도 역할은 다르다

로드맵 ≠ 분석기법 선정

로드맵은 전체 추진 경로가 중심이고, 회귀·군집·의사결정나무 같은 구체적 기법 선정은 분석 방안에 더 가깝다.

문제 현상 ≠ 분석 문제 정의

“매출이 감소했다”는 현상이고, “지역·상품군별 매출 감소 요인을 파악한다”처럼 구체화되어야 분석 문제에 가까워진다.

분석 방안 ≠ 알고리즘 하나

분석 방안은 필요한 데이터, 처리 과정, 분석 방법, 평가와 활용까지 연결해서 본다.
