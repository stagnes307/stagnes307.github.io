# 🧭 [순서 → 질문 → 해법] 1-2-1-1. 분석방안 수립의 전체 흐름

#빅데이터분석기사 #필기 #데이터분석계획 #분석방안수립 #분석로드맵 #분석문제정의

---

## 🎯 전체 그림 — 세 단계는 각각 다른 질문에 답해

분석방안 수립은 크게 **분석 로드맵 설정 → 분석 문제 정의 → 데이터 분석 방안 구체화**로 연결해서 이해하면 돼.

| 단계            | 핵심 질문                      | 핵심어                 |
| ------------- | -------------------------- | ------------------- |
| **분석 로드맵 설정** | 분석을 **어떤 순서와 단계**로 추진할까?   | 단계, 우선순위, 일정, 추진 방향 |
| **분석 문제 정의**  | 우리가 실제로 **무엇을 분석해야** 할까?   | 문제, 목표, 대상, 범위, 지표  |
| **데이터 분석 방안** | 그 문제를 **어떤 데이터와 방법으로** 풀까? | 데이터, 분석기법, 절차, 검증   |

시험에서는 이 셋을 섞어서 선지로 내기 좋아. 그래서 이름보다 **역할의 차이**를 잡는 게 중요해.

**로드맵 = 순서 / 문제 정의 = 질문 / 분석 방안 = 해법**

이렇게 **“순-문-해”**로 기억해두자.

---

## 🗺️ ① 분석 로드맵 설정 — 먼저 전체 길을 그린다

로드맵은 특정 알고리즘을 고르는 단계가 아니야. 분석 활동 전체를 바라보면서 **어떤 분석을 어느 순서로 추진할 것인지 큰 경로를 설계하는 것**에 가깝다.

예를 들어 어떤 쇼핑몰이 고객 이탈 문제를 해결하려고 한다고 해보자. 바로 머신러닝 모델부터 고르는 게 아니라,

**현황 파악 → 이탈 원인 분석 → 이탈 예측 → 현업 적용**

처럼 분석 활동을 단계화할 수 있어.

### 단계화가 필요한 이유

기업에는 분석하고 싶은 문제가 하나만 있는 게 아니야. 매출 예측도 하고 싶고, 고객 이탈도 알고 싶고, 추천 시스템도 만들고 싶을 수 있지.

그런데 데이터와 인력, 예산은 제한되어 있으니까 **어떤 분석을 먼저 하고 어떤 분석을 이후에 할지** 정해야 한다.

그래서 로드맵에서는 주로 **분석의 단계, 추진 순서, 우선순위, 일정, 필요한 자원과 결과 활용 방향**을 생각하게 돼.

### 시험에서 잡아야 할 신호

선지에 **단계적 추진, 우선순위, 중장기 계획, 일정, 추진 순서** 같은 표현이 강하게 보이면 분석 로드맵과 연결할 가능성이 높아.

반대로 “의사결정나무를 사용한다”, “회귀분석을 적용한다” 같은 말은 로드맵의 핵심이 아니야. 그건 뒤의 **구체적인 분석 방안**에 더 가깝지.

---

## 🎯 ② 분석 문제 정의 — 현업의 고민을 분석 가능한 질문으로 바꾼다

로드맵이 길을 정했다면 이제 **정확히 무엇을 풀 것인가**를 결정해야 해.

여기서 가장 중요한 구분은 **비즈니스 문제와 분석 문제는 같지 않다**는 거야.

### 비즈니스 문제와 분석 문제

쇼핑몰 담당자가 이렇게 말한다고 해보자.

> “요즘 고객들이 자꾸 떠나요.”

이건 현업에서 인식한 **비즈니스 문제**야. 하지만 이것만으로는 어떤 분석을 해야 하는지가 명확하지 않아.

분석 문제로 바꾸면 훨씬 구체적으로 만들 수 있어.

> 최근 고객 행동 데이터를 이용해 **향후 일정 기간 내 이탈 가능성이 높은 고객을 예측하고, 이탈에 영향을 미치는 주요 요인을 파악한다.**

이제 분석의 대상과 목적이 보이지?

즉,

**막연한 현상 → 분석 가능한 질문**

으로 바꾸는 과정이 분석 문제 정의의 핵심이야.

## 🔍 좋은 문제 정의에는 경계가 있다

“고객을 분석한다”는 너무 넓어.

반면,

**누구를 대상으로 하는지**,
**무엇을 알고 싶은지**,
**어떤 범위에서 볼 것인지**,
**어떤 결과를 얻어야 하는지**

가 명확하면 분석 문제도 명확해져.

예를 들어 같은 고객 데이터라도 질문에 따라 분석 방향은 완전히 달라져.

| 분석 질문                     | 분석 목적      |
| ------------------------- | ---------- |
| 어떤 고객이 구매를 많이 하는가?        | 고객 특성 파악   |
| 고객은 왜 이탈하는가?              | 원인·영향요인 파악 |
| 어떤 고객이 다음 달 이탈할 것인가?      | 예측         |
| 어떤 상품을 추천해야 구매할 가능성이 높은가? | 추천·의사결정    |

그래서 **문제 정의가 달라지면 필요한 데이터와 분석기법도 달라진다.**

이 관계가 아주 중요해.

**문제 정의 → 필요한 데이터 결정 → 적합한 분석 방법 결정**

---

## 🧪 ③ 데이터 분석 방안 — 이제 실제 해법을 설계한다

분석 문제가 명확해졌다면 그다음부터는 **어떻게 분석할 것인지** 결정할 수 있어.

여기서 단순히 “머신러닝을 사용한다”라고 끝내면 부족해.

분석 방안에는 적어도 세 가지 관점이 들어가.

### 데이터는 무엇을 사용할 것인가

분석 문제를 해결하는 데 어떤 데이터가 필요한지를 판단해야 해.

고객 이탈 예측이라면 고객의 기본 정보만 보는 것보다 구매 횟수, 최근 구매일, 방문 빈도, 이용 기간, 문의·불만 기록 같은 행동 데이터가 더 중요할 수도 있어.

그리고 필요한 데이터가 존재하는지, 확보 가능한지, 품질은 괜찮은지도 확인해야 하지.

### 어떤 분석 방법을 사용할 것인가

분석 목적과 문제 유형에 맞는 방법을 골라야 해.

현황을 알고 싶다면 기술통계나 시각화가 적합할 수 있고, 집단을 나누고 싶다면 군집분석, 미래 값을 예측하려면 회귀나 분류 같은 방법을 고려할 수 있어.

중요한 건 **기법이 먼저가 아니라 문제가 먼저**라는 거야.

“딥러닝을 써보고 싶으니까 분석 문제를 찾는다”가 아니라,

**분석 문제 → 필요한 데이터 → 적절한 방법**

순서로 생각해야 해.

### 결과를 어떻게 판단하고 활용할 것인가

분석 결과가 나왔다고 프로젝트가 끝나는 것도 아니야.

분석 결과가 충분히 정확하고 유용한지 평가해야 하고, 실제 업무에서 어떤 의사결정에 사용할지도 연결해야 해.

그래서 분석방안은 결국

**데이터 확보 → 데이터 처리 → 분석 수행 → 결과 평가 → 활용**

이라는 실행 구조까지 생각하는 단계라고 이해하면 좋아.

## 🔗 세 단계를 하나의 사례로 연결해보자

배달 플랫폼에서 **배달 지연을 줄이고 싶다**고 해보자.

### 분석 로드맵 설정

먼저 전체 추진 순서를 잡는다.

**배달 지연 현황 파악 → 지연 원인 분석 → 지연 가능성 예측 → 운영 시스템 적용**

여기서는 아직 특정 알고리즘이 핵심이 아니야. **전체 분석 프로젝트의 진행 순서**가 핵심이지.

### 분석 문제 정의

“배달이 늦다”라는 현업 문제를 분석 가능한 문제로 바꾼다.

**주문 시점의 여러 정보를 이용하여 배달 지연 발생 여부를 예측하고 주요 지연 요인을 파악한다.**

이제 무엇을 분석할지가 명확해졌어.

### 데이터 분석 방안

그러면 필요한 데이터와 방법을 결정할 수 있다.

주문시간, 거리, 음식점 준비시간, 기사 배차시간 등 필요한 데이터를 확보하고 전처리한 뒤, 지연 여부를 예측할 수 있는 분석 방법을 적용하고 결과의 성능을 평가한다.

마지막에는 예측 결과를 실제 배차나 고객 안내에 활용할 수도 있겠지.

전체 구조를 압축하면 이거야.

**“배달 지연을 줄이자”**
→ **로드맵:** 어떤 단계로 추진하지?
→ **문제 정의:** 정확히 무엇을 알아내야 하지?
→ **분석 방안:** 어떤 데이터와 방법으로 알아내지?

---

## ⚠️ 필기에서 잘 꼬이는 세 가지 경계

### 로드맵 ≠ 분석기법 선정

로드맵은 **전체 추진 경로**가 중심이야.

회귀분석, 군집분석, 의사결정나무 같은 구체적인 기법 선정은 분석 방안 쪽에 더 가깝다.

### 문제 현상 ≠ 분석 문제 정의

“매출이 감소했다”는 현상 또는 비즈니스 문제야.

“지역·상품군별 매출 감소 요인을 파악한다” 정도로 구체화되어야 분석 가능한 문제에 가까워진다.

### 분석 방안 ≠ 알고리즘 하나 고르기

분석 방안은 알고리즘뿐 아니라 **필요한 데이터, 처리 과정, 분석 방법, 평가와 활용**까지 연결해서 보는 게 좋아.

## 🧠 시험장에서 바로 쓰는 키워드 판별법

문제를 읽다가 무엇을 묻는지 헷갈리면 특정 단어를 잡아.

| 선지에서 강조되는 표현              | 가장 먼저 연결      |
| ------------------------- | ------------- |
| 단계, 순서, 우선순위, 일정, 중장기 추진  | **분석 로드맵 설정** |
| 목표, 문제, 대상, 범위, 분석 질문     | **분석 문제 정의**  |
| 데이터 확보, 전처리, 분석기법, 모델, 검증 | **데이터 분석 방안** |

그래서 선지를 볼 때 머릿속에서 이렇게 번역하면 돼.

**“언제·어떤 순서?” → 로드맵**
**“정확히 뭘 풀지?” → 문제 정의**
**“무엇으로 어떻게?” → 분석 방안**

## 🧩 마지막으로 구조를 한 줄에 묶기

분석방안 수립의 핵심 논리는 결국 **추상적인 기업의 요구를 구체적인 데이터 분석 실행계획으로 내려오는 과정**이야.

**기업의 요구**
→ **분석 로드맵 설정** : 분석의 큰 경로와 추진 순서
→ **분석 문제 정의** : 해결해야 할 분석 질문 구체화
→ **데이터 분석 방안** : 데이터·기법·절차·평가 방법 설계
→ **실제 분석 수행**

여기까지 연결되면 세 용어를 따로 암기하지 않아도 선지를 상당히 잘 분리할 수 있어.
