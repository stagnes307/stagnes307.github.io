# 🧭 [데이터가 있어야 분석도 움직인다] 1-2-2-1. 데이터 확보와 분석 작업 계획

#빅데이터분석기사 #필기 #데이터분석계획 #데이터확보계획 #분석작업계획

---

## 🎯 먼저 구조부터: 이 단원은 무엇을 계획하는가

분석을 시작한다고 바로 모델을 만드는 건 아니야. 먼저 두 가지를 결정해야 해.

> **데이터 확보 계획 = 분석에 필요한 입력을 어떻게 준비할 것인가**
> **분석 절차 및 작업 계획 = 그 데이터를 가지고 누가, 언제, 어떤 순서로 분석할 것인가**

둘의 관계를 한 줄로 잡으면 이래.

**분석 목표 → 필요한 데이터 결정 → 데이터 확보 → 분석 작업 수행 → 결과 산출**

즉, 데이터 확보 계획이 **재료 준비 계획**이라면, 분석 작업 계획은 **조리 순서와 일정표**에 가까워.

---

## 📦 1. 데이터 확보 계획

### 필요한 데이터부터 정한다

출발점은 항상 **분석 목적**이야.

예를 들어 목표가 `고객 이탈 가능성 예측`이라면 단순히 “고객 데이터가 필요하다”로는 부족해.

고객별로 다음과 같은 데이터가 필요할 수 있지.

* 고객 기본정보
* 가입기간
* 서비스 사용량
* 결제정보
* 상담·불만 기록
* 과거 이탈 여부

핵심 관계는 이거야.

**분석 목적이 달라지면 필요한 데이터도 달라진다.**

그래서 데이터 확보 계획의 첫 단계는 데이터를 닥치는 대로 모으는 게 아니라 **분석에 필요한 데이터가 무엇인지 정의하는 것**이야.

### 데이터의 출처를 확인한다

필요한 데이터를 정했으면 **어디에서 얻을 수 있는지** 찾는다.

| 구분     | 예                          |
| ------ | -------------------------- |
| 내부 데이터 | 기업 DB, 거래 기록, 로그, CRM, ERP |
| 외부 데이터 | 공공데이터, 통계자료, 외부기관 데이터      |
| 생성 데이터 | 설문조사, 실험, 센서 측정 등          |

여기서 시험에서 자주 섞이는 게 하나 있어.

**데이터 출처**와 **데이터 수집 방법**은 같은 말이 아니야.

* 출처: **어디에 있는가**
* 수집 방법: **어떻게 가져오는가**

예를 들어 공공기관 데이터가 **출처**이고, API 호출은 그 데이터를 가져오는 **방법**이 될 수 있어.

### 🔍 실제 확보 가능성을 검토한다

“필요하다”와 “확보할 수 있다”도 다르지.

그래서 다음 조건들을 같이 확인해야 해.

#### 접근 가능성

권한이 있는지, 시스템에서 추출할 수 있는지 확인한다.

#### 비용과 시간

외부 데이터를 구매해야 할 수도 있고, 데이터를 수집하는 데 시간이 오래 걸릴 수도 있어.

#### 데이터 품질

분석에 사용할 만큼 데이터가 제대로 갖춰져 있는지도 본다.

대표적으로 확인하는 요소는:

* 정확성
* 완전성
* 일관성
* 최신성·적시성

데이터가 많다고 항상 좋은 건 아니야. **분석 목적에 맞고 신뢰할 수 있는 데이터인지**가 더 중요해.

#### 법적·보안 제약

특히 개인정보가 포함되어 있다면 사용 가능 범위를 반드시 고려해야 해.

* 개인정보 보호
* 데이터 사용 권한
* 보안 정책
* 외부 데이터의 이용 조건

따라서 분석에 유용한 데이터라도 **법적으로 사용할 수 없다면 확보 대상으로 삼을 수 없어.**

## 🗂️ 데이터 확보 계획을 한 덩어리로 묶기

시험에서는 다음 구조로 기억하면 꽤 안정적이야.

**필요 데이터 → 출처 → 확보 방법 → 품질 → 제약 → 저장·관리**

| 계획 요소  | 확인할 내용                  |
| ------ | ----------------------- |
| 필요 데이터 | 분석 목적에 어떤 데이터가 필요한가     |
| 데이터 출처 | 내부·외부 어디에 존재하는가         |
| 확보 방법  | DB 추출, API, 파일 수집, 조사 등 |
| 품질     | 분석에 사용할 수준인가            |
| 비용·기간  | 현실적으로 확보 가능한가           |
| 법·보안   | 개인정보·권한 문제가 없는가         |
| 저장·관리  | 확보한 데이터를 어떻게 관리할 것인가    |

### 기억할 핵심

**데이터 확보 계획은 단순한 ‘데이터 수집 계획’보다 넓다.**

데이터를 어디서 가져올지만 정하는 것이 아니라 **필요성·가능성·품질·비용·보안까지 검토하는 계획**이라고 이해하면 돼.

## ⚙️ 2. 분석 절차 및 작업 계획

데이터 확보 방법을 정했다면 이제 분석 프로젝트를 실제 작업으로 바꿔야 해.

여기서는 **절차**와 **작업 계획**을 구별하는 게 중요해.

### 분석 절차 = 무엇을 어떤 순서로 하는가

일반적인 흐름은 다음처럼 이해할 수 있어.

**분석 목표 확인
↓
데이터 확보
↓
데이터 전처리
↓
탐색 및 분석
↓
모델링
↓
평가·검증
↓
결과 해석 및 보고**

프로젝트 성격에 따라 세부 단계는 달라질 수 있지만 핵심은 **앞뒤 작업의 논리적 순서**를 정하는 거야.

특히 중요한 관계가 있어.

> 앞 단계의 산출물이 다음 단계의 입력이 된다.

예를 들어 원천 데이터가 확보되어야 전처리를 할 수 있고, 전처리가 끝나야 신뢰할 수 있는 모델링을 진행할 수 있지.

---

## 🛠️ 작업 계획 = 절차를 실제 업무로 구체화한다

“데이터를 전처리한다”는 건 분석 절차야.

그런데 프로젝트를 실행하려면 훨씬 구체적으로 정해야 하지.

* 누가 하는가
* 언제 시작하는가
* 언제 끝나는가
* 어떤 자원이 필요한가
* 앞뒤 작업은 무엇인가
* 어떤 결과물을 만들어야 하는가

즉,

**절차 = WHAT + ORDER**
**작업 계획 = WHO + WHEN + HOW + OUTPUT**

라고 잡으면 구분이 잘 돼.

### 작업을 세분화한다

큰 업무를 관리 가능한 작은 작업으로 나눈다.

예를 들어 `데이터 준비`라는 하나의 큰 작업도 실제로는:

**데이터 추출 → 데이터 결합 → 결측치 확인 → 이상치 처리 → 변수 변환**

처럼 쪼갤 수 있어.

이렇게 프로젝트의 작업을 계층적으로 분해하는 사고가 **WBS(Work Breakdown Structure, 작업분해구조)**와 연결돼.

WBS의 핵심은 어려운 용어가 아니야.

> **큰 프로젝트를 관리 가능한 작은 작업 단위로 분해하는 것**

이라고 기억해.

---

## 📅 일정과 선후관계를 계획한다

작업을 나눴으면 무작정 동시에 진행할 수 있는지 확인해야 해.

예를 들어:

`데이터 확보`가 끝나지 않았는데 `모델 검증`부터 할 수는 없겠지.

그래서 분석 작업 계획에서는 다음을 고려한다.

* 작업 시작·종료 시점
* 예상 소요시간
* 작업 간 선후관계
* 병렬 수행 가능 여부
* 주요 완료 시점
* 인력과 자원

여기서 **마일스톤(Milestone)**이라는 개념도 알아두면 좋아.

마일스톤은 프로젝트에서 의미 있는 **중요 완료 시점이나 이정표**를 뜻해.

예를 들면:

* 데이터 확보 완료
* 전처리 완료
* 모델 후보 선정 완료
* 최종 분석 완료

---

## 📄 산출물을 명확히 한다

작업이 끝났다는 걸 무엇으로 판단할지도 정해야 해.

이때 등장하는 게 **산출물(Deliverable)**이야.

예를 들어:

| 작업     | 산출물 예    |
| ------ | -------- |
| 데이터 확보 | 원천 데이터셋  |
| 데이터 정제 | 정제 데이터셋  |
| 탐색 분석  | EDA 결과   |
| 모델링    | 분석 모델    |
| 평가     | 성능 평가 결과 |
| 최종 분석  | 분석 보고서   |

여기서 구분 하나.

**마일스톤은 시점**,
**산출물은 만들어진 결과물**이야.

둘을 같은 것으로 보면 헷갈려.

---

## 🧠 실제 프로젝트 하나로 연결해보자

### 고객 이탈 예측 프로젝트

분석 목표가 **“다음 달 이탈 가능성이 높은 고객을 찾아내는 것”**이라고 해보자.

### 데이터 확보

먼저 분석에 필요한 데이터를 정한다.

**고객정보 + 이용기록 + 결제정보 + 상담정보 + 과거 이탈 여부**

그다음:

`사내 CRM·결제 DB에서 확보 → 접근 권한 확인 → 품질 점검 → 개인정보 처리 기준 확인`

까지 계획한다.

여기까지가 주로 **데이터 확보 계획**이야.

### 분석 작업

확보가 가능하다는 판단이 섰다면 다음처럼 진행할 수 있어.

**① 데이터 추출
→ ② 데이터 결합
→ ③ 결측치·이상치 처리
→ ④ 이탈 관련 특성 탐색
→ ⑤ 예측 모델 생성
→ ⑥ 모델 평가
→ ⑦ 결과 해석 및 보고**

그리고 각각에 담당자, 기간, 필요한 자원, 산출물을 붙이면 **분석 작업 계획**이 된다.

즉, 같은 프로젝트에서도 두 계획의 역할이 분명히 달라.

---

## ⚠️ 필기에서 잘 섞이는 경계

### 데이터 확보 vs 데이터 전처리

**확보**는 필요한 데이터를 사용할 수 있도록 가져오는 단계이고,
**전처리**는 확보한 데이터를 분석에 적합한 형태로 바꾸는 단계야.

`데이터를 DB에서 추출한다` → 확보
`추출한 데이터의 결측치를 처리한다` → 전처리

### 분석 절차 vs 일정 계획

**분석 절차**는 작업의 논리적인 진행 순서.

**일정 계획**은 각 작업을 언제 수행할지를 정하는 것.

### 데이터 품질 vs 데이터 보안

품질은 **분석에 쓸 만한 데이터인가**를 본다.

보안은 **그 데이터를 적절한 권한과 방식으로 다루고 있는가**를 본다.

### 마일스톤 vs 산출물

**마일스톤** → 중요한 완료 지점
**산출물** → 실제 만들어지는 결과

이 네 쌍은 따로 구별해서 기억하는 게 좋아.

## 🧩 전체 구조를 하나의 그림으로 압축하면

```text
[분석 목표]
     │
     ▼
[필요 데이터 정의]
     │
     ▼
[출처·확보 방법 결정]
     │
     ├─ 품질
     ├─ 비용·기간
     ├─ 접근 권한
     └─ 법·보안
     │
     ▼
[데이터 확보]
     │
     ▼
[분석 작업 세분화]
     │
     ├─ 순서
     ├─ 담당자
     ├─ 일정
     ├─ 자원
     ├─ 선후관계
     └─ 산출물
     │
     ▼
[분석 수행 및 결과]
```

이 그림의 위쪽이 주로 **데이터 확보 계획**, 아래쪽이 **분석 절차 및 작업 계획**이야.

## 🔑 필기용 핵심 문장

이 단원은 아래 네 문장을 확실히 잡아두면 뼈대가 생겨.

**① 데이터 확보 계획은 분석 목적에 필요한 데이터를 정의하고, 출처·확보 방법·품질·비용·법적 제약 등을 검토하는 것이다.**

**② 분석 절차는 분석 업무의 논리적인 수행 순서를 정하는 것이다.**

**③ 분석 작업 계획은 분석 업무를 세분화하고 담당자·일정·자원·선후관계·산출물 등을 구체화하는 것이다.**

**④ 데이터 확보 계획과 분석 작업 계획은 서로 독립적인 것이 아니라, 확보 가능한 데이터를 기준으로 실제 분석 일정과 업무가 설계되는 연결 관계다.**

특히 시험장에서 가장 빠르게 떠올릴 문장은:

> **확보 계획 = 어떤 데이터를 어떻게 준비할까?**
> **작업 계획 = 준비한 데이터로 누가 언제 무엇을 할까?**

이 정도로 압축하면 돼.
