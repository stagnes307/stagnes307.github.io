데이터 수집 대상 파악

데이터 수집 대상 파악은 분석 목적에 필요한 데이터가 무엇인지 정하고, 그 데이터의 유형과 속성을 확인하는 단계야.

데이터를 많이 모으는 게 중요한 게 아니야. 분석 목적에 맞는 데이터를 제대로 모으는 것이 중요해. 예를 들어 쇼핑몰이 “고객 이탈 원인을 분석하겠다”고 하면 고객 정보, 구매 이력, 접속 이력, 문의·불만 기록, 최근 방문 시점처럼 이탈과 관련 있을 가능성이 있는 데이터를 먼저 특정해야 해.

📥 1. 데이터 수집은 무엇을 하는 과정인가?

데이터 수집(Data Collection)은 분석에 필요한 데이터를 여러 원천에서 확보하는 과정이야. 여기서 시험에서 중요한 건 “어디서 얻느냐”와 “어떤 형태로 얻느냐”를 구분하는 것이야.

데이터 데이터 원천 예시
고객 회원정보내부고객 DB
구매이력내부주문·결제 시스템
웹 행동정보내부웹 로그
날씨외부공공데이터
SNS 반응외부SNS·웹
경제지표외부정부·공공기관

내부 데이터

조직 내부의 업무 과정에서 생성되는 데이터야. 대표적으로 ERP, CRM, 거래 데이터, 고객 데이터, 생산 데이터, 웹·시스템 로그가 있어.

이미 조직 안에 있어 접근하기 쉽지만 부서별 형식 차이와 데이터 분산 문제가 생길 수 있어.

외부 데이터

조직 밖에서 확보하는 데이터야. 공공데이터, 통계자료, SNS, 뉴스·웹, 제휴기관 데이터, 구매한 상용 데이터 등이 여기에 들어가.

신뢰성, 저작권·개인정보, 실제 수집 가능 여부를 함께 고려해야 해.

💡 시험에서 이렇게 구별해

내부/외부는 데이터가 어디에서 왔는가에 대한 분류야. 반면 정형/반정형/비정형은 데이터가 어떤 구조를 가지고 있는가에 대한 분류야. 둘을 섞으면 안 돼.

🧩 2. 데이터 유형을 파악한다는 것은?

빅데이터에서 가장 기본적인 데이터 유형 분류는 정형·반정형·비정형 세 가지야.

정형

Structured Data

정해진 구조와 스키마를 가진 데이터야. 행과 열 형태의 테이블을 떠올리면 가장 쉬워.

고객번호나이구매금액
C00129120000
C0023485000

핵심: 고정된 구조 · 스키마 · 테이블

반정형

Semi-structured Data

완전히 고정된 테이블 구조는 아니지만 데이터 내부에 구조를 설명하는 요소가 포함된 데이터야. 

{
  "name": "Ailey",
  "age": 25
}

name, age처럼 구조를 식별할 수 있는 정보가 있어.

대표 예: XML · JSON · HTML · 웹 로그

비정형

Unstructured Data

미리 정해진 구조가 거의 없는 데이터야.

📝 텍스트
🖼️ 이미지
🎙️ 음성
🎬 동영상

고객 상담 녹음처럼 바로 테이블 값으로 해석하기 어려워 추가 처리나 특징 추출이 필요할 수 있어.

구분 구조 대표 예
정형고정된 스키마 존재RDB, 거래 DB
반정형고정 스키마는 약하지만 구조 식별 가능XML, JSON, HTML, 로그
비정형사전에 정의된 구조가 거의 없음텍스트, 이미지, 음성, 영상

외울 때는 이렇게 압축해.

정형
→ 표
반정형
→ 태그·키가 있는 유연한 구조
비정형
→ 문서·미디어

특히 XML과 JSON을 비정형 데이터로 착각하지 않는 것. 둘은 대표적인 반정형 데이터야.

🧬 3. ‘데이터 속성’을 왜 파악해야 할까?

데이터가 있다고 바로 분석할 수 있는 건 아니야. 같은 데이터셋 안에서도 각 변수의 의미와 사용할 수 있는 연산이 달라.

변수값의 예
고객IDC1024
성별남/여
등급일반/실버/골드/VIP
나이32
구매금액153000
가입일2026-04-15

고객ID = C1024는 식별값이라 계산하는 대상이 아니지만, 구매금액은 평균이나 합계를 계산할 수 있지. 그래서 수집 단계에서 데이터의 속성과 특성을 확인해야 해.

📊 데이터의 측정척도로 속성을 이해하기

필기시험에서는 데이터 속성을 이해할 때 명목·서열·등간·비율척도가 연결되는 경우가 많아.

명목척도 Nominal Scale

단순히 분류하기 위한 값이야.

예: 성별 · 혈액형 · 지역 · 상품 종류

서울=1, 부산=2, 대구=3처럼 숫자로 코딩해도 대구 > 부산 > 서울이라는 뜻은 아니야.

서열척도 Ordinal Scale

순서는 존재하지만 간격의 크기는 정확하게 의미하지 않는 데이터야.

예: 일반 < 실버 < 골드 < VIP

VIP가 골드보다 높은 건 알지만 VIP-골드의 차이와 골드-실버의 차이가 같다고 말할 수는 없어.

등간척도 Interval Scale

순서와 간격에 의미가 있지만 절대적인 0이 없는 척도야.

예: 섭씨온도 · 화씨온도

10℃와 20℃의 차이는 10℃지만 20℃가 10℃보다 두 배 뜨겁다고 할 수는 없어.

비율척도 Ratio Scale

순서, 간격, 비율에 모두 의미가 있고 절대적인 0이 존재해.

예: 길이 · 무게 · 나이 · 매출액 · 소득 · 구매금액

구매금액 20만 원은 10만 원의 두 배라고 할 수 있어.

🧠 네 척도를 하나의 관계로 묶기

단순 암기보다 기능이 하나씩 추가된다고 이해하면 좋아.

명목 → 서열 → 등간 → 비율로 갈수록 사용할 수 있는 정보가 많아져.

🏗️ 4. 실제 수집 대상을 파악할 때 보는 것

“필요한 데이터가 고객 데이터입니다”에서 끝내면 아직 부족해. 수집 계획을 세우려면 적어도 다음 관계를 함께 봐야 해.

무엇을 수집하는가

분석 목적에 필요한 데이터 항목을 정해.

고객 이탈 분석이라면 고객 식별정보, 이용기간, 최근 이용일, 구매빈도, 구매금액, 불만 접수 여부 등이 될 수 있어.

어디에서 수집하는가

데이터의 출처 또는 원천을 파악해.

내부 DB · 웹 서버 · 센서 · 외부기관 · 공공데이터 · SNS·웹

어떤 형태인가

데이터 유형을 확인해.

정형 · 반정형 · 비정형

어떤 속성을 갖는가

각 변수의 데이터 형식, 의미, 단위, 범위, 척도, 결측 가능성 등을 확인해.

예: age는 고객 나이를 의미하고 숫자형이며 단위는 년이고 음수라면 비정상으로 볼 수 있다.

🔄 5. 왜 이 내용이 ‘데이터 전환’까지 이어질까?

여기가 1-3-1 데이터 수집 및 전환이라는 상위 단원과 연결되는 지점이야. 데이터 유형을 파악해야 어떻게 변환해서 분석 시스템에 넣을지 결정할 수 있어.

관계형 DB

→ SQL 등을 이용해 추출하기 쉬움

JSON / XML

→ 필요한 필드를 파싱하여 구조화

텍스트

→ 전처리와 자연어 처리가 필요할 수 있음

이미지·음성

→ 분석 가능한 특징이나 표현으로 변환할 수 있음

대상 파악 → 유형·속성 파악 → 적절한 수집 → 필요한 전환 → 저장

⚠️ 필기에서 흔히 걸리는 구분

XML·JSON

반정형 데이터. “행과 열이 아니니까 비정형”이라고 판단하면 틀리기 쉬워.

데이터 출처와 데이터 유형

서로 다른 분류야. 내부/외부 → 출처, 정형/반정형/비정형 → 구조. 외부에서 받은 JSON이라면 외부 데이터이면서 반정형 데이터야.

숫자로 표현된 값

숫자라고 모두 연속형·비율척도인 건 아니야. 고객번호 = 1001은 숫자처럼 보여도 고객을 식별하는 범주형 식별자일 수 있어.

서열과 등간

서열척도는 순서만 확실해. 등간척도는 간격까지 의미가 있어.

🧭 지금 반드시 잡아야 할 연결

단순히 “JSON = 반정형”을 외우는 데서 끝나면 약해.

데이터의 구조와 속성을 알아야 수집·전환·저장 방법을 결정할 수 있다.

예를 들어 이미지 데이터를 관계형 DB의 숫자 컬럼처럼 바로 다룰 수는 없지. 반대로 이미 정형화된 거래 DB라면 별도의 비정형 분석 과정보다 필요한 컬럼을 추출하는 문제가 중심이 돼.

그래서 데이터 수집 대상 파악은 이후 수집 방식과 저장 설계를 결정하는 출발점이라고 보면 정확해.
