# 🧭 [모으기 전에 먼저 정체를 밝혀라] 1-3-1-1. 데이터 수집 대상 파악

#빅데이터분석기사 #필기 #데이터수집 #데이터유형 #데이터속성

## 🎯 왜 ‘수집 대상 파악’이 먼저일까?

이 단원의 핵심부터 잡자.

> **데이터 수집 대상 파악 = 분석 목적에 필요한 데이터가 무엇인지 정하고, 그 데이터의 유형과 속성을 확인하는 단계**야.

데이터를 많이 모으는 게 중요한 게 아니야. **분석 목적에 맞는 데이터를 제대로 모으는 것**이 중요해.

예를 들어 쇼핑몰이 **“고객 이탈 원인을 분석하겠다”**고 해보자. 그러면 아무 데이터나 긁어오는 게 아니라,

* 고객 정보
* 구매 이력
* 접속 이력
* 문의·불만 기록
* 최근 방문 시점

처럼 **이탈과 관련 있을 가능성이 있는 데이터**를 먼저 특정해야 해.

즉 흐름은 이렇게 보면 돼.

**분석 목적 → 필요한 정보 → 수집 대상 데이터 → 데이터 유형·속성 확인 → 실제 수집**

이 순서를 머릿속에 고정해두면 1-3 전체가 훨씬 편해져.

---

## 📥 1. 데이터 수집은 무엇을 하는 과정인가?

### 수집의 기본 의미

**데이터 수집(Data Collection)**은 분석에 필요한 데이터를 여러 원천에서 확보하는 과정이야.

여기서 시험에서 중요한 건 **“어디서 얻느냐”와 “어떤 형태로 얻느냐”를 구분하는 것**이야.

예를 들어 회사가 고객 분석을 한다면 다음처럼 나눌 수 있어.

| 데이터     | 데이터 원천 | 예시        |
| ------- | ------ | --------- |
| 고객 회원정보 | 내부     | 고객 DB     |
| 구매이력    | 내부     | 주문·결제 시스템 |
| 웹 행동정보  | 내부     | 웹 로그      |
| 날씨      | 외부     | 공공데이터     |
| SNS 반응  | 외부     | SNS·웹     |
| 경제지표    | 외부     | 정부·공공기관   |

### 내부 데이터와 외부 데이터

#### 내부 데이터

조직 내부의 업무 과정에서 생성되는 데이터야.

대표적으로:

* ERP 데이터
* CRM 데이터
* 거래 데이터
* 고객 데이터
* 생산 데이터
* 웹·시스템 로그

가 있어.

이미 조직 안에 존재하므로 상대적으로 접근하기 쉽지만, **부서별로 형식이 다르거나 데이터가 분산되어 있는 문제**가 생길 수 있어.

#### 외부 데이터

조직 밖에서 확보하는 데이터야.

예를 들면:

* 공공데이터
* 통계자료
* SNS 데이터
* 뉴스·웹 데이터
* 제휴기관 데이터
* 구매한 상용 데이터

같은 것들이 있어.

여기서는 특히 **신뢰성, 저작권·개인정보, 수집 가능 여부**를 함께 고려해야 해.

### 💡 시험에서 이렇게 구별해

**내부/외부**는 데이터가 **어디에서 왔는가**에 대한 분류야.

반면 뒤에서 보는 **정형/반정형/비정형**은 데이터가 **어떤 구조를 가지고 있는가**에 대한 분류야.

둘을 섞으면 안 돼.

## 🧩 2. 데이터 유형을 파악한다는 것은?

빅데이터에서 가장 기본적인 데이터 유형 분류는 다음 세 가지야.

### 정형 데이터 Structured Data

**정해진 구조와 스키마를 가진 데이터**야.

행과 열 형태의 테이블을 떠올리면 가장 쉬워.

| 고객번호 | 나이 |   구매금액 |
| ---- | -: | -----: |
| C001 | 29 | 120000 |
| C002 | 34 |  85000 |

대표적인 예는:

* 관계형 데이터베이스
* 엑셀의 정형화된 표
* ERP 데이터
* CRM 데이터
* 거래 데이터

야.

핵심 단어는 **고정된 구조, 스키마, 테이블**.

---

### 반정형 데이터 Semi-structured Data

여기서 많이 헷갈려.

반정형 데이터는 완전히 고정된 테이블 구조는 아니지만, **데이터 내부에 구조를 설명하는 요소가 포함된 데이터**야.

대표적으로:

* XML
* JSON
* HTML
* 웹 로그

등이 있어.

예를 들어 JSON을 보면:

```text
{
  "name": "Ailey",
  "age": 25
}
```

일반적인 관계형 DB의 행·열 구조는 아니지만 `name`, `age`처럼 **데이터의 구조를 식별할 수 있는 정보**가 있지.

그래서 핵심은:

> **반정형 = 고정된 테이블 구조는 없지만 태그, 키, 메타데이터 등을 통해 구조를 파악할 수 있음**

이야.

---

### 비정형 데이터 Unstructured Data

미리 정해진 구조가 거의 없는 데이터야.

대표적으로:

* 텍스트
* 문서
* 이미지
* 음성
* 동영상
* SNS 게시물

등이 있어.

가령 고객 상담 녹음 파일 하나는 DB 테이블처럼 바로 `불만유형 = 배송`, `감정 = 부정`이라고 들어 있지 않아.

분석하려면 음성을 텍스트로 바꾸거나 특징을 추출하는 등의 **추가적인 처리**가 필요하지.

---

## 🔎 정형·반정형·비정형의 경계

이 세 개는 시험에서 정말 자주 엮여.

| 구분      | 구조                    | 대표 예                |
| ------- | --------------------- | ------------------- |
| **정형**  | 고정된 스키마 존재            | RDB, 거래 DB          |
| **반정형** | 고정 스키마는 약하지만 구조 식별 가능 | XML, JSON, HTML, 로그 |
| **비정형** | 사전에 정의된 구조가 거의 없음     | 텍스트, 이미지, 음성, 영상    |

외울 때는 이렇게 압축해.

**정형 → 표**

**반정형 → 태그·키가 있는 유연한 구조**

**비정형 → 문서·미디어**

특히 **XML과 JSON을 비정형 데이터로 착각하지 않는 것**이 중요해. 둘은 대표적인 **반정형 데이터**야.

## 🧬 3. ‘데이터 속성’을 왜 파악해야 할까?

데이터가 있다고 바로 분석할 수 있는 건 아니야.

예를 들어 고객 데이터에 다음 변수가 있다고 해보자.

| 변수   | 값의 예         |
| ---- | ------------ |
| 고객ID | C1024        |
| 성별   | 남/여          |
| 등급   | 일반/실버/골드/VIP |
| 나이   | 32           |
| 구매금액 | 153000       |
| 가입일  | 2026-04-15   |

모두 데이터지만 **각 값의 의미와 사용할 수 있는 연산이 달라**.

`고객ID = C1024`는 숫자처럼 코드가 붙더라도 계산하는 값이 아니고, `구매금액`은 평균이나 합계를 계산할 수 있지.

그래서 데이터 수집 단계에서 **데이터의 속성과 특성을 확인해야 해.**

## 📊 데이터의 측정척도로 속성을 이해하기

필기시험에서는 데이터 속성을 이해할 때 **명목·서열·등간·비율척도**가 연결되는 경우가 많아.

### 명목척도 Nominal Scale

단순히 **분류하기 위한 값**이야.

예:

* 성별
* 혈액형
* 지역
* 상품 종류

숫자로 코딩되어 있다고 해도 크기를 의미하지 않아.

예를 들어:

`서울 = 1, 부산 = 2, 대구 = 3`

이라고 했다고 해서

`대구 > 부산 > 서울`

이라는 뜻은 아니야.

---

### 서열척도 Ordinal Scale

**순서는 존재하지만 간격의 크기는 정확하게 의미하지 않는 데이터**야.

예:

* 고객등급: 일반 < 실버 < 골드 < VIP
* 만족도: 불만족 < 보통 < 만족
* 석차

VIP가 골드보다 높다는 건 알지만,

> VIP와 골드의 차이 = 골드와 실버의 차이

라고 말할 수는 없어.

---

### 등간척도 Interval Scale

**순서와 간격에 의미가 있지만 절대적인 0이 없는 척도**야.

대표 예:

* 섭씨온도
* 화씨온도

10℃와 20℃의 차이는 10℃라는 의미가 있지만,

> 20℃가 10℃보다 두 배 뜨겁다

라고 할 수는 없어.

0℃가 ‘온도가 전혀 없음’을 뜻하지 않기 때문이야.

---

### 비율척도 Ratio Scale

가장 많은 연산이 가능한 형태야.

**순서, 간격, 비율에 모두 의미가 있고 절대적인 0이 존재해.**

예:

* 길이
* 무게
* 나이
* 매출액
* 소득
* 구매금액

구매금액 20만 원은 10만 원의 **2배**라고 할 수 있지.

---

## 🧠 네 척도를 하나의 관계로 묶어보자

단순 암기보다는 기능이 하나씩 추가된다고 이해하면 좋아.

**명목**
→ 분류 가능

**서열**
→ 분류 + 순서

**등간**
→ 분류 + 순서 + 동일한 간격

**비율**
→ 분류 + 순서 + 동일한 간격 + 절대적 0

즉,

**명목 → 서열 → 등간 → 비율**

로 갈수록 사용할 수 있는 정보가 많아져.

## 🏗️ 4. 실제 수집 대상을 파악할 때 보는 것

“필요한 데이터가 고객 데이터입니다”에서 끝내면 아직 부족해.

수집 계획을 세우려면 최소한 다음 관계를 함께 봐야 해.

### 무엇을 수집하는가

분석 목적에 필요한 **데이터 항목**을 정해.

예를 들어 고객 이탈 분석이라면:

* 고객 식별정보
* 이용기간
* 최근 이용일
* 구매빈도
* 구매금액
* 불만 접수 여부

등이 될 수 있어.

### 어디에서 수집하는가

데이터의 **출처 또는 원천**을 파악해.

* 내부 DB
* 웹 서버
* 센서
* 외부기관
* 공공데이터
* SNS·웹

등이지.

### 어떤 형태인가

데이터 유형을 확인해.

* 정형
* 반정형
* 비정형

여기서 실제 수집 및 전환 방식이 달라질 수 있어.

### 어떤 속성을 갖는가

각 변수의:

* 데이터 형식
* 의미
* 단위
* 범위
* 척도
* 결측 가능성

등을 확인해.

예를 들어 `age = 25`라는 값만 보는 게 아니라,

> **age는 고객 나이를 의미하며 숫자형이고, 단위는 년이며, 음수가 나오면 비정상이다**

정도로 데이터의 의미를 이해하는 거야.

## 🔄 5. 왜 이 내용이 ‘데이터 전환’까지 이어질까?

여기가 1-3-1 **데이터 수집 및 전환**이라는 상위 단원과 연결되는 지점이야.

데이터 유형을 파악해야 **어떻게 변환해서 분석 시스템에 넣을지** 결정할 수 있어.

예를 들어:

**관계형 DB**
→ SQL 등을 이용해 추출하기 쉬움

**JSON/XML**
→ 필요한 필드를 파싱하여 구조화해야 함

**텍스트**
→ 전처리와 자연어 처리가 필요할 수 있음

**이미지·음성**
→ 분석 가능한 특징이나 표현으로 변환해야 할 수 있음

그래서 흐름은:

**대상 파악 → 유형·속성 파악 → 적절한 수집 → 필요한 전환 → 저장**

이야.

이 순서를 이해하면 ‘수집’과 ‘전환’을 별개의 암기 항목으로 보지 않게 돼.

## ⚠️ 필기에서 흔히 걸리는 구분

### XML·JSON

**반정형 데이터**.

“행과 열이 아니니까 비정형”이라고 판단하면 틀리기 쉬워.

### 데이터 출처와 데이터 유형

서로 다른 분류야.

* **내부/외부** → 출처
* **정형/반정형/비정형** → 구조

예를 들어 외부에서 받은 JSON 데이터라면:

**외부 데이터이면서 반정형 데이터**

야.

### 숫자로 표현된 값

숫자라고 모두 연속형·비율척도인 건 아니야.

`고객번호 = 1001`

은 숫자처럼 보이지만 고객을 식별하는 **범주형 식별자**일 수 있어.

### 서열과 등간

서열척도는 **순서만 확실**해.

등간척도는 **간격까지 의미가 있어.**

이 차이를 기억하면 돼.

## 🧭 지금 반드시 잡아야 할 연결

단순히 **“JSON = 반정형”**을 외우는 데서 끝나면 약해.

이번 단원에서 진짜 이해해야 하는 건:

**데이터의 구조와 속성을 알아야 수집·전환·저장 방법을 결정할 수 있다**

는 인과관계야.

예를 들어 이미지 데이터를 관계형 DB의 숫자 컬럼처럼 바로 다룰 수는 없지. 반대로 이미 정형화된 거래 DB라면 별도의 비정형 분석 과정보다는 필요한 컬럼을 추출하는 문제가 중심이 돼.

그래서 **데이터 수집 대상 파악은 이후 수집 방식과 저장 설계를 결정하는 출발점**이라고 보면 정확해.
