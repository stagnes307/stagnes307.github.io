1-3-1-2. 변환·비식별화·품질검증

#빅데이터분석기사 #필기 #데이터변환 #비식별화 #데이터품질검증

이번 단원의 핵심은 수집한 데이터를 곧바로 분석하는 게 아니라, 분석 가능한 형태로 바꾸고 → 개인정보 위험을 낮추고 → 믿을 만한 데이터인지 확인한다는 흐름이야.

이 세 단계의 목적 차이부터 확실히 잡으면 문제에서 용어를 비틀어도 꽤 잘 풀려.

🔄 1. 데이터 변환 — “형태를 쓸 수 있게 바꾼다”

데이터를 여러 곳에서 수집했다고 해보자. 고객번호는 어떤 시스템에서는 00123, 다른 시스템에서는 123이고, 날짜도 2026-08-26, 26/08/2026처럼 제각각일 수 있어. 분석하려면 먼저 이런 데이터를 목적에 맞는 구조와 형식으로 변환해야 해.

형식만 바꾸는 게 아니다

데이터 변환은 원천 데이터를 목표 시스템이나 분석 환경에서 사용할 수 있도록 바꾸는 과정으로 이해하면 돼.

TRANSFORMATION LOG

형식 변환CSV → DB 테이블

표준화M·남·남성 → 남성
구조 변환필드 결합·분리
코드 변환01 → 서울
파생·계산생년월일 → 연령

변환의 중심 질문

“이 데이터를 원하는 곳에서 제대로 사용할 수 있는 형태로 만들 수 있는가?”

🕵️ 2. 데이터 비식별화 — “누구인지 알아내기 어렵게 만든다”

원본 레코드

홍길동 / 1992.03.17 / 경주시 ○○동 / 구매금액 830,000원

분석에는 구매금액이나 지역이 필요할 수 있지만 분석자가 홍길동이라는 개인을 식별할 필요는 없지. 그래서 개인정보의 일부를 삭제하거나 변형해서 특정 개인을 식별하기 어렵게 만드는 것이 비식별화야.

직접식별자만 지우면 끝일까?

아니야. 이름이나 주민등록번호처럼 그 자체로 사람을 알아볼 수 있는 정보가 없어도 1992년생 + 특정 동네 + 특정 직업처럼 여러 정보가 결합되면 다시 누구인지 추정할 가능성이 생길 수 있어. 따라서 비식별화에서는 정보의 결합에 따른 재식별 가능성도 생각해야 해.

가명처리

홍길동 → USER_1842

총계처리

개별값 → 평균·합계

데이터 삭제

상세주소 → 삭제

범주화

27세 → 20대

마스킹

홍길동 → 홍○동

개인정보 보호 ↔ 데이터 활용성

식별 위험 ↑
비식별 강도 ↑
보호와 활용 사이의 균형

비식별화를 강하게 할수록 일반적으로 개인 식별 위험은 감소하지만, 지나치게 정보를 없애면 데이터 활용 가능성도 떨어질 수 있어.

🔍 3. 데이터 품질 검증 — “그래서 이 데이터를 믿어도 되나?”

오류 레코드 예시

  • 나이: -17
  • 성별: NULL
  • 주문일: 2026-13-42
  • 동일 주문이 세 번 존재
  • 지역명은 서울, 지역코드는 부산

형식이 있다고 해서 좋은 데이터인 건 아니야. 품질 검증은 데이터가 정해진 기준과 업무 목적에 맞게 정확하고 일관되며 완전하게 관리되고 있는지 확인하는 과정으로 보면 돼.

품질 관점 확인 질문 예시
정확성실제 값이나 정의에 맞나?실제로 25세인가?
완전성필요한 값이 빠지지 않았나?고객번호가 NULL인가?
일관성관련 데이터끼리 모순되지 않나?서울 / 지역코드=부산
유효성정해진 형식·범위를 만족하나?월=13 → 범위 위반
유일성중복되어서는 안 될 값이 중복됐나?동일 주문번호 반복
