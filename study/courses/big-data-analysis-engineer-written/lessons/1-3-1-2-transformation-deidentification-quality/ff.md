🔄 1. 데이터 변환 — “분석 가능한 형태로 바꾸는 단계”

데이터를 수집했다고 바로 분석할 수 있는 건 아니야. 같은 의미의 값이 서로 다른 형식으로 저장돼 있거나, 여러 시스템의 데이터 구조가 다르거나, 분석 도구가 읽을 수 없는 형태일 수 있지.

그래서 데이터 변환(Data Transformation)은 원천 데이터를 목적에 맞는 형식·구조·값으로 바꾸는 과정이라고 이해하면 돼.

변환이 필요한 이유

예를 들어 고객 생년월일이 시스템마다 이렇게 들어왔다고 해보자.

원천 데이터	변환 후
1998/03/15	1998-03-15
980315	1998-03-15
1998년 3월 15일	1998-03-15

정보의 의미는 같지만 표현 방식이 달라. 그대로 두면 날짜 비교나 연령 계산에서 문제가 생길 수 있어.

즉,

원천 데이터 → 규칙에 따라 변환 → 분석·저장에 적합한 데이터

라는 흐름이야.

대표적인 데이터 변환
형식 변환

파일이나 데이터 표현 방식을 바꾸는 거야.

XML → JSON
Excel → CSV
문자열 "100" → 숫자 100

여기서 핵심은 데이터의 의미보다 표현 형식을 바꾼다는 점이야.

구조 변환

데이터의 테이블이나 필드 구조를 목적에 맞게 바꿔.

예를 들어

성명 = "김민수"

를

성 = "김"
이름 = "민수"

처럼 나눌 수도 있어.

반대로 여러 컬럼을 하나로 합칠 수도 있고.

값 변환

값 자체를 일정한 규칙으로 바꾸기도 해.

남성 → M
여성 → F

또는 단위를 통일해서

1.5m → 150cm

처럼 만들 수도 있어.

코드·범주 변환

서로 다른 시스템의 코드 체계를 통일하는 것도 중요해.

서울특별시 / 서울 / SEOUL

처럼 같은 의미가 여러 방식으로 표현됐다면 하나의 기준으로 맞춰야 하지.

🕶️ 2. 데이터 비식별화 — “누구인지 알아보기 어렵게 만든다”

여기가 필기에서 구분 문제가 잘 나와.

데이터 비식별화는 데이터에서 개인을 식별할 수 있는 요소를 제거하거나 변형해서 특정 개인을 알아보기 어렵게 만드는 처리야.

예를 들어 원본 데이터가

이름	나이	주소	직업
김민수	32	서울 강남구 역삼동	의사

라고 해보자.

이름만 삭제한다고 반드시 안전한 건 아니야.

32세 + 서울 강남구 역삼동 + 의사

같은 조합만으로도 특정인을 추론할 가능성이 생길 수 있거든.

그래서 비식별화에서는 직접 식별자뿐 아니라 여러 정보의 결합 가능성까지 생각해야 해.

🪪 직접 식별자와 간접 식별자

직접 식별자는 그것만으로 개인을 알아볼 가능성이 높은 정보야.

이름, 주민등록번호, 전화번호, 이메일 주소 등이 대표적이지.

반면 간접 식별자는 하나만 보면 개인을 특정하기 어렵지만 다른 데이터와 결합하면 식별 가능성이 높아질 수 있어.

나이, 성별, 지역, 직업 등이 대표적인 예야.

시험에서 중요한 사고는 이거야.

이름을 삭제했다 = 무조건 비식별화 완료

가 아니야.

다른 정보의 조합으로 개인이 다시 특정될 가능성까지 살펴봐야 해.

🎭 3. 비식별화 주요 기법

여기는 기법 이름 ↔ 처리 방식을 연결해서 기억해야 해.

가명처리

식별할 수 있는 값을 다른 값으로 바꾸는 방식이야.

김민수 → 고객A

또는

김민수 → X72A19

처럼 바꾸는 거지.

핵심은 원래 식별값을 다른 값으로 대체한다는 것.

총계처리

개별 데이터 대신 통계값이나 집계값을 사용하는 방법이야.

원본:

25세, 27세, 28세, 30세

처리:

평균 연령 = 27.5세

개인의 세부 데이터를 숨기고 전체적인 특성만 남기는 거야.

데이터 삭제

식별 가능성이 높은 값을 아예 제거해.

김민수 / 32세 / 서울

↓

32세 / 서울

주민번호 뒷자리 삭제 같은 것도 이 사고방식에 들어가.

다만 앞에서 봤듯이 일부 정보를 삭제했다고 재식별 가능성까지 자동으로 없어지는 것은 아니야.

데이터 범주화

정확한 값을 더 넓은 범주로 바꿔.

32세 → 30대

서울 강남구 역삼동 → 서울

처럼 정보의 구체성을 낮추는 거야.

시험에서는 이렇게 잡아두면 좋아.

정확한 값 → 구간·범주 = 범주화

데이터 마스킹

데이터의 일부를 가려서 원래 값을 직접 보지 못하게 하는 방법이야.

홍길동 → 홍*동

010-1234-5678 → 010-****-5678

abcdef@email.com → a*****@email.com

처럼.

여기서 특히 기억할 것:

가명처리 = 다른 값으로 대체
마스킹 = 일부를 가림

둘을 섞지 않으면 돼.

🧩 4. 비식별화 기법을 한 번에 구분하기
기법	핵심 동작	예
가명처리	다른 값으로 대체	김민수 → 고객A
총계처리	통계·집계값 사용	나이 → 평균 나이
데이터 삭제	값을 제거	주민번호 삭제
데이터 범주화	구체적 값을 범위로 확대	32세 → 30대
데이터 마스킹	일부를 가림	홍길동 → 홍*동

시험장에서 단어를 보면 동작을 떠올리면 된다.

대체 → 가명
집계 → 총계
제거 → 삭제
범위 확대 → 범주화
가림 → 마스킹

이렇게 연결해.

🧪 5. 데이터 품질 검증 — “이 데이터를 믿고 써도 되는가?”

변환도 했고 개인정보 위험도 줄였다고 끝나는 게 아니야.

마지막으로 확인해야 하는 게 데이터 품질(Data Quality)이야.

데이터 품질 검증은 데이터가 목적에 맞게 정확하고, 빠짐없고, 일관되며, 규칙을 만족하는지 확인하는 과정이라고 보면 돼.

예를 들어 이런 고객 데이터가 있다고 하자.

고객번호	나이	성별	가입일
1001	25	M	2026-01-10
1002	-5	F	2026-02-01
1002	31	여자	없음

여러 문제가 보여.

나이 = -5
→ 현실적으로 잘못된 값.

고객번호 1002 중복
→ 유일해야 하는 값이라면 문제.

M / F / 여자
→ 표현 규칙이 일관되지 않음.

가입일 없음
→ 필수 데이터라면 누락.

이런 문제를 찾아내는 것이 품질 검증이야.

🔍 6. 데이터 품질의 핵심 기준

교재에 따라 세부 용어 분류는 조금씩 달라질 수 있지만, 시험에서는 다음 관계를 먼저 정확히 잡는 게 중요해.

정확성 Accuracy

실제 값을 올바르게 표현하고 있는가?

실제 나이가 31세인데 데이터에 13세라고 저장돼 있다면 정확성 문제야.

핵심 질문:

“값이 맞는가?”

완전성 Completeness

필요한 데이터가 빠짐없이 존재하는가?

필수인 전화번호나 가입일이 NULL이라면 완전성이 떨어져.

핵심 질문:

“빠진 값은 없는가?”

일관성 Consistency

같은 데이터가 서로 모순되지 않는가?

한 시스템에서는 고객의 성별이 M, 다른 시스템에서는 F로 기록되어 있다면 일관성 문제야.

또는 같은 의미를

남 / 남성 / M / Male

처럼 제각각 사용하는 것도 관리가 필요한 부분이지.

핵심 질문:

“서로 맞아떨어지는가?”

유효성 Validity

정해진 형식·범위·규칙을 만족하는가?

나이가

-30

이라든가 날짜가

2026-13-40

이라면 허용된 규칙을 만족하지 않아.

핵심 질문:

“규칙 안에 들어오는가?”

유일성 Uniqueness

중복되어서는 안 되는 값이 중복되지 않았는가?

고객번호가 기본적으로 고객 한 명을 식별해야 하는데 동일 번호가 두 번 존재한다면 유일성 문제가 생겨.

핵심 질문:

“중복은 없는가?”

적시성 Timeliness

필요한 시점에 최신 데이터를 사용할 수 있는가?

주식 분석을 하는데 데이터가 몇 달 전 값이라면 정확하게 기록돼 있어도 사용 목적에는 맞지 않을 수 있지.

핵심 질문:

“필요한 시점의 데이터인가?”

⚠️ 7. 시험에서 특히 헷갈리는 품질 기준
정확성 vs 유효성

이 둘이 가장 흔한 함정 중 하나야.

어떤 사람의 실제 나이가 25세라고 해보자.

데이터에 30세라고 적혀 있다.

30이라는 숫자는 정상적인 나이 범위 안에 있으므로 유효할 수 있어.

하지만 실제 값 25와 다르므로 정확하지 않아.

즉,

정확성 = 현실과 맞는가
유효성 = 규칙에 맞는가

이 차이를 잡아야 해.

완전성 vs 정확성

값이 들어 있다고 정확한 건 아니야.

나이 = 999

값은 존재한다. 따라서 단순히 “비어 있지 않다”는 관점에서는 완전성 문제와 별개야.

하지만 실제 값과 다르거나 허용 범위를 벗어났다면 정확성·유효성 문제가 될 수 있어.

존재 여부와 값의 옳고 그름을 분리해서 판단하면 돼.

🧠 9. 필기용 압축 암기

시험 직전에 이 정도까지 압축할 수 있어야 해.

데이터 변환

원천 데이터를 목적에 맞는 형식·구조·값으로 변경

주요 관점:

형식 변환

구조 변환

값·코드 변환

데이터 표준화

데이터 비식별화

특정 개인을 식별하기 어렵도록 데이터를 처리

대표 기법:

가 · 총 · 삭 · 범 · 마

가명처리 → 대체

총계처리 → 집계

삭제 → 제거

범주화 → 구간 확대

마스킹 → 가림

데이터 품질 검증

데이터가 사용 목적에 맞는 품질 기준을 충족하는지 확인

특히 기억:

정확성 → 실제와 맞는가

완전성 → 빠진 값이 없는가

일관성 → 서로 모순되지 않는가

유효성 → 규칙에 맞는가

유일성 → 중복되지 않는가

적시성 → 필요한 시점의 데이터인가

🎯 10. 필기에서 보는 출제자의 관점

이 영역은 긴 정의를 그대로 외우는 것보다 사례를 보고 어떤 개념인지 식별하는 문제에 강해야 해.

그래서 세 단계로 판단하면 꽤 안정적이야.

① 무엇을 했는가?
형식이나 값을 바꿨다면 → 데이터 변환

② 왜 했는가?
개인을 알아보기 어렵게 했다면 → 비식별화

③ 무엇을 확인하는가?
오류·누락·중복·규칙 위반을 검사한다면 → 품질 검증

그리고 비식별화 문제에서는 다시

대체 / 집계 / 삭제 / 범주화 / 가림

중 어떤 동작인지 보고,

품질 문제에서는

실제값 / 누락 / 모순 / 규칙 / 중복 / 시점

중 무엇을 묻는지 잡으면 돼.

이렇게 동작 중심으로 분류하는 습관이 객관식에서 특히 강해.
