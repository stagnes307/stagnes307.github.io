## 🎯 이번 단원에서 잡아야 할 핵심

이 단원은 결국 **“한쪽 클래스의 데이터가 너무 적을 때, 어떻게 알아차리고 어떻게 보정하며, 보정이 실제로 좋아졌는지 어떻게 판단하는가?”**를 묻는 부분이야.

시험에서는 크게 세 흐름으로 연결해서 기억하면 돼.

> **불균형 상태 파악 → 불균형 처리 → 처리 전후 성능 비교**

예를 들어 사기 거래 탐지에서 정상 거래가 99,000건이고 사기 거래가 1,000건이라면, 단순히 모든 거래를 정상이라고 예측해도 정확도는 99%야. 하지만 사기 거래는 하나도 잡지 못하지.

그래서 불균형 데이터에서는 **정확도(Accuracy)만 보고 모델을 평가하면 위험하다**는 게 첫 번째 핵심이야.

---

## 🔎 1. 불균형 상태 파악 — 무엇이 문제인가?

### 다수 클래스와 소수 클래스

분류 문제에서 관측치 수가 많은 범주를 **다수 클래스(Majority Class)**, 적은 범주를 **소수 클래스(Minority Class)**라고 해.

예를 들어:

| 클래스 | 데이터 수 |  비율 |
| --- | ----: | --: |
| 정상  | 9,500 | 95% |
| 이상  |   500 |  5% |

여기서는 `정상`이 다수 클래스, `이상`이 소수 클래스야.

불균형 자체가 무조건 나쁜 것은 아니야. 현실에서 질병, 사고, 불량품, 사기처럼 원래 드문 사건도 있으니까.

문제는 **모델이 다수 클래스를 맞히는 것만으로도 좋은 성능처럼 보일 수 있다는 것**이야.

### 정확도의 함정

100명 중 실제 환자가 5명뿐이라고 해보자.

모델이 그냥 100명을 모두 정상이라고 예측하면:

* 정상 95명 → 맞음
* 환자 5명 → 전부 틀림

그런데 정확도는

$$
Accuracy = \frac{95}{100}=95\%
$$

가 돼.

**95% 정확도인데 환자를 한 명도 찾지 못한 모델**인 거지.

그래서 불균형 데이터에서는 혼동행렬을 중심으로 봐야 해.

### 혼동행렬부터 읽기

|             | 실제 Positive | 실제 Negative |
| ----------- | ----------: | ----------: |
| 예측 Positive |          TP |          FP |
| 예측 Negative |          FN |          TN |

여기서 소수 클래스가 Positive라고 생각하면 이해가 쉬워.

특히 중요한 지표는 다음과 연결돼.

$$
Precision = \frac{TP}{TP+FP}
$$

**양성이라고 예측한 것 중 실제 양성 비율**

$$
Recall = \frac{TP}{TP+FN}
$$

**실제 양성 중 모델이 찾아낸 비율**

$$
F1 = 2\times\frac{Precision\times Recall}{Precision+Recall}
$$

F1-score는 Precision과 Recall의 조화평균이야.

### 시험에서의 연결

불균형 자료에 대해 다음 표현이 나오면 경계하면 돼.

**“정확도가 매우 높으므로 분류 성능이 우수하다.”**

→ 반드시 그런 건 아니야.

소수 클래스를 거의 잡지 못해도 높은 정확도가 나올 수 있기 때문이지.

# 🛠️ 2. 불균형 처리 방법 — 데이터를 바꿀 것인가, 학습 방식을 바꿀 것인가?

불균형 처리법은 크게 이렇게 나눠보면 기억하기 편해.

1. **다수 클래스를 줄인다 → 언더샘플링**
2. **소수 클래스를 늘린다 → 오버샘플링**
3. **새 소수 데이터를 만들어낸다 → SMOTE**
4. **소수 클래스의 오류에 더 큰 벌점을 준다 → 비용민감학습 / 클래스 가중치**

---

## 📉 언더샘플링 Under-sampling

다수 클래스의 일부 데이터를 제거해서 클래스 비율을 맞추는 방법이야.

원래:

* 정상 9,000
* 이상 1,000

이라면 정상 데이터를 줄여서

* 정상 1,000
* 이상 1,000

처럼 만들 수 있어.

### 장점

데이터 수가 줄기 때문에 **학습 속도가 빨라질 수 있어.**

### 단점

여기가 시험 포인트야.

**기존 데이터를 버리기 때문에 중요한 정보가 손실될 수 있다.**

즉,

> 언더샘플링 → 다수 클래스 감소 → 정보 손실 가능

이라고 연결해.

---

## 📈 오버샘플링 Over-sampling

이번에는 반대로 **소수 클래스의 데이터를 늘리는 방법**이야.

원래

* 정상 9,000
* 이상 1,000

이라면 이상 데이터를 증가시켜

* 정상 9,000
* 이상 9,000

처럼 맞추는 거야.

가장 단순한 방식은 기존 소수 클래스 데이터를 복제하는 것이야.

### 장점

언더샘플링처럼 기존 데이터를 버리지 않아.

### 단점

똑같은 관측치를 반복해서 복제하면 모델이 그 데이터에 지나치게 맞춰질 수 있어.

즉, **과적합(Overfitting)** 가능성이 증가할 수 있어.

> 단순 오버샘플링 → 소수 데이터 반복 복제 → 과적합 위험

---

# 🧬 3. SMOTE — 그냥 복사하지 않고 새 데이터를 만든다

SMOTE는 시험에서 특히 중요해.

**Synthetic Minority Over-sampling Technique**

이름을 그대로 풀면:

> **소수 클래스의 합성 데이터를 생성하는 오버샘플링 기법**

이야.

단순 오버샘플링은 기존 데이터를 복제하지만, SMOTE는 **기존 소수 클래스 관측치 사이를 이용해서 새로운 가상의 관측치를 생성**해.

### 직관적으로 이해하기

소수 클래스에 두 점이 있다고 해보자.

$$
A=(2,2), \quad B=(4,4)
$$

SMOTE는 A나 B를 그대로 복사하기보다 그 사이에

$$
(3,3)
$$

같은 새로운 데이터를 생성하는 방식이라고 이해하면 돼.

실제로는 특정 소수 샘플과 **가까운 이웃(k-nearest neighbors)**을 이용하여 합성 표본을 만든다.

### 단순 오버샘플링과 SMOTE 비교

| 방법                   | 처리 방식                       |
| -------------------- | --------------------------- |
| Random Over-sampling | 기존 소수 클래스 관측치 복제            |
| SMOTE                | 소수 클래스 이웃 관계를 이용해 합성 관측치 생성 |

그래서 SMOTE는 단순 복제에 비해 과적합 문제를 어느 정도 완화할 수 있다는 장점이 있어.

하지만 만능은 아니야.

원래 소수 클래스에 노이즈나 이상치가 있다면 **잘못된 패턴까지 확대할 수도 있어.**

---

# ⚙️ 4. 비용 민감 학습과 클래스 가중치

샘플 자체를 늘리거나 줄이지 않고도 불균형 문제를 처리할 수 있어.

핵심은:

> **소수 클래스를 틀렸을 때 더 큰 비용을 부여한다.**

예를 들어 사기 거래 탐지에서

* 정상 거래를 사기로 잘못 판단하는 오류
* 사기 거래를 정상으로 놓치는 오류

두 가지의 실제 비용은 같지 않을 수 있어.

사기를 놓치는 게 훨씬 치명적이라면 모델에게

> “사기 거래를 잘못 분류하면 더 크게 벌점을 줄게.”

라고 학습시키는 거야.

많은 분류 알고리즘에서 이 원리를 **Class Weight**로 구현해.

즉 데이터 개수를 물리적으로 바꾸는 샘플링과 구별해야 해.

### 구별

**샘플링**

→ 학습 데이터의 클래스 분포를 변경

**클래스 가중치**

→ 데이터 개수는 유지하고 오류의 중요도를 변경

이 차이는 꽤 자주 헷갈려.

# ⚠️ 5. 중요한 실무·시험 함정 — 언제 샘플링해야 하는가?

여기서 순서가 중요해.

데이터를 먼저 훈련 데이터와 테스트 데이터로 분리한 뒤,

> **훈련 데이터에 대해서만 오버샘플링이나 SMOTE를 적용**

하는 게 원칙이야.

왜냐하면 테스트 데이터까지 SMOTE에 사용하면, 테스트 데이터가 사실상 학습 과정에 영향을 미치는 **데이터 누수(Data Leakage)**가 발생할 수 있기 때문이야.

즉,

$$
전체 데이터
$$

↓

$$
Train / Test 분리
$$

↓

$$
Train에만 SMOTE
$$

↓

$$
모델 학습
$$

↓

$$
원래 Test로 평가
$$

이 구조를 기억해.

**테스트 세트까지 억지로 50:50으로 맞출 필요가 없어.**

테스트 데이터는 가능한 한 실제 분포를 반영해야 제대로 된 성능 평가가 가능하니까.

# 📊 6. 처리 결과 비교 — 무엇이 좋아졌다고 봐야 할까?

불균형 데이터를 처리했다고 해서 무조건 모델이 좋아지는 건 아니야.

그래서 반드시

> **처리 전 모델 ↔ 처리 후 모델**

을 비교해야 해.

이때 Accuracy만 보면 안 되고 특히 다음을 본다.

### Recall

$$
Recall=\frac{TP}{TP+FN}
$$

소수 클래스를 얼마나 놓치지 않았는지를 봐.

질병 진단이나 사기 탐지처럼 **실제 Positive를 놓치면 큰 문제가 되는 상황**에서 중요해.

### Precision

$$
Precision=\frac{TP}{TP+FP}
$$

Positive라고 판단한 것 중 실제 Positive가 얼마나 되는지를 봐.

거짓 경보(False Positive)가 큰 비용을 발생시키는 상황에서 중요하지.

### F1-score

Precision과 Recall을 동시에 고려하고 싶다면 F1-score를 볼 수 있어.

$$
F1=2\frac{Precision\times Recall}{Precision+Recall}
$$

그래서 불균형 분류에서는 Accuracy보다 F1-score가 더 유용한 경우가 많아.

### ROC-AUC

ROC 곡선은 여러 분류 임계값에서

* TPR
* FPR

의 관계를 보여줘.

AUC는 ROC 곡선 아래 면적이고,

$$
AUC \rightarrow 1
$$

에 가까울수록 일반적으로 분류 능력이 좋다고 해석해.

다만 **극심한 클래스 불균형에서는 Precision-Recall 관계를 함께 확인하는 것**이 더 유용할 수도 있어.

# 🧠 7. 세 방법을 한 번에 구분하기

시험 직전에는 이 표가 가장 중요해.

| 방법      | 핵심 원리           | 장점             | 주요 위험            |
| ------- | --------------- | -------------- | ---------------- |
| 언더샘플링   | 다수 클래스 제거       | 빠른 학습, 균형 개선   | 정보 손실            |
| 오버샘플링   | 소수 클래스 증가       | 정보 손실 없음       | 과적합              |
| SMOTE   | 소수 클래스 합성 표본 생성 | 단순 복제보다 다양성 확보 | 노이즈·이상치 확대 가능    |
| 클래스 가중치 | 소수 클래스 오류에 큰 비용 | 데이터 수를 바꾸지 않음  | 가중치 설정에 따라 결과 변화 |

여기서 가장 먼저 떠올려야 할 단어를 압축하면:

> **Under = 버린다 → 정보 손실**
> **Over = 복제한다 → 과적합**
> **SMOTE = 이웃 사이에 만든다 → 합성 표본**
> **Weight = 개수 대신 벌점을 바꾼다**

# 🔄 8. 처리 전후 성능이 이렇게 바뀌었다면?

가령 SMOTE 적용 전 모델이:

| 지표        | 적용 전 |
| --------- | ---: |
| Accuracy  |  97% |
| Precision |  80% |
| Recall    |  30% |
| F1        |  44% |

이었다고 하자.

SMOTE 후:

| 지표        | 적용 후 |
| --------- | ---: |
| Accuracy  |  93% |
| Precision |  65% |
| Recall    |  78% |
| F1        |  71% |

가 됐어.

겉으로 보면 Accuracy는 **97% → 93%로 떨어졌어.**

그런데 Recall은

$$
30\%\rightarrow78\%
$$

F1은

$$
44\%\rightarrow71\%
$$

로 크게 올랐지.

그러면 소수 클래스 검출이 중요한 문제라면 **처리 후 모델이 실질적으로 더 유용할 가능성이 높아.**

이게 불균형 데이터에서 반드시 이해해야 하는 사고방식이야.

**정확도가 떨어졌다는 이유만으로 모델이 나빠졌다고 결론 내리면 안 돼.**

# 🧩 9. 시험에서 자주 섞어 놓는 개념

### 언더샘플링 vs 오버샘플링

언더샘플링은 **다수 클래스 감소**, 오버샘플링은 **소수 클래스 증가**야.

### 오버샘플링 vs SMOTE

SMOTE는 오버샘플링의 한 종류야.

하지만 단순 복제보다는 **새로운 합성 데이터를 만든다**는 점이 핵심 차이.

### Accuracy vs Recall

Accuracy는 전체 중 맞춘 비율이고,

Recall은

> **실제 Positive 중 Positive라고 찾아낸 비율**

이야.

불균형 분류 문제에서는 둘이 완전히 다른 이야기를 할 수 있어.

### 데이터 불균형 처리 vs 결측값 처리

둘은 전혀 다른 문제야.

* 결측값 처리 → 값이 비어 있음
* 불균형 처리 → 클래스별 데이터 개수가 크게 다름

용어가 같이 전처리 단원에 나오다 보니 섞지 않는 게 중요해.

# 🧭 10. 이 단원의 구조를 한 문장으로 묶으면

불균형 데이터에서는 **다수 클래스에 치우친 학습과 Accuracy의 착시가 발생할 수 있으므로**, 클래스별 분포와 혼동행렬 기반 지표를 확인하고, **언더샘플링·오버샘플링·SMOTE·가중치 조정** 등을 사용한 뒤 **Precision·Recall·F1·AUC 등의 지표로 처리 전후를 비교한다.**

이 문장을 이해하고 있으면 세부 문제들이 꽤 잘 풀려.

## 📝 필기시험용 압축 암기

**불균형 상태 파악**

→ 클래스별 빈도·비율 확인
→ Accuracy만 믿지 않기
→ 혼동행렬 기반 지표 확인

**불균형 처리**

→ 언더샘플링: 다수 ↓ / 정보 손실
