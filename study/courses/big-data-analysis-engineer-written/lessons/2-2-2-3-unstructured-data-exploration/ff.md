#빅데이터분석기사 #필기 #데이터탐색 #고급데이터탐색 #비정형데이터 #텍스트마이닝 #전처리 #패턴탐색

🎯 먼저 잡을 핵심: 비정형 데이터는 왜 바로 분석하기 어려울까?

정형 데이터는 보통 행과 열의 구조가 미리 정해져 있는 데이터야. 예를 들어 고객 테이블에 고객번호 / 나이 / 구매금액 같은 열이 있다면, 컴퓨터는 각 값이 무엇을 의미하는지 비교적 바로 알 수 있어.

그런데 이런 데이터는 어때?

“배송은 빨랐는데 제품 포장이 너무 별로였어요.”

사람은 즉시 의미를 읽어. 배송에는 긍정적이고 포장에는 부정적이라는 것도 알아차릴 수 있지. 하지만 컴퓨터 입장에서는 처음에는 그저 문자들의 연속일 뿐이야.

그래서 비정형 데이터 탐색의 전체 흐름을 먼저 하나로 기억하면 좋아.

비정형 원본 → 분석 가능한 형태로 전처리 → 특징 추출 → 패턴 탐색 → 의미 해석

이번 단원의 세 항목도 정확히 이 순서를 따른다.

① 어떤 비정형 데이터가 있는가 → ② 어떻게 분석 가능한 상태로 만드는가 → ③ 거기서 어떤 패턴을 찾는가

🗂️ 1. 비정형 데이터 유형 — 구조가 없다는 말의 정확한 의미

비정형 데이터(Unstructured Data)는 미리 정의된 데이터 모델이나 일정한 구조에 맞추기 어려운 데이터를 말해.

여기서 시험에서 조심할 게 하나 있어.

비정형 = 아무 구조도 존재하지 않는다는 뜻으로 이해하면 너무 강해.

문장에는 문법 구조가 있고, 이미지에는 픽셀 배열이 있고, 음성에는 시간에 따른 파형이 있어. 다만 관계형 데이터베이스의 표처럼 분석에 바로 사용할 수 있는 일정한 스키마가 사전에 정의되어 있지 않다는 쪽으로 이해하는 게 정확해.

대표적인 유형
유형	예	탐색하려는 것
텍스트	뉴스, SNS, 이메일, 리뷰, 문서	단어, 주제, 감성, 관계
이미지	사진, 의료영상, 위성사진	객체, 형태, 색상, 특징
오디오	음성, 음악, 녹음	음성 내용, 화자, 음향 특징
비디오	CCTV, 동영상	객체·행동·장면의 변화
웹·로그성 콘텐츠	웹 문서, 일부 로그·메시지	행동이나 내용상의 패턴

시험에서는 특히 텍스트 데이터를 중심으로 비정형 데이터 탐색을 설명하는 경우가 많아.

정형·반정형·비정형을 같이 구별하자

이 셋은 자주 섞여서 나온다.

구분	핵심	대표 예
정형 데이터	고정된 스키마와 행·열 구조	RDB 테이블, 스프레드시트
반정형 데이터	일정한 메타 구조나 태그는 있지만 고정된 표 구조는 아님	XML, JSON, HTML
비정형 데이터	사전에 정해진 분석용 구조가 뚜렷하지 않음	문서, 이미지, 음성, 영상

특히 XML과 JSON은 비정형이 아니라 반정형 데이터로 분류한다는 점을 기억해 둬.

🧹 2. 탐색 전 처리 — 의미 없는 변동을 걷어내는 단계

비정형 데이터에서는 전처리가 특히 중요해.

텍스트를 예로 들어 보자.

“빅데이터 분석은 정말 재미있다!!! 빅데이터를 공부하자.”

우리가 알고 싶은 건 느낌표가 세 개인지보다는 빅데이터·분석·재미·공부 같은 의미 있는 정보일 가능성이 높아.

따라서 원본을 그대로 세는 것이 아니라 분석 목적에 맞게 정제하고 변환해서 특징(feature)을 만들어야 한다.

텍스트 전처리의 흐름

원문 → 정제 → 토큰화 → 불용어 제거 → 정규화 → 특징 표현

정제(Cleansing)

분석에 필요하지 않은 요소를 제거하거나 수정해.

특수문자, 불필요한 공백, HTML 태그, 중복 데이터, 분석 목적상 필요 없는 문자 등이 대상이 될 수 있어.

핵심은 단순히 “많이 삭제한다”가 아니야.

분석하고 싶은 의미를 보존하면서 불필요한 잡음을 줄인다.

이게 정제의 목적이야.

토큰화(Tokenization)

문장이나 문서를 분석 가능한 작은 단위인 토큰(token)으로 나눈다.

예를 들어,

데이터 분석이 재미있다

를 단어 수준에서 나누면 대략

데이터 / 분석 / 이 / 재미있다

같은 형태가 될 수 있어.

한국어에서는 조사와 어미가 붙기 때문에 단순히 띄어쓰기만으로 처리하기보다 형태소 분석이 중요할 수 있어.

불용어 제거(Stopword Removal)

자주 등장하지만 분석 목적에는 정보량이 적은 단어를 제거하는 과정이야.

영어의 the, a, is 등이 전형적인 예이고, 한국어에서도 조사나 매우 빈번하지만 분석 가치가 낮은 표현이 대상이 될 수 있어.

다만 어떤 단어가 불용어인지는 분석 목적에 따라 달라진다.

예를 들어 감성 분석에서 안, 못 같은 부정 표현을 무턱대고 제거하면

“좋다”
“안 좋다”

의 결정적인 차이를 잃어버리겠지.

정규화(Normalization)

표현은 다르지만 실질적으로 같은 의미를 갖는 요소들을 가능한 한 일관된 형태로 만드는 과정이야.

텍스트에서는 대표적으로 어간 추출(Stemming)과 표제어 추출(Lemmatization)을 알아두면 돼.

어간 추출: 규칙에 따라 접사 등을 제거하여 어간에 가까운 형태를 얻음

표제어 추출: 문법적·사전적 정보를 활용하여 기본형인 표제어를 찾음

둘의 목적은 비슷해.

표현의 변형 때문에 같은 개념이 서로 다른 특징으로 분산되는 것을 줄이는 것.

🔢 3. 텍스트를 숫자로 바꾸기 — 컴퓨터가 탐색할 수 있는 표현 만들기

전처리했다고 바로 통계 분석이 가능한 건 아니야.

사과, 배송, 만족이라는 문자열 자체를 많은 분석 알고리즘이 그대로 계산할 수는 없으니까 수치적인 특징으로 표현해야 해.

단어 빈도

가장 단순한 방법은 단어가 몇 번 등장했는지 세는 거야.

문서에서

데이터: 15회

분석: 12회

시험: 3회

처럼 나타낼 수 있어.

단어 빈도가 높으면 해당 문서에서 중요한 단어일 가능성이 있지만, 많이 나온다고 항상 중요한 것은 아니다.

모든 문서에 흔하게 등장하는 단어라면 특정 문서의 특징을 구별하는 힘은 약하기 때문이야.

TF-IDF

여기서 TF-IDF가 등장해.

TF(Term Frequency)는 특정 문서 안에서 어떤 단어가 얼마나 자주 등장하는지를 나타내고, IDF(Inverse Document Frequency)는 너무 많은 문서에 공통적으로 등장하는 단어의 중요도를 낮추는 역할을 해.

직관적으로는 이렇게 기억하면 돼.

그 문서에서는 자주 나오지만, 다른 문서에서는 흔하지 않은 단어를 중요하게 본다.

예를 들어 모든 영화 리뷰에서 영화라는 단어가 나온다면 영화는 문서들을 서로 구별하는 힘이 약해.

반면 특정 리뷰에서 촬영기법이라는 단어가 반복되고 다른 리뷰에는 거의 없다면 그 문서의 특징을 나타낼 가능성이 더 높겠지.

그래서 단순 빈도와 TF-IDF의 차이는:

빈도 → 많이 나온 단어
TF-IDF → 해당 문서를 상대적으로 잘 특징짓는 단어

라고 잡아두면 된다.

🔍 4. 패턴 탐색 — 전처리가 끝나면 무엇을 찾을까?

이제 데이터가 분석 가능한 형태가 됐어.

패턴 탐색의 질문은 결국 이거야.

이 데이터 안에 반복적으로 나타나는 의미 있는 규칙이나 관계는 무엇인가?

비정형 데이터, 특히 텍스트에서는 여러 방향으로 탐색할 수 있어.

빈도 분석

단어나 표현이 얼마나 자주 등장하는지 확인한다.

가장 기본적인 탐색이고 핵심 키워드 후보를 찾는 데 도움이 돼.

단어 빈도를 시각적으로 보여주는 대표적인 방법으로 워드 클라우드(Word Cloud)도 있어. 일반적으로 빈도가 높거나 중요도가 높은 단어를 더 크게 표시해서 전체적인 경향을 빠르게 살펴보는 방식이지.

하지만 워드 클라우드만으로 단어 사이의 관계나 문맥을 충분히 설명할 수는 없어.

동시출현(Co-occurrence) 분석

한 단계 더 들어가면 어떤 단어들이 함께 등장하는가를 볼 수 있어.

고객 리뷰에서

배송 ↔ 빠르다
포장 ↔ 파손
가격 ↔ 만족

같은 결합이 반복될 수 있겠지.

단어 하나의 빈도보다 단어 사이의 관계를 탐색할 수 있다는 게 중요해.

이를 네트워크 형태로 표현하면 단어를 노드(node), 단어 사이의 관계를 **링크(edge)**로 나타내는 식의 분석도 가능해.

군집화(Clustering)

비슷한 특징을 가진 문서들을 자동으로 묶을 수도 있어.

예를 들어 고객 문의 10,000건을 분석했더니 자연스럽게

배송 관련 / 환불 관련 / 제품 불량 관련 / 사용법 관련

집단으로 나뉠 수 있어.

이때 정답 범주를 미리 주지 않고 데이터의 유사성을 이용하여 그룹을 찾는다면 비지도학습의 군집화와 연결돼.

토픽 모델링(Topic Modeling)

많은 문서에서 잠재적인 주제(topic)를 찾아내는 방법이야.

예를 들어 뉴스 기사 수천 개를 분석했을 때,

금리·은행·대출 → 금융 관련 주제

선수·경기·감독 → 스포츠 관련 주제

모델·데이터·알고리즘 → AI 관련 주제

처럼 함께 나타나는 단어의 분포를 이용해 문서에 숨어 있는 주제를 추론할 수 있어.

대표적인 토픽 모델링 기법으로 LDA(Latent Dirichlet Allocation, 잠재 디리클레 할당)를 기억해 두자.

여기서 LDA는 문서를 단 하나의 주제로만 고정하는 방식이라고 생각하면 안 돼. 하나의 문서가 여러 주제의 혼합으로 이루어져 있다고 보는 것이 중요한 관점이야.

감성 분석(Sentiment Analysis)

텍스트에 나타난 긍정·부정 등의 감성을 분석하는 방법이야.

“배송이 정말 빨라서 만족합니다.” → 긍정
“두 번이나 고장 났어요.” → 부정

상품 리뷰, SNS 반응, VOC 분석 등에 활용할 수 있지.

여기서도 전처리가 중요해. 앞에서 본 것처럼 부정어를 잘못 제거하면 감성 자체가 뒤집힐 수 있으니까.

🧠 5. 시험에서 연결해서 생각해야 하는 관계

이 단원은 용어를 따로 외우면 꽤 헷갈려. 입력 → 처리 → 표현 → 탐색 관계로 묶으면 훨씬 안정적이야.

비정형 원본

이 흐름에서 전처리와 패턴 탐색을 구별하는 것이 특히 중요해.

작업	목적
토큰화	분석 단위로 분리
불용어 제거	불필요한 단어 감소
어간/표제어 처리	표현의 변형 감소
TF-IDF	단어의 상대적 중요도 표현
빈도·동시출현 분석	반복과 관계 탐색
군집화	비슷한 대상 묶기
토픽 모델링	잠재 주제 발견
감성 분석	긍정·부정 등 감성 파악

즉,

전처리 = 패턴을 잘 찾을 수 있도록 데이터를 준비하는 것
패턴 탐색 = 준비된 데이터에서 실제 구조와 의미를 발견하는 것

이 경계가 선명하면 문제가 조금 변형되어도 대응하기 쉬워.

⚠️ 6. 헷갈리기 쉬운 지점만 압축
XML·JSON은 어디에 속할까?

반정형 데이터.

태그나 키처럼 구조를 알려주는 정보가 있지만 관계형 테이블처럼 고정된 행·열 스키마는 아니기 때문이야.

불용어는 무조건 제거할까?

아니야. 분석 목적에 따라 결정해야 해.

특히 감성 분석에서는 부정 표현처럼 의미를 결정하는 요소를 보존해야 할 수 있어.

단어 빈도가 높으면 중요한 단어일까?

반드시 그렇지는 않아.

그래서 여러 문서에 너무 흔한 단어의 가중치를 낮추는 TF-IDF 같은 방법이 필요해.

군집화와 토픽 모델링은 같을까?

관련은 있지만 목적이 달라.

군집화는 비슷한 관측 대상이나 문서를 묶는 것에 초점이 있고, 토픽 모델링은 문서 집합에 잠재된 주제 구조를 발견하는 것에 초점이 있어.

워드 클라우드가 문맥까지 보여줄까?

아니야. 전체적인 단어 중요도나 빈도를 직관적으로 보는 데는 좋지만 단어 사이의 의미 관계나 문맥을 충분히 보여주지는 못해.

🧩 7. 마지막으로 하나의 사례에 전부 연결해보자

온라인 쇼핑몰이 고객 리뷰 100만 건을 분석한다고 해보자.

원본 리뷰는 자유롭게 작성된 비정형 텍스트 데이터야.

먼저 HTML 태그나 불필요한 문자 등을 정제하고, 문장을 단어나 형태소 같은 단위로 토큰화한다. 분석 가치가 낮은 불용어를 제거하고 표현을 가능한 한 일관되게 정규화한다.

그다음 단어 빈도나 TF-IDF 등을 사용해서 텍스트를 분석 가능한 특징으로 표현할 수 있어.

이제 목적에 따라 패턴을 찾는다.

배송, 파손이 함께 자주 나타난다면 동시출현 관계를 볼 수 있고, 비슷한 리뷰를 배송·품질·환불 같은 집단으로 묶으면 군집화, 수많은 리뷰에 숨어 있는 주제 분포를 발견하면 토픽 모델링, 고객의 긍정·부정 반응을 파악하면 감성 분석으로 이어져.

그러니까 이 단원의 본질은 개별 용어 10개가 아니라 한 문장이야.

구조화되지 않은 원본에서 불필요한 변동을 제거하고 분석 가능한 특징을 만든 뒤, 반복되는 관계와 의미를 발견한다.

이 문장을 중심축으로 잡아두면 돼.
