3-1-1-1. 분석모형 선정

분석모형을 선정한다는 건 여러 알고리즘 중 성능이 제일 높은 걸 무조건 고르는 일이 아니야. 핵심은 분석 목적에 맞는 후보를 만들고, 적절한 기준으로 비교해서 최종 모형을 고르는 것이야.

분석 목적 확인 후보 모형 구성 선정 기준 설정 후보 모형 비교 최종 모형 선정

시험이 자주 건드리는 지점은 특히 목적 ↔ 평가기준의 연결이야.

01 / Purpose

🧩 분석 목적과 후보 모형

분석 목적이 모형의 종류를 결정한다

먼저 “무엇을 알고 싶은가?”를 정해야 해. 알고리즘 이름은 그다음이야.

분석 목적 핵심 질문 대표 후보 모형
분류어느 범주에 속하는가?로지스틱 회귀, 의사결정나무, SVM, 랜덤포레스트
회귀수치가 얼마인가?선형회귀, 회귀트리
군집비슷한 대상끼리 어떻게 묶이는가?K-means, 계층적 군집
연관분석어떤 항목들이 함께 발생하는가?Apriori
시계열 예측시간에 따라 앞으로 어떻게 변하는가?ARIMA

지도학습

정답에 해당하는 목표변수(target)가 있다.

  • 분류
  • 회귀

예: 고객 데이터에 이미 ‘이탈 여부’가 붙어 있다면 그 값을 학습할 수 있으므로 지도학습이야.

비지도학습

정답에 해당하는 목표변수가 없다.

  • 군집
  • 연관분석

예: 사전 등급 없이 행동 특성만으로 고객을 몇 개 집단으로 나누면 군집분석이 자연스럽지.

후보 모형은 하나만 잡지 않는다

이탈 고객 분류라면 로지스틱 회귀 → 의사결정나무 → 랜덤포레스트처럼 여러 후보를 만들 수 있어. 같은 데이터라도 모형마다 장단점이 다르기 때문이야.

03 / Trade-offs

🔍 성능만 높다고 최종 모형이 되는 건 아니다

해석 가능성

의사결정나무처럼 결과 구조를 비교적 쉽게 읽을 수 있는 모형이 있어. 금융·의료처럼 왜 이런 판단을 했는지 설명해야 하는 상황에서는 중요한 기준이 돼.

복잡도와 일반화

지나치게 복잡하면 학습 데이터에는 잘 맞지만 새로운 데이터에서 성능이 떨어지는 과적합(overfitting)이 생길 수 있어. 검증·테스트 데이터에서 일반화 성능을 봐야 해.

계산 비용

학습 시간, 예측 시간, 메모리 사용량, 하드웨어 요구사항도 고려 대상이야. 대용량이나 실시간 환경일수록 중요해져.

운영·적용 가능성

성능이 조금 높아도 지나치게 느리거나 유지보수가 어렵거나 설명이 불가능하면 다른 후보가 최종 선택될 수 있어.

모형 선정의 균형 지도

04 / Comparison

🥊 후보 모형 비교: 같은 조건에서 비교해야 한다

모형 A는 학습 데이터 정확도, 모형 B는 테스트 데이터 정확도로 비교하면 의미가 없어. 후보 모형은 동일한 학습·검증 조건과 평가기준에서 비교해야 해.

후보 모형 생성
동일 조건 적용
평가지표 측정
복잡도·해석력·운영성 검토
최종 모형 선정

05 / Exam Fault Lines

🧠 시험에서 구별해야 할 세 가지

분석 목적 ≠ 평가지표

목적: 고객 이탈 여부 분류 → 모형: 로지스틱 회귀 → 평가: 정확도·재현율·F1-score 등. 이 세 층을 섞지 않는 게 중요해.

후보 모형 ≠ 최종 모형

후보 모형은 비교 대상이고, 최종 모형은 평가기준에 따라 선택된 결과야.

복잡한 모형 ≠ 좋은 모형

복잡하다고 항상 좋은 게 아니야. 일반화 성능·해석 가능성·비용·운영 가능성까지 봐야 해.

🔗 한 번에 연결하면

분석 목적과 데이터 특성에 적합한 여러 후보 모형을 선정하고, 적절한 평가기준을 사용하여 성능·복잡도·해석 가능성·운영 가능성 등을 비교한 뒤 최종 분석모형을 선택한다.
범주 예측 → 분류
연속형 수치 예측 → 회귀
정답 없이 유사 대상 묶기 → 군집
후보 모델 평가 → 동일 조건에서 비교
좋은 모델 → 성능뿐 아니라 일반화·해석성·복잡성까지 고려
