🧭 [좋은 모형은 “목적”에서 시작해] 3-1-1-1. 분석모형 선정

#빅데이터분석기사 #필기 #분석모형설계 #분석절차수립 #분석모형선정

🎯 먼저 잡을 핵심: “가장 좋은 모형”이 아니라 “목적에 맞는 모형”

분석모형을 선정한다는 건 여러 알고리즘 중 성능이 제일 높은 걸 무조건 고르는 일이 아니야.

핵심 흐름은 이거야.

분석 목적 확인 → 후보 모형 구성 → 선정 기준 설정 → 후보 모형 비교 → 최종 모형 선정

여기서 시험이 자주 건드리는 포인트는 목적과 평가기준의 연결이야.

예를 들어 고객의 이탈 여부를 맞히고 싶다면 목표값은 이탈 / 비이탈처럼 범주형이지. 그러면 우선 분류 모형을 후보로 잡아야 해. 반대로 다음 달 매출액처럼 숫자를 예측한다면 회귀 모형이 기본 후보가 돼.

즉,

무엇을 알고 싶은가가 먼저이고, 어떤 알고리즘을 쓸지는 그다음이야.

🧩 1. 분석 목적과 후보 모형
분석 목적이 모형의 종류를 결정한다

분석 목적은 보통 다음처럼 나눠 볼 수 있어.

분석 목적	핵심 질문	대표 후보 모형
분류	어느 범주에 속하는가?	로지스틱 회귀, 의사결정나무, SVM, 랜덤포레스트 등
회귀	수치가 얼마인가?	선형회귀, 회귀트리 등
군집	비슷한 대상끼리 어떻게 묶이는가?	K-means, 계층적 군집 등
연관분석	어떤 항목들이 함께 발생하는가?	Apriori 등
시계열 예측	시간에 따라 앞으로 어떻게 변하는가?	ARIMA 등

여기서 중요한 구분 하나.

지도학습과 비지도학습

정답에 해당하는 목표변수(target)가 있느냐를 보면 돼.

목표변수가 있다 → 지도학습

분류

회귀

목표변수가 없다 → 비지도학습

군집

연관분석 등

예를 들어 고객 데이터에 이미 이탈 여부가 붙어 있다면 그 값을 학습할 수 있으니까 지도학습이야.

반대로 고객들을 아무 사전 등급 없이 행동 특성에 따라 몇 개 집단으로 나누려 한다면 군집분석이 자연스럽지.

후보 모형은 하나만 잡지 않는다

실무에서도 시험에서도 보통 처음부터 하나의 알고리즘을 확정한다고 생각하면 안 돼.

예를 들어 이탈 고객 분류 문제라면,

로지스틱 회귀 → 의사결정나무 → 랜덤포레스트

처럼 여러 후보를 만들고 비교할 수 있어.

왜냐하면 같은 데이터라도 모형마다 장단점이 다르기 때문이야.

⚖️ 2. 선정 기준: 무엇을 기준으로 “좋다”고 판단할까?

모형 선정 기준은 크게 성능과 실제 활용 가능성을 함께 본다고 이해하면 좋아.

예측 성능

가장 먼저 떠올릴 수 있는 기준이지.

분류에서는 대표적으로:

정확도 Accuracy

정밀도 Precision

재현율 Recall

F1-score

ROC-AUC

같은 지표를 사용할 수 있어.

회귀에서는:

MAE

MSE

RMSE

결정계수 R
2

등을 사용할 수 있고.

그런데 여기서 중요한 건 평가지표도 분석 목적에 따라 달라진다는 거야.

예: 암 환자를 찾아내는 모델

실제 환자를 정상이라고 놓치는 것이 매우 위험하다면 단순 정확도보다 재현율(Recall)이 중요할 수 있어.

그러니까 이런 사고방식이 필요해.

분석 목적 → 중요한 오류 결정 → 그 오류를 반영하는 평가 지표 선택

이 연결이 꽤 중요해.

🔍 3. 성능만 높다고 최종 모형이 되는 건 아니다

후보 모형을 비교할 때 다음 요소들도 고려해.

해석 가능성

어떤 모형은 결과를 설명하기 쉽고, 어떤 모형은 어렵지.

예를 들어 단순한 의사결정나무는

소득 > 일정 수준 → 구매 가능성 증가

같이 결과 구조를 비교적 쉽게 읽을 수 있어.

반면 아주 복잡한 앙상블이나 일부 고차원 모델은 예측력은 높더라도 결과를 설명하기 어려울 수 있어.

그래서 금융·의료처럼 왜 이런 판단을 했는지 설명해야 하는 상황이라면 해석 가능성이 중요한 선정 기준이 될 수 있어.

복잡도

모형이 지나치게 복잡하면 학습 데이터에는 아주 잘 맞는데 새로운 데이터에서는 성능이 떨어질 수 있어.

이게 바로 과적합(overfitting) 문제와 연결돼.

그래서 후보 모형을 비교할 때는 단순히 학습 데이터 성능만 보면 안 되고, 검증 데이터나 테스트 데이터에서 일반화 성능을 확인해야 해.

계산 비용

데이터가 매우 크거나 실시간 예측이 필요한 상황이라면,

학습 시간

예측 시간

메모리 사용량

하드웨어 요구사항

같은 계산 자원도 고려할 수 있어.

운영·적용 가능성

실제로 서비스에 적용할 수 있는지도 중요해.

가령 성능이 조금 더 높은 모델이 있더라도,

지나치게 느리거나

유지보수가 어렵거나

결과 설명이 불가능하다면

다른 후보가 최종 선택될 수도 있어.

🥊 4. 후보 모형 비교: 같은 조건에서 비교해야 한다

후보 모형 비교에서 핵심 원칙은 공정한 비교야.

같은 데이터셋을 두고 모형 A는 학습 데이터 정확도, 모형 B는 테스트 데이터 정확도로 비교하면 의미가 없겠지.

보통은 동일한 학습·검증 조건에서 여러 후보 모델을 평가해.

흐름으로 보면:

후보 모형 생성

↓

동일한 데이터와 평가기준 적용

↓

평가지표 측정

↓

복잡도·해석력·운영성 등 함께 검토

↓

최종 모형 선정

이렇게 이해하면 돼.

🧠 시험에서 구별해야 할 세 가지
“분석 목적”과 “평가지표”는 다르다

예를 들어:

목적: 고객 이탈 여부 분류

모형: 로지스틱 회귀

평가: 정확도, 재현율, F1-score 등

이 세 층을 섞지 않는 게 중요해.

“후보 모형”과 “최종 모형”도 다르다

후보 모형은 비교 대상이고,

최종 모형은 평가기준에 따라 선택된 결과야.

“가장 복잡한 모형 = 가장 좋은 모형”이 아니다

시험에서 은근히 함정으로 쓰기 좋아.

복잡한 모델일수록 항상 좋은 게 아니고, 일반화 성능·해석 가능성·비용·운영 가능성까지 고려해야 해.

🔗 한 번에 연결하면

이 단원을 하나의 문장으로 압축하면 이렇게 돼.

분석 목적과 데이터 특성에 적합한 여러 후보 모형을 선정하고, 적절한 평가기준을 사용하여 성능·복잡도·해석 가능성·운영 가능성 등을 비교한 뒤 최종 분석모형을 선택한다.

필기에서는 이 문장을 머릿속 기준선으로 잡으면 선지가 많이 정리돼.

특히 아래 연결은 바로 떠올릴 수 있게 만들어두자.

범주 예측 → 분류

연속형 수치 예측 → 회귀

정답 없이 유사한 대상 묶기 → 군집

후보 모델 평가 → 동일 조건에서 비교

좋은 모델 → 성능만이 아니라 일반화·해석성·복잡성까지 고려

📌 필기용 초압축 정리

분석모형 선정의 3축

목적 적합성

성능 적합성
적절한 평가 지표에서 충분한 성능을 보이는가?

활용 적합성

이 세 축으로 선지를 보면 단순 암기보다 훨씬 안정적으로 풀 수 있어.
