Requirements

1. 도구 요구조건 — 무엇을 먼저 봐야 할까?

도구를 고르기 전에 먼저 “이 분석 환경이 무엇을 요구하는가?”를 정해야 해. 몇 MB의 표와 수십 TB의 로그는 같은 조건으로 도구를 고를 수 없지.

기능성회귀·분류·시각화?
데이터 처리 능력대용량·비정형?
성능충분히 빠른가?
확장성규모 증가 대응?
호환성기존 시스템 연계?
사용 편의성학습·UI 난이도?
비용도입·운영비?
보안민감정보 보호?
유지보수성지원·업데이트?
발견해야 할 원리

어느 조건 하나가 항상 최우선인 게 아니야. 요구조건의 우선순위는 분석 목적과 환경에 따라 달라진다.

Python과 R, 너무 단순하게 외우면 생기는 함정

“Python = 머신러닝, R = 통계”라고만 외우면 위험해. 둘 다 통계와 머신러닝을 할 수 있어. 중요한 건 어떤 생태계와 활용 목적에서 상대적인 강점을 가지느냐야.

🧭
Fit by Purpose

3. 목적별 선정 — 상황을 보면 도구가 보인다

통계 분석 중심 → R

가설검정, 회귀분석, 분산분석처럼 통계 분석 기능이 핵심 요구라면 R 등의 통계 분석 환경이 유력해.

머신러닝 개발 → Python

전처리 → 학습 → 평가 → 배포까지 이어지는 작업이라면 다양한 라이브러리와 개발 환경을 갖춘 Python이 적합할 수 있어.

관계형 DB 조회·집계 → SQL

지역별 월 매출처럼 DB 내부의 조회·필터링·집계가 핵심이면 SQL이 먼저야.

초대용량 분산 처리 → Hadoop / Spark

한 서버로 처리하기 어려운 데이터라면 단일 컴퓨터 분석에서 분산 저장·분산 처리 환경으로 넘어가야 해.

Exam Traps

시험에서 만드는 세 가지 함정

“가장 뛰어난 분석 도구를 선택한다.”

절대적인 1등을 찾는 게 아니라 요구조건에 가장 적합한 도구를 찾는 거야.

“기능이 많을수록 적합하다.”

비용, 연동, 사용자 역량, 보안 조건을 만족하지 못하면 기능이 많아도 부적합할 수 있어.

“하나의 도구로 전체 분석을 해야 한다.”

아니야. SQL + Python + Spark처럼 목적에 따라 여러 도구를 조합할 수 있어.

📌 필기용 압축 정리

분석 도구 선정은 분석 목적과 환경에 필요한 요구조건을 정의하고, 후보 도구의 기능과 특성을 비교하여 가장 적절한 도구를 선택하는 과정이야.

기능성 · 성능 · 확장성 · 호환성 · 사용 편의성 · 비용 · 보안 · 유지보수

한 단계 더 이해하면

시험에서 처음 보는 도구가 등장해도 이름부터 외우려고 하지 마. 먼저 “이 상황에서 필요한 능력은 무엇이지?”라고 물어봐. 대용량·확장성이 강조되면 그 조건에 강한 도구를, 소규모 통계 분석이 핵심이면 그 목적에 적합한 도구를 고르면 돼.

결국 이 단원의 진짜 공식은 도구 이름 → 목적이 아니라 상황 → 요구조건 → 비교 → 적합한 도구야.
