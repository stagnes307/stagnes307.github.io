🧩 쪼개는 순간부터 시험이 시작된다

데이터 분할의 핵심은 비율 암기가 아니라, 모델이 학습 과정에서 보지 말아야 할 정보를 미리 보지 못하게 하면서 성능을 공정하게 측정하는 것이야.

이 목적 하나를 잡으면 학습·검증·평가 데이터의 역할, 홀드아웃·교차검증 같은 분할 방법, 그리고 데이터 누수 방지가 한 덩어리로 연결돼.

학습 → 조정 → 최종 평가

🎯 먼저 세 데이터의 역할부터 구분하자

전체 데이터가 있다고 해보자. 모델을 만드는 과정에는 서로 다른 세 가지 질문이 있어. 무엇을 보고 배우는가, 어떤 모델과 설정이 더 좋은지 무엇으로 결정하는가, 그리고 처음 보는 데이터에서도 잘 작동하는지 무엇으로 확인하는가.

🧠 왜 데이터를 굳이 나눠야 할까?

모델의 목적은 이미 본 데이터를 잘 맞히는 게 아니라 앞으로 들어올 새로운 데이터를 잘 예측하는 거야. 같은 데이터로 학습하고 같은 데이터로 성능을 재면, 이미 답을 본 문제를 다시 풀게 만드는 셈이지.

✂️ 데이터 분할 방법

홀드아웃 — 한 번 나누고 그대로 사용

전체 데이터를 일정 비율로 한 번 분리하는 가장 단순한 방법이야. 비율은 절대적인 규칙이 아니라 데이터 규모와 목적에 따라 달라져.

구분 비율 예시 역할
학습60~80%모델 학습
검증10~20%모델 선택·튜닝
평가10~20%최종 성능 평가

무작위 분할 — 데이터 순서의 영향을 줄인다

독립 표본 데이터라면 보통 무작위로 섞은 뒤 분할해. 다만 시계열 데이터에서는 함부로 섞으면 안 돼. 실제 운영에서는 과거로 미래를 예측하니까 시간 순서를 보존해야 해.

2023 → 2024 → 2025 → 2026

LOOCV — 하나만 남겨 검증

데이터가 N개라면 매번 하나만 검증에 두고 N-1개로 학습해. 사실상 K=N인 K-Fold라고 보면 돼. 데이터 활용률은 높지만 계산 부담이 커.

계층적 분할 — 클래스 비율 유지

불균형 분류에서는 원래 데이터의 클래스 비율이 학습·검증·평가 세트에서도 비슷하게 유지되도록 나누는 게 중요해.

전체 데이터
정상 95% · 사기 5%
분할 후 각 세트
정상 95% · 사기 5%에 가깝게 유지

🚨 데이터 누수 — 시험에서 특히 중요한 핵심

데이터 누수는 모델이 실제 예측 시점에는 알 수 없어야 하는 정보를 학습 과정에서 이용하게 되는 현상이야. 그러면 성능이 실제보다 훨씬 좋아 보일 수 있어.

이 정보가 실제 예측 시점에 모델에게 존재하는가?

평가 데이터가 전처리에 들어가는 경우

전체 데이터의 평균과 표준편차를 먼저 계산해 표준화한 뒤 Train/Test로 나누면, 평가 데이터의 통계 정보가 이미 학습 전처리에 섞인 거야.

잘못된 순서
전체 데이터 → 평균·표준편차 계산 → 표준화 → 분할
바람직한 순서
분할 → Train에서 기준 계산 → Train 변환 → 같은 기준으로 Test 변환

결측값 처리

평균 대체라면 Train의 평균을 계산하고, 그 값을 Train과 Validation/Test에 적용해야 해.

특성 선택

전체 데이터로 중요한 변수를 먼저 골라놓고 교차검증하면 이미 검증 데이터의 정보가 변수 선택에 들어간 셈이야. 특성 선택은 각 Fold의 학습 부분 안에서 수행해야 해.

미래 정보가 들어가는 경우

예측 시점 이후에만 알 수 있는 변수가 입력에 포함되면 시간적 누수가 발생해. 시계열에서는 미래 정보가 과거 학습으로 흘러들지 않게 막아야 해.

🧭 세 개념을 하나의 흐름으로 연결하면

Validation/Test의 정보가 Train 과정으로 흘러 들어가면 안 된다.

💡 자주 헷갈리는 함정 세 가지

검증 데이터도 학습 데이터인가?

모델 파라미터를 직접 학습시키는 데이터는 아니야. 다만 검증 결과를 보고 모델과 하이퍼파라미터를 바꾸므로 개발 과정에는 영향을 줘.

교차검증을 하면 Test가 필요 없나?

단정하면 위험해. 교차검증으로 모델과 설정을 정한 뒤, 별도의 Test 세트로 최종 성능을 확인할 수 있어.

먼저 정규화하고 나누면 왜 문제인가?

정규화 자체가 아니라 기준값을 어디서 계산했는지가 핵심이야. Train에서 기준을 배우고 Validation/Test에는 그 기준을 적용해야 해.
