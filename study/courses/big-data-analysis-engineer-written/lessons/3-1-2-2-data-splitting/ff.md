🧩 [쪼개는 순간부터 시험이 시작된다] 3-1-2-2. 데이터 분할

#빅데이터분석기사 #필기 #분석모형설계 #분석환경구축 #데이터분할 #데이터누수

빅데이터분석기사에서 데이터 분할은 단순히 “데이터를 7:3으로 나눈다” 정도로 외우면 자꾸 헷갈려. 핵심은 딱 하나야.

모델이 학습 과정에서 보지 말아야 할 정보를 미리 보지 못하게 하면서, 성능을 공정하게 측정하는 것.

이 목적을 잡아두면 학습·검증·평가 데이터의 역할, 홀드아웃·교차검증 같은 분할 방법, 데이터 누수 방지가 한 덩어리로 연결돼.

그리고 이 학습 상태는 나중에 **저장**이라고 입력하면 이어서 공부할 수 있게 저장할 수 있어. .cc를 붙이면 같은 내용을 HTML 학습 화면 형태로도 볼 수 있고.

🎯 먼저 세 데이터의 역할부터 구분하자

전체 데이터가 있다고 해보자. 모델을 만드는 과정에는 사실 서로 다른 세 가지 질문이 있어.

모델은 무엇을 보고 배우는가?

어떤 모델·설정이 더 좋은지 무엇으로 결정하는가?

최종적으로 처음 보는 데이터에서도 잘 작동하는지 무엇으로 확인하는가?

이 세 질문에 각각 대응하는 게 학습(Train), 검증(Validation), 평가(Test) 데이터야.

학습 데이터 — 모델의 파라미터를 배우는 데이터

학습 데이터(Training data)는 모델이 실제로 학습하는 데이터야.

예를 들어 선형회귀라면 회귀계수를 추정하고, 의사결정나무라면 어떤 변수와 기준으로 분기할지를 정하고, 신경망이라면 가중치를 조정하는 데 사용하지.

즉,

학습 데이터 → 모델 내부의 파라미터 결정

이라고 보면 돼.

예를 들어 고객 이탈 예측 데이터 10,000건 중 7,000건을 학습에 사용한다면, 모델은 이 7,000건 안에서 고객 특성과 이탈 여부 사이의 패턴을 배워.

검증 데이터 — 모델을 선택하고 조정하는 데이터

여기서 많이 헷갈리는 지점이 나와.

검증 데이터(Validation data)는 모델 자체를 직접 학습시키는 데 쓰는 게 아니라,

여러 모델 중 어떤 모델을 쓸지

하이퍼파라미터를 어떻게 설정할지

언제 학습을 중단할지

같은 모델 선택과 튜닝에 사용해.

예를 들어 의사결정나무의 최대 깊이를 비교한다고 해보자.

깊이 3 → 검증 정확도 82%

깊이 5 → 검증 정확도 87%

깊이 10 → 검증 정확도 83%

그러면 검증 데이터를 기준으로 깊이 5를 선택할 수 있겠지.

여기서 중요한 구분은:

파라미터(parameter)는 학습 데이터로 배우고,
하이퍼파라미터(hyperparameter)는 검증 성능을 참고해 선택한다.

평가 데이터 — 마지막 한 번의 공정한 성능 측정

평가 데이터(Test data)는 모델 개발이 끝난 뒤 최종 성능을 확인하는 데이터야.

그래서 모델 선택이나 하이퍼파라미터 조정 과정에서 평가 데이터를 계속 들여다보면 안 돼.

왜냐하면 평가 데이터 결과를 보고 계속 모델을 수정하면 결국 모델이 평가 데이터에도 간접적으로 맞춰지기 때문이야.

구조를 한 줄로 연결하면 이렇게 돼.

학습 데이터 → 모델 학습
검증 데이터 → 모델 선택·튜닝
평가 데이터 → 최종 일반화 성능 확인

여기서 시험에서 가장 중요한 단어가 일반화(generalization)야.

일반화는 모델이 학습에 사용하지 않은 새로운 데이터에서도 좋은 성능을 내는 능력을 뜻해.

🧠 왜 데이터를 굳이 나눠야 할까?

모델의 목적은 이미 알고 있는 데이터를 잘 맞히는 것이 아니야.

앞으로 들어올 새로운 데이터를 잘 예측하는 것이 목적이지.

만약 데이터를 전부 학습에 사용한 뒤 그 데이터로 성능까지 측정하면 어떻게 될까?

모델이 이미 본 문제를 다시 풀게 되는 셈이야.

예를 들어 어떤 학생이 시험 문제와 정답을 통째로 외운 다음 똑같은 문제로 시험을 본다면 100점을 받을 수도 있어. 하지만 그 점수가 실제 실력을 의미한다고 보기는 어렵지.

모델도 똑같아.

그래서

학습에 사용한 데이터 ≠ 최종 성능을 측정하는 데이터

라는 원칙이 필요해.

✂️ 데이터 분할 방법

시험에서는 단순 분할부터 교차검증까지 연결해서 알아두면 좋아.

홀드아웃 — 한 번 나누고 그대로 사용하는 방법

홀드아웃(Hold-out)은 전체 데이터를 일정 비율로 한 번 분리하는 가장 단순한 방법이야.

예를 들어:

구분	비율 예시	역할
학습 데이터	60~80%	모델 학습
검증 데이터	10~20%	모델 선택·튜닝
평가 데이터	10~20%	최종 성능 평가

비율 자체가 절대적인 규칙은 아니야.

70 : 15 : 15, 60 : 20 : 20, 80 : 10 : 10 등 데이터 규모와 목적에 따라 달라질 수 있어.

홀드아웃의 장점은 간단하고 계산이 빠르다는 것이야.

하지만 데이터가 적다면 문제가 생겨.

어떤 데이터가 우연히 학습 세트에 들어가고 어떤 데이터가 평가 세트에 들어갔느냐에 따라 성능 결과가 크게 바뀔 수 있거든.

무작위 분할 — 데이터 순서의 영향을 줄인다

일반적인 독립 표본 데이터라면 데이터를 무작위로 섞은 뒤 분할하는 경우가 많아.

예를 들어 데이터가 원래 이렇게 정렬되어 있다고 해보자.

정상 고객 → 정상 고객 → ... → 이탈 고객 → 이탈 고객

앞에서 80%를 학습 데이터로, 뒤에서 20%를 평가 데이터로 단순히 자르면 학습 데이터와 평가 데이터의 분포가 완전히 달라질 수 있겠지.

그래서 흔히 랜덤 셔플 후 분할을 사용해.

그런데 여기에도 중요한 예외가 있어.

시계열 데이터는 함부로 섞으면 안 된다

시간의 흐름이 중요한 데이터라면 무작위 분할이 오히려 잘못된 방법이 될 수 있어.

예를 들어:

2023년 → 2024년 → 2025년 → 2026년

매출 데이터를 예측한다고 해보자.

2026년 데이터를 학습시키고 2024년을 예측하게 만드는 건 실제 운영 상황과 맞지 않아.

현실에서는 항상 과거로 미래를 예측하니까.

그래서 시계열 데이터에서는 보통:

과거 데이터 → 학습
더 최근 데이터 → 검증
가장 최근 데이터 → 평가

처럼 시간 순서를 보존해야 해.

이건 데이터 누수와도 바로 연결돼.

🔄 교차검증 — 한 번의 분할이 불안할 때

데이터가 충분히 많지 않으면 한 번의 홀드아웃 결과가 우연에 크게 영향을 받을 수 있어.

그래서 등장하는 것이 교차검증(Cross Validation)이야.

가장 대표적인 것이 K-겹 교차검증(K-Fold Cross Validation)이야.

전체 데이터를 K개의 묶음으로 나누고, 그중 하나를 검증용으로 사용하고 나머지를 학습용으로 사용해.

예를 들어 5-Fold라면:

1회: [검증][학습][학습][학습][학습]
2회: [학습][검증][학습][학습][학습]
3회: [학습][학습][검증][학습][학습]
4회: [학습][학습][학습][검증][학습]
5회: [학습][학습][학습][학습][검증]

각 데이터가 한 번씩 검증 데이터 역할을 하게 되고, 나온 성능들을 평균내는 식이야.

이렇게 하면 한 번의 우연한 분할보다 모델 성능을 좀 더 안정적으로 추정할 수 있어.

K값이 커지면 어떻게 될까?

K가 커질수록 한 번의 학습에 사용하는 데이터는 많아져.

예를 들어:

5-Fold → 매번 약 80% 학습

10-Fold → 매번 약 90% 학습

하지만 K가 커질수록 모델을 더 많이 학습해야 하니까 계산량도 증가해.

따라서 시험에서는 보통 다음 관계를 기억하면 충분해.

K 증가 → 학습 데이터 비율 증가 + 계산량 증가

LOOCV — 한 건만 검증에 사용하는 극단적인 교차검증

LOOCV(Leave-One-Out Cross Validation)는 데이터가 N개라면 매번 1개만 검증 데이터로 두고 나머지 N-1개로 학습하는 방식이야.

즉 사실상 K=N인 K-Fold라고 볼 수 있어.

데이터 활용률은 높지만 모델을 N번 학습해야 하므로 데이터가 많으면 계산 부담이 커져.

⚖️ 분류에서는 계층적 분할을 주의하자

분류 문제에서 특정 클래스가 매우 적다면 단순 랜덤 분할도 위험할 수 있어.

예를 들어 전체 데이터가:

정상: 950명

사기: 50명

이라고 해보자.

운이 나쁘면 검증 데이터나 평가 데이터에 사기 사례가 지나치게 적게 들어갈 수도 있어.

그래서 계층적 분할(Stratified Split)을 사용하면 각 데이터셋의 클래스 비율을 원래 데이터와 비슷하게 유지할 수 있어.

예를 들면 원 데이터가:

정상 95% / 사기 5%

라면 학습·검증 데이터도 대략:

정상 95% / 사기 5%

가 되도록 나누는 거야.

분류 문제에서 불균형 데이터가 보이면 이 개념을 같이 떠올리면 좋아.

🚨 데이터 누수 — 시험에서 특히 중요한 핵심

이제 이 단원의 제일 중요한 부분이야.

데이터 누수(Data Leakage)란 모델이 실제 예측 시점에는 알 수 없어야 하는 정보를 학습 과정에서 이용하게 되는 현상이야.

이렇게 되면 모델 성능이 실제보다 훨씬 좋게 나타날 수 있어.

가장 중요한 판단 기준은:

“이 정보가 실제 예측 시점에 모델에게 존재하는가?”

야.

🔓 대표적인 누수 ① 평가 데이터가 학습 과정에 들어가는 경우

가장 명백한 누수야.

예를 들어 전체 데이터를 먼저 표준화한 뒤 학습/평가 데이터로 분할했다고 생각해보자.

표준화에는 전체 데이터의 평균과 표준편차가 들어가.

즉 평가 데이터의 통계 정보가 이미 학습 전처리에 섞인 거야.

잘못된 순서:

전체 데이터
↓
평균·표준편차 계산
↓
표준화
↓
Train / Test 분할

바람직한 순서는:

전체 데이터
↓
Train / Test 분할
↓
Train 데이터로 평균·표준편차 계산
↓
Train 변환
↓
같은 기준으로 Test 변환

여기서 중요한 원칙을 하나 뽑을 수 있어.

전처리도 학습의 일부다.

그래서 데이터에서 어떤 값을 추정(fit)하는 전처리는 일반적으로 학습 데이터만 이용해야 해.

🔓 대표적인 누수 ② 결측값 처리

평균값으로 결측값을 대체한다고 해보자.

전체 데이터의 평균을 먼저 계산한 뒤 데이터를 나누면 평가 데이터의 정보가 평균 계산에 포함돼.

따라서:

Train의 평균 계산 → Train 결측값 대체 → 같은 평균으로 Validation/Test 변환

처럼 처리해야 해.

표준화와 구조가 똑같지?

여기서 시험용 패턴이 보이기 시작해.

평균, 표준편차, 중앙값, 범주 빈도 등
데이터에서 ‘배워야 하는 값’은 Train에서 계산한다.

🔓 대표적인 누수 ③ 특성 선택

변수를 100개 가지고 있다고 해보자.

전체 데이터를 대상으로 목표변수와의 관계를 분석해 가장 좋은 변수 10개를 먼저 골라버린 뒤 교차검증을 한다면?

이미 검증 데이터의 정보를 사용해서 변수 선택을 한 거야.

따라서 올바른 구조는 교차검증의 각 학습 Fold 안에서 특성 선택을 수행하는 거야.

즉:

각 Fold
   ↓
Train 부분에서 특성 선택
   ↓
모델 학습
   ↓
Validation 부분에서 평가

이 원칙 때문에 실무 머신러닝에서는 전처리와 모델을 Pipeline으로 묶는 경우가 많아.

🔓 대표적인 누수 ④ 미래 정보가 들어가는 경우

고객이 대출을 연체할지를 예측한다고 해보자.

그런데 입력 변수에 연체 후 발생한 독촉 횟수가 들어가 있다면?

모델 입장에서는 예측하려는 사건의 결과를 사실상 미리 보고 있는 거야.

이런 걸 흔히 시간적 누수(temporal leakage)라고 생각할 수 있어.

시계열 데이터에서는 특히:

미래 → 과거로 정보가 넘어가지 않도록

주의해야 해.

그리고 이 전체 과정을 감싸는 규칙이:

Validation/Test의 정보가 Train 과정으로 흘러 들어가면 안 된다.

즉 데이터 누수 방지는 별도의 한 항목이 아니라 데이터 분할의 목적 자체를 지키는 원칙이라고 보면 돼.

문장을 읽었을 때 다음처럼 연결해.

여기서 하나만 특히 잡자.

“Test는 마지막에만 쓴다.”

검증 데이터와 평가 데이터를 헷갈릴 때 가장 강한 기준이야.

검증 데이터는 모델을 고르는 과정에 개입하지만, 평가 데이터는 이미 결정된 모델을 마지막으로 재는 데 사용해.

💡 자주 헷갈리는 함정 세 가지
“검증 데이터도 학습 데이터 아닌가?”

엄밀히 역할을 나누면 아니야.

모델의 파라미터 자체는 Train으로 학습해.

다만 검증 결과를 보고 하이퍼파라미터와 모델 구조를 변경하기 때문에 모델 개발 과정에는 영향을 준다.

그래서 Validation은 완전히 독립적인 최종 평가 데이터가 될 수 없어.

“교차검증을 하면 Test 데이터가 필요 없나?”

그렇게 단정하면 위험해.

교차검증은 주로 모델 선택과 성능 추정에 사용되지만, 최종적으로 완전히 독립된 성능을 확인하려면 별도의 Test 세트를 남겨둘 수 있어.

예를 들면:

전체 데이터
    ↓
Train 영역 80% ───── Test 20%
    ↓
Train 영역 안에서 5-Fold CV
    ↓
모델·하이퍼파라미터 결정
    ↓
Test로 최종 평가

이 구조가 아주 중요해.

“데이터를 먼저 정규화하고 나누면 왜 문제지?”

정규화 자체가 문제인 게 아니야.

정규화에 필요한 값을 어디서 계산했는가가 문제야.

예를 들어 최소-최대 정규화라면 최소값과 최대값을 데이터에서 계산하지.

평가 데이터까지 포함해 그 값을 계산하면 평가 정보가 학습 단계로 들어온 셈이야.

따라서:

분할 → Train에서 전처리 기준 학습 → Validation/Test에 적용

이 순서를 기억해.

🧠 [시험용 압축 기억법] “학-조-최 / 먼저 나누고 배운다”

학습 데이터 → 학습
검증 데이터 → 조정
평가 데이터 → 최종 평가

그리고 누수 방지는:

먼저 나누고, Train에서 배운다.

표준화든 결측값 대체든 특성 선택이든 데이터에서 기준을 배우는 과정은 Train에 먼저 맞춘다고 기억하면 대부분의 누수 문제를 풀 수 있어.
