이번 범위는 “형태가 일정하지 않은 데이터를 어떻게 분석 가능한 형태로 바꾸고, 어떤 절차로 분석하며, 결과를 어떻게 읽는가”가 핵심이야.

시험에서는 세부 알고리즘을 깊게 계산시키기보다, 보통 비정형 데이터 → 표현 → 전처리·분석 → 결과 해석의 흐름과 용어 구분을 묻는 경우가 많아. 이 흐름부터 잡으면 암기량이 꽤 줄어들어.

참고로 지금 학습 상태는 저장이라고 입력하면 보존할 수 있어. 또 .cc를 붙이면 같은 내용을 HTML 학습 화면 형태로 볼 수도 있어.

🧭 먼저 큰 그림: 비정형 데이터는 왜 바로 분석하기 어려울까?

정형 데이터는 행과 열이 이미 정해져 있어.

고객ID	나이	구매액
A01	31	120000
A02	44	83000

이런 데이터는 숫자나 범주가 어느 칸에 들어가는지 명확하지.

반면 비정형 데이터는 이런 식이야.

“배송은 빨랐는데 제품 품질은 기대보다 별로였어요.”

이 문장 자체에는 행·열 구조가 없어. 컴퓨터가 통계적·수학적 분석을 하려면 결국 이 문장을 숫자 형태로 변환해야 해.

그래서 비정형 데이터 분석의 중심 질문은 하나야.

“의미를 최대한 보존하면서 어떻게 수치적 표현으로 바꿀 것인가?”

🧱 1. 비정형 데이터 표현

비정형 데이터에는 텍스트, 이미지, 음성, 영상 등이 있지만 빅데이터분석기사 필기에서는 특히 텍스트 데이터의 표현 방식을 중심으로 보는 게 좋아.

단어를 분석 단위로 나누기

문장을 그대로 계산할 수는 없으니 먼저 분석 가능한 단위로 분해해.

예를 들어,

데이터 분석은 재미있다.

를

데이터 / 분석 / 재미

처럼 나눌 수 있어.

이때 사용되는 대표적인 과정이 토큰화(Tokenization)야.

한국어에서는 조사와 어미가 붙기 때문에 형태소 분석도 중요해.

예를 들어,

데이터를 분석했다

를 단순 공백 기준으로 보면

데이터를 / 분석했다

지만 형태소 단위에서는

데이터 / 분석

처럼 핵심 의미 단위를 추출할 수 있어.

불필요한 단어를 제거하기

분석 목적에 별 도움이 되지 않는 단어는 제거할 수 있어.

이를 불용어(Stopword) 제거라고 해.

예를 들어

이 제품은 정말 매우 좋은 제품입니다.

에서 분석 목적에 따라

이, 은, 정말, 매우

등을 제거하고

제품, 좋다

같은 핵심 단어를 남길 수 있어.

즉,

텍스트 → 토큰화 → 정제 → 분석 가능한 단어 집합

이라는 흐름이 생겨.

🔢 단어를 숫자로 만드는 가장 기본적인 방법
Bag of Words, BoW

BoW는 문장에서 단어가 등장했는지 또는 몇 번 등장했는지를 숫자로 표현하는 방식이야.

두 문장이 있다고 해보자.

문서 1: 빅데이터 분석 재미

문서 2: 빅데이터 분석 중요

전체 단어가

빅데이터 / 분석 / 재미 / 중요

라면 이렇게 표현할 수 있어.

문서	빅데이터	분석	재미	중요
문서 1	1	1	1	0
문서 2	1	1	0	1

이렇게 만들어진 구조를 문서-단어 행렬(Document-Term Matrix, DTM)이라고 볼 수 있어.

핵심은 단순해.

행 = 문서, 열 = 단어, 값 = 단어의 출현 정보

다만 BoW에는 중요한 약점이 있어.

나는 빅데이터를 좋아한다

와

빅데이터를 나는 좋아한다

처럼 단어 순서가 달라도 비슷한 표현이 될 수 있어.

즉, 단어의 순서와 문맥을 충분히 반영하지 못한다.

⚖️ TF-IDF: 자주 나오지만 아무 데서나 나오는 단어는 덜 중요하게

단순 빈도만 사용하면 문제가 하나 생겨.

어떤 단어가 거의 모든 문서에 많이 등장한다면, 그 단어는 특정 문서의 특징을 설명하는 데 별 도움이 되지 않을 수 있어.

그래서 사용하는 대표적인 방식이 TF-IDF야.

TF — Term Frequency

특정 문서에서 해당 단어가 얼마나 자주 등장했는지를 나타내.

쉽게 말하면,

“이 문서에서 이 단어가 얼마나 중요한가?”

를 보는 첫 번째 요소야.

IDF — Inverse Document Frequency

반대로 해당 단어가 전체 문서에서 얼마나 흔한지를 반영해.

여러 문서에 거의 다 등장하는 단어라면 구별력이 떨어지니까 가중치를 낮춰.

직관적으로는 이렇게 기억하면 돼.

TF-IDF 값이 커지는 경우

한 문서에서는 자주 등장하지만
전체 문서에서는 흔하지 않은 단어

즉, 그 문서를 특징짓는 단어일 가능성이 높아.

시험용 구분

TF가 높다 → 해당 문서에서 많이 등장

IDF가 높다 → 전체 문서에서는 드물게 등장

TF-IDF가 높다 → 특정 문서를 잘 대표할 가능성이 큼

🧠 임베딩: 단어의 의미까지 숫자로 표현하기

BoW와 TF-IDF는 기본적으로 단어의 출현 정보를 중심으로 표현해.

그런데 사람은

왕 - 남자 + 여자 ≈ 여왕

처럼 단어 사이의 의미 관계도 이해하지.

이런 의미적 관계를 벡터 공간에서 표현하려는 방식이 워드 임베딩(Word Embedding)이야.

대표적으로 알고 있어야 할 이름은:

Word2Vec

GloVe

FastText

등이 있어.

단어를 단순히

[0, 0, 1, 0, ...]

같이 표현하는 게 아니라,

[0.21, -0.54, 0.88, ...]

처럼 저차원의 실수 벡터로 표현하는 거야.

의미가 비슷한 단어는 벡터 공간에서도 비교적 가까운 위치에 나타날 수 있어.

BoW·TF-IDF와 임베딩의 차이
방식	핵심	장점	한계
BoW	단어 출현 빈도	단순하고 이해하기 쉬움	순서·문맥 반영 어려움
TF-IDF	문서별 단어 중요도	문서를 특징짓는 단어 파악	의미 관계 표현이 제한적
임베딩	단어의 의미적 벡터 표현	유사성·의미 관계 반영	모델과 학습 과정 필요

시험에서는 이 셋을 완전히 같은 것으로 보면 안 돼.

빈도 기반 표현 ↔ 의미 기반 표현

이라는 대비가 중요해.

🔄 2. 비정형 데이터 분석 절차

이 부분은 순서를 하나의 파이프라인으로 이해해야 해.

원본 데이터 → 수집 → 전처리 → 표현 → 분석 → 평가·해석
① 데이터 수집

분석 목적에 맞는 데이터를 확보해.

예를 들면:

뉴스 기사

SNS 게시물

고객 리뷰

상담 기록

웹 문서

이미지·영상·음성

여기서 중요한 건 단순히 많이 모으는 게 아니라 분석 목적과 관련 있는 데이터를 확보하는 것이야.

② 전처리

비정형 데이터는 잡음이 많아.

텍스트라면 대표적으로:

결측·중복 데이터 처리

특수문자 제거

대소문자 통일

토큰화

형태소 분석

불용어 제거

어간 추출

표제어 추출

등을 수행할 수 있어.

어간 추출과 표제어 추출

둘은 비슷하지만 개념적으로 구분할 수 있어.

어간 추출(Stemming)은 단어에서 어미 등을 제거하여 어간을 얻는 방식이고,

표제어 추출(Lemmatization)은 단어의 문법적·사전적 형태를 고려해 기본형을 찾는 방식이야.

둘 다 궁극적으로는

서로 다른 형태로 나타난 단어를 일정한 형태로 통일

하려는 목적이 있어.

🧮 ③ 데이터 표현 및 특징 추출

전처리한 텍스트를 이제 실제 분석 가능한 숫자로 변환해.

대표적으로:

BoW

DTM

TF-IDF

Word Embedding

등을 사용할 수 있어.

여기서 특징(Feature)이라는 개념을 연결하면 좋아.

머신러닝에서 분석 모델에 넣는 정보가 특징이니까,

텍스트의 단어나 임베딩 벡터가 결국 분석용 특징이 되는 거야.

🔍 ④ 분석기법 적용

표현까지 끝나면 목적에 따라 분석 방법을 선택해.

문서 분류

문서를 미리 정해둔 범주에 넣는 작업이야.

예:

고객 리뷰 → 긍정 / 부정

이건 대표적으로 지도학습 분류 문제가 될 수 있어.

감성 분석

텍스트에서 긍정·부정·중립 등의 감성을 분석해.

예를 들어:

“배송은 빠르지만 품질은 별로다.”

단순히 긍정 단어 하나, 부정 단어 하나를 세는 것보다 문맥을 고려해야 정확도가 올라가겠지.

군집 분석

정답 범주가 없는 문서들을 유사도에 따라 그룹화해.

예를 들어 고객 문의를 자동으로 묶어 보면:

배송 관련

환불 관련

제품 불량 관련

결제 관련

같은 집단이 만들어질 수 있어.

이는 비지도학습과 연결돼.

토픽 모델링

대량의 문서에서 숨어 있는 주요 주제를 추출해.

대표적으로 알아둘 알고리즘은 LDA(Latent Dirichlet Allocation)야.

예를 들어 뉴스 기사 수천 건을 분석했더니

경제

부동산

금리

환율

같은 토픽이 발견될 수 있어.

LDA에서 중요한 생각은

하나의 문서는 여러 토픽이 섞여 있고,
하나의 토픽은 여러 단어의 확률 분포로 표현될 수 있다.

는 거야.

🧭 3. 결과 해석

여기에서 자주 생기는 실수가 있어.

분석 결과로 숫자가 나왔다고 해서 그 숫자가 곧바로 현실의 의미가 되는 건 아니야.

결과는 반드시 분석 목적과 데이터의 맥락 안에서 해석해야 해.

단어 빈도 해석

어떤 고객 리뷰에서 배송이라는 단어가 가장 많이 등장했다고 해보자.

바로

“고객은 배송에 만족한다.”

라고 결론 내릴 수 있을까?

아니야.

배송이 너무 느리다

때문에 배송이라는 단어가 많이 등장했을 수도 있어.

즉,

빈도는 관심의 크기를 보여줄 수 있지만 긍정·부정의 방향까지 자동으로 설명하지는 않는다.

이 구분은 중요해.

TF-IDF 결과 해석

어떤 문서에서 환불의 TF-IDF가 높다고 해보자.

그 의미는 대체로

해당 문서에서는 환불이 자주 나타나면서, 다른 문서에서는 상대적으로 흔하지 않다.

는 뜻이야.

따라서 해당 문서를 특징짓는 핵심 단어일 가능성이 높아.

하지만 이것 역시

“환불 문제가 실제로 가장 심각하다.”

라는 현실적 인과관계를 자동으로 증명하는 건 아니야.

군집 분석 결과 해석

군집 분석에서 4개의 군집이 나왔다면 먼저 각 군집의 특징을 살펴야 해.

예를 들어:

군집	자주 등장하는 단어	해석
1	배송, 늦음, 택배	배송 문제
2	환불, 취소, 결제	환불·결제 문제
3	품질, 고장, 불량	제품 품질 문제

여기서 군집 번호 자체에는 의미가 없어.

군집 1이 군집 2보다 우월하거나 중요한 것이 아니라, 각 군집 안에 포함된 특징을 보고 사람이 의미를 부여해야 해.

토픽 모델링 결과 해석

LDA 같은 토픽 모델링에서는 보통 각 토픽에 높은 확률로 등장하는 단어를 보고 주제를 해석해.

예를 들어:

토픽 A: 금리, 은행, 대출, 기준금리, 인상

이라면 사람이 이를

“금리 및 금융정책”

같은 이름으로 붙일 수 있어.

여기서도 중요한 점은:

모델이 토픽 번호를 만들 뿐, 토픽의 의미와 이름은 분석자가 해석한다.

⚠️ 시험에서 헷갈리는 경계 세 가지
빈도와 중요도는 같은가?

아니야.

단어 빈도가 높다고 반드시 중요한 것은 아니야.

모든 문서에서 흔하게 등장하는 단어라면 문서를 구분하는 능력이 낮을 수 있어.

그래서 TF-IDF가 등장하는 거야.

빈도만 고려 → TF

전체 문서에서의 희소성까지 고려 → TF-IDF

분류와 군집은 같은가?

아니야.

분류(Classification)는 미리 정해진 정답 범주가 있는 경우가 일반적이야.

리뷰 → 긍정 / 부정

반면 군집(Clustering)은 정답 범주 없이 데이터의 유사성을 바탕으로 그룹을 찾아.

고객 문의들을 비슷한 내용끼리 묶기

즉,

분류 = 지도학습

군집 = 비지도학습

이라는 연결을 기억해.

토픽 모델링과 단어 빈도 분석은 같은가?

아니야.

단어 빈도 분석은 어떤 단어가 많이 등장했는지 보는 비교적 단순한 분석이야.

토픽 모델링은 여러 단어가 함께 나타나는 확률적 구조를 이용해 문서 집합에 숨어 있는 주제 구조를 찾는 것에 가까워.

그래서 LDA를 보면 바로

를 떠올리면 좋아.

비정형 데이터 표현은 이렇게 묶어 기억해.

BoW → 단어 출현 정보

DTM → 문서 × 단어 행렬

TF-IDF → 특정 문서를 잘 특징짓는 단어에 높은 가중치

Word Embedding → 의미적 관계를 벡터로 표현

분석 절차는:

수집 → 전처리 → 표현·특징 추출 → 분석 → 평가·해석

대표 분석은:

분류 → 정해진 범주 예측

군집 → 유사한 데이터끼리 묶기

감성 분석 → 긍정·부정 등 감정 방향 파악

토픽 모델링 → 문서 집합에 숨어 있는 주제 발견

결과 해석에서는:

숫자 자체보다 분석 목적과 맥락이 중요하다.
