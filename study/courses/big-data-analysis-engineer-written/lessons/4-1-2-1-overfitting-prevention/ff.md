#빅데이터분석기사 #필기 #분석모형개선 #과대적합 #규제 #일반화성능

🧭 먼저 잡을 핵심: 과대적합은 “학습을 너무 잘한 상태”가 아니라 “훈련 데이터에만 너무 잘 맞춘 상태”야

시험에서 과대적합(overfitting)을 볼 때 제일 먼저 잡아야 할 구분은 이거야.

훈련 데이터에서 성능이 좋은 것과
새로운 데이터에서도 성능이 좋은 것은 다른 문제다.

분석모형의 목적은 이미 본 데이터를 외우는 게 아니라, 보지 못한 데이터에서도 정확하게 예측하는 것, 즉 일반화(generalization) 하는 거야.

예를 들어 훈련 데이터 정확도가 99%인데 테스트 데이터 정확도가 72%라면, “아주 좋은 모델”이라고 말하기 어렵지. 훈련 데이터의 우연한 잡음까지 학습했을 가능성이 크거든.

이게 바로 과대적합이야.

🔎 1. 과대적합 진단: 어떤 신호를 보면 알 수 있을까?

가장 중요한 진단 기준은 훈련 성능과 검증·테스트 성능의 차이야.

훈련 성능과 검증 성능의 간격

전형적인 과대적합은 이렇게 나타나.

구분	성능
훈련 데이터	매우 높음
검증·테스트 데이터	상대적으로 낮음

즉,

Training Error ↓↓
그런데
Validation/Test Error ↑ 또는 충분히 감소하지 않음

이런 패턴이면 과대적합을 의심해.

왜 이런 차이가 생길까?

모델이 필요한 규칙뿐 아니라 훈련 데이터에만 존재하는 잡음(noise)이나 우연한 패턴까지 학습하기 때문이야.

가령 실제 규칙이 단순한 직선 관계인데, 모델이 너무 복잡해서 훈련 데이터의 점 하나하나를 모두 통과하도록 구불구불한 곡선을 만들었다고 해보자.

훈련 데이터에서는 오차가 거의 0일 수 있어.

하지만 새로운 데이터에서는 그 복잡한 곡선이 오히려 틀릴 가능성이 커져.

과대적합을 잘 일으키는 조건

대표적으로 다음 상황을 기억하면 돼.

데이터에 비해 모델이 지나치게 복잡함

학습 데이터가 너무 적음

변수가 지나치게 많음

불필요한 변수까지 사용함

의사결정나무의 깊이가 지나치게 깊음

신경망을 지나치게 오래 학습함

핵심은 하나야.

데이터가 제공하는 정보량에 비해 모델의 자유도가 너무 크면 과대적합 위험이 증가한다.

⚖️ 2. 과대적합을 이해하는 시험 핵심: 편향과 분산

과대적합 문제는 편향-분산 트레이드오프(Bias-Variance Trade-off)와 연결해서 보면 훨씬 잘 정리돼.

모델이 너무 단순한 경우

모델이 실제 관계를 충분히 표현하지 못해.

→ 편향(Bias)이 큼
→ 훈련 데이터에서도 성능이 좋지 않음
→ 과소적합(Underfitting)

모델이 너무 복잡한 경우

훈련 데이터의 작은 변화에도 모델이 크게 달라질 수 있어.

→ 분산(Variance)이 큼
→ 훈련 데이터에는 매우 잘 맞음
→ 새로운 데이터에는 약함
→ 과대적합(Overfitting)

그래서 우리가 원하는 건 단순히 “가장 복잡한 모델”이 아니야.

편향과 분산 사이에서 일반화 성능이 가장 좋은 모델을 찾는 거야.

간단히 연결하면:

너무 단순함 → 과소적합 → 높은 편향

적절한 복잡도 → 좋은 일반화 성능

너무 복잡함 → 과대적합 → 높은 분산

🛠️ 3. 규제·단순화: 모델에게 “너무 복잡하게 만들지 마”라고 제한하는 것

과대적합을 줄이는 대표적인 방향은 모델의 복잡도를 낮추는 것이야.

여기서 시험에 자주 등장하는 개념이 규제(Regularization)야.

규제의 기본 원리

보통 모델은 예측 오차를 최소화하도록 학습해.

하지만 규제를 사용하면 목표가 조금 달라져.

개념적으로는:

목적함수 = 예측 오차 + 복잡도에 대한 패널티

즉,

“데이터를 잘 맞추기는 해야 하는데, 지나치게 복잡한 모델은 벌점을 줄게.”

라는 방식이야.

🎚️ 규제 강도를 결정하는 λ

여기서 λ(lambda)도 중요해.

λ가 작으면

규제 효과가 약해.

→ 모델이 데이터를 자유롭게 학습
→ 복잡도가 높아질 수 있음
→ 과대적합 가능성 증가

λ가 커지면

규제 효과가 강해져.

→ 계수가 더 많이 제한됨
→ 모델이 단순해짐
→ 과대적합 감소 가능

하지만 너무 크게 설정하면?

모델이 지나치게 단순해져 과소적합이 생길 수 있어.

그래서 λ가 무조건 클수록 좋은 게 아니야.

적절한 규제 강도를 검증 데이터를 이용해 선택하는 것이 중요해.

✂️ 4. 규제만이 아니다: 모델 자체를 단순화하는 방법

과대적합을 줄이는 방식은 알고리즘마다 조금씩 달라.

의사결정나무

나무를 계속 깊게 만들면 훈련 데이터의 세세한 특징까지 분리할 수 있어.

그래서 과대적합을 줄이기 위해:

최대 깊이 제한

최소 노드 크기 설정

최소 분할 데이터 수 설정

가지치기(Pruning)

등을 사용해.

특히 가지치기는 시험에서 자주 연결돼.

불필요한 가지를 제거하여 나무의 복잡도를 줄이고 일반화 성능을 높이는 방식이야.

신경망

신경망에서는 대표적으로:

Dropout

Weight Regularization

Early Stopping

등을 사용할 수 있어.

Dropout

학습 과정에서 일부 뉴런을 임의로 제외해 특정 뉴런이나 경로에 지나치게 의존하는 것을 막아.

Early Stopping

검증 데이터의 성능을 보면서 학습을 중단하는 방법이야.

예를 들어:

Epoch 10 → 검증 오류 감소

Epoch 20 → 검증 오류 감소

Epoch 30 → 검증 오류 최소

Epoch 40 → 훈련 오류는 계속 감소하지만 검증 오류 증가

그렇다면 Epoch 30 부근에서 멈추는 게 더 좋아.

훈련을 계속하면 훈련 데이터에만 더 맞춰지면서 과대적합될 수 있기 때문이야.

📉 5. 일반화 성능 확인: 결국 과대적합 방지의 목적은 여기에 있어

과대적합을 방지했다는 사실은 훈련 데이터만 보고 확인하면 안 돼.

반드시 훈련에 사용하지 않은 데이터에서 성능을 확인해야 해.

일반적으로 데이터를 이렇게 구분해.

Training Set

모델의 파라미터를 학습하는 데이터.

Validation Set

모델이나 하이퍼파라미터를 선택하는 데 사용하는 데이터.

예를 들어:

규제 강도 λ

의사결정나무 깊이

신경망 구조

학습 횟수

등을 결정할 때 사용할 수 있어.

Test Set

최종 모델의 성능을 평가하는 데이터야.

특히 중요한 원칙이 하나 있어.

Test Set은 최종 평가용이므로 모델을 계속 조정하는 데 사용하면 안 된다.

테스트 데이터까지 반복해서 보고 모델을 고르면, 결국 테스트 데이터에도 간접적으로 과대적합하게 되기 때문이야.

🔁 6. 교차검증이 중요한 이유

데이터가 충분히 많으면 단순하게 train/validation/test로 나눌 수 있지만, 데이터가 제한적이면 한 번 나눈 결과가 우연에 크게 영향을 받을 수 있어.

그래서 사용하는 대표적인 방법이 교차검증(Cross Validation)이야.

K-Fold Cross Validation

전체 데이터를 K개의 부분으로 나눠.

예를 들어 5-Fold라면:

1번 Fold를 검증용, 나머지 4개를 훈련용

2번 Fold를 검증용, 나머지 4개를 훈련용

반복

총 5개의 검증 성능을 평균

이렇게 하면 특정 데이터 분할 하나에 의존하는 것보다 일반화 성능을 더 안정적으로 추정할 수 있어.

여기서 시험 연결은 이렇게 잡아.

교차검증 → 일반화 성능 추정 + 모델/하이퍼파라미터 선택

🔗 7. 전체 흐름을 하나로 연결하면

과대적합 방지는 개별 암기 항목이 아니라 하나의 과정이야.

⑤ 일반화 성능 확인

최종적으로 학습에 사용하지 않은 데이터에서 성능을 평가한다.

이 흐름의 마지막 목표가 바로:

훈련 데이터에 대한 적합도가 아니라 새로운 데이터에 대한 일반화 성능을 높이는 것

이야.

🎯 시험에서 헷갈리는 경계
🧩 “성능이 높다 = 과대적합이 아니다?”

아니야.

훈련 성능만 높다면 과대적합일 수도 있어.

훈련 성능과 검증·테스트 성능을 함께 봐야 해.

🧩 “모델을 복잡하게 하면 성능이 무조건 좋아진다?”

훈련 성능은 좋아질 가능성이 높아.

하지만 일반화 성능은 어느 지점부터 오히려 떨어질 수 있어.

🧩 “규제를 강하게 할수록 좋다?”

아니야.

너무 약하면 과대적합, 너무 강하면 과소적합이 생길 수 있어.

🧩 “테스트 데이터를 보고 λ를 고른다?”

좋은 평가 절차가 아니야.

λ 같은 하이퍼파라미터는 검증 데이터나 교차검증으로 정하고, 테스트 데이터는 최종 평가에 남겨두는 게 기본 원칙이야.

🧠 필기용 압축 기억

과대적합 진단

훈련 성능 ↑ / 검증·테스트 성능 ↓
→ 훈련 데이터의 잡음까지 학습했을 가능성

과대적합 방지

모델 복잡도 ↓
→ 규제, 변수 축소, 가지치기, Dropout, Early Stopping 등

L1 / L2

L1 = Lasso = 일부 계수 0 가능 = 변수 선택
L2 = Ridge = 계수 전반 축소

일반화 성능 확인

검증 데이터·교차검증으로 모델 선택
→ 최종 테스트 데이터로 성능 평가

한 문장으로 묶으면:

과대적합 방지는 훈련 데이터에 대한 지나친 적합을 줄이고, 규제·단순화와 검증을 통해 새로운 데이터에 대한 일반화 성능을 높이는 과정이다.
