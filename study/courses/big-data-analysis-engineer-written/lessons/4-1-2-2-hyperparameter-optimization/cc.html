01 · Search Space

🔲 탐색 공간 — 어디까지 찾아볼 것인가?

탐색 공간은 최적화 과정에서 고려할 매개변수 후보 값들의 범위 또는 집합이야. 예를 들어 의사결정나무의 최대 깊이를 다음처럼 잡을 수 있어.

max_depth ∈ {3, 5, 7, 9, 11}
형태 예
이산형트리 개수 = 100, 200, 300
연속형학습률 = 0.001 ~ 0.1
범주형kernel = linear, polynomial, RBF
혼합형깊이 + 학습률 + 알고리즘 종류
핵심 trade-off
탐색 공간이 넓을수록 좋은 후보를 발견할 가능성은 커지지만 계산량도 증가해.

02 · Search Method

🔍 탐색 방법 — 후보를 어떻게 찾아볼 것인가?

Grid Search

미리 정한 후보 값의 가능한 조합을 체계적으로 모두 탐색해.

3 / 2
3 / 5
5 / 2
5 / 5
7 / 2
7 / 5

작은 탐색 공간에서는 빠짐없이 체계적으로 확인하기 좋지만, 매개변수가 늘어나면 조합 수가 폭발할 수 있어.

Random Search

탐색 공간에서 일부 조합을 무작위로 선택해 평가해.

큰 탐색 공간에서 계산 예산을 제한하기 쉽고, 중요한 매개변수 축을 더 다양한 값으로 볼 수 있어.

Grid Search Random Search
정해진 조합을 체계적으로 탐색조합을 무작위로 추출
작은 탐색 공간에 적합큰 탐색 공간에 유리
계산량이 급증할 수 있음계산 예산을 제한하기 쉬움
후보를 빠짐없이 확인 가능모든 후보를 확인하지 않음
Grid Search = 조합을 촘촘하게 · Random Search = 넓은 공간을 무작위로

왜 Random Search가 유용할까?

🧠 중요한 매개변수 축을 더 다양하게 볼 수 있다

매개변수 A는 성능에 큰 영향을 주고 B는 거의 영향을 주지 않는다고 해보자. Grid Search가 A와 B에 각각 5개 값만 넣으면 25개 조합을 검사해도 A 자체는 5개 값만 본 셈이야. Random Search는 같은 실험 횟수에서도 A에 대해 더 다양한 값을 탐색할 수 있어.

시험 함정: “Grid Search가 항상 Random Search보다 우수하다”는 식으로 생각하면 안 돼.

03 · Validation-based Selection

🧪 검증 기반 선택 — 어떤 후보를 최종 모델로 고를까?

여러 매개변수 조합을 평가했다면 하나를 선택해야 해. 이때 훈련 데이터에서 가장 성능이 높은 조합을 그대로 고르면 훈련 데이터에 지나치게 맞춘 모델을 선택할 수 있어. 그래서 일반적으로 검증 성능을 기준으로 선택해.

후보 설정
훈련 데이터로 학습
검증 데이터로 평가
최적 설정 선택

교차검증과 연결

🔄 한 번의 검증보다 여러 fold의 평균을 본다

단순히 한 번만 훈련/검증 데이터를 나누면 우연히 특정 검증 데이터에 잘 맞는 설정이 선택될 수 있어. 그래서 하이퍼파라미터 탐색에서는 교차검증을 함께 사용하는 경우가 많아.

CV Score = (S₁ + S₂ + S₃ + S₄ + S₅) / 5

각 후보의 평균 검증 성능을 비교해 가장 좋은 값을 선택해. 그래서 Grid Search + Cross Validation 조합이 흔하고, GridSearchCV라는 이름도 여기서 나와.

⚠️ 자주 헷갈리는 포인트

Grid Search는 최적해를 항상 찾는다? 아니야. 설정한 탐색 공간 안에서 후보를 체계적으로 확인하는 거야.
Random Search는 무작위니까 무조건 성능이 떨어진다? 아니야. 큰 탐색 공간에서는 오히려 효율적일 수 있어.
훈련 성능이 가장 높은 매개변수를 고른다? 일반적으로 검증 성능을 이용해 선택해.
테스트 데이터로 최적 매개변수를 찾는다? 최종 평가용 테스트 데이터는 반복적인 매개변수 선택에 사용하지 않는 것이 원칙이야.
