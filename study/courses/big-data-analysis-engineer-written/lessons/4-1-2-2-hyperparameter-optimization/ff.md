즉,

탐색 공간 → 탐색 방법 → 검증 기반 선택

🗺️ 1. 먼저 전체 구조부터 잡자

분석모형을 만들었다고 해보자.

예를 들어 의사결정나무에는 이런 설정이 있을 수 있어.

나무의 최대 깊이

노드를 나누기 위한 최소 데이터 수

사용할 변수의 수

이 값들을 어떻게 설정하느냐에 따라 모델의 성능이 달라져.

여기서 중요한 구분이 하나 있어.

모델이 학습하는 값 vs 사람이 조정하는 값

모델 파라미터(parameter)는 데이터로부터 학습되는 값이야.

예를 들어 선형회귀의 회귀계수 β 같은 것.

반면 시험에서 매개변수 최적화라고 할 때는 실무적으로 대부분 하이퍼파라미터(hyperparameter) 조정을 떠올리면 돼.

예:

의사결정나무: max_depth

랜덤포레스트: 트리 개수

KNN: 이웃 수 k

SVM: C, kernel 관련 값

신경망: 학습률, 층 수 등

즉, 우리가 지금 배우는 건 이런 값을 어떤 후보 중에서 어떤 방식으로 찾아 최종 선택할 것인가야.

🔲 2. 탐색 공간 — “어디까지 찾아볼 것인가?”

탐색 공간(search space)은 최적화 과정에서 고려할 매개변수 후보 값들의 범위 또는 집합이야.

예를 들어 의사결정나무의 최대 깊이를 조정한다면,

max_depth∈{3,5,7,9,11}

라고 정할 수 있어.

이 {3,5,7,9,11}이 바로 탐색 공간이야.

범주형과 연속형 탐색 공간

탐색 공간은 값의 성격에 따라 다르게 구성할 수 있어.

형태	예
이산형	트리 개수 = 100, 200, 300
연속형	학습률 = 0.001 ~ 0.1
범주형	kernel = linear, polynomial, RBF
혼합형	깊이 + 학습률 + 알고리즘 종류

여기서 시험에 중요한 감각은 이것이야.

탐색 공간을 너무 작게 잡으면 좋은 값을 놓칠 수 있고,
너무 크게 잡으면 계산 비용이 커져.

즉,

넓은 탐색 공간⇒좋은 후보 발견 가능성 증가

하지만 동시에

넓은 탐색 공간⇒계산량 증가

라는 trade-off가 있어.

🔍 3. 탐색 방법 — “후보들을 어떻게 찾아볼 것인가?”

탐색 공간이 정해졌다고 해서 모든 후보를 반드시 똑같은 방식으로 확인하는 건 아니야.

대표적으로 기억해야 할 것은 Grid Search와 Random Search야.

격자 탐색 — Grid Search

Grid Search는 미리 정한 후보 값의 가능한 조합을 체계적으로 모두 탐색하는 방법이야.

예를 들어

max_depth = {3, 5, 7}

min_samples_split = {2, 5}

라면 조합은

3×2=6

개가 돼.

즉,

(3, 2)

(3, 5)

(5, 2)

(5, 5)

(7, 2)

(7, 5)

를 모두 평가하는 식이지.

장점

정해진 탐색 공간 안에서는 체계적으로 빠짐없이 확인할 수 있어.

단점

매개변수가 많아지면 조합 수가 폭발해.

예를 들어 매개변수 5개에 각각 후보가 10개씩이라면

10
5
=100,000

개의 조합이 생겨.

이런 현상을 이해할 때는 조합적 폭발을 떠올리면 돼.

무작위 탐색 — Random Search

Random Search는 탐색 공간에서 일부 조합을 무작위로 선택해서 평가하는 방식이야.

예를 들어 가능한 조합이 수천 개인데 100개만 임의로 뽑아 확인하는 식이지.

핵심 차이는 다음과 같아.

Grid Search	Random Search
정해진 조합을 체계적으로 탐색	조합을 무작위로 추출
작은 탐색 공간에 적합	큰 탐색 공간에 유리
계산량이 급증할 수 있음	계산 예산을 제한하기 쉬움
후보를 빠짐없이 확인 가능	모든 후보를 확인하지 않음

시험에서는 이렇게 기억하면 충분해.

Grid Search = 조합을 촘촘하게
Random Search = 넓은 공간을 무작위로

🧠 4. 그런데 왜 Random Search가 유용할까?

이 부분을 이해하면 단순 암기에서 벗어날 수 있어.

매개변수가 2개 있다고 하자.

A는 모델 성능에 매우 큰 영향을 줌.

B는 거의 영향을 주지 않음.

Grid Search가 A와 B에 각각 5개 값을 넣으면 총 25개 조합을 검사해.

그런데 A의 값 자체는 사실 5개만 확인한 셈이야.

Random Search는 무작위 조합을 만들기 때문에 같은 25번의 실험에서도 A에 대해 더 다양한 값을 탐색할 수 있어.

따라서 차원이 높고 중요한 매개변수가 일부에 불과한 문제에서는 Random Search가 효율적일 수 있어.

시험에서 굳이 여기까지 계산시키지는 않더라도,

“Grid Search가 항상 Random Search보다 우수하다”

라고 생각하면 안 돼.

🧪 5. 검증 기반 선택 — “어떤 후보를 최종 모델로 고를까?”

여기가 가장 중요해.

여러 매개변수 조합을 시험했다면 결국 하나를 선택해야 하잖아.

그런데 훈련 데이터에서 가장 성능이 좋은 조합을 고르면 문제가 생길 수 있어.

왜냐하면 훈련 데이터에 너무 맞춰진 모델을 선택할 수 있기 때문이야.

그래서 일반적으로는 검증 성능(validation performance)을 기준으로 선택해.

흐름은 이렇게 돼.

후보 매개변수 설정

↓

훈련 데이터로 모델 학습

↓

검증 데이터로 성능 평가

↓

검증 성능이 가장 좋은 설정 선택

이게 바로 검증 기반 선택이야.

🔄 6. 교차검증과 연결하면 더 정확해진다

단순하게 한 번만 훈련/검증 데이터를 나누면 우연히 특정 검증 데이터에 잘 맞는 설정이 선택될 수도 있어.

그래서 하이퍼파라미터 탐색에서는 교차검증(Cross Validation)을 함께 사용하는 경우가 많아.

예를 들어 5-fold 교차검증이라면 후보 하나에 대해 여러 번 학습·평가해서 평균 성능을 구해.

🚨 7. 시험에서 가장 잘 걸리는 함정: 테스트 데이터

여기서 데이터 역할을 정확히 구분해야 해.

훈련 데이터

모델을 학습한다.

검증 데이터

매개변수와 모델을 선택한다.

테스트 데이터

최종 결정이 끝난 모델의 일반화 성능을 마지막으로 평가한다.

따라서 이런 문장은 위험해.

“테스트 데이터의 성능이 가장 높은 하이퍼파라미터를 선택한다.”

일반적인 평가 원칙에서는 틀린 방향이야.

왜냐하면 테스트 데이터를 반복적으로 보면서 매개변수를 선택하면 테스트 데이터가 사실상 검증 데이터 역할을 해버리기 때문이야.

결과적으로 최종 성능 평가의 객관성이 떨어져.

정리하면:

Training→학습
Validation→선택
Test→최종평가

이 세 단어의 역할을 분리해 두면 관련 문제를 상당히 쉽게 풀 수 있어.

🧩 8. 세 개념을 하나의 사례로 연결해보자

랜덤포레스트 모델의 성능을 개선한다고 하자.

탐색 공간

우선 후보를 정해.

트리 개수: 100, 300, 500

최대 깊이: 5, 10, 20

이게 탐색 공간이야.

탐색 방법

가능한 9개 조합을 전부 확인한다면

→ Grid Search

그중 일부를 무작위로 뽑아 확인한다면

→ Random Search

검증 기반 선택

각 조합으로 모델을 학습하고 교차검증 정확도를 비교했더니

100 / 5 → 0.81

300 / 10 → 0.86

500 / 20 → 0.84

였다면,

검증 결과에 따라 300 / 10 조합을 선택해.

이게 검증 기반 선택이야.

그러니까 세 개념은 독립적인 암기 항목이 아니라,

후보 범위를 정함 → 후보를 탐색함 → 검증 성능으로 선택함

이라는 하나의 파이프라인이야.

🎯 9. 빅데이터분석기사용 압축 정리

시험장에서는 다음 세 문장을 떠올리면 돼.

탐색 공간(Search Space)
→ 최적화를 수행할 매개변수의 후보 범위와 조합

탐색 방법(Search Method)
→ 후보를 실제로 찾아보는 방법
→ 대표적으로 Grid Search, Random Search

검증 기반 선택(Validation-based Selection)
→ 후보 모델의 검증 성능을 비교하여 최적 설정을 선택

그리고 가장 중요한 전체 구조:

탐색공간설정→매개변수탐색→검증성능비교→최적매개변수선택

⚠️ 10. 자주 헷갈리는 포인트
“Grid Search는 최적해를 항상 찾는다?”

아니야.

정확히는 설정한 탐색 공간 안에서 후보를 체계적으로 확인하는 거야.

실제 최적값이 탐색 공간 밖에 있다면 찾지 못해.

“Random Search는 무작위니까 무조건 성능이 떨어진다?”

아니야.

탐색 공간이 크거나 차원이 높으면 제한된 계산량 안에서 오히려 효과적일 수 있어.

“훈련 성능이 제일 높은 매개변수를 고른다?”

일반적으로 아니야.

검증 성능을 이용해서 선택하는 것이 핵심이야.

“테스트 데이터로 최적 매개변수를 찾는다?”

최종 평가용 테스트 데이터를 반복적인 매개변수 선택에 사용하는 것은 피해야 해.

이 네 가지가 객관식 함정으로 바뀌기 좋아.
