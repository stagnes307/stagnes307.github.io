🕸️ [선이 보이면 관계가 보인다] 4-2-2-2. 관계 시각화

#빅데이터분석기사 #분석결과시각화 #관계시각화 #산점도 #상관관계 #네트워크그래프

🧭 먼저 큰 그림: 관계 시각화는 “무엇이 무엇과 연결되는가?”를 보여줘

분석 결과를 시각화할 때 관계 시각화의 목적은 변수나 객체를 따로 보는 게 아니라, 둘 이상의 대상 사이에 어떤 관계가 존재하는지 드러내는 거야.

시험에서는 크게 두 방향으로 나누면 정리가 잘 돼.

구분	핵심 질문	대표 표현
변수 관계 표현	두 변수의 값이 함께 어떻게 변하는가?	산점도, 산점도 행렬, 버블 차트, 상관행렬
네트워크·연결 표현	어떤 대상과 어떤 대상이 연결되어 있는가?	네트워크 그래프, 노드-링크 다이어그램
관계 해석	그 관계가 강한가, 방향이 있는가, 중요한 연결은 무엇인가?	상관 방향·강도, 군집, 중심성, 연결 구조

여기서 제일 중요한 구분부터 잡자.

변수 관계는 주로 값과 값의 관계를 보고,
네트워크 관계는 주로 객체와 객체의 연결 구조를 본다.

이 차이가 잡히면 뒤 내용이 훨씬 편해져.

📈 1. 변수 관계 표현: 두 값이 같이 움직이는 모양을 본다

예를 들어 광고비가 증가할수록 매출도 증가하는지 알고 싶다고 해보자.

각 관측값에 대해

x축 → 광고비

y축 → 매출액

을 놓고 점을 찍으면 산점도(Scatter Plot)가 돼.

산점도에서 읽어야 하는 세 가지
방향 — 같이 움직이나, 반대로 움직이나?

점들이 왼쪽 아래에서 오른쪽 위로 모이면:

x ↑ → y도 대체로 ↑

즉, 양의 관계야.

반대로 왼쪽 위에서 오른쪽 아래로 내려가면:

x ↑ → y는 대체로 ↓

즉, 음의 관계야.

점들이 특별한 방향 없이 흩어져 있다면 두 변수 사이의 뚜렷한 관계가 약할 수 있어.

강도 — 얼마나 일정하게 움직이나?

점들이 하나의 직선 주변에 빽빽하게 모일수록 관계가 강하다고 볼 수 있어.

강한 양의 관계        약한 관계

        •                    •     •
      •                   •
    •                         •
  •                      •
•                           •

하지만 여기서 시험에서 자주 걸리는 함정이 있어.

산점도가 보여주는 관계 ≠ 반드시 인과관계

아이스크림 판매량과 물놀이 사고가 함께 증가한다고 해서 아이스크림이 사고를 일으키는 건 아니야. 둘 모두 기온이라는 다른 변수의 영향을 받을 수 있지.

따라서:

상관관계가 있다고 해서 인과관계가 있다고 결론 내릴 수는 없다.

이 문장은 그대로 기억해도 좋아.

형태 — 반드시 직선 관계만 있는 것은 아니다

변수 관계는 선형일 수도 있지만 곡선형일 수도 있어.

예를 들어 어떤 변수 x가 증가할 때 y가 처음에는 증가하다가 다시 감소한다면, 강한 관계가 존재하더라도 선형 상관계수만으로는 충분히 잡히지 않을 수 있어.

그래서 관계 시각화에서는 단순히 숫자만 확인하지 않고 실제 점의 분포 형태를 보는 게 중요해.

🔍 2. 여러 변수의 관계: 하나씩 그리면 너무 많아진다

변수가 2개면 산점도 하나로 충분해.

그런데 변수가

매출

광고비

가격

방문자 수

구매전환율

처럼 많아지면 변수 쌍마다 관계를 확인해야 하지.

이때 사용할 수 있는 것이 산점도 행렬(Scatter Plot Matrix)이야.

산점도 행렬

여러 변수의 모든 쌍을 산점도로 배열해서 관계를 한꺼번에 살펴보는 방식이야.

예를 들어 변수 A, B, C가 있으면:

	A	B	C
A	A	A-B	A-C
B	B-A	B	B-C
C	C-A	C-B	C

덕분에

어떤 변수끼리 강한 관계가 있는지

이상치가 있는지

선형 또는 비선형 패턴이 있는지

빠르게 탐색할 수 있어.

시험 키워드는 “다변량 변수 간 관계 탐색”으로 연결해 두면 돼.

🫧 3. 버블 차트: 관계에 변수 하나를 더 얹는다

산점도는 기본적으로 x와 y, 두 변수를 표현하지.

여기에 점의 크기(size)로 세 번째 변수를 표현하면 버블 차트(Bubble Chart)가 돼.

예를 들어 기업별로:

x축 → 매출

y축 → 영업이익률

버블 크기 → 시장점유율

을 동시에 표현할 수 있어.

즉,

산점도 + 점의 크기라는 추가 정보 = 버블 차트

경우에 따라 색상까지 사용해서 네 번째 범주 정보를 추가할 수도 있지만, 너무 많은 시각적 변수를 한 번에 사용하면 오히려 해석이 어려워질 수 있어.

🧊 4. 상관행렬과 히트맵: 관계의 강도를 색으로 압축한다

변수가 많으면 모든 산점도를 보는 것도 복잡해져.

이때 각 변수 사이의 상관계수를 행렬로 만든 것이 상관행렬(Correlation Matrix)이야.

예를 들어:

	A	B	C
A	1.0	0.8	-0.2
B	0.8	1.0	-0.5
C	-0.2	-0.5	1.0

이를 색의 농도 등으로 표현하면 히트맵(Heatmap) 형태로 볼 수 있어.

여기서 핵심은 두 가지야.

부호

상관계수가 양수라면 같은 방향으로 움직이는 경향이 있고, 음수라면 반대 방향으로 움직이는 경향이 있어.

절댓값

일반적인 상관계수는 -1에서 +1 사이에 놓이며,

+1에 가까움 → 강한 양의 선형 관계

-1에 가까움 → 강한 음의 선형 관계

0에 가까움 → 선형 관계가 약함

을 의미해.

단, 0에 가깝다고 모든 종류의 관계가 없다는 뜻은 아니야. 강한 비선형 관계가 존재할 수도 있어.

🕸️ 5. 네트워크·연결 표현: 이번에는 “점의 위치”보다 “누구와 연결됐는가”가 중요해

여기서 관계 시각화의 성격이 바뀐다.

산점도에서는 한 점이 하나의 관측값이고, x축과 y축 좌표가 중요했지.

네트워크에서는 보통:

노드(Node) → 개체

링크 또는 엣지(Link / Edge) → 개체 사이의 관계

를 의미해.

예를 들어 SNS 관계라면:

민수 ─── 지영
 │       │
 │       │
현우 ─── 수진

사람들이 노드, 친구 관계가 엣지가 되는 거야.

대표적인 네트워크 데이터

사람 ↔ 사람 : 친구 관계

사용자 ↔ 사용자 : 메시지 교환

웹페이지 ↔ 웹페이지 : 하이퍼링크

상품 ↔ 상품 : 동시 구매 관계

계좌 ↔ 계좌 : 자금 이동

도시 ↔ 도시 : 교통 연결

논문 ↔ 논문 : 인용 관계

따라서 네트워크 시각화는 단순한 값의 크기보다 연결 구조 자체를 탐색하는 데 강해.

🔗 6. 방향이 있는 연결과 없는 연결

네트워크 관계를 해석할 때 중요한 구분이 있어.

무방향 네트워크

A와 B의 관계에 방향이 없는 경우야.

A ─── B

예를 들어 일반적인 “친구 관계”를 생각할 수 있어.

A와 B가 친구라면 B와 A도 친구니까.

방향 네트워크

관계에 방향이 존재하면 화살표를 사용해.

A ───→ B

예를 들어:

A가 B를 팔로우한다.

A가 B에게 송금한다.

논문 A가 논문 B를 인용한다.

같은 관계야.

여기서는 누가 누구에게 연결되는가까지 정보가 되지.

⚖️ 7. 연결의 세기도 표현할 수 있다

모든 연결이 동일한 강도일 필요는 없어.

A와 B가 메시지를 100번 교환했고, A와 C는 2번만 교환했다면 관계의 강도가 다르겠지.

이런 값을 가중치(weight)로 표현할 수 있어.

B ═════ A ─ C

시각화에서는 흔히

선의 굵기

선의 명도

숫자

등으로 연결 강도를 표현해.

따라서 네트워크는 다음처럼 확장될 수 있어.

노드 + 엣지 + 방향 + 가중치

🧠 8. 관계 해석: 그림을 예쁘게 보는 게 아니라 구조를 읽어야 해

관계 시각화 문제에서 시험이 요구하는 핵심은 결국 무엇을 해석할 수 있느냐야.

🔎 변수 관계에서 읽는 것

산점도나 상관행렬에서는 주로 다음을 읽어.

방향 → 강도 → 형태 → 이상치

예를 들어 산점도에 대부분의 점과 멀리 떨어진 점 하나가 있다면 이상치(outlier)일 가능성이 있어.

이 이상치는 상관계수나 회귀 결과에도 큰 영향을 줄 수 있으므로 관계를 해석할 때 주의해야 해.

🕸️ 네트워크에서 읽는 것

네트워크에서는 다음과 같은 질문을 던져.

누가 많이 연결되어 있는가?

연결이 많은 노드는 네트워크에서 중요한 위치에 있을 가능성이 있어.

이를 분석하기 위해 중심성(Centrality) 개념을 사용할 수 있어.

비슷한 노드끼리 덩어리를 이루는가?

서로 강하게 연결된 노드들이 집단을 만드는 현상을 찾아볼 수 있어.

이런 구조는 커뮤니티 또는 군집(Community / Cluster) 탐색과 연결돼.

어떤 노드가 집단과 집단을 이어 주는가?

두 그룹 사이를 연결하는 노드는 전체 네트워크의 흐름에서 중요한 역할을 할 수 있어.

즉, 단순히 연결 수만 많다고 모든 의미의 “중심”이 되는 건 아니야.

⚠️ 9. 시험에서 헷갈리는 경계들을 한 번에 정리하자
산점도 vs 네트워크 그래프

산점도:

“x값과 y값 사이에 어떤 관계가 있지?”

네트워크 그래프:

“어떤 객체가 어떤 객체와 연결되어 있지?”

좌표의 수치적 관계가 핵심이면 산점도, 객체 사이의 연결 자체가 핵심이면 네트워크 그래프야.

산점도 vs 버블 차트

산점도는 기본적으로 두 변수의 관계를 나타내고, 버블 차트는 버블 크기로 추가 변수를 표현할 수 있어.

상관관계 vs 인과관계

이건 가장 중요해.

상관관계

두 변수가 함께 변하는 경향이 존재한다.

인과관계

한 변수의 변화가 다른 변수의 변화를 발생시킨다.

상관관계만 관찰했다고 바로 인과관계를 주장할 수 없어.

상관계수 0 vs 관계 없음

이것도 함정이야.

상관계수가 0에 가까우면 일반적으로 선형 관계가 약하다는 뜻이지, 모든 형태의 관계가 존재하지 않는다는 의미는 아니야.

🎯 10. 빅데이터분석기사용 압축 기억법

관계 시각화는 이렇게 기억하면 돼.

“값끼리는 산점도, 연결끼리는 네트워크.”

그리고 변수 관계에서는:

방향 → 강도 → 형태 → 이상치

네트워크 관계에서는:

노드 → 엣지 → 방향 → 가중치 → 중심 → 군집

마지막으로 시험 함정:

상관 ≠ 인과
상관계수 0 ≠ 모든 관계 없음

이 세 줄이 4-2-2-2의 뼈대야.

관계 시각화
│
├─ 변수 관계
│   ├─ 산점도
│   │   ├─ 방향
│   │   ├─ 강도
│   │   ├─ 형태
│   │   └─ 이상치
│   │
│   ├─ 산점도 행렬
│   ├─ 버블 차트
│   └─ 상관행렬 / 히트맵
│
└─ 객체 간 연결
    └─ 네트워크 그래프
        ├─ 노드
        ├─ 엣지
        ├─ 방향성
        ├─ 가중치
        ├─ 중심성
        └─ 군집 / 커뮤니티

이 구조를 머릿속에 갖고 있으면 개별 시각화 이름을 외우는 부담도 줄어들어. 이름보다 먼저 “무슨 관계를 표현하려고 하지?”를 판별하면 돼.
