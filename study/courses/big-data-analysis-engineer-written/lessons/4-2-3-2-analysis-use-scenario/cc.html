01 · USER & TASK

👤 사용자·업무 정의 — “누가, 어디에 쓰는가?”

분석 결과가 아무리 정확해도 사용자가 누구인지, 어떤 업무 의사결정에 사용할지가 정해져 있지 않으면 활용으로 이어지지 않아.

예: 고객 이탈 분석

“고객별 서비스 해지 가능성을 예측했다.”

이것만으로는 아직 활용 시나리오가 아니야. 고객관리 담당자가 이 결과를 이용해 이탈 방지 고객을 선정하고 유지 활동을 수행한다까지 연결돼야 해.

분석가와 사용자는 다를 수 있다

데이터 분석가가 예측모델을 만들었더라도 실제 결과 사용자는 마케팅 담당자, 고객관리 담당자, 영업 관리자, 현장 작업자, 경영진일 수 있어. 시험에서는 실제로 결과를 이용해 행동하거나 판단하는 주체를 찾아야 해.

사용자와 업무의 연결
분석결과 사용자 업무
고객 이탈 확률 고객관리 담당자 이탈 방지 고객 선정
상품 추천 결과 마케팅 담당자 개인화 상품 추천

이상 거래 탐지 금융기관 담당자 의심 거래 점검

02 · FLOW

🔄 활용 흐름 — “결과가 실제 행동까지 어떻게 움직이는가?”

여기서 가장 중요한 구분은 분석 결과가 전달되는 것과 실제로 활용되는 것은 다르다는 거야. 대시보드에 숫자가 나타났다는 사실만으로 활용이 끝난 게 아니야.

고객 반응 기록

언제 필요한가?

실시간, 일별, 주별 등 업무 속도에 따라 달라져. 이상거래 탐지는 빠른 대응이 중요하지만 월별 매출 분석은 반드시 실시간일 필요가 없어.

어떤 형태로 전달되는가?

보고서, 대시보드, 알림, 추천 목록, 업무 시스템, 자동 의사결정 결과 등 여러 형태가 가능해.

받은 뒤 무엇을 하는가?

핵심은 여기야. 분석 → 결과 제공에서 멈추지 않고 분석 → 결과 제공 → 판단 → 업무 수행까지 연결되어야 해.

활용 흐름의 기본 골격
입력 → 분석 → 결과 → 전달 → 판단 → 조치 → 피드백
03 · PERFORMANCE

📊 성과 기준 — “그래서 실제로 좋아졌는가?”

활용 시나리오 마지막에는 분석 결과를 사용한 뒤 실제로 가치가 생겼는지 판단할 기준이 필요해.

⚠️ 핵심 함정: 모델 성능 ≠ 활용 성과

모델 정확도가 95%여도 아무도 결과를 사용하지 않았다면 비즈니스 성과는 생기지 않아. 반대로 예측 결과를 활용해 고객 유지 활동을 실시하고 이탈률이 감소했다면 실제 활용 성과가 발생한 거야.

좋은 성과 기준의 조건

“고객관리를 개선한다”처럼 모호하게 쓰기보다 전후를 측정할 수 있는 지표로 잡아야 해.

  • 고객 이탈률 감소
  • 캠페인 응답률 증가
  • 매출 증가
  • 업무 처리시간 감소
  • 불량률 감소
  • 설비 고장시간 감소

⚠️ 시험에서 잘 낚이는 세 가지

사용자를 분석가로만 생각한다

실제 결과를 이용해 의사결정이나 행동을 수행하는 주체를 봐야 해.

활용 흐름을 결과 제공에서 끝낸다

예측 결과 → 대시보드가 아니라, 그 다음의 판단과 조치까지 이어져야 해.

성과 기준을 모델 정확도로만 본다

업무 효율, 비용, 매출, 고객 유지, 품질처럼 실제 활용 가치와 연결해야 해.
