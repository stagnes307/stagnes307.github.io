🧭 먼저 큰 그림 — 리모델링은 “한 번 만든 모형을 계속 고쳐 쓰는 과정”

분석모형을 처음 만들었을 때 성능이 좋았다고 해서 계속 좋은 건 아니야.

시간이 지나면 고객 행동이 달라지고, 새로운 데이터가 쌓이고, 변수의 분포가 변하고, 업무 목표 자체가 바뀔 수도 있어.

그러면 기존 모형이 현재 데이터를 제대로 설명하거나 예측하지 못하게 돼. 이때 기존 모형을 다시 학습하거나 구조 자체를 다시 설계하는 것이 분석모형 리모델링이야.

🚨 1. 재학습 조건 — 언제 다시 학습시킬까?

가장 중요한 구분: “모형이 낡았는가?”

재학습은 단순히 시간이 지났다고 무조건 하는 게 아니야. 기존 모형의 성능이나 적용 환경이 달라졌다는 신호가 있을 때 검토해.

📉

예측 성능 저하

정확도, 정밀도, 재현율, RMSE 등이 기준 이하로 떨어짐.

🌊

데이터 분포 변화

학습 당시와 현재 입력 데이터의 특성이 달라짐.

🗂️

신규 데이터 누적

새 데이터가 충분히 쌓여 기존 학습 데이터를 보완할 수 있음.

🏢

업무 환경 변화

정책, 시장, 고객 행동, 시스템 등이 변화함.

🔗

변수 관계 변화

입력변수와 목표변수 사이의 관계가 이전과 달라짐.

➕

새로운 변수 확보

기존에 없던 유용한 설명변수가 추가됨.

데이터 드리프트와 개념 드리프트

데이터 드리프트

입력 데이터의 분포 자체가 변한 경우야.

예: 쇼핑몰 고객의 주요 연령층이 과거 20대 중심에서 현재 40대 중심으로 이동.

개념 드리프트

입력과 결과 사이의 관계 자체가 변한 경우야.

예: 과거에는 할인율이 구매를 크게 좌우했지만, 현재는 배송 속도가 구매 여부를 더 크게 결정.

입력값의 모습이 변함 → 데이터 드리프트
입력값과 결과의 관계가 변함 → 개념 드리프트

🏗️ 2. 재구축 절차 — 문제를 발견했다고 바로 새 모델부터 만들면 안 돼

리모델링의 핵심은 원인을 먼저 확인하는 것이야.

01

기존 모형 성능 모니터링

성능 저하나 이상 여부 확인.

02

성능 저하 원인 분석

데이터 변화인지, 변수 문제인지, 모형 구조 문제인지 판단.

03

데이터 재수집·정제

새로운 데이터를 확보하고 결측값·이상값 등을 처리.

04

변수 재검토

기존 변수의 유효성을 평가하고 필요하면 추가·제거·변환.

05

모형 재학습 또는 재설계

기존 알고리즘을 다시 학습하거나 새로운 구조를 적용.

06

성능 평가

검증 데이터나 테스트 데이터로 새 모형의 성능 확인.

07

기존 모형과 비교

새 모형이 실제로 개선되었는지 판단.

08

적용 및 지속적 모니터링

개선된 모형을 운영 환경에 배포하고 다시 성능을 추적.

시험 함정: 재학습과 재구축은 같은 말이 아니다

재학습

기존 모형 구조를 유지하면서 새로운 데이터로 다시 학습.

재구축

변수, 알고리즘, 구조까지 포함해 모형 자체를 다시 설계할 수 있음.

재학습 ⊂ 리모델링

⚖️ 3. 변경 전후 평가 — 새 모형이 무조건 좋은 건 아니다

리모델링의 마지막 핵심은 기존 모형과 변경된 모형을 같은 기준으로 비교하는 것이야. 새로 만들었다는 사실 자체는 개선의 증거가 아니야.

분류 문제에서 보는 지표

  • 정확도 Accuracy
  • 정밀도 Precision
  • 재현율 Recall
  • F1-score
  • ROC-AUC

회귀 문제에서 보는 지표

  • MAE
  • MSE
  • RMSE
  • R²
기존 정확도
90.0%
→
새 모형 정확도
90.2%

정확도는 올랐지만 계산량이 10배 증가했다면 실제 서비스에서는 기존 모형이 더 적절할 수도 있어. 그래서 성능만 보지 않고 운영 관점까지 함께 본다.

평가 영역 확인 내용
성능예측력이 실제로 향상됐는가
안정성특정 데이터에서만 우연히 좋아진 것은 아닌가
일반화 능력새로운 데이터에서도 잘 작동하는가
처리 비용계산 시간과 자원이 지나치게 증가하지 않았는가
업무 효과실제 업무 목표에 도움이 되는가
운영 가능성기존 시스템에서 안정적으로 사용할 수 있는가

🧠 시험용으로 세 덩어리를 연결해 보자

리모델링 문제를 보면 먼저 이 구조를 떠올리면 돼.

① 왜 바꾸는가?

재학습 조건

성능 저하 / 데이터 변화 / 환경 변화 / 신규 데이터 발생

② 어떻게 바꾸는가?

재구축 절차

모니터링 → 원인 분석 → 데이터·변수 재검토 → 재학습·재설계 → 검증

③ 정말 좋아졌는가?

변경 전후 평가

동일 기준에서 성능·안정성·비용·업무 효과 비교

🎯 특히 헷갈리기 쉬운 세 가지

X

“성능이 떨어졌다 = 즉시 새 알고리즘으로 교체한다”

아니야. 먼저 왜 성능이 떨어졌는지 원인을 분석해야 해. 데이터 품질 문제인데 알고리즘만 바꾸면 해결이 안 될 수 있거든.

X

“새로운 데이터가 생기면 반드시 재학습한다”

이것도 너무 강한 표현이야. 새 데이터가 충분히 누적됐거나 기존 모형의 성능 개선에 의미가 있을 때 재학습을 검토해. 시험에서는 항상, 반드시, 무조건 같은 표현을 조심해.

X

“변경 후 모형은 정확도만 비교하면 된다”

아니야. 성능뿐 아니라 안정성·일반화·운영 비용·업무 효과도 볼 수 있어.
