산업안전기사 필기 Lesson 2-1-3-1

요구에서 접점까지 잇는 체계설계

목표 및 성능명세의 결정 · 기본설계 · 계면설계

무엇을 달성할까? 누가 무엇을 맡을까? 어떻게 보고 조작할까?

SYSTEM DESIGN CHAIN

1. 세 단계는 끊을 수 없는 설계 사슬이야

체계설계는 장비의 모양부터 그리는 작업이 아니야. 먼저 달성할 목적을 정하고, 그 목적을 시험할 수 있는 기준으로 번역한 뒤, 인간과 기계의 역할과 접점을 구체화해야 해. 앞 단계가 모호하면 뒤 단계가 정교해도 안전한 체계가 되기 어려워.

STEP 01

목표 및 성능명세의 결정

체계가 달성해야 할 목적을 정하고, 성공 여부를 판단할 수 있도록 시간·정확도·신뢰도·환경 조건 같은 측정 기준을 붙이는 단계야.

STEP 02

기본설계

필요한 기능을 분해하고 인간과 기계에 배분하며, 하위체계의 구조와 정보 흐름을 큰 틀에서 결정하는 단계야.

STEP 03

계면설계

표시장치, 조종장치, 경보, 작업공간과 피드백을 통해 인간과 기계가 실제로 만나는 접점을 구체화하는 단계야.

MEASURABLE REQUIREMENT

2. 추상적인 목표를 시험 가능한 명세로 바꾸자

“안전하게”, “신속하게”, “편리하게”는 방향을 알려주지만 합격선을 알려주지는 않아. 좋은 성능명세는 누가, 무엇을, 어떤 조건에서, 어느 수준으로 수행해야 하는지 드러내야 해. 설계자와 평가자가 같은 기준으로 판단할 수 있어야 하지.

대상누가 수행하는가
행동무엇을 하는가
조건어디서 수행하는가
기준얼마나 잘해야 하는가
제약무엇을 지켜야 하는가

교정 표시 “위험을 빨리 알린다”는 목표에 가까워. “소음 환경에서도 위험 발생 후 2초 이내에 작업자의 95% 이상이 경보를 식별한다”라고 쓰면 측정하고 시험할 수 있는 성능명세가 돼.

수단과 목표도 구별해야 해. “적색 램프를 설치한다”는 특정 해결책이고, 진짜 목표는 “작업자가 위험 상태를 빠르고 정확하게 식별하도록 한다”야. 목표를 수단으로 고정하면 더 적절한 복합경보나 배치 대안을 놓칠 수 있어.

HUMAN PERFORMANCE

3. 인간요소도 성능명세 안에 넣어야 해

산업 체계의 성능은 기계 출력만으로 완성되지 않아. 작업자가 신호를 탐지하고, 의미를 식별하고, 판단한 뒤 정확하게 조작해야 실제 안전 성능이 만들어져. 그래서 반응시간, 오독률, 오조작률, 작업부하, 도달범위, 보호구 착용 상태와 같은 인간 변수를 명세에 반영해야 해.

지각 성능

소음·진동·조도 속에서도 신호가 보이고 들려야 해. 색상 하나에만 의존하지 말고 문자, 형태, 위치를 함께 사용하면 식별 신뢰도가 높아져.

판단 성능

정보가 너무 많거나 우선순위가 불분명하면 판단이 늦어져. 정상·주의·위험 상태와 조치 순서를 명확하게 구별해야 해.

행동 성능

보호장갑, 제한된 자세, 피로 상태에서도 조종장치에 도달하고 필요한 힘으로 작동할 수 있어야 해.

평균적인 작업자만 기준으로 삼는 것도 위험해. 체격, 연령, 경험, 감각 특성이 다른 사용자를 고려해야 해. 인간의 한계를 개인의 부주의로 돌리기 전에 체계가 그 한계를 흡수하도록 설계하는 것이 인간공학의 핵심이야.

FUNCTION ALLOCATION

4. 기본설계는 기능 분석과 역할 배분에서 시작해

먼저 상위 목적을 수행 가능한 하위 기능으로 나눠야 해. 예를 들어 안전운전은 상태 감시 → 이상 탐지 → 위험 판단 → 경보 제시 → 대응 선택 → 조작 실행 → 결과 확인으로 분해할 수 있어. 기능이 빠지거나 순서가 끊기면 사고 방어선에 빈틈이 생겨.

기계는 반복 계산, 고속 처리, 정밀 측정, 지속 감시에 강해. 인간은 불완전한 정보의 해석, 새로운 상황의 판단, 유연한 문제 해결에 상대적으로 강하지. 하지만 단순히 “잘하는 쪽에 맡긴다”로 끝내면 안 돼. 고장 시 대체 가능성, 작업자의 상황인식, 교육 수준, 유지보수성과 실패 결과까지 함께 봐야 해.

자동화의 역설: 정상 운전에서 작업자를 배제할수록 드문 비상상황에서는 오히려 작업자에게 더 어려운 판단을 갑자기 요구할 수 있어. 자동화가 무엇을 하고 있는지 보여주고, 필요할 때 안전하게 개입할 통로를 남겨야 해.

INTERFACE LOOP

5. 계면은 인간과 기계를 연결하는 번역기야

계면은 화면이나 버튼만 뜻하지 않아. 표시장치, 조종장치, 경보, 작업공간, 절차서와 소프트웨어 상호작용이 모두 포함돼. 기계가 정확한 정보를 만들어도 작업자가 그 의미를 읽지 못하거나 조작 결과를 확인할 수 없다면 전체 체계는 안전하게 작동하지 못해.

DESIGN PRINCIPLES

6. 안전한 계면을 만드는 네 가지 원리

가시성과 구별성

중요 정보는 필요한 순간에 보여야 하고 다른 정보와 혼동되지 않아야 해. 색상과 문자, 형상, 위치를 함께 사용해.

표시–조종 양립성

오른쪽 회전은 증가, 위쪽 이동은 상승처럼 조작 방향과 결과가 자연스러운 기대에 맞아야 해.

명확한 피드백

조작이 접수되었는지, 체계가 어떤 상태로 바뀌었는지 즉시 알려 반복 조작과 오판을 막아야 해.

또 하나는 오류 예방과 복구 가능성이야. 위험 조작부를 일반 조작부와 다른 형태로 만들고, 되돌리기 어려운 명령에는 확인 절차를 두며, 가능한 경우 취소와 안전 복귀 수단을 제공해야 해. 단, 모든 조작에 확인을 요구하면 경고 피로가 생기므로 결과가 중대하고 복구가 어려운 조작에 집중해야 해.

FIELD CASE

7. 프레스 비상정지 체계로 세 단계를 연결해보자

① 목표

위험 상황에서 작업자가 설비의 위험 운동을 신속히 정지시켜 상해를 방지한다.

② 성능명세

조작시간, 설비 정지시간, 접근거리, 보호장갑 착용 조건과 고장 시 안전 상태를 시험 가능한 기준으로 정해.

③ 기본 구조

위험 감지, 정지 명령, 동력 차단, 제동, 정지 확인 기능을 분해하고 사람과 제어계통에 배분해.

④ 계면 구현

비상정지 버튼을 도달하기 쉬운 곳에 배치하고 일반 조작부와 구별해. 작동 후 정지 상태를 표시하고 단순 복귀만으로 재가동되지 않게 해.

버튼만 눈에 띄게 만들었다고 안전한 것은 아니야. 제동 성능이 부족하거나 기능 배분이 잘못되면 계면 개선만으로 사고를 막을 수 없어. 목적, 구조, 접점이 하나의 검증 사슬로 이어져야 해.

EXAM TRAPS

8. 시험에서 틀리기 쉬운 경계를 교정하자

목표와 명세를 같다고 보면 안 돼. 목표는 방향이고, 성능명세는 달성 여부를 판단하는 측정 기준이야.
기본설계는 외형 꾸미기가 아니야. 기능 분석, 역할 배분, 체계 구조와 정보 흐름이 핵심이야.
계면은 화면과 버튼에만 한정되지 않아. 경보, 작업공간, 절차와 소프트웨어 상호작용도 포함돼.
자동화가 항상 안전을 높이는 것은 아니야. 상황인식을 약화하거나 비상 개입을 어렵게 하면 새로운 위험이 생겨.
계면설계는 마지막 장식 단계가 아니야. 기능 배분과 작업 절차에 영향을 주므로 설계 초기부터 반복해서 검토해야 해.

  1. 추상적 목표

문제 2

기본설계에서 가장 우선적으로 수행할 활동은 무엇일까?

  2. 기능 분석과 인간–기계 역할 배분
  3. 완제품 출하

  1. 작업부하 증가
  2. 정보량 증가
  3. 오조작 예방
  4. 자동화 제거

자동화된 체계에서도 작업자의 상황인식과 개입 통로를 유지해야 하는 이유를 한 문장으로 설명해봐.

ANSWER REVIEW

10. 정답 및 해설

문제 1 · 2번

시간과 식별 비율이 제시되어 측정하고 시험할 수 있으므로 성능명세야. “신속하게 알린다”만 있었다면 목표에 가까워.

문제 2 · 2번

기본설계는 세부 모양보다 먼저 필요한 기능, 인간과 기계의 역할, 정보 흐름과 체계 구조를 정하는 단계야.

문제 3 · 3번

형상과 위치를 구별하면 잘못된 조작부를 선택할 가능성이 줄어들어. 설계를 이용한 오류 예방에 해당해.

문제 4 예시 답안: 자동화가 실패하거나 예상하지 못한 상태가 발생했을 때 작업자가 현재 상황을 이해하고 안전하게 통제권을 회복해야 하기 때문이야.

RECALL MAP

11. 회상 요약

세 단계의 질문만 기억하면 전체 구조가 다시 떠올라.

목표·명세
무엇을 어느 수준까지?
→
기본 구조
누가 어떤 기능을?
→
계면 구현
어떻게 보고 조작할까?

목표는 방향, 성능명세는 측정 가능한 합격선, 기본설계는 기능과 역할의 뼈대, 계면설계는 인간과 기계가 만나는 실제 접점이야.

좋은 체계설계는 사람에게 조심하라고 요구하는 데서 끝나지 않아. 인간의 능력과 한계를 목표, 기능 구조, 접점 안에 처음부터 넣어 오류가 사고로 이어지지 않게 만드는 과정이야.
