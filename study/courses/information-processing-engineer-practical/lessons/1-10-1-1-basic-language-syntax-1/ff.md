## 1. 예제 기능과 요구

주문 품목 합계와 할인을 계산하는 기능을 구현한다.

```text
입력:
  단가: 0 이상, 최소 통화 단위의 정수
  수량: 1~999
  고객 등급: NORMAL, VIP
  쿠폰 할인율: 0~30 정수 백분율

규칙:
  품목 합계 = 단가 × 수량
  VIP이면 합계의 5% 할인
  쿠폰 할인은 VIP 할인 후 금액에 적용
  총 할인은 원금보다 클 수 없음
  계산 중 범위 초과와 잘못된 입력은 오류

출력:
  원금, 등급 할인, 쿠폰 할인, 최종 금액
```

이 요구는 타입, 변수, 산술·비교·논리 연산, 조건문과 반환문으로 구현할 수 있다. 금액을 실수로 할지 정수로 할지, 할인 나눗셈을 언제 반올림할지 먼저 정해야 결과가 일관된다.

## 2. 데이터 타입의 역할

**데이터 타입**은 값의 집합, 저장 표현과 허용 연산을 정한다. 같은 비트 패턴도 정수·실수·문자·주소로 해석하면 의미가 달라진다.

### 2.1 정수형

정수 타입은 부호 유무와 비트 수에 따라 범위가 달라진다.

```text
n비트 부호 없는 정수: 0 ~ 2^n - 1
n비트 2의 보수 부호 정수: -2^(n-1) ~ 2^(n-1) - 1
```

8비트 부호 없는 값은 0~255, 부호 있는 값은 보통 -128~127 범위다. C의 구체 크기는 구현과 타입에 따라 확인해야 하고 Java의 주요 정수 타입은 정해진 크기를 가지며, Python 정수는 메모리가 허용하는 범위에서 임의 정밀도로 확장되지만 외부 저장소·라이브러리 변환에는 다시 범위가 있다.

#### 오버플로

```text
단가 3,000,000,000 × 수량 4
```

32비트 부호 정수 범위를 넘는다. 더 넓은 타입으로 **곱하기 전에** 변환하거나 상한을 사전 검사한다.

```text
if unitPrice > MAX_AMOUNT / quantity:
    fail OVERFLOW
subtotal = unitPrice * quantity
```

곱한 뒤 넓은 타입에 저장하면 이미 좁은 타입 연산에서 넘쳤을 수 있다.

### 2.2 실수형

부동소수점은 넓은 크기 범위를 근사 표현하지만 많은 10진 소수를 정확히 나타내지 못한다.

```text
0.1 + 0.2가 내부적으로 정확히 0.3과 같지 않을 수 있음
```

따라서 금액·정밀한 비율 정산은 최소 통화 단위 정수나 10진 고정 정밀도 타입을 사용하고 반올림 모드·시점을 정한다. 과학 계산에서는 허용 오차로 비교한다.

```text
abs(a - b) <= absoluteTolerance + relativeTolerance * max(abs(a), abs(b))
```

NaN은 자기 자신과도 같지 않을 수 있고 무한대가 생길 수 있으므로 외부 수치 입력은 유한 여부를 검증한다.

### 2.3 논리형

참과 거짓을 나타낸다. 언어에 따라 0·빈 문자열·null·빈 컬렉션의 참/거짓 변환 규칙이 다르다.

```python
# 존재 여부와 값 자체를 구분해야 하는 예
if discount_rate is None:
    raise ValueError("discount_rate is required")
if discount_rate == 0:
    # 유효한 무할인
    pass
```

`if discount_rate:`만 사용하면 누락과 0을 같은 분기로 처리할 수 있다.

### 2.4 문자와 문자열

문자는 문자 집합의 코드 단위 또는 코드 포인트와 관련되고, 문자열은 문자 데이터의 순서다. 언어의 `char`가 항상 사용자가 보는 한 글자와 같지 않다. 결합 문자나 여러 코드 단위로 표현되는 문자가 있기 때문이다.

- 바이트 길이와 문자 수를 구분한다.
- 입력·파일·DB·네트워크의 문자 인코딩을 명시한다.
- 사용자 표시 길이와 저장 크기 제한을 같은 숫자로 보지 않는다.
- 문자열 연결 반복은 불변 문자열 언어에서 많은 중간 객체를 만들 수 있어 빌더·join을 검토한다.
- 비밀번호·토큰을 일반 문자열로 오래 보존하거나 로그에 출력하지 않는다.

### 2.5 배열과 컬렉션

배열은 같은 타입 원소를 인덱스로 접근하는 연속 또는 고정 구조이고, 리스트·맵·집합 같은 컬렉션은 동적 크기와 목적별 연산을 제공한다.

| 구조 | 적합한 목적 | 주요 주의점 |
|---|---|---|
| 배열/리스트 | 순서 있는 원소 | 인덱스 범위, 삽입 비용, 빈 목록 |
| 집합 | 중복 없는 포함 여부 | 동등성·해시, 순서 가정 금지 |
| 맵 | 키로 값 조회 | 키 유일성, 없는 키, 변경 가능한 키 |
| 큐 | 먼저 들어온 작업 처리 | 용량·과부하·공정성 |
| 스택 | 최근 항목부터 처리 | 빈 스택, 재귀 깊이 |

고정 크기 배열의 유효 원소 수와 할당 용량을 구분한다. 반복 경계가 `0 <= index < length`인지 확인한다.

### 2.6 null과 선택값

참조나 값이 없음을 `null`, `None` 등으로 표현할 수 있다. 필수값이면 입력 경계에서 거절하고, 없음이 정상 상태라면 선택 타입·명시적 분기로 처리한다.

```text
필수 customerId: null이면 오류
선택 couponCode: 없음이면 할인 미적용
조회 결과 없음: NOT_FOUND 또는 Optional로 계약
```

null을 0·빈 문자열·빈 목록으로 임의 변환하면 의미가 바뀔 수 있다.

## 3. 변수의 정의와 사용

**변수**는 값을 저장하거나 참조하기 위한 이름 있는 위치다. 선언할 때 이름, 타입, 초기값, 범위, 수명과 변경 가능성을 함께 판단한다.

### 3.1 선언과 초기화

```c
long subtotal = 0;
int quantity = 1;
```

초기화되지 않은 지역 변수를 읽으면 C에서는 정의되지 않은 동작이나 불확정 값 문제가 생길 수 있다. Java는 특정 지역 변수 사용 전 초기화를 요구하고 Python은 대입되지 않은 이름 접근에서 오류가 난다. 언어가 기본값을 주더라도 그 값이 업무상 유효하다는 뜻은 아니다.

```text
나쁜 기본값: orderId = 0인데 0이 “없음”인지 실제 ID인지 불명확
개선: 필수 생성자 인자, Optional, 별도 상태 타입
```

### 3.2 이름과 단위

```text
나쁨: n, v, time, amount
개선: itemCount, timeoutMillis, grossAmountMinor, expiresAtUtc
```

이름은 역할과 단위를 드러낸다. `start`·`end`가 포함/제외 경계인지, `rate`가 0.05인지 5인지도 명확히 한다.

### 3.3 범위

- 블록/지역 범위: 함수·블록 안에서만 접근
- 매개변수 범위: 호출에서 전달된 값
- 인스턴스 범위: 객체마다 별도 상태
- 클래스/정적 범위: 모든 인스턴스가 공유
- 전역/모듈 범위: 넓은 코드에서 접근

변수 범위는 가능한 좁게 하고 선언과 첫 사용을 가깝게 둔다. 같은 이름으로 바깥 변수를 가리는 shadowing은 읽는 사람이 다른 값을 추적하게 만들 수 있다.

```c
int total = 10;
if (condition) {
    int total = 20; /* 바깥 total을 가림 */
}
```

### 3.4 수명과 저장 기간

범위는 이름을 볼 수 있는 코드 영역이고 수명은 값·객체가 존재하는 시간이다. 지역 변수가 참조하는 힙 객체는 함수가 끝난 뒤에도 다른 참조가 있으면 남을 수 있다. 반대로 C에서 지역 변수 주소를 반환하면 함수 종료 뒤 유효하지 않다.

```c
int *bad(void) {
    int local = 10;
    return &local; /* 함수 종료 후 유효하지 않은 주소 */
}
```

### 3.5 변경 가능성과 상수

한 번 정한 값이 바뀌지 않아야 하면 `const`, `final`, 불변 바인딩 등을 사용한다.

```java
final int maxQuantity = 999;
```

참조를 final로 만들어도 참조 대상 객체 내부가 변경 가능할 수 있다. 바인딩 불변과 객체 불변을 구분한다.

상수는 마법 숫자에 의미를 주지만 모든 한 번 쓰는 값까지 전역 상수로 만들지 않는다. 업무 정책 값은 구성·버전·승인 변경 가능성도 고려한다.

### 3.6 값과 참조

```text
a = 10; b = a; b = 20
```

기본 불변 값은 복사되어 a가 유지되는 경우가 많다. 반면 리스트나 객체 참조는 같은 대상을 가리킬 수 있다.

```python
a = [1, 2]
b = a
b.append(3)
# a도 [1, 2, 3]
```

독립 복사가 필요하면 얕은·깊은 복사와 내부 객체 공유를 확인한다. 함수 인자 전달도 “값 자체”인지 “참조 값의 복사”인지 언어 규칙을 이해한다.

## 4. 연산자

### 4.1 산술 연산자

`+`, `-`, `*`, `/`, 나머지 연산과 언어별 몫 연산을 사용한다.

- 정수 나눗셈은 소수 부분을 버리는 방향이 언어·부호에 따라 확인 필요
- 0으로 나누기 오류 처리
- 나머지의 음수 피연산자 규칙 확인
- 곱셈·덧셈 전 오버플로 검사
- 단항 음수에서 최소 정수값을 부호 반전할 때 범위 초과 가능

```text
할인 = subtotal * rate / 100
```

곱셈이 먼저면 중간 오버플로가 가능하고, 나눗셈을 먼저면 작은 금액에서 정밀도를 잃는다. 넓은 타입·10진 타입과 승인된 반올림을 사용한다.

### 4.2 비교 연산자

값 동등성과 객체 동일성을 구분한다. Java의 객체 `==`는 참조 동일성이고 `equals`가 값 동등성을 담당할 수 있으며, Python의 `is`와 `==`도 목적이 다르다. C 문자열은 `==`로 내용을 비교하지 않고 문자열 비교 함수를 사용한다.

부동소수는 허용 오차로 비교하고 문자열 대소·로캘·정규화 규칙을 명시한다.

### 4.3 논리 연산자와 단락 평가

```text
AND: 둘 다 참
OR: 하나 이상 참
NOT: 참/거짓 반전
```

많은 언어의 `&&`, `||`, `and`, `or`는 왼쪽 결과로 전체가 정해지면 오른쪽을 평가하지 않는다.

```c
if (ptr != NULL && ptr->count > 0) {
    /* ptr가 null이면 오른쪽 접근 안 함 */
}
```

비단락 비트 연산자 `&`, `|`와 혼동하지 않는다. Python의 `and`·`or`는 불리언이 아닌 피연산자 자체를 반환할 수 있어 기본값 표현에서 0·빈 값 의미를 주의한다.

### 4.4 대입·복합 대입·증감

```text
x += 1
```

는 일반적으로 x를 한 번 평가해 증가하지만 언어별 형 변환 규칙이 `x = x + 1`과 미세하게 다를 수 있다. 전위·후위 증감은 반환되는 값 시점이 다르다.

```c
int x = 3;
int a = ++x; /* x=4, a=4 */
int b = x++; /* b=4, 이후 x=5 */
```

한 식에서 같은 변수를 여러 번 증감하면 평가 순서에 따라 읽기 어렵거나 C에서 정의되지 않은 동작이 될 수 있다. 문장을 분리한다.

### 4.5 비트 연산자

`&`, `|`, `^`, `~`, `<<`, `>>`는 플래그·마스크·프로토콜 필드 등에 사용한다.

```text
READ  = 0001
WRITE = 0010
EXEC  = 0100

권한 추가: permissions | WRITE
권한 확인: (permissions & WRITE) != 0
권한 제거: permissions & ~WRITE
```

부호 있는 값의 이동, 이동량 범위와 오버플로는 언어 규칙을 확인한다. 일반 업무 권한은 비트 계산만으로 끝내지 않고 의미 있는 열거·집합 타입으로 캡슐화할 수 있다.

### 4.6 조건 연산자

```text
label = isVip ? "VIP" : "NORMAL"
```

짧고 단순한 값 선택에 적합하다. 여러 조건과 부작용을 중첩하면 읽기 어렵고 분기 누락을 숨기므로 명시적 조건문으로 바꾼다.

### 4.7 우선순위와 결합 방향

```text
a + b * c     # 곱셈 먼저
(a + b) * c   # 괄호로 의도 변경
```

우선순위는 어떤 연산을 먼저 묶는지, 결합 방향은 같은 우선순위 연산의 묶임 방향이다. 실제 함수 호출·피연산자 평가 순서는 별도 규칙일 수 있다. 기억에 의존하기보다 의도가 드러나는 괄호와 중간 변수로 표현한다.

## 5. 명령문으로 기능 정의

### 5.1 순차문

문장은 기본적으로 위에서 아래로 실행된다. 한 문장에 검증·계산·상태 변경을 모두 넣지 않고 의미 단계로 분리한다.

```text
validate inputs
subtotal = calculate subtotal
vipDiscount = calculate VIP discount
couponDiscount = calculate coupon discount
finalAmount = subtotal - vipDiscount - couponDiscount
return result
```

### 5.2 조건문

```text
if invalid input:
    return error
else if VIP:
    apply VIP discount
else:
    no grade discount
```

**가드 절**로 잘못된 조건을 일찍 반환하면 깊은 중첩을 줄인다.

```text
if quantity < 1 or quantity > 999: fail
if unitPrice < 0: fail
if couponRate < 0 or couponRate > 30: fail
```

분기 순서가 결과에 영향을 주면 의사결정표로 모든 조합과 우선순위를 확인한다.

### 5.3 switch/match

한 값의 여러 경우를 나눌 때 사용한다.

```c
switch (status) {
case ORDER_DRAFT:
    /* ... */
    break;
case ORDER_CONFIRMED:
    /* ... */
    break;
default:
    /* 미지원 상태 */
    break;
}
```

C 계열에서 `break` 누락 시 다음 case로 떨어지는 fall-through가 생길 수 있다. 의도한 경우 명확히 표시한다. 패턴 매칭 언어에서는 열거값 모든 경우를 처리했는지 컴파일러 도움을 받을 수 있다.

### 5.4 반복문

```text
for each item in items:
    validate item
    add checked line amount
```

반복에서 확인할 항목:

- 초기값, 계속 조건, 갱신이 서로 맞는가?
- 빈 컬렉션과 한 원소를 처리하는가?
- 인덱스 상한이 `< length`인가?
- 반복 중 컬렉션 구조를 변경해 순회가 깨지지 않는가?
- 누적값이 초기화되고 오버플로되지 않는가?
- 입력이 무한 스트림이면 종료·취소·시간 제한이 있는가?

`break`는 반복 종료, `continue`는 이번 반복의 나머지를 건너뛴다. 여러 중첩 반복을 복잡하게 탈출하면 함수 분리·상태 변수를 검토한다.

### 5.5 반환문

함수 결과와 실행 종료를 명확히 한다. 여러 반환은 가드 절에 유용하지만 자원 정리와 사후조건이 모든 경로에서 수행되는지 확인한다. 언어의 자동 자원 관리 구문을 사용한다.

### 5.6 예외 처리

잘못된 입력 같은 예상 업무 오류와 파일·DB 연결 실패 같은 시스템 오류를 구분한다.

- 잡을 수 있고 의미 있게 처리할 예외만 잡는다.
- 빈 catch로 오류를 숨기지 않는다.
- 원인과 추적 정보를 내부에 보존하되 민감정보는 외부로 노출하지 않는다.
- `finally`, 자원 관리 구문으로 정상·예외 모두 자원을 정리한다.
- 예외를 일반 반복 흐름의 조건문처럼 남용하지 않는다.

## 6. 할인 기능 구현 의사코드

```text
function calculatePrice(unitPrice, quantity, grade, couponRate):
    if unitPrice is null or quantity is null:
        return INVALID_INPUT
    if unitPrice < 0:
        return INVALID_UNIT_PRICE
    if quantity < 1 or quantity > 999:
        return INVALID_QUANTITY
    if couponRate < 0 or couponRate > 30:
        return INVALID_COUPON_RATE

    if unitPrice > MAX_MONEY / quantity:
        return AMOUNT_OVERFLOW
    subtotal = unitPrice * quantity

    switch grade:
        NORMAL:
            gradeDiscount = 0
        VIP:
            gradeDiscount = floorAccordingToPolicy(subtotal * 5 / 100)
        otherwise:
            return INVALID_GRADE

    afterGrade = subtotal - gradeDiscount
    couponDiscount = floorAccordingToPolicy(afterGrade * couponRate / 100)

    if couponDiscount > afterGrade:
        couponDiscount = afterGrade

    finalAmount = afterGrade - couponDiscount
    return PriceResult(subtotal, gradeDiscount, couponDiscount, finalAmount)
```

검토 포인트:

- null과 0을 구분한다.
- 모든 입력 범위를 연산 전에 검사한다.
- 할인 순서와 각 단계 반올림을 요구와 일치시킨다.
- 중간 곱셈 오버플로를 검사한다.
- 알 수 없는 고객 등급에 안전한 기본 할인을 주는 대신 오류로 처리한다.
- 결과 구성으로 계산 근거를 검증 가능하게 한다.

## 10. 자주 틀리는 포인트

1. **자료형은 저장 크기만 정한다?** 값 범위·표현·허용 연산과 의미를 정한다.
2. **큰 타입 변수에 결과를 담으면 좁은 타입 곱셈 오버플로가 사라진다?** 연산 전에 피연산자를 넓히거나 상한을 검사해야 한다.
3. **부동소수는 모든 10진 소수를 정확히 표현한다?** 근사 표현이므로 금액·정밀 비교에 주의한다.
4. **0, null, 빈 문자열은 모두 값 없음이다?** 업무 의미가 다르므로 계약대로 구분한다.
5. **문자열 길이는 항상 사용자가 보는 글자 수다?** 바이트·코드 단위·코드 포인트·그래핌 수가 다를 수 있다.
6. **변수 범위와 수명은 같은 개념이다?** 이름의 가시 영역과 객체가 존재하는 시간은 다르다.
7. **final 참조면 대상 객체도 불변이다?** 참조 재대입만 막고 내부 변경은 가능할 수 있다.
8. **객체 `==`는 모든 언어에서 값 내용을 비교한다?** 참조 동일성일 수 있어 언어의 동등성 규칙을 확인한다.
9. **논리 `&&`와 비트 `&`는 불리언에서 항상 같다?** 단락 평가와 오른쪽 부작용·오류 여부가 다르다.
10. **전위·후위 증감은 최종 변수 값만 같으면 같다?** 식이 반환하는 값 시점이 다르다.
11. **우선순위가 평가 순서까지 모두 정한다?** 묶임과 피연산자 평가 순서는 구분한다.
12. **switch의 case는 자동으로 끝난다?** C 계열 일부 언어는 break 없으면 다음 case로 진행한다.
13. **for 반복은 `index <= length`가 마지막 원소까지 돈다?** 유효 인덱스가 0~length-1이면 `< length`다.
14. **예외를 잡고 아무것도 하지 않으면 견고하다?** 실패를 숨겨 잘못된 상태가 이어진다.
15. **정상 예제 하나가 맞으면 기본문법 적용이 끝난다?** 경계·null·오버플로·모든 분기와 자원 정리를 검증한다.

## 12. 정답과 해설

### 정답 1

8비트 부호 없는 정수는 `0~2^8-1`, 즉 0~255다. 2의 보수 부호 정수는 `-2^7~2^7-1`, 즉 -128~127이다.

### 정답 2

피연산자가 좁은 타입이면 곱셈 자체가 그 타입에서 먼저 수행되어 범위를 넘은 뒤 손상된 결과가 넓은 변수에 저장될 수 있다. 연산 전에 넓은 타입으로 안전하게 변환하거나 `a > MAX/b` 같은 사전 범위 검사를 하고, 언어의 checked 연산을 사용한다.

### 정답 3

이진 부동소수는 0.1 같은 많은 10진 값을 정확히 표현하지 못해 합계·비교·반올림이 업무 규칙과 달라질 수 있다. 최소 통화 단위 정수나 승인된 10진 정밀도 타입으로 소수 자릿수와 반올림 시점을 명시한다.

### 정답 4

지역 변수 이름은 함수 블록을 벗어나면 보이지 않아 범위가 끝난다. 그러나 그 변수가 가리키던 힙 객체를 다른 참조가 보유하면 객체 수명은 계속될 수 있다. 반대로 C 지역 변수 자체 주소는 함수 종료 뒤 수명이 끝나 유효하지 않다.

### 정답 5

값 복사는 독립 값을 만들어 한쪽 변경이 다른 쪽에 영향이 없을 수 있다. 참조 복사는 두 변수가 같은 변경 가능한 객체를 가리켜 한쪽 수정이 함께 보인다. 얕은 복사는 외부 껍질만 새로 만들고 내부 객체·버퍼를 공유해 예상치 못한 변경·이중 해제 문제가 생길 수 있다.

### 정답 6

`ptr != null && ptr.count > 0`은 ptr가 null이면 오른쪽을 평가하지 않아 접근을 피한다. 비단락 `&`를 쓰면 오른쪽도 평가되어 null 역참조 오류가 날 수 있고 비용·부작용도 실행된다.

### 정답 7

초기 x=3에서 `a=++x`는 먼저 x를 4로 만들고 a에 4를 준다. 이어 `b=x++`는 현재 4를 b에 준 뒤 x를 5로 만든다. 최종 a=4, b=4, x=5다.

### 정답 8

빈 입력·한 원소·최대 크기, 인덱스 상한, 누적값 초기화·오버플로, 반복 중 컬렉션 변경, break/continue 뒤 상태, 오류 시 부분 결과, 무한 입력의 시간 제한·취소, 자원 정리를 확인한다.

### 정답 9

수량 0·1·999·1000, 단가 -1·0·일반값, 쿠폰 -1·0·30·31, NORMAL/VIP/미지 등급, 최대 금액 근처 곱셈 오버플로, 작은 금액의 반올림, null 입력, VIP 후 쿠폰 순서를 시험하고 결과 불변조건도 확인한다.

### 정답 10

모든 입력의 타입·범위·단위·null 정책이 명확하고 중간 연산까지 범위를 지켜야 한다. 변수는 초기화되고 범위·수명이 작으며, 식의 변환·우선순위·부작용이 명확해야 한다. 모든 조건·반복 경로가 종료·오류 계약에 도달하고 자원이 정리되며, 정적 검사와 정상·경계·오버플로·예외 테스트가 요구 결과와 금지 상태를 검증해야 한다.

## 13. 핵심 요약

- 데이터 타입은 값의 범위·표현·허용 연산과 의미를 정하므로 중간 계산까지 충분한 타입을 선택한다.
- 정수는 부호·비트·오버플로를, 실수는 근사·NaN·반올림을, 문자열은 인코딩·길이 의미를 확인한다.
- null·0·빈 문자열·빈 컬렉션은 같은 상태로 가정하지 않고 입력 계약대로 구분한다.
- 변수는 사용 전 초기화하고 의미·단위를 이름에 담으며 범위·수명·변경 가능성을 최소화한다.
- 값 복사와 참조 공유, 얕은·깊은 복사를 구분해 공유 변경과 자원 수명 오류를 막는다.
- 산술은 나눗셈·반올림·오버플로, 비교는 값·참조 동등성, 논리는 단락 평가를 확인한다.
- 증감과 부작용을 복잡한 한 식에 넣지 않고 괄호·중간 변수로 우선순위와 의도를 드러낸다.
- 조건문은 가드 절과 의사결정표로 분기를 완전하게 하고 반복은 초기·종료·갱신·경계·부분 결과를 검토한다.
- 예외는 처리 가능한 범위에서 분류하고 숨기지 않으며 모든 반환·예외 경로에서 자원을 정리한다.
- 구현은 입출력·단위 → 타입·변수 → 식 → 제어 흐름 → 오류·자원 → 정적·동적 검증 순으로 확인한다.
