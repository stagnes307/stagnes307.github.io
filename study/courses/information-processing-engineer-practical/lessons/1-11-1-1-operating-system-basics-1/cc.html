01

수행 범위와 목표

이 레슨의 정확한 토픽은 다양한 운영체제의 특징 설명과 CLI·GUI에서 기본명령어 활용이다. 운영체제가 프로세스·메모리·파일·장치·사용자·네트워크를 관리하는 원리를 이해하고, Windows·Linux·macOS와 서버·모바일 계열의 차이를 목적에 맞게 설명하며, CLI와 GUI에서 안전한 조회·탐색·프로세스 확인·권한 확인 작업을 수행하는 실무를 다룬다.

운영체제 기능으로 작업 우선순위를 조정하는 상세 절차는 다음 레슨의 범위다. 여기서는 기본 관리 기능과 명령 사용 원칙에 집중하며 삭제·강제 종료·권한 확대 같은 위험 명령은 예제로 실행하지 않는다.

학습 목표는 다음과 같다.

  1. 커널, 사용자 공간, 프로세스·스레드, 가상 메모리, 파일시스템의 역할을 설명한다.
  2. 데스크톱·서버·모바일·실시간 운영체제의 선택 기준을 비교한다.
  3. CLI와 GUI의 장단점을 이해하고 기본 조회 명령을 안전하게 사용한다.
  4. 명령의 대상·현재 경로·권한·출력을 검증하고 작업 기록을 남긴다.
02

1. 운영체제의 역할

운영체제는 하드웨어 자원을 추상화하고 여러 프로그램이 안전하게 실행되도록 관리하는 시스템 소프트웨어다.

응용 프로그램 ↓ 시스템 호출·API 사용자 공간 라이브러리·서비스 ↓ 커널 ├─ 프로세스·스케줄링 ├─ 가상 메모리 ├─ 파일시스템 ├─ 장치 드라이버 ├─ 네트워크 └─ 보안·권한 ↓ CPU·메모리·디스크·장치

응용 프로그램이 하드웨어를 직접 제어하지 않고 운영체제의 추상화와 권한 검사를 거치므로 이식성·격리·공유가 가능해진다.

03

2. 주요 구성과 기능

2.1 커널

CPU 시간, 메모리, 장치와 입출력을 관리하는 핵심이다. 단일체형, 마이크로커널형, 혼합형 등 구조적 분류가 있지만 실제 운영체제는 역사와 목적에 따라 혼합 특성을 가질 수 있다. 구조 이름만으로 성능·안전을 단정하지 않는다.

2.2 프로세스와 스레드

프로세스는 실행 중인 프로그램의 자원·주소 공간 단위이고, 스레드는 한 프로세스 안의 실행 흐름이다. 여러 스레드는 메모리를 공유해 통신이 빠를 수 있지만 경쟁 조건이 생길 수 있다. 프로세스는 격리가 강한 대신 생성·통신 비용이 다를 수 있다.

상태는 실행, 준비, 대기, 종료 등으로 설명할 수 있다. CPU 사용률이 낮은 프로세스가 멈춘 것은 아닐 수 있고 파일·네트워크 입출력을 기다릴 수 있다.

2.3 가상 메모리

각 프로세스에 독립적인 주소 공간을 제공하고 물리 메모리와 보조 저장장치를 관리한다. 페이지 단위 매핑과 보호로 프로세스 격리를 돕는다. 메모리 부족 시 과도한 페이지 교체가 발생하면 CPU가 여유로워도 시스템이 느려질 수 있다.

2.4 파일시스템

파일과 디렉터리, 메타데이터, 권한, 저장 위치를 관리한다. 경로 구분자, 대소문자 처리, 허용 문자, 권한·소유권, 링크와 잠금 동작은 운영체제·파일시스템에 따라 다를 수 있다.

응용이 파일명 대소문자 차이에 의존하거나 절대 경로를 하드코딩하면 다른 환경에서 실패할 수 있다. 플랫폼 API로 경로를 조합하고 실제 지원 환경에서 시험한다.

2.5 사용자와 권한

사용자·그룹·역할을 통해 파일, 프로세스, 장치와 서비스 접근을 제한한다. 일상 작업을 관리자 권한으로 수행하지 않고 필요한 최소 권한을 사용한다. GUI에서 실행했다고 권한 검사가 사라지지 않으며 CLI 명령도 현재 사용자 권한으로 실행된다.

2.6 장치와 네트워크

드라이버가 장치별 세부를 공통 입출력 API로 연결한다. 네트워크 스택은 주소·전송·소켓을 제공한다. 드라이버·커널 업데이트는 기능과 보안을 개선할 수 있지만 호환·재시작 영향을 시험한다.

04

3. 다양한 운영체제의 특징 설명

3.1 Windows 계열

데스크톱·기업 환경의 폭넓은 GUI·하드웨어·관리 도구 생태계를 제공한다. 드라이브 문자와 역슬래시 경로 표기가 흔하고 PowerShell은 객체 기반 파이프라인을 제공한다. 서비스, 이벤트 로그, 레지스트리 등 고유 관리 요소가 있다.

버전·제품군마다 기능과 기본 정책이 다르므로 하나의 Windows 동작을 전체에 일반화하지 않는다.

3.2 Linux 계열

여러 배포판과 커널·사용자 공간 조합이 있으며 서버·클라우드·임베디드에서 널리 사용된다. POSIX 계열 도구, 계층적 단일 경로, 파일 소유자·그룹·권한, 셸 기반 자동화가 특징적이다.

패키지 관리자, 서비스 관리자, 기본 셸과 설정 위치는 배포판마다 다를 수 있다. 인터넷 명령을 그대로 복사하지 않고 대상 배포판 공식 문서를 확인한다.

3.3 macOS·UNIX 계열

UNIX 기반 사용자 공간과 데스크톱 GUI·개발 생태계를 결합한다. POSIX 계열 명령을 제공하지만 GNU 도구와 옵션이 다를 수 있다. 하드웨어·운영체제 통합 지원 범위와 보안 정책을 확인한다.

3.4 모바일 운영체제

터치, 배터리, 센서, 무선 네트워크, 응용 샌드박스, 권한 요청, 백그라운드 제한을 중시한다. 데스크톱처럼 장시간 백그라운드 프로세스가 항상 실행된다고 가정하지 않는다. 저장·알림·네트워크 생명주기를 플랫폼 지침에 맞춘다.

3.5 실시간·임베디드 운영체제

평균 속도보다 정해진 시간 안에 응답하는 예측 가능성이 중요할 수 있다. 제한된 메모리·전력·장치와 안전 요구를 고려한다. 일반 데스크톱 OS의 높은 평균 처리량과 실시간 보장은 다른 목표다.

3.6 서버와 데스크톱 선택

서버 운영체제는 장기 서비스, 원격 관리, 자동화, 최소 구성, 가용성과 자원 효율이 중요하고 데스크톱은 대화형 GUI·주변기기·사용자 편의 비중이 높다. 실제 제품 선택은 지원 기간, 기술·도구, 보안, 애플리케이션 호환, 운영 역량과 총비용을 본다.

5. 안전한 CLI 사용 원칙

  1. 현재 사용자, 장비, 작업 디렉터리를 확인한다.
  2. 실행 전 명령의 목적·대상·옵션과 영향 범위를 읽는다.
  3. 조회 명령으로 파일·프로세스·서비스 대상을 먼저 확인한다.
  4. 공백이 있는 경로를 올바르게 인용하고 와일드카드 확장 범위를 확인한다.
  5. 관리자 권한을 기본으로 사용하지 않는다.
  6. 인터넷의 한 줄 설치·파이프 실행을 검토 없이 실행하지 않는다.
  7. 출력에 토큰·환경 비밀이 포함될 수 있는 명령을 기록에 남기지 않는다.
  8. 변경 명령은 승인·백업·원복 절차와 함께 사용한다.

이 레슨의 예시는 읽기 전용 또는 작업 위치 변경 중심이다.

07

6. POSIX 계열 기본 명령 예시

pwd # 현재 작업 디렉터리 ls -la # 숨김 항목 포함 목록과 기본 메타데이터 whoami # 현재 사용자 uname -a # 커널·시스템 정보(표시는 환경별) ps # 현재 문맥의 프로세스 df -h # 파일시스템 사용량 du -sh ./target # 지정 디렉터리의 요약 크기 head -n 20 file.txt # 앞부분 20줄 읽기 tail -n 20 file.txt # 뒷부분 20줄 읽기

명령 옵션은 구현마다 다를 수 있다. target과 file.txt가 의도한 작업 영역인지 확인한다. 시스템 전체를 무분별하게 탐색하거나 권한 없는 파일을 읽지 않는다.

파이프는 앞 명령 출력을 다음 명령 입력으로 전달하고 리다이렉션은 파일로 보낼 수 있다. 덮어쓰기를 유발하는 리다이렉션은 기존 파일을 확인한 뒤 사용한다.

7. PowerShell 기본 명령 예시

Get-Location Get-ChildItem -LiteralPath . -Force [System.Environment]::UserName Get-ComputerInfo Get-Process Get-PSDrive -PSProvider FileSystem Get-Content -LiteralPath '.\file.txt' -TotalCount 20

PowerShell 파이프라인은 문자열보다 객체를 전달해 속성 기준 필터·정렬이 가능하다.

Get-Process | Sort-Object -Property CPU -Descending | Select-Object -First 10 Name, Id, CPU

프로세스 종료 명령은 여기서 실행하지 않는다. 이름이 같은 여러 프로세스가 있을 수 있으므로 변경 작업 전에는 정확한 ID와 소유·서비스 영향을 확인한다.

09

8. GUI 기본 활용

8.1 파일 탐색기

경로 표시, 확장자, 숨김 파일, 크기·수정일, 권한을 확인한다. 확장자를 숨긴 상태에서 report.pdf.exe 같은 파일을 문서로 오해할 수 있으므로 실제 형식을 본다. 시스템 디렉터리와 응용 데이터 경로를 임의 이동·삭제하지 않는다.

8.2 작업·활동 관리자

프로세스별 CPU, 메모리, 디스크, 네트워크와 사용자·시작 시각을 본다. 순간 CPU만으로 문제를 단정하지 않고 일정 기간과 해당 업무 부하를 연결한다. 강제 종료 전 데이터 손상과 서비스 의존성을 확인한다.

8.3 시스템·로그 도구

운영체제 버전, 장치, 저장 공간, 네트워크 설정, 이벤트·시스템 로그를 확인한다. 로그의 내부 경로·사용자 정보·토큰을 외부 보고서에 그대로 복사하지 않는다.

10

9. 기본 활용 절차와 판단 기준

9.1 목적 정의

파일 찾기, 프로세스 확인, 공간 조사처럼 작업 질문을 한 문장으로 정한다. “느리다”라면 시간대와 대상 프로그램, 지표를 구체화한다.

9.2 환경 식별

운영체제·배포판·버전·셸·현재 사용자·경로를 확인한다. 다른 OS의 명령 옵션을 그대로 적용하지 않는다.

9.3 읽기 전용 조사

GUI나 조회 명령으로 대상을 좁히고 이름·ID·경로·크기·소유자를 확인한다. 와일드카드 대신 가능한 한 정확한 경로를 사용한다.

9.4 최소 권한 작업

변경이 필요하면 필요한 대상과 권한만 승인받는다. 관리자 권한 상승 전에 원인·영향·원복을 확인한다.

9.5 결과 검증

명령 성공 코드뿐 아니라 실제 파일·프로세스·지표 상태가 목표와 맞는지 확인한다. 출력 일부만 잘라 맥락을 잃지 않는다.

9.6 기록

운영체제·버전, 실행 시각, 명령 또는 GUI 경로, 대상, 결과와 다음 판단을 남긴다. 비밀·개인정보는 제거한다.

10. 구체 시나리오

상황

개발 서버의 디스크 경보가 발생했다. 원인을 찾되 파일을 삭제할 권한은 아직 없다.

안전한 조사

  1. 장비·환경·현재 사용자와 파일시스템 사용률을 확인한다.
  2. 허용된 응용 데이터·로그 디렉터리의 크기를 읽기 전용으로 비교한다.
  3. 최근 배포 시각과 로그 증가율, 임시 파일 보존 정책을 확인한다.
  4. GUI 저장 공간 보기 또는 CLI 결과를 교차 확인한다.
  5. 큰 파일의 소유 응용, 사용 중 여부, 보존·백업 요구를 담당자에게 확인한다.
  6. 삭제·이동은 별도 승인과 원복·보존 절차 후 수행한다.

사용률이 높다는 이유로 가장 큰 파일을 즉시 지우지 않는다. 데이터베이스 로그, 현재 실행 중 파일, 감사 기록일 수 있다.

11. 산출물과 체크리스트

주요 산출물은 운영체제 특성 비교표, 환경 식별 기록, 명령·GUI 작업 절차, 조회 결과, 위험·권한 확인표다.

  • 대상 OS·버전·셸·사용자를 확인했는가?
  • 프로세스·스레드·메모리·파일의 기본 역할을 구분하는가?
  • 경로 대소문자·구분자·권한 차이를 고려했는가?
  • 명령 옵션이 대상 운영체제 구현에 맞는가?
  • 현재 경로와 정확한 대상 범위를 확인했는가?
  • 조회 후 변경하며 최소 권한을 사용하는가?
  • GUI의 숨은 기본값과 실제 확장자를 확인했는가?
  • 출력·로그에서 비밀·개인정보를 제거했는가?
  • 변경 작업 전 승인·백업·원복이 있는가?
13

12. 자주 틀리는 함정

  1. 운영체제와 커널을 항상 같은 뜻으로 쓰지 않는다.
  2. CPU 사용이 낮으면 프로세스가 아무 일도 안 한다고 보지 않는다.
  3. 가상 메모리를 단순히 디스크의 추가 RAM이라고만 설명하지 않는다.
  4. 모든 UNIX 계열 명령 옵션이 같다고 단정하지 않는다.
  5. 다른 볼륨·경로 이름이 실제 다른 장치라고 가정하지 않는다.
  6. GUI 작업은 안전하고 CLI만 위험하다고 생각하지 않는다.
  7. 관리자 권한으로 실행하면 문제가 해결된다고 보지 않는다.
  8. 인터넷 명령을 이해 없이 관리자 셸에 붙여 넣지 않는다.
  9. 프로세스 이름만 보고 강제 종료하지 않는다.
  10. 디스크 부족 때 큰 파일부터 임의 삭제하지 않는다.

13. 확인 문제

문제 1

운영체제의 핵심 관리 자원 네 가지를 쓰시오.

정답과 해설: CPU·프로세스, 메모리, 파일·저장장치, 입출력 장치를 들 수 있다. 사용자·권한과 네트워크도 관리한다.

문제 2

프로세스와 스레드의 차이는 무엇인가?

정답과 해설: 프로세스는 주소 공간과 자원의 격리 단위이고 스레드는 한 프로세스 안에서 자원을 공유하는 실행 흐름이다.

문제 3

가비지 컬렉션 언어 응용도 운영체제 파일 핸들을 고갈시킬 수 있는 이유는 무엇인가?

정답과 해설: 파일은 메모리와 다른 커널 자원이며 명시적으로 닫지 않으면 회수 시점까지 열린 채 남을 수 있기 때문이다.

문제 4

CLI의 장점과 위험을 하나씩 쓰시오.

정답과 해설: 반복 자동화와 재현 기록이 장점이고, 대상·옵션 오타를 빠르게 넓은 범위에 적용할 위험이 있다.

문제 5

현재 경로를 확인하지 않고 상대 경로 명령을 실행하면 생기는 문제는 무엇인가?

정답과 해설: 의도와 다른 디렉터리의 파일을 조회·변경할 수 있다. 작업 위치와 절대 대상을 먼저 확인한다.

문제 6

실시간 운영체제의 주요 목표는 무엇인가?

정답과 해설: 높은 평균 속도만이 아니라 정해진 시간 제약 안에서 예측 가능하게 응답하는 것이다.

문제 7

PowerShell 파이프라인의 특징은 무엇인가?

정답과 해설: 주로 텍스트가 아니라 속성을 가진 객체를 다음 명령으로 전달해 구조적으로 필터·정렬할 수 있다.

문제 8

디스크 경보에서 파일 삭제 전 확인할 네 가지는 무엇인가?

정답과 해설: 파일 소유 응용, 사용 중 여부, 보존·백업 요구, 승인·원복을 확인한다.

문제 9

프로세스 생존과 정상 동작을 구분해야 하는 이유는 무엇인가?

정답과 해설: 프로세스가 실행 중이어도 입출력 대기, 교착, 의존성 실패로 업무 요청을 처리하지 못할 수 있기 때문이다.

14. 핵심 요약

  • 다양한 운영체제의 특징 설명은 커널·프로세스·메모리·파일·장치·권한의 공통 역할과 플랫폼별 목적·생태계 차이를 설명하는 활동이다.
  • 데스크톱, 서버, 모바일, 실시간 운영체제는 사용자 상호작용·자원·예측 가능성 요구가 다르다.
  • CLI·GUI에서 기본명령어 활용은 환경·사용자·경로를 확인하고 최소 권한으로 조회·탐색·상태 확인을 수행하는 일이다.
  • CLI는 자동화·재현, GUI는 탐색·시각화에 강점이 있으며 어느 쪽도 자동으로 안전하지 않다.
  • 위험한 변경 전에 읽기 전용 조사로 정확한 대상과 영향, 승인·백업·원복을 확인한다.
  • 운영체제·버전·명령·대상·결과를 비밀 없이 기록한다.
