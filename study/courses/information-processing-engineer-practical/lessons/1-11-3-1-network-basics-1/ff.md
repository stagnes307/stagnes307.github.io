# 1-11-3-1. 네트워크 계층별 역할 설명 · 응용 특성에 맞는 TCP·UDP 적용

## 수행 범위와 학습 목표

이 레슨은 통신 문제를 기능별 계층으로 나누어 **네트워크 계층별 역할 설명**을 수행하고, 신뢰성·지연·메시지 경계·혼잡·복구 요구를 분석해 **응용 특성에 맞는 TCP·UDP 적용**을 판단하는 실무를 다룬다. 다음 레슨의 패킷 스위칭·라우팅 알고리즘·IP 세부 설명은 주범위를 침범하지 않도록 필요한 연결 관계만 언급한다.

학습 후에는 다음을 할 수 있어야 한다.

- 계층화의 목적과 캡슐화·역캡슐화 흐름을 설명한다.
- OSI 참조 모델과 TCP/IP 모델의 각 계층 역할을 대응시킨다.
- 주소·포트·프레임·패킷·세그먼트 같은 용어의 범위를 구분한다.
- TCP의 연결·신뢰성·순서·흐름·혼잡 특성과 한계를 설명한다.
- UDP의 데이터그램·낮은 오버헤드 특성과 응용 책임을 설명한다.
- 응용 요구에 따라 TCP·UDP를 선택하고 실패·관찰·보안 조건을 설계한다.

## 왜 계층으로 나누는가

네트워크 통신은 응용 데이터 표현, 종단 간 전달, 여러 네트워크 사이 전달, 같은 링크의 프레임 전송, 물리 신호 전달이 결합된 작업이다. 이를 한 덩어리로 구현하면 매체나 응용이 바뀔 때 전체를 다시 만들어야 한다. 계층화는 각 층이 아래층의 서비스를 이용하고 위층에 정해진 서비스를 제공하도록 책임과 인터페이스를 나눈다.

계층화의 장점은 모듈화, 상호운용성, 변경 영향 축소, 문제 구간 분리다. 단점은 계층마다 헤더와 처리 비용이 생기고, 실제 시스템에서는 성능과 기능 때문에 계층 경계가 완전히 깔끔하지 않을 수 있다는 점이다. 시험에서는 “상위 계층은 하위 계층의 구현 세부를 몰라도 서비스를 사용한다”는 관계를 중심으로 본다.

송신 측에서는 상위 데이터에 각 계층의 제어정보가 붙는 캡슐화가 일어나고, 수신 측에서는 이를 해석·제거하는 역캡슐화가 일어난다.

```text
응용 메시지
  ↓ 전송 계층 헤더 추가
세그먼트/데이터그램
  ↓ 네트워크 계층 헤더 추가
패킷
  ↓ 링크 계층 헤더·트레일러 추가
프레임
  ↓
물리 신호 ───────────────→ 수신 측에서 역순 처리
```

중간 장비가 모든 상위 내용을 처리하는 것은 아니다. 같은 링크 장치는 주로 링크 계층 정보를, 서로 다른 네트워크를 연결하는 장치는 주로 네트워크 계층 정보를 바탕으로 전달한다. 실제 장비는 방화벽·프록시처럼 여러 계층을 함께 볼 수 있으므로 역할과 배치 목적을 구분한다.

## OSI 7계층 역할

OSI 참조 모델은 통신 기능을 일곱 계층으로 설명하는 개념 모델이다.

| 계층 | 핵심 역할 | 대표 판단 질문 |
|---|---|---|
| 7 응용 | 사용자·프로그램에 네트워크 서비스 제공 | 어떤 업무 프로토콜과 요청·응답 의미인가? |
| 6 표현 | 데이터 형식·인코딩·압축·보호 표현 | 양쪽이 같은 형식과 문자·직렬화를 해석하는가? |
| 5 세션 | 대화 설정·유지·동기·종료 | 논리 대화와 재개 지점을 어떻게 관리하는가? |
| 4 전송 | 종단 프로세스 간 전달, 포트, 신뢰성·흐름 | 순서·재전송·경계·지연 요구는 무엇인가? |
| 3 네트워크 | 논리 주소와 네트워크 간 경로 선택 | 목적지 네트워크로 어떻게 전달하는가? |
| 2 데이터링크 | 동일 링크의 프레임·매체 접근·오류 검출 | 다음 홉과 같은 링크에서 어떻게 전달하는가? |
| 1 물리 | 비트의 전기·광·무선 신호 전송 | 매체·속도·커넥터·신호 상태가 정상인가? |

표현·세션 기능은 실제 인터넷 응용에서 별도 프로토콜 계층으로 드러나지 않고 응용 라이브러리나 보안 세션에 결합되는 경우가 많다. 그렇다고 개념이 사라진 것은 아니다. 문자 인코딩 불일치, 직렬화 버전, 세션 재개 문제를 진단할 때 해당 책임을 구분할 수 있다.

물리 계층은 비트 신호를 보내며 데이터 의미를 해석하지 않는다. 데이터링크 계층은 같은 링크에서 프레임을 전달하고 오류 검출 정보를 사용할 수 있지만 일반적으로 종단 간 전달 전체를 보장하지 않는다. 네트워크 계층은 논리 주소와 경로를 통해 여러 링크를 잇는다. 전송 계층은 종단 호스트의 특정 프로세스를 포트로 구분한다.

## TCP/IP 모델과 대응

실무에서는 보통 응용, 전송, 인터넷, 네트워크 접근 계층으로 TCP/IP 모델을 설명한다.

| TCP/IP 계층 | OSI 대응 관점 | 예시 책임 |
|---|---|---|
| 응용 | 응용·표현·세션 | HTTP, 이름 해석, 메시지 형식, 응용 세션 |
| 전송 | 전송 | TCP·UDP, 포트, 종단 전달 |
| 인터넷 | 네트워크 | IP 논리 주소, 네트워크 간 전달 |
| 네트워크 접근 | 데이터링크·물리 | 프레임, 링크 주소, 매체 신호 |

두 모델의 계층 수를 기계적으로 일치시키기보다 각 기능의 책임을 설명해야 한다. 예를 들어 HTTPS 통신 오류에서 인증서 이름·암호 협상은 응용과 보안 세션 책임에 가깝고, TCP 연결 실패는 전송·경로·정책을, 링크 단절은 하위 계층을 살핀다.

## 주소와 식별자의 범위

통신에는 여러 식별자가 동시에 사용된다.

- 링크 주소는 같은 링크에서 다음 전달 대상을 식별한다.
- IP 주소는 네트워크 계층의 논리 인터페이스를 식별한다.
- 포트 번호는 호스트 안의 전송 종단·응용 서비스를 구분한다.
- 이름은 사람이 이해하는 서비스 식별을 논리 주소로 해석하는 데 쓰인다.
- 응용 ID는 사용자·주문·요청처럼 업무 대상을 식별한다.

IP와 포트가 같다고 사용자가 같은 것은 아니며, 응용 ID를 네트워크 경로 제어에 그대로 사용하지 않는다. 연결을 흔히 원본·목적지 주소와 포트, 전송 프로토콜의 조합으로 구분하지만 주소 변환·프록시·부하분산 장비가 사이에 있으면 응용이 관찰하는 상대 정보가 달라질 수 있다.

## 계층별 장애 진단

“서버가 안 된다”를 계층별 증거로 나눈다.

1. 물리·링크: 인터페이스 상태, 매체 연결, 링크 오류·프레임 손실을 본다.
2. 네트워크: 로컬 논리 주소·경로·목적 네트워크 도달성과 정책을 본다.
3. 전송: 목적 포트 수신 여부, 연결 상태, 손실·재전송·시간 제한을 본다.
4. 응용: 이름·보안 세션·요청 형식·인증·업무 오류와 서버 로그를 본다.

한 단계가 성공했다고 상위 단계가 성공한 것은 아니다. 목적지 주소에 도달해도 포트가 닫혀 있을 수 있고, TCP 연결이 성립해도 응용 인증이나 요청 형식이 실패할 수 있다. 반대로 응용 시간 초과를 보고 무조건 서버 코드만 의심하지 말고 하위 손실·경로·혼잡과 연결 풀도 확인한다.

진단은 승인된 환경에서 최소 영향으로 수행한다. 운영망을 광범위하게 탐색하거나 임의 패킷을 보내는 대신, 알려진 대상과 표준 관찰 자료·로그·지표를 사용한다. 각 계층의 시각·상관관계 정보를 맞춰 흐름을 재구성한다.

## TCP의 핵심 특성

TCP는 연결 지향의 신뢰성 있는 바이트 스트림 전송을 제공한다. 연결 설정 후 송신 바이트에 순서를 부여하고 확인응답·재전송으로 손실을 복구하며, 수신자가 감당할 수 있는 양을 흐름 제어한다. 네트워크 혼잡에 대응해 전송량을 조절한다.

“신뢰성”은 응용 업무가 성공했다는 뜻이 아니다. 바이트가 상대 전송 계층에 전달되어도 응용이 처리·커밋하기 전에 실패할 수 있다. 응답이 끊겼다면 요청이 처리되었는지 불확실할 수 있으므로 업무 요청 ID, 멱등성, 상태 조회가 필요하다.

TCP는 메시지 경계를 보존하지 않는 바이트 스트림이다. 송신 측이 두 번 쓴 데이터가 수신 측에서 같은 두 번의 읽기로 나오리라 보장할 수 없다. 응용 프로토콜은 길이 접두어, 구분 규칙, 고정 길이, 구조화 형식 등 명확한 프레이밍을 가져야 한다.

```text
송신 write("ABC") + write("DEF")
수신 가능 예:
  read → "ABCDEF"
또는 read → "AB", 다음 read → "CDEF"
```

TCP 연결은 양방향이며 종료도 양쪽 상태가 있다. 연결 성공만 확인하고 읽기·쓰기·전체 요청 시간 제한을 두지 않으면 자원이 무기한 묶인다. 연결 풀, 유휴 연결, 부분 종료, 재연결 정책을 응용 수명주기와 맞춘다.

## TCP 적용 판단

다음 특성에는 TCP가 자연스럽다.

- 모든 바이트를 순서대로 받아야 하는 파일·문서 전송
- 요청·응답의 누락이 허용되지 않고 재전송을 기반으로 하는 업무 통신
- 큰 데이터를 스트림으로 보내며 흐름 제어가 필요한 경우
- 널리 사용되는 연결 기반 응용 프로토콜을 사용하는 경우

그러나 “중요하므로 TCP”만으로 충분하지 않다. 종단 간 업무 확인, 중복 방지, 인증·인가, 메시지 프레이밍, 시간 제한은 응용 책임이다. 오래된 연결이 살아 있어도 상대 업무 상태가 유효한지 보장하지 않으므로 건강 확인과 재인증 정책을 둔다.

TCP에서 손실된 앞부분이 복구될 때 뒤 데이터가 응용에 늦게 전달될 수 있다. 하나의 연결에 서로 독립된 실시간 흐름을 모두 실으면 특정 손실이 다른 흐름 지연으로 나타날 수 있다. 연결 분리나 상위 프로토콜의 다중화 특성을 요구에 맞게 검토한다.

## UDP의 핵심 특성

UDP는 연결 설정 없이 독립 데이터그램을 전송한다. 헤더와 상태 부담이 작고 송신한 데이터그램의 경계를 유지한다. 기본 UDP 자체는 전달, 순서, 중복 제거, 흐름·혼잡 제어를 보장하지 않는다. 데이터그램이 사라지거나 순서가 바뀌거나 중복될 수 있고, 너무 큰 데이터그램은 경로에서 분할·손실 위험이 커질 수 있다.

UDP를 선택하면 응용이 필요한 만큼만 신뢰성·순서·시간·혼잡 책임을 설계해야 한다. 모든 TCP 기능을 응용에서 다시 만들 계획이라면 검증된 전송이나 상위 프로토콜이 더 적합한지 비교한다.

다음 특성에는 UDP를 검토할 수 있다.

- 오래된 데이터보다 최신 상태가 중요해 일부 손실을 허용하는 실시간 측정
- 짧은 요청·응답이며 응용이 시간 제한과 재시도를 명확히 통제하는 경우
- 한 송신자가 여러 수신자에게 전달하는 특성이 필요한 제한된 환경
- 응용·상위 프로토콜이 별도의 신뢰성·보안·혼잡 기능을 제공하는 경우

“빠르다”는 표현은 조건부다. 연결 설정 부담과 재전송 대기는 줄 수 있지만, 손실이 큰 환경에서 응용 재시도가 늘거나 데이터그램이 크면 오히려 품질이 나빠진다. 네트워크와 응용 지표로 측정한다.

## UDP 응용 설계 요소

UDP 메시지에는 버전, 종류, 요청·상관관계 ID, 순번 또는 기준시각, 길이, 무결성 확인 정보를 필요에 따라 둔다. 수신자는 형식·길이·발신 주체·허용 빈도를 검증하고 중복·역순·오래된 데이터를 정책에 따라 처리한다.

```text
receive(datagram):
    reject if source is not an approved peer
    reject if length or version is unsupported
    reject if authentication/integrity check fails
    ignore if sequence is older than accepted window
    limit work per sender and total rate
    process within bounded resources
```

이는 방어적 의사코드다. 발신 주소만으로 신원을 확정하지 않고 승인된 인증·무결성 수단을 사용한다. 요청보다 훨씬 큰 응답을 무제한 보내는 구조는 악용될 수 있으므로 인증 전 응답량과 처리 비용을 제한한다. 재시도는 무작위 분산과 최대 횟수를 두어 동시 폭주를 피한다.

## TCP·UDP 선택표

| 판단 항목 | TCP 경향 | UDP 경향 | 추가 질문 |
|---|---|---|---|
| 전달·순서 | 전송 계층에서 제공 | 응용이 필요한 범위 구현 | 업무 확인·중복 방지는 별도인가? |
| 데이터 형태 | 바이트 스트림 | 데이터그램 경계 유지 | 프레이밍·최대 메시지 크기는? |
| 지연 | 손실 복구로 지연 가능 | 오래된 자료를 버릴 수 있음 | 일부 손실 허용과 최신성 기준은? |
| 흐름·혼잡 | 기본 제공 | 응용·상위 프로토콜 책임 | 발신 속도와 수신 용량은? |
| 연결 상태 | 설정·유지 필요 | 기본 연결 상태 없음 | 인증·경로 변경·세션은 어떻게 관리? |
| 사용 예 | 파일, 일반 업무 요청 | 제한적 실시간 상태·짧은 질의 | 검증된 상위 프로토콜이 있는가? |

선택은 프로토콜 이름이 아니라 요구 근거로 남긴다. 동일 시스템에서도 제어 명령은 TCP 기반, 손실 허용 상태 방송은 UDP 기반처럼 기능마다 다를 수 있다. 조직 방화벽·중계·관찰 도구·운영 경험도 현실적 판단 요소다.

## 실무 적용 절차

1. 송신자·수신자, 메시지 의미, 크기·빈도·최대량을 정의한다.
2. 전달·순서·중복·최신성·지연·처리 완료 보장 수준을 정한다.
3. 네트워크·전송·응용 계층의 책임과 신뢰경계를 도식화한다.
4. TCP·UDP와 검증된 상위 프로토콜 대안을 비교한다.
5. 메시지 프레이밍·버전·인증·인가·무결성·오류 계약을 설계한다.
6. 시간 제한·재시도·중복 방지·속도·자원 제한을 정한다.
7. 정상·손실·중복·역순·지연·연결 종료·과부하 조건을 안전하게 시험한다.
8. 처리량·지연 분포·재전송·손실·오류·자원 사용을 측정한다.
9. 로그·지표·상관관계 ID와 장애 진단·복구 절차를 준비한다.
10. 요구·선택 근거·시험 결과·잔여 위험을 승인하고 기준선으로 남긴다.

완료는 연결 또는 데이터그램 전송 성공이 아니다. 응용 의미의 프레이밍과 완료 기준이 정확하고, 손실·중복·지연·종료에서 안전하며, 인증·인가·자원 제한이 적용되고, 운영자가 계층별 증거로 원인을 찾을 수 있어야 한다.

## 구체 실무 시나리오

물류 센서가 장비 온도를 1초마다 보내고, 별도의 제어 서버가 설정 변경 명령을 전달한다고 하자. 온도는 다음 측정이 곧 도착하므로 간헐 손실을 허용할 수 있지만 순번이 오래된 측정이 최신값을 덮어쓰면 안 된다. 제한된 내부망에서 검증된 보안 상위 프로토콜을 사용한 UDP 데이터그램을 검토하고, 장비 ID·순번·기준시각·인증 정보를 확인한다. 발신량과 데이터그램 크기를 제한하며 손실률·지연·오래된 자료 폐기를 관찰한다.

설정 변경 명령은 누락 없이 순서대로 전달되고 결과를 확인해야 하므로 TCP 기반의 검증된 응용 프로토콜을 선택한다. 그러나 TCP 수신만으로 설정 적용 완료로 보지 않고 요청 ID와 응용 응답을 사용한다. 재연결 후 같은 명령이 반복되어도 결과가 하나인지 확인한다. 두 기능 모두 인증·인가와 업무 감사가 필요하며, 전송 선택이 이를 대신하지 않는다.

## 산출물과 체크리스트

산출물은 계층별 구성·책임도, 통신 요구 명세, TCP·UDP 대안 비교표, 메시지·오류 계약, 연결·세션·재시도 설계, 보안·자원 제한표, 시험 케이스·성능 결과, 관찰·장애 진단 절차, 선택 결정 기록이다.

- [ ] 각 계층 역할과 상하위 서비스 관계를 설명할 수 있다.
- [ ] 결과 보장과 업무 완료 보장을 구분했다.
- [ ] 메시지 크기·빈도·경계·최신성·지연 요구가 명확하다.
- [ ] TCP 바이트 스트림에 응용 프레이밍을 정의했다.
- [ ] UDP의 손실·중복·역순·크기·혼잡 책임을 반영했다.
- [ ] 시간 제한·제한 재시도·중복 방지·자원 제한이 있다.
- [ ] 검증된 주체 인증·인가와 민감정보 보호를 적용한다.
- [ ] 장애·손실·종료·재연결·과부하 시험을 수행했다.
- [ ] 처리량·지연·손실·재전송·오류 지표를 관찰한다.
- [ ] 선택 근거와 요구·시험·운영 절차가 추적된다.

## 자주 틀리는 포인트

- OSI와 TCP/IP 계층 수만 외우고 각 책임과 장애 범위를 설명하지 못한다.
- 데이터링크 오류 검출을 종단 간 업무 성공 보장으로 오해한다.
- TCP를 메시지 단위 프로토콜로 보고 한 번의 write와 read가 대응한다고 생각한다.
- TCP 전달 성공을 서버 업무 트랜잭션 완료로 간주한다.
- UDP는 항상 빠르고 TCP는 항상 느리다고 단정한다.
- UDP에서 손실·중복·역순·혼잡·최대 크기를 고려하지 않는다.
- 시간 초과 뒤 새 요청 ID로 재시도해 업무를 중복 처리한다.
- 발신 주소만 믿고 상대 인증과 메시지 무결성을 생략한다.
- 응답 크기·처리량 제한 없이 짧은 UDP 요청에 큰 응답을 보낸다.
- 응용 오류를 보고 한 계층만 조사하고 상하위 증거를 연결하지 않는다.

## 확인 문제

1. 네트워크 계층화의 장점 세 가지와 한계를 쓰시오.
2. 캡슐화와 역캡슐화의 흐름을 설명하시오.
3. OSI 전송 계층과 네트워크 계층의 역할 차이를 쓰시오.
4. 링크 주소, IP 주소, 포트 번호가 각각 식별하는 범위를 쓰시오.
5. TCP가 제공하는 신뢰성과 응용 업무 완료 보장의 차이는 무엇인가?
6. TCP가 바이트 스트림이라는 특성이 응용 설계에 미치는 영향을 쓰시오.
7. UDP가 기본 제공하지 않는 보장 다섯 가지를 쓰시오.
8. 실시간 상태 측정에 UDP를 적용할 때 필요한 방어·품질 요소를 쓰시오.
9. TCP와 UDP를 선택할 때 확인할 응용 특성 여섯 가지를 쓰시오.
10. 계층별 네트워크 장애 진단의 순서와 완료 판단 기준을 설명하시오.

## 정답과 해설

1. 모듈화, 상호운용성, 변경 영향 축소, 장애 구간 분리가 장점이다. 헤더·처리 비용과 실제 기능의 계층 횡단이 한계가 될 수 있다.
2. 송신 측은 응용 데이터에 전송·네트워크·링크 제어정보를 순서대로 붙여 신호로 보내고, 수신 측은 반대 순서로 해석·제거해 응용에 전달한다.
3. 전송 계층은 종단 프로세스 간 전달과 포트·신뢰성·흐름을 담당하고, 네트워크 계층은 논리 주소와 여러 네트워크 사이 경로 전달을 담당한다.
4. 링크 주소는 같은 링크의 인터페이스·다음 홉, IP는 논리 네트워크 인터페이스, 포트는 호스트 안의 전송 종단·응용 서비스를 식별한다.
5. TCP는 바이트의 순서·재전송을 제공하지만 상대 응용의 검증·커밋 성공까지 보장하지 않는다. 업무 응답·요청 ID·상태 조회가 별도로 필요하다.
6. 송신 write 경계가 수신 read 경계와 같지 않으므로 길이·구분자·고정 구조 같은 응용 프레이밍과 부분 읽기 처리가 필요하다.
7. 전달, 순서, 중복 제거, 흐름 제어, 혼잡 제어가 기본 보장이 아니다. 응용이 필요한 범위와 상위 프로토콜을 설계한다.
8. 메시지 버전·길이·순번·시각, 상대 인증·무결성, 오래된 자료 폐기, 속도·자원 제한, 손실·지연 관찰과 제한 재시도를 포함한다.
9. 전달·순서·중복, 메시지 경계·크기, 지연·최신성, 흐름·혼잡, 연결 수명, 보안·운영 지원 중 여섯 가지를 확인한다.
10. 물리·링크, 네트워크, 전송, 응용 증거 순으로 범위를 좁히되 상하위 지표를 상관관계로 연결한다. 정상·손실·종료·과부하에서도 요구 결과와 관찰·복구가 확인되어야 완료다.

## 핵심 요약

- 계층화는 통신 책임을 분리해 변경과 장애 분석의 범위를 줄인다.
- OSI와 TCP/IP 모델은 계층 수보다 각 기능과 상하위 서비스 관계를 이해해야 한다.
- TCP는 신뢰성 있는 바이트 스트림이지만 메시지 경계와 업무 완료는 응용 책임이다.
- UDP는 데이터그램 경계를 유지하지만 전달·순서·중복·혼잡 보장을 기본 제공하지 않는다.
- TCP·UDP 선택은 신뢰성·지연·최신성·크기·흐름·운영 요구의 근거로 판단한다.
- 모든 전송에는 인증·인가·시간 제한·중복 방지·자원 제한·관찰과 복구가 필요하다.
