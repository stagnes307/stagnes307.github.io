01

학습 범위와 수행 목표

이 레슨의 정확한 토픽은 설치 매뉴얼 구성 수립과 작성, 사용자 매뉴얼 구성 수립과 작성이다. 제품을 처음 배치하는 설치 담당자와 제품 기능을 이용하는 최종 사용자가 각자의 목표를 오류 없이 달성하도록 매뉴얼의 독자·구조·절차·검증 기준을 수립하고 실제 문서로 작성하는 방법을 다룬다.

설치 파일과 매뉴얼을 배포 미디어로 조립하는 일은 다음 레슨의 범위다. 여기서는 문서 내용과 품질에 집중한다. 특정 운영체제 화면이나 도구 버전에만 맞는 설명을 보편 규칙처럼 단정하지 않고, 지원 버전별 차이가 있다면 분기와 확인 방법을 명시한다.

학습 목표는 다음과 같다.

  1. 설치 담당자와 최종 사용자의 과업·선행지식·위험을 구분한다.
  2. 설치 전 준비, 설치, 검증, 문제 해결, 제거·원복 흐름을 작성한다.
  3. 사용자 업무 시나리오 중심으로 탐색·입력·결과·오류 복구를 설명한다.
  4. 명령·화면·용어·버전·경고의 표현 기준을 일관되게 적용한다.
  5. 문서만 보고 수행하는 독립 검증으로 누락과 모호함을 찾아 수정한다.

3. 설치 매뉴얼 구성 수립과 작성

설치 매뉴얼 구성 수립과 작성은 설치 파일 실행 방법만 쓰는 일이 아니다. 설치 가능성 판정부터 성공 검증, 실패 복구, 업그레이드와 제거까지 하나의 운영 절차로 구성한다.

3.1 권장 구성

  1. 문서 식별: 제품·버전·문서 버전·대상 플랫폼·작성/승인일
  2. 목적과 독자: 필요한 권한과 선행지식
  3. 지원 환경: OS·아키텍처·런타임·브라우저·DB 등 적용 범위
  4. 사전 요구사항: CPU·메모리·디스크, 포트, 계정, 인증서, 외부 연결
  5. 설치 전 준비: 기존 데이터 백업, 서비스 중단, 파일 무결성 확인
  6. 신규 설치: 단계별 명령·화면·기대 결과
  7. 초기 구성: 안전한 값 주입, 권한, 연결, 서비스 등록
  8. 설치 검증: 버전·프로세스·로그·건강 상태·핵심 기능
  9. 업그레이드: 지원 출발 버전, 마이그레이션, 중단 시간, 호환성
  10. 실패 처리: 증상·원인 범주·확인 위치·안전한 복구
  11. 제거·원복: 프로그램과 사용자 데이터의 처리 구분
  12. 지원 정보: 수집할 진단 정보와 문의 경로

3.2 사전 요구사항을 검증 가능하게 쓴다

“충분한 메모리”보다 최소·권장 조건과 산정 기준을 적는다. “관리자 권한 필요”라고만 쓰지 말고 어떤 단계에서 왜 필요한지 설명한다. 네트워크는 목적지, 방향, 포트, 프록시·DNS·방화벽 조건을 기술하되 비밀번호와 운영 비밀을 예제에 넣지 않는다.

코드 예시 · text

설치 전 확인표
  [ ] 배포 파일의 제품·버전·플랫폼이 요청과 일치한다.
  [ ] 게시된 무결성 값 또는 서명이 검증됐다.
  [ ] 설치 경로와 데이터 경로의 여유 공간을 확인했다.
  [ ] 필요한 계정·권한·포트가 승인됐다.
  [ ] 기존 버전과 데이터의 백업·복구 시험 근거가 있다.
  [ ] 중단 시간과 사용자 공지가 승인됐다.

3.3 단계 문장의 형식

한 단계에는 하나의 주요 행동을 쓴다. 행동 앞에 위치와 선행 조건, 뒤에 기대 결과를 둔다. 선택 경로는 조건부터 제시한다.

나쁜 예: “설정하고 실행한 뒤 문제가 없으면 계속한다.”

좋은 예:

  1. 승인된 설치 계정으로 대상 서버에 로그인한다.
  2. 설정 예제 파일을 새 운영 설정 파일로 복사한다. 원본 예제는 보존한다.
  3. 데이터베이스 주소를 환경별 비밀 관리 절차로 주입한다. 문서 예제에 실제 비밀번호를 입력하지 않는다.
  4. 구성 검증 기능을 실행한다.
  5. 결과가 valid이면 서비스 시작 단계로 진행하고, 오류면 표시된 항목만 수정한 뒤 다시 검증한다.

실제 명령은 제품·OS 공식 절차를 사용한다. 위험한 삭제·권한 완화 명령을 복구 지침처럼 제시하지 않는다.

3.4 설치 성공을 관찰 가능하게 한다

“설치가 완료되었습니다” 화면만으로 성공을 판단하지 않는다. 설치된 버전, 실행 프로세스·서비스, 포트 상태, 데이터베이스 연결, 초기 건강 점검, 핵심 읽기·쓰기 시나리오를 확인한다. 로그 파일이 생성된다는 사실뿐 아니라 오류가 없는지와 시간대·권한이 적절한지도 본다.

3.5 실패와 원복

실패 절에는 증상, 가능한 원인 범주, 안전한 확인 순서, 수집할 진단 정보, 중단·지원 기준을 적는다. 무조건 재설치하면 원인을 지우거나 데이터를 덮을 수 있다. 원복은 프로그램 파일, 설정, 데이터베이스 스키마, 사용자 데이터의 호환성을 각각 확인하고 검증된 백업에서 수행한다.

코드 예시 · text

[사전 판정]

06

5. 사용자 매뉴얼 구성 수립과 작성

사용자 매뉴얼 구성 수립과 작성은 메뉴 이름을 나열하는 것이 아니라 사용자의 업무 목표, 권한, 입력, 결과와 오류 복구를 설명하는 일이다.

5.1 권장 구성

  1. 제품과 문서 버전, 적용 범위
  2. 독자·역할별 권한과 사전 조건
  3. 로그인·로그아웃·안전한 세션 사용
  4. 화면 공통 구조, 탐색, 검색·정렬·필터
  5. 핵심 업무별 빠른 시작
  6. 기능별 입력, 실행, 결과 확인, 취소·수정
  7. 파일 가져오기·내보내기 형식과 제한
  8. 알림, 상태, 오류 메시지와 복구
  9. 접근성·키보드·표시 설정
  10. FAQ, 용어집, 개인정보·보안 주의, 지원 정보

5.2 업무 시나리오 중심으로 쓴다

메뉴 순서만 따라가면 사용자가 “월별 완료 주문 보고서 만들기” 같은 목표를 해결하기 어렵다. 목표를 제목으로 두고 다음 형식으로 설명한다.

코드 예시 · text

목표: 완료 주문을 기간별로 조회해 승인용 파일로 저장한다.
권한: 보고서 조회·내보내기 권한
준비: 조회 기간과 조직 범위
절차: 보고서 메뉴 → 조건 입력 → 결과 건수 확인 → 내보내기
성공: 화면 건수와 파일 행 수·기간이 일치
예외: 결과 0건, 권한 부족, 파일 생성 지연, 민감 열 포함 여부

입력값에는 형식, 단위, 필수 여부, 허용 범위와 예를 제공한다. 결과에는 성공 알림만 아니라 데이터가 어디에 저장되고 다음에 무엇을 할 수 있는지 적는다.

5.3 화면과 명칭을 일치시킨다

버튼·메뉴·필드 이름은 실제 제품과 동일하게 쓴다. 강조 표기 규칙을 일관되게 사용하고 화면 캡처에는 필요한 영역만 표시한다. 버전이 바뀌기 쉬운 화면 캡처만 의존하지 말고 텍스트 단계와 대체 설명을 함께 제공한다. 이미지 속 비밀·고객 데이터는 제거한다.

5.4 오류에서 회복하게 한다

오류 코드를 나열하는 데서 끝내지 않는다. 사용자가 확인할 입력, 다시 시도해도 되는 조건, 저장되지 않은 데이터, 관리자에게 전달할 지원 코드와 시각을 알려 준다. 권한 오류 때 권한을 우회하는 방법을 제시하지 않고 정식 요청 경로를 안내한다.

5.5 접근성과 안전성

색상만으로 상태를 구분하지 않고 텍스트 이름을 제공한다. 키보드 경로, 초점 순서, 확대 시 동작, 이미지 대체 설명을 검토한다. 예제 데이터는 가상값을 사용하고 비밀번호·주민번호·인증 토큰 같은 민감값을 화면·로그 예제에 넣지 않는다.

07

6. 문서 표현 규칙과 변경 관리

용어집을 정하고 같은 대상을 여러 이름으로 부르지 않는다. 경고·주의·참고를 구분한다.

  • 경고: 데이터 손실, 보안, 서비스 중단 가능성이 있는 행동 전에 배치한다.
  • 주의: 실패·오작동 가능성을 낮추기 위한 조건을 행동 전에 제시한다.
  • 참고: 필수는 아니지만 이해·효율에 도움이 되는 정보다.

문서 버전과 제품 버전의 대응표를 둔다. 제품 변경 요청에는 코드·시험뿐 아니라 매뉴얼 영향 검토를 포함한다. 버튼 이름이 바뀌거나 기본값이 달라지면 해당 절과 캡처, 색인, 번역본까지 갱신한다. 폐기된 절이 검색 결과에 남아 사용자를 잘못 안내하지 않도록 게시 상태도 관리한다.

08

7. 매뉴얼 검증 절차와 판단 기준

7.1 기술 검토

개발·설치·운영 담당자가 명령, 화면, 기본값, 권한, 오류와 원복의 사실성을 확인한다. 작성자의 기억보다 실제 승인 빌드와 시험 환경을 근거로 한다.

7.2 독립 수행 시험

제품 구현에 참여하지 않은 대상 독자가 매뉴얼만 보고 과업을 수행한다. 질문한 지점, 되돌아간 단계, 예상과 다른 결과, 소요 시간을 기록한다. 옆에서 구두 설명으로 도와주면 문서 누락을 발견할 수 없다.

7.3 환경·버전 시험

모든 지원 플랫폼 또는 대표 조합에서 분기를 확인한다. 신규 설치와 업그레이드, 권한이 충분한 경우와 부족한 경우, 정상과 오류를 포함한다. 문서의 예상 결과가 실제 제품과 다르면 제품·문서 중 어느 쪽이 요구와 맞는지 판정해 수정한다.

7.4 문서 품질 시험

링크, 목차, 색인, 검색어, 코드 블록 복사 가능성, 이미지 대체 텍스트, 확대·키보드 탐색, 인쇄·오프라인 가독성을 확인한다. 맞춤법만 통과했다고 작업 성공성이 보장되지는 않는다.

09

8. 산출물과 체크리스트

산출물은 독자·과업 분석, 문서 구성안, 용어·표기 규칙, 설치 매뉴얼, 사용자 매뉴얼, 화면·예제 자산 목록, 요구·문서 추적표, 독립 수행 시험 결과, 승인·버전 대응표다.

  • [ ] 제품·문서 버전과 지원 환경이 명확하다.
  • [ ] 독자 역할·권한·선행지식을 구분했다.
  • [ ] 설치 전 조건·백업·중단 승인·무결성 확인이 있다.
  • [ ] 각 설치 단계에 행동과 기대 결과가 있다.
  • [ ] 성공 검증·오류 확인·원복·지원 전환 기준이 있다.
  • [ ] 사용자 기능을 업무 목표와 결과 중심으로 설명했다.
  • [ ] 입력 형식·범위·예외와 복구 방법을 제공한다.
  • [ ] 실제 명칭·버전과 화면·문서 표현이 일치한다.
  • [ ] 민감정보를 제거하고 접근성을 검토했다.
  • [ ] 대상 독자가 문서만으로 독립 수행 시험을 통과했다.

9. 자주 틀리는 포인트와 실기 함정

  1. 설치 매뉴얼을 설치 버튼 순서만 나열한 문서로 만든다.
  2. “적절한 공간”, “필요한 권한”처럼 검증 불가능하게 쓴다.
  3. 명령의 실행 위치·권한·기대 결과를 생략한다.
  4. 백업 파일 생성만 확인하고 실제 복구 가능성을 확인하지 않는다.
  5. 제거와 원복을 같은 것으로 보고 데이터·스키마 호환성을 놓친다.
  6. 사용자 매뉴얼을 메뉴 사전처럼 작성해 업무 목표를 찾기 어렵게 한다.
  7. 실제 제품과 다른 버튼·필드명을 사용한다.
  8. 화면 캡처에 고객 데이터·토큰·내부 주소를 노출한다.
  9. 오류 코드만 나열하고 안전한 다음 행동을 설명하지 않는다.
  10. 작성자가 직접 검증하고 초보 독자의 독립 수행 시험을 생략한다.

문제 7

11. 정답과 해설

문제 1 정답과 해설

설치 매뉴얼은 설치·운영 담당자가 제품을 올바르게 설치·기동·검증·원복하는 것이 목표다. 사용자 매뉴얼은 권한을 가진 최종 사용자가 제품 기능으로 업무 결과를 만드는 것이 목표다.

문제 2 정답과 해설

“충분함”과 “관리자”의 범위가 없어 사전 판정이 불가능하고 불필요한 과잉 권한을 줄 수 있다. 최소·권장 용량, 산정 기준, 권한이 필요한 단계와 목적을 명시해야 한다.

문제 3 정답과 해설

실행 위치와 선행 조건, 수행할 한 가지 행동, 필요한 권한·입력, 기대 결과와 실패 시 분기를 포함한다.

문제 4 정답과 해설

설치된 제품 버전, 서비스·프로세스 상태, 외부 연결과 건강 점검, 로그 오류 여부, 핵심 읽기·쓰기 기능을 확인할 수 있다.

문제 5 정답과 해설

백업이 손상됐거나 필요한 설정·스키마가 빠졌을 수 있다. 복구 시험 또는 승인된 복구 검증, 이전 프로그램과 데이터 형식의 호환성까지 확인해야 한다.

문제 6 정답과 해설

업무 목표, 필요한 역할·권한, 준비 입력, 단계별 행동, 성공 결과, 빈 결과·권한·충돌 같은 예외와 안전한 복구를 포함한다.

문제 7 정답과 해설

증상, 사용자가 확인할 값, 재시도 조건, 저장 여부, 지원 코드·필요 진단 정보를 제공한다. 권한 우회, 데이터 무조건 삭제, 비밀 노출 같은 위험한 해결은 제시하지 않는다.

문제 8 정답과 해설

구두 설명이 문서의 누락·모호함을 대신하면 실제 고객이 혼자 수행할 때 실패할 지점을 찾을 수 없다. 질문과 막힌 단계를 관찰해 문서를 수정해야 한다.

문제 9 정답과 해설

변경의 문서 영향 분석 → 근거와 실제 빌드로 절차·화면 수정 → 기술 검토 → 지원 환경별 시험 → 대상 독자 독립 수행 → 접근성·링크 검증 → 제품·문서 버전 연결과 승인 순이다.

12. 핵심 요약

  • 설치 매뉴얼 구성 수립과 작성은 지원 환경·사전 조건·설치·초기 구성·성공 검증·문제 해결·원복을 설치 담당자의 작업 흐름으로 작성하는 일이다.
  • 설치 단계는 위치·조건·행동·기대 결과·실패 분기가 분명해야 하며 백업과 복구 가능성을 구분한다.
  • 사용자 매뉴얼 구성 수립과 작성은 메뉴 나열이 아니라 역할별 업무 목표, 입력, 절차, 결과, 오류 복구를 설명하는 일이다.
  • 실제 명칭과 안전한 예제, 접근 가능한 화면 설명, 민감정보 제거, 제품·문서 버전 추적이 필요하다.
  • 개발에 참여하지 않은 대상 독자가 매뉴얼만 보고 설치와 업무 과업을 완료해야 최종 품질을 확인할 수 있다.
