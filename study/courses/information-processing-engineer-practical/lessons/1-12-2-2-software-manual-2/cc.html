01

학습 범위와 수행 목표

이 레슨의 정확한 토픽은 설치파일·매뉴얼 배포용 미디어 제작, 제품소프트웨어 매뉴얼 작성하기의 적용 절차와 판단 기준이다. 승인된 설치 파일과 매뉴얼을 고객에게 전달할 물리·논리 미디어로 조립하고, 파일 완전성·무결성·가독성·호환성·보안을 검증하는 과정을 다룬다.

매뉴얼 본문의 구성과 문장 작성은 앞 레슨의 범위이므로 여기서는 승인된 문서를 입력으로 사용한다. “미디어”는 광디스크나 USB 같은 물리 매체뿐 아니라 다운로드 묶음, 읽기 전용 이미지, 폐쇄망 반입용 저장장치처럼 하나의 배포 단위로 관리되는 전달물을 포함한다. 실제 매체의 사용 가능 여부는 고객 보안정책과 계약을 우선한다.

학습 목표는 다음과 같다.

  1. 고객 환경·용량·보안·망 조건에 맞는 배포 미디어를 선정한다.
  2. 설치 파일, 매뉴얼, 고지, 무결성 정보를 일관된 구조로 조립한다.
  3. 대소문자·경로·인코딩·파일시스템·읽기 권한의 호환성을 검증한다.
  4. 승인 마스터와 복제본이 동일함을 해시·서명·목록으로 확인한다.
  5. 악성코드 검사, 전달·인수, 보관·폐기까지 추적 가능한 절차를 만든다.
02

1. 배포용 미디어의 역할

배포용 미디어는 여러 파일을 담는 용기만이 아니다. 수신자가 올바른 제품·버전·플랫폼을 식별하고, 설치 시작점을 찾고, 파일이 손상·변조되지 않았음을 확인하며, 필요한 매뉴얼을 오프라인에서도 열 수 있게 하는 공식 전달 산출물이다.

코드 예시 · text

승인 설치 파일 ─┐
승인 매뉴얼 ────┼→ 미디어 구성 명세 → 마스터 조립 → 독립 검증
릴리즈 노트 ────┤                              │
라이선스·고지 ──┤                              ▼
해시·서명 정보 ─┘                       승인 복제·전달·인수

개별 입력 파일이 승인됐어도 미디어 조립 과정에서 누락, 오래된 문서 혼입, 파일명 충돌, 손상, 악성코드 유입이 발생할 수 있다. 따라서 최종 미디어 자체를 새 산출물로 식별하고 검증한다.

다음 질문으로 후보를 거른다.

  • 고객망이 인터넷·사내망·완전 폐쇄망 중 무엇인가?
  • 이동식 저장장치와 실행 파일 반입이 허용되는가?
  • 전체 크기와 최대 단일 파일 크기는 얼마인가?
  • 고객 OS가 해당 파일시스템·이미지 형식·문자 인코딩을 읽는가?
  • 전달 중 기밀성, 인수자 확인, 만료, 추적이 필요한가?
  • 재전달과 긴급 패치가 얼마나 자주 필요한가?
  • 장기 보관 기간과 복구 시험 요구가 있는가?

가장 저렴한 미디어보다 필수 보안·호환 조건을 만족하는 미디어를 선택한다. 하나의 형태가 모든 고객을 만족하지 못하면 승인된 복수 형태를 운영하되 내용 동일성을 확인한다.

04

3. 배포 미디어 구성 명세

미디어를 만들기 전에 최상위 구조와 각 파일의 출처·버전을 정의한다.

코드 예시 · text

PRODUCT_4_1_RELEASE/
  START-HERE.txt
  MANIFEST.json
  CHECKSUMS.txt
  installer/
    product-4.1-platform-arch.pkg
  manuals/
    installation-guide-4.1-ko.pdf
    user-guide-4.1-ko.pdf
  release-notes/
    release-notes-4.1-ko.pdf
  licenses/
    product-license.txt
    third-party-notices.txt
  support/
    diagnostic-information.txt

START-HERE에는 제품·버전, 지원 플랫폼, 시작 문서, 무결성 확인 방법, 주의사항과 공식 지원 경로를 적는다. 자동 실행 기능은 보안정책이나 OS에서 차단될 수 있고 예기치 않은 실행 위험이 있으므로 필수 시작 수단으로 의존하지 않는다.

매니페스트에는 상대 경로, 파일 크기, 해시, 파일 역할, 입력 승인 식별자를 기록할 수 있다. 해시 파일도 같은 미디어에 있으므로 배포자 진위 확인이 필요하면 별도 신뢰 경로의 전자서명 또는 게시값과 연결한다. 해시 일치만으로 누가 만들었는지는 알 수 없다.

05

4. 파일과 디렉터리 호환성

4.1 파일명과 경로

운영체제마다 금지 문자, 예약 이름, 최대 경로, 대소문자 구분이 다르다. Manual.pdf와 manual.pdf를 별도 파일로 두면 어떤 환경에서는 충돌할 수 있다. 공백과 비ASCII 문자를 사용할 수 있어도 설치 도구·압축 해제기·스크립트가 일관되게 처리하는지 시험한다.

4.2 파일시스템과 크기

미디어 파일시스템이 큰 단일 설치 파일을 담을 수 있는지 확인한다. 임의 분할은 사용자의 조립 오류를 만들 수 있으므로 지원된 분할·검증 절차가 있을 때만 사용한다. 압축 해제 후 필요한 여유 공간도 시작 문서에 표시한다.

4.3 문서 가독성

PDF, HTML, 텍스트 등 문서 형식은 고객 환경에서 추가 유료 도구나 인터넷 없이 열 수 있어야 한다. 글꼴 포함, 문자 깨짐, 링크, 목차, 검색, 확대, 인쇄와 화면 낭독 접근성을 확인한다. HTML 문서는 원격 자산이 없어도 핵심 내용이 보여야 한다.

4.4 실행 권한과 속성

아카이브·복사 방식에 따라 실행 비트, 읽기 전용 속성, 심볼릭 링크, 긴 경로가 손실될 수 있다. 원본에서 동작했다는 이유로 복제본에서도 같다고 가정하지 않는다. 최종 미디어에서 꺼낸 파일로 설치 시험을 한다.

06

5. 무결성·기밀성·악성코드 통제

5.1 해시와 전자서명

해시는 복제 전후 파일이 같은지 확인한다. 승인된 알고리즘과 도구를 사용하고 파일별 값과 전체 이미지 값을 구분한다. 전자서명은 신뢰된 발행자와 변경 여부를 확인하는 데 쓰며 인증서 유효성·서명 시각·검증 경로 정책도 조직 기준에 따른다.

코드 예시 · text

입력 승인 해시 == 마스터 내부 파일 해시
마스터 이미지 해시 == 보관 기록의 해시
복제본 이미지 해시 == 마스터 이미지 해시
수신 후 계산 해시 == 전달 문서의 승인 해시

값 하나라도 다르면 “대부분 같음”으로 승인하지 않는다. 전송·복제 오류인지 입력 변경인지 조사하고 새 마스터를 만들 경우 전체 검증을 다시 수행한다.

5.2 악성코드와 작업 환경

조립 전 입력, 조립 환경, 최종 미디어를 승인된 최신 검사 정책으로 확인한다. 개인 USB나 인터넷에서 내려받은 유틸리티를 조립 작업에 섞지 않는다. 검사 시각, 엔진·정책 식별, 결과와 예외 승인을 기록한다. 검사 통과가 모든 보안성을 증명하는 것은 아니므로 서명·출처·파일 목록 검증과 결합한다.

5.3 기밀 데이터

공용 미디어에 고객별 라이선스, 비밀번호, 인증서 개인키, 운영 주소, 실제 데이터베이스 백업을 넣지 않는다. 고객별 정보가 꼭 필요하다면 공용 마스터와 별도 암호화 전달물을 분리하고 수신자·만료·회수 절차를 둔다.

07

6. 설치파일·매뉴얼 배포용 미디어 제작 절차

단계 1: 배포 요청과 수신 환경 확인

제품·버전·플랫폼·언어·고객, 납기, 망·매체 반입 정책, 암호화·서명·보관 요구를 확인한다. 구두 요청만으로 고객별 비밀을 포함하지 않는다.

단계 2: 승인 입력 수집

설치 파일, 설치·사용자 매뉴얼, 릴리즈 노트, 라이선스·제3자 고지, 지원 문서의 승인 버전과 해시를 수집한다. 초안, 이전 버전, 작업자 다운로드 폴더 파일을 제외한다.

단계 3: 구성 명세와 용량 산정

경로·파일명·역할·크기·해시·문서 버전을 표로 작성한다. 전체 크기뿐 아니라 단일 파일 제한, 압축 해제 공간, 향후 작은 수정 여유를 검토한다.

단계 4: 격리 환경에서 마스터 조립

깨끗한 작업 공간에 명세된 파일만 복사하고 매니페스트·시작 문서를 생성한다. 자동 생성 결과를 검토하며 생성 도구와 설정도 식별한다. 공용 마스터에는 고객 비밀을 넣지 않는다.

단계 5: 기술·콘텐츠 검증

파일 수·크기·해시를 입력과 비교하고 서명과 악성코드 검사 결과를 확인한다. 목차·링크·문자·이미지가 열리는지, 설치 파일명과 매뉴얼의 버전·명령이 맞는지 점검한다.

단계 6: 목표 환경 독립 시험

마스터에서 직접 꺼낸 설치 파일로 신규 설치와 핵심 실행을 시험하고, 미디어만 제공받은 시험자가 시작 문서를 따라 매뉴얼을 찾고 무결성을 확인하는지 본다. 폐쇄망이면 원격 링크 없이 필요한 정보가 있는지 확인한다.

단계 7: 마스터 승인과 복제

마스터 이미지 또는 묶음의 해시, 승인자, 생성 시각, 도구·입력을 기록하고 변경 불가 상태로 보관한다. 복제는 승인 마스터에서만 수행하고 각 복제본을 전수 또는 승인된 샘플링 기준으로 검증한다. 고위험 배포는 전수 해시 비교가 적합하다.

단계 8: 전달·인수·보관·폐기

수신자와 전달 채널을 확인하고 물리 매체는 봉인·일련번호·인수 기록을 관리한다. 다운로드는 계정, 만료, 횟수, 전송 암호화를 적용한다. 반환·폐기 시 보존 기간과 안전한 파기 정책을 따른다.

08

7. 제품소프트웨어 매뉴얼 작성하기의 적용 절차와 판단 기준

제품소프트웨어 매뉴얼 작성하기의 적용 절차와 판단 기준을 배포 미디어까지 연결하면 다음과 같다.

  1. 독자·과업·지원 환경을 정의한다.
  2. 제품·설치·시험 근거로 설치·사용자 매뉴얼을 작성한다.
  3. 기술 검토와 독립 수행 시험으로 내용을 승인한다.
  4. 제품 버전과 문서 버전을 연결하고 배포 대상을 고정한다.
  5. 미디어 구성 명세에 승인 문서와 설치 파일을 등록한다.
  6. 마스터 조립 후 링크·문자·가독성·파일 무결성을 검증한다.
  7. 목표 환경에서 미디어만으로 설치·업무 시작이 가능한지 시험한다.
  8. 동일 마스터를 복제·전달하고 인수·보관·폐기 이력을 관리한다.

판단 기준은 내용 정확성만이 아니다. 올바른 문서를 쉽게 찾는가, 설치 파일과 문서 버전이 일치하는가, 오프라인에서도 읽히는가, 변조·누락을 확인할 수 있는가, 수신자에게 안전하게 도달하는가를 함께 본다.

09

8. 구체 시나리오: 폐쇄망 고객용 전달 미디어

고객은 이동식 매체 반입 전 보안 검사를 요구하며 외부 링크에 접근할 수 없다. 제품 4.1의 설치 파일은 크기가 크고 한국어·영어 매뉴얼이 필요하다.

  1. 고객이 허용한 읽기 전용 이미지 또는 승인 매체와 파일시스템을 확인한다.
  2. 설치 파일 크기와 단일 파일 제한, 두 언어 문서를 포함한 전체 용량을 산정한다.
  3. 공용 설치 파일, 두 언어 매뉴얼, 릴리즈 노트, 고지, 시작 문서와 해시 목록을 조립한다.
  4. 고객 라이선스는 별도 승인 채널로 보내 공용 마스터에서 분리한다.
  5. 네트워크가 끊긴 시험 환경에서 문서 열기, 해시 확인, 설치·시작을 수행한다.
  6. 악성코드 검사와 이미지 해시를 승인 기록에 남기고 봉인·일련번호로 전달한다.
  7. 고객 인수 후 해시 일치와 매체 상태를 확인하고 수령 기록을 보관한다.

문서의 “온라인 도움말 참조” 링크만 남아 있다면 폐쇄망에서는 작업이 막힌다. 핵심 설치·오류 복구 정보는 미디어 내부에 포함해야 한다.

10

9. 산출물과 체크리스트

산출물은 배포 요청서, 수신 환경·보안 조건표, 미디어 구성 명세, 승인 입력 목록, 마스터·복제본 해시, 서명·악성코드 검사 결과, 목표 환경 시험 보고서, 승인·전달·인수·보관·폐기 기록이다.

  • [ ] 고객 망·매체·파일시스템·보안 정책을 확인했다.
  • [ ] 설치 파일과 매뉴얼의 제품·버전·플랫폼이 일치한다.
  • [ ] 초안·이전 버전·비밀·실제 고객 데이터를 제외했다.
  • [ ] 시작 문서에서 설치·매뉴얼·검증 경로를 찾을 수 있다.
  • [ ] 경로·대소문자·인코딩·단일 파일 크기 호환성을 시험했다.
  • [ ] 문서가 오프라인에서 열리고 링크·문자·접근성이 정상이다.
  • [ ] 입력·마스터·복제본·수신본의 해시 관계가 기록됐다.
  • [ ] 서명·악성코드 검사와 예외 승인이 추적된다.
  • [ ] 목표 환경에서 최종 미디어로 설치 시험을 했다.
  • [ ] 전달·인수·보관 기간·폐기 절차가 있다.

10. 자주 틀리는 포인트와 실기 함정

  1. 개별 파일 승인을 최종 미디어 승인과 같다고 본다.
  2. 용량 합계만 보고 단일 파일 크기와 파일시스템 제한을 놓친다.
  3. 대소문자만 다른 파일을 함께 넣어 대상 OS에서 충돌한다.
  4. 개발 PC에서 압축이 풀린다는 이유로 고객 환경 시험을 생략한다.
  5. 해시가 일치하면 발행자 신원도 자동 확인된다고 생각한다.
  6. 공용 미디어에 고객 라이선스·비밀번호·운영 데이터를 넣는다.
  7. 외부 링크만 제공해 폐쇄망에서 매뉴얼을 사용할 수 없게 한다.
  8. 악성코드 검사 후 파일을 수정하고 기존 검사 결과를 재사용한다.
  9. 승인 마스터가 아니라 작업자 개인 복사본에서 복제한다.
  10. 전달만 기록하고 고객 인수·보관·폐기 상태를 관리하지 않는다.

미디어 형태 선정 전에 확인할 고객 환경 조건 네 가지를 쓰시오.

12. 정답과 해설

문제 1 정답과 해설

미디어는 제품·버전 식별, 설치 시작점, 문서 탐색, 무결성 확인, 안전한 전달을 함께 제공하는 공식 산출물이다. 조립 중 누락·오래된 파일 혼입도 별도로 검증해야 한다.

문제 2 정답과 해설

망 연결 여부, 이동식 매체 허용, 대상 OS·파일시스템, 전체·단일 파일 크기, 암호화·인수 정책과 보관 기간 등을 확인한다.

문제 3 정답과 해설

상대 경로, 파일 역할, 크기, 해시, 제품·문서 버전, 입력 승인 식별자를 기록할 수 있다.

문제 4 정답과 해설

해시는 두 파일 내용의 동일·변경 여부를 비교한다. 전자서명은 신뢰 체계 안에서 발행자 진위와 서명 후 변경 여부를 검증한다.

문제 5 정답과 해설

조립 과정에서 누락, 이름 충돌, 속성 손실, 문서·설치 버전 불일치, 손상이나 악성 파일 유입이 생길 수 있기 때문이다. 최종 미디어에서 꺼낸 파일로 시험해야 한다.

문제 6 정답과 해설

원격 링크 없이 설치·오류 복구에 필요한 핵심 내용이 모두 있어야 하고, 추가 인터넷 도구 없이 열리며 문자·글꼴·검색·접근성이 정상이어야 한다.

문제 7 정답과 해설

공용 설치본을 반복 검증할 수 있고 비밀 오배송의 영향 범위를 줄인다. 고객별 자료에는 별도 수신자·만료·회수·감사를 적용할 수 있다.

문제 8 정답과 해설

복제본 전체 이미지 또는 파일 해시가 마스터와 같은지, 매체 오류가 없는지, 라벨·일련번호·봉인과 대상 정보가 맞는지 확인한다.

문제 9 정답과 해설

요청·환경 확인 → 승인 입력 수집 → 구성·용량 명세 → 격리 환경 마스터 조립 → 콘텐츠·보안 검증 → 목표 환경 시험 → 마스터 승인·복제 → 전달·인수 → 보관·폐기 순이다.

13. 핵심 요약

  • 설치파일·매뉴얼 배포용 미디어 제작은 승인 입력을 고객 환경에 맞는 전달 단위로 조립하고 최종 미디어의 완전성·호환성·무결성·보안을 다시 검증하는 과정이다.
  • 미디어는 망, 반입 정책, 용량·단일 파일, 파일시스템, 경로·인코딩, 보관 요구를 기준으로 선택한다.
  • 매니페스트·시작 문서·해시·서명은 파일 탐색과 동일성·진위 판단을 돕지만 각각의 역할을 구분해야 한다.
  • 제품소프트웨어 매뉴얼 작성하기의 적용 절차와 판단 기준은 독자·과업 정의에서 문서 승인, 버전 고정, 미디어 조립, 목표 환경 검증, 전달 이력까지 연결된다.
  • 승인 마스터와 복제·수신본의 관계를 해시와 기록으로 추적하고, 공용 파일과 고객 비밀을 분리하며, 인수·보관·폐기까지 관리한다.
