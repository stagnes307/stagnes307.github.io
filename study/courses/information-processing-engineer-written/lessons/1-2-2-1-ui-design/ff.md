# 1-2-2-1. UI 설계

> **공식 범위**: 2026년 정보처리기사 출제기준의 `소프트웨어설계 > 화면 설계 > UI 설계`에서 제시한 **감성공학**, **UI 설계 도구**를 학습한다. 특정 제품명이나 버전별 기능은 출제기준의 고정 지식이 아니므로, 감성을 설계 속성으로 변환하는 원리와 도구의 유형·선정 기준을 중심으로 설명한다.

UI 설계는 기능을 화면에 배치하는 일만이 아니다. 사용자가 느끼길 원하는 신뢰감, 편안함, 활력, 전문성 같은 정성적 목표를 색상·형태·간격·피드백·동작과 같은 구체적 속성으로 바꾸고, 적합한 도구로 시각화·시험·공유해야 한다. 이때 “예쁘다”라는 개인 취향이 아니라 사용자 조사와 평가 결과를 근거로 판단한다.

---

## 1. 토픽 ① 감성공학

### 1.1 감성공학의 뜻

**감성공학**은 사용자가 제품이나 서비스에 대해 느끼는 감성적 요구를 조사하고, 이를 설계 요소로 변환하여 평가하는 접근이다. 공학이라는 말이 붙는 이유는 감성을 막연한 영감으로 처리하지 않고 자료 수집, 분석, 설계 가설, 검증의 반복 과정으로 다루기 때문이다.

다음 두 문장은 차이가 크다.

- 막연한 요구: “젊고 믿음직한 화면으로 만든다.”
- 설계 가능한 요구: “주 사용자가 느끼는 ‘활기 있음’과 ‘신뢰감’을 핵심 감성으로 선정하고, 색 대비·정보 밀도·모서리 형태·피드백 속도 후보를 비교 평가한다.”

두 번째 문장은 감성어, 설계 변수, 평가라는 연결이 있어 검증할 수 있다.

### 1.2 감성과 사용성의 관계

감성은 사용성과 반대가 아니다. 보기 좋은 화면이라도 작업을 완료하기 어렵다면 좋은 UI가 아니며, 기능이 정확해도 불안하고 복잡하게 느껴져 사용을 꺼리면 목표를 달성하지 못한다.

| 관점 | 중심 질문 | 예시 지표 |
|---|---|---|
| 기능성 | 필요한 기능을 제공하는가? | 기능 충족 여부 |
| 사용성 | 효율적이고 오류 없이 목표를 달성하는가? | 완료율, 시간, 오류 수 |
| 감성 | 사용자가 어떤 인상과 느낌을 받는가? | 신뢰감, 편안함, 흥미 등의 평가 |
| 접근성 | 다양한 사용자가 이용할 수 있는가? | 키보드 접근, 인지 가능성 |

한 요소가 여러 관점에 영향을 줄 수 있다. 예를 들어 높은 명도 대비는 정보 인지를 돕고 안정감을 줄 수 있지만, 지나치게 강한 대비와 경고색 남용은 긴장감을 높일 수 있다. 따라서 감성 목표도 업무 맥락과 함께 평가한다.

## 2. 감성공학 적용 절차

### 단계 1: 사용자와 사용 맥락을 정의한다

누가, 어디서, 어떤 목표로, 어떤 제약에서 사용하는지 정한다. 같은 “편안함”도 병원 예약, 게임, 금융 거래에서 의미와 설계 표현이 다르다.

확인 항목:

- 주 사용자와 보조 사용자
- 사용 빈도와 숙련도
- 사용 기기와 물리적 환경
- 업무의 긴급성·위험성·개인정보 민감도
- 사용자가 이미 가진 기대와 경험

### 단계 2: 감성어를 수집한다

인터뷰, 관찰, 설문, 기존 제품 비교에서 사용자가 실제로 쓰는 표현을 모은다. `깔끔한`, `따뜻한`, `전문적인`, `경쾌한`, `안정적인`처럼 형용사 형태가 많이 쓰인다.

비슷한 단어는 묶고, 의미가 너무 넓거나 맥락과 무관한 단어는 정제한다. 설계자가 좋아하는 단어만 선택하면 편향이 생긴다.

### 단계 3: 핵심 감성 구조를 찾는다

감성어 쌍이나 평가 척도로 여러 시안을 비교한다. 예를 들어 `복잡한–단순한`, `차가운–따뜻한`, `가벼운–진중한`의 연속선에서 평가할 수 있다. 수집 결과에서 서로 비슷하게 움직이는 감성을 묶어 핵심 차원을 찾는다.

통계 기법을 사용할 수 있지만 시험 핵심은 특정 계산법이 아니라 **감성 자료를 구조화한다**는 점이다. 표본과 측정 방식이 부적절하면 숫자가 있어도 객관적 근거가 되지 않는다.

### 단계 4: 감성과 설계 요소를 연결한다

핵심 감성을 조작 가능한 UI 변수와 연결한다.

| 감성 목표 | 검토할 설계 변수 | 주의점 |
|---|---|---|
| 안정적·신뢰감 | 정보 계층, 일관된 정렬, 명확한 상태, 절제된 색 | 어두운 색만 쓰면 신뢰가 생긴다고 단정하지 않음 |
| 편안함 | 여백, 읽기 길이, 대비, 오류 문구, 단계 수 | 낮은 대비는 읽기 어려울 수 있음 |
| 활기·경쾌함 | 색 조합, 형태, 전환 리듬, 피드백 | 과도한 동작은 집중·접근성을 해칠 수 있음 |
| 전문성 | 정확한 용어, 데이터 표현, 일관된 구성 | 정보량 과다가 전문성은 아님 |

색 하나와 감성 하나를 고정적으로 대응시키지 않는다. 문화, 나이, 경험, 업무 맥락에 따라 인상이 달라지므로 여러 요소의 조합을 실제 사용자에게 검증한다.

### 단계 5: 대안을 제작하고 평가한다

설계 변수의 조합이 다른 여러 대안을 만들고, 사용자에게 감성 평가와 과업 수행을 함께 실시한다. 감성 점수만 높고 오류율이 증가한다면 대안을 수정해야 한다.

### 단계 6: 결과를 반영하고 반복한다

목표 감성과 실제 평가의 차이를 분석한다. 글자 크기, 정보 밀도, 색, 동작, 메시지 등을 수정하고 다시 평가한다. 감성공학은 한 번의 설문이 아니라 반복 설계 과정이다.

## 3. 감성 요구를 잘못 다루는 방식

1. **설계자의 취향을 사용자 감성으로 간주**: “내가 보기 좋다”는 근거가 아니다.
2. **색상 하나로 감성을 단정**: 감성은 맥락과 요소 조합에서 형성된다.
3. **긍정 감성만 추구**: 경고나 금융 승인처럼 긴장·주의가 필요한 순간도 있다.
4. **사용성을 희생**: 시각 효과 때문에 버튼 위치나 상태가 불명확해지면 실패다.
5. **한 집단의 결과를 전체 사용자로 확대**: 사용자 특성과 표본 범위를 기록해야 한다.
6. **평가 문항이 유도적**: “이 세련된 화면이 마음에 드십니까?”보다 중립적 척도가 적절하다.

## 4. 토픽 ② UI 설계 도구

### 4.1 도구는 산출물과 단계에 맞춰 선택한다

**UI 설계 도구**는 화면 구조를 표현하고, 시각 요소를 제작하고, 상호작용을 시험하고, 팀과 산출물을 공유하는 수단이다. 하나의 도구가 모든 단계에서 최선일 필요는 없다.

| 도구 유형 | 주된 용도 | 적합한 단계 | 대표 산출물 |
|---|---|---|---|
| 스케치·와이어프레임 | 정보 구조와 배치 비교 | 초기 아이디어 | 저충실도 화면 구조 |
| 화면 디자인 | 색·서체·간격·컴포넌트 정의 | 시각 설계 | 고충실도 화면 시안 |
| 프로토타이핑 | 클릭·이동·상태 변화 모의 | 상호작용 검증 | 조작 가능한 모형 |
| 흐름·다이어그램 | 사용자 작업과 화면 관계 정리 | 구조·흐름 설계 | 사용자 흐름, 상태 흐름 |
| 협업·검토 | 의견, 버전, 승인, 변경 기록 | 전 단계 | 주석, 리뷰 기록 |
| 개발 전달 | 치수·자산·상태·규칙 공유 | 구현 연계 | 설계 명세, 자산 목록 |
| 평가 지원 | 사용성·접근성·행동 결과 확인 | 검증 | 평가 결과와 개선 항목 |

제품명은 바뀌어도 위 범주는 비교적 안정적이다. 시험에서 도구를 묻는다면 “어느 단계의 어떤 산출물을 지원하는가”로 판단한다.

### 4.2 충실도에 따른 선택

**저충실도** 도구는 빠르고 수정 비용이 낮아 구조와 흐름을 논의하기 좋다. 반면 실제 시각 인상이나 정교한 동작 판단에는 한계가 있다.

**고충실도** 도구는 최종 모습과 상호작용을 현실적으로 확인하기 좋지만 제작 비용이 높고, 외형이 완성돼 보이면 이해관계자가 구조적 문제를 말하기 어려워질 수 있다.

따라서 초기에는 빠른 대안을 넓게 탐색하고, 핵심 흐름이 안정되면 필요한 부분의 충실도를 높이는 방식이 효율적이다.

### 4.3 UI 설계 도구 선정 기준

1. **목적 적합성**: 구조, 시각, 동작, 평가 중 어떤 문제를 해결하는가?
2. **표현력**: 필요한 화면 상태와 상호작용을 표현할 수 있는가?
3. **학습·제작 비용**: 팀이 일정 안에 사용할 수 있는가?
4. **협업성**: 동시 작업, 의견, 승인, 변경 이력을 지원하는가?
5. **호환성**: 개발 환경과 필요한 자산·명세를 전달할 수 있는가?
6. **재사용성**: 공통 컴포넌트와 스타일을 일관되게 관리할 수 있는가?
7. **보안·운영 조건**: 민감한 자료의 저장·권한·반출 조건에 맞는가?
8. **접근성 검토**: 대비, 키보드 흐름, 대체 표현 등을 확인할 수 있는가?

유명하거나 기능이 많은 도구가 항상 적합한 것은 아니다. 간단한 흐름 검토에 고비용 도구를 쓰면 학습과 관리 부담만 커질 수 있다.

## 5. UI 설계 도구를 활용하는 표준 흐름

### 5.1 입력을 정리한다

확정된 UI 요구, 사용자 작업, 콘텐츠, 제약을 준비한다. 도구를 먼저 열고 빈 화면에서 구성하면 중요한 요구가 디자인 취향에 묻힐 수 있다.

### 5.2 구조 대안을 빠르게 비교한다

주요 작업을 완료하는 데 필요한 정보 순서와 화면 구성을 여러 개 만든다. 이 단계에서는 색과 장식보다 정보 계층, 탐색, 오류 회복을 본다.

### 5.3 공통 요소를 정의한다

버튼, 입력 필드, 표, 메시지, 여백과 같은 공통 요소의 상태를 정의한다. 정상·비활성·오류·로딩·완료 상태가 일관되어야 한다.

### 5.4 상호작용을 연결한다

핵심 사용자 흐름을 조작 가능한 형태로 연결한다. 성공 경로뿐 아니라 입력 오류, 취소, 빈 결과, 권한 부족 상태도 포함한다.

### 5.5 사용자와 검증한다

대표 사용자가 목표 과업을 수행하도록 하고 완료 여부, 시간, 오류, 막힌 지점, 감성 평가를 수집한다. 사용자가 “좋다”고 말했는지만 기록하지 않는다.

### 5.6 개발 가능하게 전달한다

화면별 상태, 크기, 간격, 색의 역할, 콘텐츠 규칙, 자산, 동작, 예외를 명시한다. 전달 후에도 개발 결과와 설계 의도가 일치하는지 검토한다.

## 6. 적용 예시: 재난 알림 앱

### 목표

- 핵심 감성: 신뢰감, 긴급성, 침착함
- 핵심 과업: 알림 내용을 이해하고 행동 지침을 확인함
- 제약: 실외 사용, 작은 화면, 긴급 상황, 다양한 연령층

### 감성-설계 가설

```text
신뢰감 → 출처와 시각 표시를 명확히 하고 용어를 일관되게 사용
긴급성 → 우선순위를 색뿐 아니라 제목·아이콘·문구로 함께 표현
침착함 → 한 화면의 선택지를 줄이고 행동 순서를 단계적으로 제공
```

### 도구 선택

1. 저충실도 도구로 정보 우선순위와 행동 흐름을 비교한다.
2. 화면 디자인 도구로 대비와 글자 계층을 정교화한다.
3. 프로토타이핑 도구로 알림 확인·행동 지침·완료 흐름을 연결한다.
4. 평가 지원 방법으로 야외 밝기, 한 손 조작, 키보드·보조기술 사용을 검토한다.

### 판단

강한 경고색을 화면 전체에 사용해 긴급성 점수가 높아졌더라도 본문 가독성이 낮고 불안감이 과도하면 개선해야 한다. 핵심 행동의 인지, 완료율, 오류 수와 감성 평가를 함께 본다.

---

## 7. 시험 함정

1. 감성공학을 미적 디자인이나 색채 심리 하나로 축소한다.
2. 감성 요구를 설계자의 직관만으로 결정한다.
3. 감성어 수집 후 설계 요소와 연결하지 않는다.
4. 감성 평가만 하고 실제 과업의 완료율과 오류를 보지 않는다.
5. 저충실도는 품질이 낮고 고충실도는 항상 우수하다고 생각한다.
6. 프로토타이핑 도구를 최종 구현 도구와 동일시한다.
7. UI 설계 도구 선정에서 기능 수만 비교하고 협업·보안·호환성을 무시한다.
8. 공통 컴포넌트의 오류·비활성·로딩 상태를 누락한다.

## 8. 확인 문제

### 문제 1

감성공학에서 “따뜻한 화면을 만든다”라는 요구를 그대로 사용하면 부족한 이유는 무엇인가?

### 문제 2

프로젝트 초기에 여러 화면 구조를 빠르게 비교하려 한다. 저충실도와 고충실도 중 무엇이 일반적으로 적합하며, 그 이유는 무엇인가?

### 문제 3

UI 설계 도구를 고를 때 목적 적합성 외에 확인할 기준을 네 가지 쓰라.

### 문제 4

한 시안의 감성 평가 점수는 높지만 사용자 과업 오류율도 크게 증가했다. 어떻게 판단해야 하는가?

## 정답과 해설

1. **정답**: 대상 사용자와 사용 맥락, 감성의 의미, 연결할 설계 변수, 평가 기준이 없기 때문이다. 감성어를 조사하고 설계 속성과 측정 방법으로 구체화해야 한다.
2. **정답**: 저충실도가 적합하다. 제작과 수정 비용이 낮아 정보 구조와 흐름 대안을 빠르게 탐색할 수 있다. 시각 인상 검증 단계에서는 충실도를 높인다.
3. **정답 예**: 표현력, 학습·제작 비용, 협업성, 호환성, 재사용성, 보안·운영 조건, 접근성 검토 능력 중 네 가지다.
4. **정답**: 감성만으로 채택하지 않는다. 기능성·사용성·접근성과 함께 판단하고 오류 원인이 되는 설계 요소를 수정한 뒤 다시 평가한다.

---

## 9. 최종 요약

- **감성공학**은 사용자 감성을 수집·구조화하고 UI 설계 변수로 변환하여 평가하는 반복적 접근이다.
- 사용자·맥락 정의 → 감성어 수집 → 핵심 감성 도출 → 설계 요소 연결 → 대안 제작·평가 → 개선 순서로 적용한다.
- 감성, 기능성, 사용성, 접근성은 함께 만족해야 하며 색상 하나와 감성을 고정 대응시키지 않는다.
- **UI 설계 도구**는 와이어프레임, 화면 디자인, 프로토타이핑, 흐름, 협업, 개발 전달, 평가 지원 등 목적에 따라 구분한다.
- 도구는 유명세가 아니라 목적 적합성, 표현력, 비용, 협업, 호환성, 재사용, 보안, 접근성 기준으로 선택한다.
