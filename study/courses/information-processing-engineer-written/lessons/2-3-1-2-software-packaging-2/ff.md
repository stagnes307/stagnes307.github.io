# 2-3-1-2. 애플리케이션 모니터링 도구 · DRM

> **공식 범위**: 소프트웨어개발 > 제품소프트웨어 패키징 > 제품소프트웨어 패키징 > `애플리케이션 모니터링 도구`, `DRM`

## 0. 배포 이후의 운영과 권리 보호

제품소프트웨어를 전달한 뒤에는 두 가지를 지속적으로 통제해야 한다. 첫째, 애플리케이션이 실제 환경에서 정상적으로 동작하는지 관찰하고 이상에 대응해야 한다. 둘째, 디지털 콘텐츠와 소프트웨어가 허가된 사용자·범위·기간·방법 안에서 사용되도록 권리를 보호해야 한다.

이 레슨은 서로 다른 두 주제를 분리해 이해한다.

1. `애플리케이션 모니터링 도구`: 상태·성능·오류와 사용자 영향에 관한 신호를 수집·저장·분석·시각화·경보한다.
2. `DRM`: 디지털 저작물의 사용 권한과 조건을 기술·정책적으로 표현하고 배포·사용 과정에서 통제한다.

모니터링은 제품의 운영상태를, DRM은 콘텐츠와 소프트웨어의 이용권한을 중심으로 한다. 둘 다 도구를 설치하는 것만으로 목표가 달성되지 않으며 정책, 지표, 책임, 보안과 검증 절차가 필요하다.

---

## 1. 애플리케이션 모니터링 도구

### 1.1 모니터링의 목적

모니터링은 시스템에서 발생하는 신호를 지속적으로 관찰해 정상 범위를 이해하고, 이상을 조기에 발견하며, 장애 원인 분석과 용량·품질 개선에 근거를 제공하는 활동이다.

주요 질문은 다음과 같다.

- 사용자가 핵심 기능을 정상적으로 완료할 수 있는가?
- 오류율과 응답시간이 허용 범위 안인가?
- 어느 구성요소·버전·지역·사용자군에서 문제가 발생하는가?
- 자원과 의존 서비스의 상태가 악화되고 있는가?
- 배포 전후에 성능과 오류 패턴이 달라졌는가?
- 경보를 받은 담당자가 원인과 영향, 대응 절차를 찾을 수 있는가?

### 1.2 관찰 신호: 메트릭·로그·트레이스

| 신호 | 형태 | 강점 | 예시 |
|---|---|---|---|
| 메트릭(metric) | 시간에 따른 수치 집계 | 추세·임계값·대시보드 | 요청 수, 오류율, p95 응답시간 |
| 로그(log) | 사건의 구조화된 기록 | 상세 문맥·오류 내용 | 요청 ID, 상태, 오류 유형 |
| 트레이스(trace) | 한 요청의 분산 호출 경로 | 구간별 지연·의존관계 | 웹→주문→결제 호출 |
| 이벤트(event) | 배포·설정 변경·장애 등 사건 | 변화와 증상의 시간 연결 | 버전 배포, 장애 전환 |

메트릭만으로 이상 시점을 찾을 수 있지만 어떤 요청이 왜 실패했는지 부족할 수 있다. 로그는 상세하지만 전체 추세를 집계하기 어렵고, 트레이스는 서비스 간 경로에 강하지만 모든 업무 상태를 설명하지 않는다. 공통 시간 기준과 추적 ID, 버전·환경 태그로 신호를 연결한다.

### 1.3 모니터링 계층

- 사용자 관점: 화면·API의 성공률, 사용자 과업 완료, 실제 응답시간
- 애플리케이션 관점: 요청률, 오류율, 지연, 큐, 스레드, 내부 상태
- 의존성 관점: DBMS, 캐시, 메시지, 외부 API의 지연·실패
- 인프라 관점: CPU, 메모리, 저장공간, 네트워크와 인스턴스 상태
- 업무 관점: 주문·결제·가입·정산의 성공 건수와 지연

CPU가 정상이라는 사실만으로 서비스가 정상인 것은 아니다. 사용자 로그인 기능이 모두 실패해도 CPU는 낮을 수 있다. 기술 자원 지표와 사용자·업무 결과 지표를 함께 본다.

### 1.4 도구의 주요 기능

`애플리케이션 모니터링 도구`는 제품에 따라 범위가 다르지만 일반적으로 다음을 지원한다.

- 에이전트, 로그 수집기, 표준 인터페이스 등을 통한 신호 수집
- 시간·환경·버전·서비스·요청 ID 기준 저장과 검색
- 집계, 상관분석, 백분위수와 변화율 계산
- 대시보드와 상태 시각화
- 정적 임계값·동적 기준선·복합조건 경보
- 알림 전달, 담당자 배정, 이슈·대응 절차 연계
- 보존·마스킹·접근권한과 감사 관리
- 배포 전후 비교와 용량 추세 분석

에이전트 방식은 상세한 내부 정보를 얻기 쉽지만 설치·자원·호환성을 관리해야 한다. 에이전트리스 방식은 설치 부담이 적을 수 있지만 관찰 깊이가 제한될 수 있다. 실제 도구는 혼합 방식을 사용할 수 있다.

### 1.5 좋은 지표와 경보

좋은 지표는 이름, 단위, 수집주기, 계산식, 차원, 정상 범위와 소유자가 분명하다. 값이 계속 증가하는 누적 카운터와 현재 상태를 나타내는 게이지를 혼동하면 해석이 달라진다.

경보는 “CPU 80% 초과”처럼 기술값 하나보다 사용자 영향과 지속시간, 여러 조건을 연결할 때 더 유용할 수 있다.

```text
5분 동안 주문 오류율이 기준 초과
AND 요청 수가 최소 관측량 이상
→ 주문 서비스 담당자에게 심각도와 대응 절차 전송
```

순간적 변화에 모두 경보를 보내면 경보 피로가 생기고 중요한 알림을 놓친다. 지속시간, 재알림, 억제, 중복 통합, 자동 해제와 에스컬레이션 규칙을 정한다. 경보마다 영향, 확인 대시보드, 첫 대응, 소유자와 종료 조건을 연결한다.

### 1.6 모니터링 구축 절차

1. 핵심 사용자·업무 흐름과 실패 영향을 정한다.
2. 성공률·지연·처리량·가용성 등 서비스 수준 지표를 정의한다.
3. 필요한 메트릭·로그·트레이스와 공통 식별자를 설계한다.
4. 민감정보를 제외·마스킹하고 접근·보존 정책을 정한다.
5. 대표 부하에서 수집 비용과 정확성을 검증한다.
6. 정상 기준선과 대시보드를 만들고 경보 조건을 조정한다.
7. 대응 절차와 담당자, 에스컬레이션을 연결한다.
8. 실제 장애·훈련 뒤 탐지시간, 오경보, 미탐과 대응성을 개선한다.

로그에 비밀번호, 인증 토큰, 전체 개인정보를 기록하지 않는다. 진단 가치와 수집·저장 비용, 개인정보 위험의 균형을 잡는다.

## 2. DRM

### 2.1 의미와 목표

DRM(Digital Rights Management)은 디지털 콘텐츠나 소프트웨어의 저작권과 이용권한을 식별하고, 허가된 조건에 따라 접근·복제·실행·출력·전송 등을 통제하는 기술과 관리체계다.

목표는 단순 암호화가 아니다.

- 콘텐츠와 권리자·배포자를 식별한다.
- 사용자 또는 장치의 권한을 인증한다.
- 사용 횟수, 기간, 장치, 기능 등 이용조건을 표현한다.
- 콘텐츠를 보호된 형태로 유통한다.
- 허가된 환경에서만 키와 라이선스를 제공한다.
- 사용 이력·정산·권리 변경을 관리한다.
- 불법 복제·변조·무단 재배포의 억제와 추적을 지원한다.

DRM이 모든 불법 복제를 완전히 막는다고 보장할 수는 없다. 보호 수준, 사용 편의, 오프라인 요구, 접근성, 장치 변경과 고객지원 비용을 함께 고려한다.

### 2.2 참여자와 구성 요소

| 요소 | 역할 |
|---|---|
| 콘텐츠 제공자 | 저작물을 만들고 권리와 정책을 정의 |
| 배포자 | 보호된 콘텐츠를 사용자에게 전달 |
| 사용자·소비자 | 정당한 라이선스 조건에서 콘텐츠 사용 |
| 클리어링하우스 | 권리·라이선스·결제·정산 정보를 중개·관리할 수 있음 |
| 패키저 | 콘텐츠를 암호화하고 식별·권리 메타데이터와 결합 |
| 라이선스 서버 | 인증 후 권리, 조건, 키 사용정보를 제공 |
| DRM 클라이언트 | 라이선스를 검증하고 허용된 사용을 실행 |

구체 구성과 명칭은 시스템에 따라 다를 수 있다. 핵심은 콘텐츠 자체와 사용권한을 분리해 배포하고, 신뢰된 정책과 키로 사용을 통제하는 흐름이다.

### 2.3 보호 기술

- 암호화: 허가되지 않은 사용자가 콘텐츠 원문을 읽기 어렵게 한다.
- 키 관리: 생성·저장·배포·회수·갱신과 폐기를 통제한다.
- 인증·인가: 사용자·장치의 신원을 확인하고 허가된 권리를 적용한다.
- 권리 표현: 기간, 횟수, 장치, 재생·복사·인쇄 등의 조건을 기술한다.
- 워터마킹: 콘텐츠에 식별정보를 넣어 유출 추적을 지원할 수 있다.
- 핑거프린팅: 콘텐츠 또는 사용자별 특징을 이용해 식별·추적한다.
- 위변조 방지: 클라이언트·라이선스·콘텐츠 변경을 탐지·억제한다.

워터마킹은 콘텐츠를 읽지 못하게 하는 암호화와 목적이 다르다. 눈에 보이거나 보이지 않는 식별을 통해 소유권 표시 또는 유출 경로 추적에 쓰일 수 있다.

### 2.4 일반 처리 흐름

```text
권리자: 콘텐츠와 이용정책 등록
→ 패키징: 콘텐츠 암호화·식별정보 결합
→ 배포: 보호된 콘텐츠 전달
→ 사용자: 구매·구독·권한 요청
→ 라이선스 발급: 인증·결제·정책 확인 후 권리와 키 제공
→ 사용: DRM 클라이언트가 조건 확인 후 허용 기능 실행
→ 기록·정산: 사용·권리 변경과 정산 정보를 관리
```

오프라인 사용이 필요하면 만료시각과 로컬 라이선스 보호, 시계 변조, 재연결 정책을 고려한다. 장치 분실·교체, 환불, 권리 회수와 서비스 종료 시 합법 사용자의 접근을 어떻게 보장할지도 운영정책에 포함한다.

### 2.5 DRM과 다른 통제의 차이

| 통제 | 중심 목적 |
|---|---|
| 접근통제 | 시스템·자원에 누가 접근할 수 있는지 통제 |
| DRM | 전달된 디지털 저작물의 구체적 이용권한과 조건을 지속 통제 |
| DLP | 조직의 중요정보가 허가 없이 유출되는 것을 탐지·방지 |
| 암호화 | 데이터 기밀성을 위한 보호 기술로 DRM의 일부가 될 수 있음 |

DRM은 접근 허용 뒤에도 복사·재생 횟수·기간 같은 권리를 적용할 수 있다는 점이 특징이다.

## 3. 적용 예시

교육 동영상 서비스에서 다음을 구현한다고 하자.

- 모니터링: 재생 시작 성공률, 시작 지연 p95, 중간 끊김, 라이선스 발급 오류율을 메트릭으로 본다. 요청 ID로 재생 API, 라이선스 서버와 콘텐츠 전달 로그를 연결한다.
- DRM: 구독 상태와 허용 장치 수를 확인해 기간 제한 라이선스를 발급하고 보호된 동영상의 재생만 허용한다.

라이선스 발급 오류 경보가 증가하면 단순히 DRM 정책 위반으로 보지 않는다. 인증 장애, 키 서비스 지연, 잘못된 배포 버전과 합법 사용자 권한 문제를 로그·트레이스로 구분한다. 모니터링이 DRM 운영의 장애 대응을 돕지만 두 체계의 목적은 다르다.

## 4. 시험 함정

1. **모니터링을 CPU 감시로 한정**: 사용자·업무 성공률, 오류, 지연과 의존 상태를 함께 본다.
2. **메트릭·로그·트레이스 동일시**: 집계 추세, 상세 사건, 요청 경로라는 강점이 다르다.
3. **프로세스 실행이면 서비스 정상**: 핵심 기능과 사용자 결과를 확인해야 한다.
4. **모든 이상에 즉시 경보**: 경보 피로를 줄이도록 지속시간·영향·최소 관측량을 고려한다.
5. **로그에 민감정보 기록**: 진단 목적이어도 비밀·개인정보를 최소화·보호한다.
6. **DRM과 암호화 동일시**: DRM은 권리 표현·라이선스·인증·사용통제·정산을 포함한다.
7. **워터마킹과 암호화 혼동**: 워터마킹은 식별·추적, 암호화는 원문 보호가 중심이다.
8. **DRM이 복제를 완전 차단**: 보호 수준과 공격·운영·사용 편의의 현실적 균형이 필요하다.
9. **DRM과 일반 접근통제 동일시**: DRM은 전달 후에도 저작물의 구체 이용조건을 통제한다.

## 5. 확인 문제

### 문제 1

서비스 CPU와 메모리가 정상인데 모든 로그인 요청이 실패한다. 모니터링상 정상이라고 볼 수 있는가?

**정답과 해설**: 아니다. 인프라 지표는 정상일 수 있지만 사용자 핵심 기능의 성공률은 0이다. 사용자·업무 지표와 애플리케이션 오류를 함께 봐야 한다.

### 문제 2

분산 요청에서 어느 서비스 구간이 지연되는지 파악하는 데 특히 유용한 신호는?

**정답과 해설**: 트레이스다. 한 요청이 여러 서비스와 구간을 통과한 경로와 구간별 시간을 연결해 볼 수 있다.

### 문제 3

순간적으로 CPU가 80%를 넘을 때마다 호출 경보를 보내면 어떤 문제가 생길 수 있는가?

**정답과 해설**: 일시적 정상 변동까지 알림이 되어 경보 피로와 무시를 유발할 수 있다. 지속시간, 사용자 영향, 최소 부하와 다른 지표를 조합한다.

### 문제 4

DRM에서 보호된 콘텐츠와 라이선스를 분리하는 이유는?

**정답과 해설**: 동일 콘텐츠를 배포하더라도 사용자·기간·장치·기능별로 서로 다른 이용권한과 키를 적용하고 변경·회수할 수 있기 때문이다.

### 문제 5

워터마크가 있으면 콘텐츠 원문을 읽지 못하게 보호한 것인가?

**정답과 해설**: 반드시 그렇지 않다. 워터마킹은 소유·사용자 식별이나 유출 추적이 중심이며 기밀성은 암호화와 접근통제 등으로 확보한다.

## 6. 최종 요약

- `애플리케이션 모니터링 도구`는 메트릭·로그·트레이스·이벤트를 수집·저장·분석·시각화하고 이상을 경보한다.
- 인프라 지표뿐 아니라 사용자 과업, 업무 성공률, 오류·지연과 의존 서비스 상태를 함께 본다.
- 좋은 경보는 사용자 영향, 지속시간, 최소 관측량, 소유자와 대응 절차를 연결하고 경보 피로를 줄인다.
- 수집 신호에는 공통 시각·추적 ID·버전·환경을 넣되 비밀과 개인정보를 보호한다.
- `DRM`은 디지털 저작물의 식별, 암호화, 권리 표현, 인증·라이선스, 키 관리, 사용통제와 정산을 포괄한다.
- 암호화는 DRM의 보호 기술 중 하나이며 워터마킹·핑거프린팅은 식별과 추적에 활용된다.
- DRM은 일반 접근통제와 달리 콘텐츠 전달 후에도 기간·횟수·장치·기능 같은 이용조건을 적용할 수 있다.
