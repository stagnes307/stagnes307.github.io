# 3-1-2-2. 그룹 함수 · 오류 처리

## 학습 목표와 범위

이 레슨은 여러 행을 하나의 통계값으로 요약하는 **그룹 함수**와 SQL 실행 중 발생하는 실패를 탐지·분류·대응하는 **오류 처리**를 다룬다. 학습 후에는 집계 함수의 NULL 처리, GROUP BY와 HAVING의 역할, 소계·총계를 만드는 확장 그룹화의 결과를 판단할 수 있어야 한다. 또한 입력 검증, 예외 처리기, 트랜잭션 정리, 오류 정보 전달을 연결해 안전한 SQL 처리 흐름을 설계할 수 있어야 한다.

앞 레슨의 DML 명령과 윈도우 함수, 뒤 레슨의 DDL 및 트랜잭션 이론은 필요한 비교만 한다. 구체적인 오류 코드·예외 선언 문법과 ROLLUP·CUBE 지원 형태는 DBMS마다 다르므로, 여기서는 공통 원리와 시험에서 요구하는 결과 해석에 집중한다.

## 그룹 함수의 기본 개념

그룹 함수는 여러 입력 행을 받아 그룹별 하나의 결과를 만드는 함수다. 집계 함수라고도 한다. WHERE를 통과한 전체를 한 그룹으로 계산하거나, GROUP BY로 나눈 각 그룹을 따로 계산한다. 대표 함수는 COUNT, SUM, AVG, MAX, MIN이다.

| 함수 | 의미 | 일반적인 NULL 처리 |
|---|---|---|
| COUNT(*) | 행의 개수 | 행 자체를 세므로 특정 열의 NULL과 무관 |
| COUNT(표현식) | 표현식이 NULL이 아닌 행의 개수 | NULL 결과는 제외 |
| SUM(표현식) | 값의 합계 | NULL 값은 제외 |
| AVG(표현식) | 값의 평균 | NULL 값은 합계와 분모에서 제외 |
| MAX / MIN | 최댓값 / 최솟값 | NULL 값은 제외 |

NULL 제외는 NULL을 0으로 바꾼다는 뜻이 아니다. 급여 값이 100, NULL, 200일 때 AVG(급여)는 일반적으로 150이다. NULL을 0으로 바꾼 뒤 평균을 구하면 100이 되어 의미가 달라진다. “미입력 급여를 0으로 간주한다”는 업무 규칙이 명시된 경우에만 변환 후 집계한다.

입력 행이 하나도 없을 때 COUNT는 0을 반환하는 것이 일반적이고, SUM·AVG·MAX·MIN은 NULL이 될 수 있다. 보고서에서 0이 필요하다면 결과에 기본값을 적용하되, 데이터 없음과 실제 합계 0을 구분해야 하는 업무라면 함부로 합치지 않는다.

## COUNT의 세밀한 구분

COUNT(*)는 조건을 만족한 행 수를 센다. COUNT(열)은 그 열이 NULL이 아닌 행만 센다. COUNT(DISTINCT 열)은 NULL을 제외하고 서로 다른 값의 수를 센다. 다음 자료를 보자.

| 행 | 부서코드 | 상여금 |
|---|---|---:|
| 1 | D10 | 100 |
| 2 | D10 | NULL |
| 3 | D20 | 100 |
| 4 | D20 | 200 |

전체에 대해 COUNT(*)는 4, COUNT(상여금)는 3, COUNT(DISTINCT 상여금)는 2다. COUNT(1) 같은 상수 표현식도 상수가 NULL이 아니므로 행 수를 세는 결과가 될 수 있지만, 의도 표현에는 COUNT(*)가 더 분명하다. 성능이 언제나 어느 쪽이 우월하다고 단정할 수는 없으며 최적화기가 처리한다.

여러 열 조합의 고유 개수를 구하는 문법은 제품마다 차이가 있다. 단일 열 DISTINCT 집계와 동일한 방식이 모든 DBMS에서 통한다고 가정하지 말고, 필요하면 고유 조합을 먼저 만든 뒤 행 수를 세는 논리를 생각한다.

## GROUP BY의 동작

GROUP BY는 같은 그룹 기준값을 가진 행들을 묶는다.

    SELECT 부서코드,
           COUNT(*) AS 인원수,
           SUM(급여) AS 급여합계,
           AVG(급여) AS 평균급여
      FROM 사원
     WHERE 재직여부 = 'Y'
     GROUP BY 부서코드;

논리적으로 재직 행을 먼저 고른 뒤 부서코드별 그룹을 만들고 각 그룹에서 인원수와 집계를 계산한다. 결과는 부서마다 한 행이다. GROUP BY에 참여하지 않은 일반 열을 SELECT 목록에 그대로 쓰면 한 그룹 안의 어느 행 값을 표시해야 할지 결정할 수 없다. 따라서 일반적으로 SELECT 목록의 비집계 표현식은 그룹 기준과 일치해야 한다.

여러 열을 그룹 기준으로 쓰면 열별 독립 그룹이 아니라 열 값의 조합별 그룹이 된다. GROUP BY 부서코드, 직급은 부서와 직급의 각 조합마다 한 행을 만든다. D10 부서의 과장 그룹과 D20 부서의 과장 그룹은 서로 다르다.

NULL 그룹 기준은 일반적으로 집계 결과에서 같은 NULL 그룹으로 모인다. 이것은 NULL끼리 일반 비교했을 때 참이라는 뜻과 다르다. 그룹화 규칙이 NULL들을 하나의 그룹으로 다루는 것이다.

## WHERE와 HAVING

WHERE는 그룹을 만들기 전 개별 행을 거르고, HAVING은 그룹화와 집계 후 그룹을 거른다.

    SELECT 부서코드, SUM(매출액) AS 합계
      FROM 영업실적
     WHERE 매출일 >= :시작일
       AND 매출일 < :종료일
     GROUP BY 부서코드
    HAVING SUM(매출액) >= 1000000;

날짜 조건은 개별 영업 행에 적용되므로 WHERE에 둔다. “합계가 백만 이상인 부서”는 집계 결과에 대한 조건이므로 HAVING에 둔다. 집계와 무관한 행 조건을 HAVING에 두면 같은 결과가 나오는 경우도 있지만 불필요한 행을 일찍 제거하지 못하고 의도를 흐릴 수 있다.

WHERE에서는 아직 그룹 함수 결과가 만들어지지 않았으므로 보통 SUM(매출액) 같은 집계 조건을 바로 사용할 수 없다. 반대로 HAVING은 그룹 조건을 표현한다. SQL의 논리 단계와 실제 최적화기의 물리 실행을 구분한다. 최적화기가 조건을 이동해도 사용자가 작성한 의미는 유지되어야 한다.

## ROLLUP, CUBE, GROUPING SETS

일반 GROUP BY가 지정한 조합 하나만 계산한다면 확장 그룹화는 상세, 소계, 총계를 한 결과에서 만들 수 있다.

- ROLLUP(A, B)는 계층적 집계를 만든다. 일반적으로 (A, B) 상세, (A) 소계, 전체 총계의 순서로 이해한다.
- CUBE(A, B)는 가능한 조합을 폭넓게 만든다. (A, B), (A), (B), 전체 집계를 포함한다.
- GROUPING SETS는 필요한 그룹 조합을 명시적으로 선택한다. 예를 들어 ((A, B), (A), ())처럼 요구되는 수준만 계산한다.

ROLLUP의 열 순서는 중요하다. ROLLUP(연도, 분기)은 연도별 분기 상세, 연도 소계, 전체 총계라는 계층에 맞지만, 열 순서를 바꾸면 다른 소계가 나온다. CUBE는 차원이 늘 때 조합 수가 빠르게 증가하므로 필요한 결과인지 판단한다.

소계 행에서는 집계에서 빠진 그룹 열이 NULL처럼 표시될 수 있다. 실제 데이터의 NULL과 소계를 나타내는 NULL을 구별하려면 GROUPING 또는 그에 준하는 판별 기능을 사용한다. 단순히 NULL이면 “전체”라고 치환하면 원래 부서코드가 NULL인 상세 그룹까지 총계로 오인할 수 있다.

## 그룹 함수와 윈도우 함수 비교

그룹 함수는 GROUP BY와 함께 사용하면 그룹당 한 행을 만든다. 같은 SUM을 OVER와 함께 윈도우 방식으로 사용하면 원래 각 행을 유지하면서 그룹 합계를 붙일 수 있다.

| 요구사항 | 적합한 방식 |
|---|---|
| 부서별 합계만 한 줄씩 출력 | GROUP BY 부서코드 |
| 각 사원 행 옆에 소속 부서 합계 표시 | SUM(급여) OVER (PARTITION BY 부서코드) |
| 부서별 합계가 기준 이상인 부서 선택 | GROUP BY와 HAVING |
| 시간순 누계 표시 | ORDER BY와 프레임을 가진 윈도우 집계 |

시험에서는 OVER의 유무와 결과 행 수를 먼저 확인하면 혼동을 줄일 수 있다. 이 레슨의 중심은 그룹당 결과를 만드는 그룹 함수이며, 순위와 프레임 계산의 상세는 앞 레슨 범위다.

## 오류 처리의 목적

**오류 처리**는 실패를 숨기는 기술이 아니라 데이터의 일관성을 지키고 호출자에게 의미 있는 실패 정보를 전달하는 절차다. 오류는 문법 검사 단계, 객체 이름·권한 확인 단계, 실행 중 자료 처리, 제약조건 검사, 자원 부족이나 동시성 문제 등 여러 시점에 발생할 수 있다.

오류를 다음처럼 나누어 생각하면 대응이 쉬워진다.

- 입력·업무 규칙 오류: 필수값 누락, 허용 범위 위반, 존재하지 않는 업무 코드
- 데이터 오류: 유일성·참조·검사 제약 위반, 한 행 예상 질의의 다중 행 반환
- 계산 오류: 0으로 나누기, 숫자·날짜 변환 실패, 범위 초과
- 권한·객체 오류: 권한 부족, 객체 부재, 잘못된 열 이름
- 동시성·시스템 오류: 교착상태, 잠금 대기 제한, 저장 공간이나 연결 문제

사용자가 고칠 수 있는 입력 오류와 운영자가 조사해야 할 시스템 오류를 같은 메시지로 처리하면 안 된다. 재시도 가능한 일시적 오류인지, 즉시 중단해야 할 영구 오류인지도 구분한다.

## 예방, 탐지, 복구, 전달

안전한 오류 처리는 네 단계로 정리할 수 있다.

1. 예방: 자료형, 범위, 필수값, 참조 대상 존재 여부 등 명백한 입력을 검증한다.
2. 탐지: 실행 중 발생한 예외나 반환 상태를 포착한다.
3. 복구 또는 정리: 작업 전체나 저장점 이후를 되돌리고 열린 자원을 정리한다.
4. 전달: 호출자가 판단할 수 있는 오류 코드·상태·메시지를 제공하거나 예외를 다시 발생시킨다.

모든 제약을 응용 프로그램에서 미리 검사하는 것만으로는 충분하지 않다. 검사 직후 다른 트랜잭션이 데이터를 바꿀 수 있고, 동시에 같은 키를 삽입할 수도 있다. 데이터베이스 제약조건을 최종 방어선으로 두고 그 위반을 올바르게 처리한다.

오류 처리기 안에서 또 오류가 발생할 수 있다. 예를 들어 기록 테이블에 로그를 쓰려다가 같은 트랜잭션이 롤백되거나 로그 저장 자체가 실패할 수 있다. 핵심 데이터 일관성과 진단 정보 기록의 우선순위를 정하고, 민감한 SQL 원문이나 개인정보를 메시지에 그대로 남기지 않는다.

## 예외 처리 구조

절차형 SQL의 제품 중립적 흐름은 다음과 같이 표현할 수 있다.

    BEGIN
        입력을 검증한다;
        필요한 SQL 작업을 수행한다;
        결과를 반환한다;
    EXCEPTION
        WHEN 알려진_업무오류 THEN
            필요한 범위를 되돌린다;
            업무용 오류를 전달한다;
        WHEN OTHERS THEN
            필요한 범위를 되돌린다;
            진단 정보를 안전하게 기록한다;
            오류를 다시 전달한다;
    END;

특정 예외를 먼저 처리하고 포괄 예외는 마지막에 둔다. 포괄 처리기가 앞에 있으면 뒤의 구체 처리기가 도달하지 못하거나 의미가 사라진다. 예외를 잡은 뒤 아무 조치 없이 계속 진행하면 앞 단계 일부만 반영된 채 성공으로 오인될 수 있다.

일부 DBMS는 예외 이름 대신 SQLSTATE 계열 상태값, 숫자 오류 코드, 진단 영역 등을 제공한다. 특정 코드 자체를 외우기보다는 성공·경고·오류 범주, 표준 상태와 제품 고유 정보의 차이, 원래 오류를 보존할 필요를 이해한다.

## 트랜잭션과 오류의 경계

주문 등록이 주문 헤더 추가, 주문 항목 추가, 재고 차감의 세 단계라고 하자. 항목 추가 후 재고 차감이 실패했는데 앞의 변경만 확정되면 불완전 주문이 된다. 업무적으로 세 단계가 하나의 단위라면 모두 성공할 때 확정하고 하나라도 실패하면 전체를 되돌려야 한다.

저장점은 큰 트랜잭션 중 일부만 복귀할 필요가 있을 때 활용할 수 있다. 하지만 저장점 이후만 되돌렸다고 해서 오류 원인이 해결되는 것은 아니다. 계속 진행해도 일관성이 유지되는지 업무 규칙을 확인해야 한다.

교착상태처럼 한 트랜잭션이 희생되어 종료되는 오류는 제한된 횟수의 재시도를 고려할 수 있다. 반면 잘못된 외래키나 권한 부족은 같은 요청을 그대로 반복해도 성공하지 않는다. 재시도에는 횟수 제한과 지연을 두고 중복 실행에 안전한지도 살핀다.

## 적용 예시: 부서별 통계 등록

재직 사원의 부서별 급여 통계를 요약 테이블에 반영한다고 하자. 먼저 원천 조회로 부서코드, COUNT(*), COUNT(급여), SUM(급여), AVG(급여)를 확인한다. COUNT(*)와 COUNT(급여)가 다르면 급여 NULL 행이 존재한다는 뜻이다. 업무 규칙에 따라 그 행을 제외할지 오류로 볼지 정한다.

그다음 GROUP BY 부서코드로 통계를 만들고 HAVING으로 최소 인원 조건을 적용한다. 결과 반영 중 유일성 위반이 발생한다면 같은 기준일 통계가 이미 있는지 확인한다. 단순히 오류를 무시하면 이전 값이 남아 최신 통계라고 오인될 수 있다. 갱신 정책, 재실행 정책, 전체 롤백 범위를 명시해야 한다.

통계 결과에 전체 총계를 함께 표시한다면 ROLLUP을 사용할 수 있다. 소계 표시 열은 GROUPING 판별값으로 구분해 실제 NULL 부서와 총계를 혼동하지 않는다. 통계 생성과 저장이 하나의 업무 단위라면 오류 시 그 단위 전체의 일관성을 보장한다.

## 시험 함정

- COUNT(*)는 행을 세고 COUNT(열)는 NULL이 아닌 열 값을 센다.
- AVG가 NULL을 0으로 바꾸어 분모에 포함한다고 생각하면 안 된다.
- WHERE는 개별 행, HAVING은 그룹 결과를 거른다.
- GROUP BY 열이 둘이면 각 열의 별도 집계가 아니라 값 조합별 그룹이다.
- SELECT 목록의 비집계 열은 일반적으로 그룹 기준에 포함되어야 한다.
- ROLLUP과 CUBE는 같다? 아니다. ROLLUP은 계층 소계 중심이고 CUBE는 가능한 조합을 더 폭넓게 만든다.
- 소계 행의 NULL과 원천 데이터의 NULL을 단순 표시값만으로 구별하면 안 된다.
- 오류를 포착했다는 사실만으로 데이터가 복구되는 것은 아니다. 롤백·정리·전달이 필요하다.
- 모든 오류를 한 종류로 바꾸면 재시도 가능성, 사용자 조치, 운영 진단 정보를 잃는다.
- 사전 중복 조회만으로 동시 삽입을 완전히 방지할 수 없다. 제약조건과 오류 처리가 함께 필요하다.
- 예외를 무시하고 성공을 반환하면 부분 반영을 정상 처리로 오인할 수 있다.

## 확인 문제

1. 값이 100, NULL, 200인 열에 COUNT(*), COUNT(열), SUM(열), AVG(열)을 적용한 결과를 설명하라.
2. WHERE와 HAVING의 적용 대상을 비교하라.
3. GROUP BY A, B가 만드는 그룹의 기준은 무엇인가?
4. ROLLUP(A, B)와 CUBE(A, B)의 일반적인 집계 수준 차이를 쓰라.
5. 소계 행의 NULL과 실제 데이터 NULL을 구별해야 하는 이유와 방법을 설명하라.
6. 안전한 오류 처리의 예방–탐지–복구–전달 단계를 설명하라.
7. 사전 입력 검증만으로 유일성 위반을 완전히 막을 수 없는 이유는 무엇인가?
8. 모든 예외를 잡아 무시하는 방식이 위험한 이유를 두 가지 쓰라.

## 정답과 해설

1. 전체가 세 행이므로 COUNT(*)는 3, NULL 아닌 값은 두 개이므로 COUNT(열)는 2, SUM은 300, AVG는 300을 두 값으로 나눈 150이다. NULL을 0으로 바꾸라는 규칙은 없다.
2. WHERE는 그룹화 전 개별 입력 행을 제거하고, HAVING은 집계 후 만들어진 그룹을 제거한다. 집계 결과 조건은 HAVING에 둔다.
3. A 값과 B 값의 조합이다. 같은 A라도 B가 다르면 별도 그룹이며 반대도 같다.
4. ROLLUP은 (A, B), (A), 전체처럼 열 순서에 따른 계층 소계를 만들고, CUBE는 여기에 (B) 집계까지 포함한 가능한 조합을 만든다.
5. 실제 NULL 그룹을 총계라고 잘못 표시할 수 있기 때문이다. GROUPING과 같은 집계 수준 판별 기능을 사용한다.
6. 잘못된 입력을 미리 막고, 실행 실패를 포착하고, 변경을 되돌리거나 자원을 정리한 뒤, 호출자가 조치할 수 있는 상태와 메시지를 전달한다.
7. 검사와 삽입 사이에 다른 트랜잭션이 같은 키를 추가할 수 있기 때문이다. 최종적으로 데이터베이스의 유일성 제약 위반을 처리해야 한다.
8. 부분 변경이 남아도 성공처럼 보일 수 있고, 원인·재시도 여부·운영 진단 정보가 사라진다. 정상 기본값과 오류 대체값도 구분하기 어렵다.

## 최종 요약

- **그룹 함수**는 여러 행을 그룹별 한 값으로 요약하며 COUNT, SUM, AVG, MAX, MIN이 대표적이다.
- 대부분의 표현식 집계는 NULL을 제외하며, COUNT(*)와 COUNT(열), NULL과 0을 정확히 구분해야 한다.
- GROUP BY는 값 조합으로 그룹을 만들고 WHERE는 행, HAVING은 집계된 그룹을 필터링한다.
- ROLLUP은 계층 소계, CUBE는 다양한 조합, GROUPING SETS는 필요한 조합을 명시하는 데 적합하다.
- **오류 처리**는 예방, 탐지, 롤백·정리, 의미 있는 전달의 전체 과정이다.
- 예외를 숨기지 말고 업무 오류와 시스템 오류, 재시도 가능 오류를 구분하며 데이터베이스 제약을 최종 방어선으로 활용한다.
