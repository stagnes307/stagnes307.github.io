# 3-2-2-2. 조인 · 서브쿼리

## 학습 목표와 범위

이 레슨은 둘 이상의 행 원천을 관련 조건으로 결합하는 **조인**과, 다른 SQL 문장 안에 포함되어 중간 결과나 조건을 제공하는 **서브쿼리**를 다룬다. 학습 후에는 내부·외부·교차·자기 조인의 결과 행을 예측하고, 조인 조건 누락과 외부 조인 필터 위치의 영향을 설명하며, 단일행·다중행·상관 서브쿼리에 맞는 연산자를 선택할 수 있어야 한다. 또한 IN·EXISTS·ANY·ALL과 NULL의 관계를 이해하고 같은 요구사항을 조인 또는 서브쿼리로 표현할 때 정확성과 중복 가능성을 판단해야 한다.

앞 레슨의 뷰·인덱스·집합 연산자와는 필요한 비교만 한다. 구체적인 실행 계획과 힌트, 제품별 외부 조인 약식 표기는 범위 밖이며 표준적인 명시형 JOIN 표현을 중심으로 설명한다.

## 조인의 기본 원리

조인(Join)은 두 입력 행 집합에서 조건을 만족하는 행 쌍을 만들어 열 방향으로 결합하는 연산이다. 집합 연산자가 대응하는 열 구조를 맞춰 행을 위아래로 붙이는 것과 방향이 다르다.

고객과 주문을 고객번호로 연결하면 다음과 같다.

    SELECT 고객.고객번호, 고객.고객명, 주문.주문번호, 주문.주문일
      FROM 고객
      JOIN 주문
        ON 주문.고객번호 = 고객.고객번호;

논리적으로 고객 행과 주문 행의 가능한 쌍에서 ON 조건이 참인 것만 남긴다. 고객 한 명에게 주문이 세 건이면 그 고객 열이 주문마다 반복되어 결과도 세 행이다. 조인은 “테이블 두 개이므로 행 수가 항상 둘 중 큰 테이블과 같다”는 연산이 아니다. 키 관계와 일치 건수에 따라 0, 1, 여러 행이 만들어진다.

열 이름이 양쪽에 모두 있으면 테이블명이나 별칭으로 어느 열인지 한정한다. 짧은 별칭은 읽기 좋지만 의미를 알아볼 수 있어야 한다. SELECT *는 같은 이름 열과 불필요한 데이터가 섞이고 구조 변경의 영향을 크게 받으므로 필요한 열을 명시하는 편이 안전하다.

## 내부 조인

내부 조인(INNER JOIN)은 조인 조건을 만족하는 행 쌍만 반환한다. INNER 키워드는 생략할 수 있는 문법이 많다.

| 고객번호 | 고객명 |
|---|---|
| C1 | 가람 |
| C2 | 나래 |
| C3 | 다온 |

| 주문번호 | 고객번호 |
|---|---|
| O1 | C1 |
| O2 | C1 |
| O3 | C3 |

고객과 주문을 내부 조인하면 C1–O1, C1–O2, C3–O3 세 행이 나온다. 주문이 없는 C2는 조건을 만족하는 주문 쌍이 없어 결과에 나오지 않는다.

동등 조인은 등호 조건으로 관련 키를 연결한다. 비동등 조인은 범위나 대소 비교로 연결한다. 점수와 등급 기준 테이블을 “점수 >= 최저점수 AND 점수 < 상한점수”로 결합하는 것이 예다. 등급 범위가 겹치면 한 점수가 여러 행과 일치하고, 범위 사이가 비면 어느 등급과도 일치하지 않는다. 조인 문법보다 기준 데이터의 비중첩·완전성이 중요하다.

## 외부 조인

외부 조인은 일치하지 않는 행도 한쪽 또는 양쪽에서 보존하고, 대응 상대의 열을 NULL로 채운다.

- LEFT OUTER JOIN: 왼쪽 입력의 모든 행을 보존한다.
- RIGHT OUTER JOIN: 오른쪽 입력의 모든 행을 보존한다.
- FULL OUTER JOIN: 양쪽의 일치하지 않는 행까지 모두 보존한다.

앞의 고객을 왼쪽, 주문을 오른쪽으로 LEFT JOIN하면 내부 조인의 세 행에 C2 고객 한 행이 추가되고 주문번호는 NULL이다. “주문 없는 고객”은 LEFT JOIN 후 주문 쪽의 NOT NULL 키가 NULL인 행을 찾는 방식으로 구할 수 있다.

    SELECT c.고객번호, c.고객명
      FROM 고객 AS c
      LEFT JOIN 주문 AS o
        ON o.고객번호 = c.고객번호
     WHERE o.주문번호 IS NULL;

NULL일 수 있는 일반 열을 검사하면 실제 주문은 있지만 그 열만 NULL인 행을 주문 없음으로 오인할 수 있다. 주문의 기본키처럼 일치한 행에서 반드시 값이 있는 열을 검사한다.

## ON과 WHERE의 위치

외부 조인에서는 오른쪽 조건을 ON에 두는지 WHERE에 두는지가 결과를 바꿀 수 있다.

    FROM 고객 c
    LEFT JOIN 주문 o
      ON o.고객번호 = c.고객번호
     AND o.주문일 >= :기준일

이 형태는 기준일 이후 주문을 연결하되 그런 주문이 없는 고객도 보존한다.

    FROM 고객 c
    LEFT JOIN 주문 o
      ON o.고객번호 = c.고객번호
    WHERE o.주문일 >= :기준일

두 번째 형태에서 주문 없는 고객의 o.주문일은 NULL이고 WHERE 비교가 참이 아니므로 제거된다. 결과가 내부 조인처럼 좁아질 수 있다. 보존 여부를 결정하는 결합 조건은 ON에, 결합 결과 전체를 최종 필터링하는 조건은 WHERE에 둔다는 의미로 읽는다.

왼쪽 테이블 자체의 조건은 WHERE와 ON에서 의미가 달라질 수 있다. 암기식 위치 변경보다 “어느 행을 보존해야 하는가”를 작은 예시 데이터로 추적한다.

## 교차 조인과 조인 조건 누락

CROSS JOIN은 첫 입력의 각 행을 둘째 입력의 모든 행과 조합하는 카티션 곱이다. A가 m행, B가 n행이면 조건 없는 결과는 m×n행이다. 색상 3개와 크기 4개로 가능한 12개 조합을 만드는 것처럼 의도적으로 사용할 수 있다.

반면 관련 테이블 조인에서 조건을 누락하면 의도치 않은 카티션 곱이 생겨 행 수가 폭증한다. 여러 테이블을 조인할 때는 각 테이블이 연결 그래프에서 어떤 조건으로 이어지는지 확인한다. 질의는 실행되지만 결과가 중복처럼 보이는 대표 원인이다.

조인 결과가 예상보다 많다고 DISTINCT부터 붙이면 안 된다. 일대다 관계로 인한 정상 반복인지, 조건 누락인지, 중복된 원천 데이터인지 원인을 찾아야 한다. DISTINCT는 증상을 감출 뿐 잘못 연결된 금액 합계를 복구하지 못할 수 있다.

## 자기 조인

자기 조인(Self Join)은 같은 테이블을 서로 다른 역할의 별칭으로 두 번 이상 참조한다. 사원 테이블의 관리자번호가 같은 테이블의 사원번호를 참조한다면 사원과 관리자를 연결할 수 있다.

    SELECT e.사원명 AS 사원,
           m.사원명 AS 관리자
      FROM 사원 AS e
      LEFT JOIN 사원 AS m
        ON m.사원번호 = e.관리자번호;

최상위 관리자는 관리자번호가 NULL일 수 있으므로 LEFT JOIN을 사용하면 그 사원도 보존된다. 같은 기본 테이블이라고 열의 역할이 같지 않으므로 별칭 e와 m을 명확히 구분한다.

계층의 임의 깊이를 고정 횟수 자기 조인으로 처리하면 단계가 늘 때 질의를 바꿔야 한다. 재귀 질의 기능을 제공하는 DBMS도 있지만 상세 문법은 이 레슨 범위가 아니다.

## 자연 조인과 USING 주의점

NATURAL JOIN은 같은 이름 열을 자동 조건으로 쓰므로 우연히 같은 이름 열이 추가되면 결과가 바뀔 수 있다. USING은 사용할 같은 이름 열을 명시한다. 이름이 같다고 의미도 같다는 보장은 없으므로 ON으로 관계를 명확히 쓰는 편이 안전하다.

## 서브쿼리의 개념과 위치

서브쿼리(Subquery)는 SELECT, INSERT, UPDATE, DELETE 등 다른 문장 안에 포함된 질의다. 바깥 질의를 주 질의라고 한다. 서브쿼리는 괄호로 범위를 분명히 하며 사용 위치와 반환 모양에 맞아야 한다.

- 스칼라 위치: 한 행 한 열 값이 필요한 SELECT 표현식이나 비교식
- WHERE·HAVING 조건: 값 목록, 존재 여부, 비교 기준 제공
- FROM 위치: 행과 열을 가진 파생 테이블로 사용
- DML 원천 또는 대상 조건: 삽입할 결과나 변경·삭제 대상을 결정

서브쿼리 결과는 한 값, 한 열의 여러 행, 여러 열의 행 집합일 수 있다. 바깥 연산자가 기대하는 모양과 다르면 오류 또는 잘못된 판단이 생긴다.

## 단일행과 다중행 서브쿼리

단일행 서브쿼리는 결과가 한 행이어야 하며 =, <, > 같은 단일값 비교 연산자와 함께 사용할 수 있다.

    SELECT 사원명, 급여
      FROM 사원
     WHERE 급여 > (
           SELECT AVG(급여)
             FROM 사원
     );

AVG 집계는 조건 결과에 대해 한 값을 만들므로 단일값 비교에 맞다. 급여가 NULL인 행은 비교 결과가 참이 아니어서 선택되지 않는다.

서브쿼리가 여러 행을 돌려줄 수 있는데 등호 하나를 쓰면 오류가 될 수 있다. 여러 값을 다룰 때는 요구사항에 따라 IN, ANY 또는 SOME, ALL, EXISTS를 선택한다.

- IN: 반환된 값 집합 중 하나와 일치
- 비교연산자 ANY: 반환 값 중 하나 이상과 비교가 참
- 비교연산자 ALL: 반환 값 모두와 비교가 참
- EXISTS: 서브쿼리 결과 행이 하나라도 존재

예를 들어 x > ALL(10, 20, 30)은 x가 모든 값보다 커야 하므로 30보다 큰 효과다. x > ANY(10, 20, 30)은 하나보다만 커도 되므로 10보다 크면 참이 될 수 있다. 빈 집합과 NULL이 포함된 집합에서는 논리 결과를 세심히 본다.

## 상관 서브쿼리

상관 서브쿼리는 내부 질의가 바깥 질의의 현재 행 열을 참조한다.

    SELECT e.사원번호, e.사원명, e.급여
      FROM 사원 AS e
     WHERE e.급여 > (
           SELECT AVG(x.급여)
             FROM 사원 AS x
            WHERE x.부서코드 = e.부서코드
     );

각 사원 e에 대해 같은 부서의 평균을 구해 비교한다는 논리다. 비상관 서브쿼리는 독립적으로 이해할 수 있지만 상관 서브쿼리는 바깥 행의 값을 매개로 한다. 최적화기가 실제로 매 행마다 그대로 실행하지 않고 동등한 방식으로 변환할 수도 있으므로 문법 모양만으로 성능을 단정하지 않는다.

별칭 범위를 잘못 이해하면 내부의 같은 이름 열을 엉뚱한 테이블로 해석할 수 있다. 상관 조건의 양쪽 별칭을 명시해 “내부 부서코드 = 외부 부서코드”를 분명히 한다.

## EXISTS와 NOT EXISTS

EXISTS는 내부 결과의 값 자체가 아니라 행 존재 여부를 본다. SELECT 목록에 상수를 쓰든 특정 열을 쓰든 존재 판단의 핵심은 조건을 만족하는 행이 있는지다.

    SELECT c.고객번호, c.고객명
      FROM 고객 AS c
     WHERE EXISTS (
           SELECT 1
             FROM 주문 AS o
            WHERE o.고객번호 = c.고객번호
     );

고객별 주문이 하나 이상 있으면 고객 행을 한 번 선택한다. 주문이 여러 건이어도 바깥 고객 행이 자동으로 여러 번 복제되지는 않는다. 조인으로 같은 요구를 작성하면 고객이 주문 수만큼 반복될 수 있어 고유 고객을 얻으려면 별도 처리가 필요하다.

NOT EXISTS는 관련 행이 전혀 없는 대상을 찾는다. 주문 없는 고객, 필수 과목을 하나도 빠뜨리지 않은 학생 같은 부정·전체 조건 표현에 유용하다. 특히 NULL을 포함할 수 있는 NOT IN과 비교할 때 NOT EXISTS가 의도를 더 안정적으로 표현하는 경우가 많다.

## NOT IN과 NULL 함정

    WHERE 고객번호 NOT IN (
        SELECT 고객번호 FROM 차단고객
    )

서브쿼리 결과에 NULL이 하나라도 있으면 어떤 고객번호가 NULL과 다른지 일반 비교로 확정할 수 없어 전체 조건이 미정이 될 수 있다. 기대와 달리 아무 행도 나오지 않는 대표 함정이다. 서브쿼리에서 NULL을 제외한다는 보장이 있거나 명시적으로 제거해야 하며, 관계 부재를 표현할 때는 상관 NOT EXISTS를 고려한다.

NOT EXISTS에서는 외부 고객과 같은 차단 고객 행의 존재만 검사하므로 차단 테이블의 다른 NULL 행이 그 고객의 결과를 오염시키지 않는다. 다만 상관 조건 자체와 NULL 업무 의미를 정확히 설계해야 한다.

## 조인과 서브쿼리 선택

같은 요구를 여러 형태로 표현할 수 있다.

| 요구 | 자연스러운 표현 |
|---|---|
| 고객과 각 주문의 열을 함께 표시 | JOIN |
| 주문이 하나라도 있는 고객만 표시 | EXISTS |
| 전체 평균보다 급여가 높은 사원 | 단일값 집계 서브쿼리 |
| 주문 없는 고객 | LEFT JOIN 후 일치 키 NULL 또는 NOT EXISTS |
| 중간 집계 결과를 다시 조인 | FROM의 파생 테이블 또는 공통 테이블 표현식 |

정답은 항상 하나가 아니다. 결과 행 수, 중복, NULL, 가독성, 최적화 가능성을 기준으로 고른다. 현대 최적화기는 IN, EXISTS, 조인을 서로 동등한 실행 형태로 바꾸기도 하므로 “서브쿼리는 언제나 느리다”거나 “조인은 언제나 빠르다”는 단정은 틀리다. 실제 데이터 분포와 실행 계획을 측정한다.

## 통합 예시: 평균 이상 구매 고객

“각 고객의 총 주문금액이 전체 고객별 주문합계 평균 이상인 고객”을 구한다고 하자. 먼저 주문을 고객별로 그룹화한 결과가 필요하다. 그 결과를 파생 테이블로 만들고 전체 평균과 비교할 수 있다. 중요한 것은 평균 대상이 개별 주문금액인지 고객별 합계인지 단계가 다르다는 점이다.

1. 주문에서 고객별 SUM(주문금액)을 만든다.
2. 고객별 합계들의 AVG를 계산한다.
3. 각 고객 합계와 평균을 비교한다.
4. 고객명을 표시하려면 고객 테이블을 키로 조인한다.

집계 수준을 잘못 잡아 모든 개별 주문의 평균과 고객 합계를 비교하면 요구와 다른 결과다. 조인 키가 유일한지도 확인한다. 단계별 예상 행 수를 적으면 오류를 줄일 수 있다.

## 시험 함정

- 내부 조인은 일치 행만, 외부 조인은 지정된 쪽의 불일치 행도 보존한다.
- 일대다 조인은 한쪽 행을 여러 번 만들 수 있으며 이것이 반드시 잘못된 중복은 아니다.
- 외부 조인의 오른쪽 조건을 WHERE에 두면 NULL 보존 행이 제거되어 내부 조인처럼 될 수 있다.
- 조인 조건 누락은 카티션 곱을 만들어 행 수를 폭증시킨다.
- 결과가 많다고 원인 확인 없이 DISTINCT를 붙이지 않는다.
- 자기 조인은 테이블을 복사하는 것이 아니라 같은 테이블을 서로 다른 역할의 별칭으로 참조한다.
- NATURAL JOIN은 같은 이름 열을 자동 사용하므로 구조 변경에 취약할 수 있다.
- 여러 행 서브쿼리에 단일값 등호를 쓰면 안 된다.
- > ANY와 > ALL의 조건 강도가 반대처럼 느껴질 수 있으므로 구체 값으로 확인한다.
- EXISTS는 반환 열 값보다 행 존재 여부를 판단한다.
- NOT IN의 후보 집합에 NULL이 있으면 예상과 달리 결과가 사라질 수 있다.
- 상관 서브쿼리가 문법상 외부 행을 참조해도 실제 물리 실행이 반드시 행별 반복이라고 단정하지 않는다.

## 확인 문제

1. 고객 C1에 주문 두 건, C2에 주문이 없을 때 고객과 주문의 내부 조인 및 고객 LEFT JOIN의 결과 행 수를 설명하라.
2. LEFT JOIN의 오른쪽 테이블 조건을 ON과 WHERE에 둘 때 보존 행이 어떻게 달라질 수 있는가?
3. 카티션 곱의 행 수를 설명하고 의도치 않게 발생하는 원인을 쓰라.
4. 자기 조인에서 별칭이 필요한 이유는 무엇인가?
5. 단일행 서브쿼리와 다중행 서브쿼리에 적합한 연산자를 예로 들어라.
6. x > ANY(10, 20, 30)과 x > ALL(10, 20, 30)의 차이를 설명하라.
7. EXISTS로 주문 고객을 찾을 때 주문이 여러 건이어도 고객 행이 자동 복제되지 않는 이유는 무엇인가?
8. NOT IN 후보에 NULL이 있을 때 생기는 문제와 대안을 설명하라.

## 정답과 해설

1. 내부 조인은 C1의 두 주문과 일치해 두 행이고 C2는 제외된다. 고객 LEFT JOIN은 그 두 행에 주문 열이 NULL인 C2 보존 행 하나를 더해 세 행이다.
2. ON에 둔 오른쪽 조건은 그 조건을 만족하는 상대만 연결하면서 왼쪽 행을 보존한다. WHERE에 두면 연결되지 않은 행의 오른쪽 값이 NULL이라 조건을 통과하지 못해 제거될 수 있다.
3. 입력이 m행과 n행이면 조건 없는 조합은 m×n행이다. CROSS JOIN을 의도했거나 관련 테이블 사이의 조인 조건을 빠뜨렸을 때 발생한다.
4. 같은 열 이름이 사원 역할과 관리자 역할처럼 서로 다른 의미를 가지므로 각 참조와 조인 방향을 구분해야 하기 때문이다.
5. 한 값이면 =, <, > 등을 쓸 수 있다. 여러 값이면 요구에 따라 IN, ANY, ALL, EXISTS 등을 사용한다.
6. > ANY는 값 중 하나보다만 크면 되므로 이 집합에서는 10보다 크면 참이 될 수 있다. > ALL은 모든 값보다 커야 하므로 30보다 커야 한다. NULL과 빈 집합은 별도 주의한다.
7. EXISTS는 관련 내부 행이 한 건이라도 있는지에 대한 참·거짓만 바깥 고객별로 반환하기 때문이다.
8. NULL과의 비교가 미정이 되어 NOT IN 전체가 참이 되지 않을 수 있다. NULL을 확실히 제외하거나 상관 NOT EXISTS로 관계 부재를 표현한다.

## 최종 요약

- **조인**은 관련 행을 열 방향으로 결합하며 내부·외부·교차·자기 조인의 보존 범위와 결과 행 수가 다르다.
- 외부 조인에서는 ON과 WHERE의 조건 위치, 불일치 행의 NULL 채움, 일대다 반복을 정확히 추적해야 한다.
- **서브쿼리**는 반환 모양과 사용 위치에 따라 단일값, 값 목록, 파생 테이블, 존재 조건을 제공한다.
- 단일행 비교와 IN·ANY·ALL·EXISTS를 요구에 맞게 선택하고 상관 참조의 별칭을 분명히 한다.
- NOT IN과 NULL, 조인 조건 누락, 외부 조인의 사후 필터는 대표적인 시험 함정이다.
- 조인과 서브쿼리의 성능을 문법 모양만으로 단정하지 말고 결과 의미·중복·NULL과 실제 실행 계획을 함께 본다.
