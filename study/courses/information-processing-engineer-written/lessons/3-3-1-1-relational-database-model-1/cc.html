01

학습 목표와 범위

이 레슨은 데이터를 릴레이션과 제약으로 표현하는 관계 데이터 모델, 그리고 그 릴레이션에서 원하는 결과를 형식적으로 표현하는 관계데이터언어(관계대수, 관계해석)를 다룬다. 학습 후에는 릴레이션의 구조와 성질, 키·무결성의 의미를 설명하고, 관계대수의 기본·유도 연산 결과를 계산하며, 관계해석의 선언적 성격과 튜플·도메인 관계해석을 구분할 수 있어야 한다.

앞 레슨은 SQL의 조인·서브쿼리를 구현 관점에서 다뤘다. 이 레슨은 그 바탕이 되는 이론 언어에 집중한다. 다음 레슨의 시스템 카탈로그와 뷰, 이후의 모델링 절차는 범위를 침범하지 않고 필요한 연결만 언급한다.

02

관계 데이터 모델의 구성

관계 데이터 모델은 현실의 개체와 관계를 릴레이션이라는 표 형태의 논리 구조로 표현한다. 구조(Structure), 연산(Operation), 제약조건(Constraint)의 세 요소로 이해할 수 있다.

  • 구조: 릴레이션, 속성, 튜플, 도메인으로 데이터의 모양을 정의한다.
  • 연산: 관계대수나 관계해석으로 릴레이션에서 새 릴레이션을 도출한다.
  • 제약: 키와 무결성 규칙으로 허용되는 데이터베이스 상태를 제한한다.

단순히 데이터를 표로 그렸다는 사실만으로 관계 모델의 장점이 생기지는 않는다. 각 열의 의미와 도메인을 분명히 하고, 행을 식별하며, 참조 관계와 업무 규칙을 선언하고, 집합 연산이 가능한 형태로 값을 구성해야 한다.

03

릴레이션의 구조

릴레이션 스키마는 릴레이션 이름과 속성들의 정의다. 학생(학번, 이름, 학과코드)처럼 표현한다. 릴레이션 인스턴스는 특정 시점에 실제로 들어 있는 튜플들의 집합이다.

  • 속성(Attribute)은 열이며 개체나 관계의 특성을 나타낸다.
  • 튜플(Tuple)은 행이며 한 건의 사실을 나타낸다.
  • 도메인(Domain)은 한 속성이 가질 수 있는 원자값의 집합과 의미 범위다.
  • 차수(Degree)는 속성 수다.
  • 카디널리티(Cardinality)는 특정 시점의 튜플 수다.

학생 릴레이션에 학번, 이름, 학과코드 세 속성과 학생 100명이 있다면 차수는 3, 카디널리티는 100이다. 학생을 추가하면 카디널리티가 바뀌고, 이메일 속성을 추가하면 차수가 바뀐다.

속성은 같은 도메인을 사용할 수 있어도 의미가 다를 수 있다. 출발도시와 도착도시는 모두 도시코드 도메인을 쓰지만 역할이 다르다. 반대로 이름이 같은 열이라도 서로 다른 코드 체계를 쓰면 자동으로 호환된다고 볼 수 없다.

04

릴레이션의 이론적 성질

관계 이론에서 릴레이션은 튜플의 집합이므로 다음 성질로 설명한다.

  • 동일한 튜플이 중복되지 않는다.
  • 튜플의 순서는 의미가 없다.
  • 속성의 논리적 순서도 본질적인 의미가 없다.
  • 각 속성값은 해당 도메인에 속한다.
  • 한 속성의 값은 개념적으로 원자적이다.

실제 SQL 테이블은 키나 DISTINCT가 없으면 중복처럼 보이는 행을 허용할 수 있다. SELECT 결과도 ORDER BY 없이는 표시 순서가 보장되지 않는다. 관계 이론의 집합과 SQL이 사용하는 중복 허용 다중집합 성격을 구분한다.

원자성은 값의 의미와 사용 목적에 상대적인 면이 있다. 주소 전체를 한 값으로 다룰 수도 있지만 시·구별 검색과 검증이 필요하면 구성 요소로 나누는 편이 적절하다. 한 셀에 전화번호 여러 개를 쉼표로 넣는 반복 집합은 관계 연산과 제약을 어렵게 한다.

05

키와 무결성

슈퍼키는 튜플을 유일하게 식별하는 속성 집합이다. 후보키는 슈퍼키 중 최소성을 만족한다. 후보키 하나를 기본키로 선택하고 나머지는 대체키가 된다. 외래키는 다른 릴레이션의 후보키를 참조해 관계를 표현한다.

유일성과 최소성을 구분해야 한다. 학번이 유일하다면 {학번, 이름}도 유일할 가능성이 있지만 이름을 빼도 식별되므로 최소성이 없다. 따라서 슈퍼키일 수는 있어도 후보키가 아니다.

무결성은 다음처럼 정리한다.

키와 무결성 · 학습 표 1
종류핵심 규칙
도메인 무결성속성값은 정의된 자료형·범위·형식을 만족
개체 무결성기본키 값은 유일하고 NULL이 아님
참조 무결성외래키는 존재하는 참조 키 값과 일치하거나 허용된 NULL
사용자 정의 무결성업무에서 정한 추가 규칙을 만족

참조 무결성은 부모 없는 자식 참조를 막는다. 외래키 자체가 자식에서 유일해야 한다는 뜻은 아니다. 여러 학생이 같은 학과코드를 참조할 수 있다.

06

폐쇄성: 연산 결과도 릴레이션

관계 연산은 하나 이상의 릴레이션을 입력으로 받아 릴레이션을 결과로 만든다. 이를 폐쇄성이라고 한다. 결과를 다시 다른 관계 연산의 입력으로 사용할 수 있으므로 복잡한 질의를 작은 연산의 조합으로 표현할 수 있다.

예를 들어 “컴퓨터공학과 학생의 학번”은 학생 릴레이션에서 학과코드가 특정 값인 튜플을 선택한 뒤 학번 속성만 투영하는 두 연산으로 표현한다. 중간 결과 역시 릴레이션이므로 다시 수강 릴레이션과 조인할 수 있다.

관계대수와 관계해석은 표현 방식이 다르지만 안전한 범위에서 관계적으로 완전한 질의 능력을 설명하는 두 축이다. SQL은 이 이론을 기반으로 하되 중복, NULL, 정렬, 집계 등 실용 기능을 확장했다.

07

관계대수의 개념

관계대수(Relational Algebra)는 원하는 결과를 얻기 위해 어떤 연산을 어떤 순서로 적용할지를 나타내는 절차적 언어다. 입력 릴레이션에 연산자를 적용해 새 릴레이션을 만든다.

기본 연산으로 선택, 투영, 합집합, 차집합, 카티션 곱, 이름 변경을 제시하는 구성이 일반적이다. 교집합, 조인, 나눗셈은 기본 연산의 조합으로 유도할 수 있는 연산으로 설명한다.

연산 기호를 외우는 데 그치지 말고 다음 세 질문으로 결과를 판단한다.

  1. 결과에 어떤 속성이 남는가?
  2. 어떤 튜플이 남는가?
  3. 중복과 호환 조건은 어떻게 처리되는가?
08

선택과 투영

선택(Selection)은 조건을 만족하는 튜플, 즉 행을 고른다. 시그마 기호로 나타내며 결과의 속성 구조는 입력과 같다.

σ 학과코드='CS' (학생)

이는 학생 릴레이션에서 학과코드가 CS인 행만 남긴다. SQL의 WHERE와 대응해 이해할 수 있다. 선택 조건은 논리식이며 여러 조건을 AND·OR·NOT으로 결합할 수 있다.

투영(Projection)은 필요한 속성, 즉 열을 고른다. 파이 기호로 나타낸다.

π 학번,이름 (학생)

관계대수는 집합이므로 투영 결과에서 같은 튜플이 생기면 중복을 제거한다. SQL의 단순 SELECT는 중복을 유지할 수 있으므로 이론적 투영과 맞추려면 DISTINCT가 필요할 수 있다.

“CS 학과 학생의 이름”은 먼저 선택하고 이름을 투영할 수 있다.

π 이름 (σ 학과코드='CS' (학생))

선택은 행, 투영은 열이라는 구분이 가장 기본적인 시험 포인트다. 데이터베이스 설계의 “프로젝션”이라는 다른 문맥과 혼동하지 않는다.

09

합집합, 교집합, 차집합

합집합(Union)은 두 릴레이션 중 어느 한쪽에 속한 튜플을 모두 포함하고 중복은 제거한다. 교집합(Intersection)은 양쪽에 공통인 튜플만 포함한다. 차집합(Difference)은 첫 릴레이션에는 있고 둘째에는 없는 튜플을 포함한다.

이 연산에는 합집합 호환성이 필요하다. 두 릴레이션의 차수가 같고 대응 속성의 도메인이 호환되어야 한다. 속성 이름 자체보다 대응 위치와 의미가 맞도록 이름 변경을 사용할 수 있다.

차집합은 교환법칙이 성립하지 않는다. R−S와 S−R은 일반적으로 다르다. 합집합과 교집합은 입력 순서를 바꿔도 같은 집합 결과지만 차집합은 방향을 반드시 확인한다.

교집합은 차집합을 조합해 표현할 수 있다. 예를 들어 R∩S는 R−(R−S)로 도출할 수 있다. 이것이 교집합을 유도 연산으로 분류할 수 있는 이유다.

10

카티션 곱과 이름 변경

카티션 곱(Cartesian Product)은 R의 각 튜플과 S의 각 튜플을 가능한 모든 조합으로 연결한다. R이 m개, S가 n개 튜플이면 결과는 m×n개이며 속성은 양쪽 속성을 합친다.

같은 이름 속성이 양쪽에 있으면 어느 릴레이션의 속성인지 구분해야 한다. 이름 변경(Rename)은 릴레이션이나 속성에 새 이름을 주어 충돌을 피하고 자기 자신과의 연산에서 역할을 나눈다. 로 기호로 표현한다.

카티션 곱 자체는 결과가 매우 클 수 있지만 그 뒤 선택 조건을 적용하면 세타 조인을 구성할 수 있다. 실제 DBMS가 반드시 모든 조합을 물리적으로 만든 뒤 거른다는 뜻은 아니다. 관계대수식은 논리적 의미이며 최적화기는 동등한 더 효율적인 순서를 선택할 수 있다.

11

조인 연산

세타 조인은 카티션 곱 결과에 일반 비교 조건을 적용한 것이다. 동등 조인은 그 조건이 등호인 경우다. 자연 조인은 같은 의미의 공통 속성을 기준으로 동등 결합하고 중복된 조인 속성을 하나로 정리한다.

학생 ⋈ 학생.학과코드=학과.학과코드 학과

결과는 학생 속성과 일치 학과 속성을 함께 가진다. 한 학과에 학생이 여러 명이면 학과 정보가 학생마다 반복된다. 일치하지 않는 튜플은 기본 조인에서는 결과에 포함되지 않는다.

외부 조인은 일치하지 않는 튜플도 보존하도록 확장한 연산이다. 왼쪽, 오른쪽, 완전 외부 조인으로 구분하며 빈 상대 속성을 NULL에 준하는 표시로 채우는 SQL 구현을 떠올릴 수 있다. 고전적인 기본 관계대수는 NULL을 전제로 하지 않으므로 확장 연산과 SQL 의미를 구분한다.

자연 조인은 같은 이름 속성이 같은 의미와 도메인을 가진다는 전제가 필요하다. 우연히 이름만 같은 속성을 자동으로 연결하면 잘못된 결과다. 이론식에서도 필요한 경우 이름 변경 후 의도한 조건을 명시한다.

12

나눗셈 연산

나눗셈(Division)은 “모든” 조건을 표현하는 대표 연산이다. R(X, Y)를 S(Y)로 나눈 결과는 S의 모든 Y 값과 짝을 이루는 X 값들이다.

수강(학생, 과목) 릴레이션을 필수과목(과목) 릴레이션으로 나누면 모든 필수과목을 수강한 학생을 구할 수 있다. 어떤 필수과목 하나를 들은 학생이 아니라 필수과목 집합의 모든 원소와 연결된 학생이다.

작은 예를 보자. 필수과목이 DB와 OS이고, 가람은 DB·OS, 나래는 DB만, 다온은 DB·OS·NW를 수강했다면 나눗셈 결과는 가람과 다온이다. 추가 과목 NW를 들었다는 사실은 모든 필수과목 충족을 방해하지 않는다.

나눗셈은 기본 연산의 조합으로 표현할 수 있어 유도 연산으로 분류된다. 시험에서는 “모든 ~을 만족하는”이라는 문구가 나눗셈의 신호인지 살핀다.

13

관계대수식의 최적화 관점

선택을 원천 가까이 적용하면 중간 튜플 수가, 필요한 속성만 일찍 투영하면 중간 폭이 줄 수 있다. 다만 뒤 조인에 필요한 속성을 제거하면 안 되며 변환 전후 결과가 동등해야 한다. 최적화기는 이런 변환과 통계를 이용하므로 SQL 작성 순서와 물리 실행 순서가 같다고 단정하지 않는다.

14

관계해석의 개념

관계해석(Relational Calculus)은 결과가 만족해야 하는 조건을 논리식으로 기술하는 비절차적·선언적 언어다. “어떻게 연산할 것인가”보다 “어떤 성질을 만족하는 튜플을 원하는가”를 표현한다. 관계대수가 연산 순서를 제시하는 절차적 표현이라는 점과 대비된다.

관계해석은 술어 논리에 기반하며 변수, 원자식, 논리 연결자 AND·OR·NOT, 존재 한정자와 전칭 한정자 등을 사용한다. 존재 한정자는 어떤 값이 하나 이상 존재함을, 전칭 한정자는 대상 범위의 모든 값이 조건을 만족함을 표현한다.

표현력이 크다고 무한한 임의 집합을 결과로 내게 두면 실제 데이터베이스 질의로 계산할 수 없다. 결과가 데이터베이스의 유한한 값 범위에 한정되는 안전한 식, 즉 범위가 제한된 표현을 사용해야 한다. 안전한 관계해석과 관계대수는 기본적인 질의 표현력에서 대응한다고 설명한다.

15

튜플 관계해석과 도메인 관계해석

튜플 관계해석(Tuple Relational Calculus)은 변수가 릴레이션의 튜플을 가리킨다. 개념적으로 다음처럼 읽는다.

{ t | 학생(t) AND t.학과코드 = 'CS' }

“t가 학생 릴레이션의 튜플이고 학과코드가 CS인 모든 t의 집합”이다. 속성은 t.학번처럼 튜플 변수의 구성 요소로 참조한다.

도메인 관계해석(Domain Relational Calculus)은 변수가 개별 속성값을 가리킨다.

{ <학번, 이름> | EXISTS 학과코드 (학생(학번, 이름, 학과코드) AND 학과코드='CS') }

결과에 학번과 이름 값을 내고, 어떤 학과코드 값이 존재해 학생 튜플을 이루며 CS 조건을 만족한다고 표현한다. 튜플 관계해석은 행 단위 변수, 도메인 관계해석은 열 값 단위 변수라는 차이가 핵심이다.

자유 변수는 결과에 나타나는 변수이고, 한정 변수는 존재·전칭 한정자의 범위 안에 묶인 변수다. 논리식의 범위와 괄호를 잘못 두면 조건 의미가 달라진다.

16

SQL 사용자는 선언적으로 원하는 결과를 작성하고 DBMS가 실행 절차를 선택한다는 점에서 관계해석의 관점과 닮았다. 동시에 SELECT의 필터·투영·조인은 관계대수 연산으로 설명할 수 있다. 두 이론은 경쟁 개념이라기보다 관계 질의를 설명하는 서로 다른 관점이다.

17

종합 예시

학생(학번, 이름, 학과코드), 수강(학번, 과목코드), 필수과목(과목코드)이 있다고 하자.

“CS 학과 학생의 학번과 이름”은 학생에서 학과코드='CS'를 선택한 뒤 학번과 이름을 투영한다. “한 과목 이상 수강한 CS 학생”은 선택한 학생과 수강을 학번으로 조인한 뒤 학생 식별 열을 투영한다.

“모든 필수과목을 수강한 학생”은 수강을 필수과목으로 나누는 사고가 적합하다. 관계해석으로는 필수과목인 모든 과목에 대해 그 학생의 수강 튜플이 존재한다는 전칭 조건으로 표현한다. 전칭 조건은 “수강하지 않은 필수과목이 존재하지 않는다”는 이중 부정의 존재 조건으로도 바꿀 수 있다.

결과에 학생 이름을 붙이려면 나눗셈 결과의 학번을 학생 릴레이션과 조인하고 필요한 열을 투영한다. 이처럼 폐쇄성 덕분에 각 단계 결과를 다음 연산에 연결할 수 있다.

18

시험 함정

  • 차수는 속성 수, 카디널리티는 튜플 수다.
  • 관계 이론에서 튜플 순서는 의미가 없고 같은 튜플 중복이 없다.
  • 선택은 행, 투영은 열을 고른다.
  • 관계대수의 투영은 집합 의미상 중복을 제거하지만 SQL의 일반 SELECT는 중복을 유지할 수 있다.
  • 합집합·교집합·차집합에는 대응 속성의 호환성이 필요하다.
  • 차집합은 좌우를 바꾸면 결과가 달라진다.
  • 카티션 곱의 튜플 수는 두 입력 카디널리티의 곱이다.
  • 자연 조인은 이름만 같은 모든 속성을 무조건 안전하게 연결하는 방법이 아니다.
  • 나눗셈은 “일부”가 아니라 “모든 대상과 관련된” X를 구한다.
  • 관계대수는 절차적, 관계해석은 비절차적이라는 구분을 뒤바꾸지 않는다.
  • 튜플 관계해석의 변수는 행, 도메인 관계해석의 변수는 속성값을 나타낸다.
  • 무한한 결과를 허용하는 안전하지 않은 관계해석식은 실제 유한 데이터베이스 질의로 적절하지 않다.

확인 문제

  1. 관계 데이터 모델의 구조·연산·제약 세 요소를 설명하라.
  2. 학생 릴레이션의 속성이 4개이고 튜플이 200개라면 차수와 카디널리티는 각각 얼마인가?
  3. 선택과 투영의 대상 및 결과 구조 차이를 설명하라.
  4. 합집합 호환성의 조건과 차집합의 방향성을 설명하라.
  5. 카디널리티가 각각 5와 7인 두 릴레이션의 카티션 곱은 몇 튜플인가?
  6. 모든 필수과목을 수강한 학생을 구할 때 나눗셈이 적합한 이유는 무엇인가?
  7. 관계대수와 관계해석의 성격 차이를 쓰라.
  8. 튜플 관계해석과 도메인 관계해석의 변수 단위를 비교하라.
20

정답과 해설

  1. 구조는 릴레이션·속성·튜플·도메인으로 데이터 형태를 정의하고, 연산은 릴레이션에서 결과 릴레이션을 도출하며, 제약은 키와 무결성으로 허용 상태를 제한한다.
  2. 속성 수인 차수는 4, 현재 튜플 수인 카디널리티는 200이다.
  3. 선택은 조건에 맞는 행을 골라 속성 구조를 유지하고, 투영은 지정 열을 골라 속성 수를 줄일 수 있다. 관계대수의 투영 결과는 중복 튜플을 제거한다.
  4. 두 입력의 차수가 같고 대응 속성 도메인이 호환되어야 한다. R−S는 R에만 있는 튜플이고 S−R은 S에만 있는 튜플이므로 방향을 바꾸면 일반적으로 결과가 달라진다.
  5. 모든 가능한 쌍이므로 5×7=35튜플이다.
  6. 나눗셈은 S의 모든 값과 관련된 X를 반환한다. 필수과목 집합의 모든 과목과 수강 관계가 있는 학생이라는 요구에 맞는다.
  7. 관계대수는 원하는 결과를 얻는 연산과 순서를 나타내는 절차적 언어이고, 관계해석은 결과가 만족할 논리 조건을 나타내는 비절차적 언어다.
  8. 튜플 관계해석 변수는 릴레이션의 한 튜플 전체를, 도메인 관계해석 변수는 개별 속성값을 가리킨다.
21

최종 요약

  • 관계 데이터 모델은 릴레이션 구조, 관계 연산, 키와 무결성 제약으로 데이터와 허용 상태를 정의한다.
  • 릴레이션은 속성·튜플·도메인으로 구성되며 차수는 열 수, 카디널리티는 행 수다.
  • 관계대수는 선택·투영·합집합·차집합·카티션 곱·이름 변경을 기본으로 하고 조인·교집합·나눗셈 등을 조합한다.
  • 선택은 행, 투영은 열, 나눗셈은 “모든” 조건이라는 판단 기준을 기억한다.
  • 관계해석은 결과 조건을 술어 논리로 표현하는 선언적 언어이며 튜플 변수 방식과 도메인 변수 방식이 있다.
  • 안전한 관계해석과 관계대수는 관계 질의를 설명하는 대응 관점이며 SQL의 이론적 토대가 된다.
