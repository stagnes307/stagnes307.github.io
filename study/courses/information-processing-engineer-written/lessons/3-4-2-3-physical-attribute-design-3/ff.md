# 3-4-2-3. 데이터 지역화(locality)

> **공식 범위**: 데이터베이스구축 > 물리 데이터베이스 설계 > 데이터베이스 물리속성 설계 > `데이터 지역화(locality)`, `데이터베이스 물리속성 설계의 적용 절차와 판단 기준`

## 0. 자주 함께 쓰는 데이터를 가까이

데이터베이스 성능은 필요한 데이터를 찾는 논리적 방법뿐 아니라 실제로 몇 개의 블록·페이지·노드·네트워크 구간을 접근하는지에 영향을 받는다. 함께 쓰이는 데이터가 가까이 배치되고 최근 자주 쓰는 데이터가 빠른 계층에 머물면 불필요한 입출력과 원격 통신을 줄일 수 있다.

이 레슨의 목표는 다음과 같다.

1. `데이터 지역화(locality)`의 공간 지역성과 시간 지역성을 설명한다.
2. 접근 패턴, 조인, 파티션, 저장계층과 분산 배치를 이용해 관련 데이터를 가까이 두는 방법을 비교한다.
3. 지역화가 쓰기 편향, 재배치, 불균형과 가용성·규제에 주는 비용을 판단한다.
4. `데이터베이스 물리속성 설계의 적용 절차와 판단 기준`에 따라 파티셔닝·클러스터링·백업·사이징·지역화를 통합 평가한다.

여기서 locality는 **접근 관점의 물리적·논리적 근접성**이다. 특정 국가·지역에 데이터를 저장해야 하는 데이터 주권 요구와 관련될 수 있지만 두 개념을 동일시하지 않는다.

---

## 1. 데이터 지역화(locality)의 원리

### 1.1 공간 지역성

공간 지역성(spatial locality)은 한 데이터를 접근하면 물리적으로 인접하거나 논리적으로 관련된 데이터도 곧 접근할 가능성이 높다는 성질이다.

예:

- 한 주문과 그 주문의 상세행을 함께 조회
- 같은 고객의 최근 거래 목록을 연속 조회
- 특정 날짜 범위의 로그를 순차 스캔
- 한 인덱스 키 주변의 범위 값을 탐색

관련 행이 같은 또는 가까운 블록에 있으면 한 번의 블록 읽기로 더 많은 필요한 데이터를 얻을 수 있다. 반대로 무작위 위치에 흩어지면 랜덤 I/O와 캐시 미스가 늘 수 있다.

### 1.2 시간 지역성

시간 지역성(temporal locality)은 최근 접근한 데이터를 가까운 시간 안에 다시 접근할 가능성이 높다는 성질이다.

예:

- 로그인 세션과 사용자 권한을 짧은 기간 반복 확인
- 마감시간에 당일 주문 집계를 여러 번 조회
- 인기 상품 정보를 다수 요청이 반복 사용
- 동일 인덱스 상위 페이지를 반복 탐색

버퍼 캐시와 메모리 계층은 시간 지역성을 활용한다. 그러나 캐시 적중률이 높다고 모든 업무가 빠르다는 뜻은 아니다. 자주 접근하는 대형 데이터가 다른 중요한 데이터를 밀어내거나 오래된 값이 유지될 위험도 확인한다.

### 1.3 지역성의 범위

지역성은 여러 수준에서 나타난다.

| 수준 | 가까이 두는 대상 | 대표 효과 |
|---|---|---|
| 행·블록 | 같은 키·범위의 행 | 블록 읽기 감소 |
| 파티션 | 같은 기간·업무의 행 집합 | 가지치기·관리 단위 축소 |
| 테이블·인덱스 | 함께 접근하는 객체 | 저장 I/O 경로 최적화 가능 |
| 노드·샤드 | 조인·트랜잭션이 잦은 데이터 | 원격 호출·분산 조인 감소 |
| 지역·센터 | 사용자와 서비스에 가까운 복제본 | 네트워크 지연 감소 |
| 저장계층 | hot·warm·cold 데이터 | 비용과 응답시간 균형 |

가까움의 의미는 물리 디스크 주소만이 아니다. 같은 파티션, 같은 노드, 같은 장애·네트워크 영역처럼 설계 목적에 따라 달라진다.

## 2. 지역화 설계 방법

### 2.1 접근 패턴을 먼저 측정한다

지역화를 위해 업무 흐름과 쿼리에서 다음을 수집한다.

- 함께 조회·변경되는 테이블과 행 집합
- 필터·조인·정렬·집계 키와 반환 행 수
- 읽기·쓰기 빈도, 동시성과 최고 부하 시간
- 최근·과거 데이터의 접근 비율과 보존정책
- 사용자·서비스의 위치와 원격 호출 지연
- 데이터 증가, 키 분포와 특정 고객·지역의 편향
- 트랜잭션 경계와 강한 정합성이 필요한 데이터

설계자의 추측만으로 “고객별로 묶자”고 결정하지 않고 실행 통계, 업무 빈도와 성장 시나리오를 근거로 한다.

### 2.2 관련 행의 근접 배치

동일 클러스터 키, 정렬된 저장, 인덱스 조직 등 DBMS가 제공하는 물리 배치 기능을 이용할 수 있다. 고객별 최근 거래처럼 같은 키의 여러 행을 함께 읽으면 이득이 있을 수 있다.

비용:

- 새 행을 알맞은 위치에 넣는 쓰기 비용
- 키 변경과 페이지 분할·재구성
- 한 물리 순서만 최적화하므로 다른 쿼리에는 불리
- 키 편향 시 특정 블록·노드 과부하

### 2.3 파티션 정렬과 조인 지역성

자주 조인하는 큰 테이블을 호환되는 키·분할 규칙으로 나누면 같은 키 범위의 데이터가 같은 파티션·노드에 위치해 분산 조인과 데이터 이동을 줄일 수 있다.

예:

```text
orders와 order_items를 order_id 계열로 함께 배치
→ 한 주문 조회가 같은 노드 안에서 처리될 가능성 증가
```

하지만 보존정책은 주문일 기준, 분산은 고객 ID 기준처럼 서로 다른 요구가 있을 수 있다. 하나의 키가 모든 목적을 만족하지 않으므로 쿼리 비용, 관리·삭제와 부하 균형을 비교한다.

### 2.4 hot·warm·cold 계층화

- hot: 최근·빈번 접근, 낮은 지연이 필요한 데이터
- warm: 접근 빈도가 중간이고 비용·성능 균형이 필요한 데이터
- cold: 오래되거나 드물게 접근하지만 보존이 필요한 데이터

접근 빈도와 업무 중요도에 따라 저장매체·압축·복제·인덱스 수준을 다르게 할 수 있다. 단, cold 데이터도 법적 요청이나 장애 복구에 정해진 시간 안에 제공해야 할 수 있으므로 “안 쓰는 데이터”로 취급하지 않는다.

계층 이동 정책에는 기준시각, 원본·인덱스·메타데이터, 조회 경로, 복귀 시간, 암호화와 삭제가 포함되어야 한다.

### 2.5 분산·지역 배치

사용자와 가까운 읽기 복제본을 두면 지연을 줄일 수 있지만 복제지연으로 최신 쓰기가 즉시 보이지 않을 수 있다. 쓰기 주 노드가 멀면 갱신 지연이 커질 수 있고 여러 지역 쓰기는 충돌·정합성 문제를 만든다.

분산 지역화 판단:

- 읽기 후 즉시 자신의 쓰기를 봐야 하는가?
- 어느 지역에서 쓰기가 발생하는가?
- 원격 조인·트랜잭션을 얼마나 줄일 수 있는가?
- 네트워크 분리 때 가용성과 정합성 중 무엇을 우선하는가?
- 데이터 저장 위치·이전과 개인정보 규정은 무엇인가?
- 장애지역 전체 손실과 복구 목표를 어떻게 만족하는가?

### 2.6 캐시와 지역성

캐시는 반복 접근 데이터를 가까운 빠른 계층에 보관해 시간 지역성을 이용한다. 다음을 설계한다.

- 캐시 키와 값의 범위
- 만료시간과 갱신·무효화 조건
- 원본 변경 뒤 허용 가능한 오래된 값
- 캐시 미스·대량 동시 갱신과 장애 대응
- 민감데이터의 보호와 공유 범위
- 적중률뿐 아니라 원본 부하·오류와 사용자 결과

캐시는 원본 데이터베이스의 권위 있는 상태를 대체하지 않으며 잘못된 무효화는 오래된 데이터와 정합성 결함을 만든다.

## 3. 지역성의 상충관계

| 목표 | 지역화 이점 | 잠재 비용 |
|---|---|---|
| 읽기 지연 감소 | 관련 행·노드 접근 축소 | 쓰기·재배치 증가 |
| 원격 통신 감소 | 조인·트랜잭션 공동 배치 | 키 편향·노드 집중 |
| 최근 데이터 가속 | hot 계층·캐시 활용 | 오래된 값·무효화·비용 |
| 관리 단위 분리 | 기간 파티션·계층화 | 여러 접근축과 불일치 |
| 사용자 근접 배치 | 네트워크 지연 감소 | 복제지연·규제·충돌 |

읽기 성능만 높이고 쓰기 처리량, 정합성, 장애복구와 데이터 이동 비용을 무시하면 전체 품질이 나빠질 수 있다.

## 4. 데이터베이스 물리속성 설계의 적용 절차와 판단 기준

### 4.1 적용 절차

1. **요구 수집**: 데이터량·증가, 핵심 쿼리, 처리량·응답시간, RPO·RTO, 보존·보안을 확인한다.
2. **논리모델·현행 검토**: 테이블·관계·키·데이터 분포와 현재 병목을 분석한다.
3. **워크로드 분류**: 온라인·배치, 읽기·쓰기, 최근·과거, 지역별 흐름으로 나눈다.
4. **물리속성 후보 설계**: 파티션, 클러스터링, 인덱스, 지역화, 저장계층과 여유공간을 조합한다.
5. **용량·복구 연결**: 테이블·인덱스·로그·백업·복제·임시공간과 복구시간을 산정한다.
6. **대표 시험**: 실제 규모·분포·동시성에서 응답시간, I/O, 쓰기, 유지보수와 복구를 측정한다.
7. **대안 비교**: 성능, 용량, 정합성, 가용성, 보안, 운영·전환·비용을 평가한다.
8. **적용·전환 계획**: 데이터 이동, 중단, 병행운영, 검증·롤백과 책임을 정한다.
9. **운영 보정**: 통계·분포·성장·지역성 변화와 계획 퇴화를 모니터링한다.

### 4.2 판단 기준

- 주요 쿼리가 필요한 파티션·블록·노드만 접근하는가?
- 읽기 개선이 쓰기·갱신·재구성 비용보다 큰가?
- 데이터와 부하가 파티션·노드에 균형 있게 분포하는가?
- 성장·보존·백업·복구 목표를 수용하는가?
- 정합성과 트랜잭션 경계가 분산·캐시 정책과 맞는가?
- 장애 시 대체 노드·지역에서 필요한 데이터를 이용할 수 있는가?
- 암호화·접근통제·데이터 위치 규정을 충족하는가?
- 팀이 통계·파티션·계층 이동과 장애를 운영할 수 있는가?
- 전환·되돌리기와 장기 총비용이 허용되는가?

평균 응답시간 하나보다 p95·p99, 처리량, I/O, 쓰기 지연, 실패와 운영시간을 함께 비교한다.

## 5. 적용 예시

전국 매장의 판매 데이터가 중앙 데이터베이스에 있고 최근 30일 매장별 조회가 대부분이라고 하자.

- 판매일 범위 파티션으로 최근 기간 가지치기와 보관을 지원한다.
- 매장별 조회가 많아 파티션 내부에서 매장 ID의 근접 배치를 검토한다.
- 최근 30일은 빠른 저장계층과 캐시에 두고 과거 데이터는 압축 계층으로 이동한다.
- 매장 ID 분포에서 대형 매장의 쓰기 집중을 확인해 특정 파티션·노드 편향을 시험한다.
- 캐시 만료와 당일 정정 거래의 최신성 요구를 합의한다.
- 전환 전후 p95, 읽은 블록, 적재 처리량, 저장비용, 백업·복구시간을 비교한다.

## 6. 시험 함정

1. **locality를 데이터 주권과 동일시**: 접근 근접성과 법적 저장 위치는 관련될 수 있지만 다른 개념이다.
2. **공간·시간 지역성 혼동**: 인접 데이터 접근과 최근 데이터 재접근이다.
3. **지역화는 읽기만 개선**: 쓰기·재배치·키 편향과 운영비용을 추가할 수 있다.
4. **같은 파티션이면 모든 조인이 지역적**: 분할 키·규칙과 실제 실행계획이 맞아야 한다.
5. **hot 데이터는 중요 데이터와 동일**: 접근 빈도와 업무 중요도는 다른 축이다.
6. **캐시 적중률만 높으면 성공**: 최신성, 원본 부하, 오류·무효화와 사용자 결과를 본다.
7. **사용자 근처 복제본은 항상 최신**: 복제지연과 읽기 일관성 정책을 확인한다.
8. **평균 데이터 분포 사용**: 최대 키·지역·시간 편향이 병목을 만들 수 있다.
9. **물리속성 설계 후 고정**: 데이터 분포와 워크로드 변화로 주기적 보정이 필요하다.

## 7. 확인 문제

### 문제 1

같은 주문의 상세행을 연속해서 읽을 때 관련 행을 가까이 두어 얻는 것은 어떤 지역성인가?

**정답과 해설**: 공간 지역성이다. 물리·논리적으로 인접한 관련 데이터를 함께 접근할 가능성을 이용한다.

### 문제 2

최근 조회한 사용자 권한을 짧은 시간 안에 반복 사용하는 것은?

**정답과 해설**: 시간 지역성이다. 최근 접근한 데이터가 다시 필요할 가능성을 캐시 등이 활용한다.

### 문제 3

자주 조인하는 두 큰 테이블의 분할 키를 맞추는 목적은?

**정답과 해설**: 관련 행을 같은 파티션·노드에 두어 원격 데이터 이동과 분산 조인 비용을 줄이기 위해서다.

### 문제 4

읽기 복제본을 사용자 지역에 두면 어떤 일관성 위험이 있는가?

**정답과 해설**: 복제지연으로 방금 쓴 값이나 최신 변경이 즉시 보이지 않을 수 있다. 업무의 최신성 요구와 읽기 정책을 정한다.

### 문제 5

지역화 대안의 읽기 p95가 좋아졌지만 쓰기 처리량이 절반으로 줄었다. 무엇을 해야 하는가?

**정답과 해설**: 읽기 개선만으로 채택하지 않고 실제 읽기·쓰기 비중, 업무 목표, 재배치·운영비용과 다른 대안을 통합 비교한다.

## 8. 최종 요약

- `데이터 지역화(locality)`는 함께 또는 반복 접근하는 데이터를 블록·파티션·노드·지역·저장계층에서 가깝게 두는 원리다.
- 공간 지역성은 인접·관련 데이터, 시간 지역성은 최근 데이터의 재접근 가능성을 이용한다.
- 근접 배치, 파티션 정렬, hot·warm·cold 계층, 지역 복제와 캐시는 서로 다른 수준의 지역화를 제공한다.
- 읽기 지연 개선과 쓰기·재배치·편향·정합성·가용성·규제 비용을 함께 본다.
- `데이터베이스 물리속성 설계의 적용 절차와 판단 기준`은 요구·워크로드·분포를 근거로 후보를 만들고 대표 부하와 복구에서 검증하는 것이다.
- 성능, 용량, 정합성, 가용성, 보안, 운영·전환·비용을 통합 비교하고 운영 관측으로 지속 보정한다.
