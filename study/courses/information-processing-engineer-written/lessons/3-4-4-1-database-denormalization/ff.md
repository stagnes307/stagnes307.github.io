# 3-4-4-1. 데이터베이스 반정규화

## 학습 범위

이 레슨의 핵심 토픽은 **정규화**와 **데이터베이스 반정규화의 적용 절차와 판단 기준**이다. 정규화가 함수 종속과 이상 현상을 줄이는 원리를 정규형별로 이해하고, 정규화된 기준 모델을 바탕으로 성능상 필요한 부분에 반정규화를 적용하는 증거 중심 절차를 학습한다.

학습 목표는 다음과 같다.

1. 삽입·갱신·삭제 이상과 함수 종속의 관계를 설명한다.
2. 제1정규형부터 제5정규형까지 각 단계가 제거하려는 종속 문제를 구분한다.
3. 무손실 분해와 종속성 보존이 왜 중요한지 설명한다.
4. 측정된 병목을 바탕으로 반정규화 후보를 평가하고, 원천·동기화·검증·복구 규칙을 설계한다.
5. 조회 성능 이익과 쓰기·일관성·운영 비용을 함께 판단한다.

## 1. 정규화의 목적

정규화는 데이터의 논리적 의미와 종속 관계에 따라 릴레이션을 분해해 불필요한 중복과 이상 현상을 줄이는 과정이다. 목표는 테이블 수를 무조건 늘리는 것이 아니라 한 사실을 가능한 한 한곳에서 관리하고, 각 속성이 올바른 키와 종속 관계를 갖게 하는 것이다.

주문·고객·상품 사실을 한 테이블에 반복하면 고객명과 상품명이 중복되고, 일부만 고칠 때 값이 어긋난다. 정규화는 고객, 상품, 주문, 주문상세처럼 독립된 사실을 분리하고 키로 연결한다.

정규화만으로 모든 업무 제약이나 성능 문제가 해결되지는 않는다. 후보 키, 외래 키, 도메인 제약, 트랜잭션을 함께 설계하고 실제 병목이 확인될 때 제한적으로 반정규화를 검토한다.

## 2. 이상 현상

### 2.1 삽입 이상

삽입 이상은 한 사실을 저장하려고 관계없는 사실까지 입력해야 하는 문제다. 상품과 주문이 한 테이블에만 있으면 주문되지 않은 상품을 등록하기 어렵다.

### 2.2 갱신 이상

갱신 이상은 같은 사실이 중복되어 일부 행만 바뀔 때 값이 불일치하는 문제다. 고객명이 모든 주문에 있으면 이름 변경 누락이 생길 수 있다.

### 2.3 삭제 이상

삭제 이상은 한 사실을 지우며 보존할 다른 사실까지 잃는 문제다. 마지막 주문 행이 상품의 유일한 저장소라면 주문 삭제와 함께 상품 정보도 사라진다.

## 3. 함수 종속

함수 종속 X → Y는 X 값이 같으면 Y 값도 항상 같다는 의미다. X는 결정자, Y는 종속자다. 학생번호 → 학생이름처럼 표현하며, 현재 표본이 아니라 업무 규칙상 모든 유효 상태에서 성립해야 한다.

### 3.1 완전 함수 종속과 부분 함수 종속

종속자가 복합 결정자 전체에 종속하고 일부에는 종속하지 않을 때 완전 함수 종속이라 한다. 부분 함수 종속은 복합 키 일부만으로 결정되는 경우다. {주문번호, 상품번호}가 키인데 주문일자가 주문번호만으로 결정된다면 부분 종속이므로 주문 테이블로 분리한다.

### 3.2 이행 함수 종속

X → Y이고 Y → Z가 성립해 X → Z가 간접적으로 성립할 때 이행 함수 종속을 검토한다. 사원번호 → 부서번호, 부서번호 → 부서명이 성립하면 사원번호 → 부서명이 이행적으로 성립한다. 부서명을 사원 테이블에 반복 저장하면 부서명 변경 시 갱신 이상이 생길 수 있으므로 부서 정보를 분리한다.

### 3.3 다치 종속과 조인 종속

다치 종속은 한 결정자에 서로 독립적인 여러 값 집합이 있는 관계다. 한 강사의 여러 자격증과 언어를 한 테이블에 두면 모든 조합이 반복될 수 있다. 조인 종속은 여러 투영으로 분해했다가 조인해 원래 관계를 복원하는 더 일반적인 제약이다.

## 4. 정규형별 핵심

정규화는 보통 낮은 정규형 조건을 만족한 뒤 다음 정규형을 검토한다. 정규형 이름만 외우기보다 “어떤 결정자가 어떤 속성을 부적절하게 결정하는가”를 확인해야 한다.

### 4.1 제1정규형

제1정규형은 모든 속성 값이 해당 관계 모델에서 더 이상 나누지 않는 하나의 값으로 취급되도록 하고, 반복 그룹을 제거한 상태다. 한 칼럼에 전화번호 여러 개를 쉼표로 연결해 저장하면 각 번호를 독립적으로 제약·검색·갱신하기 어렵다. 고객전화처럼 행 단위로 분리할 수 있다.

원자성은 업무 관점에 따라 판단한다. 주소에서 시·도와 우편번호를 별도로 검색·검증한다면 필요한 속성으로 나누되, 문자열을 무조건 최대한 잘게 쪼개지는 않는다.

### 4.2 제2정규형

제2정규형은 제1정규형을 만족하고, 기본이 아닌 모든 속성이 후보 키 전체에 완전 함수 종속하도록 부분 함수 종속을 제거한 상태다. 특히 복합 후보 키가 있을 때 확인한다.

수강 테이블의 후보 키가 {학생번호, 과목번호}인데 학생이름은 학생번호에만, 과목명은 과목번호에만 종속한다면 부분 종속이 존재한다. 학생, 과목, 수강으로 분리하면 수강의 성적처럼 조합 전체에 종속하는 속성만 남는다. 후보 키가 단일 속성뿐이라면 그 키의 진부분집합이 없으므로 해당 키에 대한 부분 종속 문제는 발생하지 않는다.

### 4.3 제3정규형

제3정규형은 제2정규형을 만족하고 기본이 아닌 속성이 후보 키에 이행적으로 종속하는 문제를 제거한 상태로 이해할 수 있다. 사원번호가 부서번호를 결정하고 부서번호가 부서명을 결정한다면 부서명을 별도 부서 테이블로 분리한다.

### 4.4 보이스-코드 정규형

보이스-코드 정규형은 모든 비자명 함수 종속 X → Y에서 결정자 X가 슈퍼 키가 되도록 요구한다. 제3정규형보다 더 엄격하다. 여러 후보 키가 겹치는 관계에서는 제3정규형을 만족하면서도 후보 키가 아닌 결정자가 남을 수 있으며, 보이스-코드 정규형은 이를 분해 대상으로 본다.

정확한 핵심은 결정자가 슈퍼 키여야 한다는 것이다. 분해할 때는 무손실 조인과 중요한 종속성 유지도 확인한다.

### 4.5 제4정규형

제4정규형은 보이스-코드 정규형을 만족하고, 후보 키에 의해 발생하는 경우를 제외한 비자명 다치 종속을 제거한 상태다. 강사의 자격증 목록과 언어 목록이 서로 독립인데 한 테이블에 함께 저장하면 가능한 조합이 반복된다. 강사자격증과 강사언어로 분리하면 각 독립 사실을 한 번씩 저장할 수 있다.

다치 종속은 한 속성이 여러 값을 가진다는 사실만으로 자동 성립하는 것이 아니다. 두 개 이상의 독립적인 다값 사실이 같은 결정자 아래 결합되어 불필요한 조합을 만드는지를 본다.

### 4.6 제5정규형

제5정규형은 후보 키로부터 따라오는 경우를 제외한 비자명 조인 종속을 제거해, 더 작은 릴레이션으로 분해할 필요가 없는 상태를 다룬다. 공급자·부품·프로젝트처럼 세 관계의 유효 조합이 각 이항 관계의 결합으로 정확히 결정되는 특수한 경우를 생각할 수 있다.

삼항 관계라는 이유만으로 이항 관계로 나누면 원래 없던 조합이 생길 수 있으므로 실제 조인 종속을 확인해야 한다.

## 5. 분해의 품질: 무손실 조인과 종속성 보존

정규화 과정에서 테이블을 나누기만 하면 좋은 설계가 되는 것은 아니다. 분해한 릴레이션을 자연 조인했을 때 원래의 유효한 정보를 정확히 복원할 수 있어야 한다. 원래 없던 가짜 행이 생기거나 기존 행을 잃는 분해는 손실 분해이며 피해야 한다. 이를 무손실 조인 성질이라고 한다.

종속성 보존은 원래 함수 종속을 분해된 릴레이션의 제약만으로 검사할 수 있는 성질이다. 무손실 조인을 우선 확보하면서 종속성 보존과 운영 복잡도를 함께 비교한다.

## 6. 데이터베이스 반정규화의 의미

반정규화는 정규화된 기준 구조에서 측정된 성능 또는 운영 요구를 해결하기 위해 중복 칼럼, 파생값, 요약 테이블, 테이블 결합, 직접 관계 같은 구조를 의도적으로 추가하는 작업이다. 정규화를 실수로 누락한 비정상 구조와 구분해야 한다.

반정규화의 핵심 질문은 “중복을 만들 수 있는가”가 아니라 “어떤 병목을 얼마만큼 줄이며, 생긴 중복을 누가 언제 어떻게 일치시키는가”다. 성능 목표, 원천 데이터, 동기화 시점, 실패 복구, 정합성 검증, 철회 방법이 없으면 운영 가능한 설계라 보기 어렵다.

## 7. 데이터베이스 반정규화의 적용 절차와 판단 기준

### 7.1 1단계: 목표와 기준선 정의

먼저 개선하려는 업무와 수치 목표를 정한다. “조회가 느리다”가 아니라 “월말 주문 현황의 상위 95% 응답 시간이 목표를 초과한다”, “동시 사용자가 늘면 집계 질의의 CPU 사용량이 한계를 넘는다”처럼 측정 가능하게 표현한다. 현재 응답 시간, 처리량, 읽기·쓰기 비율, 데이터량, 동시성, 오류율을 기준선으로 기록한다.

### 7.2 2단계: 실제 병목 확인

실행 계획, 대기·입출력 통계, 조인 행 수, 반복 계산, 잠금, 네트워크 이동, 캐시 적중 등을 조사한다. 조인이 있다는 사실만으로 조인이 병목이라고 결론 내리지 않는다. 잘못된 조건, 누락된 인덱스, 오래된 통계, 필요 없는 열 조회, 부정확한 카디널리티 추정이 원인일 수 있다.

운영과 유사한 데이터 분포와 동시 부하에서 확인하고 평균뿐 아니라 백분위 응답 시간도 본다.

### 7.3 3단계: 대안 우선 비교

질의 재작성, 필요한 인덱스, 통계 관리, 결과 캐시, 파티셔닝, 배치 시점 조정, 불필요한 왕복 제거 등 중복을 만들지 않는 대안을 먼저 비교한다. 이런 대안이 항상 반정규화보다 우월하다는 뜻은 아니지만, 일관성 비용이 낮은 해결책으로 목표를 달성할 수 있다면 운영 위험을 줄일 수 있다.

### 7.4 4단계: 반정규화 후보 설계

병목 원인에 맞는 최소 범위의 후보를 만든다.

- 반복 조인이 병목이면 필요한 칼럼의 제한적 중복이나 관계 추가를 검토한다.
- 동일 집계의 반복 계산이 병목이면 요약 테이블 또는 파생 칼럼을 검토한다.
- 항상 함께 읽는 일대일 구조라면 테이블 병합을, 넓은 행의 일부만 자주 읽으면 수직 분할을 검토한다.
- 원격 데이터 접근이 병목이면 읽기 사본을 검토하되 최신성 요구를 명시한다.

후보별 대상 질의, 예상 이익, 저장량, 갱신 경로, 실패 형태를 기록하고 목표 달성에 필요한 최소 중복을 선택한다.

### 7.5 5단계: 의미와 원천 데이터 확정

중복값 중 어느 위치가 권위 있는 원천인지 하나로 정한다. “주문 당시 고객명”처럼 시점 의미를 가진 값은 현재 고객명의 단순 사본과 다르다. 스냅숏이면 이후 원천 변경을 반영하지 않는 것이 올바른 무결성일 수 있고, 현재값 사본이면 변경을 반드시 전파해야 한다.

원천과 파생값의 계산식, 시간 기준, 반올림, 널 처리, 집계 조건과 소유 책임을 문서화한다.

### 7.6 6단계: 동기화와 실패 처리 설계

동기식 갱신은 원천과 중복값을 같은 트랜잭션에서 바꿔 즉시 일관성을 높일 수 있지만 쓰기 지연과 잠금 범위가 커질 수 있다. 비동기 갱신은 원천 쓰기를 가볍게 할 수 있으나 일정 시간 오래된 값이 보일 수 있고 메시지 중복·순서 변경·재처리를 다뤄야 한다.

허용 최신성, 최대 지연, 중복 처리 안전성, 재시도, 실패 격리, 재구축 방법을 정한다. 구현 기술의 이름보다 실패 특성을 비교한다.

### 7.7 7단계: 성능·무결성 검증

운영과 유사한 데이터량과 읽기·쓰기 혼합 부하에서 전후를 비교한다. 목표 질의뿐 아니라 삽입·수정·삭제, 로그량, 저장량, 잠금, 복제 지연, 백업 시간도 측정한다. 원천과 중복값의 불일치를 의도적으로 만들어 탐지·복구 절차가 작동하는지 시험한다.

### 7.8 8단계: 배포·관찰·철회

기존 행 이행, 점진적 전환, 검증 쿼리, 원복 방법을 마련한다. 배포 후 응답 시간, 불일치, 동기화 지연, 저장 증가를 관찰하고 사용처와 의존성을 문서화한다.

## 8. 판단 기준표

| 판단 기준 | 반정규화에 유리한 신호 | 신중해야 할 신호 |
|---|---|---|
| 병목 증거 | 특정 조인·집계가 반복 측정에서 주된 비용 | 원인이 불명확하거나 단순 질의 오류 |
| 읽기·쓰기 비율 | 동일 읽기가 매우 많고 원천 변경이 드묾 | 변경이 빈번하고 여러 경로에서 동시에 씀 |
| 최신성 | 지연 허용 범위가 명확함 | 즉시 일관성이 법적·금전적으로 필수 |
| 동기화 | 단일 원천과 갱신 책임이 명확함 | 어느 값이 원본인지 불명확함 |
| 복구 | 재계산·재적재가 가능하고 검증 쿼리가 있음 | 불일치를 탐지하거나 되돌릴 방법이 없음 |
| 대안 | 인덱스·질의 개선으로 목표를 달성하지 못함 | 낮은 위험의 대안으로 충분히 해결 가능 |
| 전체 비용 | 읽기 이익이 쓰기·저장·운영 증가보다 큼 | 한 화면 개선 때문에 전체 시스템 비용 급증 |

## 9. 적용 예시: 일별 주문 요약

상세 주문 테이블에서 매 요청마다 날짜별 주문건수와 결제금액을 집계하는 보고서가 실제 병목이라고 하자. 후보로 일별 주문 요약 테이블을 만들고 날짜, 주문건수, 결제합계, 마지막반영시각을 저장할 수 있다.

적용 전 다음을 정한다.

1. 원천은 확정된 주문·결제 행이며 취소와 환불을 어느 날짜에 반영할지 정의한다.
2. 결제합계의 통화, 세금 포함 여부, 반올림 규칙을 고정한다.
3. 실시간 갱신인지 일정 주기 배치인지 선택하고 허용 지연을 정한다.
4. 같은 변경을 두 번 처리해도 합계가 틀어지지 않도록 처리 식별과 재실행 원칙을 설계한다.
5. 상세 원천에서 날짜별 합계를 다시 계산해 요약값과 비교하는 정합성 검사를 만든다.
6. 실패 기간을 재집계하고 보고서를 원천 조회로 되돌릴 수 있는 절차를 마련한다.

요약 조회는 빨라져도 쓰기·배치 비용은 늘어난다. 지연 취소가 있다면 과거 날짜도 재집계해야 한다.

## 10. 시험 함정

1. 정규화의 목적을 테이블 수 증가로 외우지 않는다. 종속 관계를 올바르게 표현하고 이상 현상을 줄이는 것이 목적이다.
2. 제2정규형은 모든 함수 종속을 제거하는 것이 아니다. 복합 후보 키 일부에 대한 부분 함수 종속을 제거한다.
3. 제3정규형은 제2정규형을 만족한 뒤 비키 속성 사이의 이행 종속을 다룬다.
4. 보이스-코드 정규형은 모든 결정자가 슈퍼 키가 되도록 요구하며 제3정규형보다 엄격하다.
5. 제4정규형은 단순 반복값이 아니라 독립적인 다치 종속을, 제5정규형은 비자명 조인 종속을 다룬다.
6. 분해 후 원래 정보를 정확히 복원하지 못하거나 가짜 행이 생기면 좋은 정규화가 아니다. 무손실 조인을 확인한다.
7. 반정규화는 정규화 실패와 같지 않다. 기준 모델과 측정된 병목, 관리 규칙이 있어야 한다.
8. 조인이 많다는 사실만으로 반정규화를 결정하지 않는다. 실제 실행 비용과 다른 대안을 비교한다.
9. 동기식은 언제나 좋고 비동기식은 언제나 나쁘다는 식으로 판단하지 않는다. 일관성 요구와 쓰기 비용, 허용 지연을 비교한다.
10. 반정규화 성공 여부를 조회 한 건의 속도만으로 평가하지 않는다. 쓰기, 저장, 잠금, 동기화, 복구까지 포함한다.

## 11. 확인 문제

### 문제 1

복합 키 {주문번호, 상품번호}를 가진 주문상세에 주문일자가 저장되어 있고 주문번호만으로 주문일자가 결정된다. 어떤 문제가 있으며 어떤 정규형 단계에서 주로 다루는가?

**정답과 해설:** 주문일자가 복합 키 전체가 아니라 주문번호 일부에만 부분 함수 종속한다. 제1정규형을 만족한다는 전제에서 제2정규형으로 정규화하며 주문일자를 주문 단위 테이블로 분리한다.

### 문제 2

사원번호 → 부서번호, 부서번호 → 부서명이 성립할 때 사원 테이블에 부서명을 반복 저장하면 어떤 종속이 발생하는가?

**정답과 해설:** 사원번호에서 부서번호를 거쳐 부서명이 결정되는 이행 함수 종속이 발생한다. 부서번호와 부서명을 부서 테이블로 분리하면 부서명 변경의 갱신 이상을 줄일 수 있다.

### 문제 3

정규화 분해에서 무손실 조인이 중요한 이유는 무엇인가?

**정답과 해설:** 분해된 테이블을 조인했을 때 원래의 유효한 정보를 정확히 복원해야 하기 때문이다. 원래 없던 가짜 행이 생기거나 기존 사실을 잃는다면 분해가 데이터 의미를 훼손한다.

### 문제 4

특정 보고서가 느리다는 이유만으로 즉시 요약 테이블을 만드는 것이 적절하지 않은 이유를 두 가지 쓰시오.

**정답과 해설:** 먼저 실제 병목이 반복 집계인지 실행 계획과 부하 자료로 확인해야 하고, 인덱스·질의 개선 등 중복 없는 대안으로 목표를 달성할 수 있는지 비교해야 한다. 또한 요약값의 원천, 최신성, 동기화, 실패 복구 비용이 조회 이익보다 클 수 있다.

### 문제 5

현재 고객명을 주문에 중복 저장할 때 반드시 정해야 할 네 가지 규칙을 쓰시오.

**정답과 해설:** 권위 있는 원천 위치, 고객명 변경의 반영 시점과 방식, 실패 시 재시도·복구 방법, 원천과 중복값의 불일치 탐지 방법을 정해야 한다. 주문 당시 이름을 보존하는 스냅숏인지 현재값 사본인지도 명확히 구분해야 한다.

### 문제 6

반정규화 적용 후 목표 조회는 빨라졌지만 주문 갱신 지연과 불일치가 크게 늘었다. 무엇을 기준으로 유지 여부를 판단해야 하는가?

**정답과 해설:** 사전에 정의한 전체 성능 목표와 무결성 기준으로 판단한다. 조회 응답 시간뿐 아니라 쓰기 처리량, 잠금, 로그, 불일치 건수, 동기화 지연, 복구 비용을 포함한 총효과를 비교한다. 전체 비용이 이익을 초과하면 설계를 조정하거나 철회한다.

## 12. 최종 요약

- **정규화**는 함수 종속에 따라 데이터를 분해해 중복과 삽입·갱신·삭제 이상을 줄이는 과정이다.
- 제1정규형은 반복 그룹과 비원자 값을, 제2정규형은 부분 함수 종속을, 제3정규형은 이행 함수 종속을 주로 다룬다.
- 보이스-코드 정규형은 모든 결정자가 슈퍼 키가 되도록 요구하고, 제4정규형은 비자명 다치 종속, 제5정규형은 비자명 조인 종속을 다룬다.
- 분해에서는 원래 정보를 정확히 복원하는 무손실 조인과 규칙을 효율적으로 검사하는 종속성 보존을 검토한다.
- **데이터베이스 반정규화의 적용 절차와 판단 기준**은 목표·기준선 정의, 병목 확인, 대안 비교, 최소 후보 설계, 원천·의미 확정, 동기화·실패 처리, 성능·무결성 검증, 배포·관찰·철회 순으로 정리할 수 있다.
- 반정규화는 조회 성능뿐 아니라 쓰기, 저장, 일관성, 최신성, 운영, 복구 비용까지 포함해 판단한다.
- 제품이나 버전에 따라 구현 기능은 달라질 수 있으므로 논리적 원칙과 측정 기준을 먼저 세우고, 실제 환경의 공식 문서와 부하 시험으로 세부 설계를 검증한다.
