# 3-4-5-1. 물리데이터 모델 품질 기준 · 물리 E-R 다이어그램

## 학습 범위와 목표

이 레슨은 물리 데이터베이스 설계의 결과물을 검토하는 두 주제, **물리데이터 모델 품질 기준**과 **물리 E-R 다이어그램**에 집중한다. 물리 모델이 업무 규칙을 빠짐없이 담았는지, 실제 데이터베이스에 구현할 수 있는 수준으로 구체화되었는지 판단하고, 다이어그램에서 테이블·열·키·관계·선택성을 읽는 능력을 기르는 것이 목표다. CRUD 분석이나 SQL 성능 튜닝은 다음 레슨의 범위이므로 여기서는 다루지 않는다.

학습을 마치면 다음을 할 수 있어야 한다.

- 논리 모델과 물리 모델의 차이를 설명한다.
- 품질 기준을 이용해 누락, 불일치, 무결성 위험을 찾아낸다.
- 물리 E-R 다이어그램의 테이블, 기본키, 외래키, 관계 차수와 선택성을 해석한다.
- 요구사항부터 물리 모델까지 추적하여 검토 근거를 제시한다.
- 시험 지문에서 품질 기준과 다이어그램 표기를 혼동하지 않는다.

## 1. 물리 데이터 모델의 위치

개념 데이터 모델은 업무 세계의 큰 개체와 관계를 표현하고, 논리 데이터 모델은 특정 제품에 덜 의존적인 엔터티·속성·식별자·관계를 정의한다. 물리 데이터 모델은 이를 실제 데이터베이스에 구현할 수 있도록 테이블명, 열명, 자료형, 길이, 기본값, NULL 허용 여부, 기본키와 외래키 같은 구체 항목으로 바꾼 결과다.

따라서 물리 모델의 품질은 단순히 “그림이 보기 좋은가”로 판정하지 않는다. 업무 요구를 정확히 반영하는가, 필요한 정의가 모두 있는가, 산출물 사이에 모순이 없는가, 데이터 무결성을 지킬 구조인가, 정해진 표준을 따르는가를 증거로 확인해야 한다. 물리 모델은 구현 직전의 설계 기준선이므로 작은 누락도 테이블 생성, 데이터 이행, 프로그램 개발 단계에서 큰 재작업을 만들 수 있다.

## 2. 물리데이터 모델 품질 기준

교재나 조직에 따라 품질 특성의 명칭과 묶는 방식은 조금 다를 수 있다. 시험에서는 명칭만 외우기보다 “무엇을 검사하는 기준인가”를 연결해야 한다.

### 2.1 정확성

정확성은 모델이 실제 업무 규칙과 요구사항을 올바르게 표현하는 정도다. “한 주문은 반드시 한 고객에게 속한다”는 규칙이 있다면 주문 테이블에 고객을 가리키는 외래키가 있고, 필수 관계라면 이를 빠뜨리지 않도록 제약이 설계되어야 한다. 관계 방향, 최대 차수, 필수 여부가 요구사항과 다르면 정확성 결함이다.

확인 질문은 다음과 같다.

- 속성이 올바른 테이블에 배치되었는가?
- 기본키가 한 행을 유일하게 식별하는가?
- 관계의 1:1, 1:N, N:M 의미가 업무 규칙과 일치하는가?
- 자료형과 길이가 실제 값의 의미를 훼손하지 않는가?

### 2.2 완전성

완전성은 구현에 필요한 구성 요소와 정의가 빠짐없이 존재하는 정도다. 테이블은 있는데 기본키가 없거나, 외래키 열은 있는데 참조 대상이 없거나, 열의 자료형·길이·NULL 허용 여부가 비어 있다면 완전하지 않다. 모든 요구사항이 반드시 하나의 테이블에 대응한다는 뜻은 아니며, 각 요구사항이 적절한 모델 요소로 반영되었음을 추적할 수 있어야 한다.

### 2.3 일관성

일관성은 같은 개념이 여러 산출물에서 서로 모순되지 않는 정도다. 다이어그램의 열명과 테이블 정의서의 열명이 다르거나, 한 문서에서는 고객번호가 문자형인데 다른 문서에서는 숫자형이면 일관성 문제가 된다. 동일 의미의 코드 열은 자료형, 길이, 허용 값 체계가 통일되어야 한다. 부모의 기본키와 자식의 외래키도 호환 가능한 도메인을 가져야 한다.

### 2.4 준거성 또는 표준 준수

조직의 명명 규칙, 표준 용어, 표준 도메인, 자료형 사용 원칙 같은 설계 표준을 따르는지를 본다. 예를 들어 동일한 “등록일시” 개념을 테이블마다 서로 다른 이름과 형식으로 정의하면 유지보수와 연계가 어려워진다. 다만 특정 데이터베이스 제품의 자료형 이름이나 길이를 보편적 정답처럼 암기해서는 안 된다. 문제에 제시된 표준을 기준으로 판정한다.

### 2.5 무결성

무결성은 잘못된 데이터 상태를 구조적으로 방지할 수 있는지를 본다.

- 개체 무결성: 기본키 값은 각 행을 유일하게 식별하며 NULL이 될 수 없다.
- 참조 무결성: 외래키 값은 허용된 NULL이거나 부모 테이블의 존재하는 키를 참조해야 한다.
- 도메인 무결성: 열 값은 정의된 자료형, 범위, 형식, 허용 값 조건을 만족해야 한다.

“모든 업무 규칙을 데이터베이스 제약으로 구현해야 한다”는 식의 극단적 판단은 피한다. 어떤 규칙을 데이터베이스와 응용 계층 중 어디에서 보장할지는 환경에 따라 달라질 수 있다. 품질 검토에서는 규칙의 책임 위치가 명확하고 빠짐없이 통제되는지가 중요하다.

### 2.6 추적성과 이해 가능성

추적성은 요구사항, 논리 모델, 물리 모델, 정의서 사이의 대응 관계를 따라갈 수 있는 성질이다. 이해 가능성은 이름, 설명, 범례와 표기가 해석 가능하고 모호하지 않은 정도다. 요구사항 식별자와 모델 요소의 매핑표를 사용하면 누락 여부와 변경 영향을 확인하기 쉽다.

### 2.7 중복과 변경 용이성

의미가 같은 데이터가 불필요하게 여러 곳에 저장되면 갱신 불일치 위험이 커진다. 반대로 업무상 조회 편의나 이력 보존처럼 의도적인 중복이 있을 수 있다. 중요한 것은 중복의 이유, 원본, 동기화 책임이 문서화되어 있는가이다. 변경 용이성은 한 요구 변경이 과도하게 많은 모델 요소를 수정하게 만들지 않는지를 살핀다.

## 3. 품질 검토의 절차

물리 모델 품질 검토는 다음 흐름으로 수행하면 누락을 줄일 수 있다.

1. **범위와 기준선 확정**: 검토 대상 버전, 요구사항 기준선, 명명·도메인 표준, 관련 산출물을 확정한다.
2. **구조 검토**: 모든 테이블의 기본키, 열 정의, 관계, 외래키가 완전한지 확인한다.
3. **업무 규칙 대조**: 요구사항의 개체, 속성, 관계, 필수 조건이 모델에 정확히 반영되었는지 추적한다.
4. **산출물 교차 검토**: 물리 E-R 다이어그램, 테이블 정의서, 열 정의서, 관계 정의서 사이의 이름과 속성을 비교한다.
5. **표준과 무결성 검토**: 명명 규칙, 표준 도메인, 키와 참조 규칙, NULL 정책을 확인한다.
6. **결함 기록**: 위치, 현상, 위반 기준, 영향, 수정 제안, 담당자와 상태를 기록한다.
7. **수정 후 재검토**: 수정된 요소뿐 아니라 연결된 외래키와 문서까지 함께 확인한다.

검토 결과는 “이상 있음”보다 재현 가능한 증거로 남겨야 한다. 예를 들어 “주문상세.상품번호의 길이가 상품.상품번호와 다르며 동일 식별자를 표현하므로 일관성 위반”이라고 적으면 수정 대상과 근거가 분명하다.

## 4. 물리 E-R 다이어그램

**물리 E-R 다이어그램**은 물리 데이터 모델의 구조를 시각적으로 표현한 산출물이다. 보통 테이블, 열, 기본키, 외래키, 테이블 사이 관계를 나타낸다. 사용하는 표기법에 따라 기호 모양은 다를 수 있으므로 문제에 제시된 범례를 먼저 확인해야 한다.

### 4.1 핵심 구성 요소

| 구성 요소 | 물리 모델에서 읽을 내용 | 점검 질문 |
|---|---|---|
| 테이블 | 저장 대상과 물리적 이름 | 업무상 필요한 행의 집합이 분리되어 있는가 |
| 열 | 이름, 자료형, 길이, NULL 여부, 기본값 | 값의 의미와 허용 범위가 명확한가 |
| 기본키 | 행을 유일하게 식별하는 열 또는 열 조합 | 유일하고 안정적으로 식별 가능한가 |
| 외래키 | 다른 테이블의 키를 참조하는 열 | 부모와 자식의 도메인이 호환되는가 |
| 관계 | 테이블 간 참조와 업무 연관 | 차수와 선택성이 요구사항과 맞는가 |
| 제약 조건 | 값과 관계의 유효성 규칙 | 잘못된 상태를 적절히 막는가 |

### 4.2 관계 차수와 선택성

1:1은 부모 한 행과 자식 최대 한 행이 연결되는 관계, 1:N은 부모 한 행에 자식 여러 행이 연결되는 관계다. 논리적 N:M 관계는 실제 관계를 담는 교차 테이블을 두어 두 개의 1:N 관계로 구현하는 것이 일반적이다.

선택성은 관계 참여가 필수인지 선택인지 나타낸다. 최소 차수가 0이면 관계가 없어도 되고, 1이면 반드시 하나 이상 연결되어야 한다. 최대 차수는 하나인지 여러 개인지를 나타낸다. “고객은 주문을 하지 않을 수도 있지만, 주문은 반드시 한 고객에 속한다”면 고객에서 주문으로는 0..N, 주문에서 고객으로는 정확히 1이라는 의미다.

### 4.3 식별 관계와 비식별 관계

식별 관계에서는 부모의 기본키가 자식 기본키의 일부가 된다. 자식의 식별이 부모에 의존한다. 비식별 관계에서는 부모 키가 자식의 외래키이지만 자식 기본키에는 포함되지 않는다. 어느 것이 항상 우수한 것은 아니다. 자식의 정체성과 생명주기, 키 안정성, 업무 규칙에 따라 선택하며 다이어그램에서 표기법을 확인한다.

### 4.4 논리 모델에서 물리 다이어그램으로 옮길 때

- 엔터티는 구현 단위인 테이블로 구체화한다.
- 속성은 자료형과 길이, NULL 여부를 가진 열로 구체화한다.
- 주 식별자는 기본키로 구현하되 물리적 키 전략을 문서화한다.
- 관계는 외래키와 참조 규칙으로 구체화한다.
- N:M 관계는 관계의 속성을 담을 교차 테이블로 해소한다.
- 다중 값 속성이나 반복 그룹은 별도 행 집합으로 표현할 필요가 있는지 판단한다.

## 5. 예제로 검토하기

요구사항이 다음과 같다고 하자.

- 고객은 고객번호로 식별된다.
- 고객은 주문을 하지 않을 수 있다.
- 주문은 주문번호로 식별되며 반드시 한 고객에 속한다.
- 한 주문에는 하나 이상의 상품 항목이 들어간다.
- 주문 항목은 주문 안에서 순번으로 식별된다.

물리 모델 후보는 고객(고객번호 PK, 고객명), 주문(주문번호 PK, 고객번호 FK, 주문일시), 주문항목(주문번호 PK/FK, 항목순번 PK, 상품번호 FK, 수량)이다.

검토 순서는 다음과 같다.

1. 주문의 고객번호가 고객 기본키를 참조하는지 본다.
2. 주문이 반드시 고객에 속하므로 고객번호의 필수성 표현이 맞는지 본다.
3. 주문항목의 복합 기본키가 주문번호와 항목순번으로 한 행을 유일하게 식별하는지 본다.
4. 주문항목의 주문번호가 주문을 참조하는 외래키인지 본다.
5. 다이어그램의 이름, 자료형, 필수 여부가 정의서와 같은지 교차 확인한다.

만약 다이어그램에는 주문항목.주문번호가 외래키로 표시되어 있지만 관계선이 없으면 완전성과 일관성을 모두 의심할 수 있다. 고객번호가 고객에서는 문자 12자리, 주문에서는 숫자형이라면 참조 관계의 도메인 일관성 문제다. 주문 없이 주문항목이 존재할 수 있게 그려졌다면 업무 규칙과 다른 정확성 문제다.

## 6. 비교로 정리하기

| 구분 | 논리 데이터 모델 | 물리 데이터 모델 |
|---|---|---|
| 중심 질문 | 업무 데이터의 의미와 관계는 무엇인가 | 실제 저장 구조를 어떻게 구현할 것인가 |
| 주요 요소 | 엔터티, 속성, 식별자, 관계 | 테이블, 열, 자료형, PK, FK, 제약 |
| 제품 의존성 | 상대적으로 낮음 | 구현 환경의 특성을 반영할 수 있음 |
| 검토 초점 | 업무 의미와 정규화, 관계 | 구현 완전성, 표준, 무결성, 산출물 일치 |

| 오류 상황 | 우선 연결할 품질 기준 |
|---|---|
| 요구된 테이블이 빠짐 | 완전성 |
| 부모 PK와 자식 FK의 길이가 다름 | 일관성 |
| 관계의 필수 여부가 업무 규칙과 다름 | 정확성 |
| 표준 용어 대신 임의 축약어 사용 | 표준 준수 |
| 존재하지 않는 부모를 참조할 수 있음 | 참조 무결성 |
| 요구사항과 모델 요소의 대응을 찾을 수 없음 | 추적성 |

## 7. 시험 함정

1. **다이어그램 자체와 품질 기준을 바꾸어 읽기**: E-R 다이어그램은 표현 수단이고, 정확성·완전성 등은 그 결과를 판단하는 기준이다.
2. **기본키와 외래키 혼동**: 기본키는 자기 테이블의 행을 식별하고, 외래키는 다른 테이블의 후보키나 기본키를 참조한다.
3. **1:N 방향을 선 모양만으로 추측**: 표기법마다 기호가 다르다. 범례와 FK 위치를 함께 본다.
4. **선택 관계를 관계 없음으로 해석**: 최소 차수 0은 연결될 수 없다는 뜻이 아니라 연결되지 않은 상태도 허용한다는 뜻이다.
5. **N:M을 그대로 물리 구현한다고 단정**: 관계 자체의 속성을 포함하는 교차 테이블로 해소되는지 확인한다.
6. **중복은 언제나 오류라고 단정**: 의도와 통제 없이 생긴 중복이 문제다. 승인된 이유와 일관성 유지 책임이 있으면 목적 있는 설계일 수 있다.
7. **특정 표기법의 선 모양을 보편 규칙으로 암기**: 문제에서 제공한 표기와 설명을 우선한다.
8. **모델 한 장만 검토**: 정의서와 요구사항을 교차 대조해야 완전성과 일관성을 판단할 수 있다.

## 8. 확인 문제

### 문제 1

다이어그램에는 고객번호 열이 있으나 테이블 정의서에는 해당 열이 없다. 가장 직접적으로 의심할 품질 기준은 무엇인가?

### 문제 2

주문 테이블의 고객번호가 고객 테이블의 고객번호를 참조한다. 두 열의 의미와 형식이 호환되어야 하는 이유를 쓰시오.

### 문제 3

“고객은 주문이 없어도 되지만 주문은 반드시 한 고객에 속한다”의 최소·최대 차수를 설명하시오.

### 문제 4

식별 관계와 비식별 관계의 핵심 차이는 무엇인가?

### 문제 5

논리적 N:M 관계를 물리 모델에서 보통 어떻게 해소하는가?

### 문제 6

요구사항 추적표가 물리 모델 품질 검토에 주는 효과 두 가지를 쓰시오.

### 문제 7

부모 테이블에 존재하지 않는 키를 자식 외래키에 저장할 수 있다면 어떤 무결성 문제가 있는가?

### 문제 8

“특정 데이터베이스 제품의 자료형 이름만 사용하면 물리 모델의 품질이 자동으로 보장된다”가 틀린 이유를 설명하시오.

## 9. 정답과 해설

### 정답 1

일관성이다. 같은 모델을 설명하는 다이어그램과 정의서의 내용이 서로 다르기 때문이다. 정의가 한쪽에만 있어 구현 정보가 부족하다는 점에서는 완전성도 추가로 검토한다.

### 정답 2

외래키는 부모의 식별 값을 저장하므로 의미, 자료형, 길이 같은 도메인이 호환되어야 올바른 참조와 비교가 가능하다. 불일치하면 값 손실이나 참조 실패가 생길 수 있다.

### 정답 3

고객 한 명에 연결되는 주문은 0개 이상이므로 고객에서 주문 방향은 0..N이다. 주문 한 건은 정확히 한 고객에 속하므로 주문에서 고객 방향은 1이다.

### 정답 4

부모의 키가 자식 기본키의 일부가 되어 자식 식별에 참여하면 식별 관계이고, 자식의 일반 외래키로만 존재하면 비식별 관계다.

### 정답 5

두 엔터티의 키를 참조하는 교차 테이블을 두고 N:M을 두 개의 1:N 관계로 바꾼다. 관계 자체의 속성도 이 테이블에 둘 수 있다.

### 정답 6

요구사항이 모델에 빠짐없이 반영되었는지 확인할 수 있고, 요구 변경 시 영향을 받는 테이블·열·관계를 추적할 수 있다.

### 정답 7

참조 무결성 문제다. 자식 외래키는 허용된 NULL이거나 부모의 존재하는 키를 참조해야 한다.

### 정답 8

자료형 선택은 품질의 일부일 뿐이다. 업무 규칙의 정확성, 구성 요소의 완전성, 산출물 일관성, 키와 관계의 무결성, 표준 준수까지 함께 검토해야 한다. 제품별 표현은 환경에 따라 달라질 수 있다.

## 최종 요약

- **물리데이터 모델 품질 기준**은 정확성, 완전성, 일관성, 표준 준수, 무결성, 추적성 등의 관점에서 구현 가능한 설계를 검토하는 기준이다.
- 물리 모델은 테이블, 열, 자료형, 기본키, 외래키, 관계와 제약 조건까지 구체화한다.
- **물리 E-R 다이어그램**은 물리 구조를 시각화한 산출물이며, 관계 차수와 선택성은 업무 규칙과 함께 읽어야 한다.
- 기본키는 행 식별, 외래키는 참조를 담당하며 식별 관계에서는 부모 키가 자식 기본키에 참여한다.
- 품질 검토는 기준선 확정, 구조 검토, 업무 규칙 대조, 산출물 교차 검토, 결함 기록, 재검토의 흐름으로 수행한다.
- 시험에서는 기호 모양을 외우기보다 요구사항, FK 위치, 최소·최대 차수와 품질 기준을 연결해 판단한다.
