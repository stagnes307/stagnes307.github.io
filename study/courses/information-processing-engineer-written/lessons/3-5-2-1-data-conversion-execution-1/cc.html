01

학습 범위와 목표

이 레슨은 전환을 실제로 실행하기 전에 준비해야 하는 데이터 전환 수행 계획과 단계별 누락을 방지하는 체크리스트를 다룬다. 무엇을, 누가, 언제, 어떤 순서와 승인 기준으로 수행할지 문서화하고, 실행 전·중·후의 준비 상태를 객관적 증거로 확인하는 능력이 목표다. 구체적인 데이터 검증 기법은 다음 레슨의 범위이므로 여기서는 계획의 검증 책임과 통과 기준까지만 다룬다.

학습 후에는 다음을 할 수 있어야 한다.

  • 전환 목적, 범위, 기준 시점, 중단 시간을 수행 계획에 정의한다.
  • 역할과 책임, 일정, 자원, 의존성, 위험과 복구 절차를 구성한다.
  • 모의 전환 결과를 이용해 본 전환 소요 시간과 병목을 보정한다.
  • 체크리스트 항목을 예·아니오가 아니라 기준과 증거 중심으로 작성한다.
  • 진행·중단·복구 의사결정을 위한 게이트를 설명한다.
02

1. 데이터 전환 수행 계획의 의미

데이터 전환 수행 계획은 데이터 전환을 통제된 작업으로 실행하기 위한 기준 문서다. 단순한 작업 목록이 아니라 대상과 제외 범위, 기준 시점, 담당자, 선행 조건, 단계별 입력·출력, 예상 시간, 승인 기준, 실패 시 행동을 하나의 흐름으로 연결한다.

전환은 여러 팀이 동시에 움직이고 업무 중단 시간이 제한되는 경우가 많다. 계획이 없으면 다음 문제가 생긴다.

  • 원천 추출 시점이 달라 서로 연관된 데이터 상태가 맞지 않는다.
  • 부모 데이터보다 자식 데이터가 먼저 적재되어 작업이 실패한다.
  • 오류가 발생해도 계속 진행할지 중단할지 책임자가 불명확하다.
  • 완료 시간을 넘겼는데도 되돌릴 수 있는 시점을 놓친다.
  • 작업은 끝났지만 누가 업무 개시를 승인하는지 알 수 없다.

좋은 계획은 “정상일 때의 순서”뿐 아니라 “실패할 때의 선택”을 미리 정한다.

03

2. 계획 수립의 입력 자료

계획을 세우기 전에 다음 자료의 기준 버전을 확정한다.

  • 전환 대상 시스템과 데이터 목록
  • 원천·목표 매핑 및 변환 규칙
  • 데이터 양과 예상 증가량
  • 원천·목표 시스템의 작업 가능 시간
  • 업무 중단 허용 시간과 서비스 개시 목표
  • 보안 등급과 접근 권한 요구
  • 전환 도구·작업 프로그램과 실행 환경
  • 관련 시스템과 배치의 의존 관계
  • 모의 전환 결과와 기존 결함 목록
  • 승인자, 업무 담당자, 운영 담당자의 연락 체계

기준 버전이 확정되지 않으면 전환 직전 변경된 규칙이 일부 작업에만 반영될 수 있다. 변경 요청은 영향, 재시험 필요성, 일정 영향을 검토하여 승인된 경우에만 계획 기준선에 반영한다.

04

3. 데이터 전환 수행 계획의 핵심 구성

3.1 목적과 성공 기준

목적은 “기존 고객·계약 데이터를 새 시스템으로 전환하여 업무 개시를 지원한다”처럼 업무 결과로 쓴다. 성공 기준은 측정 가능해야 한다.

  • 승인된 대상 범위가 정해진 시간 안에 적재됨
  • 치명 오류가 0건이며 허용 가능한 경미 오류가 기준 이하임
  • 핵심 업무 시나리오가 승인됨
  • 보안·감사 기록과 작업 결과가 인계됨

정확한 임계값은 프로젝트 요구에서 정해야 하며 보편적인 숫자를 임의로 만들지 않는다.

3.2 범위와 제외 범위

대상 시스템, 테이블 또는 업무 개체, 이력 기간, 기준일, 제외 상태를 명시한다. “고객 데이터”처럼 넓게 쓰지 말고 활성 고객, 탈퇴 고객 보존 범위, 첨부 데이터 포함 여부를 구분한다. 제외 데이터의 보관·조회 책임도 정한다.

3.3 전환 방식과 순서

전체분, 변경분, 최종 변경분을 어떤 흐름으로 반영할지 정한다. 공통 코드와 부모 데이터, 자식 데이터, 이력 데이터 등 의존 순서를 나타내고 각 단계의 선행 조건과 완료 산출물을 적는다.

작업 단계는 다음 정보를 가져야 한다.

3.4 일정과 전환 창

작업 준비, 서비스 중지, 최종 추출, 적재, 기본 확인, 업무 승인, 서비스 개시의 시간을 분 단위 또는 프로젝트가 요구하는 수준으로 배치한다. 단순히 각 작업의 평균 시간을 더하지 말고 의존 관계, 병렬 가능 여부, 안전 여유, 승인 대기 시간을 반영한다.

되돌리기에는 시간이 필요하므로 “서비스 개시 시각”보다 앞에 최종 의사결정 시점을 둔다. 이 시점을 넘기면 복구 완료가 허용 중단 시간을 초과할 수 있다.

3.5 조직과 역할

역할은 사람 이름만 나열하지 않고 책임을 구분한다.

  • 총괄 책임자: 진행·중단·복구 의사결정
  • 전환 실행 담당: 추출·변환·적재 작업 수행
  • 데이터 소유자: 업무 의미와 예외 승인
  • 검증 담당: 완료 기준과 결과 확인
  • 인프라·DB 담당: 자원, 접근, 백업·복구 지원
  • 애플리케이션 담당: 업무 기능 연계 확인
  • 보안 담당: 권한, 민감정보, 작업 기록 확인
  • 상황 전달 담당: 진행 상태와 장애 공지

실행자와 승인자가 항상 달라야 한다는 보편 규칙을 만들기보다, 중요한 결과에 독립적인 확인이 필요한지 위험을 기준으로 정한다.

3.6 자원과 환경

서버, 저장 공간, 네트워크 대역, 작업 계정, 도구, 로그 공간, 임시 영역을 산정한다. 전환 데이터 자체만큼 중간 파일, 오류 격리, 백업, 로그 공간이 필요할 수 있다. 권한은 작업 전에 발급하고 작업 후 회수 또는 축소할 일정을 포함한다.

3.7 위험과 대응

위험 등록부에는 발생 가능성, 영향, 조기 신호, 예방 조치, 발생 시 대응, 책임자를 기록한다.

3.8 백업, 복구와 되돌리기

복구 계획은 “백업한다”에서 끝나지 않는다.

  • 무엇을 어느 시점에 백업하는가?
  • 백업이 실제로 복원 가능한지 확인했는가?
  • 어느 단계까지 진행했을 때 어떤 상태로 되돌리는가?
  • 전환 중 원천이나 목표에서 발생한 신규 변경을 어떻게 처리하는가?
  • 복구 소요 시간이 허용 중단 시간 안에 들어오는가?
  • 복구 실행과 서비스 재개를 누가 승인하는가?

되돌리기 절차도 모의 실행해 보아야 한다. 복구하지 못하는 백업은 계획상 안전장치가 아니다.

3.9 의사소통 계획

상태 보고 시각, 보고 대상, 채널, 메시지 형식, 장애 등급별 호출 순서를 정한다. “문제 발생 시 알림”처럼 모호하게 쓰지 말고 작업 ID, 현재 단계, 예상 지연, 영향, 다음 판단 시각을 포함하도록 한다.

05

4. 모의 전환과 계획 보정

모의 전환은 본 전환과 유사한 데이터 양, 프로그램, 인프라, 순서로 전체 흐름을 연습하는 활동이다. 단위 테스트와 달리 조직 간 인계, 승인 대기, 작업 시간, 복구까지 확인한다.

모의 전환에서 수집할 정보:

  • 단계별 시작·종료 시간과 대기 시간
  • 처리 건수와 처리 속도
  • CPU, 메모리, 저장 공간, 네트워크 사용
  • 오류 종류, 건수, 재처리 시간
  • 수작업 항목과 담당자 인계 지연
  • 계획 대비 차이와 개선 조치
  • 중단·복구 절차의 실제 소요 시간

한 번 성공했다고 충분하다고 단정하지 않는다. 데이터 양과 경계값, 변경분 반영, 실패 복구 같은 주요 위험이 재현되었는지 본다. 결과로 일정, 자원, 체크리스트, 중단 기준을 갱신한다.

06

5. 체크리스트의 역할

체크리스트는 기억에 의존하기 쉬운 준비·실행·인계 항목을 빠짐없이 확인하고, 다음 단계로 진행할 수 있는 상태인지 판단하는 통제 도구다. 계획서가 전체 설계와 책임을 설명한다면 체크리스트는 현장에서 각 조건의 충족 여부와 증거를 기록한다.

좋은 항목은 다음 조건을 만족한다.

  • 한 항목에 하나의 확인 행동만 담는다.
  • 예·아니오를 판정할 구체 기준이 있다.
  • 확인 담당자와 확인 시점이 있다.
  • 로그, 화면, 문서 번호 등 증거 위치가 있다.
  • 미충족 시 행동과 의사결정 책임자가 있다.

나쁜 예: “데이터를 잘 확인했는가?”

좋은 예: “승인된 전환 대상 목록의 버전이 계획서 기준선과 일치하며 승인 문서 번호가 기록되었는가?”

07

6. 단계별 체크리스트

6.1 실행 전

  • 대상 범위, 기준일, 제외 조건이 승인되었는가?
  • 원천·목표 매핑과 변환 규칙의 버전이 확정되었는가?
  • 전환 프로그램의 배포 버전과 실행 파일이 시험 때와 같은가?
  • 작업 계정의 최소 권한과 접속 가능 여부를 확인했는가?
  • 원천·목표·임시·로그 영역의 여유 공간이 기준을 만족하는가?
  • 백업이 완료되고 복원 가능성 확인 기록이 있는가?
  • 서비스 중지와 관련 배치 중단이 승인되었는가?
  • 작업 순서, 담당자, 연락처, 승인자가 최신 상태인가?
  • 모의 전환의 미해결 치명 결함이 없는가?
  • 시스템 시각과 기준 시점이 모든 팀에 동일하게 공유되었는가?
  • 중단 판단 시각과 복구 예상 시간이 계획에 반영되었는가?

6.2 실행 중

  • 각 작업이 선행 조건 완료 후 시작되었는가?
  • 실제 시작·종료 시각과 처리 건수가 기록되는가?
  • 실패 행과 정상 행이 계획된 방식으로 분리되는가?
  • 저장 공간과 자원 사용이 경계값 안에 있는가?
  • 예상 시간 초과 조기 신호를 담당자에게 전달했는가?
  • 재시도 전에 원인과 이전 반영 상태를 확인했는가?
  • 임의 규칙 변경이나 수작업 보정이 승인 없이 이루어지지 않았는가?
  • 단계 완료 증거가 확인된 뒤 다음 단계로 진행했는가?

6.3 실행 후

  • 모든 대상 작업이 완료 또는 승인된 예외 상태인가?
  • 작업 로그, 오류 목록, 실행 버전과 산출물이 보관되었는가?
  • 업무 담당자와 검증 담당자가 결과를 승인했는가?
  • 서비스 개시 전 핵심 업무 경로가 준비되었는가?
  • 임시 권한과 민감한 중간 파일의 후속 조치가 예정되었는가?
  • 미처리 데이터와 재처리 일정, 책임자가 인계되었는가?
  • 서비스 개시 또는 복구 결정과 시각이 기록되었는가?
  • 사후 모니터링 항목과 연락 체계가 운영팀에 인계되었는가?
08

7. 게이트와 상태 관리

체크리스트 항목은 완료, 미완료, 해당 없음, 예외 승인 같은 상태를 가질 수 있다. 해당 없음에는 이유가 필요하고, 예외 승인은 위험 수용 책임자와 보완 조치를 기록해야 한다.

주요 게이트 예시는 다음과 같다.

  1. 준비 완료 게이트: 기준선, 환경, 권한, 백업, 인력이 준비됨
  2. 추출 완료 게이트: 정해진 기준 시점과 범위의 입력이 확보됨
  3. 적재 완료 게이트: 대상 단계가 오류 기준 안에서 종료됨
  4. 업무 승인 게이트: 업무 담당자가 서비스 개시 가능 상태를 승인함
  5. 개시·복구 결정 게이트: 남은 시간과 위험을 보고 최종 방향을 결정함

게이트는 작업을 불필요하게 지연시키는 절차가 아니라, 되돌리기 어려운 다음 단계로 넘어가기 전 위험을 확인하는 지점이다.

09

8. 실전 예시: 주말 전환 일정

상황:

  • 금요일 22시에 기존 서비스가 중지된다.
  • 월요일 06시 전 새 시스템을 개시해야 한다.
  • 전체분은 모의 적재되었고, 중지 시점의 최종 변경분을 반영한다.

계획 예:

  1. 21:30 준비 완료 게이트: 담당자, 권한, 저장 공간, 백업 상태 확인
  2. 22:00 서비스·관련 배치 중지와 기준 시점 확정
  3. 22:10 최종 변경분 추출
  4. 23:00 기준정보와 부모 데이터 반영
  5. 00:30 자식·이력 데이터 반영
  6. 03:00 단계 완료 확인과 업무 점검
  7. 04:00 개시 또는 복구 최종 판단
  8. 05:30 서비스 준비와 운영 인계
  9. 06:00 서비스 개시 및 집중 모니터링

04시를 최종 판단 시점으로 둔 이유는 06시까지 복구와 기존 서비스 재개를 끝낼 시간이 필요하기 때문이다. 05시 50분에 처음 복구 여부를 논의하면 사실상 선택권이 없다. 이 시점은 모의 복구 시간과 승인 대기 시간을 근거로 산정해야 한다.

체크리스트에는 “04시 현재 치명 오류 수”, “미해결 예외 목록”, “복구 예상 완료 시각”, “업무 승인자 결정”의 증거 위치를 포함한다.

10. 시험 함정

  1. 수행 계획을 일정표와 동일시: 범위, 역할, 위험, 복구, 승인 기준까지 포함해야 한다.
  2. 평균 소요 시간만 더해 전환 창 계산: 대기, 의존성, 안전 여유와 복구 시간을 반영한다.
  3. 백업 완료를 복구 준비 완료로 착각: 복원 가능성과 소요 시간을 확인해야 한다.
  4. 본 전환 직전 규칙 변경을 즉시 반영: 영향 분석과 재시험, 승인 없이 기준선을 바꾸면 위험하다.
  5. 체크리스트 항목에 여러 행동을 묶기: 일부만 충족되어도 완료로 표시되는 문제가 생긴다.
  6. 해당 없음을 빈칸으로 두기: 판단 근거와 승인자를 기록한다.
  7. 모의 전환을 프로그램 실행 시험으로만 생각: 인계, 승인, 장애와 복구까지 전체 흐름을 연습한다.
  8. 중단 기준을 오류 발생 후 정하기: 시간과 오류 영향에 따른 기준을 사전에 정의한다.
  9. 구두 승인만으로 다음 단계 진행: 결정과 근거를 추적할 수 있게 기록한다.

12. 정답과 해설

정답 1

일정뿐 아니라 목적·성공 기준, 대상과 제외 범위, 역할과 책임, 선행 조건과 작업 순서, 자원, 위험 대응, 백업·복구, 승인과 의사소통을 정의한다.

정답 2

옮기지 않은 데이터가 누락인지 의도적 제외인지 구분하고, 보관·조회·폐기 책임이 사라지는 것을 막기 위해서다.

정답 3

복구와 기존 서비스 재개에 시간이 필요하므로 일정 시점 이후에는 되돌려도 목표 시각을 지킬 수 없다. 모의 복구 시간을 근거로 선택 가능한 마지막 시점을 정한다.

정답 4

예: 단계별 소요·대기 시간, 처리 건수와 속도, 자원 사용량, 오류와 재처리 시간, 수작업 인계 시간, 복구 소요 시간 중 네 가지다.

정답 5

하나의 확인 행동, 구체적인 판정 기준, 담당자와 확인 시점, 증거 위치, 미충족 시 행동과 승인자 중 네 가지다.

정답 6

이전 실행이 어느 단계까지 반영되었는지 확인하지 않으면 중복 적재나 부분 상태가 생길 수 있다. 원인을 파악하고 재시작 지점과 정리 절차를 적용해야 한다.

정답 7

실제로 불필요한 항목인지 임의로 건너뛴 것인지 구분하고, 이후 감사와 변경 시 판단 근거를 추적하기 위해서다.

정답 8

작업용 과도 권한과 민감 데이터 사본이 남으면 보안 위험이 커진다. 작업 종료 후 권한을 회수·축소하고 승인된 보존 기간에 따라 중간 파일을 보호하거나 폐기한다.

14

최종 요약

  • 데이터 전환 수행 계획은 목적·범위·기준 시점·작업 순서·역할·일정·자원·위험·복구·승인을 연결하는 실행 기준이다.
  • 전환 창에는 정상 작업뿐 아니라 승인 대기, 안전 여유, 복구 소요 시간을 반영한다.
  • 모의 전환으로 처리 시간, 자원, 오류, 인계와 복구를 측정하고 본 계획을 보정한다.
  • 체크리스트는 항목별 판정 기준, 담당자, 시점, 증거, 미충족 행동을 갖춰야 한다.
  • 실행 전·중·후 체크리스트와 단계별 게이트로 진행·중단·복구 결정을 통제한다.
  • 시험에서는 계획을 일정표로, 백업을 복구 가능성으로, 체크 표시를 객관적 증거로 혼동하지 않는다.
