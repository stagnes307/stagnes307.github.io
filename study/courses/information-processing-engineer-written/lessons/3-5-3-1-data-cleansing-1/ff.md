# 3-5-3-1. 데이터 정제 · 데이터 품질 분석

## 학습 범위와 목표

이 레슨은 전환 대상 데이터의 문제를 발견하고 사용 가능한 상태로 개선하는 **데이터 정제**와, 데이터가 업무 목적에 적합한지 체계적으로 파악하는 **데이터 품질 분석**을 다룬다. 오류를 임의로 고치는 것이 아니라 품질 규칙, 원천 증거, 수정 책임과 이력을 바탕으로 표준화·보완·중복 처리하는 능력이 목표다. 오류 데이터의 측정식과 정량 판정 절차는 다음 레슨에서 다루므로 여기서는 품질 특성, 분석과 정제 원리에 집중한다.

학습 후에는 다음을 할 수 있어야 한다.

- 정확성, 완전성, 유효성, 일관성, 유일성, 적시성 관점으로 품질을 분석한다.
- 데이터 프로파일링과 업무 규칙 분석을 구분하고 연결한다.
- 결측, 형식 불일치, 잘못된 코드, 중복, 참조 이상을 분류한다.
- 표준화·보완·매핑·중복 병합·격리 방법을 위험에 맞게 선택한다.
- 정제 전 원본 보존, 변경 이력, 재검증이 필요한 이유를 설명한다.

## 1. 데이터 정제의 의미

**데이터 정제**는 데이터의 오류, 불일치, 중복, 결측, 비표준 표현을 찾아 정해진 품질 규칙에 맞게 수정·보완·표준화하거나 별도로 격리하는 활동이다. 영어로 cleansing 또는 cleaning이라 부르기도 한다.

정제의 목적은 모든 값을 같은 모양으로 만드는 것이 아니다. 업무 의미를 보존하면서 목표 시스템에서 신뢰할 수 있게 사용하는 것이다. 예를 들어 전화번호의 구분 기호를 통일하는 것은 표현 표준화지만, 실제 번호 자체가 틀렸다면 형식만 맞춰도 정확성은 개선되지 않는다.

정제에는 세 가지 원칙이 필요하다.

1. **근거성**: 수정 값은 원천 문서, 권위 있는 기준정보, 승인된 규칙으로 설명할 수 있어야 한다.
2. **추적성**: 어떤 원본을 어떤 규칙으로 언제 바꾸었는지 남겨야 한다.
3. **가역성 또는 복구 가능성**: 잘못된 규칙이 발견되면 원본에서 다시 처리할 수 있어야 한다.

원본을 덮어쓰고 수정 전 값을 버리면 규칙 오류를 발견해도 복구하기 어렵다. 원본 영역과 정제 결과 영역을 구분하고 규칙 버전과 변경 사유를 기록한다.

## 2. 데이터 품질 분석의 의미

**데이터 품질 분석**은 데이터가 정의된 업무 목적과 품질 규칙을 얼마나 만족하는지 구조, 값, 관계, 사용 맥락을 조사하는 활동이다. 단순히 NULL 수를 세는 기술 분석뿐 아니라 “이 값이 업무상 사실과 맞는가”, “서로 다른 시스템에서 같은 고객을 같은 방식으로 표현하는가”를 확인한다.

품질은 절대적이지 않다. 마케팅 안내를 위한 주소와 법적 고지를 위한 주소는 요구되는 정확성과 최신성이 다를 수 있다. 따라서 사용 목적, 중요 데이터 항목, 허용 예외, 책임자를 먼저 정의해야 한다.

## 3. 데이터 품질의 주요 특성

교재나 조직에 따라 품질 특성의 명칭과 분류는 다를 수 있다. 시험에서는 각 특성이 묻는 질문을 연결해 이해한다.

### 3.1 정확성

값이 현실의 대상이나 권위 있는 원천과 올바르게 일치하는 정도다. 고객 생년월일이 날짜 형식에 맞더라도 실제 생년월일과 다르면 유효하지만 정확하지 않다. 정확성은 데이터 자체만 보고 판정하기 어려우므로 기준 문서, 다른 신뢰 원천, 업무 확인이 필요하다.

### 3.2 완전성

업무에 필요한 값이나 레코드가 빠짐없이 존재하는 정도다. 필수 열의 NULL, 필요한 고객 레코드 누락, 주소의 필수 구성 요소 누락이 예다. 모든 열을 채우는 것이 완전성은 아니다. 선택 항목을 억지 기본값으로 채우면 오히려 사실성이 떨어진다.

### 3.3 유효성

값이 정해진 형식, 자료형, 범위, 코드 목록, 패턴을 만족하는 정도다. 상태가 허용 코드 중 하나인지, 종료일이 날짜로 해석 가능한지, 수량이 허용 범위인지 본다. 유효한 값이 반드시 정확한 값은 아니다.

### 3.4 일관성

같은 사실이 여러 열, 레코드, 시스템에서 서로 모순되지 않는 정도다. 우편번호와 지역명이 맞지 않거나, 고객 마스터의 등급과 계약 화면의 등급이 다르면 일관성 문제가 된다. 단, 기준 시점이 다르면 값 차이가 정상일 수 있으므로 시간 맥락을 맞춘다.

### 3.5 유일성

하나의 실제 대상을 불필요하게 여러 레코드가 나타내지 않는 정도다. 동일 고객이 이름 표기나 전화번호 형식 차이로 중복 등록될 수 있다. 기본키가 서로 다르다는 사실만으로 실제 대상이 다르다고 단정할 수 없다.

### 3.6 적시성

업무가 필요로 하는 시점에 최신 상태의 데이터를 사용할 수 있는 정도다. 어제 주소가 사실이었더라도 오늘 변경된 주소를 즉시 반영해야 하는 업무에서는 적시성이 부족할 수 있다. 갱신 주기와 허용 지연은 업무 목적에 따라 정한다.

## 4. 데이터 프로파일링

데이터 프로파일링은 실제 데이터의 구조와 분포를 조사해 품질 규칙 후보와 이상을 찾는 활동이다. 규칙을 전혀 모른 채 숫자만 보는 것이 아니라, 분석 결과를 업무 정의와 대조한다.

### 4.1 열 단위 프로파일링

- 자료형과 실제 표현 형식
- NULL, 빈 문자열, 공백 값의 존재
- 최소·최대 길이와 값 범위
- 고유 값과 중복 값의 분포
- 자주 나타나는 값과 드문 값
- 날짜·전화번호·식별자의 패턴

예를 들어 고객상태 열에서 A, B, C 외에 공백과 X가 보이면 즉시 X를 오류로 확정하기보다 코드 정의서와 폐기 코드 이력을 확인한다.

### 4.2 구조 프로파일링

테이블의 키 후보, 반복 그룹, 열 사이 종속 관계를 살핀다. 고객번호가 유일할 것으로 예상했는데 중복이 있다면 식별 규칙이나 적재 방식의 문제를 조사한다. 우편번호가 정해지면 지역 코드도 하나로 결정되어야 하는 규칙이 있다면 같은 우편번호에 여러 지역 코드가 나타나는 사례를 찾는다.

### 4.3 관계 프로파일링

부모 없는 자식, 사용되지 않는 부모, 관계별 자식 수의 이상 분포를 조사한다. 외래키가 기술적으로 정의되어 있지 않은 원천 시스템에서도 업무 키를 이용해 관계 이상을 분석할 수 있다.

### 4.4 패턴과 의미의 구분

프로파일링은 “무엇이 들어 있는지”를 보여 주고 업무 규칙은 “무엇이 들어 있어야 하는지”를 말한다. 전화번호가 모두 숫자 10자리라는 분포가 보여도 그것이 올바른 규칙인지는 업무 담당자와 표준 문서로 확인해야 한다.

## 5. 품질 규칙 만들기

품질 규칙은 기계적으로 판정할 수 있도록 대상, 조건, 예외와 근거를 명확히 쓴다.

나쁜 규칙: “주소가 정확해야 한다.”

개선된 규칙의 구조:

- 대상: 활성 고객의 배송 우편번호
- 조건: 승인된 우편번호 기준정보에 존재
- 기준 시점: 배송 기준일 현재 유효
- 예외: 해외 배송 유형은 별도 국가별 형식 적용
- 실패 처리: 보류 후 고객 정보 담당자 확인
- 근거: 주소 표준 문서와 업무 규정 식별자

규칙 종류:

- 단일 열 규칙: 필수 여부, 범위, 길이, 패턴, 코드
- 열 간 규칙: 시작일과 종료일, 상태와 사유 값
- 레코드 간 규칙: 중복, 순번 연속성, 이력 기간 겹침
- 테이블 간 규칙: 부모 존재, 합계와 상세 일치
- 시간 규칙: 기준일 현재 유효성, 갱신 지연

## 6. 데이터 오류의 유형

### 6.1 결측

필요한 값이 NULL, 빈 문자열, 공백 또는 특수한 미정 코드로 없는 상태다. 필수 여부와 업무 목적에 따라 오류인지 정상 선택값인지 판단한다.

### 6.2 형식·범위 오류

날짜 형식 불일치, 허용 길이 초과, 수량 범위 이탈처럼 정의된 도메인을 벗어난 상태다. 파싱이 가능하다고 업무상 유효한 것은 아니다.

### 6.3 코드 불일치

폐기된 코드, 정의되지 않은 코드, 시스템별 다른 코드 체계 때문에 생긴다. 승인된 매핑표와 기준 시점이 필요하다.

### 6.4 불일치

같은 사실을 나타내는 값이 열이나 시스템 사이에서 다르다. 어느 원천을 우선할지 데이터 소유권과 갱신 시점을 바탕으로 결정한다.

### 6.5 중복

한 실제 대상이 여러 레코드로 존재한다. 완전 일치 중복과 일부 속성만 비슷한 유사 중복을 구분한다. 유사하다는 이유로 자동 병합하면 서로 다른 사람이나 상품을 합칠 위험이 있다.

### 6.6 관계 오류

부모가 없는 자식, 잘못된 부모에 연결된 외래키, 허용 범위를 벗어난 관계 수가 해당한다. 부모 레코드를 임의 생성해 관계를 맞추면 의미 없는 가짜 데이터가 생길 수 있다.

### 6.7 최신성 오류

업무 허용 지연을 넘어 오래된 값이 사용되는 상태다. 단순히 수정일시가 오래되었다고 모두 오류는 아니다. 변경이 드문 기준정보는 오래되어도 유효할 수 있다.

## 7. 데이터 정제 방법

### 7.1 표준화

동일 의미를 같은 표현으로 바꾼다. 앞뒤 공백 제거, 대소문자 원칙 적용, 날짜 표현 통일, 전화번호 구분 기호 통일 등이 있다. 원래 의미 있는 공백이나 대소문자를 잃지 않도록 대상 열별 규칙을 둔다.

### 7.2 코드 매핑

원천 코드를 목표 표준 코드로 바꾼다. 다대일 매핑으로 세부 의미가 합쳐질 때 손실을 승인받고, 매핑되지 않은 값은 격리한다. 코드 기준 시점과 규칙 버전을 기록한다.

### 7.3 결측값 처리

권위 있는 다른 원천에서 보완하거나 업무 담당자에게 확인할 수 있다. 업무상 정당한 기본값이 정의되어 있을 때만 기본값을 사용한다. 평균이나 최빈값 대체는 분석 목적에서는 고려될 수 있지만 식별·계약·금액 같은 운영 데이터에 무분별하게 적용하면 사실을 만들어 내는 결과가 된다.

### 7.4 오류값 수정

명백한 오타라도 근거 없이 추정하지 않는다. 원본 문서, 기준정보, 신뢰 원천과 대조하여 수정한다. 자동 수정의 신뢰도가 낮으면 수정 후보로 제시하고 사람이 승인한다.

### 7.5 중복 제거와 병합

정확히 같은 업무 키의 중복은 생성 원인을 확인한 뒤 처리한다. 유사 중복은 이름, 연락처, 주소, 생년월일 등 여러 속성을 이용해 후보를 찾을 수 있지만 최종 병합 기준과 우선 원천이 필요하다.

병합할 때 결정할 내용:

- 대표 레코드와 유지할 식별자
- 열별 우선 원천과 최신성
- 자식 데이터의 연결 변경
- 병합 전후 대응 이력
- 잘못된 병합의 복원 방법

### 7.6 제거·격리

업무상 불필요하고 승인된 데이터는 제외할 수 있다. 수정 근거가 없거나 핵심 규칙을 위반한 데이터는 무조건 버리기보다 격리하여 원인, 책임자, 재처리 상태를 관리한다.

## 8. 데이터 정제 절차

1. **업무 목적과 중요 항목 정의**: 어떤 데이터가 어떤 업무에 쓰이는지 확인한다.
2. **품질 기준선 확보**: 표준 용어, 코드, 도메인, 소유자, 기준 시점을 확정한다.
3. **프로파일링 수행**: 값 분포, 패턴, 키, 관계의 이상 후보를 찾는다.
4. **품질 규칙 확정**: 조건, 예외, 실패 처리와 근거를 승인받는다.
5. **오류 후보 분류**: 결측, 형식, 코드, 중복, 관계, 최신성 문제로 나눈다.
6. **원인 분석**: 입력 화면, 연계, 코드 변경, 중복 프로세스 등 발생 지점을 찾는다.
7. **정제 방법 선택**: 표준화, 보완, 매핑, 수정, 병합, 격리 중 위험에 맞게 정한다.
8. **원본 보존 후 적용**: 실행 ID와 규칙 버전, 변경 전후 값을 기록한다.
9. **재검증**: 수정한 규칙과 연결된 데이터가 품질 기준을 만족하는지 확인한다.
10. **예방 조치**: 입력 검증, 표준 관리, 소유권 정비로 같은 오류의 재발을 줄인다.

정제는 한 번의 일회성 청소가 아니다. 발생 원인을 고치지 않으면 다음 추출에서 같은 오류가 다시 들어온다.

## 9. 방식 선택 비교

| 문제 | 가능한 조치 | 핵심 판단 |
|---|---|---|
| 표현만 다른 전화번호 | 표준 형식으로 변환 | 국가·내선·선행 0의 의미 보존 |
| 매핑 없는 상태 코드 | 격리 후 규칙 승인 | 임의 기본값 금지 |
| 필수 주소 누락 | 신뢰 원천 보완 또는 업무 확인 | 사실을 추정해 만들지 않기 |
| 완전 동일 중복 | 원인 확인 후 제거 | 자식 참조와 이력 확인 |
| 유사 고객 중복 | 후보 탐지 후 승인 병합 | 다른 사람을 합칠 위험 |
| 부모 없는 자식 | 원천·키 매핑 조사, 격리 | 가짜 부모 자동 생성 주의 |
| 오래된 정보 | 허용 지연과 갱신 경로 확인 | 수정일시만으로 단정 금지 |

## 10. 실전 예시: 고객 마스터 정제

분석 결과:

- 휴대전화가 하이픈 포함, 미포함, 공백 등 여러 형식이다.
- 고객상태에 A, I 외에 과거 코드 S가 남아 있다.
- 같은 이름과 생년월일을 가진 레코드가 여러 건이다.
- 활성 고객 일부의 배송 우편번호가 비어 있다.

정제 흐름:

1. 휴대전화의 국가·내선 규칙을 확인하고 표현만 표준화한다.
2. S 코드의 업무 의미와 유효 기간을 코드 이력에서 확인해 승인된 목표 코드로 매핑한다.
3. 이름과 생년월일이 같다는 이유만으로 병합하지 않고 연락처, 주소, 원천 식별자와 자식 거래를 보아 중복 후보를 검토한다.
4. 빈 우편번호는 승인된 주소 기준정보로 확정할 수 있는 경우에만 보완하고 나머지는 업무 확인 대상으로 격리한다.
5. 각 변경에 규칙 ID와 원천 키, 변경 전후 값, 처리 상태를 남긴다.
6. 정제 후 코드 유효성, 필수값, 중복 후보와 자식 관계를 다시 확인한다.

이 사례에서 휴대전화 형식 통일은 유효성과 일관성을 높일 수 있지만 실제 번호의 정확성을 보장하지는 않는다. 고객 중복 병합은 유일성을 높일 수 있지만 잘못 병합하면 정확성과 관계 무결성을 훼손한다. 한 품질 특성의 개선이 다른 특성에 미치는 영향을 함께 봐야 한다.

## 11. 시험 함정

1. **데이터 정제를 무조건 삭제로 이해**: 표준화, 보완, 매핑, 병합, 격리도 정제 방법이다.
2. **형식이 맞으면 정확하다고 판단**: 유효성과 정확성은 다르다.
3. **NULL을 모두 기본값으로 채움**: 실제 값이 없는 사실을 가리고 의미를 왜곡할 수 있다.
4. **이름과 생년월일이 같으면 같은 고객으로 병합**: 중복 후보일 뿐 추가 근거와 승인 기준이 필요하다.
5. **최신 수정일시의 원천이 항상 권위 있다고 판단**: 데이터 소유권과 업무 책임을 확인한다.
6. **프로파일링 결과 자체를 업무 규칙으로 채택**: 현재 분포에는 기존 오류가 포함될 수 있다.
7. **원본을 직접 수정하고 덮어씀**: 규칙 오류 시 복구와 감사가 어렵다.
8. **오류 행을 버리면 품질이 향상된다고 생각**: 필요한 데이터의 완전성이 낮아질 수 있다.
9. **정제 후 수정 항목만 확인**: 자식 연결, 집계와 다른 품질 규칙까지 재검증한다.

## 13. 정답과 해설

### 정답 1

수정에 신뢰할 근거가 있어야 하는 근거성, 변경 전후와 규칙을 따라갈 수 있는 추적성, 규칙 오류 시 원본에서 다시 처리할 수 있는 복구 가능성이다.

### 정답 2

“2020-02-20”은 날짜 형식에 맞아 유효하지만 실제 생년월일이 2020-02-21이면 정확하지 않다. 유효성은 규칙 충족, 정확성은 현실 사실과의 일치를 본다.

### 정답 3

정확성, 완전성, 유효성, 일관성, 유일성, 적시성이다. 분류 체계의 명칭이 다르더라도 각 질문의 의미를 파악한다.

### 정답 4

프로파일링은 실제 값의 분포와 이상 후보를 보여 주고, 업무 규칙은 허용되어야 할 상태를 정의한다. 프로파일링 결과를 기준 문서와 담당자 판단에 대조해 규칙을 확정한다.

### 정답 5

실제 사실을 알 수 없는데 값을 만들어 넣으면 정확성이 떨어지고, “미정”이라는 상태가 숨겨져 후속 업무가 잘못될 수 있기 때문이다.

### 정답 6

대표 레코드와 유지 식별자, 열별 우선 원천, 자식 데이터 연결 처리, 병합 대응 이력, 복원 방법 중 네 가지다.

### 정답 7

입력·연계·업무 절차의 원인을 그대로 두면 다음 데이터에서 같은 오류가 다시 발생해 반복 정제 비용과 위험이 커지기 때문이다.

### 정답 8

하이픈과 공백을 통일하면 표현 규칙은 만족하지만 숫자 자체가 실제 고객 번호인지 확인한 것은 아니기 때문이다. 이는 유효성·일관성과 정확성의 차이다.

## 최종 요약

- **데이터 정제**는 오류·결측·중복·불일치를 근거 있는 규칙으로 표준화, 보완, 매핑, 수정, 병합 또는 격리하는 활동이다.
- **데이터 품질 분석**은 사용 목적을 기준으로 정확성, 완전성, 유효성, 일관성, 유일성, 적시성을 조사한다.
- 프로파일링은 현재 값의 분포와 이상 후보를 보여 주며, 업무 규칙은 허용되어야 할 상태를 정의한다.
- 원본을 보존하고 규칙 버전과 변경 전후를 기록해야 재처리와 감사가 가능하다.
- 정제 방법은 근거의 신뢰도와 업무 영향에 맞게 선택하고, 중복 병합과 기본값 대체는 특히 신중해야 한다.
- 정제 후에는 수정 값뿐 아니라 키, 관계, 집계와 연관 규칙까지 재검증하고 발생 원인을 개선한다.
