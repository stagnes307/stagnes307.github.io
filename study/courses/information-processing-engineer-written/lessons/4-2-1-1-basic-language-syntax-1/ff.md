# 4-2-1-1. 데이터 타입 · 변수

## 학습 목표와 범위

이 레슨은 프로그램이 값의 의미와 가능한 연산을 표현하는 **데이터 타입**, 그리고 그 값을 이름으로 저장·참조하는 **변수**를 다룬다. 학습 후에는 정수·실수·문자·논리형과 배열·구조체·열거형·참조형의 차이를 설명하고, 정적·동적 타입 검사와 명시적·암시적 변환을 구분하며, 변수의 선언·초기화·범위·수명·값 전달 방식을 코드 추적에 적용할 수 있어야 한다.

다음 레슨은 연산자의 우선순위와 계산 규칙을 상세히 다루므로 여기서는 타입과 변수를 이해하는 데 필요한 연산 결과만 언급한다. 특정 언어의 키워드와 저장 크기는 구현마다 다르므로, 문제에서 언어와 규격이 주어진 경우에만 그 규칙을 적용한다.

## 데이터 타입의 역할

데이터 타입(Data Type)은 값의 집합, 표현 방식, 허용 연산과 의미를 정하는 분류다. 같은 비트열도 정수, 문자, 주소 중 무엇으로 해석하는지에 따라 의미가 달라진다. 타입은 잘못된 연산을 막고 필요한 저장 공간과 표현 범위를 정하며 함수와 구성요소 사이의 계약을 만든다.

예를 들어 나이는 음수가 아닌 정수 범위로, 상품명은 문자열로, 결제 완료 여부는 논리값으로 표현한다. 모든 값을 문자열로 저장하면 당장은 편해 보여도 숫자 정렬, 범위 검증, 계산을 매번 변환해야 한다. 반대로 전화번호는 숫자 모양이지만 산술 대상이 아니고 선행 0이 의미 있으므로 문자열이 자연스럽다.

타입 선택 기준은 값의 의미, 범위와 정밀도, 필요한 연산, NULL 또는 값 없음 표현, 저장·전송 호환성이다.

## 기본 데이터 타입

| 분류 | 표현 대상 | 주요 주의점 |
|---|---|---|
| 정수형 | 개수, 순번, 이산적인 수 | 표현 범위와 부호, 오버플로 |
| 실수형 | 근삿값을 허용하는 연속 수 | 부동소수점 반올림과 정확 비교 |
| 고정 정밀도 수 | 금액, 정해진 소수 자릿수 | 전체 자릿수와 소수 자릿수 |
| 문자형 | 한 문자 또는 문자 코드 단위 | 문자 집합과 문자·바이트 구분 |
| 문자열형 | 여러 문자의 순서 | 길이, 인코딩, 불변성 여부 |
| 논리형 | 참과 거짓 | 언어에 따라 별도 타입 여부와 변환 규칙 차이 |
| 열거형 | 정해진 이름 값 중 하나 | 외부 저장값과 항목 추가 호환성 |

정수형은 크기에 따라 표현 범위가 다르다. 최대값에 1을 더했을 때 오류, 순환, 더 큰 타입 승격 중 무엇이 일어나는지는 언어와 실행 방식에 따라 다르다. 시험에서 비트 수와 부호 표현이 주어지면 그 범위를 계산한다.

부동소수점은 넓은 범위를 효율적으로 나타내지만 많은 십진 소수를 정확히 표현하지 못한다. 0.1을 반복 더한 결과를 정확한 십진값과 등호 비교하면 기대와 다를 수 있다. 허용 오차 비교나 업무상 정확한 십진 타입을 선택한다.

문자 수와 바이트 수는 같지 않을 수 있다. UTF 계열처럼 한 문자가 여러 바이트가 될 수 있는 인코딩에서는 버퍼 크기, 자르기, 외부 전송 길이를 구분한다. 문자 중간 바이트를 잘라 깨진 문자를 만들지 않도록 문자 단위 API를 쓴다.

## 복합·구조 데이터 타입

배열은 보통 같은 타입의 여러 값을 연속된 인덱스로 다룬다. 인덱스 시작값과 경계는 언어마다 다를 수 있다. 범위를 벗어난 접근을 실행 시 검사하는 언어도 있고 정의되지 않은 동작이나 메모리 손상이 될 수 있는 언어도 있다.

레코드·구조체·클래스 객체는 서로 다른 타입의 필드를 하나의 의미 있는 단위로 묶는다. 좌표는 x와 y, 고객은 식별자와 이름 같은 필드를 가진다. 데이터를 묶는 것과 행동까지 캡슐화하는 객체의 구체 모델은 언어 특성 레슨에서 더 자세히 다룬다.

집합, 목록, 사전 또는 맵 같은 컬렉션은 여러 값을 저장하지만 중복 허용, 순서, 키 접근, 성능 특성이 다르다. 라이브러리로 제공되는 경우가 많으며 이 레슨에서는 타입 의미만 다룬다.

포인터 또는 참조형은 다른 값이나 객체의 위치·연결을 나타낸다. 직접 주소 연산을 허용하는지, 메모리를 자동 관리하는지, NULL 참조가 가능한지는 언어마다 다르다. 값을 복사한 것과 같은 객체를 가리키는 참조를 복사한 것을 구분해야 한다.

## 값 타입과 참조 타입

값을 대입하거나 함수에 전달할 때 실제 값이 복사되는 모델과 객체에 대한 참조가 복사되는 모델이 있다.

    a가 숫자 10
    b = a
    b를 20으로 변경

값 복사라면 a는 여전히 10이다. 반면 두 변수가 같은 변경 가능한 객체를 참조하면 한 변수를 통해 객체 내부를 바꿀 때 다른 변수로 본 내용도 바뀔 수 있다. 이것을 별칭 문제라고 한다.

“참조가 값으로 전달된다”는 표현을 주의한다. 매개변수 변수 자체에는 참조값의 복사본이 들어가므로 매개변수를 다른 객체로 재대입해도 호출자의 변수가 바뀌지 않을 수 있지만, 그 참조가 가리키는 객체를 변경하면 호출자가 관찰할 수 있다. 정확한 동작은 언어의 전달 규칙을 따른다.

얕은 복사는 바깥 구조만 새로 만들고 내부 참조는 공유할 수 있다. 깊은 복사는 연결된 내부 객체도 복제하려 하지만 순환 참조, 공유 관계, 복제하면 안 되는 자원 때문에 정의가 단순하지 않다.

## 정적 타입과 동적 타입

정적 타입 방식은 변수나 표현식의 타입을 주로 실행 전에 검사한다. 많은 오류를 일찍 찾고 최적화와 도구 지원에 도움을 줄 수 있다. 타입 추론을 사용해 명시적 타입 표기를 줄여도 컴파일 시 타입이 정해지는 언어라면 정적 타입일 수 있다.

동적 타입 방식은 값이 실행 중 타입 정보를 가지며 변수 이름이 서로 다른 타입 값을 가리킬 수 있다. 유연하지만 특정 실행 경로에서만 타입 오류가 나타날 수 있어 시험과 검사 도구가 중요하다.

강한 타입과 약한 타입이라는 말은 암시적 변환과 서로 다른 타입 혼용을 얼마나 엄격히 제한하는지를 설명할 때 쓰이지만 경계와 정의가 문헌마다 다르다. 정적=강함, 동적=약함으로 단순 대응시키면 안 된다. 동적이면서 엄격한 타입 규칙을 가질 수 있다.

## 형 변환과 형 변환 오류

형 변환은 한 타입의 값을 다른 타입 표현으로 바꾸는 것이다. 컴파일러나 실행환경이 자동 적용하는 암시적 변환과 개발자가 의도를 표시하는 명시적 변환 또는 캐스트로 구분한다.

작은 범위 정수를 큰 범위 정수로 바꾸는 확대 변환은 정보 손실 가능성이 낮다. 큰 범위를 작은 범위로 바꾸거나 실수를 정수로 바꾸는 축소 변환은 범위 초과와 소수부 손실이 생길 수 있다. 문자열을 숫자로 바꿀 때 형식과 공백, 부호, 자릿수를 검증해야 한다.

서로 다른 숫자 타입의 식에서는 공통 타입으로 승격될 수 있다. 정수끼리 나눗셈이 먼저 계산된 뒤 실수 변수에 저장되면 이미 소수부가 사라질 수 있다. 어느 피연산자를 언제 변환하는지 코드의 평가 단계에 따라 판단한다.

명시적 캐스트는 개발자가 책임지고 변환한다는 표시이지 안전을 자동 보장하는 주문이 아니다. 변환 전 범위와 실제 객체 타입을 검사한다. 실패 시 예외, 오류값, 기본값 중 무엇이 되는지는 언어와 API 규칙에 따라 다르다.

## 변수의 개념

변수(Variable)는 프로그램 실행 중 값을 저장하거나 참조하기 위해 붙인 이름이다. 변수 선언은 이름과 타입, 필요하면 저장 위치와 접근 범위를 정한다. 정의는 실제 저장 공간을 마련한다는 뜻으로 구분하기도 하지만 언어 문맥에 따라 선언과 정의 용어가 다르게 쓰인다.

    정수 count = 0

이 개념적 선언에서 count는 정수 타입이고 0으로 초기화된다. 선언만 하고 초기화하지 않은 변수의 값은 언어에 따라 기본값, 사용 금지 상태, 불확정 값이 될 수 있다. 무조건 0이라고 가정하지 않는다.

상수는 한 번 정한 값을 변경하지 않게 하는 이름이다. 의미 있는 이름은 86400 같은 숫자의 뜻을 드러내고 오타와 불일치를 줄인다. 다만 참조 상수가 가리키는 객체 내부까지 불변인지, 참조만 바꿀 수 없는지는 언어 규칙을 확인한다.

## 변수 이름과 가독성

식별자는 언어가 허용하는 문자와 규칙을 따라야 하며 예약어를 일반 이름으로 쓸 수 없는 경우가 많다. 대소문자를 구분하는지도 언어마다 다르다.

이름은 변수의 역할과 단위를 드러내야 한다. elapsedSeconds는 단위를 보여 주지만 temp1은 장기간 유지되는 코드에서 의미가 약하다. 논리 변수는 isValid처럼 참일 때의 의미가 분명한 이름이 좋다. 같은 개념을 서로 다른 약어로 혼용하지 않는다.

변수의 범위를 좁게 두면 같은 이름이 영향을 미치는 코드를 찾기 쉽고 잘못된 재사용을 줄인다. 루프 카운터처럼 짧은 범위에서는 짧은 이름도 명확할 수 있으나 범위가 넓을수록 구체적인 이름이 필요하다.

## 범위와 가시성

범위(Scope)는 소스 코드에서 이름을 참조할 수 있는 영역이다. 블록 범위, 함수 또는 메서드 범위, 모듈 범위, 전역 범위 등이 있다.

안쪽 블록에서 바깥과 같은 이름을 선언하면 바깥 변수를 가리는 섀도잉이 발생할 수 있다. 다음 의사 코드를 보자.

    count = 10
    if 조건:
        count = 0이라는 새 지역 선언
        count를 1 증가
    블록 밖의 count 출력

안쪽이 새 지역 변수 선언이라면 바깥 count는 10으로 남는다. 단순 대입이라면 바깥 변수가 바뀔 수 있다. 선언 문법과 범위 규칙을 구분해야 한다.

전역 변수는 여러 함수에서 접근하기 쉽지만 변경 주체와 순서를 추적하기 어렵고 동시 실행에서 경쟁을 만들 수 있다. 필요한 값을 매개변수로 전달하고 상태를 책임 객체에 캡슐화하면 의존성이 드러난다.

## 수명과 저장 기간

수명(Lifetime)은 실행 중 변수가 가리키는 저장 공간이나 객체가 존재하는 기간이다. 범위는 이름의 소스상 가시성이고 수명은 실행 시간의 존재이므로 같은 개념이 아니다.

함수 지역 변수는 호출 동안 존재하는 경우가 일반적이다. 정적 저장 기간 변수는 함수 호출이 끝나도 값을 유지할 수 있고, 동적으로 생성한 객체는 참조나 명시적 해제 정책에 따라 더 오래 존재할 수 있다.

지역 변수의 주소나 참조를 함수 밖으로 반환할 때 그 저장 공간이 이미 사라지는 언어라면 댕글링 참조가 된다. 자동 메모리 관리 언어는 도달 가능한 객체의 수명을 연장할 수 있지만, 불필요한 참조를 오래 유지하면 메모리가 회수되지 않는다.

범위가 끝났다고 외부 파일·네트워크 연결이 즉시 안전하게 닫힌다고 가정하지 않는다. 자원은 언어가 제공하는 명시적 정리 또는 범위 기반 관리 구문을 사용한다. 데이터 입출력 상세는 라이브러리 레슨에서 다룬다.

## 초기화와 상태 불변식

변수는 사용 전에 의미 있는 값으로 초기화한다. 기본값 0이나 빈 문자열이 업무상 “미입력”과 같은지 검토한다. 초기화 지점과 사용 지점을 가깝게 두면 잘못된 중간 상태가 줄어든다.

객체는 생성이 끝났을 때 핵심 불변식을 만족하도록 설계한다. 예를 들어 기간은 시작일이 종료일보다 늦지 않아야 한다. 필드를 하나씩 외부에서 설정하게 하면 설정 도중 불완전한 상태가 노출될 수 있다.

변경 가능한 변수가 많으면 실행 흐름을 추적하기 어렵다. 다시 대입할 필요가 없는 값은 상수나 불변 값으로 표현한다. 하지만 무조건 모든 값을 복사하는 불변 설계가 자원 사용에 유리한지는 자료 구조와 언어 구현을 함께 본다.

## 예시: 타입과 범위 추적

다음 의사 코드를 생각하자.

    정수 total = 5
    함수 add(정수 total):
        total = total + 3
        반환 total
    정수 result = add(total)

매개변수가 값으로 전달되는 일반적인 정수라면 함수 안 total은 별도 지역 변수다. result는 8이고 바깥 total은 5다. 같은 이름이지만 범위가 다르다.

다음은 정수 나눗셈 함정이다.

    정수 a = 5
    정수 b = 2
    실수 average = a / b

나눗셈이 정수 타입에서 먼저 수행되면 결과 2가 실수 2.0으로 바뀔 수 있다. 2.5가 필요하면 계산 전에 적어도 한 피연산자를 적절한 실수 타입으로 변환해야 한다. 구체 규칙은 제시된 언어를 따른다.

## 안전한 타입·변수 사용 절차

1. 값의 업무 의미와 허용 범위를 정의한다.
2. 필요한 정밀도와 연산에 맞는 타입을 선택한다.
3. 변수 범위를 가장 좁은 필요한 영역으로 둔다.
4. 선언 시점 또는 첫 사용 전에 명확히 초기화한다.
5. 암시적 변환의 손실과 오버플로를 확인한다.
6. 참조 공유와 객체 변경 가능성을 문서화한다.
7. 경계값, NULL, 잘못된 변환, 최대·최소 범위를 시험한다.
8. 이름에 역할과 단위를 나타내고 불필요한 전역 상태를 줄인다.

시험에서 코드를 추적할 때는 각 이름 옆에 타입, 현재 값, 범위를 표로 적는다. 블록 진입·종료, 함수 호출, 형 변환 지점마다 갱신하면 같은 이름의 다른 변수를 혼동하지 않는다.

## 시험 함정

- 데이터 타입은 저장 크기만이 아니라 허용 값과 연산 의미를 정한다.
- 전화번호처럼 숫자 모양인 모든 값을 숫자 타입으로 저장하지 않는다.
- 부동소수점은 많은 십진 소수를 정확히 표현하지 못한다.
- 문자 수와 UTF-8 같은 인코딩의 바이트 수는 같지 않을 수 있다.
- 정적 타입과 강한 타입, 동적 타입과 약한 타입을 일대일로 대응시키지 않는다.
- 타입 추론을 쓰면 동적 타입이 된다는 설명은 틀릴 수 있다.
- 명시적 캐스트는 정보 손실과 실패를 자동 방지하지 않는다.
- 선언만 한 지역 변수가 언제나 0으로 초기화된다고 가정하지 않는다.
- 범위는 이름을 볼 수 있는 소스 영역, 수명은 값이나 저장 공간이 존재하는 실행 기간이다.
- 같은 이름의 안쪽 변수가 바깥 변수를 가릴 수 있다.
- 참조를 복사한 것과 객체 전체를 복사한 것을 구분한다.
- 상수 참조가 가리키는 객체까지 항상 불변인지는 언어 규칙을 확인한다.

## 확인 문제

1. 데이터 타입이 정하는 세 가지 요소를 쓰라.
2. 정수형, 부동소수점형, 고정 정밀도형의 적합한 사용 사례와 주의점을 비교하라.
3. 정적 타입과 동적 타입의 검사 시점 차이를 설명하라.
4. 확대 변환과 축소 변환의 위험을 비교하라.
5. 값 타입 대입과 참조 타입 대입 후 한 변수를 통해 변경했을 때 차이를 설명하라.
6. 변수의 범위와 수명의 차이를 예로 들어 설명하라.
7. 섀도잉이 코드 추적을 어렵게 하는 이유는 무엇인가?
8. 정수 5와 2를 나눈 값을 실수 변수에 저장해도 2.5가 되지 않을 수 있는 이유는 무엇인가?

## 정답과 해설

1. 가질 수 있는 값의 집합, 내부 표현과 범위, 허용 연산 및 그 의미를 정한다.
2. 정수는 개수처럼 이산값에 적합하지만 범위 초과를 주의한다. 부동소수점은 넓은 근삿값 계산에 적합하지만 십진 정확 비교에 주의한다. 고정 정밀도는 금액처럼 정해진 소수 자릿수에 적합하며 전체·소수 자릿수를 설계한다.
3. 정적 타입은 주로 실행 전에 표현식과 변수 타입을 검사하고, 동적 타입은 실행 중 값의 타입을 확인한다. 타입 추론 여부와는 별도다.
4. 확대 변환은 보통 표현 범위가 넓어 손실 가능성이 낮다. 축소 변환은 범위 초과, 소수부 손실, 잘림이 생길 수 있어 명시적 검사와 변환이 필요하다.
5. 값 대입은 별도 값이 복사되어 한쪽 변경이 다른 쪽에 영향을 주지 않는 경향이 있다. 참조 대입은 같은 변경 가능 객체를 가리킬 수 있어 객체 내부 변경이 양쪽에서 보인다.
6. 블록 지역 이름은 블록 밖에서 보이지 않는다는 것이 범위다. 동적으로 만든 객체는 그 이름의 블록이 끝나도 다른 참조가 있으면 살아 있을 수 있다는 것이 수명이다.
7. 같은 철자의 이름이 범위마다 다른 저장 위치를 가리켜 대입이 어느 변수에 적용되는지 착각하기 쉽기 때문이다.
8. 두 피연산자가 정수이면 나눗셈이 정수 규칙으로 먼저 계산되어 소수부를 잃은 뒤 실수로 변환될 수 있기 때문이다.

## 최종 요약

- **데이터 타입**은 값의 범위·표현·허용 연산을 정하며 업무 의미와 정밀도에 맞게 선택한다.
- 정수 오버플로, 부동소수점 오차, 문자와 바이트 길이, 축소 변환의 손실을 경계한다.
- 정적·동적 타입과 강함·약함은 서로 다른 분류 축이며 언어별 규칙을 확인한다.
- **변수**는 값이나 참조에 붙인 이름이며 선언·초기화·범위·수명·변경 가능성을 함께 판단한다.
- 값 복사와 참조 공유, 얕은 복사와 깊은 복사, 범위와 수명을 구분해야 코드 결과를 정확히 추적할 수 있다.
- 변수 범위를 좁히고 의미·단위를 드러내는 이름과 명확한 초기화, 경계값 시험으로 오류를 줄인다.
