# 4-3-2-1. 인터넷 구성의 개념 · 네트워크 7 계층

> **출제 범위 기준**: 이 레슨은 정보처리기사 필기 `프로그래밍 언어 활용 > 응용 SW 기초 기술 활용 > 네트워크 기초 활용`의 **인터넷 구성의 개념**, **네트워크 7 계층**을 다룬다. 다음 레슨의 IP 주소 체계와 TCP/UDP 세부 동작은 여기서 역할만 연결하고 계산·헤더·전송 특성은 넘긴다. 제품 설정법보다 인터넷을 구성하는 요소, 패킷 전달, 계층화와 OSI 7계층의 책임 경계를 학습한다.

인터넷은 하나의 거대한 중앙 네트워크가 아니라 서로 다른 조직의 네트워크들이 공통 프로토콜과 라우팅으로 연결된 **네트워크의 네트워크**다. 통신 문제를 이해하려면 종단 시스템에서 응용 데이터가 계층별 제어정보를 덧붙여 링크로 전달되고, 중간 장비가 자기 계층의 정보를 보고 다음 경로로 넘기는 과정을 그릴 수 있어야 한다.

## 1. 인터넷을 보는 두 관점

### 1.1 구성요소 관점

인터넷은 다음 요소의 결합으로 볼 수 있다.

- **종단 시스템(end system, host)**: PC, 서버, 스마트폰, 센서처럼 응용 프로그램을 실행하고 데이터를 보내거나 받는 장치
- **통신 링크**: 유선·광·무선 등 비트를 전달하는 매체와 링크 기술
- **패킷 교환 장비**: 스위치·라우터처럼 수신한 데이터 단위를 적절한 다음 링크로 전달하는 장비
- **접속 네트워크(access network)**: 종단 시스템을 첫 라우터나 서비스 제공자에 연결하는 구간
- **ISP(Internet Service Provider)**: 접속·전송·상호 연결 서비스를 제공하는 조직과 네트워크
- **프로토콜**: 메시지 형식, 순서, 의미, 송수신 시 행동을 정한 규칙
- **이름·주소·경로 체계**: 대상을 식별하고 위치를 나타내며 전달 경로를 선택하도록 지원

서버 한 대나 와이파이 공유기 하나가 인터넷 전체를 구성하는 것은 아니다. 서로 독립적으로 운영되는 네트워크가 계층적·수평적 상호 연결과 공통 표준을 통해 종단 간 통신을 제공한다.

### 1.2 서비스 관점

응용 프로그램 입장에서는 인터넷이 프로세스 사이에 데이터를 전달하는 통신 기반을 제공한다. 웹, 전자우편, 파일 전송, 음성·영상, 게임, 원격 제어는 요구 특성이 다르다.

| 응용 요구 | 중요한 특성 예 |
|---|---|
| 파일 전송 | 내용의 정확성과 완전성 |
| 실시간 음성 | 낮은 지연과 지연 변동, 일부 손실 허용 가능 |
| 온라인 거래 | 정확성, 인증, 무결성, 중복 처리 방지 |
| 동영상 스트리밍 | 지속 처리량, 버퍼링, 적응형 품질 |
| 원격 제어 | 짧고 예측 가능한 왕복 지연, 보안 |

네트워크가 모든 요구를 자동으로 보장하는 것은 아니다. 응용·전송·네트워크·링크 계층이 각자 제공하는 기능과 한계를 조합해야 한다.

## 2. 인터넷의 가장자리와 중심부

### 2.1 네트워크 가장자리

**네트워크 가장자리(edge)**에는 사용자 단말, 서버, 데이터센터, IoT 장치 같은 종단 시스템이 있다. 실제 응용 메시지는 보통 여기서 생성·소비된다.

대표 응용 구조는 다음과 같다.

- **클라이언트–서버**: 상시 또는 장시간 동작하는 서버가 여러 클라이언트 요청에 서비스를 제공한다. 관리와 데이터 일관성을 집중하기 쉽지만 서버 용량·가용성 설계가 필요하다.
- **P2P(peer-to-peer)**: 참여 노드가 서비스를 요청하면서 동시에 제공할 수 있다. 자원 확장이 가능하지만 노드 출입, 검색, 신뢰, 보안과 일관성 관리가 복잡하다.
- **혼합형**: 중앙 서버가 인증·검색을 맡고 실제 데이터는 피어끼리 전달하는 등 두 방식을 결합한다.

클라이언트와 서버는 장치의 영구 신분이 아니라 특정 통신에서 요청을 시작하고 서비스를 제공하는 역할로 이해한다.

### 2.2 접속 네트워크

종단 시스템이 인터넷의 첫 라우터에 이르는 구간이다.

- 가정·소규모 사무실의 유선 이더넷, 무선 LAN, 광·케이블·전화선 기반 가입자망
- 기업·학교의 계층형 LAN과 전용 회선
- 이동통신 기지국을 통한 무선 접속
- 데이터센터 내부의 고속 스위치 구조

표시된 링크 속도가 곧 응용 처리량은 아니다. 여러 사용자의 공유, 무선 간섭, 프로토콜 오버헤드, 혼잡, 서버 처리능력과 종단 장치 성능이 실제 결과에 영향을 준다.

### 2.3 네트워크 중심부

**코어(core)**는 다수의 라우터와 고속 링크가 패킷을 여러 네트워크 사이로 전달하는 부분이다. 라우터는 목적지 정보와 전달표를 이용해 들어온 패킷을 적절한 출력 링크로 넘긴다.

```text
호스트 A
  → 접속 스위치/무선 장치
  → 접속 라우터
  → 여러 ISP·코어 라우터
  → 목적지 접속 라우터
  → 호스트 B
```

한 통신의 왕복 경로가 항상 같거나, 모든 패킷이 같은 물리 경로를 지나거나, 최단 거리만 선택된다고 단정하지 않는다. 정책, 장애, 혼잡, 라우팅 정보에 따라 경로가 달라질 수 있다.

## 3. 패킷 교환과 회선 교환

### 3.1 패킷 교환

메시지를 비교적 작은 **패킷(packet)**으로 나누어 링크를 공유한다. 각 패킷은 목적지까지 여러 장비를 거치며 저장 후 전달될 수 있다.

- **통계적 다중화**: 사용자가 실제로 보낼 데이터가 있을 때 링크 용량을 사용하므로 버스트형 데이터에 효율적이다.
- **저장 후 전달(store-and-forward)**: 장비가 패킷을 받은 뒤 다음 링크로 전송한다. 구현에 따라 일부를 받으며 처리를 시작할 수도 있지만 기본 계산에서는 패킷 전송 시간이 각 링크에 누적될 수 있다.
- **큐잉**: 출력 링크가 바쁘면 버퍼에서 기다린다.
- **손실**: 버퍼가 가득 차거나 오류가 발생하면 패킷이 버려질 수 있다.

패킷 교환은 링크를 효율적으로 공유하지만 모든 패킷의 지연·대역폭을 사전에 고정 보장하지는 않는다.

### 3.2 회선 교환

통신 전에 종단 사이 자원을 예약해 전용 논리 회선을 마련한다. 주파수 분할이나 시간 분할로 링크 자원을 나눌 수 있다. 일정 자원이 확보되어 예측 가능성이 높지만, 사용자가 데이터를 보내지 않는 동안에도 예약 자원이 놀 수 있다.

| 구분 | 패킷 교환 | 회선 교환 |
|---|---|---|
| 자원 | 필요할 때 통계적으로 공유 | 연결 전에 일정 자원 예약 |
| 효율 | 버스트 데이터에 유리 | 지속적·예측 가능한 흐름에 유리 |
| 지연 | 큐 상태에 따라 변동 | 설정 뒤 비교적 예측 가능 |
| 혼잡 | 큐잉·손실 가능 | 새 회선 설정이 거부될 수 있음 |

인터넷의 데이터 전달은 주로 패킷 교환을 사용한다. 그렇다고 품질 보장 기술이나 예약 개념이 전혀 없다는 뜻은 아니다. 기본 전달 방식과 부가 제어를 구분한다.

## 4. 지연, 손실, 처리량

### 4.1 노드 지연의 구성

한 장비에서 발생하는 지연은 개념적으로 다음을 포함한다.

```text
노드 지연 = 처리 지연 + 큐잉 지연 + 전송 지연 + 전파 지연
```

- **처리 지연**: 헤더 검사, 오류 확인, 출력 경로 결정 시간
- **큐잉 지연**: 출력 링크를 기다리는 시간. 트래픽에 따라 크게 변한다.
- **전송 지연**: 패킷의 모든 비트를 링크에 밀어 넣는 시간. `패킷 길이 L(bit) / 링크 전송률 R(bit/s)`
- **전파 지연**: 신호가 매체를 이동하는 시간. `거리 d / 전파 속도 s`

길이 12,000bit 패킷을 6Mbit/s 링크에 싣는 전송 지연은 `12000 / 6,000,000 = 0.002초 = 2ms`다. 거리가 늘면 전파 지연이 늘지만 전송 지연은 패킷 길이와 링크 속도에 좌우된다. 두 용어를 혼동하지 않는다.

### 4.2 대역폭과 처리량

**대역폭**은 문맥에 따라 주파수 폭 또는 링크의 명목 데이터 전송 능력을 뜻한다. **처리량(throughput)**은 실제 단위 시간당 성공적으로 전달한 데이터 양이다. 종단 경로에 100, 20, 50Mbit/s 링크가 직렬로 있고 다른 병목이 없다면 장기 처리량은 가장 좁은 20Mbit/s 링크를 넘기 어렵다.

실제 응용 유효 처리량은 헤더, 재전송, 공유 트래픽과 응용 처리 비용을 제외하므로 링크 표기 속도보다 낮을 수 있다.

### 4.3 지연 변동과 손실

패킷마다 큐 대기 시간이 달라 도착 간격이 흔들리는 현상을 **지터(jitter, 지연 변동)**라고 한다. 음성·영상은 재생 버퍼로 일부 흡수할 수 있지만 버퍼를 키우면 시작·상호작용 지연이 늘어난다.

손실은 링크 오류뿐 아니라 혼잡으로 버퍼가 가득 차도 발생한다. 상위 계층이나 응용이 재전송할 수 있지만 재전송은 지연과 부하를 추가한다.

## 5. 네트워크 범위와 토폴로지

### 5.1 범위에 따른 표현

- **PAN**: 개인 주변의 짧은 거리 장치 연결
- **LAN**: 가정·사무실·캠퍼스 같은 제한된 지역의 네트워크
- **MAN**: 도시 규모를 연결하는 네트워크라는 전통적 분류
- **WAN**: 지역·국가·대륙에 걸쳐 여러 LAN과 사이트를 연결

거리만으로 절대 구분하기보다 운영 주체, 기술, 연결 목적을 함께 본다. 인터넷은 여러 LAN·WAN·사업자망의 상호 연결이다.

### 5.2 물리·논리 토폴로지

| 형태 | 구조 | 특징 |
|---|---|---|
| 버스형 | 하나의 공통 선로에 장치 연결 | 배선이 단순할 수 있으나 공통 구간 장애·충돌 영향 |
| 스타형 | 중앙 장비에 개별 연결 | 관리·확장 용이, 중앙 장비가 중요 장애점 |
| 링형 | 장치를 고리 형태로 연결 | 순차 전달 구조 가능, 우회·이중화 없으면 단절 영향 |
| 메시형 | 여러 장치 사이에 다수 경로 | 복원력 높일 수 있으나 링크·관리 비용 증가 |
| 트리형 | 계층적으로 여러 스타를 연결 | 확장·구역화 용이, 상위 구간 용량·장애 영향 |

**물리 토폴로지**는 실제 케이블·무선 연결 모습이고, **논리 토폴로지**는 데이터가 흐르는 방식이다. 물리적으로 스타형 배선이어도 논리 전달 방식은 기술에 따라 다를 수 있다.

## 6. 네트워크 장비의 역할

장비는 주로 어느 계층 정보를 보고 전달하는지로 이해한다. 실제 제품은 여러 계층 기능을 한 장치에 결합할 수 있다.

| 장비 | 주 역할 | 주로 보는 정보 |
|---|---|---|
| 리피터 | 약해진 신호를 재생·정형해 물리 거리 연장 | 비트·신호 |
| 허브 | 들어온 신호를 여러 포트로 반복 전달 | 비트·신호 |
| 브리지 | LAN 구간을 연결하고 프레임 주소로 필터링 | 데이터 링크 주소 |
| L2 스위치 | 주소 학습표로 프레임을 필요한 포트에 전달 | 데이터 링크 주소 |
| 라우터 | 서로 다른 네트워크 사이에서 패킷의 다음 경로 선택 | 네트워크 계층 주소·라우팅표 |
| 게이트웨이 | 서로 다른 프로토콜·응용 체계를 변환·중계하는 넓은 개념 | 구현에 따라 여러 계층 |
| 무선 AP | 무선 단말을 유선 LAN 등에 연결·중계 | 주로 링크 계층 기능 |

허브와 스위치를 “포트 수가 다른 같은 장비”로 보면 안 된다. 허브는 신호를 반복해 공유 충돌 영역을 만들 수 있고, 스위치는 학습한 주소로 프레임 전달 범위를 줄인다. 라우터는 네트워크 사이 경계를 만들고 브로드캐스트 전달·경로 선택 정책을 수행한다.

**L3 스위치**, 방화벽, 로드밸런서처럼 명칭과 실제 처리 계층이 혼합된 장비가 있으므로 이름보다 기능·검사 정보·배치 위치를 확인한다.

## 7. 프로토콜과 표준화

**프로토콜(protocol)**은 통신 개체 사이 메시지의 형식·순서·의미와 송수신 때 수행할 동작을 정의한다.

- **구문(syntax)**: 필드 배치, 데이터 형식, 부호화
- **의미(semantics)**: 각 필드와 메시지가 뜻하는 것, 오류 처리
- **타이밍(timing)**: 언제 보내고 어떤 순서·속도로 처리할지

같은 케이블을 사용한다고 통신이 되는 것이 아니다. 양쪽이 계층별 프로토콜, 주소, 보안과 응용 데이터 형식을 호환해야 한다.

표준화는 다른 제조사·조직의 시스템이 상호 운용되게 한다. 국제 표준 기구와 산업·인터넷 표준화 조직이 모델·프로토콜·매체 규격을 만든다. OSI는 ISO의 참조 모델이고, 실제 인터넷은 TCP/IP 계열 프로토콜 묶음을 중심으로 운영된다. “OSI 7계층 프로토콜로 인터넷 전체가 그대로 구현됐다”는 표현은 부정확하다.

---

## 8. 계층화의 원리

### 8.1 왜 계층으로 나누는가

- 복잡한 통신 기능을 역할별로 분리해 설계·학습·시험하기 쉽다.
- 각 계층은 아래 계층의 구체 구현을 감추고 위 계층에 서비스를 제공한다.
- 표준 인터페이스를 지키면 한 계층 기술을 다른 계층 전체를 바꾸지 않고 교체할 수 있다.
- 장애를 계층별로 좁혀 진단할 수 있다.

계층화에는 헤더와 처리 비용, 계층 사이 중복 기능, 최적화 제한이 따른다. 실제 구현은 성능을 위해 인접 계층 정보를 함께 보기도 하지만, 책임 경계 모델은 여전히 분석에 유용하다.

### 8.2 서비스, 인터페이스, 프로토콜

- **서비스**: 한 계층이 바로 위 계층에 제공하는 기능
- **인터페이스**: 위 계층이 아래 계층 서비스를 사용하는 접점과 규칙
- **프로토콜**: 같은 계층의 원격 동등 개체끼리 논리적으로 통신하는 규칙

송신 호스트의 전송 계층은 수신 호스트의 전송 계층과 프로토콜 관점에서 대응하지만, 실제 비트는 아래 계층을 거쳐 물리 네트워크로 이동한다.

### 8.3 캡슐화와 역캡슐화

송신 측에서 상위 계층 데이터에 각 계층 제어정보를 붙이는 과정을 **캡슐화(encapsulation)**라고 한다. 수신 측은 헤더를 검사·제거하며 위 계층으로 전달하는 **역캡슐화(decapsulation)**를 수행한다.

```text
응용 데이터
  → [전송 헤더 | 데이터]                 세그먼트/데이터그램
  → [네트워크 헤더 | 전송 단위]          패킷
  → [링크 헤더 | 패킷 | 링크 트레일러]   프레임
  → 비트/신호
```

PDU(Protocol Data Unit) 명칭은 교재와 프로토콜에 따라 조금 다를 수 있다. 일반적으로 4계층은 세그먼트(TCP) 또는 데이터그램(UDP), 3계층은 패킷, 2계층은 프레임, 1계층은 비트라고 구분한다.

중간 L2 스위치는 주로 프레임 헤더를 보고 전달하고, 라우터는 수신 링크 프레임을 벗겨 네트워크 계층 패킷을 검사한 뒤 다음 링크용 새 프레임으로 캡슐화한다. 종단 간 응용 데이터 전체를 모든 중간 장비가 같은 방식으로 해석하지 않는다.

## 9. OSI 네트워크 7 계층

OSI(Open Systems Interconnection) 참조 모델은 통신 기능을 일곱 계층으로 나눈다. 아래에서 위로 `물리–데이터 링크–네트워크–전송–세션–표현–응용` 순서다.

| 계층 | 이름 | 핵심 책임 | 대표 단위·키워드 |
|---:|---|---|---|
| 7 | 응용(Application) | 사용자 응용에 네트워크 서비스 제공 | 응용 메시지, 웹·메일·이름 서비스 |
| 6 | 표현(Presentation) | 데이터 표현 변환, 인코딩, 압축, 암호화 | 형식·문자·직렬화 |
| 5 | 세션(Session) | 응용 개체 사이 대화 설정·유지·동기화 | 세션·체크포인트·대화 제어 |
| 4 | 전송(Transport) | 종단 프로세스 간 전달, 분할·재조립, 신뢰·흐름 제어 | 세그먼트/데이터그램, 포트 |
| 3 | 네트워크(Network) | 서로 다른 네트워크 사이 논리 주소와 경로 선택 | 패킷, 라우팅, 논리 주소 |
| 2 | 데이터 링크(Data Link) | 한 링크·LAN 구간의 프레임 전달, 매체 접근·오류 검출 | 프레임, MAC 주소 |
| 1 | 물리(Physical) | 비트를 전기·광·무선 신호로 전송 | 비트, 신호, 커넥터·변조 |

### 9.1 1계층: 물리 계층

비트 0과 1을 어떤 전압·빛·전파·변조로 표현할지, 케이블과 커넥터, 전송 속도, 동기 방식과 물리 연결을 다룬다. 의미 있는 주소나 프레임 경계를 판단하는 계층이 아니다.

대표 장애는 케이블 단선, 신호 감쇠, 잘못된 커넥터, 무선 간섭, 포트 링크 다운이다. 리피터와 전통적 허브가 주로 이 계층에서 동작한다.

### 9.2 2계층: 데이터 링크 계층

직접 연결된 노드 또는 같은 링크 범위에서 비트 흐름을 **프레임**으로 구성해 전달한다.

- 프레임 시작·끝 구분
- 물리적 또는 링크 계층 주소 사용
- 공유 매체 접근 제어
- 오류 검출, 일부 기술의 재전송·흐름 제어
- 스위치의 주소 학습과 포트 전달

오류 **검출**과 오류 **복구**를 구분한다. 체크 값으로 손상을 발견해도 해당 계층이 반드시 복구하는 것은 아니며, 버리거나 상위 계층 재전송에 맡길 수 있다.

### 9.3 3계층: 네트워크 계층

서로 다른 네트워크를 지나 목적지 호스트 방향으로 패킷을 전달한다.

- 논리 주소 지정
- 라우팅: 목적지까지 경로 정보를 만들거나 선택
- 포워딩: 개별 패킷을 입력 인터페이스에서 출력 인터페이스로 전달
- 네트워크 간 패킷 처리와 생존 범위 제어

라우팅과 포워딩은 관련 있지만 같다기보다 제어와 실제 전달의 관점 차이다. IP의 주소·서브넷·단편화 세부는 다음 레슨에서 다룬다.

### 9.4 4계층: 전송 계층

호스트 자체가 아니라 호스트 안의 **프로세스 간 종단 전달**을 제공한다.

- 응용 데이터 분할과 재조립
- 포트 번호를 통한 다중화·역다중화
- 프로토콜에 따른 순서, 오류 회복, 흐름·혼잡 제어
- 연결 지향 또는 비연결 서비스 선택

모든 전송 프로토콜이 신뢰성과 연결을 제공하는 것은 아니다. TCP와 UDP의 차이는 다음 레슨에서 상세히 다룬다.

### 9.5 5계층: 세션 계층

응용 개체 사이 대화를 설정·유지·종료하고, 반이중·전이중 같은 대화 제어와 긴 작업의 동기점·체크포인트를 제공하는 개념적 책임이다. 현대 인터넷 응용에서는 이 기능이 응용 라이브러리나 다른 계층에 통합되어 별도 프로토콜로 명확히 보이지 않을 수 있다.

### 9.6 6계층: 표현 계층

서로 다른 시스템이 데이터 의미를 공유할 수 있도록 표현을 변환한다.

- 문자 인코딩과 데이터 형식 변환
- 구조화 데이터 직렬화·역직렬화
- 압축·해제
- 암호화·복호화라는 전통적 분류

암호화는 항상 6계층에만 존재한다고 단정하지 않는다. 실제로 링크·네트워크·전송 위·응용 등 다양한 위치에 보안 기능이 구현된다. OSI 표는 기능을 설명하는 참조 모델이다.

### 9.7 7계층: 응용 계층

사용자 응용이 네트워크 서비스를 이용하게 하는 최상위 계층이다. 웹 문서 요청, 전자우편 교환, 이름 조회, 원격 파일 서비스 같은 응용 프로토콜이 위치한다.

응용 계층은 브라우저 화면 자체나 사용자 전체를 뜻하기보다, 응용 프로세스 사이에서 교환할 메시지와 동작 규칙을 제공하는 계층이다.

## 10. OSI와 TCP/IP 모델 대응

실제 인터넷 설명에는 흔히 4계층 또는 5계층 TCP/IP 모델을 사용한다.

| OSI 7계층 | TCP/IP 4계층 대응 | 설명 |
|---|---|---|
| 응용·표현·세션 | 응용 | 응용 프로토콜과 데이터 표현·세션 기능을 포괄 |
| 전송 | 전송 | 종단 프로세스 간 통신 |
| 네트워크 | 인터넷 | IP 기반 네트워크 간 전달 |
| 데이터 링크·물리 | 네트워크 액세스 | 로컬 링크 프레임과 물리 전송 |

5계층 설명에서는 네트워크 액세스를 링크와 물리로 나눈다. 계층 수가 다르다고 한 모델이 틀렸다는 의미가 아니다. 목적과 추상화 수준이 다르며, 시험 문제에서 어느 모델을 기준으로 묻는지 확인한다.

---

## 11. 계층 기반 장애 진단

네트워크 장애는 무조건 1계층부터만 고치라는 기계적 규칙보다, 증거를 계층별로 분류해 범위를 줄이는 방식이 중요하다.

### 사례: 이름으로 웹 접속이 안 된다

1. **물리/링크**: 링크 상태, 무선 연결, 프레임 오류와 로컬 스위치 연결을 확인한다.
2. **네트워크**: 논리 주소·기본 경로가 있는지, 목적지 방향 패킷 전달이 가능한지 본다.
3. **전송**: 대상 포트 연결이 방화벽·서비스 상태 때문에 거절되거나 시간 초과되는지 본다.
4. **응용**: 이름 해석 결과, 요청 형식, 인증, 서버 응답 코드를 본다.

숫자 주소로는 되지만 이름으로만 실패하면 물리 계층부터 전체를 교체하기보다 이름 해석과 응용 설정을 우선 의심할 근거가 된다. 반대로 링크 자체가 내려갔다면 상위 설정을 바꿔도 해결되지 않는다.

### 사례: 같은 LAN 장치는 되지만 외부 네트워크는 안 된다

로컬 링크 프레임 교환은 가능하다는 증거다. 기본 게이트웨이, 네트워크 계층 주소·경로, 경계 라우터와 정책을 확인한다. 이것만으로 응용 서버가 정상이라는 뜻은 아니다.

### 사례: 연결은 되지만 영상이 끊긴다

도달 가능성만 확인하지 말고 처리량, 손실, 왕복 지연, 지터, 무선 공유와 병목 링크를 측정한다. 응용 버퍼와 서버 용량도 함께 본다.

## 12. 자주 틀리는 포인트

1. **인터넷은 한 조직의 중앙 네트워크다?** 서로 다른 자율 네트워크들이 공통 프로토콜로 연결된 네트워크의 네트워크다.
2. **표시 링크 속도는 응용 처리량과 같다?** 공유·오버헤드·병목·손실 때문에 실제 처리량은 다를 수 있다.
3. **전송 지연은 거리에 비례한다?** 전송 지연은 패킷 길이/전송률이고, 거리에 주로 비례하는 것은 전파 지연이다.
4. **패킷 교환은 지연과 대역폭을 항상 보장한다?** 큐잉과 손실로 지연이 변할 수 있다.
5. **물리 스타형이면 논리 토폴로지도 반드시 스타형이다?** 물리 연결과 데이터 흐름은 구분한다.
6. **허브와 스위치는 같은 방식으로 프레임을 전달한다?** 허브는 신호를 반복하고 스위치는 링크 주소를 학습해 선택 전달한다.
7. **라우터는 주로 MAC 주소만 보고 네트워크 간 경로를 고른다?** 네트워크 계층 논리 주소와 라우팅 정보를 사용한다.
8. **프로토콜은 데이터 형식만 정한다?** 메시지 순서·의미·송수신 동작과 타이밍도 포함한다.
9. **OSI는 실제 인터넷의 유일한 프로토콜 묶음이다?** OSI 7계층은 참조 모델이고 인터넷은 주로 TCP/IP 계열을 사용한다.
10. **캡슐화하면 이전 헤더를 없앤다?** 송신 측은 계층별 제어정보를 덧붙이고 수신 측이 역캡슐화한다.
11. **전송 계층은 라우터 사이 한 링크만 책임진다?** 종단 호스트의 프로세스 간 전달을 담당한다.
12. **세션·표현 기능은 현대 시스템에서 사라졌다?** 기능은 존재하며 응용이나 라이브러리 등 다른 구현 경계에 통합될 수 있다.
13. **암호화는 언제나 OSI 6계층에만 있다?** 실제 보안 기능은 여러 계층에 구현될 수 있다.
14. **오류 검출은 곧 오류 복구다?** 손상을 발견해 버리는 것과 재전송·수정하는 것은 다르다.

## 13. 확인 문제

### 문제 1

인터넷을 “네트워크의 네트워크”라고 하는 이유를 운영 주체와 상호 연결 관점에서 설명하라.

### 문제 2

길이 20,000bit인 패킷을 10Mbit/s 링크에 전송할 때 전송 지연을 구하라. 거리 정보가 필요한가?

### 문제 3

패킷 교환에서 출력 링크보다 패킷 도착이 빠를 때 발생할 수 있는 두 현상을 쓰라.

### 문제 4

허브, L2 스위치, 라우터가 주로 처리하는 OSI 계층과 정보 단위를 각각 연결하라.

### 문제 5

송신 측 캡슐화 순서를 응용 데이터에서 프레임과 비트까지 설명하라.

### 문제 6

OSI 3계층과 4계층의 전달 대상을 각각 쓰고 차이를 설명하라.

### 문제 7

OSI 표현 계층의 대표 기능 세 가지와, 암호화를 반드시 이 계층에만 구현한다고 볼 수 없는 이유를 쓰라.

### 문제 8

도메인 이름으로는 접속이 실패하지만 같은 서버의 숫자 주소로는 접속된다. 계층 기반으로 우선 확인할 항목을 설명하라.

## 14. 정답과 해설

### 정답 1

가정·기업·학교·데이터센터·여러 ISP처럼 서로 다른 조직이 운영하는 네트워크들이 라우터와 상호 연결 지점에서 이어지고, 공통 인터넷 프로토콜과 라우팅으로 종단 간 패킷을 전달하기 때문이다.

### 정답 2

`20,000 / 10,000,000 = 0.002초 = 2ms`다. 전송 지연 계산에는 패킷 길이와 링크 전송률이 필요하며 거리는 필요하지 않다. 거리는 전파 지연 계산에 필요하다.

### 정답 3

패킷이 출력 큐에서 기다리는 **큐잉 지연**이 생기고, 버퍼가 가득 차면 패킷이 **손실**될 수 있다.

### 정답 4

허브는 주로 1계층에서 비트·신호를 반복한다. L2 스위치는 2계층에서 프레임과 링크 주소를 보고 전달한다. 라우터는 3계층에서 패킷의 논리 주소와 라우팅 정보를 보고 다음 경로를 선택한다.

### 정답 5

응용 데이터에 전송 계층 헤더를 붙여 세그먼트나 데이터그램을 만들고, 네트워크 계층 헤더를 붙여 패킷을 만든다. 링크 계층 헤더와 필요 시 트레일러를 붙여 프레임을 만들며 물리 계층이 이를 비트·신호로 전송한다.

### 정답 6

3계층은 서로 다른 네트워크를 거쳐 목적지 **호스트 방향**으로 패킷을 전달하고 경로를 선택한다. 4계층은 종단 호스트 안의 특정 **프로세스 사이** 통신을 제공하며 포트, 분할·재조립과 프로토콜별 신뢰·흐름 기능을 담당한다.

### 정답 7

문자·데이터 형식 변환, 압축·해제, 암호화·복호화가 대표 기능이다. OSI는 기능 참조 모델이며 실제 암호화는 링크, 네트워크, 전송 위, 응용 등 요구와 프로토콜에 따라 여러 위치에 구현된다.

### 정답 8

기본 물리·네트워크 도달 가능성이 있다는 증거이므로 이름 해석 서비스, 클라이언트 이름 설정, 잘못된 캐시·응답 주소를 우선 확인한다. 다만 이름에 따라 서버의 가상 호스트·인증서·응용 처리가 달라질 수 있어 응용 계층 설정도 확인한다.

## 15. 핵심 요약

- 인터넷은 종단 시스템, 접속망, 패킷 교환 장비, ISP, 링크와 공통 프로토콜이 결합된 네트워크의 네트워크다.
- 가장자리는 응용 데이터를 만들고 소비하며, 중심부는 라우터와 고속 링크로 패킷을 전달한다.
- 패킷 교환은 링크를 통계적으로 공유해 효율적이지만 큐잉 지연과 손실이 발생할 수 있다.
- 전송 지연은 `패킷 길이/전송률`, 전파 지연은 `거리/전파 속도`이며 처리·큐잉 지연과 구분한다.
- 허브는 주로 1계층, 스위치는 2계층, 라우터는 3계층 정보를 사용하지만 실제 장비는 여러 기능을 결합할 수 있다.
- 프로토콜은 메시지의 형식뿐 아니라 의미·순서·타이밍과 송수신 동작을 정한다.
- 송신 측은 상위 데이터에 헤더를 붙여 캡슐화하고, 수신 측은 역캡슐화한다.
- OSI 7계층은 물리–데이터 링크–네트워크–전송–세션–표현–응용 순서다.
- OSI는 참조 모델이고 TCP/IP 모델은 실제 인터넷 프로토콜 구조를 설명하는 다른 계층화다.
- 장애는 링크 상태, 논리 도달성, 종단 전송, 이름·응용 순으로 증거를 계층에 배치해 진단한다.
