# 5-2-1-1. 네트워크 구축 관리

## 출제범위와 학습 목표

이 레슨의 정확한 출제범위는 **IT 신기술 및 네트워크 장비 트렌드 정보**와 **네트워크 장비(라우터, 백본 스위치 등)**이다. 특정 제조사의 제품명이나 시시각각 바뀌는 속도 수치를 외우기보다, 네트워크 기능을 제어·전달·가상화·자동화·관측 관점으로 분류하고 라우터, 계층별 스위치, 게이트웨이와 보안 장비의 역할을 요구사항에 맞게 배치하는 능력을 기른다.

학습 후에는 다음을 할 수 있어야 한다.

- 라우터, L2·L3 스위치, 백본 스위치, 게이트웨이의 전달 기준을 구분한다.
- SDN, NFV, 가상 네트워크, 엣지, 자동화·가시성 흐름을 안정된 개념으로 설명한다.
- 가용성, 성능, 보안, 확장성, 운영성 요구를 네트워크 구조로 바꾼다.
- 단일 장애점, 루프, 주소·경로·대역폭과 관리망 위험을 점검한다.
- 설계, 구축, 시험, 인수와 운영 전환 절차를 제시한다.

## 1. 네트워크 구축 관리의 관점

네트워크 구축 관리는 장비를 구매해 케이블로 연결하는 일보다 넓다. 업무 트래픽의 출발지와 목적지, 성능·가용성 목표, 보안 경계, 확장 계획과 운영 능력을 분석하고 적합한 토폴로지·장비·경로·정책을 구현하여 검증하는 활동이다.

네트워크는 다음 세 관점으로 보면 이해하기 쉽다.

- 전달 관점: 프레임과 패킷을 어느 포트·경로로 보낼 것인가?
- 제어 관점: 주소, 경로, 정책과 상태 정보를 어떻게 결정할 것인가?
- 관리 관점: 구성, 감시, 장애 대응, 변경과 감사 기록을 어떻게 통제할 것인가?

최신 네트워크 기술도 이 세 관점의 위치와 자동화 정도가 달라지는 것으로 해석할 수 있다.

## 2. 계층과 전달 단위

시험에서는 장비 이름과 전달 기준을 연결한다.

| 계층 관점 | 전달 단위·기준 | 대표 기능 |
|---|---|---|
| 물리 계층 | 비트와 전기·광 신호 | 신호 전달, 중계 |
| 데이터 링크 계층 | 프레임, MAC 주소 | 같은 논리 구간 안의 스위칭 |
| 네트워크 계층 | 패킷, IP 주소 | 서로 다른 네트워크 사이 라우팅 |
| 전송 이상 | 포트, 세션, 응용 정보 | 부하 분산, 보안·응용 게이트웨이 등 |

실제 장비는 여러 계층 기능을 함께 가질 수 있다. 시험에서 “스위치는 항상 2계층”이라고 단정하지 않고 L2 스위치와 L3 스위치를 구분한다.

## 3. 네트워크 장비(라우터, 백본 스위치 등)

### 3.1 리피터와 허브

리피터는 약해진 신호를 재생하여 물리적 전달 거리를 늘리는 장비다. 허브는 여러 포트를 연결하고 들어온 신호를 다른 포트로 전달하는 공유 방식 장비로 이해한다. 목적지 MAC 주소를 학습하여 선택 전달하는 스위치와 다르다. 오늘날 실제 구축에서의 사용 비중보다 시험에서는 계층과 동작 차이를 묻는 경우가 많다.

### 3.2 브리지와 L2 스위치

브리지는 MAC 주소를 학습하여 프레임을 필요한 구간으로 전달하거나 걸러 낸다. L2 스위치는 이를 다수 포트에서 고속으로 수행하며 포트별 충돌 영역을 분리한다.

주요 기능:

- 출발지 MAC 주소와 유입 포트를 학습
- 목적지 MAC을 알면 해당 포트로 전달
- 목적지를 모르면 같은 브로드캐스트 영역 안에서 플러딩
- 브로드캐스트 프레임은 해당 논리 구간에 전달
- VLAN으로 하나의 물리 스위치를 여러 논리 브로드캐스트 영역으로 분리
- 여러 VLAN을 한 링크로 전달하는 트렁크 구성

스위치 간 이중 연결은 가용성을 높일 수 있지만 L2 루프가 생기면 프레임이 순환하고 브로드캐스트가 폭증할 수 있다. 루프 방지 프로토콜이나 루프 없는 논리 구조를 함께 설계한다.

### 3.3 라우터

라우터는 IP 주소와 라우팅 정보를 바탕으로 서로 다른 네트워크 사이에 패킷을 전달한다. 목적지 네트워크에 맞는 경로를 선택하고 다음 홉으로 보낸다.

라우팅 정보는 관리자가 입력한 정적 경로 또는 장비들이 경로 정보를 교환하는 동적 방식으로 구성할 수 있다.

| 구분 | 정적 경로 | 동적 경로 |
|---|---|---|
| 설정 | 관리자가 경로를 명시 | 프로토콜로 경로를 학습·계산 |
| 장점 | 단순 환경에서 예측 가능, 교환 부하 적음 | 변화·장애에 자동 적응 가능 |
| 부담 | 규모가 커지면 변경·누락 관리 어려움 | 설계·운영 복잡도와 제어 트래픽 |
| 적합 | 작은 고정 경로, 기본·예비 경로 | 다중 경로와 변화가 많은 구조 |

라우터는 브로드캐스트 영역을 분리하고 정책 기반 접근 통제, 주소 변환, 터널 기능을 함께 제공할 수도 있다. 모든 라우터가 같은 부가 기능을 갖는 것은 아니므로 요구와 사양을 확인한다.

### 3.4 L3 스위치

L3 스위치는 스위칭 장비 형태로 IP 라우팅 기능을 수행한다. 건물이나 데이터센터 내부의 VLAN 간 라우팅과 고속 집선에 사용할 수 있다. 라우터와 기능이 겹칠 수 있지만 배치 목적, 인터페이스 종류, 경로·보안·회선 기능, 처리 용량으로 선택한다.

### 3.5 백본 스위치

백본 스위치는 여러 액세스·분배 구간과 서버·외부 연결을 중심부에서 고속으로 집선하는 핵심 스위치다. “백본”은 특정 계층 프로토콜 이름보다 네트워크에서 맡는 중심 역할을 가리킨다.

중요 판단 요소:

- 다수 구간의 합산 트래픽을 처리할 용량
- 이중화 전원, 제어부, 링크와 장애 전환
- 충분한 포트·확장성과 경로 처리 능력
- VLAN·라우팅·접근 정책 지원
- 상태 감시, 구성 백업, 원격 관리와 로그
- 유지보수 중 서비스 영향과 교체 절차

백본 장비 하나의 성능만 높이고 이중 경로가 없으면 단일 장애점이 된다. 장비, 전원, 링크, 회선, 물리 경로와 구성의 장애 영역을 함께 본다.

### 3.6 게이트웨이

게이트웨이는 서로 다른 네트워크나 프로토콜, 데이터 표현 사이를 연결·변환하는 기능 또는 장비를 말한다. 기본 게이트웨이는 호스트가 자기 네트워크 밖으로 패킷을 보낼 때 사용하는 다음 홉이다. 응용 게이트웨이는 더 높은 계층에서 프로토콜을 중계·변환할 수 있다. 문맥에 따라 의미가 다르므로 지문의 계층과 기능을 확인한다.

### 3.7 보안·전달 보조 장비

- 방화벽: 주소, 포트, 연결 상태, 응용 정보 등의 정책으로 트래픽을 허용·차단
- 침입 탐지·방지: 공격 징후를 탐지하고 구성에 따라 차단
- 부하 분산 장비: 여러 서버로 요청을 분배하고 상태를 확인
- 프록시: 클라이언트나 서버를 대신해 요청을 중계하고 정책·캐시·검사를 적용
- VPN 게이트웨이: 신뢰할 수 없는 구간 위에 인증·암호화된 터널을 구성

한 장비가 여러 기능을 제공해도 논리적 책임과 장애 영향을 분리해 설계한다.

## 4. 네트워크 토폴로지와 계층 설계

### 4.1 대표 토폴로지

| 형태 | 특징 | 주의점 |
|---|---|---|
| 성형 | 중앙 장비에 노드가 연결 | 중앙 장비 장애 영향 |
| 버스형 | 공통 매체를 공유 | 충돌·장애 구간 분리 어려움 |
| 링형 | 고리 형태로 연결 | 절단 시 우회 구조 필요 |
| 망형 | 여러 경로로 상호 연결 | 가용성 높지만 비용·제어 복잡 |
| 트리형 | 계층적으로 분기 | 상위 집선 구간의 용량·이중화 |

현대 네트워크는 물리·논리 토폴로지가 다를 수 있다. 물리적으로 이중 연결되어도 경로 제어가 한 장비에 의존하면 논리적 단일 장애점이 남는다.

### 4.2 액세스·분배·코어 관점

액세스 계층은 사용자·단말·서버를 연결하고, 분배 계층은 정책과 경로를 집약하며, 코어 또는 백본은 큰 트래픽을 빠르고 안정적으로 전달하는 구조로 설명할 수 있다. 모든 규모에서 반드시 세 계층을 별도 장비로 나눌 필요는 없다. 작은 환경은 계층을 합칠 수 있으나 역할과 장애 범위를 명확히 한다.

## 5. IT 신기술 및 네트워크 장비 트렌드 정보

**IT 신기술 및 네트워크 장비 트렌드 정보**는 제품 이름보다 변화 방향을 이해해야 오래 적용할 수 있다.

### 5.1 SDN

소프트웨어 정의 네트워킹은 네트워크 제어 기능을 논리적으로 중앙화하거나 프로그램 가능한 형태로 제공하여 장비별 수동 설정을 줄이고 정책을 일관되게 적용하려는 접근이다.

- 응용·정책 계층: 원하는 연결과 보안 의도를 정의
- 제어 계층: 전체 상태를 바탕으로 경로·정책을 계산
- 전달 계층: 실제 패킷을 전달

제어가 중앙화되었다고 반드시 물리 장비 하나만 존재하는 것은 아니다. 논리적 중앙 관리와 제어 구성요소의 고가용성을 구분한다.

### 5.2 NFV

네트워크 기능 가상화는 방화벽, 라우팅, 부하 분산 같은 기능을 전용 하드웨어에만 묶지 않고 범용 컴퓨팅 기반의 소프트웨어 네트워크 기능으로 구현하는 접근이다. 빠른 배치와 확장에 유리하지만 처리 성능, 가속, 자원 격리, 장애 영역과 운영 복잡성을 평가해야 한다.

SDN은 주로 제어와 프로그램 가능성, NFV는 네트워크 기능을 소프트웨어화하는 관점이다. 함께 사용할 수 있지만 같은 개념은 아니다.

### 5.3 네트워크 가상화와 오버레이

물리망 위에 논리적인 네트워크를 구성하여 테넌트·업무별로 주소와 정책을 분리한다. 물리 연결을 바꾸지 않고 논리 구간을 빠르게 만들 수 있지만 물리 경로의 용량과 장애가 사라지는 것은 아니다. 오버레이 상태와 기반망 상태를 함께 관측해야 한다.

### 5.4 클라우드·하이브리드 연결

온프레미스, 여러 클라우드, 원격 사용자와 지점을 연결하면서 경로, 암호화, 이름 해석, 정책 일관성을 관리한다. “클라우드이면 자동으로 고가용”이라는 가정을 피하고 지역·회선·게이트웨이의 실패 영역과 비용을 확인한다.

### 5.5 엣지 네트워킹

데이터 발생 지점 가까이에서 처리하여 지연과 중앙 전송량을 줄이는 접근이다. 원격 지점의 제한된 자원, 간헐적 연결, 물리 보안, 중앙 정책과의 동기화를 고려한다.

### 5.6 자동화와 의도 기반 관리

장비별 명령을 반복 입력하는 대신 원하는 상태를 정의하고 구성 배포·검증·복구를 자동화한다. 템플릿 오류가 전체망에 확산될 수 있으므로 코드 검토, 단계 배포, 사전 검증, 되돌리기와 구성 이력을 갖춘다.

### 5.7 가시성·관측 가능성

장비의 단순 생존 여부뿐 아니라 흐름, 지연, 손실, 경로 변화, 정책 적용과 사용자 경험을 연계하여 문제 원인을 찾는다. 로그·지표·흐름 자료의 시각 동기화와 보존, 민감정보 보호가 중요하다.

### 5.8 신뢰 최소화와 세분화

위치가 내부라는 이유만으로 신뢰하지 않고 사용자·기기·서비스의 신원과 상황에 따라 최소 권한 연결을 허용한다. 네트워크 세분화는 침해 확산을 줄이지만 정책 수가 늘어날 수 있으므로 자산·흐름 파악과 자동 검증을 병행한다.

## 6. 구축 절차와 판단 기준

1. **업무·트래픽 분석**: 사용자, 서버, 외부 연계, 트래픽 방향·크기·시간대를 파악한다.
2. **품질 목표 정의**: 지연, 손실, 처리량, 가용성, 복구와 보안 목표를 정한다.
3. **주소·구간 설계**: 주소 계획, VLAN·서브넷, 라우팅 경계, 관리망을 설계한다.
4. **토폴로지·이중화 설계**: 장애 영역과 우회 경로, 전원·회선·물리 경로를 결정한다.
5. **장비 역할·용량 선정**: 액세스, 분배, 백본, 경계, 보안 기능과 확장 여유를 정한다.
6. **정책 설계**: 허용 흐름, 라우팅, 품질, 관리 접근, 시간 동기화와 로그를 정의한다.
7. **시험 환경 검증**: 경로, 성능, 장애 전환, 보안 정책과 관리 접속을 확인한다.
8. **단계 구축**: 영향이 작은 구간부터 반영하고 기준선과 되돌리기 절차를 유지한다.
9. **인수 시험**: 정상·부하·장애·복구·보안·운영 시나리오를 승인 기준과 비교한다.
10. **운영 전환**: 구성 백업, 도면, 주소·포트표, 감시·장애 대응과 책임을 인계한다.

### 주요 판단 기준

- 현재·예상 트래픽과 순간 집중을 감당하는가?
- 장비뿐 아니라 전원·링크·경로에 단일 장애점이 없는가?
- 장애 전환 시간이 업무 목표 안에 드는가?
- 업무·관리·외부 구간이 최소 권한으로 분리되는가?
- 구성과 정책을 재현·감사·되돌릴 수 있는가?
- 팀이 자동화·가상화 구조를 실제로 진단할 수 있는가?
- 확장 포트, 주소, 경로와 회선 비용이 지속 가능한가?

## 7. 구체 예시와 텍스트 도식

요구사항:

- 본사 사용자망과 서버망을 분리한다.
- 외부 회선 하나가 끊겨도 핵심 서비스는 계속되어야 한다.
- 서버 공개 구간과 내부 데이터 구간의 접근을 통제한다.
- 장비 관리는 업무 사용자망에서 직접 접근할 수 없어야 한다.

    [외부 회선 A]      [외부 회선 B]
          │                  │
       [경계 라우터/보안 구간 이중화]
                    │
          [백본 L3 스위치 이중화]
             ┌──────┼──────┐
             │      │      │
        사용자 VLAN  서버 VLAN  관리 VLAN
                       │
                공개 구간 / 내부 구간

검토:

1. 회선만 두 개이고 같은 물리 경로나 같은 전원에 의존하지 않는지 확인한다.
2. 백본 간 경로와 게이트웨이 장애 전환을 시험한다.
3. 사용자 VLAN에서 데이터 구간으로 필요한 업무 포트만 허용한다.
4. 관리 VLAN 접근은 승인된 관리자 단말과 강한 인증으로 제한한다.
5. 한 링크가 끊어졌을 때 루프나 경로 진동 없이 우회되는지 확인한다.
6. 정상과 장애 상태 모두에서 지연·손실·처리량 목표를 측정한다.

## 8. 자주 틀리는 포인트

1. **스위치는 모두 L2라고 단정**: L3 스위치는 IP 라우팅을 수행한다.
2. **라우터가 MAC 주소만 보고 네트워크 사이를 전달한다고 이해**: 핵심 기준은 목적지 IP와 라우팅 정보다.
3. **VLAN이 충돌 영역만 나눈다고 생각**: VLAN은 논리적 브로드캐스트 영역을 분리한다.
4. **이중 링크를 추가하면 가용성이 자동 향상**: L2 루프 방지와 경로 제어가 필요하다.
5. **백본 스위치를 특정 프로토콜 이름으로 암기**: 네트워크 중심에서 고속 집선하는 역할이다.
6. **SDN과 NFV를 같은 개념으로 취급**: 제어 프로그램 가능성과 기능 가상화의 초점이 다르다.
7. **논리적 중앙화를 단일 물리 제어기로 오해**: 제어부 자체의 고가용성을 설계할 수 있다.
8. **오버레이가 물리망 용량·장애를 해결한다고 생각**: 기반망 제약은 여전히 존재한다.
9. **최대 포트 속도만으로 장비 선정**: 전체 처리량, 지연, 기능 사용 시 성능, 확장과 장애 전환을 본다.
10. **자동화는 수동 오류를 없앤다고만 생각**: 잘못된 템플릿이 광범위하게 확산될 수 있어 검토·단계 배포가 필요하다.

## 10. 정답과 해설

### 정답 1

L2 스위치는 주로 MAC 주소와 포트 학습 정보를 사용하고, 라우터는 목적지 IP 네트워크와 라우팅 정보를 사용한다.

### 정답 2

합산 처리 용량, 전원·제어부·링크 이중화, 포트·확장성, 라우팅·정책 기능, 감시·구성 백업, 유지보수 영향 중 네 가지다.

### 정답 3

정적 방식은 단순한 고정 환경에서 예측 가능하고 교환 부하가 적지만 변경 관리가 수동이다. 동적 방식은 변화와 장애에 적응하지만 설계·운영 복잡도와 제어 트래픽이 있다.

### 정답 4

SDN은 제어 기능을 논리적으로 분리하고 프로그램 가능하게 만드는 데 초점이 있고, NFV는 전용 장비 기능을 범용 컴퓨팅 위의 소프트웨어 기능으로 구현하는 데 초점이 있다.

### 정답 5

두 회선이 같은 관로를 지나거나 같은 전원·백본 장비·제어부·기본 게이트웨이에 의존하는 경우다. 장애 영역을 끝까지 추적해야 한다.

### 정답 6

이점은 빠른 논리 구간 생성과 업무별 격리다. 주의점은 오버레이와 기반망을 함께 관측해야 하고 캡슐화·정책·장애 경로의 복잡성이 늘 수 있다는 점이다.

### 정답 7

구성 코드 검토, 사전 검증, 소규모 단계 배포, 상태 확인, 자동 중단·되돌리기, 구성 이력 중 세 가지다.

### 정답 8

정상 경로, 목표 부하, 링크·장비 장애 전환, 복구, 보안 정책 허용·차단, 관리망 접속, 로그·감시와 구성 복원 중 다섯 가지다.

### 정답 9

기본 게이트웨이는 호스트가 다른 IP 네트워크로 보낼 때 사용하는 다음 홉이고, 응용 게이트웨이는 상위 계층에서 요청이나 프로토콜을 중계·변환하는 기능이다.

## 핵심 요약

- **네트워크 장비(라우터, 백본 스위치 등)**는 전달 계층과 역할로 구분한다. L2 스위치는 MAC 기반, 라우터·L3 스위치는 IP 경로 기반으로 전달한다.
- 백본 스위치는 중심 집선 장비이므로 합산 용량, 확장, 정책, 전원·링크·제어부 이중화와 운영성을 함께 본다.
- SDN은 제어의 프로그램 가능성, NFV는 네트워크 기능의 소프트웨어화, 오버레이는 물리망 위 논리망 구성에 초점이 있다.
- **IT 신기술 및 네트워크 장비 트렌드 정보**는 클라우드·엣지 연결, 자동화, 관측, 세분화처럼 안정된 변화 방향으로 학습한다.
- 구축은 트래픽·품질 목표, 주소·구간, 토폴로지, 장비·정책, 시험, 인수와 운영 인계 순으로 수행한다.
- 최신·고속 장비보다 업무 경로, 단일 장애점, 보안 경계, 진단 가능성과 총 운영 비용이 적합성 판단의 핵심이다.
