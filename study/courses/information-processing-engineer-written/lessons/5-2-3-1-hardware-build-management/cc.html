01

출제범위와 학습 목표

이 레슨의 정확한 출제범위는 IT 신기술 및 서버장비 트렌드 정보와 서버장비 운영(Secure-OS, 운영체제, NAS, DAS, SAN, 고가용성 등)이다. 특정 제조사의 모델이나 변하기 쉬운 성능 숫자 대신 서버 가상화·자동화·가속·엣지·에너지 효율 같은 변화 방향을 이해하고, Secure-OS와 운영체제, 파일·블록 저장장치, 고가용성 구조를 업무 요구에 맞게 선정·운영하는 능력을 기른다.

학습 후에는 다음을 할 수 있어야 한다.

  • 서버의 CPU, 메모리, 입출력, 전원·냉각과 용량 계획 요소를 설명한다.
  • 가상화, 컨테이너, 고밀도·가속·엣지 서버 흐름의 효과와 위험을 비교한다.
  • Secure-OS의 참조 모니터, 강제적 접근통제, 감사와 신뢰 경로를 설명한다.
  • DAS, NAS, SAN을 연결 방식, 접근 단위, 공유와 운영 관점에서 구분한다.
  • 고가용성의 이중화, 장애 감지, 페일오버, 쿼럼과 데이터 일관성을 설계한다.
02

1. HW 구축 관리의 의미

HW 구축 관리는 서버와 저장장치의 사양을 결정해 설치하는 일뿐 아니라 업무 부하, 가용성, 보안, 확장, 전력·냉각, 유지보수와 운영 인계를 통합하는 활동이다. 가장 빠른 부품 하나보다 전체 경로의 병목과 장애 영역이 중요하다.

사용자 요청 │ ▼ 네트워크 ──> CPU·메모리 ──> 저장장치 │ │ │ 지연·대역폭 연산·캐시 IOPS·처리량·지연 └──────── 전원·냉각·운영체제·가상화 ────────┘

CPU가 남아도 저장장치 지연이 크면 업무는 느릴 수 있고, 서버를 이중화해도 같은 전원과 저장장치에 의존하면 단일 장애점이 남는다.

3. IT 신기술 및 서버장비 트렌드 정보

3.1 서버 가상화

하이퍼바이저가 물리 자원을 여러 가상머신에 나누어 제공한다. 통합·격리·배치에 유리하지만 호스트 장애, 자원 경합과 가상 경로를 감시해야 한다.

컨테이너는 호스트 커널을 공유하는 프로세스 격리 단위이므로 게스트 OS를 가진 가상머신과 구분한다. 두 기술을 계층적으로 함께 사용할 수도 있다.

3.2 통합·초융합 인프라

컴퓨팅, 저장, 네트워크와 관리 기능을 통합하여 증설과 운영을 단순화하려는 방향이다. 노드를 추가해 자원을 확장하기 쉽지만, 구성요소를 독립적으로 증설하기 어려울 수 있고 관리 계층 장애나 공급 종속을 평가해야 한다.

3.3 구성 가능·분리형 자원

CPU, 메모리, 가속기, 저장 자원을 논리적으로 조합하는 방향이다. 활용률을 높일 수 있지만 연결 지연, 호환성과 관리 제어부 장애를 평가한다.

3.4 이기종 가속

그래픽·행렬·암호·네트워크·저장 처리에 특화된 가속기를 사용하여 특정 작업의 처리량과 에너지 효율을 높인다. 모든 코드가 자동으로 빨라지는 것은 아니다. 작업의 병렬성, 데이터 이동 비용, 개발 도구, 정밀도 요구, 가속기 미사용 시 대체 경로와 공급 지속성을 본다.

3.5 엣지 서버

데이터 발생 지점 가까이에서 처리하여 지연과 중앙 전송량을 줄인다. 공장·지점·현장처럼 물리 환경이 열악하거나 관리자가 상주하지 않을 수 있으므로 원격 관리, 오프라인 동작, 물리 보안, 제한 전력과 중앙 동기화를 고려한다.

3.6 선언적·자동화된 서버 운영

펌웨어·OS·구성을 코드와 정책으로 관리해 반복성을 높인다. 잘못된 기준이 확산되지 않도록 이미지 무결성, 단계 배포, 상태 검증과 복구가 필요하다.

3.7 관측과 예측 유지보수

온도, 전원, 팬, 메모리·디스크 상태로 이상을 조기에 찾는다. 예측은 이중화·백업을 대신하지 않으며 관리 인터페이스는 분리·보호한다.

3.8 에너지 효율과 지속 가능성

처리량당 전력, 유휴 자원, 냉각, 장비 수명을 본다. 저전력 부품뿐 아니라 서버 통합, 부하 배치와 과다 용량 축소를 함께 판단한다.

05

4. 서버장비 운영: 운영체제

운영체제는 프로세스, 메모리, 파일·장치, 사용자와 네트워크 자원을 관리하고 응용에 실행 환경을 제공한다.

4.1 계정과 권한

  • 업무·관리·서비스 계정을 분리한다.
  • 서비스는 필요한 자원만 접근하는 최소 권한으로 실행한다.
  • 공유 관리자 계정보다 개인 식별 가능한 관리와 승인된 상승 권한을 사용한다.
  • 퇴직·변경·만료 계정을 회수하고 장기 미사용 권한을 점검한다.

4.2 패치와 기준 구성

지원되는 운영체제와 패키지 기준선을 정하고 보안·안정성 패치를 영향 평가 후 적용한다. 시험, 단계 반영, 재부팅·서비스 영향, 복구 방법을 계획한다. 최신 패치를 즉시 무조건 운영에 넣거나 반대로 영구 연기하는 양극단을 피한다.

4.3 프로세스·서비스

필요한 서비스만 실행하고 시작 순서, 자원 제한, 실패 재시작과 의존성을 관리한다. 자동 재시작이 반복 장애를 숨기거나 자원 고갈을 키울 수 있으므로 재시도 한도와 경보를 둔다.

4.4 로그·시간·감시

시스템, 인증, 권한 변경, 서비스 오류와 자원 지표를 중앙에서 연계할 수 있게 한다. 여러 서버의 시간 기준이 맞지 않으면 사건 순서를 재구성하기 어렵다. 로그에 비밀이나 개인정보가 과도하게 기록되지 않도록 한다.

4.5 백업과 복구

운영체제 이미지, 설정, 응용 데이터의 복구 요구가 다르므로 구분한다. 백업 성공 로그만 보지 말고 격리된 사본, 복원 시험, 복구 시간과 데이터 손실 허용 범위를 확인한다.

06

5. Secure-OS

Secure-OS는 보안 기능을 운영체제 핵심 구조에 강화하여 주체의 자원 접근을 일관되게 통제하고 감사할 수 있게 한 운영체제 또는 보안 강화 관점이다.

5.1 참조 모니터와 보안 커널

참조 모니터는 주체가 객체에 접근하려는 모든 시도를 보안 정책에 따라 중재하는 추상 개념이다. 신뢰할 수 있으려면 다음 성질이 중요하다.

  • 완전한 중재: 모든 접근이 우회 없이 검사를 거침
  • 변조 방지: 권한 없는 주체가 정책과 중재 기능을 바꿀 수 없음
  • 검증 가능성: 충분히 작고 구조화되어 분석·시험 가능

이를 핵심 부분에 구현한 신뢰 기반을 보안 커널 관점으로 설명할 수 있다.

5.2 접근통제

  • 임의적 접근통제: 객체 소유자 등의 재량으로 권한 부여
  • 강제적 접근통제: 보안 등급과 중앙 정책에 따라 시스템이 강제
  • 역할 기반 접근통제: 직무 역할에 권한을 연결

Secure-OS 문맥에서는 사용자가 임의로 낮출 수 없는 강제적 정책과 최소 권한이 강조된다. 실제 시스템은 여러 모델을 조합할 수 있다.

5.3 주요 보안 기능

  • 식별과 인증
  • 주체·객체의 보안 속성과 접근통제
  • 신뢰 경로를 통한 안전한 관리·인증
  • 보안 사건 감사와 보호된 로그
  • 프로세스·메모리·파일 격리
  • 사용 후 저장 영역의 잔존 정보 보호
  • 권한 분리와 최소 권한
  • 보안 기능 자체의 무결성 검증

Secure-OS라는 이름만으로 안전이 자동 보장되지 않는다. 잘못된 정책, 과도한 권한, 미패치 응용과 운영 실수는 별도로 통제해야 한다.

07

6. DAS, NAS, SAN

6.1 DAS

DAS는 저장장치가 서버에 직접 연결되는 구조다. 구성과 지연 경로가 비교적 단순하고 한 서버 전용으로 사용하기 쉽다. 여러 서버가 공유하려면 별도 구조가 필요하고 서버·연결 장애가 접근에 영향을 줄 수 있다.

6.2 NAS

NAS는 네트워크를 통해 파일 단위 서비스를 제공한다. 클라이언트는 경로와 파일 이름으로 접근하며 파일 공유, 권한, 잠금 기능을 저장장치가 제공한다. 여러 서버와 사용자가 문서·콘텐츠를 공유하기 편리하지만 네트워크 지연, 파일 프로토콜, 권한과 작은 파일 작업 특성을 고려한다.

6.3 SAN

SAN은 서버와 저장장치 사이에 전용 또는 논리적으로 분리된 저장 네트워크를 구성하여 블록 단위 자원을 제공한다. 서버 운영체제는 제공된 블록 장치를 디스크처럼 인식하고 그 위에 파일시스템이나 데이터 구조를 구성할 수 있다.

7. 저장 신뢰성과 RAID 관점

RAID는 여러 저장장치를 결합하여 성능 또는 장애 내성을 높이는 방식이다. 널리 학습하는 기본 관점은 다음과 같다.

  • 스트라이핑: 데이터를 나누어 여러 장치에 기록하여 병렬 성능 향상, 단독으로는 장애 내성 없음
  • 미러링: 같은 데이터를 복제하여 한 장치 장애에 대비, 용량 비용 증가
  • 패리티: 복구 정보를 분산 저장하여 용량 효율과 장애 내성을 절충, 쓰기 계산·복구 부담

RAID는 실수로 삭제한 파일, 논리 손상, 악성 변경과 사이트 재해를 막는 백업이 아니다. 장애 난 장치를 교체해 재구성하는 동안 성능과 추가 장애 위험을 고려한다.

09

8. 고가용성

고가용성은 장애와 유지보수 중에도 합의된 수준으로 서비스를 계속 제공하도록 중복 구성, 감지, 전환, 복구를 설계하는 성질이다.

8.1 활성-대기와 활성-활성

8. 고가용성 · 학습 표 4
구조특징주의점
활성-대기한 노드가 서비스하고 대기 노드가 준비대기 용량, 상태 동기화, 전환 시간
활성-활성여러 노드가 동시에 서비스부하 분산, 세션·데이터 일관성, 동시 장애

활성-활성이 항상 더 높은 가용성을 보장하지 않는다. 공유 저장장치나 공통 제어부가 단일 장애점이면 노드 수를 늘려도 효과가 제한된다.

8.2 장애 감지와 페일오버

하트비트는 노드 간 생존 상태를 확인하는 신호다. 신호가 끊겼다고 실제 서비스 장애인지 네트워크 단절인지 구분해야 한다. 오판으로 두 노드가 동시에 자신을 활성으로 간주하는 분할 뇌 상태가 생기면 같은 데이터를 동시에 갱신할 수 있다.

쿼럼은 여러 구성원의 투표나 합의로 어느 쪽이 서비스를 계속할지 결정하는 데 사용된다. 격리 장치나 차단 절차를 이용해 이전 활성 노드가 공유 자원에 접근하지 못하게 하는 통제도 중요하다.

  • 페일오버: 장애 시 대기·다른 노드로 자동 또는 통제 전환
  • 스위치오버: 유지보수 등을 위해 계획적으로 전환
  • 페일백: 복구된 원래 구성으로 되돌아가는 절차

8.3 RTO와 RPO

RTO는 장애 후 서비스를 복구해야 하는 목표 시간, RPO는 복구 시 허용 가능한 데이터 손실 시점을 뜻한다. 서버 이중화가 짧은 RTO에 도움을 줄 수 있지만 비동기 복제 지연이 있으면 RPO가 0이 아닐 수 있다. 가용성과 데이터 보호를 별도로 설계한다.

10

9. 구축·운영 절차와 판단 기준

  1. 업무 부하 분석: 거래량, 동시성, 데이터 증가, 피크와 배치 시간을 파악한다.
  2. 품질 목표 정의: 성능, 가용성, RTO·RPO, 보안과 확장 목표를 정한다.
  3. 아키텍처 선정: 베어메탈·가상화·컨테이너, 저장 방식과 HA 구조를 비교한다.
  4. 용량·환경 설계: CPU, 메모리, I/O, 네트워크, 전원, 냉각과 공간을 산정한다.
  5. 보안·운영 기준선 설계: Secure-OS 통제, 계정, 패치, 로그, 백업과 관리망을 정한다.
  6. 설치·구성: 자산·케이블 라벨, 펌웨어·OS, 저장 경로와 이중화를 기준선대로 구성한다.
  7. 시험: 정상 부하, 최대 예상 부하, 장비·전원·링크 장애, 복구와 보안 정책을 시험한다.
  8. 인수·운영 전환: 구성도, 자산, 라이선스, 백업, 감시, 장애 절차와 책임을 인계한다.
  9. 지속 운영: 용량 추세, 장애 예측, 패치, 구성 변경, 복원·전환 훈련을 수행한다.

판단 기준

  • 병목이 CPU, 메모리, 저장, 네트워크 중 어디에 있는가?
  • 장애 영향이 업무 RTO·RPO 안에 통제되는가?
  • 이중 구성요소가 같은 전원·경로·제어부에 의존하지 않는가?
  • 팀이 가상화·SAN·클러스터의 장애를 진단할 수 있는가?
  • 패치와 유지보수를 서비스 중단 없이 또는 허용 시간 안에 할 수 있는가?
  • 확장 시 특정 자원만 늘릴 수 있는가, 전체 노드를 늘려야 하는가?
  • 전력·냉각·지원·교육을 포함한 총비용이 지속 가능한가?

10. 구체 예시

요구사항:

  • 주문 서비스는 단일 서버 장애에도 계속되어야 한다.
  • 데이터 손실 허용 범위가 매우 작다.
  • 파일 공유는 여러 업무 서버가 사용한다.
  • 데이터베이스는 낮은 지연의 블록 저장장치를 요구한다.

구성 후보:

[부하 분산] ├─ [주문 서버 A: 활성] └─ [주문 서버 B: 활성/대기] │ ┌─────────┴─────────┐ │ │ [NAS 파일 공유] [SAN 블록 저장] │ [이중 저장 경로]

검토:

  1. 주문 서버의 세션·상태를 외부 저장 또는 복제하여 전환 후 이어질 수 있게 한다.
  2. 두 서버가 같은 전원과 네트워크 스위치에만 의존하지 않는지 확인한다.
  3. NAS는 문서 공유의 파일 잠금·권한·처리량을 시험한다.
  4. SAN은 서버-스위치-저장장치까지 다중 경로와 경로 장애 전환을 시험한다.
  5. 저장 복제 방식이 요구 RPO를 만족하는지 실제 장애로 확인한다.
  6. 하트비트 네트워크만 끊겼을 때 두 노드가 동시에 활성화되지 않도록 쿼럼·격리 동작을 시험한다.
  7. 백업에서 별도 환경으로 복원하여 논리 손상과 삭제에도 대비한다.
12

11. 자주 틀리는 포인트

  1. 컨테이너와 가상머신을 같은 격리 단위로 이해: 컨테이너는 일반적으로 호스트 커널을 공유한다.
  2. 코어 수 증가가 모든 프로그램 성능을 비례 향상: 병렬성, 메모리와 I/O 병목을 본다.
  3. Secure-OS가 설치되면 응용 보안이 자동 완성: 정책·권한·패치·응용 취약점은 별도 통제한다.
  4. 강제적 접근통제를 소유자의 자유로운 권한 부여로 이해: 중앙 보안 정책이 강제한다.
  5. NAS와 SAN을 모두 파일 공유 장비로 이해: NAS는 파일, SAN은 블록 서비스 관점이다.
  6. DAS는 네트워크를 통해 파일을 제공한다고 이해: 서버에 직접 연결되는 저장 구조다.
  7. RAID를 백업으로 간주: 삭제·논리 손상·사이트 재해에 별도 백업이 필요하다.
  8. 활성-활성이 항상 활성-대기보다 우수: 상태 일관성, 공통 장애점과 운영 복잡도를 본다.
  9. 하트비트 단절을 즉시 노드 장애로 확정: 네트워크 분리와 분할 뇌를 고려한다.
  10. 서버 이중화가 RPO 0을 보장: 데이터 복제 방식과 지연을 별도로 확인한다.

13. 정답과 해설

정답 1

메모리, 저장 I/O, 네트워크, 전원, 냉각, 랙 공간, 가상화 경합, 확장 여유 중 다섯 가지다.

정답 2

가상머신은 보통 게스트 운영체제와 커널을 가진 가상 시스템 단위로 격리한다. 컨테이너는 호스트 커널을 공유하면서 프로세스와 사용자 공간을 격리한다.

정답 3

모든 접근을 검사하는 완전한 중재, 권한 없는 변경을 막는 변조 방지, 충분히 작고 구조화되어 검증 가능한 성질이다.

정답 4

임의적 접근통제는 소유자 등의 재량으로 권한을 부여하고, 강제적 접근통제는 보안 등급과 중앙 정책에 따라 시스템이 접근을 강제한다.

정답 5

DAS는 서버에 직접 연결되어 주로 블록으로 접근한다. NAS는 네트워크에서 파일 서비스를 제공한다. SAN은 저장 네트워크를 통해 서버에 블록 자원을 제공한다.

정답 6

RAID는 장치 장애 내성을 높이지만 사용자의 삭제나 악성 변경·논리 손상을 그대로 복제할 수 있고, 전체 장비·사이트 재해에도 취약할 수 있다.

정답 7

활성-대기는 한 노드가 서비스하고 다른 노드가 대기하여 전환 시간과 대기 용량을 관리한다. 활성-활성은 여러 노드가 서비스하므로 부하를 나눌 수 있지만 세션·데이터 일관성과 분산 장애가 복잡하다.

정답 8

통신 단절로 둘 이상의 노드가 동시에 자신을 활성이라고 판단해 같은 자원을 갱신하는 상태다. 쿼럼과 이전 노드의 자원 접근을 차단하는 격리 통제로 줄인다.

정답 9

RTO는 장애 후 서비스 복구 목표 시간이고, RPO는 복구했을 때 허용하는 데이터 손실 시점의 범위다.

정답 10

두 서버가 같은 전원, 네트워크 스위치, 저장장치, 관리 제어부, 물리 위치 또는 소프트웨어 기준 이미지에 의존하는 경우 중 세 가지다.

핵심 요약

  • IT 신기술 및 서버장비 트렌드 정보는 가상화, 통합·구성 가능 인프라, 이기종 가속, 엣지, 자동화·관측과 에너지 효율의 목적과 위험으로 학습한다.
  • 서버장비 운영(Secure-OS, 운영체제, NAS, DAS, SAN, 고가용성 등)은 자원·보안·저장·장애 복구를 함께 관리한다.
  • Secure-OS의 핵심은 모든 접근을 중재하는 참조 모니터, 변조 방지, 검증 가능성, 강제적 정책과 감사다.
  • DAS는 직접 연결, NAS는 네트워크 파일, SAN은 저장 네트워크의 블록 서비스 관점으로 구분한다.
  • 고가용성은 노드 수보다 독립된 장애 영역, 정확한 감지, 쿼럼·격리, 상태 일관성과 실제 전환 시험이 중요하다.
  • 서버 구축은 업무 부하와 RTO·RPO에서 시작해 용량·환경·보안 기준선, 정상·장애 시험과 운영 인계로 끝난다.
