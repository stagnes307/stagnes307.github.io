01

출제범위와 학습 목표

이 레슨의 정확한 출제범위는 IT 신기술 및 데이터베이스 기술 트렌드 정보와 데이터베이스 관리기능이다. 관계형·비관계형·분산·인메모리·클라우드 관리형·다중 모델 같은 기술 흐름을 해결하려는 문제와 함께 이해하고, DBMS의 정의·조작·제어, 트랜잭션, 동시성, 무결성, 보안, 백업·복구, 복제와 감시 기능을 구축 요구에 연결하는 것이 목표다. 데이터베이스 명명·도메인 표준화는 다음 레슨에서 다룬다.

학습 후에는 다음을 할 수 있어야 한다.

  • 관계형 DB와 주요 NoSQL 유형의 데이터 모델과 접근 특성을 구분한다.
  • 분산·샤딩·복제, 인메모리, 관리형 서비스의 효과와 새 위험을 설명한다.
  • 데이터 정의·조작·제어와 카탈로그, 트랜잭션·동시성·회복 기능을 설명한다.
  • 업무 부하, 일관성, 지연, 확장, 운영 역량과 총비용으로 DB 기술을 선택한다.
  • 백업 성공이 아닌 복구 가능성과 목표 시간·손실 범위로 운영을 검증한다.
02

1. 데이터베이스 구축 관리의 관점

데이터베이스 구축 관리는 데이터를 저장할 제품을 설치하는 일을 넘어 데이터 모델, 업무 트랜잭션, 용량과 성능, 보안, 가용성, 복구와 운영 책임을 설계하고 검증하는 활동이다.

업무 요구 │ ├─ 데이터 구조·관계 ├─ 읽기/쓰기 패턴·동시성 ├─ 일관성·트랜잭션 경계 ├─ 지연·처리량·증가량 └─ 보안·가용성·복구 │ ▼ 데이터 모델·DB 기술 선정 │ ▼ 저장·접근·복제·백업·감시 설계 │ ▼ 부하·장애·복구 시험

“데이터가 크다”는 이유만으로 특정 유형을 고르지 않는다. 데이터 구조와 관계, 쿼리, 변경 패턴, 일관성, 운영 능력까지 함께 본다.

03

2. IT 신기술 및 데이터베이스 기술 트렌드 정보

2.1 관계형 데이터베이스의 진화

관계형 데이터베이스는 테이블과 관계, 선언적 질의, 트랜잭션과 무결성 통제를 강점으로 한다. 최신 흐름에서도 관계형 모델은 사라지는 것이 아니라 분산 처리, 자동 관리, 다양한 자료형과 분석 기능을 수용하며 발전한다.

적합한 상황:

  • 구조와 관계가 명확하고 조인이 중요함
  • 여러 변경을 하나의 트랜잭션으로 처리해야 함
  • 제약조건과 일관된 질의가 중요함
  • 표준화된 질의와 운영 경험이 필요함

2.2 NoSQL

NoSQL은 관계형 이외의 다양한 데이터 모델과 분산 확장 특성을 가진 데이터베이스 범주다. “SQL을 전혀 사용할 수 없음”이나 “트랜잭션을 지원하지 않음”을 뜻하지 않는다. 제품별 기능이 다르므로 모델의 기본 접근 패턴으로 구분한다.

2.3 분산 데이터베이스

여러 노드에 데이터를 배치하여 용량, 처리량, 지역 접근성과 장애 대응을 높인다.

  • 파티셔닝·샤딩: 데이터를 키·범위 등으로 나누어 노드에 분산
  • 복제: 같은 데이터를 여러 노드에 유지
  • 분산 질의: 여러 노드의 결과를 모아 처리
  • 재배치: 노드 증감과 부하 변화에 따라 데이터 이동

샤드 키를 잘못 선택하면 한 노드에 트래픽이 몰리거나 여러 샤드를 항상 조회하게 된다. 복제본이 많다고 즉시 같은 값을 보장하는 것은 아니며 동기·비동기 방식과 장애 시 쓰기 정책에 따라 최신성·지연·가용성의 균형이 달라진다.

2.4 CAP 관점

네트워크 분할이 발생한 분산 환경에서 일관성과 가용성 사이에 선택이 필요할 수 있다는 관점이다. 이를 “세 특성 중 평소에도 무조건 두 개만 가능”이라고 단순 암기하면 안 된다. 실제 판단은 분할 상황에서 오래된 읽기나 쓰기 거부를 얼마나 허용할지, 업무별 일관성 수준이 무엇인지 정하는 것이다.

2.5 인메모리 데이터베이스와 캐시

주요 데이터를 메모리에 유지하여 지연을 줄이는 접근이다. 메모리는 빠르지만 휘발성이므로 로그, 스냅샷, 복제와 복구 방식이 중요하다. 캐시는 원본 데이터베이스 앞에서 자주 읽는 값을 보관할 수 있는데, 캐시 무효화와 원본·캐시 불일치가 핵심 위험이다.

모든 데이터를 메모리에 올린다고 모든 쿼리가 빨라지는 것은 아니다. 비효율적 연산, 잠금 경합, 네트워크와 응용 호출이 병목일 수 있다.

2.6 클라우드 관리형·탄력형 데이터베이스

설치, 패치, 백업, 복제, 자동 확장 일부를 서비스 제공자가 관리한다. 운영 부담을 줄일 수 있지만 다음을 확인한다.

  • 책임 분담: 계정·데이터·쿼리·설정 중 사용자가 책임질 범위
  • 복구: 백업 보존, 복구 위치·시간과 실제 복원 절차
  • 데이터 위치와 규제
  • 네트워크 지연과 장애 시 연결
  • 비용 변동과 사용량 통제
  • 기능·API 종속과 이전 가능성

“관리형이면 운영이 필요 없다”는 판단은 틀리다. 데이터 모델, 권한, 쿼리, 용량, 비용과 업무 복구 책임은 여전히 남는다.

2.7 서버리스·자동 조정 관점

부하에 따라 용량을 자동 조정하는 방식이다. 변동 부하에 유리할 수 있으나 초기 지연, 용량 한계, 급격한 부하, 고정 부하 비용과 연결 수를 시험한다.

2.8 다중 모델과 통합 분석

관계·문서·그래프·분석 기능을 함께 지원하는 흐름이다. 통합은 편리하지만 워크로드 자원 경합, 장애 영향과 독립 확장 요구를 확인한다.

2.9 데이터 레이크·레이크하우스 관점

원시·반정형·정형 데이터를 유연하게 저장하고 테이블·품질 통제를 결합하는 흐름이다. 메타데이터, 소유권과 접근 정책이 없으면 신뢰하기 어려운 데이터가 쌓일 수 있다.

2.10 자동화·관측과 자율 관리

성능 지표, 쿼리, 자원과 장애 이력을 이용해 구성·용량·인덱스·복구를 지원하는 자동화가 확대된다. 자동 권고는 후보일 뿐 업무 결과와 쓰기 비용, 회귀를 검증해야 한다. 관리 자동화가 잘못된 변경을 넓게 적용하지 않도록 승인, 단계 적용과 되돌리기가 필요하다.

04

3. 데이터베이스 관리기능

데이터베이스 관리기능은 데이터를 정의·저장·조회·변경하고 무결성, 동시성, 보안, 회복과 성능을 통제하는 DBMS의 핵심 기능이다.

3.1 정의 기능

데이터 구조와 제약을 정의한다.

  • 스키마, 테이블, 열과 자료형
  • 기본키, 외래키, 유일성, 검사 조건
  • 뷰, 인덱스와 저장 구조
  • 사용자·권한 객체

정의 결과는 시스템 카탈로그 또는 데이터 사전에 메타데이터로 관리된다. 카탈로그는 테이블·열·제약·권한 등의 정의를 DBMS가 참조하는 정보다.

3.2 조작 기능

데이터의 조회, 삽입, 수정, 삭제를 수행한다. 선언적 질의에서는 사용자가 원하는 결과를 표현하고 DBMS가 실행 계획을 선택한다. 대량 변경은 트랜잭션 범위, 잠금, 로그 증가와 복구 시간을 고려한다.

3.3 제어 기능

데이터를 안전하고 일관되게 유지한다.

  • 무결성 제약 검사
  • 권한과 접근통제
  • 동시성 제어
  • 트랜잭션·회복
  • 감사와 로그
  • 백업·복구와 가용성
05

4. 트랜잭션과 ACID

트랜잭션은 업무상 하나의 논리적 작업 단위다.

  • 원자성: 모두 수행되거나 전혀 수행되지 않아야 함
  • 일관성: 완료 전후에 정의된 무결성 규칙을 만족
  • 격리성: 동시에 실행되는 트랜잭션이 허용된 수준으로 서로 간섭하지 않음
  • 지속성: 완료된 결과가 장애 후에도 보존

ACID는 “각 트랜잭션이 모든 시스템에서 즉시 같은 값을 보인다”는 뜻이 아니다. 분산 복제와 읽기 정책, 격리 수준에 따라 가시성이 달라질 수 있다.

06

5. 동시성 제어

여러 사용자가 같은 데이터를 읽고 쓸 때 갱신 손실, 더티 읽기, 반복 불가능 읽기, 팬텀 같은 이상을 통제한다.

5.1 잠금

공유·배타 잠금 등으로 충돌 작업의 순서를 조정한다. 정확성을 지킬 수 있지만 잠금 대기와 교착상태가 생길 수 있다. 트랜잭션을 불필요하게 길게 유지하면 경합이 커진다.

5.2 다중 버전

데이터의 여러 버전을 이용해 읽기와 쓰기의 충돌을 줄이는 방식이다. 오래 실행되는 트랜잭션이 버전 정리를 막거나 저장 공간을 늘릴 수 있으며, 허용되는 읽기 일관성은 구현과 격리 설정에 따라 다르다.

5.3 교착상태

둘 이상의 트랜잭션이 서로 가진 자원을 기다리며 진행하지 못하는 상태다. 접근 순서 통일, 짧은 트랜잭션, 감지 후 한 트랜잭션 취소와 안전한 재시도로 대응한다. 재시도는 업무 중복을 만들지 않도록 설계한다.

07

6. 무결성과 보안 관리

6.1 무결성

  • 개체 무결성: 기본키가 행을 유일하게 식별하고 NULL이 아님
  • 참조 무결성: 외래키가 존재하는 부모를 참조하거나 허용된 NULL
  • 도메인 무결성: 값이 자료형·범위·코드 규칙을 만족
  • 업무 무결성: 여러 열·테이블의 업무 규칙을 만족

모든 규칙을 응용 프로그램에만 두면 다른 입력 경로에서 우회될 수 있고, 모든 복잡한 규칙을 DB 제약에만 넣으면 운영·변경이 어려울 수 있다. 책임 위치를 명확히 하고 모든 경로에서 통제되는지 본다.

6.2 보안

  • 사용자·서비스 식별과 인증
  • 역할·업무에 따른 최소 권한
  • 관리, 응용, 읽기 전용 계정 분리
  • 전송·저장 데이터 보호와 키 관리
  • 민감 데이터 마스킹·비식별 시험 환경
  • 중요 조회·변경과 권한 변경 감사
  • 네트워크 경계와 관리 접속 제한

DB 관리자 권한 하나를 여러 사람이 공유하면 책임 추적이 어렵다. 개인 식별 가능한 관리 접근과 통제된 비상 권한 절차가 필요하다.

08

7. 로그·체크포인트와 회복

DBMS는 변경 로그를 이용하여 장애 시 완료된 작업을 재적용하거나 미완료 작업을 되돌릴 수 있다. 체크포인트는 복구 시 처음부터 모든 로그를 처리하지 않도록 기준 지점을 제공한다. 세부 알고리즘은 제품별로 다르지만 다음 원칙을 기억한다.

  • 완료된 트랜잭션의 지속성을 보장
  • 미완료 트랜잭션의 부분 변경을 제거
  • 데이터 파일과 로그의 일관된 복구 순서 유지
  • 로그 자체의 손상·공간 부족 감시

트랜잭션 로그는 백업과 목적이 겹치는 부분이 있지만 장기 보존·사이트 손상·사용자 삭제에 대한 독립 보호까지 자동 보장하지 않는다.

09

8. 백업과 복구

8.1 백업 유형 관점

  • 전체 백업: 대상 전체의 기준 사본
  • 증분 백업: 정해진 기준 이후 변경분
  • 차등 백업: 마지막 전체 백업 이후 변경분
  • 로그 기반 백업: 변경 기록을 보존해 특정 시점 복구 지원

명칭과 지원 방식은 제품에 따라 다를 수 있으므로 문제의 정의를 따른다.

8.2 복구 설계

  • RPO: 허용 가능한 데이터 손실 시점 범위
  • RTO: 서비스 복구 목표 시간
  • 백업 주기·보존·암호화·격리
  • 복구할 서버·네트워크·키와 계정
  • 복원 순서와 응용 연결 전 검증
  • 실제 복원 훈련과 소요 시간

백업 작업 성공률이 높아도 필요한 시점으로 복원하지 못하면 목표를 달성하지 못한다. 복구 시험이 최종 증거다.

10

9. 복제와 고가용성

  • 동기 복제: 확인 범위에 복제본 반영을 포함하여 데이터 손실을 줄일 수 있으나 지연과 가용성 영향
  • 비동기 복제: 원본 처리 지연을 줄일 수 있으나 장애 시 최신 변경 손실 가능
  • 읽기 복제본: 조회 부하 분산에 도움, 최신성 지연과 쓰기 후 읽기 정책 필요
  • 장애 전환: 새 주 노드 승격, 연결 전환, 이전 주 노드 격리와 데이터 수렴 필요

복제는 잘못된 삭제와 논리 오류도 복제할 수 있으므로 백업을 대체하지 않는다.

11

10. 성능·용량·감시

관찰 항목:

  • 응답 시간과 처리량
  • CPU, 메모리, 저장 I/O와 네트워크
  • 연결 수, 큐, 잠금 대기와 교착
  • 버퍼 적중과 임시 공간
  • 느린 질의와 처리 행 수
  • 데이터·로그·백업 증가량
  • 복제 지연과 장애 전환 상태
  • 권한 실패와 비정상 접근

평균 지표만 보지 말고 피크와 긴 지연, 업무 그룹을 나누어 본다. 용량 임계값에 도달한 뒤 증설을 시작하면 조달·데이터 이동 시간이 부족할 수 있으므로 증가 추세와 리드타임을 반영한다.

12

11. 구축 절차와 판단 기준

  1. 요구·데이터 분류: 구조, 관계, 민감도, 수명과 소유자를 정의한다.
  2. 워크로드 분석: 읽기·쓰기 비율, 쿼리, 동시성, 증가와 피크를 파악한다.
  3. 일관성·복구 목표 정의: 트랜잭션 경계, 최신성, RTO·RPO를 정한다.
  4. 기술·배치 선정: 관계형·NoSQL·분산·관리형 후보를 평가하고 기술 검증한다.
  5. 논리·물리 구조 설계: 키, 관계, 파티션, 접근 구조와 저장·로그 배치를 정한다.
  6. 보안·운영 설계: 권한, 암호화, 감사, 백업·복구, 복제와 감시를 정의한다.
  7. 구축·데이터 준비: 기준선대로 설치·구성하고 변경 이력을 남긴다.
  8. 시험: 기능, 동시성, 최대 부하, 장애 전환, 복원과 보안 시나리오를 검증한다.
  9. 운영 전환: 계정, 구성, 작업, 장애 절차, 용량 계획과 책임을 인계한다.
  10. 지속 개선: 쿼리·자원·복제·백업·보안 지표로 병목과 위험을 보정한다.

선정 판단

  • 핵심 쿼리와 데이터 관계가 모델에 자연스럽게 맞는가?
  • 필요한 트랜잭션·일관성 수준을 지원하는가?
  • 예상 데이터와 부하를 확장할 수 있는가?
  • 장애와 복구가 목표 RTO·RPO를 충족하는가?
  • 팀이 분산·관리형 책임 경계를 운영할 수 있는가?
  • 보안·감사·데이터 위치 요구를 충족하는가?
  • 이전·철수, 네트워크와 운영 인력을 포함한 총비용은 적절한가?
13

12. 구체 예시

상황:

  • 주문과 결제는 강한 관계와 트랜잭션이 필요하다.
  • 상품 설명은 필드가 자주 추가되고 키 중심 조회가 많다.
  • 추천용 행동 로그는 매우 크고 분석 위주다.

판단:

  1. 주문·결제는 관계형 모델에서 키·외래키와 트랜잭션 경계를 명확히 한다.
  2. 상품 설명은 문서 모델 후보를 검토하되 주문 시점의 가격·상품 참조 일관성을 별도로 설계한다.
  3. 행동 로그는 대량 저장·분석 플랫폼 후보를 검토하고 원본 보존, 스키마·품질 메타데이터와 접근통제를 둔다.
  4. 서로 다른 저장소 사이에서 하나의 전역 트랜잭션을 쉽게 가정하지 않는다.
  5. 주문 이벤트의 중복·순서·재처리와 각 저장소의 추적 식별자를 설계한다.
  6. 각 저장소의 백업·복구만이 아니라 전체 업무를 어느 순서로 복구할지 시험한다.

여러 데이터 기술을 쓰면 각 업무에 맞출 수 있지만 데이터 소유권, 동기화와 장애 분석 비용이 늘어난다. 작은 규모에서는 하나의 충분한 기술이 더 안전할 수 있다.

14

13. 자주 틀리는 포인트

  1. NoSQL을 SQL 미지원 또는 트랜잭션 불가로 단정: 제품별 기능이 다르고 중심은 다양한 비관계 모델이다.
  2. 샤딩과 복제를 동일시: 샤딩은 데이터 분할, 복제는 같은 데이터 사본 유지다.
  3. 복제본이 항상 즉시 최신이라고 판단: 동기 방식과 읽기 정책을 확인한다.
  4. CAP를 평상시 세 특성 중 무조건 두 개 선택으로 단순화: 네트워크 분할 상황의 선택을 본다.
  5. 인메모리이면 영속성과 복구가 필요 없다고 생각: 로그·스냅샷·복제가 중요하다.
  6. 관리형 DB는 운영 책임이 없다고 생각: 데이터·권한·쿼리·비용과 복구 책임이 남는다.
  7. 카탈로그를 사용자 업무 데이터로 혼동: DB 구조·권한 등의 메타데이터다.
  8. ACID 일관성을 모든 복제본의 즉시 동일성과 혼동: 트랜잭션 무결성과 분산 최신성은 구분한다.
  9. RAID·복제가 백업을 대체: 논리 오류도 복제되므로 독립 복구 사본이 필요하다.
  10. 백업 성공을 복구 성공으로 판단: 실제 목표 시점 복원과 업무 연결을 시험한다.

15. 정답과 해설

정답 1

키-값은 키로 값 조회, 문서는 자체 구조 문서 저장, 열 계열은 행 키와 열 묶음 기반 대규모 접근, 그래프는 노드·간선의 다단계 관계 탐색에 강점이 있다.

정답 2

샤딩은 데이터 집합을 나누어 여러 노드에 배치하여 용량·처리를 분산하고, 복제는 같은 데이터의 사본을 유지하여 읽기 분산·가용성·복구에 활용한다.

정답 3

데이터 모델과 쿼리, 계정·권한, 데이터 분류·암호 키, 용량·비용, 백업 정책과 업무 복구, 응용 연결 중 네 가지다.

정답 4

정의는 스키마·제약 같은 구조를 만들고, 조작은 조회·삽입·수정·삭제를 수행하며, 제어는 무결성·권한·동시성·회복과 보안을 관리한다.

정답 5

원자성은 전부 또는 전무, 일관성은 무결성 상태 유지, 격리성은 동시 작업 간 허용된 간섭 통제, 지속성은 완료 결과의 장애 후 보존이다.

정답 6

잠금은 충돌 작업을 직접 순서화하지만 대기·교착이 생길 수 있다. 다중 버전은 읽기·쓰기 충돌을 줄일 수 있지만 오래된 버전 관리와 저장 공간, 격리 의미를 관리해야 한다.

정답 7

전체는 대상 전체, 증분은 정해진 직전 기준 이후 변경분, 차등은 마지막 전체 백업 이후 모든 변경분을 저장한다. 실제 명칭·지원 방식은 시스템 정의를 따른다.

정답 8

동기 복제는 복제 확인을 기다려 손실을 줄일 수 있지만 쓰기 지연·가용성 부담이 있고, 비동기는 원본 응답을 빠르게 할 수 있지만 장애 시 미전달 최신 변경을 잃을 수 있다.

정답 9

데이터 구조·관계, 핵심 쿼리, 읽기·쓰기와 동시성, 일관성, 확장, RTO·RPO, 보안·규제, 운영 역량, 종속·총비용 중 다섯 가지다.

정답 10

복제는 장비 장애와 읽기 분산에 도움을 주지만 잘못된 삭제·논리 손상도 복제한다. 백업은 과거 시점과 독립 사본에서 복구하는 역할을 하므로 목적이 다르다.

17

핵심 요약

  • IT 신기술 및 데이터베이스 기술 트렌드 정보는 NoSQL 유형, 분산·복제, 인메모리, 관리형·탄력형, 다중 모델과 통합 분석의 목적과 위험으로 학습한다.
  • 모델은 데이터 크기만이 아니라 구조·관계, 쿼리, 트랜잭션, 일관성, 운영 능력과 총비용으로 선택한다.
  • 데이터베이스 관리기능은 정의·조작·제어, 카탈로그, 무결성, 트랜잭션·동시성, 보안, 로그·회복, 백업·복제와 감시를 포함한다.
  • 샤딩은 분할, 복제는 사본 유지이며 복제의 최신성과 손실 범위는 방식에 따라 다르다.
  • 백업 성공이 아니라 실제 복원과 RTO·RPO 충족이 복구 가능성의 증거다.
  • 자동화·관리형 서비스가 늘어도 데이터·권한·쿼리·비용·업무 복구에 대한 조직 책임은 남는다.
