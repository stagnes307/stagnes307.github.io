01

출제범위와 학습 목표

이 레슨의 정확한 출제범위는 데이터베이스 표준화와 DB 구축 관리의 적용 절차와 판단 기준이다. 같은 업무 개념을 동일한 용어·단어·도메인·코드·명명 규칙으로 표현하여 데이터 모델과 실제 데이터의 의미를 일관되게 만드는 방법을 익힌다. 앞 레슨의 DBMS 트랜잭션·백업·복제 기능을 반복하지 않고, 표준 수립·적용·변경과 품질 통제에 집중한다.

학습 후에는 다음을 할 수 있어야 한다.

  • 표준 단어, 표준 용어, 도메인, 코드와 명명 규칙을 구분한다.
  • 동의어·유사어·동음이의어를 식별하여 대표 용어를 정한다.
  • 논리명과 물리명, 자료형·길이·허용 값의 일관성을 검토한다.
  • 표준화 조직, 원칙 수립, 사전 구축, 모델 적용, 품질 점검과 변경 절차를 제시한다.
  • 의미 명확성, 유일성, 안정성, 추적성, 구현 가능성으로 표준을 판단한다.
02

1. 데이터베이스 표준화의 의미

데이터베이스 표준화는 조직에서 사용하는 데이터의 명칭, 정의, 형식, 값 체계와 관리 절차를 통일하여 같은 의미를 같은 방식으로 표현하고 공유하도록 하는 활동이다. 테이블명만 대문자로 바꾸거나 약어 목록을 만드는 것에 그치지 않는다.

표준화가 없을 때 생기는 문제:

  • 고객번호, 회원ID, 사용자코드가 같은 개념인지 알기 어렵다.
  • 같은 “상태” 열인데 시스템마다 길이와 코드 값이 다르다.
  • ‘금액’이 세전·세후·할인 전 중 무엇인지 정의가 모호하다.
  • 연계 때마다 개별 매핑과 변환을 반복한다.
  • 데이터 통합·분석에서 같은 값을 중복·누락 집계한다.
  • 설계자마다 임의 약어를 사용해 모델을 이해하기 어렵다.

표준화의 목적은 모든 업무를 억지로 하나의 단어로 합치는 것이 아니다. 의미가 같으면 대표 표현을 공유하고, 의미가 다르면 정의와 수식어로 분명히 구분하는 것이다.

03

2. 표준화 대상

2.1 표준 단어

표준 단어는 용어를 구성하는 최소 의미 단위다. 예를 들어 “고객가입일자”를 고객, 가입, 일자로 나눌 수 있다. 단어 사전에는 한글명, 영문명 또는 약어, 정의, 분류, 금지어·동의어와 사용 규칙을 둔다.

좋은 표준 단어의 조건:

  • 하나의 명확한 의미를 가짐
  • 다른 단어와 의미가 불필요하게 겹치지 않음
  • 약어가 유일하고 읽을 수 있음
  • 조사·기호·임의 숫자 같은 불필요 요소를 피함
  • 조직이 지속적으로 사용할 만큼 안정적임

2.2 표준 용어

표준 용어는 하나 이상의 표준 단어를 조합하여 업무 데이터 항목의 완전한 의미를 나타낸다. “고객가입일자”는 어떤 대상의 어떤 사건에 대한 어떤 유형의 값인지 드러낸다.

용어 사전의 주요 항목:

  • 표준 용어명과 물리명
  • 구성 단어와 조합 순서
  • 정확한 업무 정의
  • 주제 영역과 데이터 소유자
  • 표준 도메인
  • 동의어·금지어와 관련 용어
  • 생성·변경·폐기 상태와 이력

2.3 도메인

도메인은 데이터 값이 가질 수 있는 의미적·물리적 범위다. 자료형, 길이, 정밀도, 단위, 형식, 허용 값, NULL 가능성 같은 특성을 묶는다.

예:

2. 표준화 대상 · 학습 표 1
도메인의미물리 특성 예추가 규칙
고객번호고객 식별 값문자, 정해진 최대 길이유일, 임의 공백 금지
금액통화 금액숫자, 정밀도·소수 자릿수통화·반올림 규칙 필요
일자달력 날짜날짜 의미 자료형시간대 없음
여부참·거짓 상태표준 표현허용 값 목록

같은 자료형과 길이라고 같은 도메인은 아니다. 고객번호와 상품번호가 모두 문자 12자리여도 의미와 생성 규칙이 다르다.

2.4 표준 코드

표준 코드는 상태·유형·등급처럼 분류 값을 일관된 값과 의미로 관리한다. 코드명, 코드값, 설명, 유효 시작·종료, 상위 코드, 소유자와 매핑 관계를 관리한다.

코드 “01”의 의미가 시스템마다 다르면 값만 보고 통합할 수 없다. 코드 집합과 적용 열, 기준 시점을 함께 식별한다. 폐기 코드를 삭제하면 과거 데이터 해석이 어려워질 수 있으므로 사용 중지 상태와 이력을 관리한다.

2.5 표준 명명 규칙

논리명·물리명의 구성 순서, 허용 문자, 약어, 길이, 구분자, 테이블·열·키·인덱스·제약 이름 규칙을 정한다. 특정 DB 제품의 최대 길이나 예약어는 구현 환경별 제약으로 관리하고, 모든 환경에 보편적인 숫자로 단정하지 않는다.

2.6 메타데이터와 표준 사전

표준 사전은 단어·용어·도메인·코드의 정의와 관계를 담는 메타데이터 저장소다. 모델링 도구, 데이터 사전, 품질 규칙과 연계하면 비표준 이름과 도메인 불일치를 자동 점검할 수 있다.

04

3. 단어·용어 관계

3.1 동의어

표현은 다르지만 의미가 같은 단어다. 회원과 고객이 조직에서 동일 개념이라면 대표 표준어 하나를 정하고 다른 표현은 동의어 또는 금지어로 관리한다. 그러나 업무상 회원은 로그인 주체, 고객은 구매 주체로 다르면 합치면 안 된다.

3.2 유사어

의미가 비슷하지만 사용 범위나 조건이 다른 단어다. 등록일자와 가입일자는 일부 상황에서 같아 보여도 사건이 다를 수 있다. 정확한 정의와 주체·행위를 비교한다.

3.3 동음이의어

표현은 같지만 의미가 다른 용어다. “상태”가 주문 상태인지 배송 상태인지 분명하지 않으면 주문상태, 배송상태처럼 수식어로 구분한다.

3.4 금지어

의미가 모호하거나 잘못된 약어, 외래어·축약 표현을 표준 모델에서 쓰지 않도록 지정할 수 있다. 금지 이유와 대체 표준어를 제공해야 사용자가 올바르게 전환할 수 있다.

05

4. 표준화 원칙

4.1 명확성

용어 정의는 순환 정의나 “관련 정보” 같은 모호한 표현을 피한다. 대상, 사건, 값의 의미와 포함·제외 범위를 적는다.

4.2 유일성

같은 의미에는 하나의 대표 표준을 사용하고, 같은 이름에 여러 의미를 넣지 않는다. 물리 약어도 서로 다른 단어에 충돌하지 않도록 관리한다.

4.3 일관성

논리 용어, 물리 열명, 도메인, 코드, 인터페이스와 분석 지표가 같은 정의를 사용해야 한다. 부모 키와 자식 외래키는 같은 의미의 도메인을 공유한다.

4.4 안정성과 확장성

일시적인 화면 문구나 조직명에 지나치게 묶이지 않는 안정된 용어를 선택한다. 새로운 업무가 추가될 때 기존 의미를 바꾸지 않고 확장할 수 있어야 한다.

4.5 추적성

비표준 현행 항목이 어떤 표준으로 매핑되었는지, 표준이 언제 왜 바뀌었는지 추적한다. 표준 변경으로 영향을 받는 모델·인터페이스·코드와 보고서를 찾을 수 있어야 한다.

4.6 구현 가능성

업무 의미가 좋아도 목표 DB의 자료형·길이·예약어·도구 제약에서 구현 가능해야 한다. 논리 표준과 환경별 물리 변환 규칙을 구분해 관리한다.

06

5. 데이터 표준화 관리 조직

  • 데이터 표준 책임자: 정책·원칙과 최종 승인
  • 데이터 아키텍트·모델러: 표준을 모델에 적용하고 영향 분석
  • 업무 데이터 소유자: 의미, 코드와 품질 기준 승인
  • 표준 관리자: 사전 등록, 검토, 배포와 이력 관리
  • 개발·연계 담당자: 물리명·API·메시지에 표준 적용
  • 품질 담당자: 비표준 사용과 도메인·코드 위반 점검
  • 운영 담당자: 실제 스키마와 표준 기준선의 일치, 변경 배포 관리

표준 관리팀만 용어를 정하면 현업 의미가 빠질 수 있고, 각 업무팀이 독립 결정하면 중복이 커진다. 중앙 원칙과 도메인 소유자의 의미 승인을 결합한다.

07

6. 데이터베이스 표준화 절차

  1. 범위·목표 정의: 대상 시스템, 모델, 연계, 중요 데이터와 표준화 수준을 정한다.
  2. 조직·책임 수립: 신청, 검토, 승인, 배포와 예외 책임을 정한다.
  3. 현행 분석: 기존 용어·열·도메인·코드의 사용 빈도, 동의어와 충돌을 조사한다.
  4. 원칙·명명 규칙 수립: 단어 분해, 조합 순서, 약어, 금지어, 물리 변환 규칙을 정한다.
  5. 표준 사전 구축: 대표 단어, 용어, 도메인, 코드와 정의·소유자를 등록한다.
  6. 현행-표준 매핑: 기존 항목을 표준에 연결하고 미매핑·충돌을 해결한다.
  7. 모델 적용: 논리·물리 모델, 키·관계, 인터페이스에 표준을 적용한다.
  8. 품질 점검: 비표준 명칭, 잘못된 단어 조합, 도메인·코드 불일치를 검사한다.
  9. 승인·배포: 기준선 버전을 승인하고 사용자와 도구에 배포한다.
  10. 변경·예외 관리: 신규 신청, 영향 분석, 폐기·대체와 유예 기간을 관리한다.
  11. 운영 측정: 표준 준수, 예외, 중복과 변경 영향을 측정해 사전을 개선한다.

표준 사전을 먼저 완벽하게 만든 뒤 모든 개발을 시작한다는 접근은 현실적으로 지연을 만들 수 있다. 중요 영역부터 기준선을 만들고 승인된 반복 절차로 확장하되, 임시 용어가 영구 비표준으로 남지 않도록 상태와 기한을 관리한다.

08

7. DB 구축 관리의 적용 절차와 판단 기준

DB 구축 관리의 적용 절차와 판단 기준을 표준화 관점에서 보면 다음 흐름이다.

7.1 적용 절차

  1. 업무 개념 확인: 요구사항과 업무 용어의 주체, 사건, 값 의미를 정의한다.
  2. 표준 검색: 기존 단어·용어·도메인·코드가 있는지 확인한다.
  3. 재사용 또는 신규 신청: 의미가 같으면 기존 표준을 사용하고, 다르면 근거와 소유자를 포함해 신규·변경 신청한다.
  4. 충돌·영향 검토: 동의어, 동음이의어, 약어 충돌과 기존 모델·연계 영향을 분석한다.
  5. 논리·물리 적용: 용어를 단어 조합과 도메인에 연결하고 환경별 물리명으로 변환한다.
  6. 자동·수동 검증: 명명 규칙, 도메인, 코드와 업무 정의를 점검한다.
  7. 승인·기준선 반영: 표준 버전과 모델 버전을 연결해 배포한다.
  8. 구현 일치 확인: 실제 스키마·인터페이스가 승인 모델과 같은지 비교한다.
  9. 변경·폐기 관리: 사용처, 마이그레이션 기간, 호환성과 이력을 통제한다.

9. 구체 예시

현행 상황

세 시스템이 같은 고객 식별 값을 다음처럼 사용한다.

  • 시스템 A: 회원ID, 문자 10자리
  • 시스템 B: 고객번호, 문자 12자리
  • 시스템 C: CUST_NO, 숫자형

분석

이름만 보고 같은 개념으로 확정하지 않는다.

  1. 회원과 고객의 업무 정의가 같은지 확인한다.
  2. 값 발급 주체와 유일 범위가 전사인지 시스템별인지 확인한다.
  3. 선행 0이 의미 있는지, 문자·숫자 변환으로 값이 손실되는지 확인한다.
  4. 한 고객이 여러 회원 계정을 가질 수 있는지 확인한다.
  5. 인터페이스와 데이터의 실제 사용처를 조사한다.

표준화 결과 예

회원 계정과 거래 고객이 다른 개념이라면 고객번호와 회원계정번호로 별도 표준 용어를 정의한다. 고객번호 도메인은 발급 규칙, 문자 길이와 유일 범위를 명시한다. 기존 시스템의 물리 열은 즉시 모두 이름을 바꾸지 못할 수 있으므로 현행-표준 매핑과 전환 기한을 둔다.

품질 검사

  • 고객번호 용어가 승인된 고객번호 도메인을 사용하는가?
  • CUST_NO 약어가 다른 단어와 충돌하지 않는가?
  • 주문의 고객번호 외래키가 고객의 고객번호와 같은 도메인인가?
  • 연계 메시지의 customerId가 어느 표준 용어인지 추적되는가?
  • 숫자형 현행 값의 선행 0 손실을 전환 전에 확인했는가?

10. 표준 변경 관리

표준은 한번 등록하면 영원히 고정되는 것이 아니다. 법·업무·기술 변화로 수정될 수 있다.

변경 절차:

  1. 변경 사유와 대상, 새 정의를 신청한다.
  2. 기존 사용처와 데이터·인터페이스 영향을 조회한다.
  3. 이름만 바뀌는지 의미·도메인·코드가 바뀌는지 구분한다.
  4. 호환, 데이터 전환, 이중 운영과 유예 기간을 설계한다.
  5. 권한 있는 소유자와 표준 책임자가 승인한다.
  6. 새 버전을 배포하고 도구·모델·문서를 갱신한다.
  7. 사용 중지 표준의 대체 항목과 종료 시점을 공지한다.
  8. 실제 구현이 전환되었는지 추적한다.

용어 의미를 조용히 변경하면 과거 데이터와 보고서 해석이 달라진다. 기존 용어를 폐기하고 새 용어를 만들거나 버전과 유효 기간을 분명히 하는 편이 안전할 수 있다.

11. 표준화 품질 점검

자동 점검에 적합

  • 허용되지 않은 문자·구분자
  • 등록되지 않은 단어·약어
  • 명명 길이와 조합 순서
  • 표준 용어와 도메인 연결
  • 부모 키와 외래키 도메인 불일치
  • 폐기된 코드·용어의 신규 사용

사람 검토가 필요한 항목

  • 업무 정의의 정확성
  • 동의어인지 다른 개념인지
  • 도메인 단위·정밀도의 적절성
  • 신규 표준의 장기 안정성
  • 기존 표준 변경의 업무 영향
  • 예외 허용의 위험과 종료 계획

자동 점검 통과는 의미가 정확하다는 보장이 아니다. 의미와 소유권은 업무 담당자의 검토가 필요하다.

12. 자주 틀리는 포인트

  1. 표준 단어와 표준 용어를 동일시: 단어는 최소 의미 단위, 용어는 업무 항목의 완전한 표현이다.
  2. 같은 자료형이면 같은 도메인이라고 판단: 의미·단위·허용 값과 생성 규칙이 달라질 수 있다.
  3. 코드값만 같으면 같은 코드라고 판단: 코드 집합, 의미, 적용 대상과 유효 기간을 본다.
  4. 동의어를 모두 별도 표준으로 등록: 대표 표준어와 동의어·금지어 관계를 관리한다.
  5. 같은 이름이면 같은 의미라고 판단: 주문상태와 배송상태처럼 수식어로 구분한다.
  6. 물리명만 통일하면 표준화 완료: 정의, 용어, 도메인, 코드와 관리 절차가 필요하다.
  7. 현행 시스템 이름을 즉시 전부 변경: 영향과 호환, 전환·유예 계획을 먼저 세운다.
  8. 자동 검사 PASS를 의미 품질로 해석: 업무 정의는 사람 검토가 필요하다.
  9. 표준 변경 시 사전의 현재값만 수정: 사용처·과거 이력과 유효 기간을 보존한다.
  10. 조직 표준과 DB 제품 제약을 혼합: 논리 표준과 환경별 물리 변환 규칙을 구분한다.

13. 확인 문제

문제 1

데이터베이스 표준화가 필요한 이유를 네 가지 쓰시오.

문제 2

표준 단어와 표준 용어의 차이를 예로 설명하시오.

문제 3

도메인에 포함할 속성을 다섯 가지 쓰시오.

문제 4

동의어, 유사어, 동음이의어의 차이를 설명하시오.

문제 5

같은 문자 12자리인 고객번호와 상품번호가 같은 도메인이 아닌 이유는 무엇인가?

문제 6

데이터베이스 표준화 절차를 여섯 단계 이상 순서대로 쓰시오.

문제 7

신규 표준 용어 승인 판단 기준을 다섯 가지 쓰시오.

문제 8

표준 변경 시 영향 분석할 대상을 네 가지 쓰시오.

문제 9

자동 표준 점검과 사람 검토에 적합한 항목을 각각 두 가지 쓰시오.

14. 정답과 해설

정답 1

같은 개념의 일관된 표현, 연계 변환 감소, 모델 이해·재사용 향상, 통합·분석 정확성, 도메인·코드 품질 통제, 변경 영향 추적 중 네 가지다.

정답 2

표준 단어는 고객·가입·일자처럼 용어를 만드는 최소 의미 단위다. 표준 용어는 이를 조합한 고객가입일자처럼 하나의 업무 데이터 항목을 완전하게 표현한다.

정답 3

업무 의미, 자료형, 길이, 정밀도·소수 자릿수, 단위, 형식, 허용 값, NULL 가능성 중 다섯 가지다.

정답 4

동의어는 표현이 다르고 의미가 같으며, 유사어는 일부 의미가 비슷하지만 범위가 다르고, 동음이의어는 표현이 같지만 의미가 다르다.

정답 5

자료형·길이는 같아도 식별 대상, 발급 규칙, 유일 범위와 허용 값의 의미가 다르기 때문이다. 도메인은 물리 형식과 의미를 함께 가진다.

정답 6

범위·목표 정의, 조직 수립, 현행 분석, 원칙·명명 규칙 수립, 표준 사전 구축, 현행 매핑, 모델 적용, 품질 점검, 승인·배포, 변경·예외 관리의 흐름이다.

정답 7

의미 동일성, 명확성, 유일성, 도메인 적합성, 안정성, 추적성, 호환성, 구현성, 소유권 중 다섯 가지다.

정답 8

논리·물리 모델, 실제 스키마, 데이터 값, 프로그램 코드, 인터페이스, 보고서·분석 지표, 품질 규칙과 문서 중 네 가지다.

정답 9

자동 점검은 비표준 문자·약어, 명명 조합, 도메인 연결과 폐기어 사용에 적합하다. 사람 검토는 업무 정의, 동의어 판정, 단위·정밀도와 변경 영향에 적합하다.

핵심 요약

  • 데이터베이스 표준화는 단어·용어·도메인·코드·명명 규칙과 관리 절차를 통일하여 데이터 의미와 구현을 일관되게 만드는 활동이다.
  • 표준 단어는 최소 의미 단위, 표준 용어는 업무 항목, 도메인은 의미와 물리 값 범위, 코드는 분류 값 체계다.
  • 같은 표현의 다른 의미와 다른 표현의 같은 의미를 구분하고 대표어, 수식어, 동의어·금지어 관계를 관리한다.
  • DB 구축 관리의 적용 절차와 판단 기준은 표준 검색, 재사용·신규 신청, 충돌·영향 검토, 모델 적용, 검증, 승인, 구현 일치와 변경 관리로 이어진다.
  • 표준은 명확성, 유일성, 일관성, 안정성, 추적성, 호환성, 구현 가능성과 소유권으로 판단한다.
  • 자동 점검은 형식 위반을 빠르게 찾고, 업무 담당자는 정의의 정확성과 변경 영향을 검토한다.
