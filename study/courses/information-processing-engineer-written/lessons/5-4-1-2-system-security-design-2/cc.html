01

출제범위와 학습 목표

이 레슨은 조직의 자산·신뢰 경계·통제 관계를 시스템 구조로 표현하는 보안 아키텍처와, 위험 관리 및 통제 활동을 일관되게 수행하게 하는 보안 Framework를 다룬다. 학습 후에는 심층 방어, 최소 권한, 구역 분리, 제로 트러스트, 보안 참조 구조를 설명하고, 거버넌스–위험–통제–측정의 프레임워크를 조직 상황에 맞게 적용할 수 있어야 한다.

앞 레슨의 개별 서비스 공격과 서버 인증·접근통제, 다음 레슨의 로그 분석·보안 솔루션 제품 기능은 필요한 연결만 한다. 특정 표준의 판 번호나 통제 개수처럼 바뀔 수 있는 정보보다 프레임워크의 목적과 적용 절차를 우선한다.

02

보안 아키텍처의 개념

보안 아키텍처(Security Architecture)는 업무 목표와 위험을 바탕으로 정보자산, 사용자, 시스템, 네트워크, 데이터 흐름, 신뢰 경계와 보안 통제를 일관된 구조로 설계한 청사진이다. 개별 제품 목록이 아니라 “어디에서 무엇을 왜 보호하고 통제가 어떻게 협력하는가”를 설명한다.

아키텍처는 다음 질문에 답해야 한다.

  • 중요한 자산과 데이터는 무엇이며 어디에 존재하는가?
  • 사용자·서비스·관리자는 어떻게 신원을 증명하는가?
  • 어떤 구역과 흐름이 있고 어디에서 신뢰 수준이 바뀌는가?
  • 자원별 접근정책과 키·비밀은 누가 관리하는가?
  • 한 구성요소가 실패하거나 침해되면 확산을 어떻게 제한하는가?
  • 탐지, 대응, 백업, 복구는 어느 계층에서 작동하는가?
  • 통제 효과를 어떤 로그·시험·지표로 증명하는가?

기술 구조는 조직의 정책, 법적 요구, 운영 역량과 맞아야 한다. 복잡한 통제를 도입해도 운영자가 갱신·감시할 수 없다면 시간이 지나 보안 부채가 된다.

03

아키텍처 원칙

아키텍처 원칙 · 학습 표 1
원칙의미설계 적용
최소 권한필요한 대상·동작·기간만 허용역할·서비스 계정 분리, 짧은 승격
기본 거부명시 허용 외에는 거부네트워크·API·데이터 정책 허용 목록
심층 방어여러 독립 계층 통제를 중첩경계, 호스트, 응용, 데이터 보호

공격 표면 최소화불필요한 기능·경로 제거포트·계정·관리 API 비활성화
안전한 실패통제 장애 시 보호 상태 유지정책 조회 실패 때 허용 금지
단순성이해·검증 가능한 구조 유지예외 경로와 중복 도구 최소화
추적성중요 행위와 변경을 증명중앙 시각, 상관 ID, 변경 이력

심층 방어는 같은 기능의 장비를 무작정 여러 대 두는 것이 아니다. 서로 다른 실패 원인과 공격 경로를 막는 독립 통제를 배치하고, 한 통제 실패가 전체 보호 상실로 이어지지 않게 한다.

04

자산과 데이터 흐름 중심 설계

아키텍처 작업은 제품 선정 전에 자산·데이터 흐름을 그리는 것에서 시작한다.

사용자/외부 시스템 ↓ 인증·입력 경계 공개 서비스 구역 ↓ 서비스 신원·허용 API 업무 서비스 구역 ↓ 최소 권한 데이터 접근 데이터 구역 ↓ 분리된 백업·키 관리 복구 및 보존 구역

각 화살표에는 출발 주체, 목적지, 프로토콜, 데이터 등급, 인증·암호화·인가·로그 요구를 표시한다. 단방향으로 보이는 흐름에도 응답과 오류, 관리 채널이 존재한다.

개인정보가 원본 데이터베이스뿐 아니라 캐시, 검색 색인, 로그, 분석 저장소, 백업에 복제되는지 찾는다. 데이터 등급과 보존·폐기 정책을 모든 복사본에 적용한다.

05

신뢰 구역과 네트워크 분리

구역은 비슷한 신뢰와 보안 요구를 가진 자산을 묶는다. 공개 서비스, 내부 업무, 데이터, 관리, 개발·시험, 백업 구역을 예로 들 수 있다. 구역 사이 흐름은 업무에 필요한 것만 허용하고 출발지·목적지·서비스 신원을 검증한다.

네트워크 분리는 침해 확산을 줄이지만 그 자체가 사용자 인가를 대신하지 않는다. 내부 구역에서도 서비스별 신원과 최소 권한을 확인한다. 관리 구역은 일반 사용자 경로와 분리하고 높은 인증과 감사를 적용한다.

너무 큰 구역은 한 시스템 침해가 넓게 퍼지고, 지나치게 미세한 분리는 운영 복잡성과 규칙 오류를 늘린다. 자산 중요도, 통신 패턴, 운영 능력을 기준으로 적정 경계를 정한다.

예외 방화벽 규칙은 요청자, 업무 이유, 승인자, 만료일을 기록한다. 임시 예외가 영구 규칙이 되지 않도록 자동 만료와 검토를 둔다.

06

심층 방어 구조

심층 방어는 예방–탐지–대응–복구를 함께 배치한다.

  1. 경계에서 불필요한 트래픽과 대량 공격을 제한한다.
  2. 서비스가 상대 신원과 요청 형식을 검증한다.
  3. 응용이 객체와 행위별 인가를 강제한다.
  4. 운영체제가 프로세스와 파일 권한을 격리한다.
  5. 데이터가 전송·저장될 때 보호되고 키가 분리된다.
  6. 중앙 로그와 탐지가 이상 행위를 식별한다.
  7. 대응 절차가 계정·세션·시스템을 격리한다.
  8. 검증된 백업과 복구가 서비스와 데이터를 회복한다.

예방 통제가 실패할 수 있다는 전제로 탐지와 대응을 설계한다. 반대로 탐지 도구가 있다는 이유로 기본 패치와 최소 권한을 생략하지 않는다.

07

제로 트러스트 관점

제로 트러스트는 네트워크 위치만으로 암묵적으로 신뢰하지 않고 모든 접근을 명시적으로 검증하며 최소 권한을 적용하는 원칙이다. “아무도 신뢰하지 않는다”는 구호보다 다음 실천을 본다.

  • 사용자와 장치, 서비스에 고유 신원을 부여한다.
  • 요청마다 자원·행위·환경을 정책으로 평가한다.
  • 필요한 최소 범위와 짧은 기간만 접근을 허용한다.
  • 세션 중에도 위험 변화와 권한 변경을 반영한다.
  • 내부 흐름을 가시화하고 이상 행위를 탐지한다.
  • 데이터와 중요 워크로드 중심으로 보호 경계를 둔다.

모든 요청에 사용자가 비밀번호를 다시 입력하게 하는 것이 제로 트러스트는 아니다. 지속적인 신호와 인증 강도를 바탕으로 적절한 재인증을 적용한다.

기존 시스템을 한 번에 모두 바꾸기보다 중요한 자산과 관리 경로부터 신원 기반 접근, 세분화, 가시성을 단계적으로 적용한다.

08

보안 서비스와 공통 기반

아키텍처는 인증·인가, 비밀·키 관리, 감사, 구성 관리, 취약점 관리, 백업 같은 공통 보안 서비스를 어디에서 제공할지 정한다. 각 팀이 독자 구현하면 정책 불일치와 운영 비용이 커진다.

중앙화는 일관성과 감사에 유리하지만 단일 장애·공격 지점이 될 수 있다. 고가용성, 캐시된 안전 정책, 장애 시 Fail Secure 동작을 설계한다. 중앙 서비스가 모든 업무 세부를 아는 거대한 결합점이 되지 않게 표준 계약과 위임 경계를 둔다.

키 관리 서비스는 키 접근을 제한하고 교체를 지원한다. 중앙 인증 서비스는 계정 생명주기와 강한 인증을 관리한다. 정책 결정 서비스와 실제 요청을 차단·허용하는 집행 지점을 구분할 수 있다.

09

가용성과 복구 아키텍처

보안은 기밀성뿐 아니라 가용성을 포함한다. 중요 서비스는 장애 영역을 분리하고 중복 구성, 상태 복제, 용량·장애 전환 시험을 수행한다. 중복 장치가 같은 구성 오류와 같은 관리 계정에 의존하면 공통 원인 장애가 남는다.

백업은 운영 데이터와 논리적으로·권한상 분리하고 변경 불가능 보존이나 오프라인 사본을 위험에 따라 적용한다. 백업 생성 성공보다 실제 복원 시간, 복원 지점, 키·구성 포함 여부를 시험한다.

재해복구 목표는 허용 가능한 데이터 손실 시점과 서비스 복구 시간을 업무와 합의한다. 보안 사고 복구에서는 감염된 설정과 자격 증명을 그대로 복원하지 않고 신뢰 가능한 기준선과 비밀 교체가 필요하다.

10

보안 Framework의 개념

보안 Framework는 조직이 보안 위험을 식별하고 통제를 선택·구현·평가·개선하도록 공통 용어, 영역, 절차와 기준을 제공하는 체계다. 프레임워크는 특정 보안 제품이나 애플리케이션 개발 틀과 구분한다.

일반 구성은 다음과 같다.

  • 거버넌스: 책임, 정책, 자원, 의사결정과 감독
  • 자산·위험 관리: 무엇을 보호하고 어떤 위험을 수용·감소·이전·회피할지 결정
  • 보호: 접근통제, 데이터 보호, 안전한 구성, 교육과 유지보수
  • 탐지: 사건과 이상 징후를 발견하고 분석
  • 대응: 억제, 격리, 소통, 증거 보존과 원인 제거
  • 복구: 서비스와 데이터를 회복하고 교훈을 반영
  • 측정·개선: 통제 효과와 성숙도를 평가하고 우선순위를 갱신

국제 표준, 국가 지침, 산업별 규정 등 여러 체계가 있으며 조직은 적용 대상과 요구를 매핑할 수 있다. 이름과 항목 수를 기계적으로 복사하기보다 업무 위험과 법적 의무에 맞게 적용한다.

11

정책·표준·절차·지침

보안 거버넌스 문서는 수준을 구분한다.

  • 정책(Policy)은 조직이 지켜야 할 방향과 책임을 선언한다.
  • 표준(Standard)은 반드시 따라야 할 구체 요구와 기준을 정한다.
  • 절차(Procedure)는 누가 언제 어떤 순서로 수행하는지 설명한다.
  • 지침(Guideline)은 권장 방법과 선택지를 제공한다.

“중요 데이터는 보호해야 한다”는 정책만 있고 알고리즘, 키 관리, 검증 절차가 없으면 실행이 일관되지 않다. 반대로 제품 설정값만 있고 왜 필요한지와 예외 승인 원칙이 없으면 환경 변화에 대응하기 어렵다.

예외는 위험 평가, 보완 통제, 승인자, 소유자, 만료일과 개선 계획을 갖는다. 예외 목록 자체를 정기 검토한다.

12

위험 기반 통제 선정

위험은 자산 가치, 위협 가능성, 취약성, 기존 통제, 업무 영향을 고려해 평가한다. 정량값이 정확한 예측이라기보다 우선순위와 의사소통을 돕는 근거임을 이해한다.

위험 대응은 다음으로 분류한다.

  • 감소: 예방·탐지·복구 통제로 가능성이나 영향을 낮춘다.
  • 회피: 위험을 만드는 업무나 기술을 중단·변경한다.
  • 이전 또는 공유: 보험·계약 등으로 일부 영향을 나누되 책임이 완전히 사라지는 것은 아니다.
  • 수용: 비용과 편익을 검토해 승인된 책임자가 잔여 위험을 받아들인다.

통제는 예방, 탐지, 교정·복구로 구분하거나 관리적, 기술적, 물리적으로 구분할 수 있다. 한 위험에 여러 종류를 조합한다.

잔여 위험은 통제 후에도 남는 위험이다. 통제를 설치했다고 0이 되었다고 가정하지 않고 승인과 모니터링을 지속한다.

13

통제 목표와 구현의 추적성

프레임워크 요구를 시스템 구현에 연결하는 추적표를 만든다.

통제 목표와 구현의 추적성 · 학습 표 2
위험·요구통제 목표아키텍처 결정구현·운영 증거
관리자 계정 탈취강한 신원·최소 권한관리 경로 분리, 다중요소, 짧은 승격인증 정책, 접근 로그, 권한 검토
데이터 유출최소 공개·기밀성구역 분리, 필드 최소화, 키 관리데이터 흐름, 설정 검사, 복호화 감사
서비스 중단용량·복구속도 제한, 장애 영역 분리, 백업부하 시험, 장애 전환, 복원 기록
공급망 변경출처·무결성승인 저장소, 서명된 산출물구성요소 목록, 빌드 증명, 검증 로그

문서만 존재하는 통제와 실제 강제되는 통제를 구분한다. 방화벽 정책이 문서에 있어도 운영 규칙이 전부 허용이면 효과가 없다. 자동 구성 검사와 표본 시험으로 증거를 수집한다.

14

성숙도와 지표

성숙도는 개인 경험에 의존하는 임시 대응에서 정의·자동화·측정·지속 개선되는 체계로 발전하는 정도를 나타낼 수 있다. 높은 성숙도 점수 자체가 목표가 아니라 중요한 위험을 일관되게 줄이는 능력이 목표다.

지표는 패치 완료율 같은 활동 지표, 평균 탐지·복구 시간 같은 운영 지표, 재발률·복원 성공률 같은 결과 지표를 균형 있게 사용한다. 취약점 발견 수가 늘었다고 보안이 나빠졌다고만 볼 수 없다. 탐지 역량 향상일 수 있으므로 심각도, 해결 기간, 반복 원인을 함께 본다.

측정하기 쉬운 값만 목표로 삼으면 숫자를 맞추고 실제 위험을 놓칠 수 있다. 업무 영향과 통제 목표에 연결한다.

15

적용 절차

  1. 경영·업무 목표, 법적 요구, 위험 수용 기준을 확인한다.
  2. 자산·데이터·사용자·서비스와 현재 구조를 목록화한다.
  3. 신뢰 경계와 데이터 흐름, 위협과 취약성을 분석한다.
  4. 목표 보안 원칙과 참조 아키텍처를 정한다.
  5. 프레임워크 통제를 위험과 시스템에 매핑하고 우선순위를 정한다.
  6. 예방·탐지·대응·복구 통제를 구체 설계한다.
  7. 책임자, 예외, 운영 절차, 필요한 자원을 정한다.
  8. 단계적으로 구현하고 기술·절차·사람 관점으로 시험한다.
  9. 로그·감사·지표로 효과와 잔여 위험을 평가한다.
  10. 사고·변경·새 위협과 사업 변화에 따라 구조와 통제를 개선한다.

한 번 만든 아키텍처 문서를 고정하지 않는다. 신규 외부 연동, 클라우드 이전, 조직 합병, 규제 변경은 신뢰 경계와 위험을 바꾼다. 변경 검토 절차에 보안 아키텍처 검토를 포함한다.

16

방어 중심 예시: 신규 외부 서비스 연동

외부 결제 서비스와 연동한다고 하자.

사용자 요청 → 내부 인증·주문 인가 → 결제 연동 전용 서비스 → 목적지 허용 목록과 상호 신원 검증 → 최소 결제 데이터만 전송 → 응답 무결성·중복 방지 검증 → 거래·오류 감사 → 장애 시 회로 차단과 보상 절차

연동 전용 서비스는 데이터베이스 전체 권한이 아니라 필요한 주문 상태 변경만 가진다. 외부 장애가 내부 자원을 고갈시키지 않게 시간 제한과 큐를 둔다. 프레임워크 추적표에는 공급자 위험 평가, 계약, 키 교체, 장애 대응, 로그와 정기 재평가 증거를 연결한다.

17

자주 틀리는 포인트

  • 보안 아키텍처는 보안 제품 목록이 아니라 자산·흐름·경계·통제 관계의 설계다.
  • 심층 방어는 동일 제품을 중복 설치하는 것보다 독립 통제와 실패 영향 제한이 핵심이다.
  • 내부망이라는 이유만으로 암묵 신뢰하지 않고 서비스·사용자 신원을 검증한다.
  • 구역을 잘게 나눌수록 무조건 좋은 것이 아니라 운영 복잡성과 규칙 오류를 고려한다.
  • 제로 트러스트는 매 요청마다 비밀번호를 다시 입력시키는 방식이 아니다.
  • 중앙 보안 서비스는 일관성에 유리하지만 가용성과 결합도를 설계해야 한다.
  • 백업 성공 로그보다 실제 복원과 복구 시간·데이터 지점을 시험한다.
  • 보안 Framework는 특정 라이브러리나 장비가 아니라 위험과 통제 관리 체계다.
  • 정책, 표준, 절차, 지침의 강제 수준과 목적을 구분한다.
  • 위험 이전은 조직의 최종 책임과 운영 위험을 모두 없애지 않는다.
  • 통제 설치 뒤에도 잔여 위험이 남으며 수용은 책임자의 근거 있는 결정이 필요하다.
  • 지표 숫자가 좋아져도 실제 위험 감소와 연결되는지 확인한다.
18

확인 문제

  1. 보안 아키텍처가 답해야 할 질문을 다섯 가지 이상 쓰라.
  2. 최소 권한, 기본 거부, 심층 방어, 안전한 실패를 각각 설명하라.
  3. 신뢰 구역 분리의 이점과 지나친 세분화의 비용을 쓰라.
  4. 제로 트러스트의 핵심 실천을 네 가지 쓰라.
  5. 중앙 보안 서비스가 주는 장점과 단일 장애·결합 위험을 설명하라.
  6. 보안 Framework의 거버넌스–보호–탐지–대응–복구 흐름을 설명하라.
  7. 정책, 표준, 절차, 지침을 비교하라.
  8. 위험 감소·회피·이전·수용과 잔여 위험의 의미를 설명하라.
  9. 프레임워크 통제와 시스템 구현 사이 추적성이 필요한 이유는 무엇인가?
  10. 보안 지표를 발견 건수 하나로 평가하면 안 되는 이유는 무엇인가?
19

정답과 해설

  1. 중요 자산, 신뢰 경계, 신원 확인, 접근정책, 데이터 보호, 침해 확산 제한, 탐지·대응·복구, 검증 증거를 설명해야 한다.
  2. 최소 권한은 필요한 범위만 허용, 기본 거부는 명시 허용 외 거부, 심층 방어는 여러 독립 계층 중첩, 안전한 실패는 통제 장애 시 보호 상태 유지다.
  3. 구역 분리는 침해 확산과 불필요한 흐름을 줄인다. 지나치게 세분하면 정책 수와 운영 부담이 늘어 잘못된 예외와 장애를 만들 수 있다.
  4. 네트워크 위치를 신뢰하지 않고 주체·장치·서비스 신원을 확인하며, 자원별 최소 권한을 요청마다 평가하고, 위험 변화를 반영하며 내부 흐름을 가시화한다.
  5. 중앙화는 정책 일관성과 감사에 유리하다. 그러나 장애나 침해 시 영향이 넓고 모든 업무가 한 서비스에 결합될 수 있어 고가용성·안전한 캐시·명확한 계약이 필요하다.
  6. 책임과 위험 기준을 정하고 예방 통제로 보호하며 이상을 탐지하고, 사건을 격리·제거해 대응하고, 검증된 상태로 복구한 뒤 교훈을 반영한다.
  7. 정책은 방향과 책임, 표준은 의무 기준, 절차는 수행 순서, 지침은 권장 선택을 제공한다.
  8. 감소는 통제로 낮추고, 회피는 원인을 중단하며, 이전은 일부 영향을 공유하고, 수용은 남은 위험을 승인한다. 잔여 위험은 통제 후에도 남는 위험이다.
  9. 문서 요구가 실제 네트워크·응용·운영 통제로 강제되고 증거가 있는지 확인하며 누락과 중복 투자를 찾기 위해서다.
  10. 탐지 역량 향상으로 발견이 늘 수 있고 건별 영향이 다르기 때문이다. 심각도, 해결 시간, 재발, 업무 영향과 통제 효과를 함께 본다.
20

핵심 요약

  • 보안 아키텍처는 자산·데이터 흐름·신뢰 경계와 예방–탐지–대응–복구 통제를 연결한 구조다.
  • 최소 권한, 기본 거부, 심층 방어, 안전한 실패, 단순성과 추적성을 일관되게 적용한다.
  • 네트워크 위치를 암묵 신뢰하지 않고 구역 분리와 주체·서비스 신원 기반 정책으로 확산을 제한한다.
  • 보안 Framework는 거버넌스, 위험 평가, 통제 선택, 구현, 측정과 개선을 위한 공통 체계다.
  • 정책·표준·절차·지침을 구분하고 위험 대응과 잔여 위험을 책임 있게 승인한다.
  • 통제 목표–아키텍처–구현–운영 증거의 추적성을 유지하고 지표를 실제 업무 위험 감소와 연결한다.
