# 5-4-2-1. 로그 분석 · 보안 솔루션

## 출제범위와 학습 목표

이 레슨은 시스템과 서비스가 남긴 사건 기록에서 이상 징후와 원인을 찾는 **로그 분석**, 위험을 예방·탐지·차단·대응하도록 지원하는 **보안 솔루션**의 종류와 적용 기준을 다룬다. 학습 후에는 로그 원천·필드·수집·정규화·상관분석·보존 흐름을 설명하고, 방화벽·침입 탐지/방지·웹 보호·단말 보호·정보 유출 방지·통합 분석 등의 역할과 한계를 비교할 수 있어야 한다.

앞 레슨의 보안 아키텍처와 Framework, 다음 레슨의 취약점 분석 절차는 필요한 연결만 한다. 제품별 메뉴와 규칙 문법, 공격용 페이로드를 제시하지 않고 방어 목적의 관찰·선별·대응과 운영 검증에 집중한다.

## 로그의 개념과 가치

로그(Log)는 시스템, 응용 프로그램, 보안 장비와 사용자가 수행한 사건을 시간 순서로 기록한 데이터다. 정상 운영 확인, 장애 진단, 성능 분석, 보안 탐지, 감사와 사고 조사에 사용한다.

로그는 모든 사실을 완벽하게 담는 진실 그 자체가 아니다. 기록되지 않은 사건, 잘못된 시각, 손상·누락, 모호한 사용자 식별자가 있을 수 있다. 여러 원천을 상호 검증하고 기록 범위와 신뢰도를 이해해야 한다.

보안 로그의 핵심 질문은 다음과 같다.

- 언제 어떤 시스템에서 사건이 발생했는가?
- 누가 또는 어떤 서비스가 어떤 신원으로 행동했는가?
- 어디에서 어디로 어떤 자원에 접근했는가?
- 어떤 행위를 시도했고 결과는 성공·실패·거부 중 무엇인가?
- 관련된 이전·이후 사건과 변경은 무엇인가?
- 정상 기준과 비교해 얼마나 이례적인가?

## 로그 원천

| 원천 | 대표 기록 | 보안 활용 |
|---|---|---|
| 운영체제 | 로그인, 권한 상승, 프로세스, 서비스, 파일 감사 | 계정 오용·설정 변경·실행 추적 |
| 응용 프로그램 | 요청, 업무 행위, 오류, 관리자 기능 | 객체 접근·업무 이상·오류 연계 |
| 데이터베이스 | 접속, 질의 감사, 권한·스키마 변경 | 중요 데이터 조회·변경 추적 |
| 네트워크 장비 | 연결, 허용·거부, 주소 변환, 흐름 | 비정상 통신·구역 위반 |
| 인증·권한 시스템 | 인증 성공·실패, 요소 등록, 권한 부여·회수 | 계정 탈취·권한 변화 |
| 단말 보안 | 프로세스·파일·행위 탐지, 격리 | 악성 행위·확산 조사 |
| 클라우드·가상 환경 | 관리 API, 구성 변경, 자원 생성 | 통제면 오용·자산 변화 |
| 보안 장비 | 경보, 차단, 규칙 일치, 상태 | 위협 징후와 통제 작동 확인 |

한 원천만 보면 맥락이 부족하다. 인증 성공 뒤 새 관리자 권한이 부여되고, 곧바로 대량 데이터가 조회되었다면 인증·권한·데이터베이스 로그를 시간과 주체로 연결해야 한다.

## 좋은 로그 필드

좋은 보안 로그에는 사건 시각과 시간대, 시스템·서비스·버전, 사건 종류, 주체 식별자, 출발·목적 정보, 대상 자원, 행위, 결과, 이유 코드, 요청·세션 상관 식별자가 포함될 수 있다.

사람이 읽는 자유 문장만 남기면 자동 분석이 어렵다. 구조화된 필드와 안정된 사건 코드를 사용하고 상세 설명은 보조로 둔다. 필드 이름, 자료형, 허용값을 로그 스키마로 관리한다.

비밀번호, 개인키, 전체 세션 토큰, 결제 정보, 불필요한 개인정보와 요청 본문을 기록하지 않는다. 민감 식별자는 업무상 추적이 가능한 범위에서 가명화·마스킹할 수 있다. 디버그 모드가 운영에서 민감 데이터를 추가 기록하지 않는지 확인한다.

사용자 입력의 줄바꿈과 제어문자를 그대로 로그 문장에 넣으면 사건 경계를 위조하거나 파서를 혼란시킬 수 있다. 구조화된 로깅 API를 사용하고 길이·문자를 제한한다.

## 시각 동기화와 상관관계

서로 다른 시스템의 시각이 맞지 않으면 사건 순서를 잘못 판단한다. 신뢰할 수 있는 시각 동기화 체계를 운영하고 로그에는 시간대 또는 표준 시각 기준을 명시한다. 수집 시각과 발생 시각을 구분한다.

요청 상관 식별자는 사용자 요청이 게이트웨이, 여러 서비스, 데이터베이스를 지나갈 때 같은 흐름으로 연결하게 한다. 인증된 사용자 식별자, 세션 식별자의 안전한 파생값, 작업 식별자도 상관분석에 도움을 준다.

상관 식별자 자체가 접근 권한을 주는 비밀이 되지 않게 설계한다. 원래 세션 토큰 전체를 로그 상관값으로 쓰지 않는다.

## 수집과 전송

로그는 원천에만 두면 시스템 손상·장애 시 함께 사라지거나 공격자가 지울 수 있다. 중앙 수집기로 전달해 원본과 분석용 데이터를 분리하고 접근통제와 보존 정책을 적용한다.

    로그 생성
      → 로컬 버퍼와 형식 검증
      → 인증·보호된 전송
      → 중앙 수집
      → 파싱·정규화·품질 검사
      → 저장·색인
      → 규칙·상관·행동 분석
      → 경보·조사·대응

전송 실패 때 무한히 로컬 디스크를 채우지 않도록 버퍼 한도와 우선순위, 손실 경보를 둔다. 보안 중요 사건은 일반 디버그 로그보다 높은 보존 우선순위를 가질 수 있다.

로그 수집 계정은 원천 시스템을 변경할 광범위한 권한이 필요하지 않다. 수집 경로가 양방향 관리 통로가 되지 않게 최소 권한을 적용한다.

## 정규화와 데이터 품질

서로 다른 장비가 성공을 success, ok, 0처럼 다르게 표시할 수 있다. 정규화는 공통 필드와 값 체계로 변환해 검색과 상관분석을 가능하게 한다.

파서 오류로 필드가 뒤바뀌면 정상 사건이 공격처럼 보이거나 실제 경보를 놓친다. 로그 버전과 형식을 추적하고 표본 원문과 정규화 결과를 비교한다. 알 수 없는 사건을 조용히 버리지 말고 파싱 실패율을 감시한다.

중복 수집, 누락 구간, 시각 역전, 비정상 필드 증가도 품질 지표다. 수집량이 갑자기 0이 된 것은 보안 사건이 없다는 뜻이 아니라 수집 장애일 수 있다.

## 로그 무결성과 보존

로그 생성자와 분석자의 권한을 분리하고 기록 수정·삭제를 제한한다. 전송 보호, 접근 감사, 해시 연결이나 서명, 변경 불가능 저장 기능을 위험에 따라 사용할 수 있다.

보존 기간은 법적·업무·사고 조사 요구와 개인정보 최소화, 저장 비용을 함께 고려한다. 무조건 영구 보존하면 민감정보와 공격 표면이 커진다. 삭제 시점과 법적 보존 예외를 문서화한다.

원본 로그, 정규화 로그, 분석 결과의 보존 목적이 다를 수 있다. 사고 증거로 사용할 원본은 파싱 과정에서 변경하지 않고 출처·수집 시각·무결성 정보를 유지한다.

## 로그 분석의 단계

1. 분석 목적과 기간, 시스템·계정 범위를 정한다.
2. 경보 또는 현상을 확인하고 사건 시각 기준을 통일한다.
3. 관련 원천의 수집 상태와 누락·파서 오류를 점검한다.
4. 알려진 정상 변경·점검·배치 일정과 비교한다.
5. 주체·주소·장치·상관 ID로 전후 사건을 연결한다.
6. 정상 기준선과 비교해 빈도·순서·대상·결과의 이상을 찾는다.
7. 원문 증거로 정규화 결과와 경보 조건을 검증한다.
8. 영향 자산과 계정, 성공한 행위를 구분한다.
9. 대응팀에 근거·불확실성·권고 조치를 전달한다.
10. 탐지 규칙과 로그 품질 개선 사항을 반영한다.

경보 발생 자체를 침해 확정으로 보지 않는다. 오탐을 확인하되 조사 전에 자동으로 무시 목록을 넓히지 않는다. 같은 경보가 반복되면 정상인지, 통제되지 않은 위험인지 근본 원인을 찾는다.

## 기준선과 이상 탐지

기준선은 사용자·서비스·시스템의 정상 시간, 빈도, 대상, 데이터량, 오류율을 나타낸다. 새 시스템 배포와 업무 성수기에는 기준이 바뀔 수 있어 주기적으로 갱신한다.

예를 들어 백업 계정의 대량 읽기는 정해진 시간과 대상에서는 정상일 수 있지만 평소와 다른 서버·시간·명령이면 조사 대상이다. 단일 임계값보다 주체·역할·자산 중요도를 함께 본다.

이상 탐지는 알려진 패턴을 찾는 규칙 기반과 정상 행위에서 벗어난 정도를 보는 행동 기반으로 나눌 수 있다. 규칙은 설명이 쉽지만 새로운 변형을 놓칠 수 있고, 행동 기반은 알려지지 않은 변화를 찾을 수 있지만 오탐과 학습 데이터 편향을 관리해야 한다.

## 상관분석 예시

다음 사건 흐름을 방어적으로 분석한다.

    09:10 새 장치에서 인증 실패 여러 번
    09:14 같은 계정의 강한 인증 성공
    09:16 평소 없는 권한 조회
    09:18 중요 보고서 대량 다운로드 요청
    09:19 데이터 유출 방지 정책에서 일부 차단

한 사건만으로 결론 내리지 않는다. 사용자의 출장·장치 교체 여부, 다중요소 방식, 다운로드 업무 사유, 차단된 것과 성공한 데이터량을 확인한다. 필요하면 세션을 제한하고 사용자·자원 소유자에게 검증하며 관련 증거를 보존한다.

규칙은 “실패 n회” 하나보다 새 장치, 성공 전환, 고권한 행위, 대량 접근의 시간 관계를 결합한다. 값 n은 환경 규모와 정상 패턴을 측정해 조정한다.

## 보안 솔루션의 개념

**보안 솔루션**은 특정 위험을 예방·탐지·차단·조사·복구하도록 지원하는 기술과 운영 체계다. 장비를 설치했다고 보안이 자동 완성되지 않는다. 정책, 자산 범위, 정확한 배치, 로그, 담당자와 대응 절차가 함께 있어야 한다.

솔루션을 평가할 때 보호 대상, 통제 위치, 탐지·차단 방식, 암호화된 트래픽 처리, 우회 경로, 성능·가용성, 오탐·미탐, 운영 인력, 연동·증거를 본다.

## 네트워크·경계 보안 솔루션

방화벽은 주소·포트·프로토콜·연결 상태 등의 정책으로 네트워크 흐름을 허용·차단한다. 응용 내용을 깊이 이해하는 기능을 제공할 수도 있지만 제품별이다. 기본 거부와 업무 흐름별 최소 규칙, 예외 만료가 중요하다.

침입 탐지 시스템(IDS)은 관찰한 트래픽·행위에서 공격 징후를 찾아 경보하고, 침입 방지 시스템(IPS)은 통신 경로에서 탐지 후 차단까지 수행한다. 차단 모드는 오탐이 정상 서비스를 중단할 수 있어 검증과 우회·가용성 설계가 필요하다.

웹 애플리케이션 방화벽(WAF)은 웹 요청·응답의 규칙과 행동을 분석해 알려진 위험 입력과 비정상 사용을 제한한다. 안전한 코딩과 객체 단위 인가를 대신하지 않는다. 암호화된 통신을 분석하려면 복호화 위치와 키·개인정보 보호를 설계해야 한다.

가상 사설망(VPN) 등 안전한 통신 기술은 원격 구간 보호를 제공하지만 접속 후 내부 전체를 자동 신뢰하지 않는다. 사용자·장치 인증과 자원별 접근정책을 결합한다.

## 단말·서버 보안 솔루션

악성코드 방지 도구는 알려진 서명과 행위로 위험 파일·프로세스를 탐지·차단한다. 엔드포인트 탐지·대응(EDR)은 단말 행위를 더 폭넓게 수집하고 조사·격리·대응을 지원한다.

에이전트가 비활성화되거나 정책이 오래되면 보호가 약해진다. 설치율, 정책 적용, 엔진·정보 갱신, 경보 연결과 격리 시험을 확인한다. 높은 권한을 가진 에이전트 자체의 보안과 가용성도 중요하다.

호스트 침입 방지, 파일 무결성 감시, 응용 허용 목록은 서버 변경과 실행을 통제할 수 있다. 정상 배포와 충돌하지 않도록 변경 시스템과 연동하고 비상 우회는 승인·만료·감사를 둔다.

## 접근·정보 보호 솔루션

통합 계정·접근 관리(IAM)는 사용자와 역할, 인증·인가 생명주기를 관리한다. 특권 접근 관리(PAM)는 관리자 권한 요청·승인·짧은 자격 증명·세션 감사를 지원한다. 도구가 있어도 공유 계정과 영구 최고 권한을 방치하면 목적을 달성하지 못한다.

네트워크 접근 제어(NAC)는 접속 주체와 장치 상태를 확인해 네트워크 접근을 제한할 수 있다. 장치 검사 실패 때 격리·치료 구역을 제공하고 업무 중단 정책을 정한다.

데이터 유출 방지(DLP)는 중요 데이터의 저장·사용·전송 경로를 식별해 정책 위반을 탐지·차단한다. 데이터 분류와 정확한 패턴, 예외 업무가 필요하다. 암호화·압축·이미지 등 가시성 한계와 개인정보 처리 자체의 위험을 고려한다.

디지털 권한 관리, 데이터베이스 활동 모니터링, 키 관리 시스템 등도 보호 대상에 맞게 조합한다. 하나의 솔루션이 모든 데이터 흐름을 볼 수 있다고 가정하지 않는다.

## 통합 분석과 자동 대응

보안 정보·이벤트 관리(SIEM)는 여러 원천 로그를 수집·정규화·상관분석하여 검색, 경보, 보고를 지원한다. 수집하지 않는 자산과 잘못 파싱된 필드는 분석되지 않는다. 사용 사례별 필요한 로그와 품질을 먼저 정의한다.

보안 자동화·대응 체계(SOAR)는 반복 조사와 대응 절차를 플레이북으로 자동화할 수 있다. 자동 계정 잠금·호스트 격리는 영향이 크므로 승인 단계, 오탐 복구, 실행 권한, 감사와 안전 중단을 둔다.

위협 인텔리전스는 알려진 악성 지표와 행위 정보를 제공할 수 있지만 맥락·시효·신뢰도를 평가한다. 오래되거나 공유 인프라 지표를 무조건 차단하면 정상 서비스를 방해할 수 있다.

## 솔루션 선정과 배치 절차

1. 자산·데이터 흐름과 우선 위험, 통제 목표를 정한다.
2. 현재 예방·탐지·대응 공백과 중복을 분석한다.
3. 기능·성능·가용성·암호화 가시성·운영 인력을 요구사항으로 만든다.
4. 실제 정상·악성 모의 시나리오로 후보를 검증한다.
5. 최소 권한 계정, 관리망, 고가용성, 로그 연동을 설계한다.
6. 탐지 모드에서 기준선과 오탐을 조정한 뒤 차단을 단계 적용한다.
7. 담당자, 경보 심각도, 대응 시간, 예외·변경 절차를 정한다.
8. 설치율·정책 적용·수집 품질·대응 결과를 지속 측정한다.

제품 기능표가 길다는 이유로 선택하지 않는다. 기존 도구와의 통합, 분석가가 처리할 경보량, 지원 종료와 데이터 이동 가능성까지 총 소유 비용을 본다.

## 방어 중심 의사결정 예시

    경보 수신
      → 로그 수집 상태와 시각 확인
      → 경보 규칙·원문 증거 검증
      → 자산 중요도와 성공 행위 여부 평가
      → 낮은 위험: 기록·규칙 조정 후보
      → 중간 위험: 사용자·소유자 확인, 추가 수집
      → 높은 위험: 승인된 플레이북으로 세션·호스트 제한
      → 증거 보존, 원인 제거, 복구와 사후 개선

차단 결정을 경보 점수 하나에만 맡기지 않고 자산·행위·확신도와 영향 범위를 본다. 긴급 대응 뒤에는 정상 업무 복구와 오탐 원인을 검토한다.

## 자주 틀리는 포인트

- 로그는 사건의 기록이지만 누락·위조·시각 오류 가능성이 있어 여러 원천을 검증한다.
- 수집량 0은 사건 0이 아니라 수집 장애일 수 있다.
- 발생 시각과 수집 시각, 시간대를 구분한다.
- 로그에 전체 세션 토큰과 비밀번호를 남기지 않는다.
- 경보 한 건을 침해 확정으로 보지 않고 원문·맥락·정상 변경을 확인한다.
- 기준선은 고정값이 아니라 업무·시스템 변화에 맞춰 갱신한다.
- IDS는 주로 탐지, IPS는 통신 경로에서 차단까지 수행하는 관점으로 구분한다.
- WAF는 안전한 코딩과 서버의 객체 단위 인가를 대신하지 않는다.
- VPN 접속 뒤 내부 모든 자원을 허용하는 것은 최소 권한이 아니다.
- 보안 솔루션 설치와 실제 정책 적용·경보 대응은 다른 단계다.
- 자동 대응은 오탐 시 큰 장애를 만들 수 있어 승인·복구·감사가 필요하다.
- SIEM의 분석 품질은 원천 로그와 파서·시각·필드 품질에 의존한다.

## 확인 문제

1. 보안 로그가 답해야 할 핵심 질문을 다섯 가지 쓰라.
2. 운영체제·응용·인증·네트워크 로그가 제공하는 서로 다른 증거를 설명하라.
3. 구조화 로그와 상관 식별자가 분석에 유리한 이유는 무엇인가?
4. 로그 시각 동기화와 원본 무결성이 사고 조사에 중요한 이유를 설명하라.
5. 로그 분석의 범위 설정부터 대응 전달까지 절차를 쓰라.
6. 규칙 기반 탐지와 행동 기반 탐지의 장단점을 비교하라.
7. 방화벽, IDS, IPS, WAF의 통제 위치와 역할을 구분하라.
8. EDR, IAM/PAM, DLP의 보호 대상을 각각 설명하라.
9. SIEM과 SOAR의 역할과 한계를 비교하라.
10. 보안 솔루션을 선정·배치할 때 기능 외에 판단할 기준을 다섯 가지 쓰라.

## 정답과 해설

1. 시각, 시스템, 주체, 출발·목적, 대상 자원, 행위, 결과, 전후 관련 사건과 정상 기준 차이를 묻는다.
2. 운영체제는 로그인·프로세스·파일, 응용은 업무 행위와 객체, 인증은 신원·요소·권한 변화, 네트워크는 시스템 간 연결과 허용·거부 증거를 제공한다.
3. 구조화 필드는 자동 검색·집계가 가능하고, 상관 식별자는 여러 서비스를 지난 동일 요청의 사건을 연결한다.
4. 시각이 다르면 순서를 오판하고, 원본이 변조되면 증거 신뢰가 무너진다. 동기화·접근 분리·무결성 정보로 신뢰도를 높인다.
5. 목적·기간·범위 설정, 수집 품질 확인, 기준선·정상 변경 비교, 주체·시각 상관, 원문 검증, 영향 평가, 대응 전달, 규칙 개선 순이다.
6. 규칙 기반은 설명과 알려진 패턴 탐지에 강하지만 새로운 변형을 놓친다. 행동 기반은 미지 변화를 찾을 수 있으나 오탐과 학습 기준 관리가 필요하다.
7. 방화벽은 네트워크 흐름 정책, IDS는 관찰 후 탐지, IPS는 경로상 탐지·차단, WAF는 웹 요청·응답의 응용 계층 보호에 초점을 둔다.
8. EDR은 단말·서버 행위 탐지와 격리, IAM/PAM은 일반·특권 계정과 접근 생명주기, DLP는 중요 데이터의 저장·사용·전송 정책을 다룬다.
9. SIEM은 로그 수집·정규화·상관·검색을, SOAR는 조사·대응 플레이북 자동화를 지원한다. 전자는 원천 품질, 후자는 오탐과 자동 조치 영향에 주의한다.
10. 성능·가용성, 암호화 트래픽 가시성, 오탐·미탐, 운영 인력, 기존 연동, 관리 권한, 데이터 보존, 총비용과 복구 절차를 본다.

## 핵심 요약

- **로그 분석**은 신뢰 가능한 시각·주체·대상·행위·결과 필드를 여러 원천에서 수집하고 정규화해 상관관계를 찾는 과정이다.
- 로그의 누락·파서 오류·민감정보와 무결성·보존을 관리하고 경보를 원문과 정상 기준으로 검증한다.
- **보안 솔루션**은 경계, 네트워크, 웹, 단말, 계정, 데이터, 통합 분석 계층에서 서로 다른 통제 목표를 지원한다.
- IDS/IPS, WAF, EDR, IAM/PAM, DLP, SIEM/SOAR의 역할과 한계를 구분하고 한 제품을 만능 통제로 보지 않는다.
- 기능표보다 자산 위험, 배치 위치, 가용성, 오탐, 운영 인력과 대응 절차를 기준으로 선정한다.
- 자동 차단·대응에는 승인, 안전 중단, 복구와 감사를 두고 탐지 결과를 지속 개선한다.
