## 1. 품질정보체계의 기본 구조

### 품질정보란 무엇인가

품질정보는 품질에 관한 의사결정에 사용할 수 있도록 수집·가공·분류·분석된 데이터야. 검사 결과, 공정조건, 부적합 건수, 고객불만, 공급자 평가처럼 각각 흩어진 기록은 원시 데이터에 가깝고, 이를 품질목표와 비교하거나 개선 우선순위를 결정할 수 있게 정리하면 품질정보가 돼.

예를 들어 월간 부적합품 수 120개라는 값만으로는 상태를 정확히 판단하기 어려워. 총생산량 10만 개, 목표 부적합률 0.08%, 실제 부적합률 0.12%, 전월 대비 0.03%p 증가라는 맥락이 붙어야 관리자가 목표 달성 여부와 조치 필요성을 판단할 수 있어.

따라서 품질정보체계는 다음 흐름을 연결해야 해.

**품질전략 → 품질목표 → 필요한 정보 → 수집과 검증 → 분류와 분석 → 평가 → 개선조치 → 효과 확인**

이 연결이 끊기면 정보는 많지만 의사결정에는 도움이 되지 않는 정보 과잉 상태가 돼.

### 품질전략과 품질목표

**품질전략**은 고객과 시장의 요구를 충족하기 위해 조직이 장기적으로 선택한 품질 방향이야. 고객불만 최소화, 초기품질 안정화, 공급망 품질 강화가 대표적인 예야.

**품질목표**는 품질전략을 측정 가능한 값으로 바꾼 것이야. 목표에는 일반적으로 지표, 목표값, 기간, 적용범위와 책임자가 포함돼야 해.

| 구분 | 예시 |
|---|---|
| 품질전략 | 고객이 신뢰하는 무결점 제품을 공급한다 |
| 품질목표 | 연말까지 고객불만률을 0.15% 이하로 낮춘다 |
| 평가 지표 | 고객불만 건수 ÷ 출하수량 × 100 |
| 필요한 정보 | 출하수량, 불만 건수, 불만 유형, 발생 제품, 원인, 조치 결과 |
| 개선 연결 | 반복 불만 유형의 원인 제거와 효과 확인 |

“품질을 향상한다”는 문장은 방향은 나타내지만 평가 기준이 없어서 온전한 품질목표가 아니야. 반면 “2026년 4분기까지 공정불량률을 1.2% 이하로 낮춘다”는 대상, 지표, 목표값과 기한이 드러나므로 평가할 수 있어.

## 2. 품질정보 분류 체계 정립

### 분류 체계의 목적

분류 체계는 정보를 일정한 기준에 따라 구분하고 식별하는 규칙이야. 핵심 목적은 보관 자체가 아니라 다음 질문에 빠르게 답할 수 있게 만드는 데 있어.

1. 어떤 품질목표를 평가하는 정보인가?
2. 어느 제품·공정·조직에서 발생했는가?
3. 결과를 나타내는 정보인가, 원인을 찾는 정보인가?
4. 누가 생성하고 검토하며 사용하는가?
5. 어떤 조치와 효과 확인으로 연결되었는가?

좋은 분류 체계는 같은 사건을 담당자마다 다르게 입력하지 않게 하고, 여러 부서의 정보를 같은 기준으로 비교할 수 있게 해. 반대로 분류 항목이 지나치게 많으면 입력 부담과 오분류가 증가하고, 지나치게 적으면 원인 분석에 필요한 세부 차이가 사라져.

### 품질정보의 대표적 분류 축

품질정보는 하나의 축만으로 분류하기보다 목적에 맞는 여러 축을 조합하는 것이 효과적이야.

| 분류 축 | 주요 분류 | 활용 목적 |
|---|---|---|
| 정보 발생원 | 고객, 설계, 구매, 공급자, 공정, 검사, 출하, 서비스 | 정보가 발생한 위치 확인 |
| 품질 단계 | 기획, 설계, 조달, 제조, 검사, 출하, 사용 | 제품수명주기별 문제 추적 |
| 정보 성격 | 예방, 감시, 평가, 실패, 개선 | 예방과 사후관리의 균형 평가 |
| 시간 기준 | 실시간, 일간, 주간, 월간, 분기, 연간 | 보고 및 조치 주기 결정 |
| 중요도 | 치명, 중대, 경미 | 대응 우선순위 결정 |
| 정보 형태 | 정량, 정성 | 통계분석 또는 내용분석 선택 |
| 관리 상태 | 접수, 검토, 분석, 조치 중, 종결 | 처리 진행상태 추적 |
| 공개 수준 | 일반, 내부, 대외비, 개인정보 포함 | 접근권한과 보안수준 결정 |

**정량정보**는 불량률, 공정능력지수, 납기 준수율처럼 수치로 표현되는 정보야. 비교와 추세 분석에는 유리하지만 숫자만으로 현장의 맥락을 모두 설명하지 못할 수 있어.

**정성정보**는 고객의 불만 내용, 작업자의 관찰, 심사 지적사항처럼 문장이나 범주로 표현되는 정보야. 원인의 단서를 제공하지만 분류 기준이 모호하면 해석자에 따라 결과가 달라질 수 있어.

따라서 고객불만을 관리할 때는 불만 건수와 불만률 같은 정량정보뿐 아니라 불만 유형, 사용환경, 고객 진술과 재현 여부 같은 정성정보도 함께 관리해야 해.

### 분류 체계 정립 절차

#### 1단계: 품질전략과 품질목표 확인

먼저 조직이 무엇을 달성하려는지 확인해야 해. 품질목표와 연결되지 않는 정보를 무조건 많이 수집하면 관리비용만 증가할 수 있어.

#### 2단계: 정보 이용자와 의사결정 확인

경영자는 목표 달성도와 위험 추세를 필요로 하고, 품질부서는 원인과 시정조치 상태를 필요로 하며, 현장 관리자는 설비·작업조건별 이상 정보를 필요로 해. 이용자와 의사결정이 다르면 정보의 상세 수준과 제공 주기도 달라져야 해.

#### 3단계: 필요한 정보항목 도출

각 품질목표를 계산하고 원인을 분석하는 데 필요한 항목을 정해. 항목명, 정의, 단위, 데이터 출처, 수집주기, 책임자와 사용목적을 함께 규정하는 것이 좋아.

#### 4단계: 분류 축과 코드 설계

제품, 공정, 결함유형, 중요도, 발생시점과 상태를 코드화해. 이때 하나의 코드에는 하나의 의미만 부여하고, 중복되거나 경계가 겹치는 항목을 피해야 해.

#### 5단계: 분류 기준과 판정 사례 작성

“중대결함”처럼 해석이 달라질 수 있는 용어는 정의와 사례를 함께 제시해야 해. 경계 사례의 판정 원칙도 정해야 담당자별 편차를 줄일 수 있어.

#### 6단계: 시범 적용과 적합성 검토

실제 자료를 표본으로 분류해 보고 미분류, 중복분류와 오분류가 얼마나 발생하는지 확인해. 현장에서 자주 “기타”로 입력되는 정보가 있다면 필요한 분류가 빠졌을 가능성이 있어.

#### 7단계: 승인과 변경관리

분류표에 문서번호, 제정일, 개정번호, 승인자와 적용일을 부여해 공식화해. 새로운 제품이나 결함이 추가될 때 누구의 승인을 받아 어떻게 개정하는지도 정해야 해.

### 구체적 예시: 고객불만 감소 전략

회사가 고객불만률을 0.15% 이하로 낮추려 한다고 가정해 보자. 품질정보는 다음과 같이 분류할 수 있어.

| 대분류 | 중분류 | 세부분류 예시 |
|---|---|---|
| 제품 | 제품군 | A형, B형, C형 |
| 불만 현상 | 기능, 외관, 치수, 포장 | 작동 불량, 흠집, 치수 초과, 포장 파손 |
| 발생 단계 | 제조, 운송, 사용 | 조립공정, 물류센터, 고객 사용 |
| 중요도 | 치명, 중대, 경미 | 안전 영향, 기능 상실, 미관 영향 |
| 원인 | 사람, 설비, 재료, 방법, 측정, 환경 | 작업 오류, 설비 마모, 자재 편차 |
| 처리 상태 | 접수, 분석, 조치, 효과 확인, 종결 | 현재 진행상태 |
| 재발 여부 | 신규, 반복 | 동일 원인의 과거 발생 여부 |

이 구조라면 불만 건수만 세는 데 그치지 않고 “B형 제품의 포장 파손이 특정 물류구간에서 반복된다”는 개선 단서를 찾을 수 있어.

## 3. 품질정보와 품질보증 개선의 연결

### 품질보증 업무의 의미

품질보증은 제품이나 서비스가 규정된 품질요구사항을 충족할 것이라는 신뢰를 제공하기 위한 계획적이고 체계적인 활동이야. 최종검사만 강화하는 활동이 아니라 설계검토, 공급자 관리, 공정관리, 검사, 부적합 관리, 시정조치와 고객 대응을 포함해.

품질정보는 품질보증 활동이 실제로 효과가 있었는지를 보여주는 증거가 돼. 예를 들어 검사 강화 후 검출 불량은 감소했지만 고객불만이 그대로라면 검사 위치나 검사기준이 실제 고장 형태와 맞지 않을 수 있어.

### 개선 필요사항 도출 논리

개선 필요사항은 다음 네 가지 비교에서 주로 발견돼.

1. **목표와 실적의 차이**: 실제 불량률이 목표를 초과했는가?
2. **현재와 과거의 차이**: 악화 추세나 급격한 변동이 있는가?
3. **조직 간 차이**: 특정 공정·라인·공급자에서 문제가 집중되는가?
4. **조치 전후의 차이**: 시정조치 후 재발률이 실제로 감소했는가?

중요한 것은 목표 미달을 곧바로 작업자 과실로 결론 내리지 않는 거야. 측정방법이 달라졌거나 생산구성이 바뀌었을 수도 있고, 분모가 작은 상태에서 비율이 크게 변했을 수도 있어. 정보의 정의와 신뢰성을 확인한 뒤 원인을 판단해야 해.

### 선행지표와 후행지표

**후행지표**는 이미 발생한 결과를 보여줘. 고객불만률, 반품률과 최종불량률이 여기에 해당해.

**선행지표**는 미래의 품질문제를 미리 알려주는 조건을 보여줘. 설비 이상 발생률, 예방보전 준수율, 공정조건 이탈 건수와 교육 이수율이 예가 될 수 있어.

후행지표만 관리하면 문제가 발생한 뒤 대응하게 돼. 반대로 선행지표만 관리하면 실제 고객성과가 좋아졌는지를 놓칠 수 있어. 그래서 품질정보 분류 체계에는 두 종류를 함께 포함해야 해.

## 4. 품질정보 운영 절차 작성

> 학습목표: 정립된 품질정보의 분류 체계에 따라 품질정보 운영 절차 및 기준을 작성할 수 있다.

### 운영 절차에 포함할 핵심 항목

품질정보 운영 절차서는 누가, 무엇을, 언제, 어떤 방법으로 처리하는지를 명확하게 규정해야 해.

| 절차 항목 | 규정할 내용 |
|---|---|
| 목적 | 품질정보를 운영하는 이유 |
| 적용범위 | 대상 조직, 제품, 공정과 정보 |
| 용어 정의 | 불량, 부적합, 중대도 등 |
| 책임과 권한 | 작성, 검토, 승인, 조치 책임자 |
| 정보 수집 | 정보원, 항목, 방식과 주기 |
| 등록과 분류 | 코드, 등급, 상태와 등록기한 |
| 검증 | 정확성, 완전성, 유효성 확인 |
| 분석과 평가 | 지표 산식, 목표값과 판정주기 |
| 보고와 공유 | 보고 대상, 형식, 주기와 긴급보고 조건 |
| 개선조치 | 원인분석, 시정조치와 책임기한 |
| 효과 확인 | 조치 전후 비교와 종결조건 |
| 보관과 폐기 | 보존기간, 접근권한과 폐기방법 |
| 변경관리 | 기준 개정, 승인과 교육방법 |

### 표준 운영 흐름

**발생·수집 → 등록 → 분류 → 검증 → 집계·분석 → 목표 대비 평가 → 보고 → 개선조치 → 효과 확인 → 종결·보관**

각 단계에는 입력, 처리책임자, 출력과 완료기준이 있어야 해.

예를 들어 고객불만 정보의 운영 절차는 다음과 같이 작성할 수 있어.

1. 고객지원 담당자는 불만 접수 후 24시간 이내에 시스템에 등록한다.
2. 등록 시 제품코드, 제조번호, 불만유형, 중요도와 발생일을 필수 입력한다.
3. 품질담당자는 중복 여부와 입력 누락을 검증한다.
4. 안전에 영향을 줄 수 있는 치명 불만은 즉시 품질책임자에게 보고한다.
5. 원인 부서는 정해진 기한 안에 원인을 분석하고 시정조치안을 등록한다.
6. 품질부서는 조치 후 일정 기간의 재발 여부와 관련 지표를 확인한다.
7. 효과가 입증된 경우 승인권자가 종결하며, 미흡하면 추가 조치를 요구한다.
8. 종결된 기록은 정해진 보존기간과 보안등급에 따라 관리한다.

### 운영 기준을 수치화하는 방법

절차만 있고 기준이 없으면 담당자가 같은 상황을 다르게 처리할 수 있어. 따라서 가능한 항목은 측정 가능하게 작성해야 해.

| 모호한 표현 | 개선된 기준 |
|---|---|
| 신속히 등록한다 | 발생 또는 접수 후 24시간 이내 등록한다 |
| 중요한 문제를 보고한다 | 안전 영향 또는 출하중단 가능성이 있는 치명등급은 즉시 보고한다 |
| 정기적으로 분석한다 | 매월 5영업일까지 전월 실적을 집계한다 |
| 장기간 보관한다 | 승인된 기록을 종결일로부터 5년간 보관한다 |
| 적절히 검토한다 | 필수항목 누락, 중복등록, 단위 오류를 검토자가 확인한다 |

기준의 숫자는 조직의 계약조건, 법적 요구사항, 제품 위험도와 내부 규정에 맞춰 정해야 해. 무조건 짧은 기한이나 긴 보존기간을 쓰는 것이 좋은 기준은 아니야.

### 책임과 권한의 구분

**작성자**는 정보를 최초로 기록해. **검토자**는 정확성과 완전성을 확인해. **승인자**는 공식 사용이나 종결을 허가해. 이 역할을 구분하면 자기검증으로 인한 오류와 임의 종결 위험을 줄일 수 있어.

작은 조직에서는 한 사람이 여러 업무를 맡을 수 있지만, 중요한 품질판정이나 조치 종결에서는 독립적인 검토가 확보되도록 설계하는 것이 좋아.

## 5. 비교와 적용 경계

### 분류 체계와 운영 절차의 차이

| 구분 | 품질정보 분류 체계 | 품질정보 운영 절차 |
|---|---|---|
| 핵심 질문 | 이 정보는 무엇에 해당하는가? | 이 정보를 어떻게 처리할 것인가? |
| 주요 내용 | 분류 축, 코드, 명칭, 정의 | 순서, 책임, 기한, 방법, 판정기준 |
| 대표 산출물 | 정보분류표, 코드표, 데이터 사전 | 절차서, 업무흐름도, 기록양식 |
| 주요 위험 | 중복·누락·모호한 경계 | 책임 누락·처리 지연·종결 기준 부재 |

분류 체계만 있으면 정보가 정돈되지만 조치가 진행되지 않을 수 있어. 운영 절차만 있으면 처리 순서는 존재하지만 동일한 문제를 서로 다른 이름으로 기록할 수 있어. 두 요소가 함께 작동해야 품질정보체계가 완성돼.

### 품질정보와 품질기록의 차이

**품질기록**은 활동이 수행되었거나 결과가 발생했다는 객관적 증거야. 검사성적서, 심사보고서와 시정조치 기록이 여기에 해당해.

**품질정보**는 이러한 기록과 데이터를 의사결정에 사용할 수 있게 가공한 결과야. 하나의 품질기록이 품질정보의 입력이 될 수 있지만 둘이 항상 같은 것은 아니야.

### 적용 경계

정보 분류를 정교하게 만드는 것 자체가 목적이 되어서는 안 돼. 분류항목을 늘릴 때는 그 항목이 품질목표 평가, 원인분석, 법적 추적성 또는 개선조치에 실제로 사용되는지 확인해야 해.

또한 개인정보, 고객기밀과 설계정보가 포함된다면 일반 품질정보와 동일한 권한으로 공유해서는 안 돼. 정확성뿐 아니라 기밀성, 무결성과 가용성도 운영 기준에 반영해야 해.

## 6. 실무 작성 예시

### 품질정보 분류표 예시

| 정보명 | 분류 | 목적 | 발생원 | 단위·형식 | 주기 | 책임자 | 중요도 |
|---|---|---|---|---|---|---|---|
| 공정불량률 | 공정·평가정보 | 공정 품질목표 평가 | 생산·검사 | % | 일간·월간 | 공정품질 담당자 | 중대 |
| 고객불만률 | 고객·실패정보 | 고객만족 목표 평가 | 고객지원 | % | 월간 | 고객품질 담당자 | 중대 |
| 설비조건 이탈 | 공정·예방정보 | 불량 발생 가능성 감시 | 생산설비 | 건수 | 실시간 | 생산 담당자 | 중대 |
| 시정조치 재발률 | 개선·평가정보 | 조치 효과 확인 | 품질시스템 | % | 분기 | 품질보증 담당자 | 중대 |

### 품질정보 운영 절차서 예시

**목적:** 품질목표의 달성도를 객관적으로 평가하고 품질보증 업무의 개선 필요사항을 적시에 도출한다.

**적용범위:** 제품의 설계, 구매, 제조, 검사, 출하와 고객대응 과정에서 생성되는 품질정보에 적용한다.

**수집:** 각 정보 생성부서는 승인된 양식과 시스템을 사용해 지정된 기한 안에 정보를 등록한다.

**검증:** 검토자는 필수항목 누락, 단위, 중복, 이상치와 원자료 일치 여부를 확인한다.

**분류:** 검증된 정보에는 제품, 공정, 정보성격, 중요도, 발생일과 처리상태 코드를 부여한다.

**평가:** 품질부서는 정해진 산식에 따라 지표를 계산하고 목표값, 전기 실적과 추세를 비교한다.

**보고:** 목표 초과, 치명등급 또는 급격한 악화가 발견되면 정기보고를 기다리지 않고 책임자에게 보고한다.

**조치:** 담당 부서는 원인분석, 시정조치, 완료기한과 책임자를 등록한다.

**효과 확인:** 품질부서는 조치 후 지표 변화와 재발 여부를 확인하고 효과가 입증된 경우에만 종결을 승인한다.

**보관:** 기록은 정보등급과 보존기간에 따라 보호하며 기간 만료 후 승인된 방법으로 폐기한다.

## 7. 시험 함정

### 함정 1: 품질목표와 품질방침을 혼동하기

“고객에게 최고의 품질을 제공한다”는 품질방침이나 전략적 방향에 가까워. 측정 가능한 지표, 목표값과 기한이 있어야 품질목표로 평가하기 쉬워.

### 함정 2: 수집 항목만 쓰고 분류 기준을 빠뜨리기

불량 건수, 검사 결과와 고객불만을 수집한다고 쓰는 것만으로 분류 체계가 완성되지는 않아. 발생원, 정보성격, 중요도, 제품·공정, 처리상태 같은 분류 기준이 필요해.

### 함정 3: 절차를 부서명만 나열하기

영업부, 품질부, 생산부처럼 담당 부서만 나열하면 업무 흐름이 드러나지 않아. 수집, 등록, 검증, 분석, 보고, 조치와 효과 확인의 순서를 제시해야 해.

### 함정 4: 개선조치 후 완료 처리하기

조치를 실행했다는 사실만으로 종결하면 안 돼. 지표 개선과 재발 여부를 통해 효과를 확인해야 해.

### 함정 5: 불량률의 분모를 쓰지 않기

불량률은 불량수량을 무엇으로 나누는지 명확해야 해. 검사수량, 생산수량 또는 출하수량에 따라 값과 의미가 달라져.

### 함정 6: 중요도와 발생빈도를 동일하게 보기

발생이 드물어도 안전에 영향을 주는 결함은 치명적일 수 있어. 빈도와 심각도는 별도 기준으로 평가해야 해.

### 함정 7: “기타” 분류를 무제한 허용하기

“기타” 비율이 높아지면 정보가 구체적인 개선 단서로 연결되지 않아. 기타 항목을 정기적으로 검토하고 반복되는 유형은 공식 분류로 추가해야 해.

## 9. 정답 및 해설

### 문제 1 정답: 2

품질정보는 품질목표를 평가하고 개선사항을 도출하기 위해 운영돼. 따라서 어떤 전략과 목표를 지원할 정보인지 먼저 정해야 해.

### 문제 2 정답: 4

발생원, 중요도와 처리상태는 여러 담당자가 일관되게 적용할 수 있는 분류 기준이야. 개인적 선호는 재현성과 객관성이 없어서 공식 분류 기준으로 사용할 수 없어.

### 문제 3 정답: 2

정보는 수집·등록된 뒤 분류와 검증을 거치고, 분석·평가 결과에 따라 조치돼. 조치가 끝난 뒤에는 효과를 확인해야 종결할 수 있어.

### 문제 4 해설

“신속하게”의 시간 한계가 없어 담당자마다 다르게 판단할 수 있어. “접수 후 24시간 이내 등록하고 치명등급은 즉시 품질책임자에게 보고한다”처럼 기한과 조건을 명시해야 해.

### 문제 5 정답: 효과 확인

조치를 실행했다는 사실과 문제가 해결되었다는 사실은 달라. 조치 전후 지표와 재발 여부를 확인해야 시정조치의 유효성을 판단할 수 있어.

### 문제 6 예시 답안

제품 또는 모델, 발생공정, 결함유형, 중요도, 발생일, 작업조, 설비, 자재 로트, 원인, 처리상태를 활용할 수 있어. 이 가운데 목적에 필요한 항목을 선택하되 각 항목의 정의와 코드 기준도 함께 정해야 해.

## 10. 요약

1. 품질정보체계는 **품질전략 → 품질목표 → 정보 수집 → 분류·분석 → 평가 → 개선 → 효과 확인**을 연결하는 구조야.
2. 품질정보 분류 체계는 발생원, 품질 단계, 정보 성격, 중요도, 형태와 처리상태 같은 기준으로 설계해.
3. 분류 항목은 서로 겹치지 않고 담당자가 동일하게 판정할 수 있도록 정의와 사례를 제공해야 해.
4. 품질정보 운영 절차에는 목적, 적용범위, 책임과 권한, 수집, 검증, 분류, 분석, 보고, 개선조치, 효과 확인, 보관과 변경관리가 포함돼야 해.
5. “신속히”나 “적절히” 같은 표현보다 기한, 산식, 보고조건과 종결조건을 측정 가능하게 규정해야 해.
6. 품질목표 미달은 개선의 신호지만, 원인을 판단하기 전에 데이터 정의와 신뢰성을 먼저 확인해야 해.
7. 시정조치는 실행으로 끝나지 않고 효과 확인과 재발 방지까지 완료되어야 해.
