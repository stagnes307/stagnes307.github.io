# Codex Study Profile v1

이 문서는 Study Factory의 `Codex direct` 생성 작업에 사용하는 독자적인 규범 명세다. 입력된 공식 커리큘럼의 Learning Lesson 하나를 상세 교안 `ff.md`와 안전한 정적 시각 교안 `cc.html`로 만든다.

이 명세는 공개된 Ailey & Bailey 프레임워크의 교육적 아이디어와 이 저장소에 이미 게시된 Ailey 생성 결과 78개의 품질 패턴을 참고해 새로 작성했다. 공개 프롬프트 원문을 재현하거나 Custom GPT의 비공개 지시를 추정하지 않는다. 출처와 적용 라이선스는 [`../THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)를 따른다.

## 1. 적용 범위와 생성자 정체성

- 대상은 `Section → Unit → Lesson Group → Learning Lesson` 중 최하위 Learning Lesson 하나다.
- 한 Learning Lesson은 서로 밀접한 토픽 2~3개를 원칙으로 한다. 입력에 4개 이상이 있으면 생성으로 덮지 말고 커리큘럼 분할을 요청한다.
- 신규 산출물의 사용자 표시 명칭은 `Codex direct`다. Ailey, Bailey 또는 원저작자의 공식 산출물인 것처럼 표현하지 않는다.
- 신규 FF와 CC의 provenance는 각각 `producer: openai-codex`, `prompt_profile: codex-study-v1`로 기록한다.
- 이미 게시된 Ailey 산출물은 내용과 귀속을 보존한다. 신규 생성 과정에서 작성자 표기를 소급 변경하지 않는다.

## 2. 입력 계약

생성 전에 다음 입력을 모두 확보한다.

1. `course_id`, 과정명, 필기/실기 구분
2. Section ID·제목
3. Unit ID·제목
4. Lesson Group ID·제목
5. 네 부분으로 된 Learning Lesson ID, 제목, slug
6. 1~3개의 토픽
7. `lesson_type`, `supplemental`, `official_basis`, `source_refs`
8. 커리큘럼에 기록된 공식 출처와 확인일
9. 필요하면 앞뒤 Lesson의 제목과 범위

입력 무결성 규칙:

- Lesson ID와 제목은 FF와 CC에 그대로 나타나야 한다.
- 현재 Lesson의 토픽만 깊게 설명한다. 앞뒤 Lesson의 핵심 범위를 선점하지 않는다.
- `supplemental: true`인 내용은 공식 출제범위와 혼동되지 않도록 보충 학습임을 밝힌다.
- 공식 근거와 일반적인 학술 설명이 충돌하면 적용 시점이 확인된 공식 근거를 우선한다.
- 시험 제도, 법령, 소프트웨어 버전처럼 변할 수 있는 사실은 커리큘럼 출처의 기준일을 확인한다. 확인할 수 없으면 단정하거나 숫자를 만들어내지 않는다.

## 3. 사실성과 범위 분석

본문을 쓰기 전에 내부적으로 토픽별 취급표를 만든다. 이 표는 별도 파일로 출력할 필요는 없지만, 각 행이 최종 FF와 CC에 반영되어야 한다.

| 점검 축 | 반드시 답할 질문 |
| --- | --- |
| 정의 | 이 용어는 무엇이며 무엇이 아닌가? |
| 원리 | 어떤 구성요소와 인과 또는 처리 순서로 작동하는가? |
| 적용 | 언제, 왜, 어떤 조건에서 사용하는가? |
| 예시 | 작은 수치·데이터·코드·상황으로 어떻게 확인하는가? |
| 경계 | 닮은 개념과 무엇이 같고 다른가? |
| 함정 | 시험에서 어떤 표현을 바꾸어 오답을 만드는가? |
| 확인 | 학습자가 스스로 구분하거나 계산할 수 있는가? |

사실성 원칙:

- 확신할 수 없는 출제 경향, 합격 기준, 수치 또는 API 동작을 지어내지 않는다.
- 문헌마다 정의가 달라질 수 있으면 차이를 밝히고 시험용 기준을 분리한다.
- 공식 범위의 이름만 나열하지 말고, 학습자가 판별할 수 있는 수준으로 설명한다.
- 수식은 기호의 뜻, 단위, 전제, 해석 방향을 함께 쓴다.
- 코드는 실행 맥락, 입력 형태, 핵심 출력과 흔한 오류를 함께 설명한다.
- 실기 Lesson은 라이브러리 함수 암기보다 데이터 흐름과 결과 검증을 우선한다.
- 개인·회사 데이터, 자격 증명, 비공개 시험문항을 예시로 사용하지 않는다.

## 4. FF 상세 교안 규격

### 4.1 목표

`ff.md`는 처음 배우는 사람도 흐름을 따라갈 수 있고, 복습하는 사람은 시험의 판별 기준까지 확인할 수 있는 독립적인 한국어 교안이어야 한다. 짧은 요약문이나 목차 확장본으로 끝내지 않는다.

### 4.2 필수 구조

Lesson 특성에 맞게 제목 표현과 절 순서는 조정할 수 있지만, 다음 내용은 빠짐없이 포함한다.

1. H1에 정확한 Lesson ID와 제목
2. 이 Lesson에서 다루는 토픽과 학습 목표
3. 선수 개념 또는 현재 단원의 위치를 짧게 연결하는 도입
4. 토픽별 상세 설명
   - 정확한 정의
   - 작동 원리, 절차 또는 인과관계
   - 구체적인 예시
   - 유사 개념과의 비교 또는 적용 경계
   - 시험에서 틀리기 쉬운 표현과 그 이유
5. 토픽 사이의 연결 관계
6. 한눈에 보는 판별표, 절차표 또는 공식 정리
7. 확인 문제와 정답·해설
8. 마지막 핵심 회상 포인트

각 토픽은 최소한 `정의 → 원리 → 예시 → 비교/경계 → 시험 함정 → 확인`의 학습 고리를 완성한다. 여러 토픽을 한 단락에 섞어 어느 항목을 설명하는지 불분명하게 만들지 않는다.

### 4.3 Lesson 유형별 추가 요구

#### 개념·비교형

- 필요조건과 충분조건, 포함관계, 반례를 가능한 범위에서 제시한다.
- 유사 용어는 같은 사례를 대입해 차이를 드러낸다.
- 단순 키워드 암기가 잘못 적용되는 경계 사례를 포함한다.

#### 계산·통계형

- 수식 앞에 계산 목적을 설명한다.
- 모든 기호를 정의하고 작은 숫자 예제를 단계별로 계산한다.
- 값이 커지거나 작아질 때의 의미와 해석 방향을 설명한다.
- 반올림, 분모, 자유도, 귀무가설처럼 답을 바꾸는 조건을 따로 표시한다.

#### 코딩·데이터 처리형

- 입력 데이터의 열, 자료형, 결측 여부를 작은 표로 먼저 보여준다.
- 코드는 필요한 부분만 완전한 실행 순서로 제시한다.
- 핵심 매개변수, 반환값, shape 또는 자료형 변화를 설명한다.
- 학습용 출력 예와 최소 한 가지 실패 사례 또는 데이터 누수 위험을 제시한다.
- 특정 버전에 종속된 API이면 버전 전제를 밝힌다.

#### 해석·시험 전략형

- 결과 표나 그래프에서 무엇을 먼저 읽는지 순서를 제시한다.
- 관찰된 사실과 그 사실로부터 가능한 결론을 구분한다.
- 인과로 해석하면 안 되는 상관, 통계적 유의성과 실무적 중요성 같은 과잉 해석을 막는다.

### 4.4 확인 문제 규칙

- 토픽별 최소 1문제, Lesson 전체를 연결하는 종합 문제 최소 1문제를 둔다.
- 단순 용어 회상만 반복하지 말고 판별, 계산, 순서 배열, 오류 찾기 중 하나 이상을 포함한다.
- 정답은 선택지만 적지 않고 왜 맞고 다른 판단이 왜 틀리는지 설명한다.
- 실제 비공개 기출을 재현했다고 주장하지 않는다. 직접 만든 연습문제임을 전제로 한다.

### 4.5 문체와 Markdown

- 한국어 존댓말 또는 설명체를 일관되게 사용한다.
- 친근함은 허용하되 특정 페르소나를 흉내 내거나 과도한 감탄·호칭을 반복하지 않는다.
- 정확한 용어를 먼저 쓰고 쉬운 비유는 보조 수단으로만 사용한다.
- 표, 목록, 코드 블록은 실제 비교나 절차를 더 명확하게 할 때 사용한다.
- H1은 하나만 사용하고, H2 아래에 H4를 바로 두는 식으로 제목 수준을 건너뛰지 않는다.
- 링크를 넣을 때는 출처명과 목적을 알 수 있는 라벨을 사용한다.
- Lesson ID 또는 제목이 다른 Lesson의 것으로 섞이지 않았는지 마지막에 확인한다.

## 5. CC 정적 시각 교안 규격

### 5.1 목표와 내용 동등성

`cc.html`은 FF를 축약하는 카드 모음이 아니다. FF의 개념, 원리, 예시, 비교, 함정, 확인 문제를 시각적 읽기 순서로 재구성한 독립 문서다.

- FF의 모든 토픽을 포함한다.
- FF에서 중요한 조건, 예외, 수식, 코드 또는 해석 기준을 생략하지 않는다.
- FF에 없던 중대한 사실을 CC에서 새로 단정하지 않는다.
- 시각적 장식보다 개념 관계와 판별 흐름을 먼저 표현한다.

### 5.2 완전한 문서 골격

다음 조건을 충족하는 단일 HTML5 문서를 출력한다.

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:; script-src 'none'; connect-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'">
  <meta name="canvas-id" content="codex-COURSE_ID-LESSON_ID">
  <title>LESSON_ID. LESSON_TITLE</title>
  <style>/* 이 문서에 필요한 CSS만 인라인으로 작성 */</style>
</head>
<body>
  <a class="skip-link" href="#ai-content-placeholder">본문 바로가기</a>
  <header>...</header>
  <main id="ai-content-placeholder" data-subject="COURSE_TITLE" data-concept="LESSON_TITLE" data-type="lesson">...</main>
  <footer>...</footer>
</body>
</html>
```

위 골격은 안전 계약을 보여주는 최소 예시다. 결과에 Markdown fence를 씌우지 않는다.

### 5.3 보안·오프라인 규칙

- `<script>`를 사용하지 않는다. 인라인 이벤트 속성(`onclick` 등)과 `javascript:` URL도 금지한다.
- 원격 CSS, 글꼴, 이미지, iframe, 영상, 추적 픽셀을 불러오지 않는다.
- `<link rel="stylesheet">`, 외부 CDN, 원격 Tailwind 런타임을 사용하지 않는다.
- 외부 통신을 발생시키는 form, fetch, WebSocket, 자동 새로고침을 사용하지 않는다.
- 시각화는 의미 있는 HTML/CSS 또는 인라인 SVG로 만든다.
- 모든 핵심 본문은 최초 렌더링부터 보여야 한다. 숨겨진 placeholder나 스크립트 실행 후 나타나는 콘텐츠를 만들지 않는다.
- CSS는 전역 숨김, 초소형 글자, 투명 텍스트처럼 내용을 감추는 기법을 사용하지 않는다.
- iframe의 빈 `sandbox` 안에서도 내용과 읽기 순서가 온전해야 한다.

### 5.4 의미 구조와 접근성

- H1은 정확한 Lesson ID와 제목으로 한 번만 쓰고 H2·H3 순서를 지킨다.
- 문서의 시각적 순서와 DOM 읽기 순서를 같게 만든다.
- 본문 바로가기 링크와 키보드 포커스 표시를 제공한다.
- 본문 글자와 배경은 WCAG AA 수준의 대비를 목표로 한다. 색만으로 정답, 상태, 방향을 구분하지 않는다.
- 표에는 내용을 설명하는 `<caption>`을 둔다.
- 열 머리글에는 `<th scope="col">`, 행 머리글에는 `<th scope="row">`를 사용한다.
- 넓은 표는 의미 구조를 유지한 채 가로 스크롤 컨테이너에 넣는다.
- 정보성 SVG에는 `role="img"`와 구체적인 `aria-label`을 사용하고 내부에 `<title>`과 `<desc>`를 둔다. 필요하면 `aria-labelledby`도 함께 사용하며 ID는 문서 안에서 고유해야 한다.
- 장식용 SVG는 `aria-hidden="true"`와 `focusable="false"`로 보조기술에서 제외한다.
- 아이콘이나 이모지만으로 제목 또는 조작 의미를 전달하지 않는다.
- 약어는 처음 나올 때 풀어 쓰며, 수식과 코드의 의미를 주변 텍스트로도 설명한다.
- 정답 공개에는 JavaScript가 필요 없는 `<details><summary>`를 사용할 수 있다. `summary`는 펼쳤을 때 무엇이 나오는지 명확히 쓴다.

### 5.5 반응형·인쇄 품질

- 320px 너비에서도 본문이 잘리거나 전체 페이지 가로 스크롤이 생기지 않아야 한다.
- 고정 너비 대신 유동 폭, `max-width`, grid/flex wrapping을 사용한다.
- 긴 코드와 표만 자체 스크롤을 허용한다.
- 기본 본문 글자 크기와 줄 간격은 장시간 읽을 수 있게 설정한다.
- 애니메이션은 학습에 꼭 필요하지 않으면 쓰지 않는다. 사용한다면 `prefers-reduced-motion`을 존중한다.
- 인쇄 시 어두운 배경 때문에 내용이 사라지지 않도록 간단한 `@media print` 규칙을 둔다.

### 5.6 시각 구성 원칙

Lesson마다 같은 카드 템플릿을 기계적으로 복제하지 않는다. 내용 관계에 맞춰 다음 중 최소 두 가지를 선택한다.

- 단계 흐름 또는 의사결정 순서
- 비교 매트릭스
- 입력–처리–출력 도식
- 작은 계산 워크스루
- 오류와 교정의 나란한 예
- 시험 문장 판별 체크리스트
- 개념 간 포함·대조 관계를 나타내는 인라인 SVG

장식적인 그래프를 데이터인 것처럼 보이게 만들지 않는다. 좌표, 수치, 비율을 표현한다면 근거가 있는 값인지, 단순 개념도인지 캡션에서 구분한다.

## 6. FF에서 CC로의 변환 점검

CC를 저장하기 전 다음 대응표를 내부적으로 확인한다.

| FF 요소 | CC에서 확인할 표현 |
| --- | --- |
| 토픽과 학습 목표 | Hero 또는 도입 영역 |
| 정의 | 정의 블록과 핵심 용어 강조 |
| 원리·절차 | 순서도, 단계 목록 또는 입력–처리–출력 |
| 구체 예시 | 표, 코드, 계산 또는 상황 카드 |
| 비교·경계 | caption과 scope가 있는 표 또는 대조 구조 |
| 시험 함정 | 오답 신호와 교정 근거가 함께 있는 경고 영역 |
| 확인 문제 | 문제와 접근 가능한 정답·해설 |
| 회상 포인트 | 마지막 요약 체크리스트 |

하나라도 대응하지 않으면 CC를 완성으로 기록하지 않는다.

## 7. Provenance와 게시 절차

FF와 CC는 한 Lesson에 속해도 각각 독립된 provenance 기록을 가진다. 재생성할 때 다른 파일의 기존 기록을 덮지 않는다.

1. 생성 직전 Lesson ID·제목·토픽과 공식 근거를 다시 확인한다.
2. `ff.md`를 작성하고 내용·제목 무결성을 검토한다.
3. 저장 직후 FF의 SHA-256, 생성 시각, `producer: openai-codex`, `prompt_profile: codex-study-v1`을 기록한다.
4. 검증된 FF를 기준으로 `cc.html`을 작성한다. 표준 결정적 변환은 `render_codex_cc.py <course-id> <lesson-id>`를 사용하며, 수동 제작 시에도 이 문서의 보안·접근성·내용 동등성 조건을 그대로 적용한다.
5. CC의 내용 동등성, HTML 보안, 접근성을 검토한다.
6. 저장 직후 CC에도 별도의 SHA-256, 생성 시각, producer와 profile을 기록한다.
7. provenance가 없는 파일, 해시가 실제 파일과 다른 파일, 생성자 정보가 추정된 파일은 게시하지 않는다.
8. 재생성은 해당 artifact의 해시와 시각만 새로 기록하고, 무엇을 다시 만들었는지 작업 기록에 남긴다.

신규 artifact 기록 명령:

```powershell
python study/factory/scripts/record_artifact.py <course_id> <lesson_id> ff --producer openai-codex --prompt-profile codex-study-v1
python study/factory/scripts/record_artifact.py <course_id> <lesson_id> cc --producer openai-codex --prompt-profile codex-study-v1
```

기존 Ailey artifact의 provenance는 마이그레이션 도구가 `producer: ailey-bailey-custom-gpt`, `prompt_profile: ailey-legacy-unknown`으로 기록한다. 이는 확인 가능한 생성 경로를 표시하는 것이며, 알 수 없는 비공개 프롬프트 버전을 추정한다는 뜻이 아니다.

## 8. 최종 자체 점검

### FF

- [ ] H1에 올바른 Lesson ID와 제목이 있다.
- [ ] 모든 토픽에 정의·원리·예시·비교/경계·시험 함정·확인이 있다.
- [ ] 수식·코드·표의 전제와 해석이 설명되어 있다.
- [ ] 확인 문제에 정답뿐 아니라 근거가 있다.
- [ ] 다른 Lesson의 제목·ID·핵심 범위가 섞이지 않았다.
- [ ] 확인하지 못한 사실을 단정하지 않았다.

### CC

- [ ] FF의 핵심 내용이 빠짐없이 대응한다.
- [ ] 완전한 HTML 문서이며 `lang="ko"`와 정확한 title/H1이 있다.
- [ ] CSP가 있고 script, 이벤트 핸들러, 원격 asset이 없다.
- [ ] 본문이 최초 렌더링부터 보인다.
- [ ] 모든 표에 caption과 적절한 `scope`가 있다.
- [ ] 정보성 SVG에 접근 가능한 이름과 설명이 있다.
- [ ] 키보드 포커스, 대비, 모바일 너비, 인쇄를 확인했다.
- [ ] Markdown fence가 없다.

### 게시

- [ ] FF와 CC 각각의 해시·생성 시각·producer·prompt profile이 기록되었다.
- [ ] Study Factory validator가 오류 없이 통과한다.
- [ ] 로컬 HTTP 서버에서 FF 탭과 CC iframe을 직접 확인했다.
- [ ] 공개 저장소에 비공개 데이터, 세션, 토큰 또는 브라우저 프로필이 없다.
